我们可用第5章中的数据结构和遍历算法为基础去构建任何图上的计算.但是该章中提出的所有算法处理的都是无权图—即每条边都具有相同的值或权的图. 对于加权图问题处理却是另一番天地，道路网络的边会自然而然地与数值相关联，如建造费用、遍历时间、长度以及限速值，事实证明，找出此类图中的最短路径要比无权图中的广度优先搜索更复杂，但解决此问题会为更多领域的应用大开方便之门. 其实第5章所给的图数据结构也可用于加权图，但需要略加改动，下面给出具体实现. 该邻接表结构由一个链表数组构成，而从顶点a中出来的边将会出现在edges［x］表中：

### 6.1.1 Prim算法

Prim最小生成树算法从一个顶点开始，接下来每次在树中剩下未完成部分长出一条边，直到所有的项点都被纳入而结束.

贪心算法从所有可选项中选出最好的局部选项而不考虑全局结构，它以这种方式来决定下一步该做什么，由于我们寻求权最小的树，最小生成树的贪心算法自然应是不断选择能扩大树顶点数量且权值最小的边. PrimMST（G）任选一个顶点S，从该点开始建树。while（还有未入树的顶点）do 挑选一个位于树中顶点和未入树的顶点之间权最小的边. 将所选边和顶点加入树TPrim中. Prim算法无疑会创建一棵生成树，因为在树中顶点和未入树项点之间添加边绝不可能引入环.但是，为什么它在所有生成树中权最小呢？

人们处理问题自然会想到贪心启发式方法，但它不一定能找到全局最优解，关于这一点我们已经见过很多其他的实例.因此，我们得特别小心地去论证这类断言. 我们运用反证法.假设存在一个图G且Prim算法未能给它返回最小生成树，由于我们以增量式方法建树，这意味着肯定会有一些特定时刻我们走错了路.

假设在插入边（z,g）之前，构成TPrim的边集依然是某棵最小生成树Tmin的子树，而选择边（z,g）之后将我们带离了最小生成树（见图6.3（a）），这可是致命一击. 然而怎样才算是走错路呢？如图6.3（b）所示，在Tmin中必定会有一条从z到y的路径p. 这条路径肯定用到一条边（，22），其中在TPrim中而 2却不在．（01,22）至少具有和（z， ）一样的权值，要不然Prim算法会在（z,g）获得机会前将（2， 2）选走.从Tmin中插入（z,3）且删除（21,22）所留下的生成树其权值不会比变更前更大，这意味着Prim算法没有在选择（z,g）这条边时犯下致命错误，因此得出矛盾.

这种想法最简单的实现是：给每一个顶点指派一个布尔变量以标记该顶点是否在树中（下面代码中的数组intree），接下来在每次迭代中搜索所有边，从而找到权最小的边且恰好带上一个intree中的顶点.！这里的实现技高一筹：我们对每个未入树的顶点一直跟踪记录与其相连且权值最低的边. 每次迭代时在所有尚未入树的顶点中找出这种权值最低的边加入树.我们在每次迭代后必须更新到达非树顶点的最低权值.

然而，由于最新加入的顶点是树中的唯一变更，所有边权的更新只可能来自该项点的出边：

```c
void prim(graph *g, int start)
{
    int i;                  /* 计数器 */
    edgenode *p;            /* 暂用指针 */
    bool intree[MAXV + 1];  /* 顶点已入树中？ */
    int distance[MAXV + 1]; /* 加入树中的开销 */
    int v;                  /* 当前要处理的顶点 */
    int w;                  /* 下一候选顶点 */
    int weight;             /* 边权 */
    int dist;               /* 以start为起点的当前最短距离 */

    for (i = 1; i <= g->nvertices; i++) {
        intree[i] = false;
        distance[i] = MAXINT;
        parent[i] = -1;
    }
    distance[start] = 0;
    v = start;
    while (intree[v] == false) {
        intree[v] = true;
        p = g->edges[v];
        while (p != NULL) {
            w = p->y;
            weight = p->weight;
            if ((distance[w] > weight) && (intree[w] == false)) {
                distance[w] = weight;
                parent[w] = v;
            }
            p = p->next;
        }
        v = 1;
        dist = MAXINT;
        for (i = 1; i <= g->nvertices; i++)
            if ((intree[i] == false) && (dist > distance[i])) {
                dist = distance[i];
                v = i;
            }
        if (dist == MAXINT)
            break; /* 剩余顶点均不可达 */
    }
}

```

### 6.1.2 Kruskal算法
是另一种寻找最小生成树的方法，事实证明这种算法在稀疏图中更为高效.与Prim算法相同的是，Kruskal算法也是贪心算法.而与Prim算法的不同之处在于，它不从某个特定的顶点开始. Kruskal 算法不断构建顶点的连通分量，最后在最小生成树中完工.起初每个顶点都在待成树之中建立了相互独立的分量，算法考虑所留存边中权最小的那条，并测试它的两个端点是否在同一个连通分量中并重复此过程.若是在的话，这条边就会被抛弃，因为加上它之后会在待成树中创建一个环，如果端点是在不同分量中，我们将这条边插入，并将两个分量合并成一个.由于每一个连通分量都将一直维持树的形态，因此我们从不需要对环进行显式的测试.

```c
typedef struct {
    int x;
    int y;
    int weight;
} edge_pair;

int weight_compare(const void *a, const void *b)
{
    const edge_pair *ea = a;
    const edge_pair *eb = b;

    if (ea->weight < eb->weight)
        return -1;
    if (ea->weight > eb->weight)
        return 1;
    return 0;
}

int to_edge_array(graph *g, edge_pair e[])
{
    int i;
    int n = 0;
    edgenode *p;

    /* Kruskal 的输入是无向图；邻接表中每条边出现两次，只收集一次。 */
    for (i = 1; i <= g->nvertices; i++)
        for (p = g->edges[i]; p != NULL; p = p->next)
            if (i < p->y) {
                e[n].x = i;
                e[n].y = p->y;
                e[n].weight = p->weight;
                n++;
            }

    return n;
}

void kruskal(graph *g)
{
    int i;                  /* 计数器 */
    int nedges;             /* 实际收集到的无向边数 */
    set_union s;            /* 用于集合合并的数据结构 */
    edge_pair *e;            /* 边数据结构的数组 */

    set_union_init(&s, g->nvertices);
    e = malloc((g->nedges > 0 ? g->nedges : 1) * sizeof(*e));
    if (e == NULL)
        return;
    nedges = to_edge_array(g, e);
    /* 按权值升序对边排序 */
    qsort(e, nedges, sizeof(*e), weight_compare);
    for (i = 0; i < nedges; i++) {
        if (!same_component(&s, e[i].x, e[i].y)) {
            printf("edge (%d, %d) in MST\n", e[i].x, e[i].y);
            union_sets(&s, e[i].x, e[i].y);
        }
    }
    free(e);
}

```

```c
void set_union_init(set_union *s, int n)
{
    int i;                  /* 计数器 */

    for (i = 1; i <= n; i++) {
        s->p[i] = i;
        s->size[i] = 1;
    }
    s->n = n;
}

int find(set_union *s, int x)
{
    if (s->p[x] == x)
        return x;
    else
        return find(s, s->p[x]);
}

void union_sets(set_union *s, int s1, int s2)
{
    int r1, r2;              /* 集合的根 */

    r1 = find(s, s1);
    r2 = find(s, s2);
    if (r1 == r2)
        return;              /* 已在同一个集合中 */
    if (s->size[r1] >= s->size[r2]) {
        s->size[r1] = s->size[r1] + s->size[r2];
        s->p[r2] = r1;
    }
    else {
        s->size[r2] = s->size[r1] + s->size[r2];
        s->p[r1] = r2;
    }
}

bool same_component(set_union *s, int s1, int s2)
{
    return find(s, s1) == find(s, s2);
}

```

### 6.1.4 最小生成树的变种
最小生成树算法有很多有趣的性质，有助于你解决许多紧密相关的问题：

- 最大生成树——假设一家坏心眼的电话公司拿到了将一片房屋互连的合同；公司收费正比于他们所安装的电话线数量.很自然，他们会尽量去建最昂贵的生成树，任何图的最大生成树（marimum spanning tree）都能通过简单对所有边权取负值再运行Prim算法而获得.在边被取负值的图中最负的那棵树就是未取负值之前的最大生成树.

大多数图算法并不能这么简单地适用于负数情况.事实上，最短路径算法处理负数就会出问题，可以肯定地告诉你，这种取负数的技术用于最短路径算法无法产生最长的路径.

- 最小积生成树——假设我们要找一棵能最小化边权之积的生成树，这里假定所有边权都是正数.由于log（a.6）=log（a）+log（b），边权被它们的对数取代后的图的最小生成树给出了原图的最小积生成树.
- 最小瓶颈生成树—有时我们要寻找一棵生成树，该树中权最大的边在所有生成树的此类边里是最小的事实上，每棵最小生成树都符合这种特性，证明直接参照Kruskal算法的正确性证明可得.

当边权被解释为费用、容量或者强度时，此类瓶颈生成树会有很有意思的应用，求解这类问题有一个效率略低但是概念上更为简单的方式，可从图中删除所有“较重”的边，再看看删完后的图是否依然连通.这种测试可以用简单的BFS/DFS完成.

### 6.3.1 Dijkstra算法
是一种在边加权和/或顶点加权的图中寻找最短路径的一种备选方法.给定一个起点s,Dijkstra算法会找到图中从s到剩下每个项点之间的最短距离，包括你想要的终点。假设图G中从s到t的最短路径途径某个中间顶点z.

显然这条路径肯定包含从s到z的最短路径作前缀，因为如果不这样的话，我们可以使用较短的s到z前缀来缩短s到t的路径. 因此，在找到从s到t的路径前，我们必须计算从s到z的最短路径. Dijkstra算法将执行若干轮，每轮会构建一条从s到某个新顶点z的最短路径，确切地说，遍取已找到最短路径的所有顶点k，z是尚未处理的顶点中能最小化dist（S, k） +w0（k,z）的那个，其中dist（s, ki）是从s到k最短路径的长度，而w0（k， zr）是从k到边的长度. 上述思路会让我们想到一个类似于动态规划的策略.

从s到它自身的最短路径是平凡的（除非有负权边），因此dist（S, s）=0. 接下来，如果（5,g）是从s出发权值最小的边，那么则意味着dist（s,g）=w0（8,g）.在后续轮次中，一旦确定了到节点z的最短路径，我们就检查从z出发的所有边，看看从s途经z是否会有一条抵达某个未知顶点的更好路径.

```text
ShortestPathDijkstra(G, s, t)
known = {s}
for i = 1 to n do
    dist[i] = ∞
    parent[i] = NIL
dist[s] = 0
for each edge (s, v) do
    dist[v] = w(s, v)
    parent[v] = s
last = s
while (last ≠ t) do
    在尚未找到最短路径的顶点中，选出使 dist[u] 最小的顶点 x
    for each edge (x, v) do
        if dist[v] > dist[x] + w(x, v) then
            dist[v] = dist[x] + w(x, v)
            parent[v] = x
    last = x
    known = known ∪ {x}

```

这段伪代码在目标顶点 `t` 的最短距离确定后停止；下面的 C 实现继续计算从 `s` 到所有顶点的最短距离。`parent` 数组记录每个顶点的前驱，可从 `t` 沿此前驱回溯以重建路径。这里的基本想法与Prim算法极为相似.对于顶点树中的那些结点，目前已掌握从s开始到它们的最短路径，而每次迭代我们刚好就加入一个顶点.就像在Prim算法中那样，我们对树外的所有项点记录迄今为止所能发现的最短路径，再将这些顶点按费用递增的次序插入. Dijkstra算法与Prim算法的区别在于它们如何对每个树外顶点的需求程度进行评测. 在最小生成树问题中，我们所关心的只是下一个可能被选上的树边的权.

在最短路径问题中，我们想纳入那个离s最近（以最短路径距离衡量）的树外顶点.这是一个同时涉及两种因素的函数：新加入的边（k,z）的权与从s到这条边所连的那个树内顶点k之间的距离. 实现实际上，两种算法的伪代码掩盖了它们算法实现上的极度相似.其实，算法实现的改动很小，下面我们给出一个Dijkstra算法的实现，它基于Prim算法的代码实现，也就刚好改了三行代码——而其中之一仅仅是函数名而己！以下实现假设边权非负，且有限最短路径长度能由 `int` 表示。

```c
void dijkstra(graph *g, int start) /* 原来是：prim(g, start) */
{
    int i;                  /* 计数器 */
    edgenode *p;            /* 暂用指针 */
    bool intree[MAXV + 1];  /* 顶点还在树中吗？ */
    int distance[MAXV + 1]; /* 从start到所有顶点的距离 */
    int v;                  /* 当前要处理的顶点 */
    int w;                  /* 下一候选顶点 */
    int weight;             /* 边权 */
    int dist;               /* 以start为起点的当前最短距离 */

    for (i = 1; i <= g->nvertices; i++) {
        intree[i] = false;
        distance[i] = MAXINT;
        parent[i] = -1;
    }
    distance[start] = 0;
    v = start;
    while (intree[v] == false) {
        intree[v] = true;
        p = g->edges[v];
        while (p != NULL) {
            w = p->y;
            weight = p->weight;
            /* 改动 */
            if ((distance[v] != MAXINT) &&
                (weight <= MAXINT - distance[v]) &&
                (distance[w] > (distance[v] + weight))) {
                /* 改动 */
                distance[w] = distance[v] + weight;
                parent[w] = v; /* 译者注：此处未改，原书标记有误。 */
            }
            p = p->next;
        }
        v = 1;
        dist = MAXINT;
        for (i = 1; i <= g->nvertices; i++)
            if ((intree[i] == false) && (dist > distance[i])) {
                dist = distance[i];
                v = i;
            }
        if (dist == MAXINT)
            break; /* 剩余顶点均不可达 */
    }
}

```

这种算法找到的不止是从s到t的最短路径.它实际上找到了从s到所有其他顶点的最短路径.这会定义一棵以s为根的最短路径生成树，对于无权图来说，它就是广度优先搜索树，但是在一般意义下这棵树实际上提供的是从s到所有其他顶点的最短路径. 分析 Dijkstra算法的运行时间是多少？按照这里的实现来看其复杂度是O（n2），它与Prim算法正确版本的运行时间一样.除了条件扩展-之外，它和Prim算法就是相同的算法、从start到某个给定顶点t的最短路径长度正好就是distance ［t］的值.我们怎么去用dijkstra找到实际路径呢？可以从t开始沿着parent指针反向行走，直到找到start为止， 1译者注：指改动前后判断语句中的关于distance［w］的条件变化.

如果没有这样的路径存在会遇到-1而终止.这与5.6.2节中我们在find-path（）子程序中所做的一模一样. Dijkstra算法只能在没有负权边的图中正确运行.原因是在执行的过程中我们可能会遇到一条权值非常小的负权边，其“负”作用大到会改变从s到已在树中的一些其他顶点之间的最近路线.

事实上，从你家到邻居家最划算的方法就是：不断在银行的大堂进来出去，只要你从该家银行获得足够多的钱财收益值得你如此绕来绕去！大多数应用并不涉及负权边，这使得我们更多地限于学术性讨论.下面要讲的Floyd- Waushall算法2可以正确无误地在带负权的图中找出最短路径，但却没法处理权为负值的环，因为这种环会引出一个极度畸形的最短路径结构. 除非银行限制每个客户只能拿一次回馈奖金，否则你会进出银行大堂无数次来攫取收益，而永远不会再考虑朝你真实的行程终点迈出一步！

### 停下来想想：处理节点费用的最短路径问题

假设给我们一个图，它的权都定义在顶点而不是边上。那么从 z 到 y 的路径费用就是路径中所有顶点的权之和。请给出一个在这种顶点加权图中寻找最短路径的高效算法。

解：一个自然的想法是修改已有的边权图算法（也即 Dijkstra 算法）用于顶点加权。只需在任何提到边权的地方，以边所在终点的权替换即可，并从存储顶点权的数组中读取。

然而，我更喜欢让 Dijkstra 算法保持完整，因此改为构造一个边加权图，再用 Dijkstra 算法求解。

只要将输入图的每条有向边（i,j）的权值设置为顶点j的费用，那么Dijkstra算法就可以处理这种图了. 这种技术能够被拓展到各种各样不同的领域中，比如当顶点和边都存在费用的时候.

### 6.3.2 所有点对路径
假设你想找到图的“中心”顶点—就是到其他所有顶点的最长（或平均）距离最小的那个项点，这可能会是一个开始新业务的最佳地点.或者也许你需要知道图的直径——在所有项点对上最短路径距离中的最长距离值，这可能对应发送一封信或者一个网络数据包所用的最长时间.这些问题以及其他应用会需要计算给定图中所有顶点对之间的最短距离. 由于图中n个项点都是起点，我们可对所有顶点逐个调用Dijkstra算法来解决所有点对最短路径（all-pairs shortest path）问题.

然而，Floyd和Warshall提出的所有点对最短路径算法更巧妙，它能以图的权值矩阵为底子构建出这个n×n的最短距离矩阵. 1译者注：作者用风趣的语言解释了负权.假设你去银行可能获得它回馈给你的奖金，那么每多去一次就会获益更多，而这相对于费用而言就是负权.那么，我们不着急去邻居家而应先去最大化收益，最后才去邻居家使得费用最小， 2 译者注：作者在本书中混用Floyd算法和Floyd-Warshall算法两种叫法，我们统一为Floyd-Warshall算法，并对原文关于算法作者的语句略作修改.

Floyd-Warshall算法最好用在邻接矩阵数据结构上，这样不是浪费空间，因为我们需要储存的距离都是成对的，也就是说共有n2个.下面的adjacency_matrix类型尽最大所能（也即MAXV个）为矩阵分配空间，它还会记录图中有多少个顶点.

```c
typedef struct {
    int weight[MAXV + 1][MAXV + 1]; /* 邻接（权值）信息 */
    int nvertices;                  /* 图中顶点数 */
} adjacency_matrix;

```

邻接矩阵实现的重点在于我们如何表示图中缺失的边.对于无权图通常约定1表示图中的边而0表示无边.如果用上述数字去表示边的权，却刚好给出了错误的解释，原因是原来表示无边的0在这里被解释为顶点之间不需任何费用即可到达.

与之相反，我们应该将每一个不是边的矩阵元素初始化为MAXINT.这样我们既可以测出这里是否有边，还能在最短路径计算中自动忽略无边情况，因为只有真正的边才会被用到，不过前提是MAXINT大于待处理图的直径. 有很多方式刻画图中两个节点之间最短路径的特征.Floyd-Warshall算法这样做：初始对图中顶点从1到n编号.我们不是用这些数字去标记顶点，而是给这些顶点一个处理次序，考虑从到j仅用编号为1，2，，k的项点作为可用的中间节点，这样的最短路径长度我们定义为W［i,j. 这意味着什么？

当k=0时我们不允许有中间顶点，因此唯一容许的路径就是图中原有的边，因此初始所有点对最短路径矩阵由最初的邻接矩阵组成.我们将执行n次迭代，其中第k次迭代仅让前k个顶点作为每对顶点z和g之间路径可用的中间步.1 在每次迭代中我们允许可能成为最短路径的集合再大一些，方法是添加一个新顶点作为可用的中介点.允许第k个项点作为路径中的一站，但仅在存在一条经过k的较短路径时才可行，于是 WIi，那=min（W1i，那一1，W位，则一上+WIk，那一工）。

本算法的正确性很精妙，我强烈建议你去将它完全弄明白，不过算法实现却非常简单，里面完全没有复杂的编程技巧：

```c
void floyd(adjacency_matrix *g)
{
    int i, j;       /* 二维数组尺寸计数器 */
    int k;          /* 中间顶点计数器 */
    int through_k;  /* 经过顶点 k 后的路径长度 */

    for (k = 1; k <= g->nvertices; k++)
        for (i = 1; i <= g->nvertices; i++)
            for (j = 1; j <= g->nvertices; j++) {
                through_k = g->weight[i][k] + g->weight[k][j];
                if (through_k < g->weight[i][j])
                    g->weight[i][j] = through_k;
            }
}

```

1 译者注：作者在本节中使用了步（step）和汽车站点（stop）的比喻描述路径中的顶点.

Floyd-Warshall所有点对最短路径算法可在O（n*）时间内运行完毕，这在渐近意义下不比调用Dijkstra算法n次的方法要好.然而上述程序的循环非常紧凑，并且代码非常简短，这两点让Floyd-Warshall算法性能更好而且也更实用.值得注意的是，很少有图算法在邻接矩阵中运行得比在邻接表中更好，Floyd-Warshall算法就是其中一个. 上述所编写的Floyd-Warshall算法的输出不能让我们重建任意所给一对顶点间的实际最短路径.

如果我们为每对顶点（z，g）在算法中所选用的最后一个中间项点维护一个父亲矩阵P，那么这些最短路径可以复原，比如说从z到y最短路径中最后一个中间顶点的这个值是k.从到y的最短路径则是从z到k最短路径再连上从k到y最短路径，可以对给定矩阵P递归式操作重建从z到y的最短路径.但是要注意，大多数所有点对的应用都只需要距离矩阵这个输出结果.这些任务才是设计Floyd-Warshall算法的目的.

### 6.3.3 传递闭包

Floyd-Warshall算法还有一项重要应用，就是计算传递闭包（transitive closure）.在分析 -个有向图时，我们经常对给定节点能够到达哪些顶点感兴趣. 举例来说，考虑一个胁迫图（blackmail graph），如果某人i握有另一个人j的敏感个人信息，并足以让要求j去做i想做的佳何事，那么这个胁迫图中就存在一条有向边（i,j）. 在图中的n个人中，你希望雇其中一个作为你的私人代表.那么谁的胁迫潜力最强？

最简单的答案可能是度最高的顶点，但是一个更好的私人代表应该是：一个拥有胁迫链会引出图中成员最多的那个人.Steve也许只能直接胁迫Miguel，但是如果Miguel可以敲诈剩下的任何人，那么Steve就是你要雇的人. 从任一节点可到达的项点都能通过广度优先搜索或深度优先搜索来获取.但是整批顶点则可用所有点对最短路径来计算.

如果运行完Floyd-Warshall算法之后，从到j的最短路径长度现在仍为MAXINT，你就可确定从到j不存在任何有向路径.

任何一对顶点路径的权小于MAXINT，这肯定是可达的，不论是在图论还是在胁迫这个词的字面意义上都成立. 传递闭包会在15.5节中更详细地讨论.

```c
typedef struct flow_edgenode {
    int y;                  /* 相邻顶点 */
    int capacity;           /* 边的容量 */
    int flow;               /* 该方向上的有符号流量，反向边取负值 */
    int residual;           /* 该边的残存容量 */
    struct flow_edgenode *reverse; /* 对应的反向边 */
    struct flow_edgenode *next; /* 表中下一条边 */
} flow_edgenode;

typedef struct {
    flow_edgenode *edges[MAXV + 1];
    int degree[MAXV + 1];
    int nvertices;
    int nedges;
    bool directed;
} flow_graph;

flow_edgenode *parent_edge[MAXV + 1];

bool valid_edge(flow_edgenode *e)
{
    return e->residual > 0;
}

void initialize_flow_search(flow_graph *g)
{
    int i;

    for (i = 1; i <= g->nvertices; i++) {
        processed[i] = discovered[i] = false;
        parent[i] = -1;
        parent_edge[i] = NULL;
    }
}

void flow_bfs(flow_graph *g, int start)
{
    queue q;
    int v;
    int y;
    flow_edgenode *p;

    init_queue(&q);
    enqueue(&q, start);
    discovered[start] = true;

    while (empty_queue(&q) == false) {
        v = dequeue(&q);
        process_vertex_early(v);
        p = g->edges[v];

        while (p != NULL) {
            if (valid_edge(p)) {
                y = p->y;
                if ((processed[y] == false) || g->directed)
                    process_edge(v, y);
                if (discovered[y] == false) {
                    enqueue(&q, y);
                    discovered[y] = true;
                    parent[y] = v;
                    parent_edge[y] = p;
                }
            }
            p = p->next;
        }
        process_vertex_late(v);
        processed[v] = true;
    }
}

/* 由输入图构造代码提供：初始化容量/残量，并为每对边设置互指的 reverse 指针。 */
void add_residual_edges(flow_graph *g);
int path_volume(flow_graph *g, int start, int end, int parents[]);
void augment_path(flow_graph *g, int start, int end, int parents[], int volume);

```

我们用广度优先搜索去寻找任意从源点到汇点且能增加总流量的路径，并用该路径来扩充总流量，当此类增广路径不再存在时，我们结束函数并带回最大流.

```c
void netflow(flow_graph *g, int source, int sink)
{
    int volume;             /* 增广路径的权 */

    add_residual_edges(g);
    initialize_flow_search(g);
    flow_bfs(g, source);
    volume = path_volume(g, source, sink, parent);
    while (volume > 0) {
        augment_path(g, source, sink, parent, volume);
        initialize_flow_search(g);
        flow_bfs(g, source);
        volume = path_volume(g, source, sink, parent);
    }
}

```

任何从源点到汇点的增广路径都会提升流量，所以我们用 `flow_bfs` 寻找这样一条路径。它在发现顶点前调用 `valid_edge`，只沿残量为正的边遍历；这样，已饱和的边不会被加入搜索树。 `add_residual_edges` 由输入图构造代码提供，须将正向边初始化为 `flow = 0`、`residual = capacity`，并为每条正向边加入反向边（`capacity = 0`、`flow = 0`、`residual = 0`），同时设置一对边互指的 `reverse`。搜索记录实际的前驱边，增广时据此前驱边和 `reverse` 指针更新流量与残量，因此不会因相同端点间有多条弧而选错边。

```c
int path_volume(flow_graph *g, int start, int end, int parents[])
{
    flow_edgenode *e;       /* 需要考察的边 */

    if (parents[end] == -1)
        return 0;
    e = parent_edge[end];
    if (start == parents[end])
        return e->residual;
    else
        return min(path_volume(g, start, parents[end], parents),
                   e->residual);
}

void augment_path(flow_graph *g, int start, int end, int parents[], int volume)
{
    flow_edgenode *e;       /* 需要考察的边 */
    flow_edgenode *reverse; /* 对应的反向边 */

    if (start == end)
        return;
    e = parent_edge[end];
    reverse = e->reverse;
    e->flow += volume;
    e->residual -= volume;
    reverse->flow -= volume;
    reverse->residual += volume;
    augment_path(g, start, parents[end], parents, volume);
}

```

分析上述增广路径算法肯定收敛于最优解.然而，每个增广路径可能都只会给总流量增加一点儿，因此在理论上该算法最终收敛所用的时间可能会是任意值，不过Edmonds和Karp已在［EK72］中证明，一直选择最短无权增广路径可保证0（n）次增广操作足以找到最优解，事实上，我们上面实现的就是Edmonds-Karp算法，因为我们用了一个从源点开始的广度优先搜索来寻找下一条增广路径.2 1译者注：这里考虑的容量都是整数值，每次对1个单位进行操作。2译者注：此处的无权路径实际上对每条边加了单位权，因此广度优先搜索可以找到最短路径。

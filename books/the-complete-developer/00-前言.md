## 引言

如今几乎所有的编程工作都要求至少对全栈开发有粗浅的了解，但如果你是初学者，可能会难以找到进入这个庞大主题的合适入口，甚至可能不知道这个术语是什么意思。

简单来说，全栈 Web 开发通常指使用 JavaScript 及其众多框架（framework）来构建完整的 Web 应用。它要求精通传统的前端（frontend）和后端（backend）开发，还要求能够编写中间件（middleware）和各种应用程序接口（application programming interface，API）。

此外，一名全面发展的全栈开发者还要能够处理数据库，并具备专业技能，比如编写自动化测试、独立部署自己的代码。要做到这一切，他们必须理解 HTML、CSS 和 JavaScript，以及这门语言的带类型版本 TypeScript。关于其中一些术语的速成介绍，参见第 xxiv 页的"全栈应用的组成部分"。

如果这听起来很多，那你来对地方了。本书将向你介绍现代应用的每个组成部分，并教你如何使用一些应用最广泛的技术来构建它们。

### 本书适合哪些读者？

本书有两个主要读者群体。第一类是希望通过掌握全栈开发来推进职业生涯的专业前端或后端工程师。第二类是有兴趣学习 Web 开发、尚无经验的入门开发者。

虽然本书从零开始介绍许多技术，但它假定你对 HTML、CSS 和 JavaScript，以及大多数 Web 应用的客户端/服务器（client/server）架构已有一定的熟悉程度。想要温习，可以参阅 Sam Taylor 的 The Coding Workbook（No Starch Press，2020），它教你如何用 HTML 和 CSS 构建网站；再借助 Peter Gasston 的 The Book of CSS3, 2nd edition（No Starch Press，2014）来精进你的 CSS 技能。要熟悉 JavaScript，我推荐 Nick Morgan 的 JavaScript Crash Course（No Starch Press，2024），这是一本面向初学者的快节奏 JavaScript 教程；以及 Marijn Haverbeke 的 Eloquent JavaScript, 3rd edition（No Starch Press，2018），适合深入学习 JavaScript。

### 本书包含哪些内容？

本书分为两部分。第 I 部分（Part I）由第 1 章到第 10 章组成，向你介绍现代技术栈的各个组成部分。每章聚焦一项技术，并着重讲解作为全栈开发者需要掌握的主题。练习会鼓励你从第 1 页起就开始编写应用代码。

- **第 1 章：Node.js**　介绍 Node.js 及其生态系统，它让你能够在浏览器之外运行 JavaScript 代码。随后，你将使用 Node.js 和 Express.js 框架，用 JavaScript 创建自己的简单 Web 服务器。

- **第 2 章：现代 JavaScript**　聚焦对全栈开发者有用的现代 JavaScript 语法，包括如何使用模块（module）编写可维护的代码包。我们将探讨定义变量和常量的不同方式、箭头函数（arrow function），以及异步代码技术。你将用它们重写你的 JavaScript 服务器。

- **第 3 章：TypeScript**　介绍 TypeScript（JavaScript 的超集 superset），并重点说明现代全栈开发如何从中受益。我们会讨论 JavaScript 的缺点与陷阱，以及如何通过类型推断（inference）有效地利用 TypeScript 的类型系统。本章最后，你将使用类型注解（type annotation）、自定义类型和接口（interface）重构你的 JavaScript 服务器。

- **第 4 章：React**　讨论 React 这一最常用的用户界面组件库之一。你将看到它的组件如何简化全栈开发，并学习如何使用它的 JSX 元素、虚拟 DOM（virtual DOM）和钩子（hooks）。随后，你将使用 React 为你的 Express.js 服务器添加响应式用户界面。

- **第 5 章：Next.js**　聚焦 Next.js 这一构建在 React 之上的领先 Web 应用框架。你将使用 Next.js 基于文件的路由（file-based routing）创建页面和自定义 API 路由，然后学习在框架内渲染页面的不同方式。最后，作为练习，你将把 Express.js 服务器迁移到 Next.js。

- **第 6 章：REST 和 GraphQL API**　全面讲解 API：它们是什么，以及如何在全栈 Web 开发中使用它们。我们将探索两类 API：REST 和 GraphQL。本章最后，你将为你的 Next.js 全栈应用添加一个 Apollo GraphQL 服务器。

- **第 7 章：MongoDB 与 Mongoose**　讨论传统关系型数据库（relational database）与 MongoDB 等非关系型数据库之间的区别。你将把 Mongoose 对象数据建模（object data modeling）工具加入技术栈，以简化数据库操作。随后，你将把 GraphQL API 连接到你自己的 MongoDB 数据库。

- **第 8 章：使用 Jest 框架进行测试**　解释自动化测试和测试驱动开发（test-driven development）对全栈开发的重要性。我们将探索不同类型的测试、常见的测试模式，以及测试替身（test double）、桩（stub）、伪实现（fake）和模拟对象（mock）的概念。最后，你将使用 Jest 框架为你的 Next.js 应用添加几个基本的快照测试（snapshot test）。

- **第 9 章：使用 OAuth 进行授权**　讨论认证（authentication）与授权（authorization），以及全栈开发者如何通过集成第三方服务，利用 OAuth 协议来处理这些任务。我们将走查这一授权流程及其组成部分。你将在命令行上完整运行一次 OAuth 交互，以深入探究每个步骤。

- **第 10 章：使用 Docker 进行容器化**　介绍如何使用 Docker 部署你的应用。我们会讲解微服务架构（microservice architecture）的概念，然后涵盖 Docker 生态系统的所有相关组件：主机（host）、Docker 守护进程（daemon）、Dockerfile、镜像（image）、容器（container）、卷（volume）和 Docker Compose。最后，你将把应用拆分为自包含的微服务。

在第 II 部分，你将运用新学到的知识构建一个 Web 应用，以应用第 I 部分介绍的概念、工具和框架。Food Finder 应用是一个位置搜索服务，让用户使用自己的 GitHub 账号登录，并维护一份想去之地的愿望清单。

- **第 11 章：搭建 Docker 环境**　运用你关于 Docker 和容器化的知识搭建开发环境，为 Food Finder 应用打下基础。你将使用 Docker Compose 把应用开发与本地系统解耦，然后添加一个 MongoDB 服务器作为独立服务。

- **第 12 章：构建中间件**　创建 Food Finder 应用中间件的第一部分。在这里，你将把 Mongoose 连接到 MongoDB 服务，并创建它的模式（schema）、模型（model）、服务（service）和自定义类型。有了这些组件，你就能够对数据库中的数据进行创建、读取、更新和删除操作。

- **第 13 章：构建 GraphQL API**　运用你关于 GraphQL 的知识，为 Food Finder 应用添加一个 Apollo GraphQL 服务器，然后实现一个公开的 GraphQL API。你将能够使用 Apollo 沙盒（sandbox），通过 GraphQL 在你的 MongoDB 服务器上读取和更新数据。

- **第 14 章：构建前端**　使用 React 组件和 Next.js 框架为 Food Finder 应用构建前端。至此，你将已经实现了一个完整的现代全栈应用：它通过你的自定义中间件从数据库读取数据，并将数据渲染到应用的前端。

- **第 15 章：添加 OAuth**　为应用添加 OAuth 流程，让访客可以登录以维护个人的地点愿望清单。你将使用 Auth.js 的 next-auth 包来添加使用 GitHub 的登录选项。

- **第 16 章：在 Docker 中运行自动化测试**　使用 Jest 建立自动化快照测试，并配置一个新服务来自动运行这些测试。

### 全栈应用的组成部分

在本书中，我们会讨论应用的各个部分。本节为你速览：当我们使用前端、中间件和后端这些术语时，指的是什么。

#### 前端

前端是网站或 Web 应用面向用户的部分。它运行在客户端（client）上，通常是 Web 浏览器。你可以把它想象成 Web 应用的"前台"。例如，在 https://www.google.com 上，前端就是一个带有简单搜索框的页面；当然，前端开发可以比这复杂得多——看看 Google 的搜索结果页，或者你最近访问的某个网站的界面就知道了。

前端开发者关注用户参与度、体验和界面。他们依靠 HTML 创建网站界面的元素，依靠 CSS 进行样式设置，依靠 JavaScript 实现用户交互，并借助 Next.js 之类的框架把一切整合到一起。

#### 中间件

中间件连接应用的前端和后端，并承担应用的所有杂务，比如与第三方服务集成、传输和更新数据。你可以把它想象成公司楼层里的员工。

作为全栈开发者，我们经常编写中间件来处理应用的路由（routing），也就是为特定 URL 提供正确的数据、处理数据库连接，以及执行授权。例如，在 https://www.google.com 上，中间件会向服务器请求着陆页的 HTML。然后，中间件的另一部分检查用户是否已登录，如果已登录，还检查应该展示哪些个人数据。与此同时，中间件的第三部分则整合来自每条数据流的信息，然后用正确的 HTML 响应服务器的请求。

全栈应用中间件的一个重要组成部分是它的 API 层（API layer），即对外暴露应用 API 的部分。一般而言，API 是为连接两台机器而编写的代码。API 通常让前端代码（或第三方）能够访问应用的后端。JavaScript 驱动的开发依赖两个主要的架构框架来创建 API：REST 和 GraphQL，两者都会在第 6 章中介绍。

你可以用任何编程语言编写中间件。大多数全栈开发者使用现代 JavaScript 或 TypeScript，但也可以改用 PHP、Ruby 或 Go。

#### 后端

后端是 Web 应用不可见的部分。在 JavaScript 驱动的应用中，后端运行在服务器上，通常是 Express.js，不过也有人使用 Apache 或 NGINX。你可以把它想象成 Web 应用的"后台"。

更具体地说，后端处理所有涉及应用数据的操作。它对存储在数据库中的值执行创建、读取、更新和删除（create, read, update, delete，CRUD）操作，并通过中间件的 API 层返回用户请求的数据集。对于 https://www.google.com 来说，后端就是在数据库中搜索你在前端输入的关键词的代码，而这些关键词是后端通过中间件收到的。中间件随后会将这些搜索结果与其他相关信息组合起来。然后，用户就会看到由前端渲染出的搜索结果页面。

后端开发可以用任何编程语言完成。全栈开发者通常使用现代 JavaScript 或 TypeScript。其他选择包括 PHP、Ruby、Elixir、Python、Java，以及 Symfony、Ruby on Rails、Phoenix 和 Django 等框架。

### JavaScript 与全栈开发简史

所有开发者都应该了解自己所使用工具的背景。在开始开发之前，让我们先了解一点历史。

全栈开发者这一职位是随着 JavaScript 一起发展起来的。JavaScript 起初不过是一种运行在用户浏览器中的脚本语言。开发者用它为网站添加能立即对用户行为做出反应的元素，比如手风琴折叠菜单（accordion）、弹出菜单和遮罩层（overlay），而不需要向应用的服务器发起请求。

直到 2000 年代后期，大多数 JavaScript 库的设计目标都是提供一致的接口，以处理各浏览器厂商特有的兼容性问题。当时的 JavaScript 引擎往往很慢，尤其是在与 HTML 交互、更新或修改 HTML 时。因此，JavaScript 被视为一门古怪的前端脚本语言，备受后端开发者的轻视。

曾有多个项目尝试推广在后端使用 JavaScript，但在 2009 年 Node.js 发布之前，这些尝试都未获得关注。第 1 章将介绍的 Node.js 是一个用于开发后端的 JavaScript 工具。此后不久，Node.js 的包管理器（package manager）npm 为全栈 JavaScript 开发补齐了缺失的生态系统。

这个生态系统包括大量 JavaScript 库，用于操作数据库、构建用户界面和编写服务器端代码（其中许多我们都将在本书中探讨）。这些新工具让开发者能够在客户端和服务器两端可靠地使用 JavaScript。特别重要的是，Google 于 2010 年发布了 Angular 框架，Meta（当时还叫 Facebook）于 2013 年发布了 React。这些互联网巨头投入构建 JavaScript 工具的决心，使全栈 Web 开发成为一种抢手的职业角色。

### 环境搭建

在本书中，你会编写代码并运行命令行工具。你可以使用任何自己喜欢的开发环境，以下是一些指引。

如今最常用的代码编辑器是 Visual Studio Code，你可以从 https://code.visualstudio.com 下载。它是微软的开源编辑器，在 Windows、macOS 和 Linux 上免费使用。此外，你可以通过大量第三方插件来扩展和配置它，并按自己的喜好调整外观。不过，如果你习惯使用其他编辑器，比如 Vim 或 Emacs，也可以继续使用。本书不要求使用特定的工具。

取决于你的操作系统，默认的命令行程序是命令提示符（Command Prompt，Windows）或终端（Terminal，macOS 和 Linux）。这些程序在创建、切换和列出目录内容等任务上使用的语法略有不同。本书展示的是 Linux 和 macOS 版本的命令。如果你使用 Windows，就需要针对你的操作系统调整命令。例如，Windows 不使用 ls，而是用 dir 来列出当前目录中的文件和文件夹。微软官方的命令行参考在这里列出了所有可用的命令：https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/windows-commands#command-line-reference-a-z。

与本书相关的操作系统之间最显著的区别，是多行 cURL 命令中用于换行的转义字符（escape character）。这个转义字符在 macOS 上是 `\`，在 Windows 上是 `^`。我们会在第 6 章首次使用 cURL 时指出这些差异。

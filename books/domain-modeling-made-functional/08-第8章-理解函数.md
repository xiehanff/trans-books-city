## 函数无处不在

首先来看看，函数式编程为什么与面向对象（object-oriented）编程如此不同。函数式编程有许多不同的定义，我打算挑一个非常简单的：

> 函数式编程，就是像函数真的很重要那样去编程。

在大多数现代语言中，函数都是第一类对象，但偶尔使用函数（或 lambda）并不意味着你就是在“做”函数式编程。函数式编程范式的关键在于：函数无处不在，用于一切场合。

例如，假设我们有一个由较小的部件组装而成的大型程序。

在面向对象的方法中，这些部件是类和对象。

在函数式的方法中，这些部件是函数。

再比如，我们需要对程序的某个方面进行参数化，或者想降低组件之间的耦合。

面向对象的方法会使用接口和依赖注入（dependency injection）。

函数式的方法会用函数来进行参数化。

又如，我们想遵循“不要重复自己”（don't repeat yourself，DRY）原则，在许多组件之间复用代码。

面向对象的方法可能会使用继承，或者装饰器模式（Decorator pattern）之类的技术。

函数式的方法则是把所有可复用的代码放进函数中，再用组合把它们粘接起来。

因此，重要的是理解：函数式编程并不只是风格上的差异，而是一种完全不同的思考编程的方式。如果你是新接触它，应当以初学者的心态来学习 FP。

也就是说，与其从另一种范式的角度提问（比如“我怎样遍历一个集合？”或“我怎样实现策略模式？”），不如问如何解决同样的底层问题（“我如何对集合中的每个元素执行一个动作？”或“我如何对行为进行参数化？”）。我们程序员面对的问题是相同的，但函数式编程使用的解决方案与面向对象编程使用的非常不同。

## 函数是“东西”

在函数式编程范式中，函数本身就是“东西”（thing）。而既然函数是东西，它们就可以作为输入传给其他函数（一个函数与普通输入一起进入外层函数，处理后产生输出）。

它们也可以作为函数的输出被返回（一个函数接收输入，返回的输出是另一个函数）。

它们还可以作为参数传给某个函数，用来控制该函数的行为（作为参数传入的函数决定了外层函数的行为方式）。

把函数当作东西，打开了一个充满可能性的世界。一开始可能很难理解，但你已经可以看到：仅凭这条基本原则，就能相当快速地构建出复杂的系统。

> **术语警示：“高阶函数（higher-order function）”**
>
> 以其他函数作为输入或输出、或者把函数当作参数的函数，称为高阶函数，常缩写为 HOF。

### 在 F# 中把函数当作“东西”

我们来看看“函数是东西”在 F# 中如何运作。下面是四个函数定义：

```fsharp
let plus3 x = x + 3            // plus3 : x:int -> int
let times2 x = x * 2           // times2 : x:int -> int
let square = (fun x -> x * x)  // square : x:int -> int
let addThree = plus3           // addThree : (int -> int)
```

前两个定义与我们之前见过的一样。在第三个定义中，`let` 关键字用于为一个匿名函数（anonymous function，也称 lambda 表达式）指定名字（square）。在第四个定义中，`let` 关键字用于为先前定义的函数（plus3）指定名字（addThree）。这几个函数都是 `int -> int` 函数：接收一个 int 作为输入，输出一个新的 int。

现在，因为函数是东西，我们可以把它们放进一个列表：

```fsharp
// listOfFunctions : (int -> int) list
let listOfFunctions =
  [addThree; times2; square]
```

在 F# 中，列表字面量以方括号为界，元素之间用分号（而不是逗号！）分隔。

现在我们可以遍历这个列表，依次对每个函数求值：

```fsharp
for fn in listOfFunctions do
  let result = fn 100   // 调用该函数
  printfn "If 100 is the input, the output is %i" result

// 结果 =>
// If 100 is the input, the output is 103
// If 100 is the input, the output is 200
// If 100 is the input, the output is 10000
```

`let` 关键字不只用于定义函数——它通常用来为值指定名字。例如，下面用 `let` 为字符串 "hello" 指定名字：

```fsharp
// myString : string
let myString = "hello"
```

用同一个关键字（`let`）来定义函数和简单的值，并非偶然。让我们通过一个例子看看原因。在第一段代码中，我定义了一个名为 square 的函数：

```fsharp
// square : x:int -> int
let square x = x * x
```

而在第二段代码中，我为一个匿名函数指定了 square 这个名字。这里的 `let` 定义的是简单值还是函数？

```fsharp
// square : x:int -> int
let square = (fun x -> x * x)
```

答案是：两者都是！函数是一个东西，可以被指定名字。所以 square 的第二个定义与第一个定义本质上是相同的，二者可以互换使用。

### 函数作为输入

我们说过，“函数是东西”意味着它们可以被用作输入和输出，下面来看看这在实践中是什么样子。

首先，看看把函数用作输入参数。这里有一个名为 evalWith5ThenAdd2 的函数，它接收一个函数 fn，用 5 调用它，然后在结果上加 2：

```fsharp
let evalWith5ThenAdd2 fn =
  fn(5) + 2

// evalWith5ThenAdd2 : fn:(int -> int) -> int
```

查看底部的类型签名，可以看到编译器已推断出 fn 必须是一个 `(int -> int)` 函数。

现在来测试一下。首先定义 add1，它是一个 `(int -> int)` 函数，然后把它传入：

```fsharp
let add1 x = x + 1     // 一个 int -> int 函数
evalWith5ThenAdd2 add1 // fn(5) + 2 变成 add1(5) + 2
//                     // 所以输出是 8
```

结果正如所料，是 8。

任何 `(int -> int)` 函数都可以作为参数使用。所以我们再定义一个不同的函数，比如 square，把它作为参数传入：

```fsharp
let square x = x * x     // 一个 int -> int 函数
evalWith5ThenAdd2 square // fn(5) + 2 变成 square(5) + 2
//                       // 所以输出是 27
```

这一次结果是 27。

### 函数作为输出

现在转向函数作为输出。为什么你会想这么做？

返回函数的一个非常重要的理由是：你可以把某些参数“固化”（bake in）到函数中。

例如，假设你有三个不同的整数加法函数，像这样：

```fsharp
let add1 x = x + 1
let add2 x = x + 2
let add3 x = x + 3
```

显然，我们想去掉这种重复。怎么做呢？

答案是创建一个“加法器生成器”——一个返回“加法”函数的函数，要加的数字已经被固化在其中（adderGenerator 接收 numberToAdd，返回一个新函数；这个新函数接收 x，输出 numberToAdd + x）。

下面是代码的样子：

```fsharp
let adderGenerator numberToAdd =
  // 返回一个 lambda
  fun x -> numberToAdd + x

// val adderGenerator :
//    int -> (int -> int)
```

看类型签名，它清楚地告诉我们：这个函数接收一个 int 作为输入，产出一个 `(int -> int)` 函数作为输出。

我们也可以让 adderGenerator 返回一个具名函数而非匿名函数，像这样实现：

```fsharp
let adderGenerator numberToAdd =
  // 定义一个嵌套的内部函数
  let innerFn x =
    numberToAdd + x

  // 返回内部函数
  innerFn
```

正如前面 square 的例子所示，这两种实现实际上是相同的。你更喜欢哪一种？

最后，看看 adderGenerator 在实践中可能如何使用：

```fsharp
// 测试
let add1 = adderGenerator 1
add1 2     // 结果 => 3

let add100 = adderGenerator 100
add100 2   // 结果 => 102
```

### 柯里化

利用返回函数这一技巧，任何多参数函数都可以被转换为一系列单参数函数。这种方法叫作柯里化（currying）。

例如，一个像 add 这样的双参数函数：

```fsharp
// int -> int -> int
let add x y = x + y
```

可以像上面看到的那样，通过返回一个新函数，转换为一个单参数函数：

```fsharp
// int -> (int -> int)
let adderGenerator x = fun y -> x + y
```

在 F# 中，我们不需要显式地做这件事——每个函数都是柯里化的函数！也就是说，任何签名为 `'a -> 'b -> 'c` 的双参数函数，也都可以解释为一个接收 `'a` 并返回 `('b -> 'c)` 函数的单参数函数，参数更多的函数依此类推。

### 偏应用

如果每个函数都是柯里化的，那就意味着你可以拿任何多参数函数，只传入一个参数，就会得到一个新函数：该参数已被固化在内，其余参数仍然需要提供。

例如，下面的 sayGreeting 函数有两个参数：

```fsharp
// sayGreeting: string -> string -> unit
let sayGreeting greeting name =
  printfn "%s %s" greeting name
```

但我们可以只传入一个参数，创建几个把问候语固化在内的函数：

```fsharp
// sayHello: string -> unit
let sayHello = sayGreeting "Hello"

// sayGoodbye: string -> unit
let sayGoodbye = sayGreeting "Goodbye"
```

这些函数现在还剩一个参数：名字。只要提供它，我们就得到最终输出：

```fsharp
sayHello "Alex"
// 输出："Hello Alex"

sayGoodbye "Alex"
// 输出："Goodbye Alex"
```

这种“固化”参数的做法叫作偏应用（partial application），是一种非常重要的函数式模式。例如，在第 9 章《实现：组合一个管道》（Implementation: Composing a Pipeline）中，当我们开始实现下单工作流时，会看到它被用来做依赖注入。

## 全函数

数学函数把每个可能的输入都关联到一个输出。在函数式编程中，我们试图以同样的方式设计函数，使每个输入都有对应的输出。这类函数称为全函数（total function）。

为什么要费这个劲？因为我们希望尽可能把事情显式化，让所有效果都记录在类型签名中。

我们用一个相当无聊的函数来演示这个概念：twelveDividedBy，它用整数除法返回 12 除以输入的结果。用伪代码表示的话，我们可以用一张情形表来实现，像这样：

```fsharp
let twelveDividedBy n =
  match n with
  | 6 -> 2
  | 5 -> 2
  | 4 -> 3
  | 3 -> 4
  | 2 -> 6
  | 1 -> 12
  | 0 -> ???
```

那么，输入为零时答案应该是什么？十二除以零是未定义的。

如果我们并不在乎每个可能的输入都有对应的输出，可以直接对零的情况抛出异常，像这样：

```fsharp
let twelveDividedBy n =
  match n with
  | 6 -> 2
  ...
  | 0 -> failwith "Can't divide by zero"
```

但让我们看看以这种方式定义的函数的签名：

```fsharp
twelveDividedBy : int -> int
```

这个签名暗示：传入一个 int，就能拿回一个 int。但这是个谎言！你并不总能拿回一个 int；有时候你得到的是一个异常。而这一点并没有在类型签名中显式表达。

如果类型签名不说谎就太好了。那样一来，函数的每个输入都会有一个合法的输出，没有任何异常（exception 这个词的两层含义都适用）。我们来看看如何做到这一点。

一种技术是限制输入，排除非法的值。就这个例子而言，我们可以创建一个受约束的新类型 NonZeroInteger 并传入它。零根本不在输入值的集合中，因此永远不需要处理：

```fsharp
type NonZeroInteger =
  // 定义为受约束的非零 int。
  // 再加上智能构造函数（smart constructor）等
  private NonZeroInteger of int

/// 使用受限的输入
let twelveDividedBy (NonZeroInteger n) =
  match n with
  | 6 -> 2
  ...
  // 0 不可能出现在输入中
  // 因此无需处理
```

这个新版本的签名如下：

```fsharp
twelveDividedBy : NonZeroInteger -> int
```

这比前一版本好得多。你立刻就能看出对输入有什么要求，而无需阅读文档或查看源码。这个函数不说谎，一切都是显式的。

另一种技术是扩展输出。采用这种方法时，我们可以接受零作为输入，但把输出扩展为“一个有效的 int”与“一个未定义的值”之间的选择。我们将使用 Option 类型来表示这种“有值”与“无值”之间的选择。实现如下：

```fsharp
/// 使用扩展的输出
let twelveDividedBy n =
  match n with
  | 6 -> Some 2 // 有效
  | 5 -> Some 2 // 有效
  | 4 -> Some 3 // 有效
  ...
  | 0 -> None   // 未定义
```

这个新版本的签名会是：

```fsharp
twelveDividedBy : int -> int option
```

它的含义是：你给我一个 int，如果输入可接受，我可能会还你一个 int。同样，这个签名是显式的，不会误导你。

即便是在这样一个无聊的例子中，我们也能看到使用全函数的好处。两个变体的函数签名都把所有可能的输入和输出显式地表达了出来。在本书后面的部分，尤其是在讲错误处理的那一章，我们会看到用函数签名记录所有可能输出的真实用法。

## 函数组合

我们在类型的语境下讨论过“组合”——通过组合其他类型来创建新类型。现在来谈谈函数组合（function composition）：把第一个函数的输出连接到第二个函数的输入，从而把函数组合起来。

例如，这里有两个函数。第一个接收一个苹果作为输入，输出一根香蕉。第二个接收一根香蕉作为输入，输出一些樱桃。第一个函数的输出类型与第二个函数的输入类型相同，因此我们可以像这样把它们组合在一起（苹果 → 第一个函数 → 香蕉 → 第二个函数 → 樱桃，第一个函数的输出恰好是第二个函数的输入）。

把它们组合在一起之后，我们得到了一个新函数（苹果 → 组合后的新函数 → 樱桃，中间环节的香蕉已不再可见）。

这种组合的一个重要方面是信息隐藏。你无法看出这个函数是由更小的函数组合而成的，也无法知道那些更小的函数操作的是什么。在这个例子中，香蕉去哪儿了？这个新函数的使用者甚至不知道曾经存在过一根香蕉。我们成功地把这一信息对最终组合而成的函数的使用者隐藏了起来。

### F# 中的函数组合

函数组合在 F# 中是如何运作的？

在 F# 中，只要第一个函数的输出类型与第二个函数的输入类型相同，任意两个函数就可以粘接在一起。这通常是通过一种叫作“管道”（piping）的方式完成的。

F# 中的管道与 Unix 中的管道非常相似。你从一个值开始，把它喂给第一个函数；取第一个函数的输出，喂给下一个函数，依此类推。序列中最后一个函数的输出，就是整条管道的输出。

F# 中的管道操作是 `|>`。对第一个例子使用管道，代码会像这样：

```fsharp
let add1 x = x + 1     // 一个 int -> int 函数
let square x = x * x   // 一个 int -> int 函数

let add1ThenSquare x =
  x |> add1 |> square

// 测试
add1ThenSquare 5       // 结果是 36
```

我们为 add1ThenSquare 定义了参数 x。在实现中，这个参数被喂给第一个函数（add1），启动数据在管道中的流动。

再看另一个例子。第一个函数是 `int -> bool` 函数，第二个函数是 `bool -> string` 函数，组合而成的函数是 `int -> string`：

```fsharp
let isEven x =
  (x % 2) = 0              // 一个 int -> bool 函数

let printBool x =
  sprintf "value is %b" x  // 一个 bool -> string 函数

let isEvenThenPrint x =
  x |> isEven |> printBool

// 测试
isEvenThenPrint 2          // 结果是 "value is true"
```

### 用函数构建完整的应用

组合原则可以用来构建完整的应用。

例如，从应用最底层的基础函数开始（每个基础函数各自接收输入、返回输出）。

然后我们把它们组合起来，创建出服务函数，比如这样（输入 → 多个基础函数依次处理 → 输出）。

接着，我们可以使用这些服务函数，把它们粘合在一起，创建出一个处理完整工作流的函数（输入 → 多个服务函数依次处理 → 输出）。

最后，我们可以把这些工作流并行组合，再创建一个控制器/分发器，根据输入选择要调用的具体工作流，从而构建出一个应用，如图所示（多个工作流并排组合；其上是一个控制器/分发器函数，它接收输入，并决定把工作交给哪个工作流处理）。

构建函数式应用就是这样。每一层都由一个拥有输入和输出的函数构成。一路向上，全都是函数。

在第 9 章《实现：组合一个管道》中，我们将看到这些思想如何付诸实践——通过组装一系列较小的函数，实现下单工作流的管道。

### 组合函数时的挑战

当一个函数的输出与另一个函数的输入匹配时，组合很容易。但如果函数不那么容易匹配上，会发生什么？

常见的情况是：底层类型本可以匹配，但函数的“形状”不同。

例如，一个函数可能输出 `Option<int>`，而第二个函数需要的是普通的 int。反过来，一个函数可能输出 int，而第二个函数需要 `Option<int>`。

处理列表、表示成功/失败的 Result 类型、async 等时，也会出现类似的不匹配问题。

使用组合时的许多挑战，都在于设法调整输入和输出使它们匹配，从而让函数能够连接在一起。一种流行的做法是把两边都转换成同一个类型——可以说是两边的“最小公倍数”。

例如，如果输出是 int 而输入是 `Option<int>`，那么能同时涵盖两者的“最小”类型——最小公倍数——就是 Option。如果我们用 `Some` 把 functionA 的输出转换为 Option，调整后的值就可以用作 functionB 的输入，组合就能发生（functionA 输出的 int 经 `Some` 转换为 `Option<int>`，正好匹配 functionB 的输入）。

下面用真实的代码演示这个例子：

```fsharp
// 一个以 int 为输出的函数
let add1 x = x + 1

// 一个以 Option<int> 为输入的函数
let printOption x =
  match x with
  | Some i -> printfn "The int is %i" i
  | None -> printfn "No value"
```

要把它们连接起来，我们用 `Some` 构造器把 add1 的输出转换为 Option，然后它就可以被管道传给 printOption 的输入：

```fsharp
5 |> add1 |> Some |> printOption
```

这是一个非常简单的类型不匹配问题示例。在为下单工作流建模、随后尝试把这些函数组合起来时，我们已经见过更复杂的例子。在接下来的两章实现章节中，我们会花相当多的时间把函数调整成统一的形状，使它们能够被组合。

在本章中，我们认识了 F# 函数式编程的基本概念——把函数当作无处不在的构建块，并把它们设计成可组合的。

掌握了这些原则之后，我们终于可以开始做一些真正的编码了！在下一章中，我们将把这些概念付诸实践，从为下单工作流构建一条管道开始。

# 第 6 章　应用作者样式

*Chapter 6: Applying Author Styles*

在上一章中，我们给每个 pre 元素设置了灰色背景。效果还行，有默认样式也是件好事，但网站总想对自己的外观有发言权。网站靠层叠样式表（Cascading Style Sheets，CSS）[1] 做到这一点，它允许网页作者（以及，我们将会看到的，浏览器开发者）定义网页应有的样子。

## 6.1 用函数解析

网页改变自身外观的一种方式是使用 style 属性。例如，下面这行代码改变元素的背景色：

```html
<div style="background-color:lightblue"></div>
```

更一般地说，style 属性包含一组用分号分隔的「属性–值」对（property–value pair）。浏览器查看这些 CSS「属性–值」对来决定元素的外观，例如决定它的背景色。

要把这个功能加入浏览器，我们得先从解析这些「属性–值」对开始。我会使用递归的解析函数，这是逐步构建复杂解析器的好办法。思路是：每个解析函数都在待解析的文本中向前推进，并返回它解析出的数据。我们会为不同类型的数据编写不同的函数，并把它们组织到一个 CSSParser 类里，由这个类保存待解析的文本以及解析器在其中的当前位置：

```python
class CSSParser:
    def __init__(self, s):
        self.s = s
        self.i = 0
```

让我们从小处着手，逐步搭建。解析空白字符的函数让索引 i 越过每个空白字符：

```python
def whitespace(self):
    while self.i < len(self.s) and self.s[self.i].isspace():
        self.i += 1
```

空白字符没有意义，所以没有解析数据要返回。但解析属性名时，我们要把结果返回：

```python
def word(self):
    start = self.i
    while self.i < len(self.s):
        if self.s[self.i].isalnum() or self.s[self.i] in "#-.%":
            self.i += 1
        else:
            break
    if not (self.i > start):
        raise Exception("Parsing error")
    return self.s[start:self.i]
```

这个函数让 i 越过所有词字符，¹与 whitespace 的做法很像。但为了返回解析出的数据，它会记下自己从哪里开始，并提取它所经过的子串。

解析函数可能失败。我们刚写的 word 函数在 i 没有前进至少一个字符时抛出异常——否则，说明它一开始指向的就不是词。²类似地，要检查某个字面冒号（或其他标点字符），可以这样写：

```python
def literal(self, literal):
    if not (self.i < len(self.s) and self.s[self.i] == literal):
        raise Exception("Parsing error")
    self.i += 1
```

解析函数的一大妙处是它们能相互组合。例如，「属性–值」对就是一个属性、一个冒号和一个值，³中间夹着空白字符：

```python
def pair(self):
    prop = self.word()
    self.whitespace()
    self.literal(":")
    self.whitespace()
    val = self.word()
    return prop.casefold(), val
```

我们可以把解析函数放进循环里来解析序列。例如，style 属性就是一连串的「属性–值」对：

```python
def body(self):
    pairs = {}
    while self.i < len(self.s):
        prop, val = self.pair()
        pairs[prop.casefold()] = val
        self.whitespace()
        self.literal(";")
        self.whitespace()
    return pairs
```

在浏览器里，我们必须时刻想着错误处理。有时是网页作者犯了错；有时是我们的浏览器不支持其他浏览器支持的某个特性。所以，解析不过的「属性–值」对应跳过，解析通过的则保留。我们可以用这个小函数来跳过内容；它会在遇到给定字符集合中的任意一个字符时停下，并返回那个字符（如果是被字符串末尾挡下的，则返回 None）：

```python
def ignore_until(self, chars):
    while self.i < len(self.s):
        if self.s[self.i] in chars:
            return self.s[self.i]
        else:
            self.i += 1
    return None
```

当某个「属性–值」对解析失败时，我们跳到下一个分号，或者跳到字符串末尾：

```python
def body(self):
    # ...
    while self.i < len(self.s):
        try:
            # ...
        except Exception:
            why = self.ignore_until([";"])
            if why == ";":
                self.literal(";")
                self.whitespace()
            else:
                break
    # ...
```

跳过解析错误是把双刃剑。它会隐藏错误信息，让作者更难调试样式表，也让你的解析器更难调试。⁴所以在大多数编程场景中，这种「一网打尽」式的错误处理是一种代码坏味道（code smell）。

但在 Web 上，「一网打尽」式的错误处理却有一个不寻常的好处。Web 是一个由众多浏览器组成的生态系统，⁵这些浏览器（举例来说）支持不同种类的属性值。⁶在一种浏览器里能解析的 CSS，换一种浏览器可能就解析不了。有了静默的解析错误，浏览器只是忽略自己看不懂的东西，网页便基本能在所有浏览器中正常工作。这条原则（有各种各样的名字：「Postel 定律」⁷、「数字原理」⁸或「鲁棒性原则」）是说：产出最大限度地符合规范的输出，但接受哪怕最低限度符合规范的输入。

> **深入探索**
>
> 这种解析方法在形式上叫作针对 LL(1) 语言 [2] 的递归下降解析（recursive descent parsing）。采用这种方法的解析器可以非常、非常快 [3]，至少在你愿意下大功夫的时候是如此。对浏览器来说，解析越快，页面加载就越快。

## 6.2 style 属性

既然 style 属性已经解析好了，我们就可以把解析出的信息用在浏览器的其余部分。让我们在一个 style 函数里做这件事，把解析好的 style 属性存进节点的 style 字段：

```python
def style(node):
    node.style = {}
    if isinstance(node, Element) and "style" in node.attributes:
        pairs = CSSParser(node.attributes["style"]).body()
        for property, value in pairs.items():
            node.style[property] = value
```

这个方法可以在 HTML 树中递归，确保每个元素都拿到样式：

```python
def style(node):
    # ...
    for child in node.children:
        style(child)
```

在浏览器的 load 方法中调用 style，位置在解析 HTML 之后、执行布局之前。有了存在每个元素上的样式信息，浏览器就可以在绘制（paint）时查询它来获取样式信息：

```python
class BlockLayout:
    def paint(self):
        # ...
        bgcolor = self.node.style.get("background-color",
                                    "transparent")
        if bgcolor != "transparent":
            x2, y2 = self.x + self.width, self.y + self.height
            rect = DrawRect(self.x, self.y, x2, y2, bgcolor)
            cmds.append(rect)
        # ...
```

我暂时删掉了 pre 元素默认的灰色背景，不过很快就会把它加回来。

在你的浏览器里打开本章的网页版 [4] 测试代码：本章开头那个代码块现在应该有浅蓝色背景了。

这就是网页改变外观的一种方式。而且在 Web 早期，⁹类似的方式是唯一的办法。但老实说，这很折腾——你得给每个元素都设上 style 属性，而一旦要重新设计页面，要改的属性就太多了。CSS 的发明正是为了改进这种状况：

- 一个 CSS 文件可以同时为许多网页设置一致的样式。
- 一行 CSS 可以同时为许多元素设置一致的样式。
- CSS 面向未来，并支持特性各异的浏览器。

为了达到这些目标，CSS 在 style 属性的基础上扩展出两个相关的思想：选择器（selector）与层叠（cascading）。选择器描述一组「属性–值」对适用于哪些 HTML 元素。¹⁰两者的组合称为一条规则（rule），如图 6.1 所示。

```text
main p { font-size: 20px; }
```

（`main p` 是选择器（Selector），`font-size` 是属性（Property），`20px` 是值（Value），花括号内的整体是声明体（Body））

*图 6.1　一条带标注的 CSS 规则。*

让我们为浏览器加上对 CSS 的支持。我们需要把 CSS 文件解析成选择器和「属性–值」对，找出页面上哪些元素与每个选择器匹配，再把这些属性值复制到元素的 style 字段中。

> **深入探索**
>
> 其实，在 CSS 出现之前，人们是用 font [5]、center [6] 这类专门的表现性标签来设置页面样式的（更别说本章已经见过的 <b> 和 <i> 标签了）。这样做实现起来容易，却很难让页面保持一致。<body> 上还有 text、vlink [7] 之类的属性，可以统一设置文字颜色，主要是给链接用的。

## 6.3 选择器

选择器有很多种，但我们的浏览器只支持两种：标签选择器（tag selector，p 选中所有 <p> 元素，ul 选中所有 <ul> 元素）和后代选择器（descendant selector，article div 选中所有拥有 article 祖先的 div 元素）。¹¹

我们为每种选择器写一个类，用来存放选择器的内容，比如标签选择器的标签名：

```python
class TagSelector:
    def __init__(self, tag):
        self.tag = tag
```

每个选择器类还要能测试选择器是否匹配某个元素：

```python
class TagSelector:
    def matches(self, node):
        return isinstance(node, Element) and self.tag == node.tag
```

后代选择器的工作方式与此类似。它由两部分组成，而这两部分本身也是选择器：

```python
class DescendantSelector:
    def __init__(self, ancestor, descendant):
        self.ancestor = ancestor
        self.descendant = descendant
```

然后 matches 方法是递归的：

```python
class DescendantSelector:
    def matches(self, node):
        if not self.descendant.matches(node): return False
        while node.parent:
            if self.ancestor.matches(node.parent): return True
            node = node.parent
        return False
```

现在，要创建这些选择器对象，我们需要一个解析器。在这里，它只是又一个解析函数：¹²

```python
class CSSParser:
    def selector(self):
        out = TagSelector(self.word().casefold())
        self.whitespace()
        while self.i < len(self.s) and self.s[self.i] != "{":
            tag = self.word()
            descendant = TagSelector(tag.casefold())
            out = DescendantSelector(out, descendant)
            self.whitespace()
        return out
```

CSS 文件只是一连串选择器和声明块：

```python
def parse(self):
    rules = []
    while self.i < len(self.s):
        self.whitespace()
        selector = self.selector()
        self.literal("{")
        self.whitespace()
        body = self.body()
        self.literal("}")
        rules.append((selector, body))
    return rules
```

又一次，我们停下来想想错误处理。首先，在解析 CSS 时调用 body，需要让它在遇到右花括号时停下：

```python
def body(self):
    # ...
    while self.i < len(self.s) and self.s[self.i] != "}":
        try:
            # ...
        except Exception:
            why = self.ignore_until([";", "}"])
            if why == ";":
                self.literal(";")
                self.whitespace()
            else:
                break
    # ...
```

其次，解析选择器时也可能出现解析错误。这时，我们想跳过整条规则：

```python
def parse(self):
    # ...
    while self.i < len(self.s):
        try:
            # ...
        except Exception:
            why = self.ignore_until(["}"])
            if why == "}":
                self.literal("}")
                self.whitespace()
            else:
                break
    # ...
```

错误处理很难做得恰到好处，所以一定要像第 4 章测试 HTML 解析器那样测试你的解析器。下面是一些你可能会碰到的问题：

- 如果输出里少了某些规则或属性，多半是一个被错误处理掩盖住的 bug。去掉几个 try 块，看看能否把问题修好。
- 如果你看到多出来的规则或属性，而它们是正确内容被「啃坏」的版本，多半是哪里忘了推进 i。
- 如果遇到死循环，检查错误处理代码是否总会让 i 前进。除 whitespace 外，每个解析函数都应该始终让 i 递增。

你还可以在每个解析函数的开头和结尾¹³加上 print 语句，输出解析函数的名字¹⁴、索引 i，¹⁵以及解析出的数据。输出量会很大，但这是揪出疑难 bug 的万无一失之法。

> **深入探索**
>
> 解析器以任意字节作为输入，因此解析器的 bug 往往容易被恶意者利用。解析器的正确性因而对浏览器安全至关重要，许多 [8] 解析器 [9] bug [10] 已经证明了这一点。如今，浏览器开发者使用模糊测试（fuzzing）[11] 来寻找并修复这类 bug。

## 6.4 应用样式表

解析器调试完毕，下一步就是把解析好的样式表应用到网页上。由于每条 CSS 规则都可能作用于页面上的许多元素，这需要遍历所有元素和所有规则。当某条规则适用时，它的「属性–值」对会被复制到该元素的样式信息中：

```python
def style(node, rules):
    # ...
    for selector, body in rules:
        if not selector.matches(node): continue
        for property, value in body.items():
            node.style[property] = value
    # ...
```

务必把这个循环放在解析 style 属性的那个循环之前：style 属性应当覆盖样式表里的值。

要试一试，我们还需要一份样式表。每个浏览器都自带一份浏览器样式表（browser style sheet），¹⁶其中定义了各种 HTML 元素的默认样式。对我们的浏览器来说，它大概长这样：

```css
pre { background-color: gray; }
```

把它存进一个新文件 browser.css，并让浏览器在启动时读取它：

```python
DEFAULT_STYLE_SHEET = CSSParser(open("browser.css").read()).parse()
```

现在，浏览器加载网页时，就可以应用这份默认样式表，为每个元素建立默认样式：

```python
def load(self, url):
    # ...
    rules = DEFAULT_STYLE_SHEET.copy()
    style(self.nodes, rules)
    # ...
```

浏览器样式表是整个 Web 的默认样式。而各个网站也可以用 CSS 为整个站点设置一致的风格，办法是用 link 元素引用 CSS 文件：

```html
<link rel="stylesheet" href="/main.css">
```

必不可少的 rel 属性表明这个 link 指向一个样式表，¹⁷href 属性则是样式表的 URL。我们需要找出所有这类 link，下载它们的样式表并加以应用，如图 6.2 所示。

```text
浏览器 请求 Page.html → 服务器 返回 Page.html
浏览器解析页面，发现 <link href="main.css" ...> → 浏览器 请求 main.css → 服务器 返回 main.css
```

*图 6.2　浏览器为网页加载相关资源（比如样式表）。*

由于接下来几章还要处理类似的任务，我们不妨稍微泛化一下，编写一个把树转换成节点列表的递归函数：

```python
def tree_to_list(tree, list):
    list.append(tree)
    for child in tree.children:
        tree_to_list(child, list)
    return list
```

我特意让这个辅助函数既能用于 HTML 树也能用于布局树，以备后用。我们可以把 tree_to_list 和 Python 列表推导式结合起来，抓取每个被链接样式表的 URL：¹⁸

```python
def load(self, url):
    # ...
    links = [node.attributes["href"]
            for node in tree_to_list(self.nodes, [])
            if isinstance(node, Element)
            and node.tag == "link"
            and node.attributes.get("rel") == "stylesheet"
            and "href" in node.attributes]
    # ...
```

这些样式表 URL 通常不是完整的 URL；它们是一种叫作相对 URL（relative URL）的东西，可以是：¹⁹

- 普通 URL，指定 scheme、host、path 等；
- 主机相对 URL（host-relative URL），以斜杠开头，但沿用现有的 scheme 和 host；
- 路径相对 URL（path-relative URL），不以斜杠开头，按文件名的方式去解析；
- scheme 相对 URL（scheme-relative URL），以「//」开头、后跟完整的 URL，应使用现有的 scheme。

要下载这些样式表，我们需要把每个相对 URL 转换成完整的 URL：

```python
class URL:
    def resolve(self, url):
        if "://" in url: return URL(url)
        if not url.startswith("/"):
            dir, _ = self.path.rsplit("/", 1)
            url = dir + "/" + url
        if url.startswith("//"):
            return URL(self.scheme + ":" + url)
        else:
            return URL(self.scheme + "://" + self.host + \
                        ":" + str(self.port) + url)
```

此外，由于早期 Web 架构的缘故，浏览器还要负责解析相对 URL 中的父目录（..）：

```python
class URL:
    def resolve(self, url):
        if not url.startswith("/"):
            dir, _ = self.path.rsplit("/", 1)
            while url.startswith("../"):
                _, url = url.split("/", 1)
                if "/" in dir:
                    dir, _ = dir.rsplit("/", 1)
            url = dir + "/" + url
```

现在，浏览器可以请求每个被链接的样式表，并把其中的规则加入 rules 列表：

```python
def load(self, url):
    # ...
    for link in links:
        style_url = url.resolve(link)
        try:
            body = style_url.request()
        except:
            continue
        rules.extend(CSSParser(body).parse())
```

这里的 try/except 会忽略下载失败的样式表，但它也可能掩盖你代码里的 bug，所以如果哪里不对劲，可以试着暂时把它删掉。

> **深入探索**
>
> 每个浏览器引擎都有自己的浏览器样式表（Chromium [13]、WebKit [14]、Gecko [15]）。重置样式表（reset style sheet）[16] 常被用来消除这些差异。这之所以可行，是因为网页样式表的优先级高于浏览器样式表——和我们的浏览器中一样，不过真实浏览器是靠调整优先级 [17] 做到这一点的。²⁰但如果浏览器样式表里有后代选择器，我们就会遇到 bug。

## 6.5 层叠

现在，一个网页可以有任意多份样式表作用其上。既然两条规则可能作用于同一个元素，规则的顺序就很重要：它决定哪些规则优先、何时一条规则覆盖另一条。

在 CSS 中，正确的顺序叫作层叠顺序（cascade order），它基于规则的选择器，并以文件顺序作为决胜依据。这套机制允许更具体的规则覆盖更宽泛的规则，于是浏览器样式表、全站样式表，再加上某个网页专用的样式表，全都可以共存。

由于我们的浏览器只有标签选择器，层叠顺序只需数一数选择器的个数：

```python
class TagSelector:
    def __init__(self, tag):
        # ...
        self.priority = 1
class DescendantSelector:
    def __init__(self, ancestor, descendant):
        # ...
        self.priority = ancestor.priority + descendant.priority
```

于是规则的层叠顺序就只是这些优先级：

```python
def cascade_priority(rule):
    selector, body = rule
    return selector.priority
```

现在调用 style 时，我们需要像这样对规则排序：

```python
def load(self, url):
    # ...
    style(self.nodes, sorted(rules, key=cascade_priority))
    # ...
```

注意，排序之前规则处于文件顺序。Python 的 sorted 函数会保持优先级相同的元素之间的相对顺序，因此文件顺序正好起到了决胜作用，理应如此。

搞定：我们给浏览器加上了 CSS！我是说——背景色的 CSS。不过，网页设计远不止于此。比如，你在改背景色的同时，可能还想改前景色——也就是 CSS 的 color 属性。但这里有个麻烦：color 影响的是文字，而没有办法选中一个文字节点。这怎么能行得通呢？

> **深入探索**
>
> 网页还可以提供备选样式表（alternative style sheet）[18]，有些浏览器提供了（相当冷僻的）方法，可以从默认样式表切换到备选样式表。CSS 标准还允许用户样式（user style）[19]，即为网站设置自定义样式表，其优先级介于 [20] 浏览器样式表与网站提供的样式表之间。

## 6.6 继承样式

在 CSS 中，文字样式的运作方式叫作继承（inheritance）。继承的意思是：如果某个节点没有某个属性的值，就用它父节点的值。文字节点也不例外。有些属性会被继承，有些不会，这取决于具体的属性。背景色不被继承，但文字颜色和其他字体属性会。

让我们为四个字体属性实现继承：font-size、font-style（用于斜体）、font-weight（用于粗体）和 color：

```python
INHERITED_PROPERTIES = {
    "font-size": "16px",
    "font-style": "normal",
    "font-weight": "normal",
    "color": "black",
}
```

字典中的值是各属性的默认值。接下来我们把真正的继承逻辑加进 style 函数。它必须放在其他循环之前，因为显式规则应当覆盖继承值：

```python
def style(node, rules):
    # ...
    for property, default_value in INHERITED_PROPERTIES.items():
        if node.parent:
            node.style[property] = node.parent.style[property]
        else:
            node.style[property] = default_value
    # ...
```

继承字体大小还带点小波折。网页可以用百分比作为字体大小：h1 { font-size: 150% } 会让标题比周围文字大 50%。可要是 h1 标签里又套了个 code 元素呢——它会继承那个 150% 的 font-size 吗？总不该比标题里的其他文字再大 50% 吧？实际上，浏览器会在这些值被继承之前，把百分比形式的字体大小解析成绝对的像素单位；这叫作「计算样式」（computed style）。²¹

```python
def style(node, rules):
    # ...
    if node.style["font-size"].endswith("%"):
        # ...
    for child in node.children:
        style(child, rules)
```

解析百分比大小只有一个棘手的边界情况：根元素 html 的百分比大小。此时，百分比相对于默认字体大小：²²

```python
def style(node, rules):
    # ...
    if node.style["font-size"].endswith("%"):
        if node.parent:
            parent_font_size = node.parent.style["font-size"]
        else:
            parent_font_size = INHERITED_PROPERTIES["font-size"]
        node_pct = float(node.style["font-size"][:-1]) / 100
        parent_px = float(parent_font_size[:-2])
        node.style["font-size"] = str(node_pct * parent_px) + "px"
```

注意，这一步发生在各种来源的样式值都处理完之后（所以我们用的是最终的 font-size 值），但又发生在递归之前（这样任何子节点都可以假定它父节点的 font-size 已经被解析成了像素值）。

> **深入探索**
>
> 给页面计算样式可能很慢，所以真实浏览器会施展各种技巧：为后代选择器使用布隆过滤器（bloom filter）[22]，为简单选择器建立索引 [23]，以及各种形式的共享 [24] 和并行化 [25]。某些形式的共享对减少内存占用也很重要——计算样式可能非常庞大！

```python
class BlockLayout:
    def recurse(self, node):
        if isinstance(node, Text):
            for word in node.text.split():
                self.word(node, word)
        else:
            if node.tag == "br":
                self.flush()
            for child in node.children:
                self.recurse(child)
```

> **深入探索**

## 6.8 小结

本章实现了一个初级但完整的样式引擎，涵盖 CSS 文件的下载、解析、匹配、排序和应用。也就是说，我们：

- 编写了一个 CSS 解析器；
- 同时支持了 style 属性和被链接的 CSS 文件；

## 6.10 练习

**6.1　字体。** 实现 font-family 属性。它是一个可继承的属性，用来指明元素中应使用哪种字体。让 <code> 元素内的文字使用像 Courier 这样好看的等宽字体。当心字体缓存。

**6.2　宽度/高度。** 为块级布局加上对 width 和 height 属性的支持。它们的值可以是像素值，直接设置布局对象的宽度或高度；也可以是单词 auto，此时沿用现有的布局算法。

**6.3　类选择器。** 任何 HTML 元素都可以有 class 属性，其值是该元素的类名列表，以空格分隔。CSS 的类选择器（class selector），比如 .main，作用于所有带 main 类的元素。实现类选择器；它们的优先级应当高于标签选择器。如果实现得正确，你应该能看到本书代码块的语法高亮。

**6.4　display。** 目前，layout_mode 函数依赖一份硬编码的块级元素列表。在真实浏览器中，这件事由 display 属性控制。实现默认值为 inline 的 display 属性，并把块级元素列表搬进浏览器样式表。

**6.5　简写属性。** CSS 的「简写属性」（shorthand property）可以同时设置多个相关的 CSS 属性；例如 font: italic bold 100% Times 一次性设置了 font-style、font-weight、font-size 和 font-family 属性。为你的解析器添加简写属性支持。（如果你没有实现 font-family（练习 6.1），忽略那一部分即可。）

**6.6　内联样式表。** <link rel=stylesheet> 语法允许导入外部样式表（即通过单独的 HTTP 请求加载的样式表）。还有一种以内联方式提供样式表的办法：借助 <style> 标签把它作为 HTML 的一部分——直到下一个 </style> 标签之前的所有内容都会被当作样式表来解释。²⁶内联样式表适合制作自包含的示例网页，但更重要的是，它能减少到服务器的往返网络请求数量，让网站加载更快。由于样式表通常不含左尖括号，你无需修改 HTML 解析器就能实现这个特性。

**6.7　快速后代选择器。** 目前，匹配 div div div div div 这样的选择器可能很耗时——最坏情况下是 O(nd)，其中 n 是选择器的长度，d 是布局树的深度。修改后代选择器的匹配代码，使其在 O(n + d) 时间内完成。让 DescendantSelector 存放一个基础选择器的列表，而不是只放两个选择器，或许会有帮助。

**6.8　选择器序列。** 有时你想同时按标签和类来选中元素。做法是把选择器直接连写，中间什么都不加。²⁷例如 span.announce 选中同时匹配 span 和 .announce 的元素。实现一个新的 SelectorSequence 类来表示它们，并修改解析器来解析它们。优先级取各选择器之和。²⁸

**6.9　!important。** CSS 的「属性–值」对可以用 !important 语法标记为「重要的」，像这样：

```css
#banner a { color: black !important; }
```

这会给该「属性–值」对（但不包括同一声明块里的其他属性对！）高于其他任何选择器的优先级（其他 !important 属性除外）。解析并实现 !important，让以这种方式标记的「属性–值」对的优先级比普通「属性–值」对高 10 000。

**6.10　:has 选择器。** :has 选择器 [29] 是后代选择器的逆运算——它根据是否存在某个后代来为祖先设置样式。实现 :has 选择器，并分析你的实现的渐近复杂度。有一种每元素均摊 O(1) 的巧妙实现——你能找到它吗？²⁹

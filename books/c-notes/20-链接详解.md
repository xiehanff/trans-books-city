# 第20章 链接详解

链接是将编译生成的目标文件组合成可执行文件的过程。理解链接有助于解决编译错误、组织大型项目。

## 编译过程

从源代码到可执行文件经历四个阶段：

```
源代码(.c) -> 预处理 -> 编译 -> 汇编 -> 链接 -> 可执行文件
            (.i)      (.s)   (.o)          (无后缀/.exe)
```

### 预处理

处理 `#include`、`#define`、条件编译等预处理指令。

```bash
gcc -E hello.c -o hello.i
```

预处理后的文件包含展开后的宏和插入的头文件内容。

### 编译

将预处理后的代码转换为汇编代码。

```bash
gcc -S hello.i -o hello.s
# 或直接从 .c 文件
gcc -S hello.c -o hello.s
```

### 汇编

将汇编代码转换为机器码，生成目标文件。

```bash
gcc -c hello.s -o hello.o
# 或直接从 .c 文件
gcc -c hello.c -o hello.o
```

目标文件包含机器指令，但地址尚未最终确定。

### 链接

将目标文件和库文件组合，确定最终地址，生成可执行文件。

```bash
gcc hello.o -o hello
# 或直接从 .c 文件一步完成
gcc hello.c -o hello
```

## 目标文件格式

### ELF 格式

Linux 使用 ELF（Executable and Linkable Format）格式，包含以下部分：

```
+------------------+
|    ELF Header    |  文件类型、架构、入口点等
+------------------+
| Section Headers  |  各节的描述信息
+------------------+
|     .text        |  代码段
+------------------+
|     .rodata      |  只读数据
+------------------+
|     .data        |  已初始化的全局/静态变量
+------------------+
|     .bss         |  未初始化的全局/静态变量
+------------------+
|    .symtab       |  符号表
+------------------+
|    .strtab       |  字符串表
+------------------+
|    .rel.text     |  代码段重定位信息
+------------------+
|    .rel.data     |  数据段重定位信息
+------------------+
```

### 查看目标文件

```bash
# 查看文件头
readelf -h hello.o

# 查看节表
readelf -S hello.o

# 查看符号表
readelf -s hello.o
nm hello.o

# 查看反汇编
objdump -d hello.o

# 查看所有内容
readelf -a hello.o
```

### .text、.data、.bss

```c
int global_init = 100;     // .data 节
int global_uninit;         // .bss 节

const int const_val = 200; // .rodata 节

void func() {              // .text 节
    static int s_init = 1; // .data 节
    static int s_uninit;   // .bss 节
    int local = 0;         // 栈上，不在目标文件中
}
```

`.bss` 节不占用文件空间，只记录大小，程序加载时由操作系统初始化为零。

## 符号解析

### 符号类型

- **全局符号**：本模块定义、可被其他模块引用的符号（非 static 的全局变量和函数）
- **外部符号**：其他模块定义的全局符号
- **本地符号**：本模块定义、只能本模块引用的符号（static 全局变量和函数）

```c
// global.c
int global_var;           // 全局符号
static int static_var;    // 本地符号

void global_func() {}     // 全局符号
static void static_func() {}  // 本地符号
```

### 符号表

```bash
$ nm global.o
0000000000000000 T global_func
0000000000000000 C global_var
0000000000000000 t static_func
0000000000000004 b static_var
```

符号类型说明：
- `T/t`：代码段（.text），大写表示全局，小写表示本地
- `D/d`：数据段（.data）
- `B/b`：BSS 段（.bss）
- `U`：未定义（需要外部链接）
- `C`：未初始化的全局符号

### 链接时的符号解析

链接器收集所有目标文件的符号定义，解析每个未定义的符号引用。

```c
// a.c
extern int external_var;  // 未定义符号，需要从其他模块获取
int main() {
    return external_var;
}
```

```c
// b.c
int external_var = 42;    // 定义符号
```

```bash
gcc -c a.c -o a.o
gcc -c b.c -o b.o
gcc a.o b.o -o program
```

如果找不到符号定义，链接器报错：

```
undefined reference to `external_var'
```

### 符号冲突

多个目标文件定义同名全局符号会导致多重定义错误：

```
multiple definition of `global_var'
```

建议：全局变量使用 `static` 限制作用域，或使用命名前缀避免冲突。

## 重定位

### 什么是重定位

编译时无法确定全局变量和函数的最终地址，需要链接器重定位。

目标文件中使用临时地址（通常是 0），并在重定位表中记录需要修改的位置。

### 重定位过程

```c
// main.c
extern int external_var;

int main() {
    return external_var;
}
```

编译后 `main.o` 中：

```asm
main:
    mov eax, [0]      ; 临时地址 0，需要重定位
    ret
```

重定位表记录：偏移 3 处需要填充 `external_var` 的最终地址。

链接时，链接器确定 `external_var` 的地址（如 `0x4010`），修改指令：

```asm
main:
    mov eax, [0x4010] ; 重定位后的地址
    ret
```

### 查看重定位信息

```bash
$ readelf -r main.o

Relocation section '.rel.text' at offset 0x200 contains 1 entries:
  Offset    Info  Type          Symbol Value
  00000003  0009  R_X86_64_32   external_var   0
```

## 静态链接与动态链接

### 静态链接

将库代码直接复制到可执行文件中。

```bash
# 创建静态库
gcc -c lib.c -o lib.o
ar rcs libmylib.a lib.o

# 使用静态库
gcc main.c -L. -lmylib -o program
# 或直接指定文件
gcc main.c libmylib.a -o program
```

优点：
- 可执行文件独立，不依赖外部库
- 加载时无需额外工作

缺点：
- 文件体积大
- 库更新需要重新编译

### 动态链接

程序运行时加载共享库。

```bash
# 创建动态库
gcc -shared -fPIC lib.c -o libmylib.so

# 使用动态库
gcc main.c -L. -lmylib -o program

# 运行时需要设置库路径
export LD_LIBRARY_PATH=.:$LD_LIBRARY_PATH
./program
```

`-fPIC` 生成位置无关代码（Position Independent Code），使代码可在任意地址加载运行。

优点：
- 文件体积小
- 多个程序可共享同一份库内存
- 库更新无需重新编译程序

缺点：
- 加载时有额外开销
- 依赖外部库文件

### 动态链接过程

1. 程序加载时，动态链接器（ld-linux.so）被加载
2. 动态链接器查找程序需要的共享库
3. 将共享库映射到进程地址空间
4. 解析符号引用，填充 GOT（全局偏移表）和 PLT（过程链接表）

### 查看动态库依赖

```bash
$ ldd program
linux-vdso.so.1 =>  (0x00007ffd1234)
libc.so.6 => /lib/x86_64-linux-gnu/libc.so.6 (0x00007f123456)
/lib64/ld-linux-x86-64.so.2 (0x00007f654321)
```

## 库文件

### 静态库（.a / .lib）

静态库是多个目标文件的归档文件。

```bash
# 创建静态库
ar rcs libfoo.a foo1.o foo2.o foo3.o

# 查看静态库内容
ar -t libfoo.a

# 提取目标文件
ar -x libfoo.a
```

### 动态库（.so / .dll）

```bash
# 创建动态库
gcc -shared -fPIC -o libfoo.so foo1.c foo2.c

# 查看动态库符号
nm -D libfoo.so
readelf -s libfoo.so

# 查看动态库信息
readelf -d libfoo.so
```

### 库的搜索顺序

链接时搜索库的路径顺序：

1. `-L` 指定的路径（从左到右）
2. 环境变量 `LIBRARY_PATH` 指定的路径
3. 默认路径（如 `/usr/lib`、`/usr/local/lib`）

运行时搜索动态库的路径顺序：

1. RPATH（编译时嵌入路径）
2. 环境变量 `LD_LIBRARY_PATH`
3. RUNPATH
4. `/etc/ld.so.cache`
5. 默认路径（`/lib`、`/usr/lib` 等）

```bash
# 设置 RPATH
gcc main.c -L. -lfoo -Wl,-rpath,/path/to/lib -o program
```

### 库的版本

动态库有版本号：`libfoo.so.1.2.3`

- 1：主版本号，不兼容的 API 变化
- 2：次版本号，向后兼容的功能增加
- 3：补丁版本号，bug 修复

```bash
# 创建带版本的库
gcc -shared -Wl,-soname,libfoo.so.1 -o libfoo.so.1.2.3 foo.c

# 创建符号链接
ln -s libfoo.so.1.2.3 libfoo.so.1
ln -s libfoo.so.1 libfoo.so
```

## 链接错误排查

### 未定义引用

```
undefined reference to `func'
```

原因：
- 忘记链接库或目标文件
- 库的链接顺序错误（依赖者在前，被依赖者在后）
- 函数声明与定义不匹配

```bash
# 正确顺序：main.o 依赖 libfoo.a
gcc main.o -L. -lfoo -o program  # 正确
gcc -L. -lfoo main.o -o program  # 可能错误
```

### 多重定义

```
multiple definition of `var'
```

原因：
- 多个源文件定义了同名全局变量
- 头文件中定义了非 static 变量或非 inline 函数

解决方案：
- 使用 `static` 限制作用域
- 头文件中只声明，在一个源文件中定义
- 使用 `extern` 声明外部变量

```c
// header.h
extern int global_var;  // 声明

// source.c
int global_var = 0;     // 定义
```

### 找不到库

```
cannot find -lfoo
```

解决方案：
- 检查库文件是否存在
- 使用 `-L` 指定库路径
- 检查库文件名是否正确

### 运行时找不到库

```
error while loading shared libraries: libfoo.so: cannot open shared object file
```

解决方案：
- 设置 `LD_LIBRARY_PATH`
- 编译时设置 `-Wl,-rpath`
- 将库安装到系统目录

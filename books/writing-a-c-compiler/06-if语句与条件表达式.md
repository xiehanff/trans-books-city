# 第 6 章　if 语句与条件表达式

*Chapter 6: If Statements and Conditional Expressions*

上一章你学习了如何编译顺序执行一列语句的程序。但大多数 C 程序的执行路径要更复杂：它们常常需要根据程序当前的状态，在运行时决定执行哪些语句。程序执行语句的顺序称为它的控制流（control flow），而允许你改变程序控制流的语言构造则称为控制结构（control structure）。

本章你将实现你的第一个控制结构：if 语句。你还将实现条件表达式（conditional expression）。与 if 语句一样，条件表达式让你能控制运行哪段代码。例如，条件表达式 `(a == 0) ? 3 : 4` 在 a 等于 0 时求值为 3，否则求值为 4。在第 4 章实现短路的 && 和 || 运算符时，我们已经为 if 语句和条件表达式打下了大量基础。我们已经拥有能让我们有条件地执行或跳过代码的 TACKY 构造，因此 TACKY 生成之后的各个阶段都无需改动。让我们开始吧！

## 词法分析器

本章将添加四个词法单元（token）：

- `if`：一个关键字，标志 if 语句的开始
- `else`：一个关键字，标志 if 语句中 else 子句的开始
- `?`：一个问号，条件表达式中第一个与第二个操作数之间的分隔符
- `:`：一个冒号，条件表达式中第二个与第三个操作数之间的分隔符

一旦你的词法分析器支持了这四个词法单元，就可以对它进行测试。

## 解析器

现在我们将更新解析器以支持 if 语句和条件表达式。由于这是两个不同的语言构造，我们将逐一处理，先从 if 语句开始。

### 解析 if 语句

我们首先扩展 statement AST 节点以支持 if 语句。清单 6-1 给出了该节点更新后的定义。

```text
statement = Return(exp)
          | Expression(exp)
          | If(exp condition, statement then, statement? else)
          | Null
```

*清单 6-1：statement AST 节点的定义，包含 if 语句*

新的 If 构造器接受三个参数。条件表达式（condition），有时称为控制表达式（controlling expression），决定该语句的语句体是否执行。then 语句是 if 语句的第一个子句，在 condition 的结果非零时执行。第二个子句 else 语句是可选的。如果它存在，则在 condition 的结果为 0 时执行。

正如我在上一章提到的，if 语句中的每个子句本身都是单个语句。虽然看起来像多条语句，但清单 6-2 中这种 if 语句的语句体实际上是一个单独的复合语句（compound statement）。

```c
if (a == 3) {
    a = a + 1;
    int b = a * 4;
    return a && b;
}
```

*清单 6-2：语句体为复合语句的 if 语句*

我们还没有实现复合语句，所以目前还无法编译清单 6-2 这样的代码。清单 6-3 给出了一个我们可以编译的 if 语句示例。

```c
if (a == 3)
    return a;
else
    b = 8;
```

*清单 6-3：不含任何复合语句的 if 语句*

我们也可以编译嵌套在其他 if 语句中的 if 语句，如清单 6-4。

```c
if (a)
    if (a > 10)
        return a;
    else
        return 10 - a;
```

*清单 6-4：嵌套在另一个 if 语句中的 if 语句*

注意，清单 6-1 中的 AST 定义没有 else if 构造，因为一个 if 语句最多只能有一个 else 子句。else if 子句其实只是一个包含了另一个 if 语句的 else 子句。以清单 6-5 为例。

```c
if (a > 100)
    return 0;
else if (a > 50)
    return 1;
else
    return 2;
```

*清单 6-5：嵌套在 else 子句中的 if 语句*

让我们按照更贴近其解析方式的形式重新排版这段代码：

```c
if (a > 100)
    return 0;
else
    if (a > 50)
        return 1;
    else
        return 2;
```

清单 6-5 的 AST 将如下所示：

```text
If(
    condition=Binary(GreaterThan, Var("a"), Constant(100)),
    then=Return(Constant(0)),
    else=If(
        condition=Binary(GreaterThan, Var("a"), Constant(50)),
        then=Return(Constant(1)),
        else=Return(Constant(2))
    )
)
```

清单 6-6 展示了对文法（grammar）的修改，它们与 AST 的修改完全对应。

```text
<statement> ::= "return" <exp> ";"
              | <exp> ";"
              | "if" "(" <exp> ")" <statement> ["else" <statement>]
              | ";"
```

*清单 6-6：语句的文法规则，包含 if 语句*

我们可以用简单的递归下降解析来处理这条新产生式规则。有意思的是，这条规则是有二义性的，但这种二义性不会给我们的解析器带来任何问题。让我们再看看清单 6-4：

```c
if (a)
    if (a > 10)
        return a;
    else
        return 10 - a;
```

有两种解析这段代码的方式都符合我们的新文法规则：我们可以把 else 子句与第一个或第二个 if 语句分组。换句话说，我们可以像这样解析这段代码：

```c
if (a) {
    if (a > 10)
        return a;
    else
        return 10 - a;
}
```

或者像这样解析：

```c
if (a) {
    if (a > 10)
        return a;
}
else
    return 10 - a;
```

C 标准明确指出这两种选择中的第一种是正确的：else 子句总是应当与离它最近的 if 语句分组。然而，文法本身并没有告诉我们在这些选项中该选哪一个。文法的这一特性称为悬空 else 二义性（dangling else ambiguity），它会给自动把形式文法转换为解析代码的解析器生成器（parser generator）带来问题。

幸运的是，悬空 else 二义性对我们这类手写的递归下降解析器来说不是问题。每当我们解析一个 if 语句时，都会在语句体之后立即寻找 else 关键字；如果找到了，就直接解析 else 子句。在清单 6-4 这样的情形中，这意味着我们最终会把 else 子句解析为内层 if 语句的一部分，而这正是正确的行为。

现在就动手实现这条产生式规则吧；之后我们继续讨论条件表达式。

### 解析条件表达式

条件运算符 ? : 是一个三元运算符（ternary operator），接受三个操作数。在清单 6-7 中，我们把它添加到 exp AST 节点。

```text
exp = Constant(int)
    | Var(identifier)
    | Unary(unary_operator, exp)
    | Binary(binary_operator, exp, exp)
    | Assignment(exp, exp)
    | Conditional(exp condition, exp, exp)
```

*清单 6-7：exp AST 节点的定义，包含条件表达式*

在清单 6-8 中，我们把它添加到 `<exp>` 文法规则。

```text
<exp> ::= <factor> | <exp> <binop> <exp> | <exp> "?" <exp> ":" <exp>
```

*清单 6-8：表达式的文法规则，包含条件表达式*

接下来需要确定它的优先级和结合性。三元表达式的优先级和结合性如何运作并不那么直观。诀窍是把它看成一个二元表达式，只不过中间的运算符是 `? <exp> :`。这个"运算符"很容易解析，因为它由 ? 和 : 词法单元分隔；它只是恰好包含了一整个子表达式。（只在解析阶段这样理解，不要在后续阶段也这样想。我们可以像解析二元表达式一样解析它，但求值方式完全不同！）这样我们就能定义条件运算符相对于其他二元运算符的优先级：它高于赋值，低于其他所有运算符。例如，表达式

```c
a = 1 ? 2 : 3
```

会被解析为

```c
a = (1 ? 2 : 3)
```

但

```c
a || b ? 2 : 3
```

会被解析为：

```c
(a || b) ? 2 : 3
```

同样的逻辑也适用于第三个操作数。我们把

```c
1 ? 2 : 3 || 4
```

解析为

```c
1 ? 2 : (3 || 4)
```

但把

```c
1 ? 2 : a = 5
```

解析为：

```c
(1 ? 2 : a) = 5
```

语义分析遍会拒绝最后这个表达式，因为 `1 ? 2 : a` 不是合法的左值（lvalue）。不过，任何表达式都可以出现在 ? 和 : 词法单元之间，甚至是赋值表达式。这两个词法单元就像括号一样，界定了表达式的起止位置。因此，条件表达式

```c
x ? x = 1 : 2
```

等价于：

```c
x ? (x = 1) : 2
```

把一个条件表达式嵌套到另一个条件表达式中时，同样的逻辑依然适用，也就是说

```c
a ? b ? 1 : 2 : 3
```

会被解析为：

```c
a ? (b ? 1 : 2) : 3
```

接下来看结合性。条件运算符是右结合的，所以

```c
a ? 1 : b ? 2 : 3
```

会被解析为：

```c
a ? 1 : (b ? 2 : 3)
```

既然条件表达式可以像古怪的二元表达式那样解析，我们（几乎）可以用现有的优先级爬升（precedence climbing）代码来处理它们。首先，把 ? 加入优先级表；表 6-1 列出了我们所有的优先级值。

*表 6-1：二元与三元运算符的优先级值*

| 运算符 | 优先级 |
| --- | --- |
| * | 50 |
| / | 50 |
| % | 50 |
| + | 45 |
| - | 45 |
| < | 35 |
| <= | 35 |
| > | 35 |
| >= | 35 |
| == | 30 |
| != | 30 |
| && | 10 |
| \|\| | 5 |
| ? | 3 |
| = | 1 |

在优先级爬升过程中，我们只查看 `? <exp> :` 这个"运算符"的第一个词法单元，所以 ? 进表而 : 不进。

接下来，我们再次更新优先级爬升代码。在上一章中，我们把赋值作为特殊情况处理，以便为它使用 Assignment AST 节点。现在我们把条件表达式也作为特殊情况处理。清单 6-9 给出了更新后的优先级爬升伪代码。与清单 5-8 中该算法的上一版本相比的变化以粗体标出。

```text
parse_exp(tokens, min_prec):
    left = parse_factor(tokens)
    next_token = peek(tokens)
    while next_token is a binary operator and precedence(next_token) >= min_prec:
        if next_token is "=":
            take_token(tokens) // 从词法单元列表中移除 "="
            right = parse_exp(tokens, precedence(next_token))
            left = Assignment(left, right)
        else if next_token is "?":
            middle = parse_conditional_middle(tokens)
            right = parse_exp(tokens, precedence(next_token))
            left = Conditional(left, middle, right)
        else:
            operator = parse_binop(tokens)
            right = parse_exp(tokens, precedence(next_token) + 1)
            left = Binary(operator, left, right)
        next_token = peek(tokens)
    return left
```

*清单 6-9：支持条件表达式的优先级爬升*

parse_conditional_middle 函数（我在这里没有给出它的代码）只需消耗 ? 词法单元，然后解析一个表达式（最小优先级重置为 0），再消耗 : 词法单元。接着，我们用解析其他任何表达式右部相同的方式来解析第三个操作数：递归调用 parse_exp。由于条件运算符与赋值一样是右结合的，我们把递归调用中的最小优先级设为 precedence(next_token)，而不是 precedence(next_token) + 1。最后，我们用三个操作数构造出 Conditional AST 节点。

清单 6-10 给出了完整的 AST 定义，支持 if 语句和条件表达式的修改以粗体标出。这些就是本节前面引入的那些修改；我把它们汇总在这里以便查阅。

```text
program = Program(function_definition)
function_definition = Function(identifier name, block_item* body)
block_item = S(statement) | D(declaration)
declaration = Declaration(identifier name, exp? init)
statement = Return(exp)
          | Expression(exp)
          | If(exp condition, statement then, statement? else)
          | Null
exp = Constant(int)
    | Var(identifier)
    | Unary(unary_operator, exp)
    | Binary(binary_operator, exp, exp)
    | Assignment(exp, exp)
    | Conditional(exp condition, exp, exp)
unary_operator = Complement | Negate | Not
binary_operator = Add | Subtract | Multiply | Divide | Remainder | And | Or
                | Equal | NotEqual | LessThan | LessOrEqual
                | GreaterThan | GreaterOrEqual
```

*清单 6-10：包含条件表达式与 if 语句的抽象语法树*

清单 6-11 展示了文法的相应修改。

```text
<program> ::= <function>
<function> ::= "int" <identifier> "(" "void" ")" "{" {<block-item>} "}"
<block-item> ::= <statement> | <declaration>
<declaration> ::= "int" <identifier> ["=" <exp>] ";"
<statement> ::= "return" <exp> ";"
              | <exp> ";"
              | "if" "(" <exp> ")" <statement> ["else" <statement>]
              | ";"
<exp> ::= <factor> | <exp> <binop> <exp> | <exp> "?" <exp> ":" <exp>
<factor> ::= <int> | <identifier> | <unop> <factor> | "(" <exp> ")"
<unop> ::= "-" | "~" | "!"
<binop> ::= "-" | "+" | "*" | "/" | "%" | "&&" | "||"
          | "==" | "!=" | "<" | "<=" | ">" | ">=" | "="
<identifier> ::= ? 一个标识符词法单元 ?
<int> ::= ? 一个常量词法单元 ?
```

## TACKY 生成

我们可以用现有的 TACKY 指令实现 if 语句和条件表达式。这里采用与第 4 章短路 && 和 || 运算符相同的基本思路：先求值控制表达式，再用条件跳转跳到语句或表达式的相应子句。让我们先实现 if 语句。

### 将 if 语句转换为 TACKY

形如 `if (<condition>) then <statement>` 的语句应当翻译为清单 6-12 中的 TACKY。

```text
<condition 的指令>
c = <condition 的结果>
JumpIfZero(c, end)
<statement 的指令>
Label(end)
```

*清单 6-12：if 语句的 TACKY*

就是这样！首先，我们求值控制表达式 `<condition>`。如果结果为 0，就跳到整个 if 语句的末尾；否则，执行 `<statement>` 的指令。如果语句还带有 else 子句，生成的 TACKY 也只是稍微复杂一点点。语句 `if (<condition>) then <statement1> else <statement2>` 翻译为清单 6-13 中的 TACKY。

```text
<condition 的指令>
c = <condition 的结果>
JumpIfZero(c, else_label)
<statement1 的指令>
Jump(end)
Label(else_label)
<statement2 的指令>
Label(end)
```

*清单 6-13：带 else 子句的 if 语句的 TACKY*

与清单 6-12 一样，我们先求值控制表达式，然后在结果为 0 时执行条件跳转。但这次不是跳到 if 语句的末尾，而是跳到 else_label，然后执行 `<statement2>`。如果控制表达式求值为非零值，我们执行 `<statement1>`，然后跳到整条语句的末尾。条件表达式可以用类似的方式处理；接下来就看看它们。

### 将条件表达式转换为 TACKY

对条件表达式来说，与短路表达式一样，C 标准对哪些子表达式会执行、何时执行提供了保证。要求值表达式 `<condition> ? <clause1> : <clause2>`，必须先求值 `<condition>`，然后根据 `<condition>` 的结果求值 `<clause1>` 或 `<clause2>` 之一。例如，你不能先对两个子句都求值，再求值 `<condition>` 来决定采用哪个结果，因为那样可能产生意想不到的副作用。结论就是：我们将以与 if 语句非常相似的方式处理条件表达式。唯一的区别是，表达式与语句不同，它会产生一个结果，需要存入正确的目的位置。表达式 `<condition> ? <e1> : <e2>` 将生成清单 6-14 中的 TACKY。

```text
<condition 的指令>
c = <condition 的结果>
JumpIfZero(c, e2_label)
<计算 e1 的指令>
v1 = <e1 的结果>
result = v1
Jump(end)
Label(e2_label)
<计算 e2 的指令>
v2 = <e2 的结果>
result = v2
Label(end)
```

*清单 6-14：条件表达式的 TACKY*

它与清单 6-13 中的 TACKY 几乎一模一样。唯一的区别是，每个子句结尾都要把结果复制进临时变量 result。

与往常一样，处理 if 语句和条件表达式时生成的所有标签和临时变量名都应当唯一。一旦 TACKY 生成阶段可以工作，你就能编译本章的测试用例了。

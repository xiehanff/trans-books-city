# 第 11 章　添加视觉效果

*Chapter 11: Adding Visual Effects*

目前我们的浏览器只能画出彩色的矩形和文本——相当无聊！真实浏览器支持各种各样的视觉效果，它们改变像素和颜色混合在一起的方式。为了实现这些效果，同时也为了让浏览器更快，我们需要对表面（surface）的控制权——它是快速滚动、视觉效果、动画以及许多其他浏览器能力背后关键的底层特性。为了获得这种控制权，我们还将改用 Skia 图形库，甚至窥探一下它的内部机制。

## 11.1 安装 Skia 与 SDL

Tkinter 擅长绘制基本图形和处理输入，但它既不能让我们控制表面¹，也缺乏大多数视觉效果的实现。自己实现这些效果会很有趣，但这超出了本书的范围，所以我们需要一个新的图形库。让我们使用 Skia [1]，也就是 Chromium 所用的那个库。与 Tkinter 不同，Skia 不处理输入，也不创建图形窗口，所以我们将把它与 SDL [2] GUI 库搭配使用。除了带来新能力之外，改用 Skia 还能让我们在更低的层面上控制图形和光栅化（rasterization）。

### 安装

首先安装 Skia [3] 和 SDL [4]：

```text
python3 -m pip install skia-python==87 pysdl2 pysdl2-dll
```

与本书其他地方一样，你可能需要先安装 pip 包，或者使用 IDE 的包安装器。如果你用的是 Linux，还需要安装额外的依赖，比如 OpenGL 和 fontconfig。此外，你可能装不了 pysdl2-dll；这种情况下，你需要改在系统包管理器中查找 SDL。更多细节请查阅 skia-python 和 pysdl2 的网页。

注意，我显式指定安装的是 Skia 的 87 版。Skia 会定期发布更改 API 或破坏兼容性的版本；87 版相当老，在大多数系统上应该都能可靠工作。在你自己的项目中，或者在给 Skia 提交缺陷报告之前，请务必使用更新的 Skia 版本。未来版本的 Python 也可能不再支持 Skia 87；我们的移植说明 [5] 解释了如何在本书代码中使用较新的 Skia 版本。

ctypes 模块是 Python 的标准组成部分；我们将用它来在 Python 类型和 C 类型之间转换。如果这些导入有任何失败，请检查 Skia 和 SDL 是否正确安装了。

## 11.2 SDL 创建窗口

第一项大工程是改用 SDL 来创建窗口并处理事件。浏览器的主循环首先需要一些样板代码来启动 SDL：

```python
if __name__ == "__main__":
    sdl2.SDL_Init(sdl2.SDL_INIT_EVENTS)
    browser = Browser()
    browser.new_tab(URL(sys.argv[1]))
    # ...
```

接下来，我们要在 Browser 里创建一个 SDL 窗口，取代 Tkinter 窗口。SDL 的咒语如下：

```python
class Browser:
    def __init__(self):
        self.sdl_window = sdl2.SDL_CreateWindow(b"Browser",
            sdl2.SDL_WINDOWPOS_CENTERED, sdl2.SDL_WINDOWPOS_CENTERED,
            WIDTH, HEIGHT, sdl2.SDL_WINDOW_SHOWN)
```

窗口创建好了，我们还需要处理发送给窗口的事件。SDL 没有 mainloop 或 bind 方法；我们必须自己实现：

```python
def mainloop(browser):
    event = sdl2.SDL_Event()
    while True:
        while sdl2.SDL_PollEvent(ctypes.byref(event)) != 0:
            if event.type == sdl2.SDL_QUIT:
                browser.handle_quit()
                sdl2.SDL_Quit()
                sys.exit()
            # ...
```

ctypes 和 PollEvent 的细节在这里并不太重要，但要注意 SDL_QUIT 是一个事件，在用户关闭最后一个打开的窗口时发送。它所调用的 handle_quit 方法只是清理窗口对象：

```python
class Browser:
    def handle_quit(self):
        sdl2.SDL_DestroyWindow(self.sdl_window)
```

用 mainloop 取代 tkinter.mainloop：

```python
if __name__ == "__main__":
    # ...
    mainloop(browser)
```

至于 Browser 构造函数里所有的 bind 调用，我们可以为各种类型的事件（比如点击、键入等）直接调用相应的方法。SDL 的写法如下：

```python
def mainloop(browser):
    while True:
        while sdl2.SDL_PollEvent(ctypes.byref(event)) != 0:
            # ...
            elif event.type == sdl2.SDL_MOUSEBUTTONUP:
                browser.handle_click(event.button)
            elif event.type == sdl2.SDL_KEYDOWN:
                if event.key.keysym.sym == sdl2.SDLK_RETURN:
                    browser.handle_enter()
                elif event.key.keysym.sym == sdl2.SDLK_DOWN:
                    browser.handle_down()
            elif event.type == sdl2.SDL_TEXTINPUT:
                browser.handle_key(event.text.text.decode('utf8'))
```

我修改了各个事件处理方法的签名。例如，handle_click 方法现在接收一个 MouseButtonEvent 对象（所幸它包含 x 和 y 坐标），而 handle_enter 和 handle_down 方法则完全不接收参数，反正我们也不用那个参数。你需要相应地修改 Browser 中这些方法的签名。

## 11.3 表面与像素

让我们窥探一下这些 SDL 调用的内部。当我们创建 SDL 窗口时，就是在请求 SDL 分配一个表面（surface），即一块表示屏幕上像素的内存。² 创建和管理表面将是本章的重点。在如今的大屏幕上，表面会占用大量内存，因此妥善处理表面对浏览器性能至关重要。

表面是一个图形缓冲区（graphics buffer）的表示，你可以向其中绘制像素（表示颜色的位）。创建 SDL 窗口时，我们已经隐式地创建了一个 SDL 表面；接下来再为 Skia 创建一个用于绘制的表面：

```python
class Browser:
    def __init__(self):
        self.root_surface = skia.Surface.MakeRaster(
            skia.ImageInfo.Make(
                WIDTH, HEIGHT,
                ct=skia.kRGBA_8888_ColorType,
                at=skia.kUnpremul_AlphaType))
```

每个像素都有颜色。注意 ct 参数，意思是「颜色类型」，它指明这个表面的每个像素都应表示为红、绿、蓝和 alpha 值，每个值占 8 个比特。换句话说，像素基本上是这样定义的：

```python
class Pixel:
    def __init__(self, r, g, b, a):
        self.r = r
        self.g = g
        self.b = b
        self.a = a
```

这个 Pixel 定义只是示意性的例子，并不是我们浏览器中的真实代码。它代表的是 SDL 和 Skia 内部那些略微更复杂的代码。³

用红、绿、蓝分量来定义颜色是相当标准的做法⁴，也与计算机屏幕的工作方式相对应。⁵ 例如，在 CSS 中，我们用一个井号加 6 个十六进制数字来表示任意颜色，比如 #ffd700，红、绿、蓝各占两位数字：⁶

```python
def parse_color(color):
    if color.startswith("#") and len(color) == 7:
        r = int(color[1:3], 16)
        g = int(color[3:5], 16)
        b = int(color[5:7], 16)
        return skia.Color(r, g, b)
```

到目前为止见过的颜色都可以直接用这种语法来指定：

```python
NAMED_COLORS = {
    "black": "#000000",
    "white": "#ffffff",
    "red":   "#ff0000",
    # ...
}

    # ...

        return parse_color(NAMED_COLORS[color])

        return skia.ColorBLACK
```

遇到更多颜色名时，你可以从列表 [16] 中补充；本书的示例会用到 blue、green、lightblue、lightgreen、orange、orangered 和 gray。注意，不支持的颜色会被解释成黑色，这样至少能在屏幕上画出点东西。⁷

现在，让我们运用对表面和颜色的理解，把内容从 Skia 表面（我们将把镶边和页面内容绘制到那里）复制到 SDL 表面（真正显示在屏幕上的那个）。这一步有点麻烦，因为我们要在两个底层库之间搬运数据，但其实只是把像素从一个地方复制到另一个地方。首先，获取表示 Skia 表面的字节序列：

```python
class Browser:
    def draw(self):
        # ...
        skia_image = self.root_surface.makeImageSnapshot()
        skia_bytes = skia_image.tobytes()
```

接下来，我们需要把数据复制到 SDL 表面。这需要告诉 SDL 像素按什么顺序存储，以及你计算机的字节序（endianness）[17]：

```python

            self.RED_MASK = 0xff000000
            self.GREEN_MASK = 0x00ff0000
            self.BLUE_MASK = 0x0000ff00
            self.ALPHA_MASK = 0x000000ff
```

```python

            self.GREEN_MASK = 0x0000ff00
            self.BLUE_MASK = 0x00ff0000
```

然后，CreateRGBSurfaceFrom 方法把这些数据包装成一个 SDL 表面（并不复制字节）：

```python
class Browser:
    def draw(self):
        # ...
        depth = 32 # 每像素的比特数
        pitch = 4 * WIDTH # 每行的字节数
        sdl_surface = sdl2.SDL_CreateRGBSurfaceFrom(
            skia_bytes, WIDTH, HEIGHT, depth, pitch,
            self.RED_MASK, self.GREEN_MASK,
            self.BLUE_MASK, self.ALPHA_MASK)
```

最后，我们把所有这些像素数据画到窗口本身上，办法是将它从 sdl_surface 位块传输（blitting，即复制）到 sdl_window 的表面：⁸

```python
class Browser:
    def draw(self):
        # ...
        rect = sdl2.SDL_Rect(0, 0, WIDTH, HEIGHT)
        window_surface = sdl2.SDL_GetWindowSurface(self.sdl_window)
        # SDL_BlitSurface 才是真正执行复制的那一个。
        sdl2.SDL_BlitSurface(sdl_surface, rect, window_surface, rect)
        sdl2.SDL_UpdateWindowSurface(self.sdl_window)
```

这样我们就能从 Skia 表面复制到 SDL 窗口了。最后一步：我们必须把浏览器绘制到 Skia 表面上。

> **深入探索**
> 我们把颜色标准视作理所当然，但像 CIELAB [18] 这样的颜色标准其实源自对人类视觉 [19] 的逆向工程研究。屏幕使用红、绿、蓝三个颜色通道，是为了匹配人眼中的三类视锥细胞（cone cell）[20]。这些视锥细胞因人而异：有些人的更多 [21]，有些人的更少 [22]（通常是一种由 X 染色体携带的遗传性状）。此外，不同人拥有不同比例的视锥细胞类型，而这些视锥细胞类型使用的蛋白质结构各不相同，它们所响应的绿、红、蓝光的确切频率也有差异。因此，对颜色的研究融合了软件、硬件、化学、生物学和心理学。

## 11.4 用 Skia 光栅化

我们想把文本、矩形等绘制到 Skia 表面上。这个步骤——为表面的像素着色以在其上画出形状——叫做「光栅化」，是图形库的一项重要任务。在 Skia 中，光栅化通过画布（canvas）API 进行。画布只是一个向特定表面绘制的对象：

```python
class Browser:
    def draw(self, canvas, offset):
        # ...
        canvas = self.root_surface.getCanvas()
        # ...
```

我们浏览器的绘制命令需要在这个画布上调用 Skia 方法。要画一条线，可以使用 Skia 的 Path 对象：⁹

```python
class DrawLine:
    def execute(self, canvas, scroll):
        path = skia.Path().moveTo(self.x1 - scroll, self.y1) \
                        .lineTo(self.x2 - scroll, self.y2)
        paint = skia.Paint(
            Color=parse_color(self.color),
            StrokeWidth=self.thickness,
            Style=skia.Paint.kStroke_Style,
        )
        canvas.drawPath(path, paint)
```

注意这里涉及的步骤。我们先创建一个 Path 对象，然后调用 drawPath 把这条路径真正绘制到画布上。这个 drawPath 调用接受第二个参数 paint，它定义了到底该如何执行这次绘制。我们指定了颜色，但还需要指明我们想沿着路径画一条线，而不是填充路径的内部（后者才是默认行为）。为此，我们把样式设为「描边（stroke）」——一个标准术语，指沿着某个形状的边框绘制。¹⁰

绘制文本时也类似，使用 drawString：

```python
class DrawText:
    def execute(self, canvas, scroll):
        paint = skia.Paint(
            AntiAlias=True,
            Color=parse_color(self.color),
        )
        baseline = self.top - scroll - self.font.getMetrics().fAscent
        canvas.drawString(self.text, float(self.left), baseline,
            self.font, paint)
```

再次注意，我们创建了一个 Paint 对象来指定颜色，并请求抗锯齿（anti-aliased）文本。¹¹ 我们没有指定「样式」，因为我们想填充文本的内部，这正是默认行为。

最后，绘制矩形时使用 drawRect：

```python
class DrawRect:
    def execute(self, canvas, scroll):
        paint = skia.Paint(
            Color=parse_color(self.color),
        )
        canvas.drawRect(self.rect.makeOffset(0, -scroll), paint)
```

这里，rect 字段需要变成 Skia 的 Rect 对象。

把第 7 章引入的旧 Rect 类删掉，改用 skia.Rect。凡是构造 Rect 的地方，都换成 skia.Rect.MakeLTRB（意为「make left-top-right-bottom」）或 MakeXYWH（意为「make x-y-width-height」）。凡是检查矩形各边（比如 left）的地方，都换成 Skia Rect 上对应的函数（比如 left()）。还要把对 containsPoint 的调用替换为 Skia 的 contains。

趁现在，我们再给其他绘制命令也加上一个 rect 字段，取代它们原有的 top、left、bottom 和 right 字段：

```python
class DrawText:
    def __init__(self, x1, y1, text, font, color):
        # ...
        self.rect = \
            skia.Rect.MakeLTRB(x1, y1, self.right, self.bottom)
class DrawLine:
    def __init__(self, x1, y1, x2, y2, color, thickness):
        # ...
        self.rect = skia.Rect.MakeLTRB(x1, y1, x2, y2)
```

要绘制轮廓（outline），还是画矩形，但要把 Paint 的 Style 参数设为 Stroke_Style：

在其他几个布局对象中（paint 和 layout 里都有）、在 DrawText 中、在 Chrome 的 draw 方法中、在 BlockLayout 的 text 方法中，以及 TextLayout 的 layout 方法中，都有对 measure 的调用。把它们全部改为使用 measureText。此外，在 LineLayout 的 layout 方法和 DrawText 中，我们调用了字体的 metrics 方法。在 Skia 中，这个方法叫 getMetrics，要取得上伸部（ascent）和下伸部（descent），需要读取其结果的 fAscent 和 fDescent 字段。重要的是，在 Skia 中 ascent 需要取反。Skia 里，上伸和下伸向下为正、向上为负，所以 ascent 通常为负——与 Tkinter 正好相反。Tkinter 提供的 linespace 字段在 Skia 中没有对应物，但你可以用 descent 减去 ascent 来代替：

```python
def linespace(font):
    metrics = font.getMetrics()
    return metrics.fDescent - metrics.fAscent
```

## 11.5 浏览器合成

Skia 和 SDL 刚刚让我们的浏览器变得更复杂了，但这些库提供的底层控制很重要，因为它让我们能优化滚动这类常见交互。

到目前为止，每当用户滚动网页，我们都不得不清空画布并把上面的所有内容从头重新光栅化。这很低效——我们画的是同样的像素，只是位置不同罢了。当内容复杂或屏幕很大时，过于频繁的光栅化会造成可感知的卡顿，还会消耗笔记本电脑和手机的电量。真实浏览器用一种我称之为浏览器合成（browser compositing）的技术来优化滚动：把整个网页绘制到一个隐藏的表面，然后只把相关的像素复制到窗口本身。

为此，我们需要两个新的 Skia 表面：一个用于浏览器镶边，一个用于当前 Tab 的内容。只有当页面内容变化时，我们才需要重新光栅化 Tab 表面；而当（比如）用户在地址栏里输入时则不需要。而且滚动 Tab 完全不需要任何光栅化——我们只是把当前 Tab 表面的不同部分复制到屏幕上而已。我们分别把这两个表面叫做 chrome_surface 和 tab_surface：¹³

```python
class Browser:
    def __init__(self):
        # ...
        self.chrome_surface = skia.Surface(
            WIDTH, math.ceil(self.chrome.bottom))
        self.tab_surface = None
```

我没有立即显式创建 tab_surface，因为需要先对页面内容进行布局，才知道这个表面需要多高。

我们还需要把浏览器的 draw 方法拆分成三部分：

- raster_tab 把页面光栅化到 tab_surface；
- raster_chrome 把浏览器镶边光栅化到 chrome_surface；
- draw 把镶边表面和 Tab 表面合成（composite）起来，并把结果从 Skia 复制到 SDL。¹⁴

先来做这个拆分：

```python
class Browser:
    def raster_tab(self):
        canvas = self.tab_surface.getCanvas()
        canvas.clear(skia.ColorWHITE)
        # ...
```

```python
    def raster_chrome(self):
        canvas = self.chrome_surface.getCanvas()
        canvas.clear(skia.ColorWHITE)
        # ...
    def draw(self):
        canvas = self.root_surface.getCanvas()
        canvas.clear(skia.ColorWHITE)
        # ...
```

由于我们没有在启动时创建 tab_surface，因此需要在 raster_tab 的开头创建它：¹⁵

```python
import math
class Browser:
    def raster_tab(self):
        tab_height = math.ceil(
            self.active_tab.document.height + 2*VSTEP)
        if not self.tab_surface or \
                tab_height != self.tab_surface.height():
            self.tab_surface = skia.Surface(WIDTH, tab_height)
        # ...
```

这里我们根据布局树的高度来计算页面边界，如果页面元素能伸出其父元素下方（或右侧），这种做法就不正确了——不过我们的浏览器并不支持这类特性。注意，如果页面高度变化，就需要重建 Tab 表面。

接下来，draw 应当把镶边表面和 Tab 表面复制到根表面。此外，我们需要把 tab_surface 向下移动 chrome_bottom、再向上移动 scroll，并把裁剪范围限制在窗口中不与浏览器镶边重叠的区域：

```python
class Browser:
    def draw(self):
        # ...
        tab_rect = skia.Rect.MakeLTRB(
            0, self.chrome.bottom, WIDTH, HEIGHT)
        tab_offset = self.chrome.bottom - self.active_tab.scroll
        canvas.save()
        canvas.clipRect(tab_rect)
        canvas.translate(0, tab_offset)
        self.tab_surface.draw(canvas, 0, 0)
        canvas.restore()
```

```python
        chrome_rect = skia.Rect.MakeLTRB(
            0, 0, WIDTH, self.chrome.bottom)
        canvas.save()
        canvas.clipRect(chrome_rect)
        self.chrome_surface.draw(canvas, 0, 0)
        canvas.restore()
        # ...
```

注意这里的 draw 调用：它们把 tab_surface 和 chrome_surface 复制到画布，而画布绑定的是 root_surface。clipRect 和 translate 调用确保我们复制的是正确的部分。

最后，在 Browser 中所有调用 draw 的地方，现在都需要先调用 raster_tab 或 raster_chrome。例如在 handle_click 中，我们这样做：

```python
class Browser:
    def handle_click(self, e):
        if e.y < self.chrome.bottom:
            # ...
            self.raster_chrome()
        else:
            # ...
            self.raster_tab()
        self.draw()
```

注意，当只有 Tab 变化时，我们不会重绘镶边，反之亦然。同样，在 handle_down 中，我们完全不需要调用 raster_tab，因为滚动并不会改变页面。不过，点击网页可能导致导航到新页面，所以我们确实需要检测这种情况，并在 URL 变化时光栅化浏览器镶边：

```python
class Browser:
    def handle_click(self, e):
        if e.y < self.chrome.bottom:
            # ...
        else:
            # ...
            url = self.active_tab.url
            tab_y = e.y - self.chrome.bottom
            self.active_tab.click(e.x, tab_y)
            if self.active_tab.url != url:
                self.raster_chrome()
            self.raster_tab()
```

在 Tab 中还有一些相关的改动。我们把 Tab 的 draw 方法改名为 raster。在它内部，我们不再需要把滚动偏移传给各个 execute 方法，也不需要考虑 chrome_bottom，因为我们总是把整个 Tab 绘制到 Tab 表面上：

```python
class Tab:
    def raster(self, canvas):
        for cmd in self.display_list:
            cmd.execute(canvas)
```

同样，我们也可以从每条绘制命令的 execute 方法中去掉 scroll 参数：

```python
class DrawRect:
    def execute(self, canvas):
        paint = skia.Paint(
            Color=parse_color(self.color),
        )
        canvas.drawRect(self.rect, paint)
```

我们的浏览器现在使用合成式滚动，滚动更快更流畅——这都要归功于我们混合使用中间表面来存储已光栅化的内容，除非内容真的变了，否则不会重新光栅化。

> **深入探索**
> 真实浏览器会在各种不同的情况下分配新表面，例如实现加速的溢出滚动，以及 transform [29] 和 opacity 等某些 CSS 属性的动画——这些都可以不经光栅化完成。它们还允许通过 CSS 的 overflow: scroll [30] 滚动任意 HTML 元素。DOM 元素的基本滚动与我们刚实现的非常相似。但要完全通用、而且性能出色地实现它，是极具挑战性的。滚动很可能是浏览器渲染引擎中单一最复杂的特性，它牵涉的边角情况和微妙之处几乎无穷无尽。

## 11.6 透明度

快速绘制形状已经是个挑战，而当有多个形状时还会多出一个问题：两个形状重叠时，像素应该是什么颜色？到目前为止，我们的浏览器只处理过不透明（opaque）的形状，¹⁶答案很简单：取上面那个形状的颜色。但现在我们需要更细致的处理。

考虑 CSS 中的半透明颜色。它们使用 8 个十六进制数字的颜色，最后两位表示透明程度。例如，颜色 #00000080 是 50% 透明的黑色。在白色背景上，它看起来是灰色；但在橙色背景上，效果如图 11.2 所示。注意文本呈现出一种深橙色，因为它的颜色是 50% 黑色与 50% 橙色的混合。现实世界中的许多物体是半透明的：比如磨砂玻璃、云朵或彩色纸。透过它们看去，你会看到多种颜色混合在一起。计算机屏幕能工作也是基于这个道理：红、绿、蓝三种光混合在一起 [31]，在我们眼中呈现为另一种颜色。设计师在叠加层、阴影和工具提示中使用这种效果，¹⁷所以我们的浏览器需要支持颜色混合。

*图 11.2　黑色半透明文本混合进灰色背景的例子。*

*图 11.3　灰色背景上的黑色文本，再半透明地混合进其祖先元素的例子。*

Skia 通过在解析出的颜色上设置「alpha」字段来支持这种透明效果：

```python
def parse_color(color):
    # ...
    elif color.startswith("#") and len(color) == 9:
        r = int(color[1:3], 16)
        g = int(color[3:5], 16)
        b = int(color[5:7], 16)
        a = int(color[7:9], 16)
        return skia.Color(r, g, b, a)
    # ...
```

验证一下你的浏览器是否为上面的例子渲染出深橙色文本。这表明它确实在把黑色与背景原有的橙色混合在一起。

不过，CSS 还有另一种微妙不同的创建透明效果的方式。¹⁸这里，50% 的透明度是通过 opacity 属性应用于整个元素，如图 11.3 所示。现在这个不透明度同时作用于背景和文本，所以背景变得浅了一些。但注意，文本现在是灰色，而不是深橙色。黑色和橙色的像素不再混合在一起了！这是因为 opacity 引入了 CSS 所谓的层叠上下文（stacking context）[32]。其中大多数细节现在并不重要，但操作顺序很重要。在第一个例子中，黑色像素先被设为透明，然后再与背景混合。也就是说，50% 透明的黑色像素与橙色像素混合，得到深橙色。在第二个例子中，黑色像素先与背景混合，然后才把结果变透明。也就是说，全黑的像素替换了全橙的像素，得到的只是黑色像素，随后才被设成 50% 透明。

要按正确的顺序应用混合——这是实现 opacity 之类效果所必需的——就需要更加小心地处理表面。

> **深入探索**
> 元素形成层叠上下文，大多是因为与分层有关的 CSS 属性（如 z-index）或与视觉效果有关的属性（如 mix-blend-mode）。另一方面，能让元素可滚动的 overflow 属性却不会引入层叠上下文，我认为这是个失误。¹⁹原因在于，在现代浏览器内部，滚动是在 GPU 上通过偏移两个表面来完成的。如果没有层叠上下文，浏览器可能（取决于网页结构）不得不同步移动多个拥有复杂绘制顺序的独立表面来实现滚动。固定定位（fixed）和粘性定位（sticky）的元素也会形成层叠上下文，因为它们与滚动有交互。

## 11.7 混合与层叠

为了正确处理操作顺序，浏览器不是把混合应用于单个形状，而是应用于一棵表面树（见图 11.4）。从概念上讲，每个形状都绘制到自己的表面上，然后混合进它的父表面。中间表面的不同结构会产生不同的视觉效果。²⁰光栅化一个网页需要自底向上遍历这棵概念树：要光栅化一个表面，你必须先光栅化它的内容（包括它的子表面），然后这些内容再被混合进父表面。²¹

*图 11.4　渲染出的网页实际上是一系列不同表面层叠与混合的结果。*

为了配合这种使用模式，在 Skia 中，表面构成一个栈。你可以把一个新表面压入栈中，把内容光栅化到它上面，然后把它弹出，这会使它与下面的表面混合。光栅化时，每当需要应用某个视觉效果，你就把一个新表面压入栈；等该效果所要应用的所有元素都光栅化完毕后，再弹出并混合，就像这样：

```python
# 绘制父元素
canvas.saveLayer(None, skia.Paint(Alphaf=0.5))
# 绘制子元素
canvas.restore()
```

这里，saveLayer 调用是让 Skia²² 把所有子元素先绘制到一个单独的表面上，等到调用 restore 时再把它们混合进父表面。saveLayer 的第二个参数指定具体的混合类型，这里通过 Alphaf 参数请求 50% 的不透明度。

saveLayer 和 restore 就像一对括号，把子绘制操作包围起来。这意味着我们的显示列表不再只是一个线性的绘制操作序列，而是一棵树。因此在显示列表中，我们用一个 Opacity 命令来处理不透明度，它以一系列其他绘制命令作为参数：

```python
class Opacity:
    def __init__(self, opacity, children):
        self.opacity = opacity
        self.children = children
        self.rect = skia.Rect.MakeEmpty()
        for cmd in self.children:
            self.rect.join(cmd.rect)
    def execute(self, canvas):
        paint = skia.Paint(
            Alphaf=self.opacity
        )
        canvas.saveLayer(None, paint)
        for cmd in self.children:
            cmd.execute(canvas)
        canvas.restore()
```

现在，我们可以用 Opacity 把某个元素绘制的那些绘制命令包起来，为整个元素添加透明效果。我打算通过给布局对象新增一个 paint_effects 方法来实现，这个方法接收一个待包装的绘制命令列表：

```python
class BlockLayout:
    def paint_effects(self, cmds):
        cmds = paint_visual_effects(
            self.node, cmds, self.self_rect())
        return cmds
```

我把 Opacity 命令的实际构造放在一个新的全局 paint_visual_effects 方法里（因为其他对象类型也会用到它）：

```python
def paint_visual_effects(node, cmds, rect):
    opacity = float(node.style.get("opacity", "1.0"))
    return [
        Opacity(opacity, cmds)
    ]
```

还需要修改 paint_tree 来调用 paint_effects，但必须在递归处理子元素之后，而且仅当 should_paint 为真时才调用。这是因为这些视觉效果作用于整个子树的显示列表，而不只是当前对象；而且它们不适用于「匿名」对象（见第 8 章）。

```python
def paint_tree(layout_object, display_list):
    if layout_object.should_paint():
        cmds = layout_object.paint()
    for child in layout_object.children:
        paint_tree(child, cmds)
    if layout_object.should_paint():
        cmds = layout_object.paint_effects(cmds)
    display_list.extend(cmds)
```

注意，paint_visual_effects 接收一个命令列表，返回另一个命令列表。只不过输出的列表总是单独一条包装了原始内容的 Opacity 命令——这很合理，因为我们首先需要把这些命令绘制到一个表面上，然后在混合进父表面时对它应用透明效果。

> 我强烈推荐 Bartosz Ciechanowski 的一篇博文 [36]，它以非常漂亮的可视化方式概述了本章探讨的许多相同概念，还包含更多关于 Skia 这类库如何实现某些特性的内容，比如直线和文本的矢量图形光栅采样，以及当表面的像素阵列在分辨率或方向上不匹配时对表面做的插值。

## 11.8 合成像素

现在让我们停下来探究一下不透明度在底层到底是如何工作的。Skia、SDL 以及许多其他颜色库都为每个像素增加了第四个值——alpha——来处理不透明度。²³alpha 为 0 表示像素完全透明（也就是说，无论颜色是什么，反正你都看不见它们），alpha 为 1 表示完全不透明。

当一个带 alpha 的像素与另一个像素重叠时，最终颜色是两者颜色的混合。颜色具体如何混合，由 Skia 的 Paint 对象定义。当然，Skia 相当复杂，但我们可以在 Python 中把这些绘制操作勾勒出来，写成之前引入的概念性 Pixel 类上的方法。

当我们应用一个带 Alphaf 参数的 Paint 时，Skia 做的第一件事就是把所请求的不透明度施加到每个像素上：

```python
class Pixel:
    def alphaf(self, opacity):
        self.a = self.a * opacity
```

我要强调，这段代码并不是我们浏览器的一部分——我只是用 Python 代码来说明 Skia 内部在做什么。

Alphaf 参数作用于单个表面中的像素。但有了 saveLayer 之后，我们会得到两个表面，它们的像素全部对齐，因此我们需要把成对的对应像素合并，也就是混合（blend）。

这里的术语可能会让人犯迷糊：我们想象「上面」的像素正在混合进「下面」的像素，所以我们把上面的表面称为源表面（source surface），其中的像素是源像素（source pixel）；把下面的表面称为目标表面（destination surface），其中的像素是目标像素（destination pixel）。合并它们的方式有很多种，但 Web 上的默认方式叫做「简单 alpha 合成」，也就是 source-over 合成。用 Python 实现，代码看起来是这样的：²⁴

```python
class Pixel:
    def source_over(self, source):
        new_a = source.a + self.a * (1 - source.a)
        if new_a == 0: return self
        self.r = \
            (self.r * (1 - source.a) * self.a + \
                source.r * source.a) / new_a
        self.g = \
            (self.g * (1 - source.a) * self.a + \
                source.g * source.a) / new_a
        self.b = \
            (self.b * (1 - source.a) * self.a + \
                source.b * source.a) / new_a
        self.a = new_a
```

这里，目标像素 self 被修改为混入源像素 source。红、绿、蓝三个颜色通道的数学表达式完全相同，本质上是以 alpha 为权重对源颜色和目标颜色求加权平均。²⁵你可以把带 Alphaf 参数的 saveLayer 的整体操作想象成这样：²⁶

```python
for (x, y) in destination.coordinates():
    source[x, y].alphaf(opacity)
    destination[x, y].source_over(source[x, y])
```

Source-over 合成是合并两个像素值的一种方式。但它并不是唯一的方法——只要愿意，你完全可以写出任何能合并两个像素值的计算。有两种能产生有趣效果的计算，传统上称为「multiply（正片叠底）」和「difference（差值）」，它们使用的都是简单的数学运算。

「multiply」把颜色值相乘：

```python
class Pixel:
    def multiply(self, source):
        self.r = self.r * source.r
        self.g = self.g * source.g
        self.b = self.b * source.b
```

「difference」计算它们的绝对差：

```python
class Pixel:
    def difference(self, source):
        self.r = abs(self.r - source.r)
        self.g = abs(self.g - source.g)
        self.b = abs(self.b - source.b)
```

CSS 通过 mix-blend-mode 属性 [40] 支持这两种以及许多其他混合模式（blend mode），²⁷就像这样：

*图 11.5　mix-blend-mode 取 difference 值的例子。*

```html
<div style="background-color:orange">
    Parent
    <div style="background-color:blue;mix-blend-mode:difference">
        Child
    </div>
    Parent
</div>
```

这段 HTML 的效果如图 11.5 所示。当蓝色与橙色重叠时，我们看到的是粉色：蓝色的 (red, green, blue) 颜色通道为 (0, 0, 1)，橙色为 (1, 0.65, 0)，因此用「difference」混合得到的像素是 (1, 0.65, 1)，也就是粉色。²⁸在像素层面，发生的事情大致是这样的：

```python
for (x, y) in destination.coordinates():
    source[x, y].alphaf(opacity)
    source[x, y].difference(destination[x, y])
    destination[x, y].source_over(source[x, y])
```

这看起来很怪，但从概念上讲，它先把目标混合进源（忽略 alpha），然后再把源绘制到目标之上（考虑 alpha）。从某种意义上说，混合因此发生了两次 [41]。

Skia 原生支持 multiply [42] 和 difference [43] 混合模式：

```python
def parse_blend_mode(blend_mode_str):
    if blend_mode_str == "multiply":
        return skia.BlendMode.kMultiply
    elif blend_mode_str == "difference":
        return skia.BlendMode.kDifference
    else:
        return skia.BlendMode.kSrcOver
```

接着，我们可以定义一个新的 Blend 操作，在浏览器中支持混合：

```python
class Blend:
    def __init__(self, blend_mode, children):
        self.blend_mode = blend_mode
        self.children = children
```

```python
        self.rect = skia.Rect.MakeEmpty()
        for cmd in self.children:
            self.rect.join(cmd.rect)
    def execute(self, canvas):
        paint = skia.Paint(
            BlendMode=parse_blend_mode(self.blend_mode),
        )
        canvas.saveLayer(None, paint)
        for cmd in self.children:
            cmd.execute(canvas)
        canvas.restore()
```

在设置了 mix-blend-mode 时应用它，只需对 paint_visual_effects 做一个简单的修改：

```python
def paint_visual_effects(node, cmds, rect):
    # ...
    blend_mode = node.style.get("mix-blend-mode")
    return [
        Blend(blend_mode, [
            Opacity(opacity, cmds),
        ]),
    ]
```

注意这里的操作顺序：我们先应用透明效果，然后把结果混合进页面的其余部分。如果把 Opacity 和 Blend 的调用顺序换过来，就没有可以混合进去的东西了！

> **深入探索**
> Alpha 看似直观，但它比你以为的要更不显然：例如，可以看看 alpha 的联合发明人（也是皮克斯的联合创始人）撰写的这段 alpha 历史 [44]。实现方式也有好几种选择。例如，包括 Skia 在内的许多图形库会用不透明度去乘颜色通道，而不是专门分配一整个颜色通道。这种预乘（premultiplied）[45] 表示通常更高效；例如，上面的 source_over 最后不得不除以 self.a，因为不这样做结果就是预乘形式的。如果全程使用预乘表示，就可以省去一次除法。此外，alpha 在缩放 [46] 时如何表现也并不显然。

## 11.9 裁剪与遮罩

「multiply」和「difference」混合模式看起来可能有点晦涩，但混合模式是实现逐像素操作的一种灵活手段。一个常见的用例是裁剪（clipping）——把一个表面与给定形状求交集。它之所以叫裁剪，是因为这就像在第一张纸上再放一张纸（称为遮罩（mask）），然后用剪刀沿着遮罩的边缘剪裁。

在 Web 上裁剪内容的强大方法²⁹五花八门，但最常见的形式要数 overflow 属性。这个属性有很多可能的取值，³⁰但我们这里只关注 overflow: clip，它会切断元素中位于元素边界之外的内容。

通常，overflow: clip 会与 height 或 rotate 之类能让元素的子元素伸出父元素的属性搭配使用。我们的浏览器并不支持这些属性，但有一个需要用到 overflow: clip 的边角情况：圆角。³¹考虑这个例子：

```html
<div
    style="border-radius:30px;background-color:lightblue;overflow:clip">
    This test text exists here to ensure that the "div" element is
    large enough that the border radius is obvious.
</div>
```

这段 HTML 的效果如图 11.7 所示。可以看到，角落附近的字母被切掉了，以保持边缘是干脆利落的圆角。这就是裁剪；如果没有 overflow: clip 属性，这些字母就会被完整地画出来。

有点反直觉的是，我们将用混合模式来实现裁剪。我们会新建一个表面（即遮罩），在其中画一个圆角矩形，然后把它与元素内容混合。但我们想看到的是元素内容而不是遮罩，所以在做这次混合时，我们会使用 destination-in 合成。destination-in 合成 [49] 的意思基本上是：保留目标表面中与源表面相交的像素。源表面的颜色不会被用到——只用到它的 alpha。在我们的场景中，源表面是圆角矩形遮罩，目标表面是想要裁剪的内容，所以 destination-in 正好合适。用代码表示，destination-in 是这样的：

```python
class Pixel:
    def destination_in(self, source):
        self.a = self.a * source.a
```

现在，在 paint_visual_effects 中，我们需要创建一个新图层，把遮罩图像画进去，然后用 destination-in 混合把它与元素内容混合：

```python
def paint_visual_effects(node, cmds, rect):
    # ...
    if node.style.get("overflow", "visible") == "clip":
        border_radius = float(node.style.get(
            "border-radius", "0px")[:-2])
        cmds.append(Blend("destination-in", [
            DrawRRect(rect, border_radius, "white")
        ]))
    return [
        Blend(blend_mode, [
            Opacity(opacity, cmds),
        ]),
    ]
```

这里我把 destination-in 作为混合模式传入，但请注意这有点取巧的成分，它其实并不是 mix-blend-mode 的合法取值：

```python
def parse_blend_mode(blend_mode_str):
    # ...
    elif blend_mode_str == "destination-in":
        return skia.BlendMode.kDstIn
    # ...
```

这段代码先用 cmds 画出所有元素内容（并应用不透明度），然后在另一个图层上画一个圆角矩形作为遮罩，并使用 destination-in 混合来裁剪元素内容。这里我选择用白色来画圆角矩形，但颜色并不重要，只要不透明就行。

注意这种遮罩技术与前文剪刀的物理类比有多相似：两个图层分别扮演两张纸的角色，而 destination-in 合成扮演剪刀的角色。³²

> **深入探索**
> 圆角在计算领域有一段有趣的历史 [50]。如今看来简单的特性，在内存有限、又没有硬件浮点运算的早期个人电脑上实现起来非常复杂 [51]。即使后来浮点硬件乃至 GPU 成了标配，border-radius CSS 属性也要到 2010 年前后才出现在浏览器中。³³而近来，动画、视觉效果、多进程合成以及硬件叠加层（hardware overlay）[52] 的引入，又让圆角的实现变得相当复杂。例如，clipRRect 快速路径在硬件视频叠加层和嵌套圆角裁剪等情况下可能无法生效。

## 11.10 优化表面使用

我们的浏览器现在能正确工作了，但使用的表面实在太多了。例如，对于一个带有一些文本内容、不需要任何特效的单个 div，显示列表中目前会分配 18 个表面。如果根本没发生混合，我们本应只需要一个！让我们盘点一下我们的代码能为一个元素创建的所有表面：

- 顶层表面用于应用混合模式。由于它是顶层表面，它还把元素与页面的其他部分隔离开，使裁剪只作用于该元素。
- 第一个嵌套表面用于应用不透明度。
- 第二个嵌套表面用于实现裁剪。

但并非每个元素都应用了不透明度、混合模式或裁剪，大多数时候我们都可以跳过这些表面的创建。例如，如果实际上没有应用不透明度，就没有理由在 Opacity 中创建表面：

```python
class Opacity:
    def execute(self, canvas):
        paint = skia.Paint(
            Alphaf=self.opacity,
        )
        if self.opacity < 1:
            canvas.saveLayer(None, paint)
        for cmd in self.children:
            cmd.execute(canvas)
        if self.opacity < 1:
            canvas.restore()
```

类似地，如果没有混合发生，Blend 也未必需要创建图层。但这里的逻辑要更微妙一点：Blend 操作不仅应用混合，还会隔离元素内容，这在元素被 overflow 裁剪时很重要。所以，当没有混合模式时，我们跳过在 Blend 中创建图层；而在需要裁剪时，我们把混合模式设为一个特殊的、非标准的 source-over 值：

```python
def paint_visual_effects(node, cmds, rect):
    if node.style.get("overflow", "visible") == "clip":
        if not blend_mode:
            blend_mode = "source-over"
        # ...
```

我们把它解析为默认的 source-over 混合模式：

```python
def parse_blend_mode(blend_mode_str):
    # ...
    elif blend_mode_str == "source-over":
        return skia.BlendMode.kSrcOver
    # ...
```

这其实没有必要，因为 parse_blend_mode 本来就会把未知字符串解析为 source-over 混合，但显式写出来更好。总之，现在如果没有传入混合模式，Blend 就可以跳过 saveLayer：

```python
class Blend:
    def execute(self, canvas):
        paint = skia.Paint(
            BlendMode=parse_blend_mode(self.blend_mode),
        )
        if self.blend_mode:
            canvas.saveLayer(None, paint)
        for cmd in self.children:
            cmd.execute(canvas)
        if self.blend_mode:
            canvas.restore()
```

现在，当 Opacity 和 Blend 并不真正需要时，我们会跳过多余表面的创建。但还有一种情况表面用多了：Opacity 和 Blend 会各自创建一个表面，而不是共用一个。让我们直接把不透明度合并进 Blend 来解决这个问题：³⁴

```python
class Blend:
    def __init__(self, opacity, blend_mode, children):
        self.opacity = opacity
        self.blend_mode = blend_mode
        self.should_save = self.blend_mode or self.opacity < 1
```

```python
        self.children = children
        self.rect = skia.Rect.MakeEmpty()
        for cmd in self.children:
            self.rect.join(cmd.rect)
    def execute(self, canvas):
        paint = skia.Paint(
            Alphaf=self.opacity,
            BlendMode=parse_blend_mode(self.blend_mode),

            canvas.saveLayer(None, paint)

            cmd.execute(canvas)
```

现在 paint_visual_effects 看起来是这样的：

```python
def paint_visual_effects(node, cmds, rect):
    # ...

        # ...
        cmds.append(Blend(1.0, "destination-in", [
            DrawRRect(rect, border_radius, "white")
        ]))

```

注意，我为用于裁剪的那个 Blend 指定了 1.0 的不透明度。

> **深入探索**
> 实现高质量的光栅化库本身就非常有趣——想了解更多，请看 Real-Time Rendering [55]。³⁵如今，在 GPU 可用时充分利用它尤为重要，而浏览器经常在挑战极限。浏览器团队通常自带光栅化库专家，或与他们紧密合作：例如 Chromium 用 Skia，WebKit 用 Core Graphics [56]。这两个库也用在浏览器之外：Core Graphics 用于 iOS 和 macOS，Skia 用于 Android。

## 11.11 小结

好了，我们的浏览器现在不仅能画无聊的文本和方框，还支持：

- 借助额外表面实现浏览器合成，让滚动更快；
- 通过 alpha 通道实现半透明；
- 通过 mix-blend-mode 实现用户可配置的混合模式；
- 通过 destination-in 混合或直接裁剪实现圆角矩形裁剪；
- 在可能的情况下避免使用表面的优化。

除了这些新特性，我们还从 Tkinter 升级到了 SDL 和 Skia，这让浏览器更快、响应更灵敏，也为后续更多浏览器性能方面的工作打下了基础。

## 11.13 练习

**11.1　滤镜。** filter CSS 属性允许指定各种更复杂的效果 [58]，比如灰度（grayscale）或模糊（blur）。实现它们很有意思，其中一些（比如 blur）在 Skia 中有内置支持。实现 blur。请仔细考虑模糊发生的时机——相对于透明、裁剪和混合等其他效果而言。

**11.2　命中测试。** 如果一个元素带有 border-radius，那么有可能点击到元素之外、却仍在它的外围矩形之内的位置——也就是角落处被「圆掉」的那部分。这不应该被算作点击了该元素，但我们的浏览器目前会这样。修改 click 方法，把圆角半径考虑进去。

**11.3　兴趣区域。** 我们的浏览器现在把整个网页绘制到一个表面上，这意味着一个非常长的网页（比如本章的网页版 [59]！）会创建一个巨大的表面，从而占用大量内存。请改为只绘制一个高度有限的「兴趣区域」，比如 4 ∗ HEIGHT 像素。你需要记录兴趣区域在页面上的位置，把其中正确的部分绘制到屏幕上，并在用户试图滚动到兴趣区域之外时重新光栅化兴趣区域。使用 Skia 的 clipRect 操作来避免绘制兴趣区域之外的内容。

**11.4　溢出滚动。** 一个 overflow 属性设为 scroll 且具有固定像素高度的元素是可滚动的。（你可能想先完成练习 6.2，让 height 得到支持。）实现某种版本的 overflow: scroll。我推荐如下用户交互方式：用户点击可滚动元素内部使其获得焦点，然后可以按方向键上下滚动。你需要记录布局溢出（layout overflow）[60]。作为附加挑战，请确保支持嵌套在其他可滚动元素内部的可滚动元素。

**11.5　触摸输入。** 如今许多桌面屏幕（当然还有所有移动屏幕）都支持触摸与多点触控输入。而 SDL 有支持它们的 API [61]。实现 click 的触摸输入变体。³⁶

# 第 11 章 序列化

*Chapter 11: Serialization*

在本书的示例中，我们把工作流设计为带有输入和输出的函数，输入来自命令（Command），输出则是事件（Event）。可是，这些命令从哪里来？这些事件又到哪里去？它们来自（或去往）位于我们限界上下文之外的某些基础设施——比如消息队列、Web 请求等。

这些基础设施并不理解我们特定的领域，因此我们必须把领域模型中的类型转换成基础设施能理解的东西，例如 JSON、XML 或 protobuf 之类的二进制格式。[30]

我们还需要某种方式来跟踪工作流所需的内部状态，例如一个 Order 的当前状态。同样，我们很可能会使用数据库之类的外部服务。

显然，与外部基础设施协作的一个重要方面，就是能够把领域模型中的类型转换成易于序列化（serialization）和反序列化（deserialization）的东西。

因此，本章就将学习如何做到这一点：我们会看到如何设计可序列化的类型，然后看到如何在这些中间类型与领域对象之间来回转换。

## 持久化与序列化

先从一些定义开始。我们说持久化（persistence）就是指寿命超过创建它的进程的状态。而序列化（serialization）则是从领域特定的表示转换为易于持久化的表示（如二进制、JSON 或 XML）的过程。

例如，每当「订单表单已到达」事件发生时，我们的下单工作流实现就会被实例化并运行。但当代码停止运行之后，我们希望它的输出能以某种方式留存下来（「被持久化」），以便业务的其他部分可以使用这些数据。「留存下来」并不一定意味着要存进正规的数据库——它也可以存成文件或放进队列。而且我们不应该对持久化数据的生命周期做任何假设——它可能只保留几秒钟（比如在队列里），也可能要保留几十年（比如在数据仓库里）。

本章聚焦于序列化，下一章再讨论持久化。

## 为序列化而设计

正如我们在「在限界上下文之间传输数据」一节中所讨论的，我们复杂的领域类型——各种表示选择和约束的特殊类型深深地嵌套在一起——并不适合交给序列化器（serializer）处理。因此，无痛序列化的诀窍是：先把领域对象转换成一种专门为序列化而设计的类型——数据传输对象（Data Transfer Object，DTO）——然后序列化这个 DTO，而不是领域类型。

对于反序列化，则按同样的方式反方向进行：

- 序列化：领域对象 → DTO → JSON 等序列化格式
- 反序列化：JSON 等序列化格式 → DTO → 领域对象

一般而言，我们希望反序列化过程尽可能干净。也就是说，只要底层数据没有以某种方式损坏，反序列化到 DTO 就应该总是成功。任何领域相关的验证（比如验证 OrderQty 的整数边界，或检查 ProductCode 是否有效）都应该在 DTO 到领域类型的转换过程中、在限界上下文内部完成——在那里我们对错误处理有更好的控制。

## 把序列化代码接入工作流

序列化过程只是可以加入工作流管道的又一个组件：反序列化步骤加在工作流的前端，序列化步骤加在工作流的末端。

例如，假设我们有一个像这样的工作流（这里暂且忽略错误处理和 Result）：

```fsharp
type MyInputType = ...
type MyOutputType = ...

type Workflow = MyInputType -> MyOutputType
```

那么反序列化步骤的函数签名可能是这样：

```fsharp
type JsonString = string
type MyInputDto = ...

type DeserializeInputDto = JsonString -> MyInputDto
type InputDtoToDomain = MyInputDto -> MyInputType
```

而序列化步骤可能是这样：

```fsharp
type MyOutputDto = ...

type OutputDtoFromDomain = MyOutputType -> MyOutputDto
type SerializeOutputDto = MyOutputDto -> JsonString
```

显然，所有这些函数可以像这样串联成一条管道：

```fsharp
let workflowWithSerialization jsonString =
  jsonString
  |> deserializeInputDto   // JSON 转 DTO
  |> inputDtoToDomain      // DTO 转领域对象
  |> workflow              // 领域中的核心工作流
  |> outputDtoFromDomain   // 领域对象转 DTO
  |> serializeOutputDto    // DTO 转 JSON
  // 最终输出是另一个 JsonString
```

然后，这个 workflowWithSerialization 函数就是暴露给基础设施的函数。它的输入和输出只是 JsonString 之类的东西，因此基础设施与领域是隔离的。

当然，实践中并没有这么简单！我们还需要处理错误、异步（async）等等。但这展示了基本概念。

### DTO 作为限界上下文之间的契约

我们消费的命令由其他限界上下文的输出触发，而我们工作流发出的事件又会成为其他限界上下文的输入。这些事件和命令构成了一种我们的限界上下文必须支持的契约（contract）。当然，这是一种松散的契约，因为我们希望避免限界上下文之间的紧耦合。尽管如此，这些事件和命令的序列化格式（也就是 DTO）即使要改，也应该谨慎行事。这意味着你应当始终完全掌控序列化格式，而不应该任由某个库「自动魔法般地」替你把事情办了！

## 一个完整的序列化示例

为了演示把领域对象与 JSON 之间来回序列化和反序列化的实际做法，我们来构建一个小例子。假设我们想要持久化一个像这样定义的领域类型 Person：

```fsharp
module Domain = // 我们的领域驱动类型

  /// 约束为非 null 且最多 50 个字符
  type String50 = String50 of string

  /// 约束为大于 1900/1/1 且小于今天日期
  type Birthdate = Birthdate of DateTime

  /// 领域类型
  type Person = {
    First: String50
    Last: String50
    Birthdate : Birthdate
    }
```

String50 和 Birthdate 这两个类型无法直接序列化，所以我们先创建一个对应的 DTO 类型 Dto.Person（Dto 模块中的 Person），它的所有字段都是基本类型，像这样：

```fsharp
/// 一个用来集中存放所有与 DTO 相关的
/// 类型和函数的模块。
module Dto =

  type Person = {
    First: string
    Last: string
    Birthdate : DateTime
    }
```

接下来，我们需要 toDomain 和 fromDomain 函数。这些函数与 DTO 类型相关联，而不是与领域类型相关联，因为领域不应该知道 DTO 的存在，所以我们把它们也放进 Dto 模块中一个名为 Person 的子模块里。

```fsharp
module Dto =

  module Person =
    let fromDomain (person:Domain.Person) :Dto.Person =
      ...

    let toDomain (dto:Dto.Person) :Result<Domain.Person,string> =
      ...
```

如前所述，在 F# 4.1 之前的版本中，当模块与类型同名时，我们需要使用 CompilationRepresentation 特性（attribute）。

这种提供一对 fromDomain 和 toDomain 函数的模式，我们会贯穿始终地使用。

先来看把领域类型转换成 DTO 的 fromDomain 函数。这个函数总会成功（不需要 Result），因为复杂领域类型总是可以毫无错误地转换为 DTO。

```fsharp
let fromDomain (person:Domain.Person) :Dto.Person =
  // 从领域对象中取出基本类型值
  let first = person.First |> String50.value
  let last = person.Last |> String50.value
  let birthdate = person.Birthdate |> Birthdate.value

  // 组合各组成部分，创建 DTO
  {First = first; Last = last; Birthdate = birthdate}
```

反方向上，toDomain 函数把 DTO 转换成领域类型；由于各种验证和约束可能会失败，toDomain 返回的是 Result<Person,string> 而不是普通的 Person。

```fsharp
let toDomain (dto:Dto.Person) :Result<Domain.Person,string> =
  result {
    // 从 DTO 中获取每个（经过验证的）简单类型，以成功或失败的形式返回
    let! first = dto.First |> String50.create "First"
    let! last = dto.Last |> String50.create "Last"
    let! birthdate = dto.Birthdate |> Birthdate.create

    // 组合各组成部分，创建领域对象
    return {
      First = first
      Last = last
      Birthdate = birthdate
    }
  }
```

我们使用了 result 计算表达式（computation expression）来处理错误流，因为像 String50 和 Birthdate 这样的简单类型，它们的 create 方法返回的是 Result。

例如，我们可以按照「简单值的完整性」一节讨论的方法来实现 String50.create。代码如下所示。注意，我们把字段名作为参数传入，这样就能得到有帮助的错误消息：

```fsharp
let create fieldName str : Result<String50,string> =
  if String.IsNullOrEmpty(str) then
    Error (fieldName + " must be non-empty")
  elif str.Length > 50 then
    Error (fieldName + " must be less that 50 chars")
  else
    Ok (String50 str)
```

### 封装 JSON 序列化器

序列化 JSON 或 XML 这类事情我们并不想自己动手编写——我们可能更愿意使用第三方库。不过，这类库的 API 未必对函数式风格友好，所以我们可能想封装一下序列化和反序列化例程，让它们适合在管道中使用，并把所有异常都转换为 Result。下面以封装标准 .NET JSON 序列化库（Newtonsoft.Json）的一部分为例：

```fsharp
module Json =

  open Newtonsoft.Json

  let serialize obj =
    JsonConvert.SerializeObject obj

  let deserialize<'a> str =
    try
      JsonConvert.DeserializeObject<'a> str
      |> Result.Ok
    with
    // 捕获所有异常并转换为 Result
    | ex -> Result.Error ex
```

我们创建了自己的 Json 模块来盛放这些改造过的版本，这样我们就可以调用序列化函数 Json.serialize 和 Json.deserialize 了。

### 完整的序列化管道

有了 DTO 与领域类型之间的转换器以及序列化函数，我们就可以把一个领域类型——Person 记录——一路转换为 JSON 字符串：

```fsharp
/// 把一个 Person 序列化为 JSON 字符串
let jsonFromDomain (person:Domain.Person) =
  person
  |> Dto.Person.fromDomain
  |> Json.serialize
```

测试一下，我们会得到期望的 JSON 字符串：

```fsharp
// 用于测试的输入
let person : Domain.Person = {
  First = String50 "Alex"
  Last = String50 "Adams"
  Birthdate = Birthdate (DateTime(1980,1,1))
  }

// 使用序列化管道
jsonFromDomain person

// 输出为
// "{"First":"Alex","Last":"Adams","Birthdate":"1980-01-01T00:00:00"}"
```

组合序列化管道非常简单，因为所有阶段都不涉及 Result；但组合反序列化管道就棘手一些，因为 Json.deserialize 和 PersonDto.fromDomain 都可能返回 Result。解决方案是使用 Result.mapError 把潜在的失败转换为一个公共的选择类型，然后用 result 表达式把错误隐藏起来，正如我们在「转换为公共错误类型」一节中学到的那样：

```fsharp
type DtoError =
  | ValidationError of string
  | DeserializationException of exn

/// 把一个 JSON 字符串反序列化为 Person
let jsonToDomain jsonString :Result<Domain.Person,DtoError> =
  result {
    let! deserializedValue =
      jsonString
      |> Json.deserialize
      |> Result.mapError DeserializationException

    let! domainValue =
      deserializedValue
      |> Dto.Person.toDomain
      |> Result.mapError ValidationError

    return domainValue
    }
```

我们先用一个没有错误的输入来测试：

```fsharp
// 用于测试的 JSON 字符串
let jsonPerson = """{
  "First": "Alex",
  "Last": "Adams",
  "Birthdate": "1980-01-01T00:00:00"
  }"""

// 调用反序列化管道
jsonToDomain jsonPerson |> printfn "%A"
```

```fsharp
// 输出为：
//  Ok {First = String50 "Alex";
//      Last = String50 "Adams";
//      Birthdate = Birthdate 01/01/1980 00:00:00;}
```

可以看到，整体结果是 Ok，Person 领域对象已被成功创建。

现在我们把 JSON 字符串改成带错误的——一个空白的名字和一个非法的日期——再运行一次代码：

```fsharp
let jsonPersonWithErrors = """{
  "First": "",
  "Last": "Adams",
  "Birthdate": "1776-01-01T00:00:00"
  }"""

// 调用反序列化管道
jsonToDomain jsonPersonWithErrors |> printfn "%A"

// 输出为：
//  Error (ValidationError [
//        "First must be non-empty"
//        ])
```

可以看到，我们确实得到了 Result 的 Error 分支，以及其中一条验证错误消息。在真实应用中，你可以把它记录到日志，也可以把错误返回给调用方。（在这个实现中，我们只返回第一个错误。要想返回所有错误，参见「使用应用式函数并行组合」一节。）

反序列化期间的错误处理还有另一种做法：干脆不处理，直接让反序列化代码抛出异常。选择哪种做法，取决于你想把反序列化错误当作预期中的情况来处理，还是当作让整条管道崩溃的「恐慌」（panic）。而这又取决于你的 API 有多公开、你对调用方的信任程度，以及你希望就这类错误向调用方提供多少信息。

### 使用其他序列化器

上面的代码使用的是 Newtonsoft.Json 序列化器。你也可以使用其他序列化器，但可能需要给 PersonDto 类型添加一些特性（attribute）。例如，要用 DataContractSerializer（用于 XML）或 DataContractJsonSerializer（用于 JSON）序列化一个记录类型，就必须给 DTO 类型标注 DataContractAttribute 和 DataMemberAttribute：

```fsharp
module Dto =
  [<DataContract>]
  type Person = {
    [<field: DataMember>]
    First: string
    [<field: DataMember>]
    Last: string
    [<field: DataMember>]
    Birthdate : DateTime
    }
```

这也体现了把序列化类型与领域类型分开的另一个好处——领域类型不会被这类复杂的特性「污染」。一如既往，把领域的关注点与基础设施的关注点分开总是好的。

关于序列化器，另一个值得了解的有用特性是 CLIMutableAttribute，它会生成一个（隐藏的）无参构造函数，而这常常是那些基于反射（reflection）的序列化器所需要的。

最后，如果你确定只会与其他 F# 组件协作，可以使用 F# 专用的序列化器，例如 FsPickler[31] 或 Chiron。[32] 注意，这样一来你就引入了限界上下文之间的一种耦合：它们必须全部使用同一种编程语言。

### 处理序列化类型的多个版本

随着时间的推移和设计的演化，领域类型可能需要修改——字段可能被增加、删除或重命名。这反过来也会影响 DTO 类型。DTO 类型充当着限界上下文之间的契约，而重要的是不能破坏这份契约。这意味着，你可能不得不随时间推移支持同一 DTO 类型的多个版本。做法有很多种，但这里没有篇幅展开。Greg Young 的著作《Versioning in an Event Sourced System》[33] 对各种可用的方案做了很好的讨论。

## 如何把领域类型转换为 DTO

我们定义的领域类型可能相当复杂，而对应的 DTO 类型却必须是只包含基本类型的简单结构。那么，面对一个特定的领域类型，该如何设计对应的 DTO 呢？我们来看一些指导原则。

### 单分支联合类型

单分支联合类型（single-case union）——也就是本书中所说的「简单类型」——在 DTO 中可以用其底层的基本类型来表示。

例如，如果 ProductCode 是这样一个领域类型：

```fsharp
type ProductCode = ProductCode of string
```

那么对应的 DTO 类型就是 string。

### 选项类型

对于选项类型（option），我们可以用 null 来替代 None 分支。如果选项包装的是引用类型（reference type），我们什么也不用做，因为 null 本身就是合法的值。而对于 int 之类的值类型（value type），就需要使用对应的可空类型，例如 Nullable<int>。

### 记录类型

定义为记录（record）的领域类型在 DTO 中仍然可以是记录，只要把每个字段的类型都换成对应的 DTO 等价类型即可。

下面这个例子演示了单分支联合类型、可选值和记录类型的组合：

```fsharp
/// 领域类型
type OrderLineId = OrderLineId of int
type OrderLineQty = OrderLineQty of int
type OrderLine = {
  OrderLineId : OrderLineId
  ProductCode : ProductCode
  Quantity : OrderLineQty option
  Description : string option
  }

/// 对应的 DTO 类型
type OrderLineDto = {
  OrderLineId : int
  ProductCode : string
  Quantity : Nullable<int>
  Description : string
  }
```

### 集合

列表（list）、序列（sequence）和集合（set）应转换为数组（array），因为每种序列化格式都支持数组。

```fsharp
/// 领域类型
type Order = {
  ...
  Lines : OrderLine list
  }

/// 对应的 DTO 类型
type OrderDto = {
  ...
  Lines : OrderLineDto[]
  }
```

对于映射（map）和其他复杂集合，采取的做法取决于序列化格式。使用 JSON 格式时，应当可以直接把 map 序列化成 JSON 对象，因为 JSON 对象本身就是键值对的集合。

对于其他格式，你可能需要创建一种特殊的表示。例如，map 在 DTO 中可以表示为一个记录数组，其中每个记录是一个键值对：

```fsharp
/// 领域类型
type Price = Price of decimal
type PriceLookup = Map<ProductCode,Price>

/// 表示 map 的 DTO 类型
type PriceLookupPair = {
  Key : string
  Value : decimal
  }
type PriceLookupDto = {
  KVPairs : PriceLookupPair []
  }
```

或者，map 也可以表示成两个平行的数组，反序列化时再把它们按位置拉链（zip）到一起。

```fsharp
/// 表示 map 的另一种 DTO 类型
type PriceLookupDto = {
  Keys : string []
  Values : decimal []
  }
```

### 用作枚举的可区分联合类型

很多情况下，你会遇到每个分支都只是一个名字、不携带额外数据的联合类型。这类联合可以用 .NET 枚举（enum）来表示，而枚举在序列化时通常又被表示为整数。

```fsharp
/// 领域类型
type Color =
  | Red
  | Green
  | Blue

/// 对应的 DTO 类型
type ColorDto =
  | Red = 1
  | Green = 2
  | Blue = 3
```

注意，反序列化时，你必须处理 .NET 枚举值不在已列举值之列的情况。

```fsharp
let toDomain dto : Result<Color,_> =
  match dto with
  | ColorDto.Red -> Ok Color.Red
  | ColorDto.Green -> Ok Color.Green
  | ColorDto.Blue -> Ok Color.Blue
  | _ -> Error (sprintf "Color %O is not one of Red,Green,Blue" dto)
```

另一种做法是，把枚举风格的联合序列化为字符串，用分支的名字作为值。不过，这种做法对重命名问题更敏感。

### 元组

元组（tuple）在领域里应该不常出现，但如果出现了，多半就需要用一个专门定义的记录来表示，因为大多数序列化格式都不支持元组。下面的例子中，领域类型 Card 是一个元组，而对应的 CardDto 类型是一个记录。

```fsharp
/// 元组的组成部分
type Suit = Heart | Spade | Diamond | Club
type Rank = Ace | Two | Queen | King // 为清晰起见，未列全

// 元组
type Card = Suit * Rank

/// 对应的 DTO 类型
type SuitDto = Heart = 1 | Spade = 2 | Diamond = 3 | Club = 4
type RankDto = Ace = 1 | Two = 2 | Queen = 12 | King = 13
type CardDto = {
  Suit : SuitDto
  Rank : RankDto
  }
```

### 选择类型

选择类型（choice type）可以表示为这样一个记录：用一个「标签」（tag）字段表示当前使用的是哪个选择，再为每个可能的分支各设一个字段，存放与该分支相关联的数据。在 DTO 中转换某个特定分支时，该分支对应的字段会有数据，而其他分支对应的其他字段则都为 null（如果字段是列表，则为空）。

有些序列化器可以直接处理 F# 可区分联合（discriminated union）类型，但你对它们所用的格式没有控制权。如果另一个限界上下文使用了不同的序列化器、不知道如何解释这些格式，就会出问题。由于 DTO 是契约的一部分，最好对格式进行显式的控制。

下面是一个拥有四个选择的领域类型（Example）的例子：

- 一个空分支，标记为 A
- 一个整数，标记为 B
- 一个字符串列表，标记为 C
- 一个名字（使用上面定义的 Name 类型），标记为 D

```fsharp
/// 领域类型
type Name = {
  First : String50
  Last : String50
  }

type Example =
  | A
  | B of int
  | C of string list
  | D of Name
```

下面是对应的 DTO 类型的样子，每个分支的数据类型都被替换成了可序列化的版本：int 替换为 Nullable<int>，string list 替换为 string[]，Name 替换为 NameDto。

```fsharp
/// 对应的 DTO 类型
type NameDto = {
  First : string
  Last : string
  }

type ExampleDto = {
  Tag : string // "A"、"B"、"C"、"D" 之一
  // A 分支没有数据
  BData : Nullable<int>  // B 分支的数据
  CData : string[]       // C 分支的数据
  DData : NameDto        // D 分支的数据
  }
```

序列化很直接——只需转换所选分支对应的数据，并把所有其他分支的数据置为 null：

```fsharp
let nameDtoFromDomain (name:Name) :NameDto =
    let first = name.First |> String50.value
    let last = name.Last |> String50.value
    {First=first; Last=last}

let fromDomain (domainObj:Example) :ExampleDto =
  let nullBData = Nullable()
  let nullCData = null
  let nullDData = Unchecked.defaultof<NameDto>
  match domainObj with
  | A ->
      {Tag="A"; BData=nullBData; CData=nullCData; DData=nullDData}
  | B i ->
      let bdata = Nullable i
      {Tag="B"; BData=bdata; CData=nullCData; DData=nullDData}
  | C strList ->
      let cdata = strList |> List.toArray
      {Tag="C"; BData=nullBData; CData=cdata; DData=nullDData}
  | D name ->
      let ddata = name |> nameDtoFromDomain
      {Tag="D"; BData=nullBData; CData=nullCData; DData=ddata}
```

这段代码的要点如下：

- 我们在函数开头为每个字段准备好了 null 值，然后把它们赋给与当前所匹配分支无关的字段。

- 在 B 分支中，Nullable<_> 类型不能直接赋值为 null，必须改用 Nullable() 函数。

- 在 C 分支中，数组可以直接赋值为 null，因为数组是 .NET 类（class）。

- 在 D 分支中，NameDto 这样的 F# 记录同样不能赋值为 null，所以我们用了「后门」函数 Unchecked.defaultOf<_> 来为它创建 null 值。这个函数在正常代码中绝不应使用，只有在需要为互操作或序列化创建 null 时才会用到。

反序列化这种带标签的选择类型时，我们对 Tag 字段做模式匹配，然后分别处理每个分支。而且在尝试反序列化之前，必须始终检查与标签关联的数据不为 null：

```fsharp
let nameDtoToDomain (nameDto:NameDto) :Result<Name,string> =
    result {
      let! first = nameDto.First |> String50.create
      let! last = nameDto.Last |> String50.create
      return {First=first; Last=last}
    }

let toDomain dto : Result<Example,string> =
  match dto.Tag with
    | "A" ->
      Ok A
    | "B" ->
      if dto.BData.HasValue then
        dto.BData.Value |> B |> Ok
      else
        Error "B data not expected to be null"
    | "C" ->
      match dto.CData with
      | null ->
        Error "C data not expected to be null"
      | _ ->
        dto.CData |> Array.toList |> C |> Ok
    | "D" ->
      match box dto.DData with
      | null ->
        Error "D data not expected to be null"
      | _ ->
        dto.DData
        |> nameDtoToDomain  // 返回的是 Result……
        |> Result.map D     // ……所以必须用 "map"
    | _ ->
      // 其他所有情况
      let msg = sprintf "Tag '%s' not recognized" dto.Tag
      Error msg
```

在 B 和 C 分支中，从基本类型值到领域值的转换不会出错（在确保数据非 null 之后）。而在 D 分支中，从 NameDto 到 Name 的转换可能失败，所以返回的是一个 Result，我们必须用 D 分支的构造函数对它做映射（使用 Result.map）。

### 用键值对映射序列化记录和选择类型

对复合类型（记录和可区分联合）的另一种序列化方法是，把所有内容都序列化成一个键值对映射。换句话说，所有 DTO 都以同一种方式实现：.NET 类型 IDictionary<string,obj>。这种方法特别适用于 JSON 格式，因为它与 JSON 对象模型非常契合。

这种方法的优点是，DTO 结构中不再隐含任何「契约」——键值对映射什么都能装——因此有利于实现高度解耦的交互。缺点则是彻底没有契约了！这意味着，当生产者和消费者之间的预期不匹配时，将很难察觉。有时候，一点点耦合反而有用。我们来看一些代码。使用这种方法，序列化一个 Name 记录会像这样：

```fsharp
let nameDtoFromDomain (name:Name) :IDictionary<string,obj> =
  let first = name.First |> String50.value :> obj
  let last = name.Last |> String50.value :> obj
  [
    ("First",first)
    ("Last",last)
  ] |> dict
```

这里我们先创建一个键值对列表，再用内置函数 dict 从中构建出一个 IDictionary。如果随后把这个字典序列化为 JSON，其输出看起来就和我们专门定义一个 NameDto 类型再序列化一模一样。

需要注意的一点是，这里的 IDictionary 用 obj 作为值的类型。这意味着记录中所有的值都必须用向上转型运算符（upcast）:> 显式地转换为 obj。

对于选择类型，返回的字典将恰好只有一个条目，但键的取值取决于具体的选择。例如，如果要序列化 Example 类型，键就会是 "A"、"B"、"C" 或 "D" 之一。

```fsharp
let fromDomain (domainObj:Example) :IDictionary<string,obj> =
  match domainObj with
  | A ->
    [ ("A",null) ] |> dict
  | B i ->
    let bdata = Nullable i :> obj
    [ ("B",bdata) ] |> dict
  | C strList ->
    let cdata = strList |> List.toArray :> obj
    [ ("C",cdata) ] |> dict
  | D name ->
    let ddata = name |> nameDtoFromDomain :> obj
    [ ("D",ddata) ] |> dict
```

上面的代码采用了与 nameDtoFromDomain 类似的做法。对每个分支，我们先把它转换成可序列化的格式，再转型为 obj。在 D 分支中，数据是一个 Name，它的可序列化格式就是另一个 IDictionary。

反序列化就要麻烦一些。对每个字段，我们需要 (a) 在字典中查找它是否存在，(b) 如果存在，把它取出来并尝试转型为正确的类型。

这正需要一个辅助函数，我们叫它 getValue：

```fsharp
let getValue key (dict:IDictionary<string,obj>) :Result<'a,string> =
  match dict.TryGetValue key with
  | (true,value) ->  // 找到键了！
    try
      // 向下转型到类型 'a 并返回 Ok
      (value :?> 'a) |> Ok
    with
    | :? InvalidCastException ->
      // 转型失败
      let typeName = typeof<'a>.Name
      let msg = sprintf "Value could not be cast to %s" typeName
      Error msg
  | (false,_) ->     // 未找到键
    let msg = sprintf "Key '%s' not found" key
    Error msg
```

那么我们来看如何反序列化一个 Name。我们首先必须取得 "First" 键上的值（这可能产生错误）。如果成功，就对它调用 String50.create 得到 First 字段（这也可能产生错误）。"Last" 键和 Last 字段同理。一如既往，我们会使用 result 表达式来让日子好过一点。

```fsharp
let nameDtoToDomain (nameDto:IDictionary<string,obj>) :Result<Name,string> =
  result {
    let! firstStr = nameDto |> getValue "First"
    let! first = firstStr |> String50.create
    let! lastStr = nameDto |> getValue "Last"
    let! last = lastStr |> String50.create
    return {First=first; Last=last}
  }
```

要反序列化诸如 Example 这样的选择类型，我们需要逐个分支测试对应的键是否存在。如果存在，就可以尝试取出它并转换成领域对象。同样，出错的可能性很多，所以每个分支我们都会用 result 表达式。

```fsharp
let toDomain (dto:IDictionary<string,obj>) : Result<Example,string> =
  if dto.ContainsKey "A" then
    Ok A    // 不需要额外的数据
  elif dto.ContainsKey "B" then
    result {
      let! bData = dto |> getValue "B" // 可能失败
      return B bData
      }
  elif dto.ContainsKey "C" then
    result {
      let! cData = dto |> getValue "C" // 可能失败
      return cData |> Array.toList |> C
      }
  elif dto.ContainsKey "D" then
    result {
      let! dData = dto |> getValue "D" // 可能失败
      let! name = dData |> nameDtoToDomain  // 也可能失败
      return name |> D
      }
  else
    // 其他所有情况
    let msg = sprintf "No union case recognized"
    Error msg
```

### 泛型

很多情况下，领域类型是泛型（generic）的。如果序列化库支持泛型，你也可以用泛型来创建 DTO。

例如，Result 类型就是泛型的，可以像这样转换成泛型的 ResultDto：

```fsharp
type ResultDto<'OkData,'ErrorData when 'OkData : null and 'ErrorData: null> = {
  IsError : bool  // 取代 "Tag" 字段
  OkData : 'OkData
  ErrorData : 'ErrorData
  }
```

注意，泛型类型 'OkData 和 'ErrorData 必须约束为可空（nullable），因为在对应的 JSON 对象中，它们可能缺失或为 null。

如果序列化库不支持泛型，你就得为每个具体情形创建专门的类型。这听起来可能很繁琐，但你可能会发现，实践中需要序列化的泛型类型非常少。

例如，下面把下单工作流的 Result 类型转换成 DTO，用的就是具体类型而非泛型类型：

```fsharp
type PlaceOrderResultDto = {
  IsError : bool
  OkData : PlaceOrderEventDto[]
  ErrorData : PlaceOrderErrorDto
  }
```

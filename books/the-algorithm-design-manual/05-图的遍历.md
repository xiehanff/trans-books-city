## 5.1 图的风格

图G=（V,E）定义在顶点集V上，且包含边的集合E，而E则是由V中有序或无序的顶点对组成.在公路网的建模中，顶点可能代表城市或交叉路口，而某些顶点对之间则以公路/边相连.在计算机程序的源代码分析中，顶点可能代表一行代码，如果某行代码y在另一行代码z之后执行，则这两行之间有边相连，在人际互动分析中，顶点通常代表人，而有关系的人之间以边相连. 图有若干基本属性（如图5.2所示），它们会影响到我们的抉择- 应该选择何种数据结构表示图？到底有哪些算法能很好地处理这个图问题？

undirected directed unweighted 12 weighted simple non-simple dense cyclic acyclic embedded topological G explicit 图 5.2 图的一些重要特性/风格因此，处理任何一个图问题的第一步就是确定图的风格（favor）：

- 无向和有向（Undirected us. Directed）—称图G 三（V,E）为无向图，若边（z,g）属于E意味着（g，z）也在E中：否则，我们称该图为有向图，城市之间的公路网通常是无向的，因为稍大一点的公路都有双向车道，城市内部的道路网几乎总是有向的，因为免不了在某些地方暗藏单行道，表示程序流的图通常是有向的，因为执行过程从一行流往下一行，而仅在分支处改变方向.图论中所感兴趣的图大多是无向的.
- 加权和无权（Weighted vs. Unweighted）—加权图中每条边（或每个顶点）会赋以数值或权.在表示公路网的图中，边可能以道路长度、行驶时间或限速值赋权，这取决于实际应用的需求，在无权图中，不同的边和顶点不存在费用值上的差别.

寻找两个顶点之间的最短路径时，加权图和无权图的区别会变得特别明显，对于无权图，最短路径应具有数量最少的项点，它可通过本章所讨论的广度优先搜索找到. 而加权图中的最短路径则需要像第6章中所讨论的那几个精巧算法才能解决.

- 简单和非简单（Simple US. Non-simple）—一以图来求解问题时，有几类边会使图的处理变得复杂.自圈（self-loop）指仅涉及一个顶点的边，也就是（z,z）.称边（z,3）为多重边，若它在图中不止出现一次.

在实现图算法时，这两种结构都需要特别注意，因此，任何能避开这两种结构的图便可称沩简单图.本章后续的所有图算法实现均假设输入为简单图，不处理自圈或多重边.

- 稀疏和稠密（Sparse us. Dense）一称图为稀疏图，仅当所有可能出现的顶点对（包含n个项点的简单无向图最多会有（2）对顶点）中仅有一小部分确实连成了边的时候.

所有可能出现的顶点对中要是有一大部分形成了边，那么此时图称为稠密图.什么是稀疏，而什么又是稠密，它们之间并没有一个法定的分界，不过一般来说，稠密图所拥有的边数是项点数的平方量级，而稀疏图的边数则是项点数的线性量级.

稀疏图常常是特定问题的产物.公路网肯定是稀疏图，其原因在于公路的交叉不会很多.我所知道最惊人的交叉路口也仅仅才汇集了7条公路，电子元件的接头也与之类似，它同样受限于元件通常所能连接导线的根数，不过这个结论可能在电源或地线处不成立.！

- 有环和无环（Cyclic ws. Acyclic）—无环图中不包括任何环路.树是连通的无环无向图，它也是保留图结构特性里最简单的那一类，此外，树天生是一种递归结构，因为切断任何边将留下两棵较小的树.

有向无环图通常缩写为DAG.这种图很自然地会出现在调度问题之中，其中有向边（z， ）意味着活动必须出现在活动y之前.有一种称为拓扑排序（topological

sorting）的操作会遵照有向无环图中顶点次序约束关系排好这些项点.拓扑排序通常是有向无环图上任何算法都要执行的第一步，我们将在5.10.1节中的讨论中看到这一点.

- 嵌人和拓朴（Embedded ws. Topologzcal）-

—称图为嵌入图（embedded graph），若其顶点和边都能赋以几何位置.因此，任何图的图画（drawing）2都是一种嵌入（embedding），这种嵌入可以是算法意义上的，也可以是物理意义上的.

在少数情况下，图的结构会完全由它所嵌入的几何来规定.例如，如果给我们一堆平面上的点，而我们要寻找访问所有点且花费最少的巡游（即旅行商问题），其底层拓扑结构是每对顶点都连通的那种完全图（complete graph）. 完全图中边的权值通常由点与点之间的欧氏距离来确定.

点的网格是由几何所得拓扑的另一实例.许多n×m网格上的问题需要在相邻点之间走动，因此网格上的边是由几何隐式定义的.

1译者注：从顶点度的角度看，若大多数顶点度的上界不随顶点数而变，这种图一般是稀疏图.公路中交叉路口的分叉一般是3或4，而电子元件的接头也基本上只能连两到三条导线，而少数顶点的度也不会影响到图的稀疏性.

2译者注：所谓图画（drawing），可想象在纸上所画出的图（包括顶点和边），显然图的图画不止一种，事实上，图画有其严格的定义，如边是一条曲线，可参阅图论书籍.

- 隐式和显式（Implicit US. Eaplicit）—某些图不是显式构建完毕再进行遍历的，它们是随用随建的. 回溯搜索就是一个很好的实例.这个隐式形成的搜索图（search

graph）的项点是搜索向量的状态，而状态之间相连的有向边可在搜索过程中直接生成.相比于在分析处理之前显式构建图而言，以隐式图来搜索通常更简单，因为这样你不需要存储整个图.

- 有标和无标（Labeled vs. Unlabeled）

—有标图中每个顶点会赋一个唯一的名字或标识以将该顶点与其他顶点区分开.而在无标图中则不作此类区分.

现实中所出现的图通常会很自然地被加上标签，而且这些标签也是有实际意义的，比如交通网络中的城市名.实际应用中的一个常见问题是同构测试（isomorphism

testing）—在忽略标签情况下确定两个图的拓扑结构是否完全相同.此类问题通常可利用回溯求解，即在两个图中对每个项点都试着指派各种不同的标签来判定它们是否具有相同的结构.

### 5.1.1 友谊图

正确地建立问题的模型非常重要，为了论证这个观点，让我们考虑这样的图：图中的顶点代表人，两个人之间存在边当且仅当他们是朋友（例如图5.3）.此类图称为社交网络（social network），它可在任何人群上作出明确定义—假定这些人在你附近，在你的学校/企业，他们的范围甚至可以横跨整个世界.近年来兴起了分析社交网络的一个完整学科，其原因是人及其行为有许多有趣的方面若视为友谊图的属性则可得到最佳诠释.

Bill Clinton Hillary Clinton Monica Lewinsky Al Gore Saddam Hussein 图 5.3 友谊图局部我们在现实生活中能遇到的图大多是稀疏的，而友谊图就是一个很好的实例，即便是地球上最爱交友的人所认识的人也只占世界总人口中极少的一部分. 我们借此机会来说明前文所述及的图论术语.

事实证明，“夸夸其谈”（talking the talk）也是“身体力行”（walking the walk）的一个重要组成部分，因为要想解决问题你得先搞清原理：

- 如果我是你的朋友，这意味着你是我的朋友吗？

—该问题实际上问的是图是否是有向的.称图为无向图如果边（z,g）始终蕴涵（g,z）.否则图被称为是有向图，“知道”图是有向的，因为我知道许多名人而他们却从来没听说过我，我希望“友谊”图也是一个无向图.

- 朋友与你有多亲近？在加权图中，每条边都与一个数值属性相关联.我们可对朋友关系的强弱程度建模，方法是给每条边取一个合适的值，范围不妨从-10（敌人）到10（血誓兄弟-）.公路网络图的边可用其道路长度、行驶时间或限速值赋权，具体依用途而定.如若假定图中所有边的权值相等，该图称为无权图.
- 我是自己的朋友吗？—这个问题能让我们知道某个图是否为简单图，这个词的意思是该图不包含自圈和多重边.形如（2，2）的边称为自圈，有时人们通过不同方式会多次建立朋友关系.譬如z和y是大学同班同学，而现在他们在同一家公司一起工作.

我们可用多重边（maltiedges）对此类关系建模，比如多条从心到y的边，你可用不同的标签区分之.

说实话，简单图在实际中常常更易于处理，因此我们最好还是断言没有人是自己的朋友吧.

- 谁的朋友最多？—顶点的度（degree）是其邻边个数.最受欢迎的人意味着他是友谊图中度最高的顶点.离群索居的隐士则意味着零度顶点.

相对于边较少的稀疏图（sparse graph），稠密图（dense graph）中大多数项点拥有较高的度.正则图（regular graph）中所有顶点拥有完全相同的度.一个正则友谊图在社交特性上真正达到了极致.

- 我的朋友在我附近居住吗？—社交网络与地理并不脱节.你的许多朋友之所以是你的朋友只是因为他们碰巧住在你附近（例如邻居），或者他们曾住在你附近（例如大学室友）.

因此，一个对社交网络的完整认知需要一个嵌入图（embedded graph），其中每个顶点都与它在这个世界上所居住的那个点关联，这种地理信息可能不会显式地编码，但友谊图生来就嵌于平面上的这一事实决定了我们如何去解释对友谊图的所有分析.

- 噢，你也认识她？——像Myspace和LinkedIn这样的社交网络服务，建立在这样的假定下：任意成员与其在该社交网络上的朋友之间的关联有着明确无误（explicitly）的界定.2构成此类图的是从某人/顶点z到某人/顶点g的有向边.

即便假定真实世界人之间的朋友关系也是明确的，但它们所形成的整个友谊图却未明确（implicitlg）呈现.人人都知道谁是自己的朋友，但却无法搞清别人的朋友关系，只有问当事人才能确定.“六度分离”理论认为世界上任何两个人（例如Skiena和美国总统）之间都有一条很短的关联路径，但这对我们寻找该路径没什么帮助.我所能找到与总统之间的最短路径包含三跳（Steven Skiena - Bob MeGrath - John

Marberger - George W. Bush），但很有可能存在更短的路径（比如说，要是他曾与我的牙医一起上大学的话）.友谊图存于每个人但难显露，因此我也没有办法很容易地检验是否还有更短路径.

- 邻接矩阵（Adjacency matriz）：我们可用一个n × n的矩阵M表示G，若（ij）是G的一条边则矩阵元素M［i，=1，反之则为0.这样可以快速回答“（i,j）是否在G中”的问题，并且对边的插入和删除能迅速进行数据更新.但是，对于拥有较多顶点而边却相对较少的图而言，邻接矩阵会占用过多空间.

考虑一个表示纽约市曼哈顿街道地图的图.每两条街的交叉口都将是该图的一个顶点.相邻的交叉口以边相连.这个图有多大呢？曼哈顿大致是一个网格，它有15条大道，每条大道与200条左右的街道相交，由于每个顶点与其他四个顶点邻接，而每条边被两个项点共享，因此这会给我们带来大约3000个顶点和6000条边.这些数据数量不多，存储起来应该很容易而且会很高效，但一个存储该图的邻接矩阵将会拥有3000× 3000 =9000000个单元，并且几乎全是空的！通过将多个比特压缩为计算机字存储，或是在无向图上仿照三角矩阵的数据形式存储，这个方案还有节约空间的潜力可挖.但这些方法都失去了邻接矩阵极其优美的那种简明性，而且更关键的是对于稀疏矩阵而言邻接矩阵的存储空间仍然保持着那与生俱来的平方量级.

- 邻接表（Adjacency lists）：通过使用链表存储每个顶点的相邻点，我们可以更高效地表示稀疏矩阵.邻接表需要指针，不过别怕，一旦你有过使用链接结构的经验这就没什么了.

邻接表会让验证某条边（i，j）是否在G中的这个问题变得比较困难，因为我们得在相应的列表中从头找到尾.然而让人诧异的是，很容易设计出能够完全规避此类查询需求的图算法.典型的做法是，我们用一次深度优先搜索或广度优先搜索去扫视图中所有边，并在我们访问当前边时对这条边可能会影响到的数据进行更新.图5.5总结了邻接表和邻接矩阵之间的权衡结果.！对比项目对于测试（z,3）是否在图中，哪个更快？哪个能更快地求出顶点的度？对于稀疏图，哪个占内存更少？对于稠密图，哪个占内存更少？对于边的插入和删除，哪个更快？哪个能更快地遍历图？

typedef struct edgenode {
    int y;                  /* 邻接信息 */
    int weight;             /* 边的权值，如果有的话 */
    struct edgenode *next;  /* 列表中下一条边 */
} edgenode;

typedef struct {
    edgenode *edges[MAXV + 1]; /* 邻接信息 */
    int degree[MAXV + 1];      /* 每个顶点的出度 */
    int nvertices;             /* 图中的顶点数 */
    int nedges;                /* 图中的边数 */
    bool directed;             /* 此图有向吗？ */
} graph;

```

void initialize_graph(graph *g, bool directed)
{
    int i;                  /* 计数器 */

    g->nvertices = 0;
    g->nedges = 0;
    g->directed = directed;
    for (i = 1; i <= MAXV; i++)
        g->degree[i] = 0;
    for (i = 1; i <= MAXV; i++)
        g->edges[i] = NULL;
}

```

真正读图时则要把每条边插入到这个数据结构中：

```c
void read_graph(graph *g, bool directed)
{
    int i;                  /* 计数器 */
    int m;                  /* 边的条数 */
    int x, y;               /* 边 (x, y) 中的顶点 */

    initialize_graph(g, directed);
    scanf("%d %d", &(g->nvertices), &m);
    for (i = 1; i <= m; i++) {
        scanf("%d %d", &x, &y);
        insert_edge(g, x, y, directed);
    }
}

```

关键的子程序是insert_edge. 新的edgenode型结构体将插到相应邻接表的起始位置，因为表内元素的次序无关紧要.我们用布尔型标记变量directed来设定插入过程的参数，这样可以确定是需要插入每条边的两个副本还是仅仅插入一个.请留意解决此问题所用到的递归：

```c
void insert_edge(graph *g, int x, int y, bool directed)
{
    edgenode *p;            /* 暂用指针 */

    p = malloc(sizeof(edgenode));   /* 分配 edgenode 结构体存储空间 */
    p->weight = 0;
    p->y = y;
    p->next = g->edges[x];
    g->edges[x] = p;        /* 在表首插入 */
    g->degree[x]++;
    if (directed == false)
        insert_edge(g, y, x, true);
    else
        g->nedges++;
}

```

在屏幕上输出该数据结构所存储的图也就两重循环的事，一重循环遍取所有项点，另 -重循环遍取顶点的邻边：

```c
void print_graph(graph *g)
{
    int i;                  /* 计数器 */
    edgenode *p;            /* 暂用指针 */

    for (i = 1; i <= g->nvertices; i++) {
        printf("%d: ", i);
        p = g->edges[i];
        while (p != NULL) {
            printf(" %d", p->y);
            p = p->next;
        }
        printf("\n");
    }
}

```

以设计精良的图数据类型作为范本来构建自己的数据类型是个好主意.你也可以直接用那些范本作为应用程序的基础，这样会更好，我们推荐LEDA（参见19.1.1节）或Boost（参见19.1.3节），它们堪称现有通用图数据结构中设计最好的.LEDA和Boost可能比你所要的功能更强大（因此某种程度上更慢/更庞大），但是它们能很好地解决许多问题，因此大多数情况下你会非常乐意去放弃手忙脚乱的DIY过程中所带来的收获（当然也有可能一无所获）.

## 5.5 遍历图

最基本的图问题也许就是以一套系统性的方案去访问所有边和顶点.实际上，在图上所有简易的记账操作（例如在屏幕上输出图、复制图和各种图表示方法的等价转换）都是图遍历的应用. 迷宫可以很自然地以图表示，图中每个顶点代表迷宫的一个交叉点，而每条边则代表迷宫的一条通道.因此，要想被称为图遍历算法，那它就必须得能让我们从各式各样的迷宫中走出来.

出于算法效率的考虑，我们必须确保不会陷在迷宫中，也就是说不会重复访问同一个地点.出于算法正确性的考虑，我们必须以一套系统性的方案进行遍历以保证能够走出迷宫.一言以蔽之，我们的搜索必须走遍图中的每条边和每个顶点。图遍历的关键思想是每当我们首次访问一个项点时都要对其进行标记，并对那些邻边尚未探查完的顶点予以记录.尽管在神话故事中走迷宫会用面包屑或解开的线团标记已访问的地点，但程序里却没有这些道具，我们将凭借布尔标记或枚举类型去遍历. 每个顶点将处于以下三种状态其一；

- 未发现（undiscovered）

-尚未发现的项点处于其初始状态.

- 已找到（discovered）

-该项点已被发现，但我们还没有查完与其关联的边.

- 处理完（processed）所有与该顶点相关联的边都已访问过.

显而易见，只有在我们发现了某个项点后才能去处理它，因此每个顶点在整个遍历过程中的状态按未发现到已找到最后到处理完这样不断推进.

我们还必须维护一个结构，它包含着我们已找到但是尚未处理完的顶点.初始只有一个起始顶点，我们将其设为已找到状态。要想完全探查某个项点2，我们必须评测离开的每条边.如果某条边指向了一个未发现的顶点z，我们则将a标为已发现并把它加入列表等待随后的探查.要是一条边指向状态为处理完的顶点，我们可以忽略此边，因为再走老路不会让我们了解关于该图的新信息.我们还可以忽略所有指向已发现的顶点（尚未处理完），因为这种顶点早已存于待处理的顶点列表中.

每条无向边都会被恰好处理两次，分别发生在对它的两个端点探查的时候，有向边将只会被处理一次，发生在探查它的源顶点的时候.连通分量中的每条边和每个顶点最终都肯定会被访问.原因何在？我们假设存在一个一直未访问的项点u，它的邻接点已经访问过，该邻接点w终将被探查，那么随后我们肯定会去访问w.因此，我们必将找到所有那些等着被发现的顶点.

下面我们来描述这些遍历算法的运行机制以及遍历次序的重要意义.

```c

{

    int v;
    int y;
    edgenode *p;

    init_queue(&q);
    enqueue(&q, start);
    discovered[start] = true;

    while (empty_queue(&q) == false) {
        v = dequeue(&q);
        process_vertex_early(v);
        p = g->edges[v];

        while (p != NULL) {
            y = p->y;
            if ((processed[y] == false) || g->directed)
                process_edge(v, y);
            if (discovered[y] == false) {
                enqueue(&q, y);
                discovered[y] = true;
                parent[y] = v;
            }
            p = p->next;
        }
        process_vertex_late(v);
        processed[v] = true;
    }
}

```

## 5.7 广度优先搜索的应用

大多数的基本图算法会遍历图一或两次，与此同时我们也会增进对图的了解.用邻接表方案实现算法是正确的选择，此类算法肯定都是线性时间，因为广度优先搜索对于有向图和无向图都能在O（n+m）时间内运行完毕，这同时也是最优算法，因为我们读入有n个顶点和m条边的图至少就得这么久，不要指望能更快了. 窍门是搞清楚遍历方法在什么场景下能够必然奏效.下面我们将给出若干实例.

### 5.7.1 连通分量

“六度分离理论”认为，世界上任意两个人总会有一条较短的路径相连.我们称一个图是连通的，如果图中任意两个项点之间都有一条路径.如果这个理论是正确的，那意味着友谊图肯定是连通的. 无向图的连通分量（connected component）是满足任意顶点间都存在路径的一个最大项点子集.

因此图被切成了若干相互无关的“碎片”（连通分量），而碎片之间是无法连通的.如果我们设想远在世界的未知之地有个没有被发现的部落，那么它就会在友谊图中独自形成一个连通分量.一个离群索居的隐士或者一个极其烦人的家伙可能会代表一个仅有单个顶点的连通分量. 大量看上去很复杂的问题都可化简为寻找连通分量或对其计数的问题.

### 5.7.2 双色图
项点着色问题要给图中每个顶点指派一个标签（或颜色）使得没有边会连接两个同色顶点.我们可以给每个顶点都指派一个与其他点完全不一样的颜色，这样很容易就完全避免了冲突.然而，我们的目标是使用尽可能少的颜色，顶点着色问题通常出现在调度应用中，例如编译器中的寄存器分配.

## 5.8 深度优先搜索

图遍历算法主要有两种：广度优先搜索（Breadth-First Search, BFS）和深度优先搜索（Depth-First Search, DFS）. 对某些问题来说，用哪种搜索没一点区别，而在另一些问题中两种搜索之间的区别却是至关重要的. BFS和DFS之间的区别在于它们探查顶点的次序，而这完全取决于存储已找到但未处理完的顶点所用的容器.

- 队列——可在先入先出（FIFO）的队列中存储顶点，我们会先去探查最早入队的顶点.这样我们的探查从起始顶点开始缓慢地扩散开来，最后形成一个广度优先搜索，
- 栈—可在后进先出（LIFO）的栈中存储顶点，我们会沿着某条路径蹒跚前行去探查顶点，若是有新的邻居就去拜访它，并且只在我们完全被之前已找到的顶点包围时才回退到上层.这样我们的探查很快会从起始项点附近离开，最终形成一个深度优先搜索. 我们的dfs实现为每个项点引入了一个概念称为遍历时间并对其实时维护，每当我们进入或离开任意顶点时，我们的time时钟就会走一格.对每个顶点我们会记录进入时间和离开时间. 深度优先搜索有一个很简洁的递归实现，它可避免我们显式地在代码中使用栈：

```text
DFS(G, u)
    state[u] = “已找到”
    按实际需求对u进行处理
    time = time + 1
    entry[u] = time
    for each (v ∈ Adj[u]) do
        按实际需求对(u, v)这条边进行处理
        if state[v] = “未发现” then
            p[v] = u
            DFS(G, v)
    state[u] = “处理完”
    exit[u] = time
    time = time + 1

```

时间区间的特性很有意思，而且也非常有用，在深度优先搜索算法里有如下两条：

- 谁是祖先？——假设在深度优先搜索树中心是y的祖先.这意味着我们肯定是在进入y之前就已进入了z，因为没人能在自己的父亲或是祖父之前就生出来！另外，我们在离开a之前肯定已经离开y了，因为深度优先搜索的机制确保了我们不能先离开心，直到我们完成对所有子孙的搜索才能从离开进而回退到上一层.因此g的时间区间肯定真包含于祖先x的时间区间.
- 有多少个子孙？的离开时间和进入时间之差可以告诉我们w在深度优先搜索树中有多少个子孙，由于time时钟每次进入顶点和离开顶点时都会自增1，所以时间差值的一半就代表w的子孙数.

我们将在若干应用问题中使用深度优先搜索的进入和离开时间，特别是拓扑排序和双连通/强连通分量.我们得在顶点的入口和出口分别采取不同的操作，这样会让afs所调用的process_vertex_early和process_vertex_late子程序与前文不同.

深度优先搜索的另一个重要特性是，它将一个无向图的边恰好划分为两类：树边和反向边.树边会找到新项点，而这种父子关系会记录到parent数组中，反向边中一个端点是当前正在进行扩展的项点，而另一个端点则是该项点的祖先，所以这种边会指回到树中而不是扩展出新顶点.图5.10给出了一个具体实例.

图 5.10 一个无向图和它的深度优先搜索树深度优先搜索将所有边划为以上两类的这个特性让人非常惊奇.为什么一条边不能指向顶点的兄弟或表兄弟节点而只能是祖先节点呢？从给定顶点可达的节点在我们完成对w的遍历之前已经被扩展过，因此指向兄弟或表兄弟的这种拓扑对于无向图来说是不可能的.事实上，边的这种分类是证明基于深度优先搜索的算法其正确性的基石. 实现深度优先搜索可视为使用栈而非队列的广度优先搜索.以递归实现afs非常简单优美，同时我们也不必在遍历过程中自行维护一个栈去存储顶点.

```c
void dfs(graph *g, int v)
{
    edgenode *p;            /* 暂用指针 */
    int y;                  /* 下一顶点 */

    if (finished)
        return;             /* 允许搜索提前终止 */
    discovered[v] = true;
    time = time + 1;
    entry_time[v] = time;
    process_vertex_early(v);
    p = g->edges[v];
    while (p != NULL) {
        y = p->y;
        if (discovered[y] == false) {
            parent[y] = v;
            process_edge(v, y);
            dfs(g, y);
        }
        else if (((!processed[y]) && (parent[v] != y)) || (g->directed))
            process_edge(v, y);
        if (finished)
            return;
        p = p->next;
    }
    process_vertex_late(v);
    time = time + 1;
    exit_time[v] = time;
    processed[v] = true;
}

```

深度优先搜索所用的思想基本上与回溯是一致的，我们将在7.1节中学习回溯.这两种技术都需要尽全力深入前行去穷举搜索一切可能，如果继续向前搜索已无新发现则回退到上一层.二者都适合以递归算法形式描述，这样理解起来最简单.

> [!TIP]

> [!TIP] 所得教益：深度优先搜索利用进入/离开时间组织顶点，并据此将边划分为树边和反向边。这种组织结构让深度优先搜索发挥作用。

算法设计范式通常不算深奥，深度优先搜索也是如此。但它的细节并不简单，正确性取决于处理边和顶点的时机。

对于处理顶点的时间，可以选在尚未遍历的出边之前（process- vertex_early（）），也可以选在处理完所有出边之后（process_vertex_late（））. 有时我们在两个时间点都会采取一定的操作，也就是说，process_vertex_early（）会初始化一个数据结构来记录不同顶点的信息，而这些信息将会在处理边的时候进行更新，最后再用process_vertex_1ate（）去分析加工. 无向图中每条边（z,g）既在项点z的邻接表中又在顶点y的邻接表中，因此对任意一条边（z,g），我们有两个处理它的时间点，也就是在探查a和探查g的时候.

将一条边标记为树边或反向边出现在这条边首次被探查到的时候.我们第一次看到某条边时，通常是处理这条边最合理的时机.有时我们想在第二次见到同一条边时去做一些不同的操作。但是，当我们在探查z时遇到了（z，g）这条边，如何判断我们之前是否已经在探查g时遍历过这条边呢？如果顶点g的状态是未发现，那么这个问题很简单：（z,g）此时己成为树边，因此这肯定是第一次遇到（z,g）.如果y已被处理完，这个问题也很简单：因为当我们探查g时已经查过这条边，因此这肯定也是第一次.

可是如果y是x的祖先，也就是说g的状态是已找到，答案又是什么呢？这肯定是我们的第一次遍历，除非y是z的父亲——也就是说（3，2）是一条树边（可通过测试y== parent［x］成立与否来确定），仔细思考一下你就会确信这个结论是正确的. 我发现每当我试着实现一个基于深度优先搜索的算法时，其中所蕴含的微妙之处都能让我有新的体会.

我强烈建议你仔细分析下面这些实现，看看哪里会有疑难情况并把它们搞清楚.

## 5.9 深度优先搜索的应用

### 5.9.1 寻找环
反向边是在无向图中寻找环的关键.如果没有反向边那么所有边都是树边，而树中并不存在环，不过，只要有从z到其祖先g的反问边，就会创建一个包含从y到z路径的环.这个环用dfs很容易找到：

```c
void process_edge(int x, int y)
{
    if (discovered[y] && (parent[x] != y)) {  /* 找到反向边！ */
        printf("Cycle from %d to %d: ", y, x);
        find_path(y, x, parent);
        printf("\n\n");
        finished = true;
    }
}

```

这个环检测算法之所以正确，是因为我们可保证会处理每条无向边且仅在第一次遇到时检测处理.否则任何一条无向边的两次遍历都能建立一个两顶点假环（z，g,z）.找到首个环之后我们利用finished标志提前退出.

## 5.10 有向图的深度优先搜索

我们已经看到无向图的深度优先搜索是非常有用的，因为它对图中的边给出了很清晰的组织结构，如图5.10所示. 遍历无向图时，每条边要么在深度优先搜索树中，要么是指向树中祖先的反向边，让我们再回想一下原因.假设我们遇到了一个指向子孙顶点的“正向边”（z,g）.在这种情况下，早在探查y的时候我们就会找到（z，3）并已让它成为反向边.

假设我们遇到了一个将两个无关顶点连接起来的“跨越边”（z，g）.同样是早在我们探查y时就会找到这条边，不过会让它成为树边. 对于有向图而言，深度优先搜索中能为边标出的类型会更加多样化.实际上图5.14中边的4种情况全都有可能出现在有向图遍历中，事实证明这种分类在处理有向图算法时仍然是非常有用的.

我们通常会对不同情况下的边采用不同的操作. 树边正向边反向边跨越边图 5.14 深度优先搜索/广度优先搜索在遍历时所遇到的边可能出现的4种情况每条边可以很容易地依据其端点的状态、进入时间以及父子关系来正确地标记这条边，其函数实现请看下面的代码：

```c
int edge_classification(int x, int y)
{
    if (parent[y] == x)
        return TREE;

    if (discovered[y] && !processed[y])
        return BACK;
    if (processed[y] && (entry_time[y] > entry_time[x]))
        return FORWARD;
    if (processed[y] && (entry_time[y] < entry_time[x]))
        return CROSS;

    printf("Warning: unclassified edge (%d, %d) \n", x, y);
}

```

### 5.10.1 拓扑排序
拓扑排序是有向无环图（DAG）上最重要的操作.它会将所有项点排成一条直线并使所有的有向边都从左指向到右，图5.15给出了一个具体实例.图若包含有向环则不会存在这样的排序，因为你没办法在环线上一直向右，事实上你还会回到起始点！每个有向无环图都至少有一个拓扑排序.拓扑排序的重要性是它会给我们一种工序每个项点有若干后续顶点，当前项点若未处理完则所有后续顶点不能开工.假设边代表优先权的约束，那么（z，g）这条边则意味着任务必须在任务y之前完成.那么任何拓扑排序就定义了一个合规的调度.实际上，对于给定的一个有向无环图存在很多这样的排序. 但是实际应用中需要你更深入地探讨拓扑排序.假设我们要在有向无环图中寻找从x到g的最短（或最长）路径.拓扑序关系下出现于y之后的顶点对于寻找此类路径一点用处

E F G 图 5.15 一个只有一种拓扑排序（G, A,B,C,E,E,D）的有向无环图都没有，因为没办法从它们那里回到y.我们可在拓扑序关系下从左到右依次对所有顶点进行恰当的处理即可，注意不仅要考虑它们的出边所带来的影响，还要明了我们每步所需的信息在之前已经全部看到了，事实证明，拓扑排序基本上在任何有向图的算法问题中都起着至关重要的作用，15.2节中的相关讨论便是明证. 拓扑排序可用深度优先搜索高效地完成.一个有向图是有向无环图当且仅当我们遇不到反向边.逆向依次记录标为处理完的顶点，便可找到有向无环图的一个拓扑排序，为什么呢？对于每条有向边（z,3），考虑当我们探查项点z遇到这条边时会发生什么情况：

- 如果y目前未发现，那么我们得开始对y的深度优先搜索，完成后才能继续处理z.因此g在之前就会被标为处理完，那么在拓扑序关系中心出现于在g之前，事实上也必须在y之前.
- 如果y现在已找到但是没有处理完，那么（z,g）是一条反向边，而有向无环图中绝不允许有这种边出现.
- 如果y已经处理完，它将会在z处理完之前早已标记过了.因此在拓扑序关系中心出现于在y之前，事实上z也必须在y之前.

### 5.10.2 强连通分量
我们经常会关注强连通分量将图分为尽可能大的若干块并使任意块中的所有顶点对之间存在有向路径.如果有向图中任意两个顶点之间存在一条有向路径，那么该图就是强连通图（strongly connected graph）. 公路网应该是强连通图，否则就会存在某些地方，你可以从家开车到那里，但是无法在不违反单行标志的情况下开回家，使用图的遍历去测试某个图G=（V,E）是否为强连通图很简单，而且可在线性时间内完成.首先，从任意顶点心开始一个搜索.

要是从心开始可到达图中每个顶点（也就是说从心开始的广度优先搜索或深度优先搜索可找到所有顶点），这样当然最好，要不然G就不可能是强连通图.现在我们创建一个图G”=（V'，E），其顶点集和G一样，而边集则是G中所有的边反转而得—也就是说有向边（g,2） E'当且仅当（z,g）€E.因此G'中任意从到z的路径都对应着G中从z到的路径.

通过从G'中的心开始进行深度优先搜索，我们便能找到G中所有能通过有向路径到达v的那些顶点.该图是强连通图当且仅当G中全部顶点满足：既可到达也能从到达. 非强连通的图可划分为若干强连通分量，如图5.16（左）所示.我们可通过深度优先搜索来找出此类强连通分量的集合，以及将这些分量连到一起的弱连通边.

我们观察到利用深度优先搜索很容易找到有向环，这是因为深度优先搜索树中任意反向边再配以向下的树边便可给出这样的环，可据此设计强连通分量算法.该有向环中所有顶点肯定位于同一个强连通分量中，因此，我们可以将环上的顶点收缩为能代表该环的单一顶点，然后再重复这个过程.当图中不再存在有向环时，上述操作将会停止，最后剩下的每个项点代表一个不同的强连通分量. 我们实现这个想法的方案会让你联想到寻找双连通分量问题（5.9.2节）.

我们将可到达的最老顶点这个概念加以改动，从而适应有向图的独有性质：（1）存在非树边，（2）从某顶点可能会返回到其他分量中，因为算法在有向图上运行，我们还得去应对正向边（从一个顶点图 5.16 一个图的强连通分量（左）与该图相关的深度优先搜索树（右）到它的子孙）和跨越边（从一个项点指回到一个非祖先但之前已找到的顶点）.我们的算法每次会从树中剥离一个强连通分量，并将分量编号指派给该分量中的每个项点.

我们将1ow［v］定义为v能遇到的最老项点，但得确认该项点和v在同一个强连通分量中，这个项点不必是v的祖先，但也许会是v的一位远房表兄弟，原因是有向图中可能存在跨越边，指向图中业已形成的强连通分量中某个项点的那种跨越边对我们来说毫无用处，因为没办法从那里再回到v，不过指向同一个强连通分量的跨越边会和反向边一起公平竞争最老顶点.正向边对于深度优先搜索树中边的可达性没有任何影响，因此可将其忽略：

int low[MAXV + 1];         /* v能遇到的最老且肯定位于v所在分量的顶点 */

process_edge(int x, int y)
{
    int class;              /* 边的分类 */

    class = edge_classification(x, y);
    if (class == BACK) {
        if (entry_time[y] < entry_time[low[x]])
            low[x] = y;
    }
    if (class == CROSS) {
        if (scc[y] == -1)    /* 分量编号尚未获取 */

                low[x] = y;
    }
}

只要从v可到达的最低顶点是v，就意味着找到了新的强连通分量.如果是这样的话我们就将栈中位于该分量的所有顶点清空，反之则将这个可以到达和追溯的最老祖先的信息告知v的父亲，这样它也能从中获益.

```c
void process_vertex_early(int v)
{
    push(&active, v);
}

void process_vertex_late(int v)
{
    if (low[v] == v) {
        pop_component(v);  /* (parent[v], v) 这条边切开了强连通分量 */
    }
    if (parent[v] > 0) {   /* 仅当v不为根 */
        if (entry_time[low[v]] < entry_time[low[parent[v]]])
            low[parent[v]] = low[v];
    }
}

void pop_component(int v)
{
    int t;                  /* 用于暂时存储顶点 */
    components_found = components_found + 1;
    scc[v] = components_found;
    while ((t = pop(&active)) != v) {
        scc[t] = components_found;
    }
}

```

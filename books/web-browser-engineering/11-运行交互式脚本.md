# 第 9 章　运行交互式脚本

*Chapter 9: Running Interactive Scripts*

最早的 Web 应用就像上一章的留言簿（guest book）那样：用户的每一个操作，都要由服务器生成一个全新的网页。但到了 2000 年代初期，用 JavaScript 增强的 Web 应用取而代之——这类应用能够动态更新页面，并对用户的操作立即做出响应。下面，我们就来为浏览器添加对这项关键 Web 技术的支持。

## 9.1 安装 DukPy

亲手编写一个 JavaScript 解释器（interpreter）超出了本书的范围，¹ 所以本章使用 dukpy 库来执行 JavaScript。

DukPy [1] 封装了一个名为 Duktape [2] 的 JavaScript 解释器。最著名的 JavaScript 解释器当属浏览器所用的那些：TraceMonkey（Firefox）、JavaScriptCore（Safari）和 V8（Chrome）。这些实现速度极快，但也极其复杂；与它们不同，Duktape 追求简单和可扩展，通常被嵌入到更大的 C 或 C++ 项目之中。²

和其他 JavaScript 引擎一样，DukPy 不仅能执行 JavaScript 代码，还允许这些代码调用导出的 Python 函数。我们将利用这一特性，让 JavaScript 代码能够修改它正在其上运行的网页。

使用 DukPy 的第一步是安装它。在大多数机器上——包括 Windows、macOS 和 Linux 系统——你应该都可以用下面这条命令完成安装：

```
python3 -m pip install dukpy
```

> **安装**
> 如果你的 Python 版本实在太旧，可能得先安装 pip 包，也许还要用到命令行的 easy_install。如果你是通过集成开发环境（IDE）来编写 Python 的，可能需要用该 IDE 的包安装器。如果以上都不奏效，你还可以从源码自行构建。如果你跟随本书时用的不是 Python，可能需要跳过本章，不过也可以尝试直接绑定 dukpy 所使用的 duktape 库。

要测试 DukPy 是否安装正确，可以执行这段代码：

```python
import dukpy
dukpy.evaljs("2 + 2")
```

如果第一行就报错，说明你多半没把 DukPy 装上。³ 如果第二行报错，或者出现段错误（segfault），则有可能是 Duktape 编译失败，或者不支持你的系统，你可能需要进一步排查。

> **怪癖**
> 给 JavaScript 老手的提示：DukPy 并不实现 `let`、`const` 或箭头函数等较新的语法。为了契合本书的审美，你需要使用世纪之交那种「老派」的 JavaScript。

## 9.2 运行 JavaScript 代码

上面的测试展示了在 DukPy 中运行 JavaScript 代码的方式：直接调用 evaljs 就可以了！下面我们就把这门新本领用到浏览器里。

在 Web 上，JavaScript 存放在 `<script>` 标签中。通常，`<script>` 标签带有一个 `src` 属性，其值是一个相对 URL，指向某个 JavaScript 文件，这一点和 CSS 文件很像。`<script>` 标签也还可以在起始标签和结束标签之间直接包含 JavaScript 源代码，但我们不去实现这一点。⁴

查找并下载这些脚本的过程，与我们在 CSS 中的做法类似。首先，我们要找出所有脚本：

```python
class Tab:
    def load(self, url, payload=None):
        # ...
        scripts = [node.attributes["src"] for node
                   in tree_to_list(self.nodes, [])
                   if isinstance(node, Element)
                   and node.tag == "script"
                   and "src" in node.attributes]
        # ...
```

接着，运行所有脚本：

```python
def load(self, url, payload=None):
    # ...
    for script in scripts:
        script_url = url.resolve(script)
        try:
            body = script_url.request()
        except:
            continue
        print("Script returned: ", dukpy.evaljs(body))
    # ...
```

这些代码应当在样式计算和布局之前运行。要试用一下，先创建一个带 script 标签的简单网页：

```html
<script src=test.js></script>
```

然后往 test.js 里写一个极其简单的脚本，比如这样：

```javascript
var x = 2
x + x
```

把浏览器指向那个页面，你应该会看到：

```text
Script returned: 4
```

这就是你的浏览器运行的第一段 JavaScript！

> **深入探索**
> 实际上，真实浏览器在解析到 `<script>` 标签的那一刻就会运行其中的 JavaScript 代码，而不是等整个页面解析完毕。至少，默认行为是这样的；实际存在很多选项 [3]。我们浏览器的做法，相当于真实浏览器设置了 `defer` [4] 属性之后的行为。默认行为要想高效实现，要棘手得多 [5]。

## 9.3 导出函数

目前，我们的浏览器只是把脚本中最后一个表达式的值打印出来；而在真实浏览器中，脚本必须调用 console.log 函数来打印。为了支持这一点，我们需要把一个函数从 Python 导出到 JavaScript。后面要导出的函数会很多，为了不给 Tab 对象塞进一堆新方法、把它搞得一团糟，我们把这类代码放进一个新的 JSContext 类：

```python
class JSContext:
    def __init__(self):
        self.interp = dukpy.JSInterpreter()
    def run(self, code):
        return self.interp.evaljs(code)
```

DukPy 的 JSInterpreter 对象保存着所有 JavaScript 变量的值，让我们可以运行多段 JavaScript 代码片段，并在它们之间共享变量值和其他状态。

我们在加载页面时创建这个新的 JSContext 对象：

```python
class Tab:
    def load(self, url, payload=None):
        # ...
        self.js = JSContext()
        for script in scripts:
            # ...
            self.js.run(body)
```

对所有脚本使用同一个 JSContext 还有一个附带好处：现在可以运行两个脚本，让其中一个定义变量、另一个使用该变量，比如在这样一个页面上：

```html
<script src=a.js></script>
<script src=b.js></script>
```

假设 a.js 的内容是 `var x = 2;`，b.js 的内容是 `console.log(x + x)`；变量 x 在 a.js 中赋值，却在 b.js 中使用。在真实的 Web 浏览器里，这很常见，因为一个脚本定义的库函数，可能正是另一个脚本想要调用的。

接下来，为了让 JavaScript 能与外部世界交互，DukPy 允许我们向它「导出」函数。例如，我们可以像这样导出 Python 的 print 函数：

```python
class JSContext:
    def __init__(self):
        # ...
        self.interp.export_function("log", print)
```

在 JavaScript 里，可以用 DukPy 的 call_python 函数来调用导出的函数。例如：

```javascript
call_python("log", "Hi from JS")
```

示意图：浏览器 --evaljs--> JavaScript（浏览器求值执行 JavaScript 代码）；JavaScript --call_python--> 浏览器（JavaScript 回调浏览器导出的 Python 函数）。

*图 9.1　浏览器可以求值执行 JavaScript，而 JavaScript 代码也可以回调浏览器。*

这段 JavaScript 运行时，DukPy 会把 JavaScript 字符串 "Hi from JS" 转换成 Python 字符串，⁵ 然后把这个 Python 字符串传给我们导出的 print 函数，由 print 把它打印出来。

由于我们的最终目标是拥有 console.log [6] 函数，而不是 call_python 函数，因此需要定义一个 console 对象，再给它一个 log 属性。这可以用 JavaScript 完成：

```javascript
console = { log: function(x) { call_python("log", x); } }
```

如果你对 JavaScript 不太熟，⁶ 说明一下：这段代码定义了一个名为 console 的变量，它的值是一个对象字面量（object literal），带有一个属性 log，而 log 的值是一个调用 call_python 的函数。浏览器与 JavaScript 之间的交互如图 9.1 所示。

我们可以把这段 JavaScript 代码称作我们的「JavaScript 运行时（runtime）」；它要在任何用户代码之前运行，所以我们把它放进 runtime.js 文件，并在 JSContext 创建时——也就是运行任何用户代码之前——执行它：

```python
RUNTIME_JS = open("runtime.js").read()
class JSContext:
    def __init__(self):
        # ...
        self.interp.evaljs(RUNTIME_JS)
```

现在，你应该可以把 `console.log("Hi from JS!")` 放进一个 JavaScript 文件，从浏览器中运行它，并在终端里看到输出。你也应该可以多次调用 console.log。

退一步看：当我们在浏览器中运行 JavaScript 时，实际上混合了几种东西——实现 JavaScript 解释器的 C 代码；实现某些 JavaScript 函数的 Python 代码；把 Python API 包装得更像 JavaScript API 的 JavaScript 运行时；当然，还有一段用 JavaScript 写成的用户代码。这里的复杂度可不小！

> **深入探索**
> 如果一个脚本长时间运行，或者出现死循环，我们的浏览器就会卡住，完全无法响应用户。这是 JavaScript 的单线程语义及其基于任务的「运行至完成」（run-to-completion）调度 [8] 所导致的。某些 API（如 Web Workers [9]）允许有限度的多线程，但这些线程无法访问 DOM。

## 9.4 处理崩溃

JavaScript 代码的崩溃，调试起来令人抓狂。你可以通过写出糟糕的代码来引发崩溃，也可以显式抛出异常，就像这样：

```javascript
throw Error("bad");
```

当网页运行的 JavaScript 崩溃时，浏览器应当忽略这次崩溃。网页可不能把我们的浏览器搞垮！可以这样实现：

```python
class JSContext:
    def run(self, script, code):
        try:
            return self.interp.evaljs(code)
        except dukpy.JSRuntimeError as e:
            print("Script", script, "crashed", e)
```

不过，随着本章内容的推进，你还会碰到另一类崩溃：我们自己的 JavaScript 运行时中的崩溃。这类崩溃不能忽略，因为那是我们自己的代码。调试它们是件苦差事：DukPy 默认不显示回溯（backtrace），而如果运行时代码又调用了某个导出函数且该函数崩溃，情况就更加混乱。

下面是应对这类崩溃的几点技巧。首先，如果崩溃发生在某个 JavaScript 函数内部，可以这样包裹该函数的函数体：

```javascript
function foo() {
    try {
        // ...
    } catch(e) {
        console.log("Crash in function foo()", e.stack);
        throw e;
    }
}
```

这段代码会捕获所有异常，并在重新抛出之前先打印堆栈跟踪（stack trace）。如果崩溃发生在一个导出函数内部，你则需要在 Python 一侧包裹那个函数：

```python
class JSContext:
    def foo(self, arg):
        try:
            # ...
        except:
            import traceback
            traceback.print_exc()
            raise
```

这些问题调试起来并不轻松，因为 Python 与 JavaScript 之间的这些调用交织得相当复杂。正因为这类 bug 很难缠，调试时才更值得按部就班地来，先收集大量信息，再着手修复。

## 9.5 返回句柄

到目前为止，JavaScript 的求值虽然有趣，却没什么用处，因为 JavaScript 无法对页面本身做出任何修改。（如果 JavaScript 除了打印什么也干不了，那还运行它做什么？谁会去盯着浏览器的控制台输出看呢？）我们需要允许 JavaScript 修改页面。

JavaScript 通过调用一大类方法来操纵网页，这些方法统称为 DOM API。DOM API 规模庞大，而且还在不断变大，所以我们不会实现它的全部，甚至不会实现其中的大部分。但有几个核心函数足以体现完整 API 的关键要素：

- querySelectorAll 返回与选择器匹配的所有元素；
- getAttribute 返回元素某个属性的值；
- innerHTML 用新的 HTML 替换元素的内容。

我们将实现这些 API 的简化版本。⁷

先从 querySelectorAll 开始。首先，导出一个函数：

```python
class JSContext:
    def __init__(self):
        # ...
        self.interp.export_function("querySelectorAll",
            self.querySelectorAll)
        # ...
```

在 JavaScript 中，querySelectorAll 是 document 对象上的方法，我们需要在 JavaScript 运行时中定义它：

```javascript
document = { querySelectorAll: function(s) {
    return call_python("querySelectorAll", s);
}}
```

在 Python 一侧，querySelectorAll 首先要解析选择器，然后找出并返回匹配的元素。解析选择器时，我会调用 CSSParser 的 selector 方法：⁸

```python
class JSContext:
    def querySelectorAll(self, selector_text):
        selector = CSSParser(selector_text).selector()
```

接下来要找出并返回所有匹配的元素。为此，JSContext 需要能访问 Tab，尤其是它的 nodes 字段。所以在创建 JSContext 时，把 Tab 传进来：

```python
class JSContext:
    def __init__(self, tab):
        self.tab = tab
        # ...
class Tab:
    def load(self, url, payload=None):
        # ...
        self.js = JSContext(self)
        # ...
```

现在，querySelectorAll 就能找出所有匹配选择器的节点了：

```python
def querySelectorAll(self, selector_text):
    # ...
    nodes = [node for node
             in tree_to_list(self.tab.nodes, [])
             if selector.matches(node)]
```

最后，我们需要把这些节点返回给 JavaScript。你可能会想这样写：

```python
def querySelectorAll(self, selector_text):
    # ...
    return nodes
```

然而，这会抛出一个错误：⁹

```text
_dukpy.JSRuntimeError: EvalError:
Error while calling Python Function:
TypeError('Object of type Element is not JSON serializable')
```

示意图：JavaScript 一侧有 Window、Node、Element 等对象；浏览器一侧有 Element 与 Text 构成的节点树；JavaScript 的每个 Node 都通过一个 handle（句柄）与浏览器侧对应的 Element 相关联。

*图 9.2　JavaScript 中的 Node 对象与浏览器中的 Element/Text 对象之间的关系，是通过句柄来维护的。*

DukPy 想告诉你的是：它完全不知道拿 querySelectorAll 返回的 Element 对象怎么办。毕竟，Element 类只存在于 Python 中，JavaScript 里可没有！

Python 对象必须留在浏览器的 Python 一侧，因此 JavaScript 代码需要通过某种间接方式来引用它们。我会使用一个简单的数字标识符，并把它称为句柄（handle）（见图 9.2）。¹⁰

我们需要记录句柄与节点之间的映射关系。先创建一个 node_to_handle 数据结构，把节点映射到句柄，再建一个反方向的 handle_to_node 映射：

```python
class JSContext:
    def __init__(self, tab):
        # ...
        self.node_to_handle = {}
        self.handle_to_node = {}
        # ...
```

现在，querySelectorAll 的处理函数可以为每个节点分配句柄，并改为返回这些句柄：

```python
def querySelectorAll(self, selector_text):
    # ...
    return [self.get_handle(node) for node in nodes]
```

get_handle 函数应当在句柄尚不存在时创建一个新句柄：

```python
class JSContext:
    def get_handle(self, elt):
        if elt not in self.node_to_handle:
            handle = len(self.node_to_handle)
            self.node_to_handle[elt] = handle
            self.handle_to_node[handle] = elt
        else:
            handle = self.node_to_handle[elt]
        return handle
```

如此一来，querySelectorAll 的处理函数返回的就类似 [1, 3, 4, 7]，其中每个数字都是某个元素的句柄，DukPy 可以毫无障碍地把它们转换成 JavaScript 对象。当然，在 JavaScript 一侧，querySelectorAll 不应该返回一堆数字，而应该返回一个 Node 对象的列表。¹¹ 所以，让我们在运行时中定义一个包装句柄的 Node 对象：¹²

```javascript
function Node(handle) { this.handle = handle; }
```

我们在 querySelectorAll 的包装函数里创建这些 Node 对象：¹³

```javascript
document = { querySelectorAll: function(s) {
    var handles = call_python("querySelectorAll", s);
    return handles.map(function(h) { return new Node(h) });
}}
```

## 9.6 包装句柄

现在我们有了一些 Node，能拿它们做什么呢？一个简单的 DOM 方法是 getAttribute——Node 对象上的一个方法，让你能够获取 HTML 属性的值。实现 getAttribute 意味着解决与 querySelectorAll 相反的问题：把 JavaScript 一侧的 Node 对象传送到 Python 那边去。

解决办法与 querySelectorAll 类似：不传送 Node 对象本身，而是传送它的句柄：

```javascript
Node.prototype.getAttribute = function(attr) {
    return call_python("getAttribute", this.handle, attr);
}
```

在 Python 一侧，getAttribute 函数接收两个参数：一个句柄和一个属性名：

```python
class JSContext:
    def getAttribute(self, handle, attr):
        elt = self.handle_to_node[handle]
        attr = elt.attributes.get(attr, None)
        return attr if attr else ""
```

注意，如果该属性没有被赋值，get 方法会返回 None，而 DukPy 会把它转换成 JavaScript 的 null。别忘了把这个函数导出为 getAttribute。

我们终于凑齐了足够的 DOM API，可以为文本输入区实现一个小小的字符计数功能了：

```javascript
inputs = document.querySelectorAll('input')
for (var i = 0; i < inputs.length; i++) {
    var name = inputs[i].getAttribute("name");
    var value = inputs[i].getAttribute("value");
    if (value.length > 100) {
        console.log("Input " + name + " has too much text.")
    }
}
```

不过，理想情况下，我们希望每次用户在输入框中打字时都更新字符计数。这就要求每次按键都运行 JavaScript。接下来就实现它。

> **深入探索**
> DOM 中的 Node 对象对应于浏览器中的 Element 节点。因此，它们既有 JavaScript 对象属性（property），也有 HTML 属性（attribute）。这两者很容易混淆；更糟的是，许多 DOM 对象属性会自动「反射」（reflect）[11] 属性的值。例如，Node 对象上的 id 属性提供了对底层 Element 的 id 属性 [12] 的读写访问。这非常方便，免得到处调用 setAttribute 和 getAttribute。但这种反射只适用于特定的字段；设置凭空捏造的 JavaScript 属性并不会创建相应的 HTML 属性，反过来也一样。

## 9.7 事件处理

浏览器一加载完网页就会执行 JavaScript 代码，而这些代码往往希望根据用户的操作来改变页面。

其工作原理是：每当用户与页面交互，浏览器就会生成事件（event）。每个事件都有一个类型，比如 change、click 或 submit，并且发生在某个目标元素上。addEventListener 方法让 JavaScript 能够响应这些事件：`node.addEventListener("click", func)` 会设置 func，使其在 node 对应的元素每次产生 click 事件时运行。它基本上就是浏览器版的 Tk 的 bind——见图 9.3。我们来实现它。

先从生成事件开始。我会创建一个 dispatch_event 方法，并在每次事件产生时调用它。这首先包括在页面中点击的任何时候：

示意图：浏览器 --run--> JavaScript（运行脚本）；JavaScript --addEventListener--> 浏览器（注册监听器）；JavaScript --querySelectorAll--> 浏览器（查询元素）；用户点击后，浏览器把 click 事件派发回 JavaScript 中的监听器。

*图 9.3　事件发生时，浏览器会调用 JavaScript。*

```python
class Tab:
    def click(self, x, y):
        # ...
        elif elt.tag == "a" and "href" in elt.attributes:
            self.js.dispatch_event("click", elt)
            # ...
        elif elt.tag == "input":
            self.js.dispatch_event("click", elt)
            # ...
        elif elt.tag == "button":
            self.js.dispatch_event("click", elt)
            # ...
        # ...
```

其次，在更新输入区内容之前：

```python
class Tab:
    def keypress(self, char):
        if self.focus:
            self.js.dispatch_event("keydown", self.focus)
            # ...
```

最后，在提交表单时、但还没真正把请求发给服务器之前：

```python
def submit_form(self, elt):
    self.js.dispatch_event("submit", elt)
    # ...
```

到目前为止一切顺利——可是 dispatch_event 方法该做些什么呢？它需要运行传给 addEventListener 的监听器（listener），所以这些监听器得找个地方存起来。由于这些监听器是 JavaScript 函数，这部分数据要保存在 JavaScript 一侧，放在运行时的某个变量里。我把这个变量叫作 LISTENERS；我们要用它按句柄和事件类型来查找，所以让它把句柄映射到一个字典，字典再把事件类型映射到监听器列表：

```javascript
LISTENERS = {}
Node.prototype.addEventListener = function(type, listener) {
    if (!LISTENERS[this.handle]) LISTENERS[this.handle] = {};
    var dict = LISTENERS[this.handle];
    if (!dict[type]) dict[type] = [];
    var list = dict[type];
    list.push(listener);
}
```

要派发一个事件，需要在 LISTENERS 中按类型和句柄查找，像这样：

```javascript
Node.prototype.dispatchEvent = function(type) {
    var handle = this.handle;
    var list = (LISTENERS[handle] && LISTENERS[handle][type]) || [];
    for (var i = 0; i < list.length; i++) {
        list[i].call(this);
    }
}
```

注意，dispatchEvent 用到了函数的 call 方法，它会设置该函数内部 this 的值。按照 JavaScript 的惯例，我把它设置为事件所发生的那个节点。

当事件发生时，浏览器从 Python 一侧调用 dispatchEvent：

```python
class JSContext:
    def dispatch_event(self, type, elt):
        handle = self.node_to_handle.get(elt, -1)
        self.interp.evaljs(
            EVENT_DISPATCH_JS, type=type, handle=handle)
```

这里的 EVENT_DISPATCH_JS 常量是一段用来派发新事件的 JavaScript 代码字符串：

```python
EVENT_DISPATCH_JS = \
    "new Node(dukpy.handle).dispatchEvent(dukpy.type)"
```

于是，在 Python 一侧调用 dispatch_event，就会运行 JavaScript 一侧的 dispatchEvent，后者进而运行所有的事件监听器。这段代码里的 dukpy JavaScript 对象，保存着传给 evaljs 的具名参数 type 和 handle。

有了这整套事件处理机制，每当输入区发生变化时，我们就能更新字符计数了：

```javascript
function lengthCheck() {
    var name = this.getAttribute("name");
    var value = this.getAttribute("value");
    if (value.length > 100) {
        console.log("Input " + name + " has too much text.")
    }
}
var inputs = document.querySelectorAll("input");
for (var i = 0; i < inputs.length; i++) {
    inputs[i].addEventListener("keydown", lengthCheck);
}
```

注意，lengthCheck 用 this 来引用真正发生变化的那个输入元素，这是由 dispatchEvent 设置好的。

到目前为止一切都好——不过理想情况下，长度检查不应该打印到控制台，而应该把警告加到网页本身上。要做到这一点，我们不仅要能读取页面，还要能修改页面。

> **深入探索**
> JavaScript 于 1995 年 [13] 诞生，是 Netscape Navigator 的一部分。它的名字是为了显示其与 Java [14] 语言的相似性，它的语法也正是因此带着 Java 味。然而在表象之下，JavaScript 是一门远比 Java 动态的语言——考虑到它作为 Web 渐进增强机制的角色，这一点恰如其分。例如，任何对象（包括 Element 之类的内建对象）上的任何方法或属性，都可以在任何时候被动态覆盖。正因如此，才有可能用 polyfill（垫片）[15] 来弥合浏览器之间的差异，为其他 JavaScript 代码添加看上去如同内建的功能。

## 9.8 修改 DOM

到目前为止，我们实现的 DOM 方法都是只读的；现在需要能改变页面的方法了。完整的 DOM API 提供了许多这类方法，但为了简单起见，我只实现 innerHTML，它的用法如下：

```javascript
node.innerHTML = "This is my <b>new</b> bit of content!";
```

换句话说，innerHTML 是 node 对象的一个属性，带有一个在该字段被修改时运行的设置器（setter）。这个设置器接收新值（它必须是一个字符串），把它当作 HTML 来解析，并让解析出来的新 HTML 节点成为原节点的子节点。

我们来着手实现，先从 JavaScript 一侧开始。JavaScript 有一个冷僻的 Object.defineProperty 函数可以用来定义设置器，DukPy 支持它：

```javascript
Object.defineProperty(Node.prototype, 'innerHTML', {
    set: function(s) {
        call_python("innerHTML_set", this.handle, s.toString());
    }
});
```

在 innerHTML_set 中，我们需要解析 HTML 字符串。这件事实际比你想的要棘手，因为我们浏览器的 HTML 解析器是为解析完整的 HTML 文档而设计的，而不是这种文档片段（fragment）。作为一种权宜的、大体够用的变通手法，¹⁴ 我就直接把这段 HTML 包进 html 和 body 元素里：

```python
def innerHTML_set(self, handle, s):
    doc = HTMLParser("<html><body>" + s + "</body></html>").parse()
    new_nodes = doc.children[0].children
```

别忘了导出 innerHTML_set 函数。注意，我们提取的是 body 元素的所有子节点，因为一次 innerHTML_set 调用可能同时创建多个节点。这些新节点现在必须成为调用 innerHTML_set 的那个元素的子节点：

```python
def innerHTML_set(self, handle, s):
    # ...
    elt = self.handle_to_node[handle]
    elt.children = new_nodes
    for child in elt.children:
        child.parent = elt
```

我们要更新这些解析出来的子节点的 parent 指针，否则它们会指向我们为了辅助解析而添加的那个假 body 元素。

看起来大功告成了——可你一试就会发现，脚本调用 innerHTML_set 后什么也没有发生。这是因为，我们虽然改了 HTML 树，却没有重新生成布局树和显示列表，浏览器展示的还是旧页面。

每当页面发生变化，我们都需要调用 render 来更新渲染：¹⁵

```python
class JSContext:
    def innerHTML_set(self, handle, s):
        # ...
        self.tab.render()
```

JavaScript 现在可以修改网页了！¹⁶

我们到留言簿里试一试。假设我们想给留言簿条目加上 100 字符的限制，免得冗长而不知所云的牢骚话混进来。首先，切换到服务器代码库，在留言簿表单后面添加一个 `<strong>`。起初这个元素是空的，但一旦段落太长，我们就往里面写一条错误消息。

> **深入探索**
> 这段代码有一个不易察觉的内存泄漏（memory leak）：如果你在 JavaScript 中访问某个 HTML 元素（从而为它创建了句柄），然后又（用 innerHTML）把该元素从页面上移除，Python 将无法对这个 Element 对象进行垃圾回收（garbage collection），因为它仍然存储在 node_to_handle 映射里。如果 JavaScript 还能通过句柄访问那个 Element，这是好事；否则就是坏事。解决这个问题相当棘手，因为它需要 Python 和 JavaScript 的垃圾回收器相互协作 [17]。

## 9.9 事件默认行为

到目前为止，事件产生后，浏览器会运行监听器，然后照旧执行它通常为该事件所做的动作——默认动作（default action）。现在，我希望 JavaScript 代码能够取消这个默认动作。这需要几步。首先，事件监听器应当接收一个事件对象作为参数。该对象应有一个 preventDefault 方法；当这个方法被调用时，默认动作就不应发生。

首先，我们需要事件对象。回到我们的 JavaScript 运行时：

```javascript
function Event(type) {
    this.type = type
    this.do_default = true;
}
Event.prototype.preventDefault = function() {
    this.do_default = false;
}
```

注意 do_default 字段，它用来记录 preventDefault 是否已被调用。现在，我们要给 dispatchEvent 传一个 Event 对象，而不只是事件类型：

```javascript
Node.prototype.dispatchEvent = function(evt) {
    var type = evt.type;
    // ...
    for (var i = 0; i < list.length; i++) {
        list[i].call(this, evt);
    }
    // ...
    return evt.do_default;
}
```

在 Python 中，我们现在需要创建一个 Event 传给 dispatchEvent：

```python
EVENT_DISPATCH_JS = \
    "new Node(dukpy.handle).dispatchEvent(new Event(dukpy.type))"
```

还要注意 dispatchEvent 返回 evt.do_default，这不仅是 JavaScript 的标准做法，在从 Python 派发事件时也很有用，因为 Python 的 dispatch_event 可以把这个布尔值返回给它的调用方：

```python
class JSContext:
    def dispatch_event(self, type, elt):
        # ...
        do_default = self.interp.evaljs(
            EVENT_DISPATCH_JS, type=type, handle=handle)
        return not do_default
```

这样一来，每当事件发生，浏览器就可以检查 dispatch_event 的返回值，若为 True 就停下来。在 click 方法中，这样的地方有三处：

```python
class Tab:
    def click(self, x, y):
        while elt:
            # ...
            elif elt.tag == "a" and "href" in elt.attributes:
                if self.js.dispatch_event("click", elt): return
                # ...
            elif elt.tag == "input":
                if self.js.dispatch_event("click", elt): return
                # ...
            elif elt.tag == "button":
                if self.js.dispatch_event("click", elt): return
                # ...
            # ...
        # ...
```

submit_form 中有一处：

```python
class Tab:
    def submit_form(self, elt):
        if self.js.dispatch_event("submit", elt): return
```

keypress 中也有一处：

```python
class Tab:
    def keypress(self, char):
        if self.focus:
            if self.js.dispatch_event("keydown", self.focus): return
```

现在，我们的字符计数代码可以阻止用户提交表单了：它可以用一个全局变量记录当前是否允许提交，然后在有人尝试提交时检查该变量，必要时取消这次提交：

```javascript
var allow_submit = true;
function lengthCheck() {
    // ...
    allow_submit = value.length <= 100;
    if (!allow_submit) {
        // ...
    }
}
var form = document.querySelectorAll("form")[0];
form.addEventListener("submit", function(e) {
    if (!allow_submit) e.preventDefault();
});
```

这样，评论太长时就无法提交表单了！

呃……只是在「这个」浏览器里无法提交罢了。既然存在不运行 JavaScript 的浏览器（比如我们一章之前的浏览器），我们也应该在服务器端检查长度：

```python
def add_entry(params):
    if 'guest' in params and len(params['guest']) <= 100:
        ENTRIES.append(params['guest'])
    return show_comments()
```

注意，我们不应该——也不能——指望浏览器一定会执行 JavaScript，因为浏览器是用户的代理（agent），而不是我们的。理想情况下，网页应当写成：没有 JavaScript 也能正确工作，有了 JavaScript 则工作得更好。这叫作渐进增强（progressive enhancement）[18]，它意味着我们不用 JavaScript 去重复浏览器本来就能做的事情。

收尾之想：虽然我们的留言簿现在有了一点 JavaScript 代码，但它的主体仍是 HTML、CSS、表单元素以及其他标准 Web 特性。JavaScript 就这样扩展了 Web，而不是取代它。这与不久前谢幕的 Adobe Flash [19]，以及更早的 Java Applets [20] 形成鲜明对比——后者是自成一体的插件，输入与渲染都由它们自己处理。

> **深入探索**
> 搜索引擎在不停地爬取（crawl）[21] Web，并对能找到的所有网页做索引（index）[22]。在早期，索引不过是加载 HTML、解析并提取信息而已。但如今，许多单页应用（single-page app）[23] 网站会用 JavaScript 把站点「水合（hydrate）」[24]¹⁷ 成完整内容。在这类网站上，水合发生之前，站点中的信息都藏在 JavaScript 数据结构里。因此，搜索引擎在索引期间不仅要解析 HTML，还要运行 JavaScript（并加载样式表）。换句话说，索引系统使用的就是浏览器（例如无头 Chrome（headless Chrome）[25]）——这是浏览器在 Web 生态系统中现身的又一个地方。

## 9.10 总结

我们的浏览器现在可以代表网站运行 JavaScript 应用了。诚然，在庞大的 DOM API 中它只支持四个方法，但仅这些就演示了：

- 生成句柄（handle），让脚本能够引用页面元素；
- 从页面元素读取属性值；
- 写入并修改页面元素；
- 挂载事件监听器，让脚本能够响应页面事件。

网页现在可以通过一段巧妙的脚本添加新功能，而不必等待浏览器开发者把它加进浏览器本身。附带的好处是，一个网页现在有资格赢得「Web 应用」这个响亮的头衔了。

## 9.12 练习

### 9.1 `Node.children`

为 JavaScript 的 Node 添加对 children [26] 属性的支持。Node.children 以数组的形式返回一个节点的直接 Element 子节点，不包含文本子节点。¹⁸

### 9.2 `createElement`

document.createElement [27] 方法创建一个新元素，这个元素随后可以用 Node 上的 appendChild [28] 和 insertBefore [29] 方法挂到文档上；与 innerHTML 不同，这里不涉及解析。请实现这三个方法。

### 9.3 `removeChild`

Node 上的 removeChild [30] 方法会把给定的子节点分离并返回，使该子节点——及其子树——回到「游离」状态。（之后可以用 appendChild 和 insertBefore 把它重新挂到别处，或者将其删除。）请实现这个方法。这个实现起来更有挑战性，因为你还需要把相应的子树从 Python 一侧移除。

### 9.4 ID

当 HTML 元素带有 id 属性时，会预定义一个指向该元素的 JavaScript 变量。因此，如果页面里有一个 `<div id="foo"></div>`，就会有一个变量 foo 引用该节点。¹⁹ 请在你的浏览器中实现这一点。务必处理节点被添加和移除的情况（例如通过 innerHTML）。

### 9.5 事件冒泡

现在，你只能给 a（锚点）元素挂 click 处理器，别的元素都不行。请修复这一点。你会遇到的一个挑战是：点击一个元素时，也同时点击了它的所有祖先。在 Web 上，这种怪异之处由事件冒泡（event bubbling）[32] 处理：当事件在某个元素上产生时，监听器不仅在该元素上运行，也在它的各个祖先上运行。请实现事件冒泡，并确保监听器可以在事件对象上调用 stopPropagation 来阻止事件沿树向上冒泡。请反复确认点击链接仍然有效，并确保 preventDefault 仍能成功地阻止「点击链接后真正跳转」这一行为。

### 9.6 序列化 HTML

读取 innerHTML [33] 应当返回一个包含 HTML 源代码的字符串。该源代码应当反映元素当前的属性；例如：

```javascript
element.innerHTML = '<span id=foo>Chris was here</span>';
element.id = 'bar';
// 打印 "<span id=bar>Chris was here</span>"：
console.log(element.innerHTML);
```

请为 innerHTML 实现这一读取行为（getter）。另外实现 outerHTML，它与 innerHTML 的区别在于：它包含元素本身，而不只是它的子节点。

### 9.7 脚本添加的脚本与样式表

innerHTML API 可能把 `<script>` 或 `<link>` 元素加进文档，但目前我们的浏览器在这种情况下并不会加载它们。请修复这一点。同样，当 `<link>` 元素从文档中移除时，它的样式表也应当从全局列表中移除；请把这一点也实现了。²⁰

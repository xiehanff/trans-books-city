# 第 14 章　让内容无障碍可访问

*Chapter 14: Making Content Accessible*

到目前为止，我们一直专注于让浏览器成为开发 Web 应用的有效平台。但归根结底，浏览器是一种用户代理（user agent）。这意味着它应当尽其所能地帮助用户访问和使用 Web 应用。因此，浏览器提供了一系列无障碍（accessibility）[1] 特性，利用声明式 UI 以及 HTML 和 CSS 的灵活性，让用户能够通过触摸、键盘或语音与网页交互。

## 14.1　什么是无障碍？

无障碍（accessibility）指的是用户可以更改或自定义他们与网页交互的方式，从而使网页更易于使用。¹ Web 独一无二的灵活核心技术，意味着浏览器提供了大量无障碍特性²，允许用户自定义网页的渲染方式，还可以用键盘、语音，或借助某种辅助软件与网页交互。

当然，需要自定义的原因和自定义本身一样多种多样。世界卫生组织发现 [2]，全球多达 15% 的人口患有某种形式的残疾，其中许多属于严重或永久性的。他们中的几乎所有人都能从本章介绍的无障碍特性中大大受益。对某个人来说，残疾越严重，这些特性对其而言就越是至关重要。

有些无障碍需求会随时间出现又消失。例如，在我儿子出生时³，我和妻子轮流照顾婴儿，结果我有很多时间在夜间工作。为了尽量保住宝贵的睡眠，我希望屏幕别那么亮，并且很感激许多网站提供了深色模式。后来我发现，当双手忙着抱孩子时，用语音记笔记很方便。而当我设法哄孩子睡觉时，把电视调成静音、阅读隐藏式字幕（closed captions），结果成了看电影的最佳方式。

使用这些无障碍工具的深层原因是暂时的；但另一些用途可能持续更久，甚至是永久性的。例如，我一直非常感激路缘坡道（curb cuts）[3]，它让推着婴儿车散步方便多了。⁴ 而且很有可能，像我的许多亲戚一样，我的视力会随着年龄增长而恶化，到那时我就需要把电脑永久设置成更大的文字。对于更严重、更永久性的残疾，还有屏幕阅读器（screen reader）[4]⁵ 这样的高级工具。学会并有效地使用它们需要时间，但对需要它们的人来说是革命性的。

无障碍覆盖了从微小的便利调整到高级无障碍工具的整个光谱。⁶ 但所有类型的无障碍工作（无论物理的还是数字的）都有这样一条关键经验：一旦一个无障碍工具被造出来，有创造力的人们就会发现它能在工具设计者从未预见的各种场合派上用场。深色模式可以帮你区分工作邮箱和个人邮箱；网页缩放能帮你在一张纸上打印整个网页；键盘快捷键让你借助肌肉记忆，向一个没有批量模式的 Web 应用提交许多相似的订单。

此外，无障碍与催生 Web 的那些原则（参见本书引言）同源：用户控制、多模态内容和互操作性。这些原则让 Web 能够被所有类型的浏览器和操作系统访问，也正是这些原则让 Web 能被所有类型、所有能力的人访问。

> **深入探索**
> 在美国、英国、欧盟和许多其他国家，网站无障碍在许多情况下是法律强制要求的。例如，依据 1973 年《康复法案修正案》（Rehabilitation Act Amendments of 1973，含后来追加的修正案）[6] 的第 508 条 [5] 及相关法规 [7]，美国政府网站必须做到无障碍。依据《美国残疾人法案》（Americans with Disabilities Act）[8]，非政府网站也被要求无障碍，不过这一法律要求在实践中究竟意味着什么还不清楚 [9]，因为它目前主要由法院逐案裁定。在英国，2010 年《平等法案》（Equality Act 2010）[10] 为网站确立了类似规则，并在 2018 年为政府网站追加了更严格的规定。欧盟的类似法律是《欧洲无障碍法案》（European Accessibility Act）[11]。

## 14.2　缩放

让我们从最简单的无障碍问题开始：屏幕上的文字太小，难以阅读。这是我们大多数人迟早都会遇到的问题，也可能是最常见的用户残疾问题。解决它最简单也最有效的办法是增大字体和元素尺寸。这种方法称为缩放（zoom）⁷，意思是把页面当作所有 CSS 尺寸都按指定系数放大或缩小之后来进行布局。

要实现它，我们首先需要一种触发缩放的办法。在大多数浏览器上，这通过 Ctrl-+、Ctrl-- 和 Ctrl-0 键完成；使用 Ctrl 修饰键意味着你可以在文本输入框中输入 +、- 或 0 而不会触发缩放功能。为了处理修饰键，我们需要在事件循环（event loop）中同时监听「按下键」（key down）和「释放键」（key up）两种事件，并记录 Ctrl 键是否被按下：

```python
def mainloop(browser):
    # ...
    ctrl_down = False
    while True:
        if sdl2.SDL_PollEvent(ctypes.byref(event)) != 0:
            elif event.type == sdl2.SDL_KEYDOWN:
                # ...
                elif event.key.keysym.sym == sdl2.SDLK_RCTRL or \
                    event.key.keysym.sym == sdl2.SDLK_LCTRL:
                    ctrl_down = True
            elif event.type == sdl2.SDL_KEYUP:
                if event.key.keysym.sym == sdl2.SDLK_RCTRL or \
                    event.key.keysym.sym == sdl2.SDLK_LCTRL:
                    ctrl_down = False
                # ...
```

现在，我们可以在按键处理代码中为「按住 Ctrl 键时按下键」的情形添加一个分支：

```python
def mainloop(browser):
    while True:
        if sdl2.SDL_PollEvent(ctypes.byref(event)) != 0:
            elif event.type == sdl2.SDL_KEYDOWN:
                if ctrl_down:
                    if event.key.keysym.sym == sdl2.SDLK_EQUALS:
                        browser.increment_zoom(True)
                    elif event.key.keysym.sym == sdl2.SDLK_MINUS:
                        browser.increment_zoom(False)
                    elif event.key.keysym.sym == sdl2.SDLK_0:
                        browser.reset_zoom()
                # ...
```

这里，传给 increment_zoom 的参数表示应该放大（True）还是缩小（False）。

Browser 的代码只是通过一个主线程任务把调用委托给 Tab：

```python
class Browser:
    # ...
    def increment_zoom(self, increment):
        task = Task(self.active_tab.zoom_by, increment)
        self.active_tab.task_runner.schedule_task(task)
    def reset_zoom(self):
        task = Task(self.active_tab.reset_zoom)
        self.active_tab.task_runner.schedule_task(task)
```

最后，Tab 通过调整一个新的 zoom 属性来响应这些命令。该属性从 1 开始，充当网页上所有「CSS 尺寸」的乘数：⁸

```python
class Tab:
    def __init__(self, browser, tab_height):
        # ...
        self.zoom = 1
    # ...
    def zoom_by(self, increment):
        if increment:
            self.zoom *= 1.1
            self.scroll *= 1.1
        else:
            self.zoom *= 1/1.1
            self.scroll *= 1/1.1
        self.scroll_changed_in_tab = True
        self.set_needs_render()
    def reset_zoom(self):
        self.scroll /= self.zoom
        self.zoom = 1
        self.scroll_changed_in_tab = True
        self.set_needs_render()
```

注意，缩放时我们需要设置 needs_render 标志，以便缩放完成后重绘屏幕。还要注意，缩放页面时我们还需要调整滚动位置，⁹ 并在导航到新页面时重置缩放级别：

```python
class Tab:
    def load(self, url, payload=None):
        self.zoom = 1
        # ...
```

缩放系数应该乘到所有 CSS 尺寸上，所以我们在布局期间需要能访问它。做法有几种，但一种简单的做法是把它作为参数传给 DocumentLayout 的 layout：

```python
class DocumentLayout:
    def layout(self, zoom):
        self.zoom = zoom
        child = BlockLayout(self.node, self, None)
        # ...
class Tab:
    def render(self):
        # ...
            self.document.layout(self.zoom)
```

其他所有布局对象也都可以有一个 zoom 字段，在布局时从父对象复制而来。下面是 BlockLayout；其他布局类也应照做：

```python
class BlockLayout:
    def layout(self):
        self.zoom = self.parent.zoom
        # ...
```

现在，各处方法需要把字体大小按缩放比例缩放。由于「乘以缩放系数」是个常见操作，我们把它封装成一个辅助方法 dpx：¹⁰

```python
def dpx(css_px, zoom):
    return css_px * zoom
```

不要把 dpx 看成一个简单的辅助方法，而要看成一次单位转换：从 CSS 像素（CSS 声明中指定的单位）转换为设备像素（实际绘制到屏幕上的东西）。在真实浏览器中，这个方法还可以把高 DPI 显示屏之类的差异考虑进去。

我们将用这个转换来调整 BlockLayout 的 word 和 input 方法中的字体大小，以及 InputLayout 中的字体大小：

```python
class BlockLayout:
    def word(self, node, word):
        # ...
        px_size = float(node.style["font-size"][:-2])
        size = dpx(px_size * 0.75, self.zoom)
    def input(self, node):
        # ...
        px_size = float(node.style["font-size"][:-2])
        size = dpx(px_size * 0.75, self.zoom)
class InputLayout:
    def layout(self):
        # ...
        px_size = float(self.node.style["font-size"][:-2])
        size = dpx(px_size * 0.75, self.zoom)
```

还有 TextLayout 中的字体大小：¹¹

```python
class TextLayout:
    # ...
    def layout(self):
        # ...
        px_size = float(self.node.style["font-size"][:-2])
        size = dpx(px_size * 0.75, self.zoom)
```

以及文本框固定的 INPUT_WIDTH_PX：

```python
class BlockLayout:
    # ...
    def input(self, node):
        w = dpx(INPUT_WIDTH_PX, self.zoom)
```

最后，还有一个需要针对缩放做调整的棘手位置，在 DocumentLayout 内部。这里有两组长度：整体的 WIDTH，以及页面四周的 HSTEP/VSTEP 内边距。WIDTH 来自应用程序窗口本身的尺寸，因此它以设备像素为单位，不需要转换。但 HSTEP/VSTEP 是页面布局的一部分，因此它以 CSS 像素为单位，确实需要转换：

```python
class DocumentLayout:
    def layout(self, zoom):
        # ...
        self.width = WIDTH - 2 * dpx(HSTEP, self.zoom)
        self.x = dpx(HSTEP, self.zoom)
        self.y = dpx(VSTEP, self.zoom)
        child.layout()
        self.height = child.height
```

> **深入探索**
> 在高分辨率屏幕上，CSS 像素会同时被缩放（zoom）和一个 devicePixelRatio [15] 因子所缩放。¹³ 这个因子对设备像素进行缩放，使得每英寸大约有 96 个 CSS 像素 [16]（许多老式桌面显示器正是如此）。例如，初代 iPhone 每英寸 163 像素；该设备上的浏览器使用 devicePixelRatio 为 2，这样 96 个 CSS 像素就对应 192 个设备像素，约合 1.17 英寸。¹⁴ 当一台设备连接多个显示器时，这种缩放会变得尤其棘手：窗口可能从低分辨率显示器切换到高分辨率显示器（devicePixelRatio 随之改变），甚至被分割在两个分辨率不同的显示器上。

## 14.3　深色模式

另一种有用的视觉变化是使用更暗的颜色，以帮助那些对光线格外敏感、在夜间使用设备，或者单纯偏好更深配色方案的用户。浏览器的深色模式（dark mode）特性应当把浏览器界面和网页本身都切换成黑底白字，并把其余的背景色调得更暗。¹⁵

我们将在事件循环中用 Ctrl-d 触发深色模式：

```python
def mainloop(browser):
    while True:
        if sdl2.SDL_PollEvent(ctypes.byref(event)) != 0:
            elif event.type == sdl2.SDL_KEYDOWN:
                if ctrl_down:
                    # ...
                    elif event.key.keysym.sym == sdl2.SDLK_d:
                        browser.toggle_dark_mode()
```

深色模式激活时，浏览器界面和网页内容都需要换一种方式绘制。浏览器界面要简单一些，所以我们先从它开始。我们先加一个 dark_mode 字段来表示深色模式是否激活：

```python
class Browser:
    def __init__(self):
        # ...
        self.dark_mode = False
    def toggle_dark_mode(self):
        self.dark_mode = not self.dark_mode
```

接下来只需要在 dark_mode 打开时把 raster_chrome 中的所有颜色翻转过来。我们可以把前景色和背景色存进可复用的变量里：

```python
class Browser:
    def raster_chrome(self):
        if self.dark_mode:
            background_color = skia.ColorBLACK
        else:
            background_color = skia.ColorWHITE
        canvas.clear(background_color)
        # ...
```

类似地，在 Chrome 的 paint 中，我们需要使用正确的前景色：

```python
class Chrome:
    def paint(self):
        if self.browser.dark_mode:
            color = "white"
        else:
            color = "black"
```

然后，我们只需要在所有地方用 color 替代 black。请在 paint 中完成这个修改。¹⁶

现在，我们还希望网页内容也从浅色模式切换到深色模式。首先，当用户请求深色模式时要通知 Tab：

```python
class Browser:
    # ...
    def toggle_dark_mode(self):
        # ...
        self.dark_mode = not self.dark_mode
        task = Task(self.active_tab.set_dark_mode, self.dark_mode)
        self.active_tab.task_runner.schedule_task(task)
```

在 Tab 中：

```python
class Tab:
    def __init__(self, browser, tab_height):
        # ...
        self.dark_mode = browser.dark_mode
    def set_dark_mode(self, val):
        self.dark_mode = val
        self.set_needs_render()
```

注意，深色模式设置翻转时我们需要重新渲染页面，这样用户才能真的看到新颜色。顺带一提，切换标签页时我们还需要设置深色模式，因为所有标签页应该统一为深色或浅色：

```python
class Browser:
    def set_active_tab(self, tab):
        # ...
        task = Task(self.active_tab.set_dark_mode, self.dark_mode)
        self.active_tab.task_runner.schedule_task(task)
```

现在，我们需要让页面的颜色以某种方式依赖于深色模式。最容易改的是由浏览器设置的默认文字颜色和文档背景色。例如，默认文字颜色来自 INHERITED_PROPERTIES 字典，我们可以直接根据深色模式来修改它：

```python
class Tab:
    # ...
    def render(self):
        if self.needs_style:
            if self.dark_mode:
                INHERITED_PROPERTIES["color"] = "white"
            else:
                INHERITED_PROPERTIES["color"] = "black"
            style(self.nodes,
                sorted(self.rules, key=cascade_priority))
```

页面背景则由 Browser 在 draw 方法中绘制，我们也可以让它依赖于深色模式：

```python
class Browser:
    # ...
    def draw(self):
        # ...
        if self.dark_mode:
            canvas.clear(skia.ColorBLACK)
        else:
            canvas.clear(skia.ColorWHITE)
```

现在，如果你打开浏览器并切换到深色模式，应该能看到黑底白字，如图 14.3 所示。

> **深入探索**
> 浏览器实在不应该在页面毫不知情的情况下更改颜色；如果与页面的主题冲突，可读性可能变得极差！正确的做法是，网页通过 color-scheme meta 标签 [18] 或 CSS 属性 [19] 来表明 [17] 自己支持深色模式。浏览器根据该 meta 标签是否存在来判断应用深色模式是否安全。在 color-scheme 被标准化之前，网页原则上可以通过替代样式表（alternative style sheets）[20] 提供备选配色方案，但几乎没有浏览器支持（主要浏览器中只有 Firefox），它也没有被普遍使用。

## 14.4　自定义深色模式

我们这个简单的深色模式实现，对于只有背景加文字的页面工作得很好。但要有好看的深色模式，我们还需要调整页面上的所有其他颜色。例如，按钮和输入元素可能需要更暗的背景色，网页开发者在页面上用到的各种颜色也一样。

为此，CSS 使用了媒体查询（media queries）[21]。这是一种特殊的语法，本质上把一些 CSS 规则包进一个带某种条件的 if 语句里；条件为真时这些 CSS 规则会生效，条件为假时它们被忽略。prefers-color-scheme 条件用于检测深色模式。例如，下面这段 CSS 只在深色模式下让 `<div>` 黑底白字：

```css
@media (prefers-color-scheme: dark) {
    div { background-color: black; color: white; }
}
```

网页开发者可以在自己的样式表中使用 prefers-color-scheme 查询，调整自己选定的颜色以适应用户的请求；但我们也可以在浏览器默认样式表中使用 prefers-color-scheme 媒体查询，来调整链接、按钮和文本输入框的默认颜色：

```css
@media (prefers-color-scheme: dark) {
    a { color: lightblue; }
    input { background-color: #2222FF; }
    button { background-color: #992500; }
}
```

这里我挑选了非常具体的十六进制颜色，既保留了蓝色和橙色的整体配色，又确保与白色前景文字有最大对比度，便于阅读。选择能保证最大对比度的颜色（「AAA」[22] 评级）很重要。这个工具 [23] 用于检查前景色和背景色的对比度，非常方便。

要实现媒体查询，我们得从解析这种语法开始：

```python
class CSSParser:
    def media_query(self):
        self.literal("@")
        assert self.word() == "media"
        self.whitespace()
        self.literal("(")
        self.whitespace()
        prop, val = self.pair([")"])
        self.whitespace()
        self.literal(")")
        return prop, val
```

然后，在 parse 中，我们记录当前的配色方案，并在每次进入或退出一条 @media 规则时更新它：¹⁷

```python
class CSSParser:
    def parse(self):
        # ...
        media = None
        self.whitespace()
        while self.i < len(self.s):
            try:
                if self.s[self.i] == "@" and not media:
                    prop, val = self.media_query()
                    if prop == "prefers-color-scheme" and \
                        val in ["dark", "light"]:
                        media = val
                    self.whitespace()
                    self.literal("{")
                    self.whitespace()
                elif self.s[self.i] == "}" and media:
                    self.literal("}")
                    media = None
                    self.whitespace()
                else:
                    # ...
                    rules.append((media, selector, body))
```

注意，我修改了规则列表，让它不仅存储选择器和规则体，还存储这些规则所属的配色方案——None 表示无论什么配色方案都适用，dark 表示仅深色模式，light 表示仅浅色模式。这样，style 函数就可以忽略不适用的规则：

```python
def style(node, rules, tab):
    # ...
    for media, selector, body in rules:
        if media:
            if (media == "dark") != tab.dark_mode: continue
        # ...
```

## 14.5　键盘导航

眼下，我们浏览器的大多数特性都用鼠标触发，¹⁹ 这对手部有伤病或残疾的用户是个问题——对偏爱键盘的高级用户同样是个问题。因此，理想情况下，每个浏览器特性都应该既可以通过键盘、也可以通过鼠标来使用。这包括浏览器界面交互，比如后退导航、输入 URL、退出浏览器；也包括网页交互，比如提交表单、在文本区输入、浏览链接，以及选择页面上的条目。

我们先从浏览器界面开始，因为它最容易。这里，我们需要允许用户用键盘完成后退导航、在地址栏输入，以及创建和切换标签页。我们还将添加一个退出浏览器的键盘快捷键。²⁰ 我们让事件循环中的这些快捷键都使用 Ctrl 修饰键，以免干扰正常输入：Ctrl-Left 后退、Ctrl-l 聚焦地址栏、Ctrl-t 新建标签页、Ctrl-Tab 切换到下一个标签页、Ctrl-q 退出浏览器：

```python
def mainloop(browser):
    while True:
        if sdl2.SDL_PollEvent(ctypes.byref(event)) != 0:
            elif event.type == sdl2.SDL_KEYDOWN:
                if ctrl_down:
                    # ...
                    elif event.key.keysym.sym == sdl2.SDLK_LEFT:
                        browser.go_back()
                    elif event.key.keysym.sym == sdl2.SDLK_l:
                        browser.focus_addressbar()
                    elif event.key.keysym.sym == sdl2.SDLK_t:
                        browser.new_tab(
                            "https://browser.engineering/")
                    elif event.key.keysym.sym == sdl2.SDLK_TAB:
                        browser.cycle_tabs()
                    elif event.key.keysym.sym == sdl2.SDLK_q:
                        browser.handle_quit()
                        sdl2.SDL_Quit()
                        sys.exit()
                        break
```

这里，focus_addressbar 和 cycle_tabs 方法是新的，但它们的内容只是从 handle_click 复制而来：

```python
class Chrome:
    def focus_addressbar(self):
        self.focus = "address bar"
        self.address_bar = ""
class Browser:
    def focus_addressbar(self):
        self.lock.acquire(blocking=True)
        self.chrome.focus_addressbar()
        self.set_needs_raster()
        self.lock.release()
    def cycle_tabs(self):
        self.lock.acquire(blocking=True)
        active_idx = self.tabs.index(self.active_tab)
        new_active_idx = (active_idx + 1) % len(self.tabs)
        self.set_active_tab(self.tabs[new_active_idx])
        self.lock.release()
```

现在，浏览器界面中的任何点击都可以用键盘操作替代了。但网页本身的点击呢？这就更棘手了，因为网页可以有任意数量的链接。所以标准的解决方案是让用户用 Tab 键遍历页面上所有可点击的东西，再按 Enter 真正点击它们。²¹

我们将通过扩展 focus 的实现来完成它。每个 Tab 上已经有一个 focus 属性，指出哪个输入元素正在捕获键盘输入。让我们允许按钮和链接也可被聚焦。当然，它们并不捕获键盘输入，但当用户按下 Enter 时，我们就去按下按钮或导航到链接。我们首先在事件循环中绑定这些键：

```python
def mainloop(browser):
    while True:
        if sdl2.SDL_PollEvent(ctypes.byref(event)) != 0:
            elif event.type == sdl2.SDL_KEYDOWN:
                # ...
                elif event.key.keysym.sym == sdl2.SDLK_RETURN:
                    browser.handle_enter()
                elif event.key.keysym.sym == sdl2.SDLK_TAB:
                    browser.handle_tab()
```

注意，这几行并不放在 if ctrl_down 块内，因为我们绑定的是 Tab 和 Enter，而不是 Ctrl-Tab 和 Ctrl-Enter。在 Browser 中，我们只是把这些键转发给活动标签页的 enter 和 advance_tab 方法：²²

```python
class Browser:
    def handle_tab(self):
        self.focus = "content"
        task = Task(self.active_tab.advance_tab)
        self.active_tab.task_runner.schedule_task(task)
    def handle_enter(self):
        # ...
        elif self.focus == "content":
            task = Task(self.active_tab.enter)
            self.active_tab.task_runner.schedule_task(task)
        # ...
```

让我们从 advance_tab 方法开始。每次调用它时，浏览器都应该把焦点推进到下一个可聚焦的东西。这首先需要定义哪些元素是可聚焦的（focusable）：

```python
def is_focusable(node):
    return node.tag in ["input", "button", "a"]
class Tab:
    def advance_tab(self):
        focusable_nodes = [node
            for node in tree_to_list(self.nodes, [])
            if isinstance(node, Element) and is_focusable(node)]
```

接下来，在 advance_tab 中，我们需要找出当前聚焦的元素在这个列表中的位置，以便把焦点移到下一个：

```python
class Tab:
    def advance_tab(self):
        # ...
        if self.focus in focusable_nodes:
            idx = focusable_nodes.index(self.focus) + 1
        else:
            idx = 0
```

最后，只需要聚焦选中的元素。如果我们已经遍历完最后一个可聚焦节点（或者一开始就没有可聚焦节点），我们就取消页面焦点，把焦点移到地址栏：

```python
class Tab:
    def advance_tab(self):
        if idx < len(focusable_nodes):
            self.focus = focusable_nodes[idx]
        else:
            self.focus = None
            self.browser.focus_addressbar()
        self.set_needs_render()
```

现在元素被聚焦后，用户应该能通过按 Enter 与它交互。由于用户执行的具体操作各不相同（导航一个链接、按下一个按钮、清空一个文本输入框），我们把这称为「激活」（activating）该元素：

```python
class Tab:
    def enter(self):
        if not self.focus: return
        self.activate_element(self.focus)
```

activate_element 方法对不同类型的元素做不同的事情：

```python
class Tab:
    def activate_element(self, elt):
        if elt.tag == "input":
            elt.attributes["value"] = ""
            self.set_needs_render()
        elif elt.tag == "a" and "href" in elt.attributes:
            url = self.url.resolve(elt.attributes["href"])
            self.load(url)
        elif elt.tag == "button":
            while elt:
                if elt.tag == "form" and "action" in elt.attributes:
                    self.submit_form(elt)
                elt = elt.parent
```

这些激活代码都是从 Tab 的 click 方法复制来的。注意，聚焦在文本输入框上时按 Enter 会清空该输入框；在大多数浏览器中，这样做会提交所在表单。这个怪异的设定是我们没有实现退格键（第 8.3 节）的一个权宜之计。

click 方法现在可以重写为直接调用 activate_element：

```python
class Tab:
    def click(self, x, y):
        while elt:
            if isinstance(elt, Text):
                pass
            elif is_focusable(elt):
                self.focus_element(elt)
                self.activate_element(elt)
                return
            elt = elt.parent
```

此外，由于现在任何元素都可以被聚焦，keypress 需要先检查聚焦的是否是输入元素，再往其中输入文字：

```python
class Tab:
    def keypress(self, char):
        if self.focus and self.focus.tag == "input":
            if not "value" in self.focus.attributes:
                self.activate_element(self.focus)
            # ...
```

我调用了 activate_element 来创建一个空的 value 属性。

类似地，InputLayout 原本会为任何被聚焦的元素绘制光标。现在按钮元素也能被聚焦了，它需要更谨慎一些：

```python
class InputLayout:
    def paint(self):
        # ...
        if self.node.is_focused and self.node.tag == "input":
            # ...
        # ...
```

最后，注意有时激活一个元素会提交表单或导航到新页面，这意味着我们聚焦的元素已不复存在。这种情况下我们必须确保清除焦点：

```python
class Tab:
    def load(self, url, payload=None):
        self.focus = None
        # ...
```

我们现在能够聚焦链接、按钮和文本输入框了。但与任何浏览器特性一样，值得问一句：网页作者是否应该能够自定义它。对于键盘导航，作者可能希望某些链接不可聚焦（比如指向小节标题的「永久链接」，它们对大多数用户只是噪音），也可能希望更改用户在可聚焦条目之间按 Tab 遍历的顺序。

浏览器为此支持 tabindex HTML 属性。tabindex 属性是一个数字。元素的 tabindex 为负时不可聚焦；tabindex 值较小的元素排在较大者以及完全没有 tabindex 的元素之前。为实现这一点，我们需要按 tab 索引对可聚焦元素排序，所以需要一个返回 tab 索引的函数：

```python
def get_tabindex(node):
    tabindex = int(node.attributes.get("tabindex", "9999999"))
    return 9999999 if tabindex == 0 else tabindex
```

默认值 "9999999" 是一个小技巧，用来确保没有 tabindex 属性的元素排在有该属性的元素之后。现在我们可以在 advance_tab 中按 get_tabindex 排序：

```python
class Tab:
    def advance_tab(self):
        focusable_nodes = [node
            for node in tree_to_list(self.nodes, [])
            if isinstance(node, Element) and is_focusable(node)]
        focusable_nodes.sort(key=get_tabindex)
        # ...
```

由于 Python 的排序是「稳定的」，两个 tabindex 相同的元素在 focusable_nodes 中的相对位置不会改变。

此外，tabindex 非负的元素会自动变为可聚焦，即使它不是链接、按钮或文本输入框。这很有用，因为这样的元素可能监听 click 事件。为了支持它，我们首先扩展 is_focusable 来考虑 tabindex：

```python
def is_focusable(node):
    if get_tabindex(node) < 0:
        return False
    elif "tabindex" in node.attributes:
        return True
    else:
        return node.tag in ["input", "button", "a"]
```

如果你为焦点示例打印出 focusable_nodes，应该会得到：

```text
[<a tabindex="1" href="/">,
<button tabindex="2">,
<div tabindex="3">,
<div tabindex="12">,
<input>,
<a href="http://browser.engineering">]
```

我们还需要确保在元素被激活时发送 click 事件。注意，就像点击元素一样，激活元素的操作也可以被 JavaScript 用 preventDefault 取消。

```python
class Tab:
    def enter(self):
        if not self.focus: return
        if self.js.dispatch_event("click", self.focus): return
        self.activate_element(self.focus)
```

现在，浏览器和网页内容都有了可配置的键盘导航。而且这几乎没写什么新代码，主要是把现有方法中的代码搬到新的独立方法里。键盘导航简化而非复杂化了我们的浏览器实现，这是一个常见的结果：改进无障碍往往意味着泛化和精炼既有概念，最终让代码整体上更可维护。

> **深入探索**
> 为什么元素被激活时发送的是 click 事件，而不是一个专门的 activate 事件？Internet Explorer 确实用过 [30] 一个专门的 activate 事件，其他浏览器也曾发送 DOMActivate [31] 事件，但现代标准要求：即使元素是通过键盘而非鼠标点击激活的，也要发送 click 事件。当开发者没怎么考虑无障碍、只注册了 click 事件监听器时，这样做效果更好。

## 14.6　指示焦点

得益于我们的键盘快捷键，用户现在可以通过键盘到达任何链接、按钮或文本输入框。但如果你真的用这种方式浏览网站，会有点难以分辨当前聚焦的是哪个元素。一个视觉指示——类似于我们在文本输入框上使用的光标——可以帮助有视力的用户判断是否已到达想要的元素，还是需要继续按 Tab。在大多数浏览器中，这个视觉指示是一个勾勒出被聚焦元素的焦点环（focus ring）。

为了实现焦点环，我们将使用与绘制文本光标相同的机制。回想一下，目前文本光标是在 InputLayout 的 paint 方法中通过画一条竖线添加的。我们将在该方法中添加一个 paint_outline 调用，在被聚焦元素周围画一个矩形：

```python
def paint_outline(node, cmds, rect, zoom):
    if not node.is_focused: return
    cmds.append(DrawOutline(rect, "black", 1))
```

在一个新的 focus_element 方法中设置这个 is_focused 标志，今后我们就用它来更改 Tab 的 focus 字段：

```python
class Tab:
    def focus_element(self, node):
        if self.focus:
            self.focus.is_focused = False
        self.focus = node
        if node:
            node.is_focused = True
```

轮廓绘制应该放在 paint_effects 中，因为它绘制在子树之上。

```python
class InputLayout:
    def paint_effects(self, cmds):
        cmds = paint_visual_effects(self.node, cmds, self.self_rect())
        paint_outline(self.node, cmds, self.self_rect(), self.zoom)
        return cmds
```

我还把光标绘制改为仅当节点被聚焦且是输入元素时才进行。用 Tab 移到一个按钮元素上不应该画出光标！

不幸的是，处理链接要复杂一点。因为一个 `<a>` 元素对应多个 TextLayout 对象，所以并不存在唯一一个可以放置这段代码的布局对象。此外，这些 TextLayout 可能被拆分到多行，所以我们可能需要画不止一个焦点环。为绕过这个问题，让我们在 LineLayout 中绘制焦点环。每个 LineLayout 找出其中所有被聚焦的子 TextLayout，并在它们整体周围画一个矩形。

```python
class LineLayout:
    def paint_effects(self, cmds):
        outline_rect = skia.Rect.MakeEmpty()
        outline_node = None
        for child in self.children:
            if child.node.parent.is_focused:
                outline_rect.join(child.self_rect())
                outline_node = child.node.parent
        if outline_node:
            paint_outline(
                outline_node, cmds, outline_rect, self.zoom)
        return cmds
```

你还应该给 BlockLayout 加一个 paint_outline 调用，因为用户可以用 tabindex 让任何元素变得可聚焦。²³

现在，当你用 Tab 遍历页面时，应该能看到被聚焦的元素被黑色轮廓高亮。而如果一个链接恰好跨多行，你会看到我们的浏览器用多个焦点矩形，把聚焦的对象标示得一清二楚。

只除了一个问题：如果被聚焦的元素被滚动到了屏幕外，依然没有办法知道焦点在哪。为了解决这个问题，我们需要在用户用 Tab 聚焦到它时自动把它滚动到屏幕上。这有点棘手，因为判断元素是否在屏幕外需要布局。所以，与其立即滚动，我们不如在 Tab 上设置一个新的 needs_focus_scroll 位：

```python
class Tab:
    def __init__(self, browser, tab_height):
        # ...
        self.needs_focus_scroll = False
    def focus_element(self, node):
        if node and node != self.focus:
            self.needs_focus_scroll = True
```

然后，run_animation_frame 可以在重置该标志之前完成适当的滚动：

```python
class Tab:
    def run_animation_frame(self, scroll):
        # ...
        if self.needs_focus_scroll and self.focus:
            self.scroll_to(self.focus)
        self.needs_focus_scroll = False
        # ...
```

要真正执行滚动，我们需要找到与被聚焦节点对应的布局对象：

```python
class Tab:
    def scroll_to(self, elt):
        objs = [
            obj for obj in tree_to_list(self.document, [])
            if obj.node == self.focus
        ]
        if not objs: return
        obj = objs[0]
```

然后，我们滚动到它：

```python
class Tab:
    def scroll_to(self, elt):
        # ...
        if self.scroll < obj.y < self.scroll + self.tab_height:
            return
        document_height = math.ceil(self.document.height + 2*VSTEP)
        new_scroll = obj.y - SCROLL_STEP
        self.scroll = self.clamp_scroll(new_scroll)
        self.scroll_changed_in_tab = True
```

这里，我调整滚动位置以确保该对象距离屏幕顶部 SCROLL_STEP 像素，不过真实浏览器向上与向下滚动时可能采用不同的逻辑。

焦点轮廓现在基本可用了，在焦点示例上试试，它甚至能自动滚动到屏幕内。图 14.5 展示了我按 Tab 聚焦到「this is a link」元素后的效果。

理想情况下，焦点指示器应该可以自定义，让网页作者能确保被聚焦的元素足够显眼。在 CSS 中，这通过「:focus 伪类（pseudo-class）[32]」完成。基本上，这意味着你可以写一个这样的选择器：

```css
div:focus { ... }
```

然后这个选择器只应用于当前被聚焦的 `<div>` 元素。²⁴

为了实现它，我们需要解析这种新式的选择器。让我们修改 selector，让它调用一个新的 simple_selector 子例程来解析标签名和可能的伪类：

```python
class CSSParser:
    def selector(self):
        out = self.simple_selector()
        # ...
        while self.i < len(self.s) and self.s[self.i] != "{":
            descendant = self.simple_selector()
            # ...
```

在 simple_selector 中，解析器先解析一个标签名，然后检查其后是否跟着冒号和一个伪类名：

```python
class CSSParser:
    def simple_selector(self):
        out = TagSelector(self.word().casefold())
        if self.i < len(self.s) and self.s[self.i] == ":":
            self.literal(":")
            pseudoclass = self.word().casefold()
            out = PseudoclassSelector(pseudoclass, out)
        return out
```

PseudoclassSelector 包装另一个选择器：

```python
class PseudoclassSelector:
    def __init__(self, pseudoclass, base):
        self.pseudoclass = pseudoclass
        self.base = base
        self.priority = self.base.priority
```

匹配很直接：

```python
class PseudoclassSelector:
    def matches(self, node):
        if not self.base.matches(node):
            return False
        if self.pseudoclass == "focus":
            return node.is_focused
        else:
            return False
```

未知的伪类则永远不会匹配任何东西。

被聚焦的元素现在可以被设置样式了。但理想情况下，我们还应该能自定义焦点轮廓本身，而不只是元素。这可以通过添加对 CSS outline 属性 [34] 的支持来完成，它长这样（3 像素粗的红色轮廓）：²⁵

```css
outline: 3px solid red;
```

我们可以把它解析成一个粗细和一个颜色：

```python
def parse_outline(outline_str):
    if not outline_str: return None
    values = outline_str.split(" ")
    if len(values) != 3: return None
    if values[1] != "solid": return None
    return int(values[0][:-2]), values[2]
```

然后绘制解析出的轮廓：

```python
def paint_outline(node, cmds, rect, zoom):
    outline = parse_outline(node.style.get("outline"))
    if not outline: return
    thickness, color = outline
    cmds.append(DrawOutline(rect, color, dpx(thickness, zoom)))
```

更好的是，我们可以把默认的两像素黑色轮廓移进浏览器默认样式表，像这样：

```css
input:focus { outline: 2px solid black; }
button:focus { outline: 2px solid black; }
div:focus { outline: 2px solid black; }
```

而且，我们现在可以在深色模式触发时把轮廓改成白色，这对于让它在黑色背景上显眼很重要：

```css
@media (prefers-color-scheme: dark) {
    input:focus { outline: 2px solid white; }
    button:focus { outline: 2px solid white; }
    div:focus { outline: 2px solid white; }
    a:focus { outline: 2px solid white; }
}
```

最后，把我们所有的 paint 方法改为使用 parse_outline 而不是 is_focused 来绘制轮廓。下面是 LineLayout：

```python
class LineLayout:
    def paint_effects(self, cmds):
        # ...
        for child in self.children:
            outline_str = child.node.parent.style.get("outline")
            if parse_outline(outline_str):
                outline_rect.join(child.self_rect())
                outline_node = child.node.parent
```

## 14.7　无障碍树

缩放、深色模式和焦点指示器能帮助看细节有困难的用户，但如果用户完全看不见屏幕，²⁶ 他们通常会改用屏幕阅读器。这个名字基本说明了一切：屏幕阅读器把屏幕上的文字大声读出来，让用户不必看见屏幕也能知道上面写了什么。

那么：屏幕阅读器应该说什么？我们基本上必须克服两大挑战。第一，网页上除了文字还包含各种视觉提示，我们需要为屏幕阅读器用户再现它们。例如，当焦点位于 `<input>` 或 `<button>` 元素上时，屏幕阅读器需要说出来，因为这些用户看不见浅蓝色或橙色的背景。第二，在听屏幕阅读器时，用户必须能把浏览器引导到自己感兴趣的那部分页面。²⁷ 例如，用户可能想跳过页眉和导航菜单，甚至跳过页面的大部分内容，直到到达感兴趣的段落。而一旦到达感兴趣的部分，他们可能想让它读给自己听；如果某个句子或短语特别复杂，他们可能想让屏幕阅读器再读一遍。你可以在图 14.7 所示视频的演讲中看到屏幕阅读器导航的例子²⁸，具体是 2:36–3:54 那一段。²⁹

为了支持这一切，浏览器把页面组织成一棵树，并用这棵树与屏幕阅读器交互。树的较高层表示段落、标题或导航菜单之类的条目，较低层表示文字、链接或按钮。³⁰ 这听起来大概很像 HTML——也确实很像！但正如 HTML 树与布局树并不完全对应一样，这棵树与 HTML 树也没有精确的对应。例如，一些 HTML 元素（如 `<div>`）是为了样式而对内容分组，这对屏幕阅读器用户毫无意义。反过来，一些 HTML 元素可能在屏幕上不可见，³¹ 却与屏幕阅读器用户相关。因此，浏览器会构建一棵单独的无障碍树（accessibility tree）[39] 来支持屏幕阅读器导航。

让我们在我们的浏览器中实现无障碍树。它在紧随布局之后的一个渲染阶段中构建：

```python
class Tab:
    def __init__(self, browser, tab_height):

        self.needs_accessibility = False
        self.accessibility_tree = None

        # ...

            self.needs_accessibility = True
            self.needs_paint = True
            self.needs_layout = False
        if self.needs_accessibility:

            self.accessibility_tree.build()
            self.needs_accessibility = False
```

无障碍树由 AccessibilityNode 构成：

```python
class AccessibilityNode:
    def __init__(self, node):
        self.node = node
        self.children = []
        self.text = ""
```

AccessibilityNode 上的 build 方法递归地创建无障碍树。为此，我们遍历 HTML 树，并为每个节点确定它在无障碍树中扮演的「角色」（role）。有些元素（如 `<div>`）没有角色，因此不会出现在无障碍树中；而像 `<input>`、`<a>` 和 `<button>` 这样的元素则有默认角色。³² 我们可以根据节点的标签名来计算角色，或者在存在特殊的 role 属性时从它取得：

```python
class AccessibilityNode:
    def __init__(self, node):
        # ...
        if isinstance(node, Text):
            if is_focusable(node.parent):
                self.role = "focusable text"
            else:
                self.role = "StaticText"
        else:
            if "role" in node.attributes:
                self.role = node.attributes["role"]
            elif node.tag == "a":
                self.role = "link"
            elif node.tag == "input":
                self.role = "textbox"
            elif node.tag == "button":
                self.role = "button"
            elif node.tag == "html":
                self.role = "document"
            elif is_focusable(node):
                self.role = "focusable"
            else:
                self.role = "none"
```

构建无障碍树只需递归遍历 HTML 树。沿途跳过角色为 none 的节点，但仍递归进入它们的子节点：

```python
class AccessibilityNode:
    def build(self):
        for child_node in self.node.children:
            self.build_internal(child_node)
    def build_internal(self, child_node):
        child = AccessibilityNode(child_node)
        if child.role != "none":
            self.children.append(child)
            child.build()
        else:
            for grandchild_node in child_node.children:
                self.build_internal(grandchild_node)
```

> **深入探索**
> 在多进程浏览器（如 Chromium [41]）中，有一个与操作系统交互的浏览器进程，以及加载网页的多个渲染进程。由于屏幕阅读器 API 是同步的，Chromium 会存储两份 [42] 无障碍树，一份在浏览器中，一份在每个渲染器中，两者之间只发送变更。另一种设计由 Chromium 化之前的 Microsoft Edge 和其他一些浏览器采用：让每个渲染进程直接响应来自操作系统的无障碍 API 请求。这免除了复制无障碍树的需要，但把操作系统暴露给单个标签页可能带来安全问题。

## 14.8　屏幕阅读器

通常，屏幕阅读器是独立于浏览器之外的应用程序；³³ 浏览器通过操作系统特定的 API 与它通信。为了让本书与平台无关，并更清晰地展示屏幕阅读器如何与无障碍树交互，我们对屏幕阅读器支持的讨论将改为包含一个直接集成在浏览器中的最小屏幕阅读器。

但我们内置的屏幕阅读器应该放在 Browser 里，还是每个 Tab 里？现代浏览器通常在类似 Browser 的层面与屏幕阅读器通信，我们也照做。³⁴ 所以，我们要做的第一件事就是把标签页的无障碍树发送到浏览器线程。这将是第 12.9 节引入的提交（commit）概念的一个直接扩展。首先，我们把树加进 CommitData：

那么，屏幕阅读器应该说什么？这其实不由浏览器决定——屏幕阅读器是一个独立的应用程序，往往被它的用户重度定制，可以自行决定。但作为简单的调试辅助，让我们写一个在网页加载完成后把整页读出来的屏幕阅读器；当然，真实的屏幕阅读器比这灵活得多。

要朗读整个文档，我们需要知道如何朗读每个 AccessibilityNode。这必须回到 Tab 中决定，因为朗读文本会包含浏览器线程无法访问的 DOM 内容。所以，我们给 AccessibilityNode 加一个 text 字段，并在 build 中根据节点的角色和周围的 DOM 上下文来设置它。对文本节点来说它就是文本本身；其他情况下它描述元素标签，以及它是否被聚焦。

```python
class AccessibilityNode:
    def __init__(self, node):
        # ...
        self.text = ""
    def build(self):
        for child_node in self.node.children:
            self.build_internal(child_node)
        if self.role == "StaticText":
            self.text = repr(self.node.text)
        elif self.role == "focusable text":
            self.text = "Focusable text: " + self.node.text
        elif self.role == "focusable":
            self.text = "Focusable element"
        elif self.role == "textbox":
            if "value" in self.node.attributes:
                value = self.node.attributes["value"]
            elif self.node.tag != "input" and self.node.children and \
                isinstance(self.node.children[0], Text):
                value = self.node.children[0].text
            else:
                value = ""
            self.text = "Input box: " + value
        elif self.role == "button":
            self.text = "Button"
        elif self.role == "link":
            self.text = "Link"
        elif self.role == "alert":
            self.text = "Alert"
        elif self.role == "document":
            self.text = "Document"
        if self.node.is_focused:
            self.text += " is focused"
```

真实的屏幕阅读器还有更多的功能：地标（landmark）、以不同粒度浏览文本、按请求重复朗读文字等等。这些功能以各种方式利用无障碍树和各种节点的角色。但由于本书的关注点是浏览器而非屏幕阅读器本身，本章余下部分让我们专注于其他支持无障碍的浏览器特性。

> **深入探索**
> 无障碍树不只是给屏幕阅读器用的。例如，有些用户偏好触觉输出，比如点字盲文显示器（braille display）[46]，以替代或补充语音输出。虽然输出设备截然不同，无障碍树仍然包含页面上有什么内容、能否交互、其状态如何等全部信息。此外，通过在所有输出设备上使用同一棵无障碍树，使用不止一种辅助技术（比如盲文显示器加屏幕阅读器）的用户必然能收到一致的信息。

## 14.9　无障碍警报

脚本并不直接与无障碍树交互，就像它们不直接与显示列表交互一样。不过，有时脚本需要告知屏幕阅读器它们为什么要对页面做某些更改，以便给屏幕阅读器用户更好的体验。最常见的例子是告诉你刚才做的某个操作失败了的警报（alert）³⁵。屏幕阅读器用户需要警报被立即读出来，无论它被插入到文档中的哪个位置。

alert 角色满足了这一需求。屏幕阅读器会立即³⁶朗读带有该角色的元素，无论用户当前在文档的什么位置。注意，没有任何 HTML 元素的默认角色是 alert，所以这需要页面作者显式设置 role 属性。

接下来是实现。我们首先需要让脚本能更改 role 属性，也就是添加对 setAttribute 方法的支持。在 JavaScript 一侧，它只是调用一个浏览器 API：

```javascript
Node.prototype.setAttribute = function(attr, value) {
    return call_python("setAttribute", this.handle, attr, value);
}
```

Python 一侧同样很简单：

```python
class JSContext:
    def __init__(self, tab):
        # ...
        self.interp.export_function("setAttribute",
            self.setAttribute)
    # ...
    def setAttribute(self, handle, attr, value):
        elt = self.handle_to_node[handle]
        elt.attributes[attr] = value
        self.tab.set_needs_render()
```

现在我们可以实现 alert 角色了。在无障碍树中搜索带有该角色的元素：

```python
class Browser:
    def __init__(self):
        # ...
        self.active_alerts = []
    def update_accessibility(self):
        self.active_alerts = [
            node for node in tree_to_list(
                self.accessibility_tree, [])
            if node.role == "alert"
        ]
        # ...
```

现在，我们不能每一帧都把每个警报读一遍；我们需要记录哪些元素已经读过，免得读两遍：

```python
class Browser:
    def __init__(self):
        # ...
        self.spoken_alerts = []
    def update_accessibility(self):
        # ...
        for alert in self.active_alerts:
            if alert not in self.spoken_alerts:
                self.speak_node(alert, "New alert")
                self.spoken_alerts.append(alert)
```

由于 spoken_alerts 指向无障碍树内部，每当无障碍树重建时，我们都需要更新它，让它指向新树。就像合成那样，利用无障碍树中的节点指针在新旧无障碍树之间匹配无障碍节点。注意，虽然这个匹配可以放在 commit 里做，但我们希望那个方法尽可能快，因为它会同时阻塞浏览器线程和主线程。所以最好在 update_accessibility 中做：

```python
class Browser:
    def update_accessibility(self):
        # ...
        new_spoken_alerts = []
        for old_node in self.spoken_alerts:
            new_nodes = [
                node for node in tree_to_list(
                    self.accessibility_tree, [])
                if node.node == old_node.node
                and node.role == "alert"
            ]
            if new_nodes:
                new_spoken_alerts.append(new_nodes[0])
        self.spoken_alerts = new_spoken_alerts
        # ...
```

注意，如果一个节点失去了 alert 角色，我们就会把它从 spoken_alerts 中移除，这样它以后重新获得 alert 角色时会被再次朗读。这听起来像个极端情况，但用单个元素承担所有警报（比如只是把它的 class 从 hidden 改成 visible）是一种常见模式。

现在你应该能加载这个示例 [47]，并在按钮被点击后听到警报文本：³⁷

```html
<div>Alert text</div>
<button>Toggle alert role</button>
<script src="example14-alert-role.js"></script>
```

> **深入探索**
> alert 角色是 ARIA 所谓「实时区域」（live region）的一个例子：页面中会因用户操作而变化的区域。还有其他角色（如 status 或 alertdialog），实时区域也可以更细粒度地配置：通过 aria-live 属性设置其「礼貌程度」（assertive 通知会打断用户，polite 则不会）；通过 aria-atomic 和 aria-relevant 设置要播报哪些变化；通过 aria-busy 设置实时区域是处于完成状态还是中间状态。此外，创建实时区域只需要 aria-live 就够了；不需要任何角色。

## 14.10　语音与视觉交互

得益于本章的工作，我们的渲染管线现在基本上有两个不同的输出：用于视觉交互的显示列表，和用于屏幕阅读器交互的无障碍树。许多用户只会使用其中之一。不过，把两者结合起来使用也很有价值。例如，用户可能视力有限——能大致分辨网页上的条目，却无法阅读文字。这样的用户可能用鼠标浏览页面，但需要屏幕阅读器把鼠标下的条目读给他们听。

让我们来试试。实现这个特性需要每个无障碍节点知道自己在页面上的几何位置。然后用户就可以让屏幕阅读器判断哪个对象在鼠标下方（通过命中测试（hit testing）[48]）并把它读出来。

获取几何信息很棘手，因为无障碍树是由 HTML 树生成的，而几何信息要在布局树中才能拿到。让我们给每个 Element 对象加一个 layout_object 指针来帮忙：³⁸

```python
class Element:
    def __init__(self, tag, attributes, parent):
        # ...
        self.layout_object = None
class Text:
    def __init__(self, text, parent):
        # ...
        self.layout_object = None
```

现在，构造布局对象时，我们可以填写其 Element 的 layout_object 字段。在 BlockLayout 中，它看起来像这样：

```python
class BlockLayout:
    def __init__(self, node, parent, previous):
        # ...
        node.layout_object = self
```

请务必在其余每种布局对象的构造函数中都加上类似的一行代码。然后每个 AccessibilityNode 就可以存储布局对象的边界：

```python
class AccessibilityNode:
    def __init__(self, node):
        # ...
        self.bounds = self.compute_bounds()
    def compute_bounds(self):
        if self.node.layout_object:
            return [absolute_bounds_for_obj(self.node.layout_object)]
        # ...
```

注意，我这里使用的是 absolute_bounds_for_obj，因为我们关心的是屏幕上的绝对坐标，即经过 translate 之类变换之后的坐标。

不过还有一个复杂之处：node.layout_object 可能没有被设置；例如，文本节点就没有。³⁹ 同样，采用行内布局的节点一般也没有。所以我们需要沿树向上找到一个拥有 BlockLayout 的祖先，并把当前节点子树中所有 LineLayout 里的所有文本节点合并起来。由于可能有多个 LineLayout 和多个文本节点，边界需要用一个 skia.Rect 对象的数组来表示：

```python
class AccessibilityNode:
    def compute_bounds(self):
        # ...
        if isinstance(self.node, Text):
            return []
        inline = self.node.parent
        bounds = []
        while not inline.layout_object: inline = inline.parent
        for line in inline.layout_object.children:
            line_bounds = skia.Rect.MakeEmpty()
            for child in line.children:
                if child.node.parent == self.node:
                    line_bounds.join(skia.Rect.MakeXYWH(
                        child.x, child.y, child.width, child.height))
            bounds.append(line_bounds)
        return bounds
```

那么让我们实现悬停朗读特性。首先我们需要在事件循环中监听鼠标移动事件，SDL 中它叫 MOUSEMOTION：

```python
def mainloop(browser):
    while True:
        if sdl2.SDL_PollEvent(ctypes.byref(event)) != 0:
            # ...
            elif event.type == sdl2.SDL_MOUSEMOTION:
                browser.handle_hover(event.motion)
```

浏览器应当监听悬停位置，判断它是否在某个无障碍节点上，并高亮该节点。我们不想打乱正常的渲染节奏，所以在 handle_hover 中保存悬停事件，然后在 composite_raster_and_draw 中响应它：

```python
class Browser:
    def __init__(self):
        # ...
        self.pending_hover = None
    def handle_hover(self, event):
        if not self.accessibility_is_on or \
            not self.accessibility_tree:
            return
        self.pending_hover = (event.x, event.y - self.chrome.bottom)
        self.set_needs_accessibility()
```

当用户悬停到一个节点上时，我们要做两件事。第一，把它的边界画在屏幕上；这能帮助用户看到自己悬停在什么上面，对调试也有帮助。请在 paint_draw_list 中完成；先找到用户悬停其上的无障碍节点（注意需要把滚动考虑进来）：

```python
class Browser:
    def __init__(self):
        # ...
        self.hovered_a11y_node = None
    def paint_draw_list(self):
        # ...
        if self.pending_hover:
            (x, y) = self.pending_hover
            y += self.active_tab_scroll
            a11y_node = self.accessibility_tree.hit_test(x, y)
```

顺便说一下，a11y_node 里的缩写 a11y——一个「a」、数字「11」、再一个「y」——是「accessibility」一词常见的简写。⁴⁰ hit_test 函数在无障碍树上递归：

```python
class AccessibilityNode:
    def contains_point(self, x, y):
        for bound in self.bounds:
            if bound.contains(x, y):
                return True
        return False
    def hit_test(self, x, y):
        node = None
        if self.contains_point(x, y):
            node = self
        for child in self.children:
            res = child.hit_test(x, y)
            if res: node = res
        return node
```

命中测试完成后，浏览器就知道用户悬停在哪个节点上了；把这些信息保存在 Browser 上——这样轮廓才能跨帧保留——然后绘制轮廓：

```python
class Browser:
    def paint_draw_list(self):
        if self.pending_hover:
            # ...
            if a11y_node:
                self.hovered_a11y_node = a11y_node
            self.pending_hover = None
```

最后，我们可以在 paint_draw_list 末尾绘制轮廓：

```python
class Browser:
    def paint_draw_list(self):
        # ...
        if self.hovered_a11y_node:
            for bound in self.hovered_a11y_node.bounds:
                self.draw_list.append(DrawOutline(
                    bound,
                    "white" if self.dark_mode else "black", 2))
```

注意轮廓的颜色取决于深色模式是否开启，以确保高对比度。

现在我们画出了轮廓。但我们还想把用户悬停的内容读出来。为此我们需要另一个标志 needs_speak_hovered_node，每当悬停从一个元素移到另一个元素时就设置它：

```python
class Browser:
    def __init__(self):
        # ...
        self.needs_speak_hovered_node = False
    def paint_draw_list(self):
        if self.pending_hover:
            if a11y_node:
                if not self.hovered_a11y_node or \
                    a11y_node.node != self.hovered_a11y_node.node:
                    self.needs_speak_hovered_node = True
                # ...
```

这个难看的条件语句是为了处理两种情况：一是之前没有悬停任何对象而现在悬停到了一个对象上，二是把鼠标从一个对象移到另一个对象上。这两种情况我们都要设置该标志，然后在 update_accessibility 中使用它：

```python
class Browser:
    def update_accessibility(self):
        # ...
        if self.needs_speak_hovered_node:
            self.speak_node(self.hovered_a11y_node, "Hit test ")
        self.needs_speak_hovered_node = False
```

现在你应该能打开无障碍模式，把鼠标移到页面上，同时获得关于悬停内容的视觉和听觉反馈了！

> **深入探索**
> 一个常见的问题是：网页作者自制输入元素，却不怎么考虑它们的无障碍。原因在于内置的输入元素很难设置样式，于是作者们自己动手做了更好看的。
>
> 内置输入元素常常包含多个独立的部件，比如文件输入中的路径和按钮、checkbox 元素中的复选框，或 select 下拉框中的弹出菜单，而 CSS（目前）不擅长给这类「复合」元素设置样式，尽管 ::backdrop 或 ::file-selector-button 这类伪元素 [49] 有所帮助。也许最好的解决方案是为全新的、可完全设置样式 [51] 的输入元素制定标准 [50]。

## 14.11　总结

本章介绍了无障碍——确保所有用户都能访问网站并与网站交互的特性——并展示了如何解决浏览器中若干最常见的无障碍问题。关键要点如下：

- HTML 的语义化和声明式本质，使无障碍特性成为自然的扩展。
- 无障碍特性常常服务于多种需求，几乎每个人都会以这样或那样的方式从中受益。
- 无障碍树与显示列表类似，驱动着浏览器与屏幕阅读器及其他辅助技术（assistive technology）的交互。
- 深色模式、键盘导航和轮廓等新特性需要能被网页作者自定义，才能获得最大的可用性。

## 14.13　练习

### 14.1　对比度良好的焦点环

用两道轮廓改善焦点指示器的对比度：一道较粗的白色轮廓和一道较细的黑色轮廓，以确保焦点环与周围内容之间有对比度。

### 14.2　focus 方法与事件

为 DOM 元素添加对 JavaScript focus [52] 方法以及相应的 focus 与 blur 事件的支持。确保 focus() 只对可聚焦的元素生效。小心：在读取元素位置之前，先确保布局是最新的。

### 14.3　朗读时高亮元素

朗读整个文档的方法可以工作，但如果能在朗读发生的同时高亮正在被读的元素就更好了，方式类似于我们为鼠标悬停所做的。请实现它。你可以考虑把 speak_document 方法替换成一个 advance_accessibility 方法，它把无障碍焦点移动一个节点并朗读它。

### 14.4　宽度媒体查询

放大或缩小会导致页面以 CSS 像素计的宽度发生变化。这意味着有些原先能舒适放在页面上的元素现在放不下了；而如果页面变得足够窄，换一种布局可能更合适。max-width 媒体查询 [53] 允许开发者基于可用宽度为页面设置不同样式；只有当页面以 CSS 像素计的宽度小于或等于给定长度时，它才生效。⁴¹ 请实现这个媒体查询。测试放大或缩小能否触发它。

完成练习后，下面这个示例 [55] 在窄屏上应该显示绿色文字。HTML：

```html
    <link rel=stylesheet href="example14-maxwidth-media.css">
    This text becomes green when the width is 700px or less.
```

CSS：

```css
    @media (max-width:700px) {
        * { color: green }
    }
```

### 14.5　混合行内元素

让焦点环在嵌套的行内元素上正确工作。例如，在 `<a>a <b>bold</b> link</a>` 中，当用户聚焦链接时，焦点环应该把三个词一起围住；如果行内元素跨行，则用多个矩形。但当用户聚焦一个块级元素时，例如 `<div tabindex=2> many<br> lines</div>`，则不应该每一行都有一个焦点环，而应该把整个块作为整体。

### 14.6　线程化无障碍

目前的无障碍代码在浏览器线程上朗读文本，并在朗读期间阻塞浏览器线程。这用起来很让人恼火。把朗读移到一个新的无障碍线程来解决它。

### 14.7　高对比度模式

实现 forced-colors 高对比度模式。它应当用一小组高对比度颜色之一替换所有颜色。

### 14.8　focus-visible

当用户用 Tab 移到一个链接上时，我们大概想显示焦点指示器；但如果用户是用鼠标点击了它，大多数浏览器不会显示——用户知道被聚焦的元素在哪里！多余的焦点指示器可能难看，或令人分心。请实现一个类似的启发式规则。点击按钮应该聚焦它，但不显示焦点指示器。（请在焦点示例上测试一个放在表单外面的按钮，这样点击按钮不会导航到新页面。）但无论是点击还是用 Tab 聚焦输入元素，都应该显示焦点环。另外，添加对 :focus-visible 伪类 [56] 的支持。它只在元素被聚焦且浏览器本会绘制焦点环时才适用（焦点环本会可见，故得此名）。这让自定义组件能更改焦点环的样式，同时不失去我上面提到的有用的浏览器启发式规则。

### 14.9　操作系统集成

添加 accessible_output [57] Python 库，并用它直接与你操作系统内置的屏幕阅读器集成。试试本章的一些示例，并与真实浏览器的行为做比较。

### 14.10　zoom CSS 属性

添加对 zoom CSS 属性的支持。它向 Web 开发者暴露与缩放无障碍特性相同的功能，此外还允许只把它应用于指定的 HTML 子树。

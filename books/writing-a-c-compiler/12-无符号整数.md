# 第 12 章　无符号整数

*Chapter 12: Unsigned Integers*

本章中，你将实现两种有符号整数类型的无符号（unsigned）对应物：unsigned int 和 unsigned long。你要扩展寻常算术转换（usual arithmetic conversions）以处理无符号整数，并实现有符号类型与无符号类型之间的强制转换。在后端，你将使用几条新的汇编指令来完成无符号整数运算。

第 11 章的重点是推断和追踪类型信息的一般方法；现在，我们可以在这项工作的基础上，用相对少的力气添加新类型。在修改编译器之前，先快速概览一下有符号类型与无符号类型之间的转换。

## 再谈类型转换

每种整数类型转换都有两个方面需要考虑：整数的值如何变化，以及它的二进制表示如何变化。我们在上一章 int 与 long 之间的转换中已经见过这一点。符号扩展（sign extension）把有符号整数的表示从 32 位改成 64 位，但不改变它的值。把 long 截断（truncate）成 int 同样会改变表示，而且如果原来的值放不进新类型，它的值也会改变。

记住这一区别之后，我会把类型转换分成四种情形来讨论。对于每种情形，我先描述整数的表示会如何变化，再解释这如何与 C 标准中关于值应如何变化的规则相对应。

### 在同尺寸的有符号与无符号类型之间转换

第一种情形是在同尺寸的有符号（signed）与无符号类型之间转换：也就是 int 与 unsigned int 之间、long 与 unsigned long 之间。这些转换不改变整数的二进制表示，唯一变化的是是否用补码（two's complement）来解释它的值。我们来考虑这种解释上的变化带来的影响。

如果一个有符号整数是正数，它的最高位是 0，因此把它解释为无符号整数不会改变它的值。反过来也一样：如果一个无符号整数小于对应有符号类型能表示的最大值，它的最高位必然是 0。因此，如果我们用补码重新解释它，它的值也不会改变。正如你在上一章学到的，把整数转换到新类型时，标准要求我们在可能的情况下保持它的值不变。我们这里就满足了这个要求。

剩下的是最高位为 1 的整数。当我们把一个负的有符号整数重新解释为无符号时，最高位的含义就从负变成了正。如果最高位是 1，其效果相当于给这个值加上 2^N，其中 N 是该类型的位数。这正是标准要求的行为；第 6.3.1.3 节第 2 段规定，如果值无法由新类型表示且新类型是无符号的，“则反复加上或减去刚好比新类型所能表示的最大值大 1 的值，直到该值落入新类型的范围之内。”

反过来，把一个最高位为 1 的无符号类型转换为对应的有符号类型，会从它的值中减去 2^N。这与我们上一章为转换到有符号整数所选择的实现定义（implementation-defined）行为一致，该行为沿用 GCC：“该值按 2^N 取模，以落入类型范围之内。”

### 将 unsigned int 转换为更大的类型

第二种情形是把 unsigned int 转换为更大的类型：long 或 unsigned long。处理这种情形时，我们要对整数做零扩展（zero extension），用 0 填充新表示的高位。这种转换总是保持原值不变，因为我们只是给一个正数添加前导 0。

### 将有符号 int 转换为更大的类型

第三种情形是把有符号 int 转换为 long 或 unsigned long。我们已经用符号扩展把 int 转换为 long，把 int 转换为 unsigned long 也采用同样的方式。如果 int 是正数，符号扩展只是添加前导 0，无论你把结果解释为有符号还是无符号，值都保持不变。如果值是负数，先做符号扩展、再把结果解释为 unsigned long，会给它的值加上 2^64，这正是标准要求的行为。

### 从较大类型转换到较小类型

最后一种情形是把较大的类型（long 或 unsigned long）转换为较小的类型（int 或 unsigned int）。我们一律通过截断值来处理这种情形。其效果是反复加上或减去 2^32，直到值落入新类型的范围——等价地说，就是把这个值按 2^32 取模——这正是我们想要的行为。我不会一步步推导为什么截断整数在每种情况下都能得到正确的值；你可以自己举几个例子算一算，或者干脆相信我说的。

解析类型说明符（type specifier）比上一章更复杂，因为同一个类型有太多不同的写法。例如，下面这些都是指定 long 类型的合法方式：

类型说明符的顺序无关紧要，因此 long signed、long int signed 等等指定的也都是同一个类型。清单 12-3 的伪代码提供了一种在这片混乱中理清秩序的办法。

```text
parse_type(specifier_list):
    if (specifier_list is empty
        or specifier_list contains the same specifier twice
        or specifier_list contains both "signed" and "unsigned"):
        fail("Invalid type specifier")
    if specifier_list contains "unsigned" and "long":
        return ULong
    if specifier_list contains "unsigned":
        return UInt
    if specifier_list contains "long":
        return Long
    return Int
```

*清单 12-3：从一列类型说明符确定类型*

我们先检查错误情形。要指明一个类型，至少需要一个说明符，而且同一个说明符不能出现两次；例如，你不能把类型写成 int long int。（long long 类型说明符会让这个校验变复杂，但我们不实现它。）你也不能在同一次类型说明中同时包含 signed 和 unsigned 说明符，因为它们互相矛盾。

一旦确认输入指定的是合法类型，我们就检查 unsigned 和 long 说明符。如果两者都在，类型就是 unsigned long；否则，如果有 unsigned，类型是 unsigned int；如果有 long，类型是 long；如果两者都没有，类型是 int。基本上，int 是默认类型，unsigned 和 long 说明符可以用来指明一个不同于默认的类型。C 标准第 6.7.2 节第 2 段枚举了指定每种类型的所有方式。

我们还需要处理常量词法单元。上一章的清单 11-6 演示了如何解析有符号常量词法单元，这里我就不再给出无符号常量词法单元对应的伪代码了，逻辑是一样的。如果一个无符号整数常量词法单元的值在 unsigned int 能表示的范围内——也就是 0 到 2^32 − 1 之间（含两端）——我们就把它解析为 ConstUInt；否则解析为 ConstULong。

无符号长常量词法单元总是被解析为 ConstULong。如果任何一种无符号常量词法单元的值不在 unsigned long 的范围内（0 到 2^64 − 1 之间），我们就抛出错误。如果你好奇，C 标准第 6.4.4.1 节给出了确定整数常量类型的完整规则。

## 类型检查器

本章不需要修改循环标记遍和标识符解析遍，只需要在类型检查器（type checker）中处理无符号整数。

首先，我们要更新对寻常算术转换的实现，它会隐式地把二元表达式中的操作数转换为一个公共类型（common type）。我们逐条来看 C 标准第 6.3.1.8 节第 1 段定义的整数类型寻常算术转换规则。第一条规则不言自明：

> 如果两个操作数具有相同的类型，则不需要进一步转换。

第二条稍微难懂一些：

> 否则，如果两个操作数都是有符号整数类型，或者都是无符号整数类型，则将整数转换秩（integer conversion rank）较低的类型的操作数转换为秩较高的类型的操作数。

这条的意思只是“如果两个整数的符号性相同，就把较小的类型转换成较大的类型”。我们在把值从 int 隐式转换为 long 时已经在这么做了。第 6.3.1.1 节第 1 段规定了每种整数类型的整数转换秩，它只给出各种类型尺寸上的相对次序，而不精确限定其大小。在我们目前拥有的类型中，long 和 unsigned long 的秩最高，其次是 int 和 unsigned int。同一类型的有符号版本和无符号版本总是具有相同的秩。由于这种相对转换秩，long 保证至少和 int 一样大，但不一定更大。（事实上，在大多数 32 位系统上这两个类型一样大。）不管它们的实际尺寸如何，long 与 int 的公共类型是 long，unsigned long 与 unsigned int 的公共类型是 unsigned long。这里没有什么意外的。

第三条规则讨论的是一个操作数有符号、另一个无符号的情形：

> 否则，如果具有无符号整数类型的操作数的秩大于或等于另一个操作数类型的秩，则将具有有符号整数类型的操作数转换为具有无符号整数类型的操作数的类型。

也就是说，如果两个类型一样大，或者无符号类型更大，我们就选无符号类型。例如，int 与 unsigned int 的公共类型是 unsigned int，int 与 unsigned long 的公共类型是 unsigned long。剩下的情形是有符号类型更大，这由第四条规则覆盖：

> 否则，如果具有有符号整数类型的操作数的类型可以表示具有无符号整数类型的操作数的类型的所有值，则将具有无符号整数类型的操作数转换为具有有符号整数类型的操作数的类型。

在 System V x64 ABI 下，long 可以表示 unsigned int 类型的每一个值，因此 unsigned int 与 long 的公共类型是 long。在 long 和 int 一样大的实现中，情况就不是这样了：long 的秩比 int 高，却表示不了 unsigned int 的每一个值。第五条也是最后一条规则覆盖的就是这类实现。尽管这条规则与我们无关，为了完整起见我还是把它列出来：

> 否则，将两个操作数都转换为与具有有符号整数类型的操作数的类型相对应的无符号整数类型。

因此，在 long 和 int 一样大的系统上，long 与 unsigned int 的公共类型是 unsigned long。

以上内容可以归结为求公共类型的三条规则，清单 12-4 用伪代码描述了它们。

```text
get_common_type(type1, type2):
  ❶ if type1 == type2:
        return type1
  ❷ if size(type1) == size(type2):
        if type1 is signed:
            return type2
        else:
            return type1
  ❸ if size(type1) > size(type2):
        return type1
    else:
        return type2
```

*清单 12-4：求两个整数的公共类型*

首先，如果两个类型相同，任选其一 ❶；否则，如果它们一样大，选无符号的那个 ❷；如果大小不同，选较大的那个 ❸。除了寻常算术转换之外，我们还要对表达式类型检查的逻辑做一处很小的更新：像我们已有的给有符号常量标注类型那样，给无符号常量标注正确的类型。

接下来看看我们如何在符号表中记录静态变量的初始值。我们要添加两种新的静态初始化器（static initializer），正如我们添加了两种新的常量一样：

```text
static_init = IntInit(int) | LongInit(int) | UIntInit(int) | ULongInit(int)
```

我们需要按照本章开头介绍的类型转换规则，把每个初始化器转换成它所初始化变量的类型。考虑下面这个声明：

```c
static unsigned int u = 4294967299L;
```

值 4,294,967,299 超出了 unsigned int 的范围。把 u 加入符号表时，我们会通过从这个值中减去 2^32 把它转换为 unsigned int。（实践中，你多半可以直接使用你所用实现语言里等价的整数类型转换。）得到的初始化器是 UIntInit(3)。

同理，下面这个声明用一个超出 int 范围的值来初始化一个 int：

```c
static int i = 4294967246u;
```

把这个值按 2^32 取模之后，得到的初始化器是 IntInit(-50)。

严格说来，为有符号变量和无符号变量准备不同的静态初始化器并不是必需的。你也可以用 IntInit 同时表示 int 和 unsigned int 的初始化器，用 LongInit 同时表示 long 和 unsigned long 的初始化器。归根结底，无论你把一个初始化器表示成有符号值还是无符号值，汇编器写出的字节都是一样的：指令 `.long -50` 和 `.long 4294967246` 的含义完全相同。单独设立 UIntInit 和 ULongInit 初始化器只是让我们的类型转换更容易追踪。

*清单 12-5：向 TACKY 添加 ZeroExtend 指令*

现在我们必须为转换到无符号类型或从无符号类型转换而来的强制转换（cast）表达式生成正确的 TACKY。在本章开头，我们讨论过把整数转换为新类型的四种情形分别如何影响其二进制表示。清单 12-6 演示了每种情形下应发射哪些 TACKY 指令。

```text
emit_tacky(e, instructions, symbols):
    match e with
    | --snip--
    | Cast(t, inner) ->
        result = emit_tacky(inner, instructions, symbols)
        inner_type = get_type(inner)
        if t == inner_type:
            return result
        dst = make_tacky_variable(t, symbols)
      ❶ if size(t) == size(inner_type):
            instructions.append(Copy(result, dst))
      ❷ else if size(t) < size(inner_type):
            instructions.append(Truncate(result, dst))
      ❸ else if inner_type is signed:

      ❹ else:

```

*清单 12-6：把强制转换表达式转换为 TACKY*

与上一章一样，如果内部表达式已经是正确的类型，强制转换表达式什么都不用做。否则，我们先检查原类型与目标类型是否一样大 ❶。如果一样大，就不需要扩展、截断或以其他方式改变内部值，因为它在汇编中的表示不会改变。我们只需把它复制到一个具有正确类型的临时变量中。这里的 Copy 指令看起来可能多余，但在汇编生成阶段，我们需要靠它来帮助追踪类型信息。某些 TACKY 指令生成的汇编会因其操作数是有符号还是无符号而不同。如果我们不把每个表达式的结果存入具有正确类型的变量，就会生成错误的汇编。

接下来，检查目标类型是否比原类型小 ❷。如果是，就发射一条 Truncate 指令。如果这项检查也不成立，那么这个强制转换表达式就是把较小的类型转换为较大的类型：原类型是有符号时就发射 SignExtend 指令 ❸，是无符号时就发射 ZeroExtend 指令 ❹。

一旦你的编译器能为无符号常量和强制转换表达式生成正确的 TACKY，就可以测试了。

## 汇编中的无符号整数运算

在大多数情况下，操作有符号值和无符号值可以使用完全相同的汇编指令。不过，有两种情形需要我们对无符号值做不同处理：比较和除法。我们还需要把新的 ZeroExtend 指令翻译成汇编。在更新汇编生成阶段之前，先来看看无符号比较、无符号除法和零扩展在汇编中是如何工作的。

### 无符号比较

在第 4 章，你学过如何比较两个整数：先发射一条 cmp 指令设置 RFLAGS 寄存器，再发射一条行为取决于该寄存器状态的条件指令。比较无符号整数时我们采用同样的方法，但需要依赖不同标志位的不同的条件码（condition code）。

一些执行算术运算的指令，包括 add、sub 和 cmp，并不区分有符号值和无符号值。清单 12-7 演示了同一个运算如何同时实现有符号加法和无符号加法。

```text
  1000
+ 0010
------
  1010
```

*清单 12-7：二进制整数相加*

如果把操作数和结果都解释为 4 位无符号整数，清单 12-7 计算的是 8 + 2 = 10；如果把它们解释为 4 位有符号整数，计算的就是 −8 + 2 = −6。只要我们对操作数和结果做一致的解释，两种方式都能得到正确答案。你可以把 add、sub 以及大多数其他算术汇编指令的结果看成一段比特序列，它对应两个可能的值：一个有符号值，一个无符号值。

处理器执行完其中某条指令后，RFLAGS 中的一些标志告诉我们结果的有符号值，另一些标志告诉我们无符号值，还有一些对两种值都适用。（有些标志与这些指令的结果无关，我们不用管它们。）第 4 章讨论过三个标志：零标志（zero flag，ZF）、符号标志（sign flag，SF）和溢出标志（overflow flag，OF）。无论把结果解释为有符号还是无符号，ZF 都适用，因为零在这两种情况下的表示相同。而 SF 和 OF 只对结果的有符号值给出有意义的信息。

例如，SF 表示结果是负数。第 4 章里我们利用这个标志得出 a - b 为负，在那种情况下，假设没有溢出，我们就知道 a 小于 b。但对无符号值——它们按定义就是正数——这一套行不通。看看清单 12-8，它用 4 位无符号整数计算 15 − 3。

```text
  1111
- 0011
------
  1100
```

*清单 12-8：二进制整数相减*

由于 15 大于 3，这个运算的结果是正数 12。结果最高位是 1 这一事实，并不能说明哪个操作数更大。类似地，OF 告诉我们某条指令结果的有符号值从正绕到了负、或从负绕到了正，这对了解它的无符号值毫无帮助。

要比较无符号整数，我们要使用进位标志（carry flag，CF）。这个标志表示结果的无符号值发生了回绕（wrap around），因为正确的值小于 0 或者大于该类型能表示的最大值。例如，假设我们要用 4 位无符号整数计算 15 + 1。15 的 4 位无符号表示是 1111；给它加 1，它会回绕成 0000。这次计算会把进位标志置为 1。如果我们计算 0 − 1，结果朝另一个方向回绕成 1111（也就是 15），进位标志同样会被置位。如果 a < b，a - b 的结果总会发生回绕并置起进位标志；如果 a > b，结果总能用一个无符号整数表示，因此不会回绕。我们把 a 和 b 解释为无符号整数，走读一遍 cmp b, a 会如何影响 CF 和 ZF：

- 如果 a == b，那么 a - b 为 0，因此 ZF 为 1、CF 为 0。
- 如果 a > b，那么 a - b 是一个正数。它大于 0 且小于等于 a，因此不会回绕。ZF 和 CF 都为 0。
- 如果 a < b，那么 a - b 是负数，因此必然回绕。ZF 为 0、CF 为 1。

注意，ZF 和 CF 互斥；一次运算绝不会同时把它们置位。本章需要的所有条件码都依赖这两个标志之一或两者。表 12-1 列出了这些条件码。

*表 12-1：无符号比较的条件码*

| 条件码 | 含义 | 标志 |
| --- | --- | --- |
| E | a == b | ZF 置位 |
| NE | a != b | ZF 未置位 |
| A | a > b | CF 未置位且 ZF 未置位 |
| AE | a >= b | CF 未置位 |
| B | a < b | CF 置位 |
| BE | a <= b | CF 置位或 ZF 置位 |

我们继续使用已有的 E 和 NE 条件码来测试相等和不等，但要用新的条件码来判断两个操作数哪个更大。新条件码中的 A 和 B 分别是 “above”（高于）和 “below”（低于）的助记符。新条件码可以像旧条件码一样出现在条件跳转指令和 set 指令中。清单 12-9 演示了如何在 EDX 中的无符号值大于 10 时把 EAX 置为 1。

```asm
cmpl    $10, %edx
movl    $0, %eax
seta    %al
```

*清单 12-9：在汇编中执行无符号比较*

这与有符号比较的模式完全相同：先发射 cmp 指令，再把目标清零，最后发射一条带相应条件码后缀的 set 指令。

**无符号回绕与有符号溢出**

你在第 4 章学过，有符号整数运算的结果溢出时，行为是未定义的。无符号整数则不然。C 标准第 6.2.5 节第 9 段规定了当无符号整数运算的结果放不进结果类型时该如何处理：“涉及无符号操作数的计算永远不会溢出，因为无法用结果的无符号整数类型表示的结果，会按比该结果类型所能表示的最大值大 1 的数取模。”

这与标准对“把值转换为无符号类型”所要求的行为完全相同，绝非巧合；它也是我们为转换到有符号类型所选择的实现定义行为。在这三种情形下，我们都是通过把结果截断到相应宽度来得到这个行为的。

我们用来执行算术运算的汇编指令本身就能正确处理无符号回绕，所以这里不需要为此做任何特殊处理。不过，等我们在第 III 部分实现常量折叠（constant folding）时，就必须把它考虑进去了。

### 无符号除法

对大多数算术运算来说，同一条指令都能正确处理有符号和无符号整数。但除法不行。假设我们要计算 1000 / 0010。如果把这些值解释为 4 位有符号整数，这是 −8 / 2，结果是 −4，表示为 1100；如果是 4 位无符号整数，这是 8 / 2，结果是 4，即 0100。一条指令不可能在两种情况下都给出正确的结果。

因此，我们需要一条新指令 div 来执行无符号除法。这条指令的工作方式与 idiv 完全一样。它接受一个操作数，作为除数；被除数是存放在 EDX 和 EAX 中的值（如果处理的是四字（quadword），则是 RDX 和 RAX）。它把商存入 EAX 或 RAX，把余数存入 EDX 或 RDX。

由于被除数是无符号的，我们要把它从 EAX 零扩展到 EDX（或从 RAX 零扩展到 RDX），而不是做符号扩展。为此，我们把 RDX 清零，而不是发射 cdq 指令。

### 零扩展

最后一个要实现的运算是零扩展。我们可以把一个长字（longword）移入寄存器，从而把它零扩展成四字；这会自动把寄存器的高 4 字节清零。之后如果需要把这个值存入内存，再把整个 8 字节的值移到最终目的地即可。下面的代码对 -4(%rbp) 处的值做零扩展，然后把结果保存到 -16(%rbp)：

```asm
movl    -4(%rbp), %eax
movq    %rax, -16(%rbp)
```

我们用 4 字节的 movl 指令把值复制进寄存器，再用 8 字节的 movq 指令把它复制出去。如果零扩展运算的最终目的地是寄存器而不是内存中的位置，那么只需要第一条 4 字节的 movl 指令。

另外还有一条单独的 movz 指令，用于对小于 4 字节的源值做零扩展。我们现在还用不到它，但到第 16 章实现字符类型时会用到。

## 汇编生成

既然你已经知道如何在汇编中处理无符号整数，就可以扩展汇编生成阶段了。清单 12-10 给出了最新的汇编 AST，本章新增的部分以粗体标出。

```text
program = Program(top_level*)
assembly_type = Longword | Quadword
top_level = Function(identifier name, bool global, instruction* instructions)
          | StaticVariable(identifier name, bool global, int alignment, static_init init)
instruction = Mov(assembly_type, operand src, operand dst)
            | Movsx(operand src, operand dst)
            | MovZeroExtend(operand src, operand dst)
            | Unary(unary_operator, assembly_type, operand)
            | Binary(binary_operator, assembly_type, operand, operand)
            | Cmp(assembly_type, operand, operand)
            | Idiv(assembly_type, operand)
            | Div(assembly_type, operand)
            | Cdq(assembly_type)
            | Jmp(identifier)
            | JmpCC(cond_code, identifier)
            | SetCC(cond_code, operand)
            | Label(identifier)
            | Push(operand)
            | Call(identifier)
            | Ret

unary_operator = Neg | Not
binary_operator = Add | Sub | Mult
operand = Imm(int) | Reg(reg) | Pseudo(identifier) | Stack(int) | Data(identifier)
cond_code = E | NE | G | GE | L | LE | A | AE | B | BE
reg = AX | CX | DX | DI | SI | R8 | R9 | R10 | R11 | SP
```

*清单 12-10：带无符号运算的汇编 AST*

我们添加了上一节讨论的新条件码和无符号 div 指令，还添加了一条 MovZeroExtend 指令来处理零扩展。目前这条指令只是一个占位符。在指令修复（fix-up）遍中，我们会根据它的目的地是在内存中还是寄存器中，把它替换成一条或两条 mov 指令。（眼下目的地总在内存中，所以总是需要两条 mov 指令；等我们在第 III 部分实现寄存器分配后，这一点会改变。）等到添加字符类型时，MovZeroExtend 还将代表真正的 movz 指令，用于对 1 字节的值做零扩展。

我们来回顾一下汇编生成遍需要做的修改。首先，把源码级类型转换为汇编类型时，有符号与无符号整数的区别会丢失：TACKY 中的 long 和 unsigned long 值在汇编中都变成四字，int 和 unsigned int 值都变成长字。

把比较指令从 TACKY 转换为汇编时，我们先查出任一操作数的类型（两个操作数保证类型相同），再根据该类型是否有符号选择合适的条件码。例如，要处理

```text
Binary(LessThan, Var("src1"), Var("src2"), Var("dst"))
```

我们先在符号表中查出 src1 或 src2 的类型。假设类型是 UInt，此时我们会生成以下汇编指令：

```text
Cmp(Longword, Pseudo("src2"), Pseudo("src1"))
Mov(Longword, Imm(0), Pseudo("dst"))
SetCC(B, Pseudo("dst"))
```

这些指令与有符号比较所生成的指令完全相同，只是用的是 B 条件码而不是 L。

处理 TACKY 的 Divide 或 Remainder 运算时，我们照旧把第一个操作数复制到 EAX。然后，如果操作数是有符号的，就把 EAX 符号扩展到 EDX 并发射一条 idiv 指令；如果是无符号的，就把 EDX 清零并发射一条 div 指令。（当然，如果操作数是四字，我们就用 RAX 和 RDX 而不是 EAX 和 EDX。）例如，我们会把

```text
Binary(Remainder, ConstULong(100), Var("x"), Var("dst"))
```

翻译成：

```text
Mov(Quadword, Imm(100), Reg(AX))
Mov(Quadword, Imm(0), Reg(DX))
Div(Quadword, Pseudo("x"))
Mov(Quadword, Reg(DX), Pseudo("dst"))
```

最后，我们把每条 ZeroExtend TACKY 指令转换为一条 MovZeroExtend 汇编指令。

表 12-2 到表 12-5 总结了 TACKY 到汇编转换的最新更新。新增构造以及对现有构造转换方式的改动以粗体标出。

| | 无符号 | `Mov(<src1 type>, src1, Reg(AX))` `Mov(<src1 type>, Imm(0), Reg(DX))` `Div(<src1 type>, src2)` `Mov(<src1 type>, Reg(AX), dst)` |

接下来，我们更新伪寄存器（pseudoregister）替换遍和指令修复遍。

### 替换伪寄存器

我们要扩展这一遍以处理新的 Div 和 MovZeroExtend 指令。除此之外，这里没有什么要改的。这一遍关注的是每个操作数的汇编类型而非源码级类型，因此不区分有符号和无符号操作数。

### 修复 Div 与 MovZeroExtend 指令

接下来要改写 Div 和 MovZeroExtend 两条指令。与 Idiv 一样，新的 Div 指令不能使用常量操作数。我们按照改写 Idiv 的同样方式来改写它：必要时把它的操作数复制到 R10。

我们用一条或两条 mov 指令替换 MovZeroExtend。如果它的目的地是寄存器，只需发射一条 movl 指令。例如，我们会把

```text
MovZeroExtend(Stack(-16), Reg(AX))
```

改写为：

```text
Mov(Longword, Stack(-16), Reg(AX))
```

如果它的目的地在内存中，我们就先用一条 movl 指令零扩展到 R11，再从那里移到目的地。因此，我们会把

```text
MovZeroExtend(Imm(100), Stack(-16))
```

改写为：

```text
Mov(Longword, Imm(100), Reg(R11))
Mov(Quadword, Reg(R11), Stack(-16))
```

这一遍不会有其他改动。

本章中，你基于第 11 章打下的基础实现了两种无符号整数类型。你啃完了 C 标准中有关类型转换的规则，探究了这些转换对整数的表示和值的双重影响。在类型检查器中，你学习了有符号整数和无符号整数如何转换到公共类型；在汇编生成阶段，你实现了零扩展、无符号除法以及无符号比较。

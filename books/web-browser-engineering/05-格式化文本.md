# 第 3 章　格式化文本

*Chapter 3: Formatting Text*

在上一章中，我们的浏览器创建了一个图形化窗口，并在上面绘制了一个字符网格。这对中文来说没问题，但英文文本的字符宽度各不相同，并且被组合成不能从中间断行的单词。¹ 在本章中，我们将添加这些能力。你甚至将能在你的浏览器中阅读本章 [1]！

## 3.1　什么是字体？

到目前为止，我们调用 `create_text` 时都是传入一个字符和两个坐标，把文本写到屏幕上。但我们从未指定过它的字体（font）、大小或样式。要谈论这些事情，我们需要创建并使用字体对象。

字体究竟是什么？嗯，在往昔岁月里，印刷工人把小小的金属铅字排在字轨上，给它们涂上油墨，再压到一张纸上，就得到了一页印刷品（参见图 3.1）。金属字模装在一个个盒子里，每种字母一盒，所以你会有一个（大的）装 e 的盒子、一个（小的）装 x 的盒子，以此类推。这些盒子又放在一个个字盘（case）里（参见图 3.2），一盘装大写字母、一盘装小写字母。一整套字盘被称为一个 font（字体）。² 自然，如果你想印更大的文本，就需要不同（更大）的字模，于是那就是另一种字体；一组字体的集合被称为一个 type（活字），这也是我们把打字称作 typing 的原因。各种变体——比如粗体或斜体字母——则被称为该 type 的「字面」（face）。

这套命名反映的是印刷机的世界：来自不同铸字厂（foundry）的金属字模，装在盒子里，再装进字盘里。我们的现代世界取而代之的是下拉菜单，旧词汇已经不再匹配它。「font」如今可以指 font（字体）、typeface（字型）或 type（活字），³ 而且我们说一个字体包含若干种不同的字重（weight）（如「bold」（粗体）和「normal」（常规）），⁴ 若干种不同的样式（style）（如「italic」（斜体）和「roman」（正体）——非斜体的名字就叫这个），⁵ 以及任意的字号。⁶ 欢迎来到魔法墨水（magic ink）的世界。⁷

*图 3.1　一幅描绘印刷机工人的版画。（Daniel Nikolaus Chodowiecki [2] 绘，Wikipedia [3]，公有领域。）*

然而，Tk 的字体对象对应的是 font 一词更古老的含义：具有固定大小、样式和字重的一个 type。例如：⁸

```python
import tkinter.font
class Browser:
    def __init__(self):
        # ...
        bi_times = tkinter.font.Font(
            family="Times",
            size=16,
            weight="bold",
            slant="italic",
        )
```

> **怪癖**
> 你的计算机上可能没有安装「Times」；你可以用 `tkinter.font.families()` 列出可用字体，然后另挑一个。

*图 3.2　字盘中的金属活字和一个排字手托。（Willi Heidelbach 摄，Wikipedia [4]，CC BY 2.5 [5]。）*

字体对象可以传给 `create_text` 的 `font` 参数：

```python
canvas.create_text(200, 100, text="Hi!", font=bi_times)
```

> **深入探索**
> 在往昔岁月里，美国的排字工人把装金属字模的盒子按「加州字盘」（California job case）[7] 排布，它把小写和大写字母并排放在同一个字盘里，令排版更轻松。而大写/小写（upper-/lower-case）这套命名法还要早好几个世纪。

## 3.2　测量文本

文本在竖直和水平两个方向上都占据空间，字体对象的 `metrics` 和 `measure` 方法度量的就是这些空间：⁹

*图 3.3　字体的各种垂直度量。字体中所有字形（glyph）都共享相同的 ascent（上伸高度）、x-height（x 字高）和 descent（下伸深度），并排布在一条共享的基线（baseline）上。不过，各字形的 measure（步进宽度，又称 advance）可以不同。*

示意图：一条水平基线穿过单词 "Hey"；基线上方依次是 x-height 虚线与字形顶端（Ascent 区），下方是 Descent 区；「Measure」箭头标出单个字形占据的水平宽度。

```python
>>> bi_times.metrics()
{'ascent': 15, 'descent': 4, 'linespace': 19, 'fixed': 0}
>>> bi_times.measure("Hi!")
24
```

`metrics` 调用给出关于文本竖直尺寸的信息（参见图 3.3）：`linespace` 是文本的整体高度，其中包含「伸到线上方」的 ascent 和「垂到线下方」的 descent。¹⁰ 当不同大小的单词位于同一行时，ascent 和 descent 就很重要：它们应当「沿着那条线」对齐，而不是沿各自的顶部或底部对齐。

让我们再深挖一下。记住 `bi_times` 是 16 号的 Times：为什么 `font.metrics` 报告它实际上有 19 像素高？嗯，首先，大小 16 意味着 16 点（point，磅）——点被定义为 1/72 英寸——而不是 16 像素，¹¹ 你的显示器每英寸大概有 100 个像素。¹² 那 16 点度量的并不是字母本身，而是字母当年由之雕刻而来的金属字块，所以字母自身必定小于 16 点。事实上，同样 16 号的不同字体，字母高度各不相同：¹³

```python
>>> tkinter.font.Font(family="Courier", size=16).metrics()
{'fixed': 1, 'ascent': 13, 'descent': 4, 'linespace': 17}
>>> tkinter.font.Font(family="Times", size=16).metrics()
{'fixed': 0, 'ascent': 14, 'descent': 4, 'linespace': 18}
>>> tkinter.font.Font(family="Helvetica", size=16).metrics()
{'fixed': 0, 'ascent': 15, 'descent': 4, 'linespace': 19}
```

`measure()` 方法更直接：它告诉你文本在水平方向上占据多少空间，单位是像素。这当然取决于具体文本，因为不同字母有不同的宽度：¹⁴

```python
>>> bi_times.measure("Hi!")
24
>>> bi_times.measure("H")
13
>>> bi_times.measure("i")
5
>>> bi_times.measure("!")
7
>>> 13 + 5 + 7
25
```

你可以用这些信息在页面上布局文本。例如，假设你想把文本「Hello, world!」分成两段绘制，让「world!」显示为斜体。让我们使用两种字体：

```python
font1 = tkinter.font.Font(family="Times", size=16)
font2 = tkinter.font.Font(family="Times", size=16, slant='italic')
```

现在我们可以布局这段文本，从 (200, 200) 开始：

```python
x, y = 200, 200
canvas.create_text(x, y, text="Hello, ", font=font1)
x += font1.measure("Hello, ")
canvas.create_text(x, y, text="world!", font=font2)
```

你应该会看到「Hello,」和「world!」正确对齐，并且第二个单词是斜体。

不幸的是，这段代码有一个 bug，只是被示例文本的选择掩盖了：把「world!」换成「overlapping!」，这两个单词就会重叠。这是因为你传给 `create_text` 的坐标 `x` 和 `y` 告诉 Tk 的是把文本的中心放在哪里。它之所以对「Hello, world!」有效，只是因为「Hello,」和「world!」一样长！

幸运的是，传入坐标的含义是可配置的。我们可以把 `anchor` 参数设为 `"nw"`（意即文本的「西北」角），指示 Tk 把我们给出的坐标当作文本的左上角：

```python
x, y = 200, 225
canvas.create_text(x, y, text="Hello, ", font=font1, anchor='nw')
x += font1.measure("Hello, ")
canvas.create_text(x, y, text="overlapping!", font=font2, anchor='nw')
```

修改 `draw` 函数，把 `anchor` 设为 `"nw"`；上一章我们不需要这么做，因为所有中文字符的宽度都相同。

> **深入探索**
> 如果你觉得字体度量令人困惑，你不是一个人！2012 年，密歇根州最高法院审理了 Stand Up for Democracy 诉 Secretary of State 一案 [9]，这个案件归根结底关乎一次全民公投是否有效，而争议焦点正是字号的定义。法院（正确地）裁定：字号是字母由之雕刻而来的金属字块的大小，而不是字母本身的大小。

## 3.3　逐词布局

在第 2 章中，`layout` 函数逐字符遍历文本，并在空间用尽时移到下一行。这在中文里是合适的，因为每个字符差不多就是一个词。但在英文里，你不能在一个单词中间移到下一行。相反，我们需要一次一个单词地布局文本：¹⁵

```python
def layout(text):
    # ...
    for word in text.split():
        # ...
    return display_list
```

与中文字符不同，单词的大小各不相同，所以我们需要测量每个单词的宽度：

```python
def layout(text):
    font = tkinter.font.Font()
    # ...
    for word in text.split():
        w = font.measure(word)
    # ...
```

这里我选用 Tk 的默认字体。现在，如果我们在 `cursor_x` 处绘制文本，它的右端将位于 `cursor_x + w`。那可能已经越过了页面的右缘，这种情况下我们需要通过换行到下一行来腾出空间：

```python
def layout(text):
    for word in text.split():
        # ...
        if cursor_x + w > WIDTH - HSTEP:
            cursor_y += font.metrics("linespace") * 1.25
            cursor_x = HSTEP
```

注意，这个代码块只展示 `for` 循环的内部。`layout` 的其余部分应保持原样。另外，我调用 `metrics` 时带了一个参数；那会直接返回指定的度量值。最后，注意我在递增 `y` 时把 linespace 乘以了 1.25。试着去掉这个乘数：你会看到文本变得更难读，因为各行挨得太近了。¹⁶ 通常的做法是在行与行之间加入「行间距」（line spacing），也就是 leading（行距）。¹⁷ 25% 的行间距是一个常见的量。

现在 `cursor_x` 和 `cursor_y` 已经持有单词开始处的位置，于是我们把它加入显示列表，最后更新 `cursor_x` 使之指向单词末尾：

```python
def layout(text):
    for word in text.split():
        # ...
        display_list.append((cursor_x, cursor_y, word))
        cursor_x += w + font.measure(" ")
```

我把 `cursor_x` 递增 `w + font.measure(" ")` 而不是 `w`，因为我想在单词之间保留空格：`split()` 调用移除了所有空白字符，这里把它加回来。不过我没有把这个空格加进 `if` 条件中的 `w`，因为一行里最后一个单词后面并不需要空格。

> **深入探索**
> 在单词中间断行称为连字符断词（hyphenation），可以通过 `hyphens` CSS 属性 [10] 开启。目前最先进的是 Knuth–Liang 连字符断词算法 [11]，它用一个单词片段字典来为可能的断词点排定优先级。起初，CSS 规范与这一算法并不兼容 [12]，但新近的 `text-wrap-style` 属性 [13] 修复了这个问题。

## 3.4　为文本设置样式

目前，页面上的所有文本都用一种字体绘制。但网页有时会用 `<b>` 和 `<i>` 标签指定文本应为粗体或斜体。支持这一点会很棒，但现有代码对此束手无策：`layout` 函数只接收页面的文本作为输入，因此无从知晓粗体和斜体标签在哪里。

让我们修改 `lex`，让它返回一个词法单元（token）列表：一个词法单元要么是 `Text` 对象（对应标签之外的一段字符），要么是 `Tag` 对象（对应标签的内容）。你需要自己编写 `Text` 和 `Tag` 这两个类：¹⁸

```python
class Text:
    def __init__(self, text):
        self.text = text
class Tag:
    def __init__(self, tag):
        self.tag = tag
```

现在 `lex` 必须把文本收集到 `Text` 和 `Tag` 对象中：¹⁹

```python
def lex(body):
    out = []
    buffer = ""
    in_tag = False
    for c in body:
        if c == "<":
            in_tag = True
            if buffer: out.append(Text(buffer))
            buffer = ""
        elif c == ">":
            in_tag = False
            out.append(Tag(buffer))
            buffer = ""
        else:
            buffer += c
    if not in_tag and buffer:
        out.append(Text(buffer))
    return out
```

这里我把 `text` 变量改名为 `buffer`（缓冲区），因为它现在暂存的是尚待使用的文本或标签内容。这个名字还提醒我们：在循环结束时，需要检查是否还有缓冲下来的文本、该拿它怎么办。在这里，`lex` 把累积的文本倾倒为一个 `Text` 对象。而未完成的标签，比如 `Hi!<hr` 中的那种，则被丢弃。²⁰

注意 `Text` 和 `Tag` 是不对称的：`lex` 会避免产生空的 `Text` 对象，却不避免空的 `Tag` 对象。这是因为空的 `Tag` 对象代表 HTML 代码 `<>`，而空的 `Text` 对象不代表任何内容。

既然修改了 `lex`，现在传给 `layout` 的就不仅是页面的文本，还有其中的标签。所以 `layout` 必须遍历词法单元，而不是文本：

```python
def layout(tokens):
    # ...
    for tok in tokens:
        if isinstance(tok, Text):
            for word in tok.text.split():
                # ...
    # ...
```

`layout` 还可以检查标签词法单元，在页面的指示下更换字体。让我们先支持字重和样式，为此用两个对应的变量：

```python
weight = "normal"
style = "roman"
```

当看到粗体和斜体的开、闭标签时，这两个变量必须随之改变：

```python
if isinstance(tok, Text):
    # ...
elif tok.tag == "i":
    style = "italic"
elif tok.tag == "/i":
    style = "roman"
elif tok.tag == "b":
    weight = "bold"
elif tok.tag == "/b":
    weight = "normal"
```

注意，这段代码不仅能正确处理 `<b>bold</b>` 和 `<i>italic</i>` 文本，还能处理 `<b><i>bold italic</i></b>` 文本。²¹

`style` 和 `weight` 变量用来选择字体：

```python
if isinstance(tok, Text):
    for word in tok.text.split():
        font = tkinter.font.Font(
            size=16,
            weight=weight,
            slant=style,
        )
        # ...
```

由于字体是在 `layout` 中计算、却在 `draw` 中使用的，我们需要把所用的字体加进显示列表的每个条目：

```python
if isinstance(tok, Text):
    for word in tok.text.split():
        # ...
        display_list.append((cursor_x, cursor_y, word, font))
```

务必更新 `draw`，让它预期并使用显示列表条目中这个新增的 font 字段。

> **深入探索**
> 斜体字体诞生于意大利（故得此名），用来模仿一种称作「chancery hand」（文书手写体）[14] 的草书手写风格。非斜体字体被称为 roman（正体），因为它们模仿罗马纪念碑上的文字。还有一个小众的第三选项：oblique（倾斜体）字体 [15]，它看起来像正体字体，只是倾斜了。

## 3.5　Layout 对象

加上了这么多标签之后，`layout` 已经变得相当庞大：大量局部变量，控制流也有些复杂。这是一个信号，说明它配得上变成一个类，而不是函数：

```python
class Layout:
    def __init__(self, tokens):
        self.display_list = []
```

于是 `layout` 中的每个局部变量都变成 `Layout` 的一个字段：

```python
self.cursor_x = HSTEP
self.cursor_y = VSTEP
self.weight = "normal"
self.style = "roman"
self.size = 16
```

旧 `layout` 的核心是一个遍历词法单元的循环，我们可以把这个循环体移成 `Layout` 上的一个方法：

```python
def __init__(self, tokens):
    # ...
    for tok in tokens:
        self.token(tok)
def token(self, tok):
    if isinstance(tok, Text):
        for word in tok.text.split():
            # ...
    elif tok.tag == "i":
        self.style = "italic"
    # ...
```

实际上，`isinstance(tok, Text)` 分支的主体也可以移到它自己的方法里：

```python
def word(self, word):
    font = tkinter.font.Font(
        size=16,
        weight=self.weight,
        slant=self.style,
    )
    w = font.measure(word)
    # ...
```

既然所有内容都已从 `Browser` 旧的 `layout` 函数中移出，就可以用对 `Layout` 的调用来替换它：

```python
class Browser:
    def load(self, url):
        body = url.request()
        tokens = lex(body)
        self.display_list = Layout(tokens).display_list
        self.draw()
```

做这种大型重构时，循序渐进非常重要。一次性改完一切看似更高效，但那种效率伴随着失败的风险：想做的事太多，结果把自己绕晕，不得不放弃整个重构。所以，先花一点时间确认你的浏览器仍能正常工作，再继续前进。

总之，这次重构把所有文本处理代码隔离进了它自己的方法，主 `token` 函数只按标签名进行分支。让我们利用这种更干净的新组织来添加更多标签。字重和样式已经就绪，字号便是排版精进的下一站。改变字号的一个简单办法是 `<small>` 标签和它已被弃用的姊妹标签 `<big>`。²²

我们在字体样式和字重上的经验提示了一个简单做法：定制 `Layout` 的 `size` 字段。它起初是：

```python
self.size = 12
```

该变量用于创建字体对象：

```python
font = tkinter.font.Font(
    size=self.size,
    weight=self.weight,
    slant=self.style,
)
```

通过更新这个变量，就能改变 `<big>` 和 `<small>` 标签中的字号：

```python
def token(self, tok):
    # ...
    elif tok.tag == "small":
        self.size -= 2
    elif tok.tag == "/small":
        self.size += 2
    elif tok.tag == "big":
        self.size += 4
    elif tok.tag == "/big":
        self.size -= 4
```

试着用 `<small>` 包住一整段文字，就像对待一段小字条款那样，然后享受你新获得的排版自由。

> **深入探索**
> `<b>`、`<i>`、`<big>` 和 `<small>` 全都源自 Web 早期那个尚无 CSS 的年代。如今，CSS 可以改变元素的外观，因此像 `<b>` 和 `<small>` 这样描述视觉的标签名已经失宠。话虽如此，`<b>`、`<i>` 和 `<small>` 仍各有若干与外观无关的含义 [16]。

## 3.6　不同尺寸的文本

*图 3.4　混用多种字体时一行的布局方式。所有单词都沿一条共享的基线绘制。整行的 ascent 和 descent 由该行所有单词的最大 ascent 和最大 descent 决定，并且行前与行后都会加上 leading（行距）。*

示意图：Top → Half-Leading → Ascent → Baseline（单词 "Hey" 坐在基线上）→ Descent → Half-Leading → Bottom；整行的 ascent/descent 取行内各单词的最大值。

开始混用字号，比如 `<small>a</small><big>A</big>`，你很快就会注意到字号代码的一个问题：文本是沿顶部对齐的，就好像挂在晾衣绳上。但你知道，英文文本通常是这样书写的：所有字母对齐到一条看不见的基线上。

让我们想想如何修复。如果把较大的文本上移，它会与上一行重叠，所以必须把较小的文本下移。这意味着它的竖直位置必须晚些计算，即在大文本经过 `token` 之后。但由于较小的文本先进入循环，我们需要一个针对文本行的两遍（two-pass）算法：第一遍确定哪些单词进入该行并计算它们的 x 坐标；第二遍竖直地对齐这些单词并计算它们的 y 坐标（参见图 3.4）。

让我们从第一阶段开始。由于一行会包含来自多个标签的文本，我们需要在 `Layout` 上有一个字段来存放「将成之行」。该字段 `line` 将是一个列表，`word` 方法会把单词添加到其中，而不是添加到显示列表。`line` 中的条目将有 x 坐标而没有 y 坐标，因为 y 坐标在第一阶段还不计算：

```python
class Layout:
    def __init__(self, tokens):
        # ...
        self.line = []
        # ...
    def word(self, word):
        # ...
        self.line.append((self.cursor_x, word, font))
```

新的 `line` 字段本质上是一个缓冲区，单词在被放置之前暂存于此。第二阶段则是在一行完成时把这个缓冲区冲刷（flush）出去：

```python
class Layout:
    def word(self, word):
        if self.cursor_x + w > WIDTH - HSTEP:
            self.flush()
```

*图 3.5　把一行上的单词对齐。*

示意图：同一行中大小不同的单词从各自按顶部对齐，改为沿共同基线对齐：较小的单词整体下移，使其基线与较大单词的基线重合。

与缓冲区打交道时的惯例一样，我们还得确保在所有词法单元处理完之后，把缓冲区再冲刷一次：

```python
class Layout:
    def __init__(self, tokens):
        # ...
        self.flush()
```

这个新的 `flush` 函数有三项职责：

- 它必须把单词沿基线对齐（参见图 3.5）；
- 它必须把所有这些单词加入显示列表；
- 它必须更新 `cursor_x` 和 `cursor_y` 字段。

既然我们希望单词「排在那条线上」，那就先来计算那条线应该在哪里。这取决于该行中最高的单词：

```python
def flush(self):
    if not self.line: return
    max_ascent = max([font.metrics("ascent")
        for x, word, font in self.line])
```

于是基线位于 `self.y` 下方 `max_ascent` 处——实际上还要再多一点，以计入行距：²³

```python
baseline = self.cursor_y + 1.25 * max_ascent
```

现在我们知道了那条线的位置，就可以相对于它放置每个单词，并将其加入显示列表：

```python
for x, word, font in self.line:
    y = baseline - font.metrics("ascent")
    self.display_list.append((x, y, word, font))
```

注意 `y` 如何从基线出发，向上移动恰好容纳该单词 ascent 的距离。现在，`y` 必须向下移到基线下方足够远处，以容纳下伸最深的字母：

```python
max_descent = max([metric["descent"] for metric in metrics])
self.cursor_y = baseline + 1.25 * max_descent
```

最后，`flush` 必须更新 `Layout` 的 `cursor_x` 和 `line` 字段。`x` 和 `line` 很简单：

```python
self.cursor_x = HSTEP
self.line = []
```

现在所有文本都沿那条线对齐了，即使混用了文本尺寸也一样。此外，这个新的 `flush` 函数对其他断行任务也很方便。例如，在 HTML 中，`<br>` 标签²⁴ 会结束当前行并另起一行：

```python
def token(self, tok):
    # ...
    elif tok.tag == "br":
        self.flush()
```

类似地，段落由 `<p>` 和 `</p>` 标签定义，所以 `</p>` 也会结束当前行：

```python
def token(self, tok):
    # ...
    elif tok.tag == "/p":
        self.flush()
        self.cursor_y += VSTEP
```

我在这里给 `cursor_y` 额外加了一点，好在段落之间留出些空隙。

> 实际上，浏览器不仅支持水平书写系统，也支持竖直书写系统 [19]，比如一些传统的东亚书写方式。一个特别的挑战是蒙古文 [20]：它自上而下、从左到右成行书写。许多蒙古国政府网站 [21] 使用的就是这种文字。

## 3.7　字体缓存

既然你已经实现了带样式的文本，你大概已经注意到——除非你用的是 macOS²⁵——在像本章 [1] 这样的大网页上，我们的浏览器比上一章明显变慢了。这是因为文本布局，尤其是逐个测量单词的那部分，相当慢。²⁶

不幸的是，很难让文本测量快上多少。面对比例字体（proportional font）以及微调（hinting）、字距调整（kerning）等复杂字体特性，测量文本可能需要相当复杂的计算。但在大网页上，某些单词很可能大量出现——例如，本章里「the」一词出现了 200 多次。与其一遍又一遍地测量这些单词，不如只测一次，然后缓存（cache）结果。在普通英文文本上，这通常能带来显著的加速。

缓存是个好主意，好到大多数文本库都已实现了它，通常是把这些测量结果缓存到每个 `Font` 对象里。但由于我们的 `text` 方法为每个单词新建一个 `Font` 对象，缓存形同虚设。要让缓存生效，我们需要尽可能复用 `Font` 对象，而不是不断新建。

我们把缓存存放在一个全局的 `FONTS` 字典里：

```python
FONTS = {}
```

这个字典的键是 size/weight/style 三元组，值则是 `Font` 对象。²⁷ 我们可以把缓存逻辑本身放进一个新的 `get_font` 函数：

```python
def get_font(size, weight, style):
    key = (size, weight, style)
    if key not in FONTS:
        font = tkinter.font.Font(size=size, weight=weight,
            slant=style)
        label = tkinter.Label(font=font)
        FONTS[key] = (font, label)
    return FONTS[key][0]
```

然后，`word` 方法就可以调用 `get_font`，而不是直接创建 `Font` 对象：

```python
class Layout:
    def word(self, word):
        font = get_font(self.size, self.weight, self.style)
        # ...
```

现在，相同的单词会使用相同的字体，文本测量也会命中缓存。

> **深入探索**
> 像中文这样的文字系统，其字体可能有好几兆字节，因此通常存放在磁盘上，仅在需要时才加载进内存。这使得字体加载很慢，缓存也就更加重要。浏览器还为文本的测量、整形（shaping）和渲染准备了大量缓存。由于网页含有大量文本，这些缓存最终成为加速渲染最重要的组成部分之一。

## 3.8　总结

上一章我们得到的是一个把字符排成网格的浏览器。现在它做的是标准的英文文本布局，因此：

- 文本逐词布局；
- 行在单词边界处断开；
- 文本可以是粗体或斜体；
- 可以混用不同尺寸的文本。

现在你可以用我们的浏览器来阅读一篇文章、一篇博文，甚至一本书了！

## 3.10　练习

### 练习 3.1　居中文本（Centered text）

本书网站 [23] 的页面标题是居中的；让你的浏览器对 `<h1 class="title">` 与 `</h1>` 之间的文本做同样的事。每一行都必须单独居中，因为不同行的长度各不相同。²⁸

### 练习 3.2　上标（Superscripts）

添加对 `<sup>` 标签的支持。该标签中的文本应当更小（约为正常文本大小的一半），并且放置时应使上标的顶部与普通字母的顶部对齐。

### 练习 3.3　软连字符（Soft hyphens）

软连字符（soft hyphen）在 Python 中写作 `\N{soft hyphen}`，它表示文本渲染器可以（但不必）在此处插入连字符并把单词断到两行。请添加对它的支持。²⁹ 如果一个单词在一行末尾放不下，检查它是否含有软连字符；若有，就把这个单词断行。记住，一个单词里可能有多个软连字符，而且断词时务必把连字符画出来。「supercalifragilisticexpialidocious」这个词是个不错的测试用例。

### 练习 3.4　小型大写字母（Small caps）

让 `<abbr>` 元素以小型大写字母（small caps）渲染文本，LIKE THIS（就像这样）。在 `<abbr>` 标签内，小写字母应当以更小、大写且加粗的形式呈现，而所有其他字符（大写字母、数字等）应当用正常字体绘制。

### 练习 3.5　预格式化文本（Preformatted text）

添加对 `<pre>` 标签的支持。与普通段落不同，`<pre>` 标签内的文本不会自动断行，空格、换行等空白字符都会保留。还要使用一种等宽字体（fixed-width font），比如 Courier New 或 SFMono。确保标签在 `<pre>` 标签内照常工作：应当可以在一个 `<pre>` 里把某些文本加粗。如果你同时也做了练习 1.4，效果会最好。

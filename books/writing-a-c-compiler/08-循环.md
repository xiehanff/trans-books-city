# 第 8 章　循环

*Chapter 8: Loops*

本章将添加所有与循环相关的内容：for、while 和 do 循环，再加上用于跳过循环中部分代码的 break 和 continue 语句。这些是你在本书中实现的最后一批语句。完成本章之后，如果你已经实现了所有额外加分特性，你的编译器将能够处理所有种类的 C 语句。

不过，你还得先做些准备工作！你将更新词法分析器和解析器以支持全部五种新语句。然后，你将添加一个新的语义分析遍，我们称之为循环打标签（loop labeling）。这一新遍（在本章开头的示意图中以粗体标出）会对 AST 进行标注，把每条 break 或 continue 语句与包含它的循环关联起来。最后，你将把每条新语句翻译成一串 TACKY 指令。所有新语句都可以用你已经定义过的 TACKY 指令来实现，因此在 TACKY 生成之后的各个阶段都不需要改动。

本章的新语句会引入一些需要处理的边界情况和错误。在开始改词法分析器之前，我们先简要讨论一下这些语句。

## 循环及如何跳出循环

先来看三种循环语句，然后再讨论 break 和 continue 语句。清单 8-1 展示了一个 while 循环的例子。

```c
while ( ❶ a > 0)
    a = a / 2;
```

*清单 8-1：一个 while 循环*

首先，我们求值该语句的控制表达式（controlling expression）❶。如果它是 0（即假），循环结束，我们接着执行下一条语句。如果它非零，我们就执行 while 循环体，然后回到控制表达式，如此周而复始。

do 循环（如清单 8-2 所示）与此几乎完全相同。

```c
do
    a = a + 1;
while (a < 100);
```

*清单 8-2：一个 do 循环*

唯一的区别是：我们先执行循环体，再检查控制表达式。这意味着循环体至少会被执行一次。与 if 语句体一样，循环体也是单条语句，它可以是包含声明的复合语句（compound statement）。你在循环体中声明的任何变量，在控制表达式里都不在作用域内。例如，清单 8-3 是无效的。

```c
do {
    int a = a + 1;
} while (a < 100);
```

*清单 8-3：控制表达式使用了作用域之外的变量的 do 循环*

for 循环的情况开始变得更复杂。它有两种不同的形式。第一种如清单 8-4 所示，循环头部（loop header）由三个表达式组成。

```c
int a;
for ( ❶ a = 0; ❷ a < 5; ❸ a = a + 1)
    b = b * 2;
```

*清单 8-4：初始子句为表达式的 for 循环*

初始表达式 ❶ 在第一次循环迭代之前求值一次。然后，每次迭代时我们：

1. 求值控制表达式 ❷。如果它为假，循环终止。否则，我们……
2. 执行语句体。
3. 求值最终表达式 ❸。

你可以省略循环头部中任意或全部表达式。如果省略初始表达式或最终表达式，那么在正常情况下应当求值该子句的地方什么也不会发生。如果省略控制表达式，该循环的行为就如同其控制表达式恒为真（即非零）。也就是说，除非循环体中含有能将控制权转移出循环体的 break、goto 或 return 语句，否则它永远不会终止。

清单 8-5 展示了第二种 for 循环，其初始子句（initial clause）是声明而非表达式。

```c
for (int a = 0; a < 5; a = a + 1)
    b = b * 2;
```

*清单 8-5：初始子句中带有声明的 for 循环*

for 循环头部会引入一个新的作用域，因此你可以写出清单 8-6 这样的代码。

```c
int a = 5;
for (int a = 0; a < 5; a = a + 1)
    b = b + a;
```

*清单 8-6：在 for 循环之前和循环头部声明两个同名变量*

在这个清单中，循环头部声明的变量 a 隐藏了前一行声明的变量 a。而且，由于复合语句总是会引入新的作用域——当它作为循环体出现时也不例外——清单 8-7 同样有效。

```c
❶ int a = 5;
for ( ❷ int a = 0; a < 5; a = a + 1) {
  ❸ int a = 1;
    b = b + a;
}
```

*清单 8-7：在 for 循环之前、循环头部和循环体中声明三个同名变量*

在清单 8-7 中，有三个互不相同却都叫 a 的变量：一个在循环开始之前声明 ❶，一个在循环头部声明 ❷，还有一个在循环体中声明 ❸。

虽然 for 循环头部中的各个表达式是可选的，但循环体是必需的。（do 循环和 while 循环的循环体同样必需。）不过，循环体可以是一条空语句（null statement），如清单 8-8 所示。

```c
while ((a = a + 1) < 10)
    ;
```

*清单 8-8：用空语句作为循环体*

这里孤零零的 ; 是一条空语句。尽管这条语句什么也不做，我们也必须把它写出来，这样解析器才能确定循环在哪里结束。正如我们在第 5 章实现空语句时看到的，它们并不是循环特有的构造；在任何能使用其他语句的地方，你都可以使用空语句。不过在实践中，它们大多出现在循环体中，因为在其他地方很少派得上用场。

现在来谈谈 break 和 continue 语句。这两者都只能出现在循环内部。（严格说来，这话不完全对；break 语句也可以出现在 switch 语句内部，你可以把 switch 作为本章的一个额外加分特性来实现。）break 语句（如清单 8-9 所示）会跳转到循环结束之后的位置。

```c
while (1) {
    a = a - 1;
    if (a < 0)
        break;
}
return a;
```

*清单 8-9：一条 break 语句*

执行到这条 break 语句时，我们会跳转到 while 循环之后的 return 语句。

break 语句只终止最内层的循环。例如，考虑清单 8-10 中的代码片段。

```c
while (b > 0) {
    do {
        a = a - 1;
        if (a < 0)
            break;
    } while (1);
    b = b * a;
}
return b;
```

*清单 8-10：用 break 语句跳出两个嵌套循环中的内层循环*

到达这个清单中的 break 语句时，我们会跳出内层循环，但不会跳出外层循环，因此会跳转到 b = b * a;。在本章中，我会把包含某条 break 或 continue 语句的最内层循环称为该语句的外围循环（enclosing loop）。（把它叫作「最小外围循环」（smallest enclosing loop）会更贴合 C 标准的术语，但那样说有点拗口。）

continue 语句会跳转到外围循环的循环体中最后一条语句之后的位置。考虑清单 8-11 中的例子。

```c
while (a > 0) {
    a = a * b;
    if (b > 0)
        continue;
    b = b + 1;
    return b;
❶}
```

*清单 8-11：一条 continue 语句*

到达 continue 语句时，我们会跳过它后面的所有语句，跳转到循环体的末尾 ❶。从那里开始，while 循环照常执行，也就是说它会跳回控制表达式。for 循环中的 continue 语句（如清单 8-12 所示）的工作方式与此相同。

```c
for (int i = 0; i < 5; ❶ i = i + 1) {
    a = a * i;
    if (b > 0)
        continue;
    b = b + 1;
❷}
```

*清单 8-12：for 循环中的一条 continue 语句*

在这个清单中，我们仍然从 continue 语句跳转到循环体的末尾 ❷。然后，和往常一样，跳转到最终表达式 ❶。

如果 break 或 continue 语句出现在循环之外，如清单 8-13 所示，编译应当失败。

```c
int main(void) {
    break;
}
```

*清单 8-13：一条无效的 break 语句*

不过，这些语句出现在循环内很深的嵌套层次中完全没问题，比如清单 8-14 中的 break 语句。

```c
while (1) {
    if (a > 4) {
        b = b * 2;
        return a + b;
    } else {
        int c = a ? b : 5;
        {
            int d = c;
            break;
        }
    }
    return 0;
}
return 1;
```

*清单 8-14：出现在循环内若干层深处的 break 语句*

这条 break 语句会跳转到 return 1;，因为那正是循环结束之后的位置。

一个循环中出现多条 break 和 continue 语句是合法的，如清单 8-15 所示。

```c
for (int i = 0; i < 10; i = i + 1) {
    if (i % 2 == 0)
        continue;
    if (x > y)
        continue;
    break;
}
```

*清单 8-15：一个循环内的多条 break 和 continue 语句*

## 解析器

接下来，我们更新 AST。我们将添加五个新语句：

```text
statement = Return(exp)
          | Expression(exp)
          | If(exp condition, statement then, statement? else)
          | Compound(block)
          | Break
          | Continue
          | While(exp condition, statement body)
          | DoWhile(statement body, exp condition)
          | For(for_init init, exp? condition, exp? post, statement body)
          | Null
```

break 和 continue 语句简单到了极点。while 和 do 语句也相对简单：两者都有一个循环体和一个控制表达式。for 语句最复杂：它包含一个初始子句、一个可选的控制表达式、一个可选的最终表达式以及一个循环体。初始子句可以是声明、表达式或者什么都没有，因此我们需要一个新的 AST 节点来描述它：

```text
for_init = InitDecl(declaration) | InitExp(exp?)
```

把所有这些组合起来，就得到了最新的 AST 定义，如清单 8-16 所示。

```text
program = Program(function_definition)
function_definition = Function(identifier name, block body)
block_item = S(statement) | D(declaration)
block = Block(block_item*)
declaration = Declaration(identifier name, exp? init)
for_init = InitDecl(declaration) | InitExp(exp?)
statement = Return(exp)
          | Expression(exp)
          | If(exp condition, statement then, statement? else)
          | Compound(block)
          | Break
          | Continue
          | While(exp condition, statement body)
          | DoWhile(statement body, exp condition)
          | For(for_init init, exp? condition, exp? post, statement body)
          | Null
exp = Constant(int)
    | Var(identifier)
    | Unary(unary_operator, exp)
    | Binary(binary_operator, exp, exp)
    | Assignment(exp, exp)
    | Conditional(exp condition, exp, exp)
unary_operator = Complement | Negate | Not
binary_operator = Add | Subtract | Multiply | Divide | Remainder | And | Or
                | Equal | NotEqual | LessThan | LessOrEqual
                | GreaterThan | GreaterOrEqual
```

*清单 8-16：带有循环及 break、continue 语句的抽象语法树*

本章更新 AST 时有一个麻烦之处。循环打标签遍会为程序中的每条 break、continue 和循环语句标注一个标签（label）（我们会用这些标签把每条 break 和 continue 语句与其外围循环关联起来）。这意味着你需要某种方式把这些标签附加到 AST 中的新语句上。有几种不同的选择。一种是为每个新构造函数都加一个标签参数，像这样：

```text
statement = --snip--
          | Break(identifier label)
          | Continue(identifier label)
          | While(exp condition, statement body, identifier label)
          | DoWhile(statement body, exp condition, identifier label)
          | For(for_init init, exp? condition, exp? post, statement body, identifier label)
```

如果采用这种方案，你可能需要在解析期间使用占位标签，然后在循环打标签遍中把它们替换为真正的标签。另一种选择是定义两个 AST 数据结构：一个不带标注，在循环打标签之前使用；另一个带标注，在循环打标签之后使用。哪种做法合适，取决于你编写编译器所用的语言（也取决于你的个人品味）。

更新 AST 之后，我们要对文法（grammar）做相应的修改，如清单 8-17 所示。

```text
<program> ::= <function>
<function> ::= "int" <identifier> "(" "void" ")" <block>
<block> ::= "{" {<block-item>} "}"
<block-item> ::= <statement> | <declaration>
<declaration> ::= "int" <identifier> ["=" <exp>] ";"
<for-init> ::= <declaration> | [<exp>] ";"
<statement> ::= "return" <exp> ";"
              | <exp> ";"
              | "if" "(" <exp> ")" <statement> ["else" <statement>]
              | <block>
              | "break" ";"
              | "continue" ";"
              | "while" "(" <exp> ")" <statement>
              | "do" <statement> "while" "(" <exp> ")" ";"
              | "for" "(" <for-init> [<exp>] ";" [<exp>] ")" <statement>
              | ";"
<exp> ::= <factor> | <exp> <binop> <exp> | <exp> "?" <exp> ":" <exp>
<factor> ::= <int> | <identifier> | <unop> <factor> | "(" <exp> ")"
<unop> ::= "-" | "~" | "!"
<binop> ::= "-" | "+" | "*" | "/" | "%" | "&&" | "||"
          | "==" | "!=" | "<" | "<=" | ">" | ">=" | "="
<identifier> ::= ? 一个标识符词法单元 ?
<int> ::= ? 一个常量词法单元 ?
```

*清单 8-17：带有循环及 break、continue 语句的文法*

我建议编写一个解析可选表达式的辅助函数。你可以用这个辅助函数来解析 for 循环头部中的两个可选表达式，另外还可以用它解析表达式语句和空语句。这个辅助函数应当允许你指定哪个词法单元标志着可选表达式的结束；文法中大多数可选表达式后面都跟着分号，但 for 循环头部的第三个子句后面跟的是右括号。

## 语义分析

你的编译器的语义分析阶段目前只执行一项任务：解析变量名。本章中，它将承担一项全新的任务：循环打标签。循环打标签遍把每条 break 和 continue 语句与其外围循环关联起来。更具体地说，这一遍为每条循环语句分配一个唯一的 ID，并为每条 break 和 continue 语句标注其外围循环的 ID。如果它在循环之外发现了 break 或 continue 语句，就会抛出错误。在 TACKY 生成期间，我们将利用这些标注，把每条 break 和 continue 语句转换为一个跳转，跳到相对其外围循环的正确位置。

我们将在两个独立的遍（pass）中分别完成变量名解析和循环打标签，每一遍都会遍历整个程序。我们先扩展变量解析遍来处理本章的新语句，然后再实现循环打标签遍。

### 扩展变量解析

你需要扩展 resolve_statement，让它遍历本章添加的五种新语句。对 while 和 do 循环的处理方式与 if 语句一样：递归处理每个子语句和子表达式。解析 break 和 continue 语句则更加简单；由于它们没有任何子语句或子表达式，你什么都不用做。

解析 for 循环稍微复杂一点点，因为循环头部会引入一个新的变量作用域。清单 8-18 演示了如何在 resolve_statement 中处理 for 循环。

```text
resolve_statement(statement, variable_map):
    match statement with
    | --snip--
    | For(init, condition, post, body) ->
        new_variable_map = copy_variable_map(variable_map)
        init = resolve_for_init(init, new_variable_map)
        condition = resolve_optional_exp(condition, new_variable_map)
        post = resolve_optional_exp(post, new_variable_map)
        body = resolve_statement(body, new_variable_map)
        return For(init, condition, post, body)
```

*清单 8-18：解析一个 for 循环*

我们首先复制一份新的变量映射表（variable map），就像在复合语句开头所做的那样。复制映射表可以确保在循环头部声明的变量在循环之外不可见，而且当它隐藏了外层作用域的变量时，也不会触发编译器错误。

接下来，我们用 resolve_for_init 处理初始子句，稍后会看到它的实现。然后，我们使用新的变量映射表遍历 for 循环的控制表达式、最终表达式和循环体。我不会提供 resolve_optional_exp 的伪代码，它负责处理可选的控制表达式和最终表达式；它只是在表达式存在时调用 resolve_exp，在表达式不存在时什么也不做。

清单 8-19 给出了 resolve_for_init 的伪代码。

```text
resolve_for_init(init, variable_map):
    match init with
    | InitExp(e) -> return InitExp(resolve_optional_exp(e, variable_map))
    | InitDecl(d) -> return InitDecl(resolve_declaration(d, variable_map))
```

*清单 8-19：解析 for 循环的初始子句*

我们对初始子句中的表达式或声明的解析方式，与它出现在程序其他任何地方时完全相同。如果该子句是声明，调用 resolve_declaration 会把新声明的变量加入变量映射表，使其在循环的其余部分可见。

### 循环打标签

解析完变量之后，我们会再次遍历程序，为每条循环、break 和 continue 语句标注一个 ID。每当遇到一条循环语句，我们就为它生成一个唯一的 ID。然后，在遍历循环体时，我们把同一个 ID 附加到遇到的每条 break 和 continue 语句上。来看几个例子。在接下来的三个清单中，标记 ❶ 和 ❷ 表示附加到 AST 上的 ID。虽然循环打标签遍标注的是 AST 而不是源文件，但为了便于阅读，这些清单以源代码的形式呈现。

清单 8-20 展示了我们如何标注一个包含两个连续循环的代码片段。

```c
❶ while (1) {
    a = a - 1;
    if (a < 0)
      ❶ break;
}

❷ for (int b = 0; b < 100; b = b + 1) {
    if (b % 2 == 0)
      ❷ continue;
    a = a * b;
}
return a;
```

*清单 8-20：标注 break、continue 语句及其外围循环*

这个清单中的两个循环各获得自己的 ID。我们用 ID ❶ 标注 while 循环，用 ID ❷ 标注 for 循环。每条 break 或 continue 语句都标注其外围循环的 ID，因此 break 语句标注为 ID ❶，continue 语句标注为 ID ❷。

如果多条 break 或 continue 语句位于同一个外围循环中，它们都会标注相同的 ID，如清单 8-21 所示。

```c
❶ for (int i = 0; i < 10; i = i + 1) {
    if (i % 2 == 0)
      ❶ continue;
    if (x > y)
      ❶ continue;
  ❶ break;
}
```

*清单 8-21：标注同一循环中的多条 break 和 continue 语句*

由于标记为 ❶ 的 for 循环是那两条 continue 语句和那条 break 语句的外围循环，我们把这三条语句全部标注为 ID ❶。

如果 break 或 continue 语句出现在嵌套循环中，我们用其外围循环（也就是最内层循环）的 ID 来标注它。清单 8-22 展示了如何标注嵌套循环。

```c
❶ while (a > 0) {
  ❷ for (int i = 0; i < 10; i = i + 1) {
        if (i % 2 == 0)
          ❷ continue;
        a = a / 2;
    }
    if (a == b)
      ❶ break;
}
```

*清单 8-22：标注嵌套循环*

外层 while 循环和内层 for 循环分别标记为 ❶ 和 ❷。由于 continue 语句出现在内层循环中，我们把它标注为 ID ❷。break 语句位于外层循环中，所以我们把它标注为 ID ❶。

### 实现循环打标签

为了实现这个编译器遍，我们在遍历 AST 时把当前循环 ID 作为参数传递下去，就像在变量解析遍中把变量映射表作为参数传给 resolve_statement、resolve_exp 等函数一样。当我们位于循环之外时，当前 ID 为 null、None，或者你的实现语言用来表示「值不存在」的任何东西。当我们遇到一条循环语句时，就生成一个新的 ID 并用它标注该语句。然后，在遍历循环体时，我们把它作为当前 ID 传递下去。当我们遇到 break 或 continue 语句时，就用传给我们的 ID 标注它。清单 8-23 中的伪代码展示了如何用循环 ID 标注语句。

```text
label_statement(statement, current_label):
    match statement with
    | Break ->
        if current_label is null:
            fail("break statement outside of loop")
        return ❶ annotate(Break, current_label)
    | Continue ->
        if current_label is null:
            fail("continue statement outside of loop")
        return ❷ annotate(Continue, current_label)
    | While(condition, body) ->
        new_label = ❸ make_label()
        labeled_body = label_statement(body, new_label)
        labeled_statement = While(condition, labeled_body)
        return ❹ annotate(labeled_statement, new_label)
    | --snip--
```

*清单 8-23：循环标注算法*

make_label 辅助函数 ❸ 生成唯一的循环 ID；你可以在这里复用那个在 TACKY 中生成唯一标签的辅助函数。annotate 辅助函数接收一个语句 AST 节点和一个标签，返回该 AST 节点带有此标签标注的副本。在这里，我们用它来标注 Break ❶、Continue ❷ 和 While ❹ 语句。我没有提供 annotate 的定义，因为它取决于你在 AST 中究竟如何表示循环标注。我还省略了处理 DoWhile、For 以及之前各章添加的所有语句的伪代码。处理 DoWhile 和 For 的方式与 While 基本相同。要处理其他任何类型的语句，只需对每个子语句递归调用 label_statement，并传递相同的 current_label 值。

更新完循环打标签遍之后，你就可以测试整个语义分析阶段了。

## TACKY 生成

接下来，我们把每种新语句转换为 TACKY。本章不会修改 TACKY 中间表示（IR），因为这些语句都可以用现有的 TACKY 指令来实现。

### break 与 continue 语句

break 语句无条件地跳转到程序中的另一个位置，因此我们用一条 Jump 指令来实现它。continue 语句也是如此。唯一的问题在于要跳转到哪里。上一节添加的循环标注帮我们回答了这个问题。

每当我们把一条循环语句转换为 TACKY 时，我们都会在循环体指令的紧后面发射（emit）一个 Label。该循环中的任何 continue 语句都可以实现为跳转到这个标签，我把它称为 continue 标签。我们还会发射另一个 Label 作为整个循环的最后一条指令；我把它称为 break 标签。

这些标签由循环标注遍中添加的 ID 派生而来。例如，如果某个循环被标注为 loop0，那么它的 break 标签和 continue 标签可能分别是 break_loop0 和 continue_loop0。使用这个示例命名方案，我们会把一个标注为 ID loop0 的 Break AST 节点转换为下面这条 TACKY 指令：

```text
Jump("break_loop0")
```

我们会把带有相同标注的 Continue 节点转换为：

```text
Jump("continue_loop0")
```

你不必非得采用这个命名方案（不过你的命名方案必须保证这些标签不会与 TACKY 程序中的任何其他标签冲突）。关键在于，把 break 或 continue 语句转换为 TACKY 时派生的标签，与把其外围循环转换为 TACKY 时派生的标签是同一个，因为该语句与其外围循环标注了相同的 ID。

### do 循环

我们可以分三步执行语句 do <body> while (<condition>);。首先，执行循环体。然后，求值条件并把结果与零比较。最后，如果结果非零，就跳回循环的开头。清单 8-24 演示了如何在 TACKY 中实现这些步骤。

```text
Label(start)
<instructions for body>
<instructions for condition>
v = <result of condition>
JumpIfNotZero(v, start)
```

*清单 8-24：do 循环的 TACKY 指令*

我们还需要 break 标签和 continue 标签。continue 标签放在循环体和条件之间，break 标签放在最末尾，即 JumpIfNotZero 之后。加上这两个标签，就得到了 do 循环完整的 TACKY，如清单 8-25 所示。

```text
Label(start)
<instructions for body>
Label(continue_label)
<instructions for condition>
v = <result of condition>
JumpIfNotZero(v, start)
Label(break_label)
```

*清单 8-25：带有 break 和 continue 标签的 do 循环 TACKY 指令*

现在，循环体中的任何 continue 语句都会跳转到 continue 标签，任何 break 语句都会跳转到 break 标签。只有当 break 或 continue 语句出现在循环体中的某处时，这些标签才有必要存在——否则它们不会被用到——但为了简单起见，我们会始终发射它们。这样一来，我们就不需要判断循环中是否包含 break 或 continue 语句。

### while 循环

我们对 while 循环的处理与 do 循环类似，但这次要先执行条件，再执行循环体，然后使用 JumpIfZero 在条件为假时退出循环。我们可以把语句 while (<condition>) <body> 转换为清单 8-26 中的 TACKY。

```text
Label(start)
<instructions for condition>
v = <result of condition>
JumpIfZero(v, end)
<instructions for body>
❶ Jump(start)
Label(end)
```

*清单 8-26：while 循环的 TACKY 指令*

现在来确定 break 标签和 continue 标签放在哪里。这一次，我们不需要额外的 Label 指令；可以直接复用清单 8-26 中已经存在的 Label 指令。我们把 break 标签放在这个清单末尾的 Label 指令处。它将同时作为 JumpIfZero 指令和循环体中任何 break 语句的跳转目标。

类似地，我们把 continue 标签放在这个清单开头的 Label 指令处。这与把 continue 标签放在循环体末尾 ❶ 之后的效果相同，因为循环体后面的那条指令是一个无条件跳转，会立即把我们带回循环开头。让 continue 语句直接跳转到循环开头，可以绕过那条 Jump 指令，从而使它们稍微更高效一点。

清单 8-27 展示了在把 while 循环转换为 TACKY 时如何使用 break 标签和 continue 标签。

```text
Label(continue_label)
<instructions for condition>
v = <result of condition>
JumpIfZero(v, break_label)
<instructions for body>
Jump(continue_label)
Label(break_label)
```

*清单 8-27：带有 break 和 continue 标签的 while 循环 TACKY 指令*

这段 TACKY 与清单 8-26 完全相同，只是用 continue_label 和 break_label 取代了 start 和 end。

### for 循环

最后一项任务是把 for 循环转换为 TACKY。我们会把语句 for (<init> ; <condition> ; <post>) <body> 转换为清单 8-28 中的 TACKY，其中包含了 break 标签和 continue 标签。

```text
<instructions for init>
Label(start)
<instructions for condition>
v = <result of condition>
JumpIfZero(v, break_label)
<instructions for body>
Label(continue_label)
<instructions for post>
Jump(start)
Label(break_label)
```

*清单 8-28：for 循环的 TACKY 指令*

首先，我们执行 <init>。然后，我们执行控制表达式 <condition>，并检查结果是否为零。如果是，就跳转到最末尾的 Label(break_label)，既不执行循环体也不执行最终表达式。否则，我们执行循环体，接着执行最终表达式 <post>，然后跳回 Label(start)，开始下一次循环迭代。我们不会再次执行 <init>，因为 Label(start) 位于 <init> 之后。注意，continue 标签出现在循环体的末尾、紧挨着 <post> 之前，而 break 标签出现在整个循环的最末尾，它身兼两职：既是 JumpIfZero 指令的目标，也是任何 break 语句的目标。

接下来，我们逐一分析如何处理循环头部的三个子句。第一个子句可以是表达式、声明或者什么都没有。如果它是声明或表达式，我们的处理方式与 for 循环之外的声明或表达式完全相同。如果它不存在，我们就不发射任何指令。

第二个子句是控制表达式。如果这个表达式存在，我们就完全按照 while 和 do 循环中控制表达式的方式把它转换为 TACKY。如果它不存在，C 标准规定该表达式「由一个非零常量替换」（6.8.5.3 节第 2 段）。我们当然可以在条件跳转中直接使用一个非零常量：

```text
JumpIfZero(Const(1), break_label)
```

但这条指令毫无作用；Const(1) 永远不会等于零，所以我们永远也不会跳转。因此，我们干脆完全省略 JumpIfZero 指令，因为这是产生相同行为的更高效方式。

最后，我们需要处理第三个子句 <post>。如果它存在，我们就把它转换为 TACKY；如果它不存在，我们就不发射任何指令。

## 附加挑战：switch 语句

你可以选择在本章实现 switch、case 和 default 语句。为了支持这些语句，你需要对语义分析阶段做大幅修改。首先，你需要修改循环标注遍，因为 break 语句既可以跳出循环，也可以跳出 switch 语句。但是，你不能在 switch 语句内部使用 continue 语句，所以这一遍需要区别对待 continue 语句和 break 语句。

你还需要额外的分析——很可能要放在单独的一个编译器遍中——来收集每个 switch 语句内部出现的各个 case。要生成 switch 语句的 TACKY，你需要该语句中所有 case 的列表。然而，这些信息并不能直接从 AST 中得到。switch 语句中的 case 可能嵌套在好几层之下，也可能 switch 语句体中根本不包含任何 case。你需要把这些信息以更便于使用的形式附加到 AST 上。

使用 --switch 标志可以启用 switch 语句的测试：

```bash

```

# 第 14 章　指针

*Chapter 14: Pointers*

到目前为止，你实现的只有算术类型（arithmetic type）。这些类型有很多共同之处：它们都支持相同的基本数学运算，而且你总能从一种类型隐式转换到另一种类型。在第 II 部分的余下章节中，我们将添加几种非算术类型，比如指针、数组和结构。这些类型与算术类型之间、以及它们彼此之间都差别很大。它们不支持普通的算术运算；相反，每种类型都支持自己独有的一组操作。

本章中，你将实现表示内存地址的指针类型（pointer type）。你还将添加两个操作指针的新运算符：取地址运算符（address operator）`&` 和解引用运算符（dereference operator）`*`。你将学习如何解析复杂的类型说明符，以及如何检测几种新的类型错误。在 TACKY 和汇编生成阶段，你将添加一些新构造来读取和写入内存中的位置。在后续章节添加更多非算术类型时，你还会继续在这些改动的基础上构建。

首先，我们来讨论几个贯穿本章的关键概念：对象、值和左值转换。

## 对象与值

对象和值在前面的章节中已经出现过，但我从未精确定义过这两个术语，也没有解释过它们之间的区别。你可以把值（value）看作一串带有类型的位。例如，位序列

```text
11111111111111111111111111111111
```

配上 int 类型后的值就是 -1。到目前为止，我们遇到过的只有整数值和浮点值。

对象（object）是内存中包含一个值的一个位置。到目前为止，我们见过的对象只有变量。从程序员的角度看，每个对象都有一个内存地址——在其整个生命周期中固定不变——以及一个值——你可以通过赋值表达式来更新它。（在实践中，某些对象可能存储在寄存器而非内存中，而且并非每个对象的值都能更新，但这些例外我们现在可以先忽略。）

在第 5 章中，我把左值（lvalue）描述为可以出现在赋值表达式左侧的表达式。现在我们可以采用 C 标准 6.3.2.1 节第 1 段中更精确的定义：“左值是一个……可能指代（designate）一个对象的表达式。”（注意，尽管名字里带“值”，左值并不是值；它是表达式。）求值一个非左值表达式会产出一个值。而根据标准 5.1.2.3 节第 2 段，求值一个左值会“确[定]被指代对象的同一性”。如果一个表达式指代了一个对象，你就可以对它赋值；否则不能。

当你在像 `x + 1` 这样的表达式中使用一个对象时，你实际上使用的是它当前的值。但当你给一个对象赋值时，你并不关心它当前的值——它马上就要被覆盖了；你关心的是它的位置——也就是你要写入的地方。换句话说，如果 x 是一个 int 类型的变量，你有时把它当作一个 int 类型的值，有时又把它当作一个可以存放 int 值的容器。C 标准把第一种情况——在表达式中使用对象的值——称为左值转换（lvalue conversion）。说它是“转换”，是因为你把一个指代对象的左值转换成了一个普通的值。如果左值作为赋值表达式的左操作数，或者作为 `&` 运算符的操作数出现，它不会经历左值转换；如果它出现在表达式中的其他任何位置，就会经历左值转换。例如，在表达式 `x = 3` 和 `y = &x` 中，x 是左值；而在表达式 `foo(x)`、`x == y` 和 `a = x` 中，x 不是左值。在后面的章节中，我们还会遇到其他不做左值转换的表达式。

有了这套术语，我们谈论指针时就不会陷入一团乱麻。现在我们可以精确地讨论指针支持哪些操作了。

## 指针上的操作

本节中，我会介绍取地址运算符 `&`——它获取指向一个对象的指针——和解引用运算符 `*`——你通过它经由指针访问一个对象。我还会讨论指针的强制转换和比较，以及一个涉及 `&` 运算符的特殊情形。我暂不讨论指针的加法和减法；我们会在下一章实现它们。

### 取地址与解引用操作

要看 `&` 和 `*` 操作如何工作，让我们走一遍清单 14-1 中的程序。我们会特别留意这个程序中哪些表达式指代对象、哪些表达式产生值。

```c
int main(void) {
    int x = 0;
    int *ptr = &x;
    *ptr = 4;
    return *ptr;
}
```

*清单 14-1：一个使用 `&` 和 `*` 操作的简单程序*

我们首先声明变量 x。由于 x 是一个对象，它有一个地址，尽管每次运行程序时这个地址并不相同。假设在某一次运行清单 14-1 的过程中，x 落在了内存地址 0x7ffeee67b938 上。它还有一个值 0。由于 x 的类型是 int，我们也会把它的值解释为 int。

接下来，我们声明变量 ptr，它也是一个对象。ptr 的类型是 int *，即“指向 int 的指针”，它表示某个 int 类型对象的地址。和 x 一样，ptr 也有地址；假设是 0x7ffeee67b940。它还有一个值：表达式 `&x` 的结果。`&` 运算符取其操作数的地址，这意味着它的操作数必须指代一个有地址的对象。换句话说，操作数必须是左值。然而，`&` 运算符的结果不是对象；它是一个指针类型的值。

在表达式 `&x` 中，操作数是左值 x。求值 `&x` 得到值 0x7ffeee67b938，也就是 x 的地址。我们把这个值赋给变量 ptr，就像我们可以把任何值赋给类型兼容的变量一样。为了帮助大家理清思路，图 14-1 展示了程序运行到这个时刻栈中的内容。

```text
0x7ffeee67b940:  ptr = 0x7ffeee67b938 ──► 0x7ffeee67b938:  x = 0
```

*图 14-1：清单 14-1 中声明的各对象的地址与初始值*

如图所示，0x7ffeee67b938 既是 x 的地址，又是 ptr 的值。我之前说过，值是一串带有类型的位；值 0x7ffeee67b938 的类型是 int *，因为它是某个 int 类型对象的地址。

在清单 14-1 的下一行，我们有赋值表达式 `*ptr = 4`，它由几个子表达式组成。右边是常量 4；左边是变量 ptr，它本身又是解引用表达式 `*ptr` 的一部分。常量没什么特别有趣的，但另外两个子表达式很有意思。其中最内层的表达式 ptr 指代一个 int * 类型的对象。我们没有对它赋值，也没有取它的地址；我们只是读取它的值。因此，我们对它隐式地做左值转换，得到一个 int * 类型的值 0x7ffeee67b938。我们在解引用表达式 `*ptr` 中使用这个值。解引用表达式是一个左值，所以它的结果是一个对象。在这里，这个对象就是位于地址 0x7ffeee67b938 处的对象，因为那正是被解引用的值。因为我们是在给对象 `*ptr` 赋值，而不是使用它的值，所以它不经历左值转换。图 14-2 展示了这条语句执行之后栈中的内容。

```text
0x7ffeee67b940:  ptr = 0x7ffeee67b938 ──► 0x7ffeee67b938:  x = 4
```

*图 14-2：通过解引用指针赋值之后栈中的内容*

在最后的 return 语句中，我们又解引用了一次 ptr。同样，`*ptr` 的结果是位于地址 0x7ffeee67b938 处的对象。不过这一次，我们没有给这个对象赋值，也没有对它应用 `&` 运算符。因此，我们执行左值转换，得到该对象当前的值 4。

现在你已经理解了 `*` 和 `&` 如何作用于对象和值，我们来谈谈与指针类型之间的转换。

### 空指针与类型转换

值为 0 的整型常量表达式称为空指针常量（null pointer constant），它可以隐式转换为任何指针类型。这个转换的结果是一个空指针（null pointer）：

```c
int *null = 0;
```

由于空指针不是有效的内存地址，解引用它的结果是未定义的。在实践中，解引用空指针很可能使你的程序崩溃。C 标准允许像 `(long) 0` 和 `10 - 10` 这样的常量表达式作为空指针常量，但我们只支持像 0 和 0ul 这样的常量字面量。（这与我们在第 10 章对静态初始化器施加的限制相同。）

除空指针常量之外，在整数和指针之间做隐式转换是非法的。考虑下面这段代码：

```c
int x = 0;
int *ptr = x;
```

因为 x 的类型是 int，把它赋给 int * 类型的 ptr 是非法的。出于同样的原因，把非零常量赋给指针也是非法的：

```c
int *ptr1 = 3;
int *ptr2 = 0x7ffeee67b938;
```

这两行对 ptr1 和 ptr2 的声明都是非法的，因为 3 和 0x7ffeee67b938 是整数，不是指针。注意，一个表达式的类型与它的值是否是有效的内存地址毫无关系。即使 0x7ffeee67b938 恰好是一个有效的地址，常量表达式 0x7ffeee67b938 仍然是一个 long，而不是指针。

把一种指针类型隐式转换为另一种指针类型同样是非法的（与 void * 之间的双向转换是例外，void 我会在第 17 章介绍）。例如，你不能把 double * 隐式转换为 long *：

```c
double *d = 0;
long *l = d;
```

GCC 会对前面三段代码片段中的隐式转换发出警告，但仍然会编译它们。我们将采取更严格的立场，把这些隐式转换当作错误。

另一方面，指针类型之间以及指针类型与整数类型之间的显式强制转换（cast）是合法的。清单 14-2 展示了一个从 double * 到 unsigned long * 的显式强制转换的例子。

```c
double negative_zero = -0.0;
double *d = &negative_zero;
❶ unsigned long *l = (unsigned long *) d;
```

*清单 14-2：一次显式的指针类型转换*

经过显式强制转换和赋值 ❶ 之后，d 和 l 包含同一个内存地址，只是被解释为两种不同的指针类型。

一个重要的警示：在这次转换之后解引用 l 会导致未定义行为。除少数例外，如果我们以某种类型（称为它的有效类型，effective type）声明一个对象，然后用一个不同类型的表达式去访问它，结果就是未定义的。换句话说，从一种指针类型强制转换到另一种指针类型总是合法的，但使用那个转换表达式的结果可能并不合法。在清单 14-2 中，negative_zero 的有效类型是 double，所以我们不能通过类型为 unsigned long 的表达式 `*l` 访问它。关于可以用哪些类型的表达式访问一个对象的完整规则——非官方地称为严格别名规则（strict aliasing rules）——写在 C 标准 6.5 节第 6–7 段中。幸运的是，由于我们既不需要检测未定义行为，也不需要优雅地处理它，我们可以忽略这些规则；我们的实现会很乐意编译违反这些规则的程序。

最后，你可以在指针类型和整数类型之间显式强制转换。当你把一个空指针常量强制转换为指针类型时，结果是一个空指针。当你把任何其他整数强制转换为指针类型，或者把任何指针强制转换为整数类型时，结果是实现定义（implementation-defined）的。在 x64 系统上，内存地址是无符号的 64 位整数，比如 0x7ffeee67b938。因此，如果你把一个 unsigned long 转换为指针（或反过来），它的值不会改变。把任何其他整数类型与指针类型相互强制转换，效果等同于与 unsigned long 相互转换。例如，如果你把值为 -1 的有符号 int 或 long 强制转换为指针类型，会得到最大的可表示内存地址 0xffffffffffffffff。这个地址不太可能持有有效的对象，所以解引用它很可能导致未定义行为。

把指针类型强制转换为 double，或者把 double 强制转换为指针类型，是非法的。

### 指针比较

你可以用 `==` 和 `!=` 运算符比较相同类型的指针。两个非空指针在指向同一个对象（或者，等我们实现数组之后，指向刚好越过同一个数组末尾的位置）时比较相等；否则比较不相等。指向有效对象的指针与空指针比较永远不相等，两个空指针比较永远相等。你还可以在任何“把表达式与零比较”的构造中使用指针，包括逻辑 `!`、`&&` 和 `||` 表达式，条件表达式中的条件，以及 if 语句或循环的控制条件。在所有这些情形中，空指针算作零，任何非空指针都算作非零。

你也可以用其他关系运算符（比如 `>`）比较指针，但我们暂时不支持。这类指针比较在操作指向数组元素的指针时最有用，所以我们会在下一章添加数组时实现它。

### 对解引用指针的 & 操作

我们之前看到，`&` 运算符的操作数必须是左值。由于解引用得到的指针是左值，你可以用这个运算符取它的地址，就像清单 14-3 中那样。

```c
int *ptr = &var;
int *ptr2 = &*ptr;
```

*清单 14-3：取解引用指针的地址*

表达式 `&*ptr` 是合法的，但不是很有用。内层表达式指代存储在某个地址处的对象，外层表达式取该对象的地址。你最终得到的正好是 ptr 的值，也就是你一开始解引用的那个地址。

实际上，C 标准把 `&*<exp>` 当作特例处理：6.5.3.2 节第 3 段指出，“[* 运算符]和 & 运算符都不会被求值，结果如同两者都被省略，只是运算符的约束条件仍然适用，且结果不是左值。”换句话说，`&*<exp>` 的结果总是 `<exp>` 的值。通常，像清单 14-3 中那样，我们是否求值 `*` 和 `&` 运算符无关紧要；无论哪种方式，我们最终都会得到 `<exp>`。唯一的例外是 `<exp>` 不是有效的内存地址时，比如清单 14-4。

```c
int *null_ptr = 0;
int *ptr2 = &*null_ptr;
```

*清单 14-4：取解引用空指针的地址*

解引用 null_ptr 通常会导致运行时错误。然而，由于清单 14-4 中的 `&` 和 `*` 表达式不会被求值，这段代码等价于：

```c
int *null_ptr = 0;
int *ptr2 = null_ptr;
```

因此，清单 14-4 可以无错运行；它把 null_ptr 和 ptr2 都初始化为空指针。

## 解析器

接下来，我们要把指针类型和两个新的指针运算符加入 AST。指针类型由它所指向的对象的类型递归构造而成；int *、double * 和 unsigned long * 都是合法的类型。你还可以声明指向指针的指针，所以 int **、long *** 等等也是合法的类型。因此，AST 递归地定义指针类型：

```text
type = Int | Long | UInt | ULong | Double
     | FunType(type* params, type ret)
     | Pointer(type referenced)
```

在 C 中，由较简单的类型构造出来的类型称为派生类型（derived type）。指针类型和函数类型都是派生类型。我们在后面章节中要实现的数组类型和结构类型也是派生类型。指针所指向的类型称为它的被引用类型（referenced type）。例如，int * 的被引用类型是 int。

我们将扩展 exp AST 节点来表示解引用和取地址运算符：

```text
exp = --snip--
    | Dereference(exp)
    | AddrOf(exp)
```

从语法上讲，这两个都是一元运算符，所以如果你愿意，也可以扩展 unary_operator 而不是 exp。但我认为把它们做成两种独立的表达式更容易，因为在类型检查和 TACKY 生成期间，我们对它们的处理方式与其他一元运算符大不相同。清单 14-5 展示了更新后的 AST，本章新增的内容以粗体标出。

```text
program = Program(declaration*)
declaration = FunDecl(function_declaration) | VarDecl(variable_declaration)
variable_declaration = (identifier name, exp? init, type var_type, storage_class?)
function_declaration = (identifier name, identifier* params, block? body,
                        type fun_type, storage_class?)
type = Int | Long | UInt | ULong | Double
     | FunType(type* params, type ret)
     | Pointer(type referenced)
storage_class = Static | Extern
block_item = S(statement) | D(declaration)
block = Block(block_item*)
for_init = InitDecl(variable_declaration) | InitExp(exp?)
statement = Return(exp)
          | Expression(exp)
          | If(exp condition, statement then, statement? else)
          | Compound(block)
          | Break
          | Continue
          | While(exp condition, statement body)
          | DoWhile(statement body, exp condition)
          | For(for_init init, exp? condition, exp? post, statement body)
          | Null
exp = Constant(const)
    | Var(identifier)
    | Cast(type target_type, exp)
    | Unary(unary_operator, exp)
    | Binary(binary_operator, exp, exp)
    | Assignment(exp, exp)
    | Conditional(exp condition, exp, exp)
    | FunctionCall(identifier, exp* args)
    | Dereference(exp)
    | AddrOf(exp)
unary_operator = Complement | Negate | Not
binary_operator = Add | Subtract | Multiply | Divide | Remainder | And | Or
                | Equal | NotEqual | LessThan | LessOrEqual
                | GreaterThan | GreaterOrEqual
const = ConstInt(int) | ConstLong(int)
      | ConstUInt(int) | ConstULong(int)
      | ConstDouble(double)
```

*清单 14-5：加入指针类型与解引用、取地址运算符的抽象语法树*

接下来，我们要更新文法并弄清楚如何解析它。`*` 和 `&` 运算符可以像其他任何一元运算符一样解析，所以我们把它们加入 `<unop>` 文法规则：

```text
<unop> ::= "-" | "~" | "!" | "*" | "&"
```

解析声明和强制转换表达式中的指针类型则更具挑战性。我们需要一种可以扩展到处理一般派生类型（而不仅仅是指针）的方法；否则，下一章处理数组时我们将不得不把它彻底重写。我们先更新解析器以支持声明中的派生类型，然后再处理强制转换表达式中的派生类型。

### 解析声明

一个函数或变量声明由三部分组成：一串说明符、一个声明器（declarator），以及可选的初始化器或函数体。你已经知道初始化器和函数体长什么样，这里就不再赘述。说明符在前面的章节中也很熟悉了：它包括存储类说明符（比如 static，决定标识符的存储类和链接性）和类型说明符（比如 int，决定我要称作基本类型（basic type）的东西）。基本类型要么就是标识符的类型，要么是其类型派生的起点。（这个特定术语并没有出现在 C 标准中，但在其他讨论 C 声明的材料中有时会出现。）声明器是除此之外的一切：它指出被声明的标识符，以及我们要对基本类型应用的类型派生序列。例如，var、*var、foo(int a) 和 foo[3] 都是声明器。

最简单的声明器就是一个标识符：

```c
int var;
```

这里，基本类型是 int，声明器是 var，所以它声明一个名为 var 的 int 类型变量。这个声明不包含任何类型派生。

要派生新类型，我们把像 var 这样的声明器嵌套进另一个声明器里：

```c
int *(var);
```

这里我们有一个指针声明器 *(var)，其中包含嵌套的声明器 var。指针声明器取某个类型 t，派生出“指向 t 的指针”类型，所以这个声明把 var 声明为“指向 int 的指针”类型。注意，C 的语法允许我们用括号括住任何声明器。我把 var 括在括号里是为了让这里的嵌套关系一目了然，但省略括号后这个声明的含义相同：

```c
int *var;
```

我们用多层嵌套的声明器来指定多个类型派生；这些派生从外到内应用，决定最终的类型。最内层的声明器总是一个普通的标识符。下面是三个嵌套声明器的例子：

```c
int *(*(var));
```

完整的声明器是 *(*(var))，其中包含 *(var)，后者又包含 var。与上一个例子一样，这个声明器中的括号不起作用；我只是为了清晰才加上它们。

我们来走一遍这里的类型派生。从外到内，我们从基本类型 int 开始。接着我们看到一个指针声明器，于是派生出“指向 int 的指针”类型。然后又看到一个指针声明器，于是派生出“指向指向 int 的指针的指针”类型。最后我们遇到标识符，它完成整个声明，但不添加任何类型信息。我们最终得到变量 var，它的类型是“指向指向 int 的指针的指针”。

另外两种声明器是函数声明器（我们已经支持）和数组声明器（下一章添加）。函数声明器取某个类型 t，派生出“返回 t 的函数”类型。我们来分解一个函数声明：

```c
int foo(void);
```

这里的完整声明器是 foo(void)，它包含嵌套的声明器 foo。把每个声明器都用括号括起来，可以得到下面这个等价的声明：

```c
int ((foo)(void));
```

我们从基本类型 int 开始。外层声明器告诉我们要派生“返回 int 的函数”类型，内层声明器表明我们声明的是标识符 foo。当然，函数声明器还会声明函数的形参。每个形参和声明非常相似，都包含一个基本类型和一个声明器：

```c
int foo(int a, int *b);
```

我们早已知道，形如 (void) 的形参列表是一个特例：它声明该函数没有形参。

最后，数组声明器从类型 t 出发，派生出“n 个 t 类型元素的数组”类型。例如，下面的代码包含声明器 arr[3]，其中嵌套着声明器 arr：

```c
int arr[3];
```

它声明 arr 是一个由三个 int 元素组成的数组。

更复杂的声明可以混合嵌套指针、数组和函数声明器。用后缀表达式表示的函数声明器和数组声明器，优先级高于指针声明器，所以

```c
int *arr[3];
```

等价于：

```c
int *(arr[3]);
```

要解释这个声明，我们从 int 出发，应用外层的指针声明器得到“指向 int 的指针”，再应用内层的数组声明器得到“由三个指向 int 的指针组成的数组”，最后是最内层的声明器 arr。如果想声明一个指向数组的指针，就要用括号覆盖这个优先级：

```c
int (*arr)[3];
```

同样地，下面这个声明声明的是一个指向单形参函数的指针：

```c
int (*fptr)(int a);
```

函数指针在 C 中是合法的，但我们在本书中不会实现它。你还可以嵌套声明器来指定彻头彻尾非法的类型。例如，int foo(void)(void); 声明一个返回函数的函数，而那个函数又返回 int。这个声明在语法上是良构的，但在语义上无效；函数不能返回另一个函数。

现在你已经理解了声明器的基本语法，可以着手为它编写文法规则了。关于声明器的完整描述，见 C 标准的 6.7.6 节。我还推荐 Steve Friedl 的“Reading C Type Declarations”，它以比标准更容易理解的方式描述了声明器的语法（http://unixwiz.net/techtips/reading-cdecl.html）。

由于声明器有多个优先级层次，我们需要多条文法规则来定义它们的语法。在最高优先级，一个 `<simple-declarator>` 是单个标识符或带括号的声明器：

```text
<simple-declarator> ::= <identifier> | "(" <declarator> ")"
```

在下一个优先级，是 C 文法所称的直接声明器（direct declarator），包括函数声明器和数组声明器。本章我们只支持函数声明器：

```text
<direct-declarator> ::= <simple-declarator> [<param-list>]
<param-list> ::= "(" "void" ")" | "(" <param> {"," <param>} ")"
<param> ::= {<type-specifier>}+ <declarator>
```

在 `<direct-declarator>` 的定义中，直接声明器既可以是一个简单声明器，也可以是一个函数声明器（由形参列表的存在来表明）。注意，与前几章相比，我们对 `<param-list>` 做了一点修改，把这个符号重构成包含形参列表两侧的括号，并把单个形参的定义移进单独的 `<param>` 符号。最重要的是，`<param>` 的定义现在包含一个声明器，而不是一个普通的标识符。这让我们能够解析指针类型的形参（最终也能解析数组类型的形参）。最后，我们定义包含指针声明器的顶层 `<declarator>`：

```text
<declarator> ::= "*" <declarator> | <direct-declarator>
```

不幸的是，这个文法与我们的 AST 定义并不真正对应。一个小问题是，它允许我们指定不支持的类型，包括函数指针、返回函数的函数，以及接受其他函数作为实参的函数。更严重的问题是，在我们的文法中，类型派生从外到内应用，而在 AST 定义中，它们从内到外应用。让我们重新看一个前面见过的声明：

```c
int (*arr)[3];
```

我们想解析这个声明并构造“指向由三个 int 元素组成的数组的指针”类型。如果我们尝试用递归下降解析来构造这个类型，会发生什么？首先，我们会遇到基本类型 int。然后，我们会看到一个左括号，它标志着一个直接声明器的开始。在那个直接声明器内部，我们会找到一个指针声明器——然后就卡住了。我们应当派生一个指针类型，但指向什么的指针？到目前为止我们看到的基本类型是 int，但“指向 int 的指针”是不对的。由于类型派生从外到内应用，我们应当先派生出数组类型。但我们做不到，因为解析器必须先消耗掉带括号的内层声明器，才能到达指定数组类型的 [3]。

我们在这里卡住，是因为能识别文法符号的顺序与应用类型派生的顺序不匹配。解析一个声明时，我们无法边解析边派生它的类型。因此，我们先把每个声明器解析成一个更贴近文法的一次性表示，比如清单 14-6 中的那个。

```text
declarator = Ident(identifier)
           | PointerDeclarator(declarator)
           | FunDeclarator(param_info* params, declarator)
param_info = Param(type, declarator)
```

*清单 14-6：表示声明器的语法*

我们可以用标准的递归下降解析，按照刚才引入的文法规则，产出一个 declarator 构造。

下一步是遍历这个声明器，派生出我们将用来构造 AST 节点的全部信息：声明的类型、它的标识符，以及各形参的标识符。在每一层，我们应用相应的类型派生，然后递归处理内层声明器。清单 14-7 给出了这一步的伪代码。

```text
process_declarator(declarator, base_type):
    match declarator with
    | Ident(name) -> return (name, base_type, []) ❶
    | PointerDeclarator(d) -> ❷
        derived_type = Pointer(base_type)
        return process_declarator(d, derived_type)
    | FunDeclarator(params, d) -> ❸
        match d with
        | Ident(name) -> ❹
            param_names = []
            param_types = []
            for Param(p_base_type, p_declarator) in params: ❺
                param_name, param_t, _ = process_declarator(p_declarator, p_base_type)
                if param_t is a function type:
                    fail("Function pointers in parameters aren't supported")
                param_names.append(param_name)
                param_types.append(param_t)

            derived_type = FunType(param_types, base_type)
            return (name, derived_type, param_names)
        | _ -> fail("Can't apply additional type derivations to a function type")
```

*清单 14-7：从声明器派生类型与标识符信息*

process_declarator 函数接受两个参数。第一个是声明器本身。第二个 base_type 是到目前为止我们已经派生出的类型。最初，它是声明开头那串说明符所指示的基本类型。例如，如果我们处理声明 double **fun(int x)，我们会从基本类型 double 出发。process_declarator 的结果将是一个三元组：声明的标识符、它派生出的类型，以及各形参的名字。如果声明的是一个变量，或者声明的是一个没有形参的函数，形参名列表将为空。利用这三个值，我们就能构造出声明 AST 节点。

我们来看看如何从 declarator 构造中提取这些值。最简单的情形是声明器就是一个标识符 ❶。我们不需要应用任何类型派生，也不需要引入任何形参，所以直接返回标识符、未改动的 base_type 以及空的形参名列表。例如，处理声明 int x; 时，我们会立即命中这种情形并返回 ("x", Int, [])。

第二种情形处理指针声明器 ❷。此时，我们从 base_type 派生出一个指针类型。然后用刚刚派生的类型和仍待处理的内层声明器，递归调用 process_declarator。

最后一种情形处理函数声明器 ❸。这种情形稍有不同，因为内层声明器必须是一个普通的标识符。如果它是另一个函数声明器，我们会得到一个返回函数的函数，这不合法。如果它是一个指针声明器，我们会得到一个函数指针，而函数指针我们不实现。因此，我们验证内层声明器是一个普通标识符，而不是递归地去解析它 ❹。

假设内层声明器有效，下一步就是确定函数类型和形参名。我们遍历声明器中的各个形参，对每一个递归调用 process_declarator 来得到它的类型和名字 ❺。与此同时，我们验证这些函数形参中没有一个本身是函数。（C 标准实际上允许你用函数类型声明形参，但它要求编译器把它们隐式调整为函数指针类型。由于我们不支持函数指针，我们将拒绝它们。）处理完每个形参之后，我们构造完整的函数类型，并返回与这个声明相关的全部信息。

清单 14-8 展示了如何把所有这些部分组合起来，解析一条完整的声明。

```text
parse_declaration(tokens):
    specifiers = parse_specifier_list(tokens)
    base_type, storage_class = parse_type_and_storage_class(specifiers)
    declarator = parse_declarator(tokens)
    name, decl_type, params = process_declarator(declarator, base_type)
    if decl_type is a function type:
        <construct function_declaration>
    else:
        <construct variable_declaration>
```

*清单 14-8：解析一条完整的声明*

我们首先按通常的方式确定声明的基本类型：从 token 中消耗一串说明符，再把这些说明符转换为类型和存储类。接下来解析声明器，然后调用 process_declarator 确定它的完整类型和名字。最后，我们检查得到的类型，判断这是函数声明还是变量声明，并相应地解析声明的其余部分。

### 解析类型名

指针类型也可以出现在强制转换表达式中：

```c
int *result_of_cast = (int *) exp;
```

但你不能在强制转换表达式中使用声明器，因为声明器必须包含标识符。C 语法用抽象声明器（abstract declarator）解决了这个问题——它是不带标识符的声明器。我们现在先添加抽象指针声明器，下一章再添加抽象数组声明器。（我们不需要抽象函数声明器，因为它只用于指定函数指针。）

抽象声明器可以是一串一个或多个 `*` 词法单元，表示一串指针类型派生：

```c
(int ***) exp;
```

抽象声明器可以像非抽象声明器一样带括号：

```c
(int (*)) exp;
```

外层抽象声明器还可以包含带括号的内层抽象声明器：

```c
(int *(*)) exp;
```

这些括号目前没有什么用处。等下一章添加数组之后，它们会变得更有用。例如，表达式

```c
(int *[3]) exp;
```

把 exp 强制转换为“由三个指向 int 的指针组成的数组”类型，因为抽象数组声明器 [3] 按更高的优先级解析。这个强制转换表达式是非法的，因为你不能把表达式强制转换为数组类型。另一方面，下面这个表达式没有问题：

```c
(int (*)[3]) exp;
```

它把 exp 强制转换为“指向由三个 int 元素组成的数组的指针”类型；带括号的指针声明器优先级更高，所以数组声明器先应用于 int。

我们用两条文法规则定义抽象声明器：

```text
<abstract-declarator> ::= "*" [<abstract-declarator>]
                        | <direct-abstract-declarator>
<direct-abstract-declarator> ::= "(" <abstract-declarator> ")"
```

`<abstract-declarator>` 与普通的 `<declarator>` 一样，由指针声明器或直接声明器构成。两者的关键区别在于，在抽象指针声明器中，内层声明器是可选的。换句话说，单独一个 `*` 是合法的抽象声明器，但不是合法的普通声明器。

`<direct-abstract-declarator>` 是用括号括起来的 `<abstract-declarator>`。下一章，这个符号还将涵盖抽象数组声明器。与处理普通声明器一样，我们把抽象声明器解析成一个一次性 abstract_declarator 结构。清单 14-9 定义了这个结构。

```text
abstract_declarator = AbstractPointer(abstract_declarator)
                    | AbstractBase
```

*清单 14-9：表示抽象声明器的语法*

AbstractBase 表示基本情形，即一个 `*` 词法单元后面没有跟着内层声明器。例如，我们会把抽象声明器 *(*) 解析为 AbstractPointer(AbstractPointer(AbstractBase))。目前，abstract_declarator 只是告诉我们找到了多少层指针间接（本例中是两层）。用这么一套精细的结构来传达一个数字，多少有些小题大做，但它为下一章的数组声明器打下了基础。

强制转换表达式中的类型名，是一串类型说明符后跟一个可选的抽象声明器，整体用括号括起来：

```text
<factor> ::= --snip--
           | "(" {<type-specifier>}+ [<abstract-declarator>] ")" <factor>
           | --snip--
```

要处理强制转换表达式，你需要一个 process_abstract_declarator 函数，类似于清单 14-7 中的 process_declarator，把一个基本类型和一个 abstract_declarator 转换为派生类型。这个函数会比 process_declarator 简单；它不处理函数声明器，而且只返回一个类型，不返回标识符或形参列表。

### 综合起来

我们已经讲完了要对解析器做的全部修改。清单 14-10 展示了完整的文法，本章的改动以粗体标出。

```text
<program> ::= {<declaration>}
<declaration> ::= <variable-declaration> | <function-declaration>
<variable-declaration> ::= {<specifier>}+ <declarator> ["=" <exp>] ";"
<function-declaration> ::= {<specifier>}+ <declarator> (<block> | ";")
<declarator> ::= "*" <declarator> | <direct-declarator>
<direct-declarator> ::= <simple-declarator> [<param-list>]
<param-list> ::= "(" "void" ")" | "(" <param> {"," <param>} ")"
<param> ::= {<type-specifier>}+ <declarator>
<simple-declarator> ::= <identifier> | "(" <declarator> ")"
<type-specifier> ::= "int" | "long" | "unsigned" | "signed" | "double"
<specifier> ::= <type-specifier> | "static" | "extern"
<block> ::= "{" {<block-item>} "}"
<block-item> ::= <statement> | <declaration>
<for-init> ::= <variable-declaration> | [<exp>] ";"
<statement> ::= "return" <exp> ";"
              | <exp> ";"
              | "if" "(" <exp> ")" <statement> ["else" <statement>]
              | <block>
              | "break" ";"
              | "continue" ";"
              | "while" "(" <exp> ")" <statement>
              | "do" <statement> "while" "(" <exp> ")" ";"
              | "for" "(" <for-init> [<exp>] ";" [<exp>] ")" <statement>
              | ";"
<exp> ::= <factor> | <exp> <binop> <exp> | <exp> "?" <exp> ":" <exp>
<factor> ::= <const> | <identifier>
           | "(" {<type-specifier>}+ [<abstract-declarator>] ")" <factor>
           | <unop> <factor> | "(" <exp> ")"
           | <identifier> "(" [<argument-list>] ")"
<argument-list> ::= <exp> {"," <exp>}
<abstract-declarator> ::= "*" [<abstract-declarator>]
                        | <direct-abstract-declarator>
<direct-abstract-declarator> ::= "(" <abstract-declarator> ")"
<unop> ::= "-" | "~" | "!" | "*" | "&"
<binop> ::= "-" | "+" | "*" | "/" | "%" | "&&" | "||"
          | "==" | "!=" | "<" | "<=" | ">" | ">=" | "="
<const> ::= <int> | <long> | <uint> | <ulong> | <double>
<identifier> ::= ? An identifier token ?
<int> ::= ? An int token ?
<long> ::= ? An int or long token ?
<uint> ::= ? An unsigned int token ?
<ulong> ::= ? An unsigned int or unsigned long token ?
<double> ::= ? A floating-point constant token ?
```

*清单 14-10：加入指针类型与解引用、取地址运算符的文法*

我们对文法做了三处大的修改。第一，在函数、变量和形参声明中，用 `<declarator>` 符号取代了简单的标识符。第二，在强制转换表达式中用对应的 `<abstract-declarator>` 符号指定指针类型。第三，添加了新的一元运算符 `&` 和 `*`。

## 语义分析

接下来是语义分析！我们将扩展类型检查器，验证涉及指针的表达式，并推断这些表达式的类型。标识符解析遍也会有一点变化；我们会把其中一项验证移入类型检查器。

我们需要检测三种类型错误：

1. 对某个类型应用它不支持的运算符。例如，你不能对指针做乘法或除法，也不能解引用算术值。
2. 对两个不兼容类型的值进行操作。这包括试图把指针与 double 相比较之类的错误。之所以会遇到这类错误，是因为 C 一般不允许与指针类型之间的隐式转换，而对算术类型则允许。
3. 在需要左值的地方没有使用左值。我们已经要求赋值表达式的左侧是左值；现在我们还将要求 AddrOf 表达式的操作数也是左值。我们还会扩展左值的定义，把解引用得到的指针与变量一并纳入。

第三类错误是目前在标识符解析期间处理的。现在就把这项验证从标识符解析遍中移除；稍后你会把它加进类型检查器。（顺手确保标识符解析遍会遍历新的 Dereference 和 AddrOf 表达式。）接下来，我们更新表达式类型检查的逻辑。

### 类型检查指针表达式

我们几乎要调整我们所支持的每一种表达式的类型检查方式。先从新的 Dereference 和 AddrOf 表达式开始，然后再更新现有构造的类型检查逻辑。

#### Dereference 与 AddrOf 表达式

Dereference 表达式的操作数必须是指针类型。它产生一个结果，类型为其操作数的被引用类型（也就是它指向的类型）。清单 14-11 演示了如何对 Dereference 表达式做类型检查，并用正确的结果类型标注它。

```text
typecheck_exp(e, symbols):
    match e with
    | --snip--
    | Dereference(inner) ->
        typed_inner = typecheck_exp(inner, symbols)
        match get_type(typed_inner) with
        | Pointer(referenced_t) ->
            deref_exp = Dereference(typed_inner)
            return set_type(deref_exp, referenced_t)
        | _ -> fail("Cannot dereference non-pointer")
```

*清单 14-11：类型检查一个 Dereference 表达式*

我们照例先对表达式的操作数做类型检查。然后查询操作数的类型。如果它是指向某个类型 referenced_t 的指针，我们就把 referenced_t 设为整个表达式的结果类型。否则，抛出错误。

要对 AddrOf 表达式做类型检查，我们首先检查它的操作数是左值（也就是 Var 或 Dereference 表达式）。然后记录它的结果类型，即指向其操作数类型的指针。清单 14-12 演示了如何对 AddrOf 做类型检查。

```text
    | AddrOf(inner) ->
        if inner is an lvalue:
            typed_inner = typecheck_exp(inner, symbols)
            referenced_t = get_type(typed_inner)
            addr_exp = AddrOf(typed_inner)
            return set_type(addr_exp, Pointer(referenced_t))
        else:
            fail("Can't take the address of a non-lvalue!")
```

*清单 14-12：类型检查一个 AddrOf 表达式*

接下来，我们用 Equal 和 NotEqual 对指针比较做类型检查。（用 GreaterThan、LessThan 和其他关系运算符进行的指针比较，留到第 15 章处理。）我们还会处理条件表达式，它遵循类似的类型规则。

#### 比较与条件表达式

正如你在前几章学到的，比较运算的两个操作数必须类型相同，或者至少能隐式转换为相同类型。然而，我们无法对指针类型做隐式转换——无论转入还是转出。因此，如果 Equal 或 NotEqual 操作的任一操作数是指针，我们就要求两个操作数类型相同。目前，空指针常量是这条规则的唯一例外；它们是我们唯一能隐式转换为指针类型的表达式。（等我们实现 void 之后，还会允许 void * 与其他指针类型之间的隐式转换。）

例如，下面这段代码把一个指针与空指针常量做比较：

```c
double *d = get_pointer();
return d == 0;
```

在这个例子中对 d == 0 做类型检查时，我们会隐式地把 0 强制转换为 double * 类型的空指针。清单 14-13 定义了一个识别空指针常量的辅助函数。

```text
is_null_pointer_constant(e):
    match e with
    | Constant(c) ->
        match c with
        | ConstInt(0) -> return True
        | ConstUInt(0) -> return True
        | ConstLong(0) -> return True
        | ConstULong(0) -> return True
        | _ -> return False
    | _ -> return False
```

*清单 14-13：检查一个表达式是否是空指针常量*

这个函数概括了一个表达式要算作空指针常量的三个条件：它必须是常量字面量，必须是整数，而且值必须是 0。（记住，我们对空指针常量的定义比 C 标准更窄；标准除常量字面量外还允许更复杂的常量表达式。）

清单 14-14 定义了另一个辅助函数，判断两个（至少一个结果为指针的）表达式是否类型兼容。

```text
get_common_pointer_type(e1, e2):
    e1_t = get_type(e1)
    e2_t = get_type(e2)
    if e1_t == e2_t:
        return e1_t
    else if is_null_pointer_constant(e1):
        return e2_t
    else if is_null_pointer_constant(e2):
        return e1_t
    else:
        fail("Expressions have incompatible types")
```

*清单 14-14：求两个表达式的公共类型，其中至少一个具有指针类型*

当一个操作指针的表达式要求它的两个操作数类型相同时，get_common_pointer_type 会确定这个类型应当是什么。如果传给它的两个表达式类型不同，且其中任何一个都不是空指针常量，它们就不兼容，于是我们抛出错误。

定义好 get_common_pointer_type 之后，我们终于可以对 Equal 和 NotEqual 表达式做类型检查了。清单 14-15 演示了如何类型检查一个 Equal 表达式；NotEqual 的处理方式相同。

```text
typecheck_exp(e, symbols):
    match e with
    | --snip--
    | Binary(Equal, e1, e2) ->
        typed_e1 = typecheck_exp(e1, symbols)
        typed_e2 = typecheck_exp(e2, symbols)
        t1 = get_type(typed_e1)
        t2 = get_type(typed_e2)
        if t1 or t2 is a pointer type:
          ❶ common_type = get_common_pointer_type(typed_e1, typed_e2)
        else:
          ❷ common_type = get_common_type(t1, t2)
        converted_e1 = convert_to(typed_e1, common_type)
        converted_e2 = convert_to(typed_e2, common_type)
        equality_exp = Binary(Equal, converted_e1, converted_e2)
        return set_type(equality_exp, Int)
```

*清单 14-15：类型检查一个 Equal 表达式*

这遵循了类型检查比较运算的惯常模式：对两个操作数做类型检查，求它们的公共类型，把它们都转换到该类型，然后把结果的类型设为 Int。与前几章相比，关键的变化在于求公共类型的方式。如果任一操作数是指针，就使用我们刚刚定义的辅助函数 ❶；否则，继续使用 get_common_type ❷。

当我们把两个操作数转换为公共的指针类型时，会看到三种可能的结果之一：

- 两个操作数类型本来就相同，两次 convert_to 调用都不起作用。
- 一个操作数是空指针常量，把它隐式转换为另一个操作数的类型。
- 两个操作数类型不兼容，get_common_pointer_type 抛出错误。

我们用类似的逻辑对条件表达式做类型检查。表达式 `<cond> ? <clause1> : <clause2>` 的第二个和第三个操作数，遵循与 Equal 或 NotEqual 表达式的操作数相同的类型约束。如果其中任何一个是指针，我们就对两个操作数做验证，并用 get_common_pointer_type 求出公共类型，然后把它们转换到该类型。`<cond>` 表达式既可以是指针，也可以是算术值，因为无论哪种情况，我们都可以把它与零比较。

#### 赋值与“如同赋值”的转换

接下来，我们处理赋值表达式。我们首先验证赋值表达式的左侧是左值。然后，把表达式右侧的值转换为左侧对象的类型，转换非法就失败。C 标准所称的“如同赋值”的类型转换（type conversion “as if by assignment”）会在好几个地方出现，而不只是在赋值表达式中，所以我们要再编写一个辅助函数来处理它。清单 14-16 定义了这个辅助函数。

```text
convert_by_assignment(e, target_type):
    if get_type(e) == target_type:
        return e
    if get_type(e) is arithmetic and target_type is arithmetic:
        return convert_to(e, target_type)
    if is_null_pointer_constant(e) and target_type is a pointer type:
        return convert_to(e, target_type)
    else:
        fail("Cannot convert type for assignment")
```

*清单 14-16：把表达式按“如同赋值”转换为目标类型*

这里的规则毫不意外：我们可以把值赋给同类型的对象，可以把任何算术类型隐式转换为任何其他算术类型，还可以把空指针常量隐式转换为任何指针类型。除此之外，都会抛出错误。

我们会用这个辅助函数转换赋值表达式的右侧，此外还有几个地方也会用到。对函数调用做类型检查时，我们用 convert_by_assignment 把每个实参转换为对应形参的类型。我们还用它把变量初始化器转换为正确的类型，并检测类型非法的初始化器，比如下面这个：

```c
int *d = 2.0;
```

最后，我们用 convert_by_assignment 把 return 语句中的值转换为函数的返回类型，并检测返回错误类型的函数，比如清单 14-17。

```c
int *bad_pointer(void) {
    return 2.0;
}
```

*清单 14-17：返回不兼容类型之值的函数*

之后实现 void 时，我们会扩展 get_common_pointer_type 和 convert_by_assignment，使其接受与 void * 之间的隐式转换。

#### 其他表达式

我们还需要处理强制转换表达式、一元运算符，以及除 Equal 和 NotEqual 之外的二元运算符。先从强制转换开始。如前所述，把指针强制转换为 double，或把 double 强制转换为指针，是非法的。如果你的类型检查器遇到这种强制转换，应当抛出错误。除此之外，它可以完全像处理其他任何强制转换表达式一样，处理与指针类型之间的转换。

接下来处理一元运算符。对指针应用 Negate 或 Complement 运算符是非法的，因为对内存地址取负或按位取补不会产生有意义的结果。对指针应用 Not 运算符则没有问题，因为把内存地址与零比较是合理的。

二元运算符以几种不同的方式处理指针。首先是布尔 And 和 Or 运算符。这两个运算符的类型检查逻辑不会改变。与 Not 一样，它们都接受指针。由于它们不把操作数转换为公共类型，它们可以操作指针与算术操作数的任意组合。

另一方面，算术运算符 Multiply、Divide 和 Remainder 不接受指针。把它们中任何一个应用到指针类型的操作数上，都应产生错误。指针的加法和减法是合法的，用 GreaterThan、LessThan、GreaterOrEqual 和 LessOrEqual 进行的指针比较也是合法的，但我们要到下一章才会实现它们。它们不会出现在本章的测试中。目前，你的编译器既可以假设永远不会见到这些表达式，也可以显式地拒绝它们。

### 在符号表中跟踪静态指针初始化器

现在来谈谈静态初始化器。指针类型的静态变量和非静态变量一样，可以初始化为空指针：

```c
static int *ptr = 0;
```

因此，我们需要一种方法，在符号表中把空指针表示为 static_init。与其为空指针定义一个专门的构造，我们直接使用 ULongInit(0) 初始化器，因为指针就是无符号的 64 位整数。

用其他静态变量的地址来初始化指针类型的静态变量也是合法的：

```c
static int a;
static int *a_ptr = &a;
```

但我们的实现不会支持这种静态初始化器；我们已经决定，常量字面量是我们唯一接受的静态初始化器。

## TACKY 生成

本章我们将在 TACKY 中引入三条操作指针的新指令。第一条 GetAddress 对应 AST 中的 AddrOf 运算符：

```text
GetAddress(val src, val dst)
```

这条指令把 src 的地址复制到 dst——src 必须是变量，不能是常量。我们还会添加两条解引用指针的指令：

```text
Load(val src_ptr, val dst)
Store(val src, val dst_ptr)
```

Load 指令以内存地址 src_ptr 作为源操作数。它取出该内存地址处的当前值，并复制到 dst。Store 指令以内存地址 dst_ptr 作为目的操作数，把 src 的值写入该地址。清单 14-18 定义了完整的 TACKY 中间表示（IR），三条新指令以粗体标出。

```text
program = Program(top_level*)
top_level = Function(identifier, bool global, identifier* params, instruction* body)
          | StaticVariable(identifier, bool global, type t, static_init init)
instruction = Return(val)
            | SignExtend(val src, val dst)
            | Truncate(val src, val dst)
            | ZeroExtend(val src, val dst)
            | DoubleToInt(val src, val dst)
            | DoubleToUInt(val src, val dst)
            | IntToDouble(val src, val dst)
            | UIntToDouble(val src, val dst)
            | Unary(unary_operator, val src, val dst)
            | Binary(binary_operator, val src1, val src2, val dst)
            | Copy(val src, val dst)
            | GetAddress(val src, val dst)
            | Load(val src_ptr, val dst)
            | Store(val src, val dst_ptr)
            | Jump(identifier target)
            | JumpIfZero(val condition, identifier target)
            | JumpIfNotZero(val condition, identifier target)
            | Label(identifier)
            | FunCall(identifier fun_name, val* args, val dst)
val = Constant(const) | Var(identifier)
unary_operator = Complement | Negate | Not
binary_operator = Add | Subtract | Multiply | Divide | Remainder | Equal | NotEqual
                | LessThan | LessOrEqual | GreaterThan | GreaterOrEqual
```

*清单 14-18：为 TACKY 添加指针操作*

把 Dereference 和 AddrOf 转换为 TACKY 相当棘手，因为这些转换依赖于上下文。一个 Dereference 表达式可以以三种方式之一使用：对它做左值转换、对它赋值，或者取它的地址。在这三种情形下，我们会生成不同的 TACKY 指令。类似地，AddrOf 的操作数是变量时，我们用一种方式处理；操作数是解引用指针时，用另一种方式处理。我们先看看每种情形下应当生成什么指令，然后给出一种把要处理的特殊情况数量降到最少的 TACKY 转换策略。

### TACKY 中的指针操作

要解引用一个指针，然后对结果做左值转换，我们使用 Load 指令。此时，我们可以把表达式 `*<exp>` 翻译为清单 14-19。

```text
<instructions for exp>
ptr = <result of exp>
result = Load(ptr)
```

*清单 14-19：经历左值转换的指针解引用的 TACKY 实现*

当我们想给解引用指针赋值，而不是对它做左值转换时，我们使用 Store。我们把形如 `*<left> = <right>` 的赋值表达式翻译为清单 14-20。

```text
<instructions for left>
ptr = <result of left>
<instructions for right>
result = <result of right>
Store(result, ptr)
```

*清单 14-20：赋值表达式左侧的指针解引用的 TACKY 实现*

我们先算出 ptr，即某个对象的地址，以及 result，即我们要赋给该对象的值。然后，我们用 Store 执行赋值。注意，这里的单条 Store 指令同时实现了原表达式中的解引用和赋值两个操作。

最后来看 AddrOf 表达式。如果它的操作数是变量，我们用 GetAddress 得到指向它的指针。因此，我们把 `&var` 翻译为：

```text
result = GetAddress(var)
```

但如果操作数是解引用指针，那么外层的 AddrOf 和内层的 Dereference 表达式都不会被求值。看到形如 `&*<exp>` 的表达式时，我们只把内层的 `<exp>` 翻译为 TACKY。

### TACKY 转换策略

为了管理所有这些不同的情形，我们将用两个不同的函数把表达式转换为 TACKY。第一个是现有的 emit_tacky 函数。这个函数将不再返回 TACKY 操作数，而是返回一个新构造 exp_result，表示尚未经历左值转换的表达式结果。第二个函数 emit_tacky_and_convert 会调用 emit_tacky，对结果做左值转换（如果它是左值而不是常量），然后把它作为 TACKY 操作数返回。在大多数上下文中，我们用 emit_tacky_and_convert 处理表达式。但在处理不应做左值转换的表达式——比如赋值表达式的左侧——时，我们直接调用 emit_tacky。

先来定义 exp_result：

```text
exp_result = PlainOperand(val) | DereferencedPointer(val)
```

DereferencedPointer 顾名思义，表示被解引用指针所指代的对象。它接受单个参数：一个指针类型的 TACKY 操作数。PlainOperand 表示普通的常量或变量。它的参数是任意类型的 TACKY 操作数。exp_result 构造本身不是 TACKY 操作数，所以它不会出现在 TACKY 指令中。它只是帮助我们处理那些作用于对象而非值的 AddrOf 和赋值表达式。对于这些表达式，我们会根据其操作数是解引用指针还是普通变量，生成不同的指令。在后面的章节中，我们会添加更多解引用指针的运算符，比如数组下标和访问结构成员的 `->` 运算符。到那时，DereferencedPointer 构造函数将格外有用，因为它让我们能用统一的方式表示所有这些不同运算符的结果。

现在来更新 emit_tacky。我们会在整个函数中做几处修改。第一，凡是当前对子表达式递归调用 emit_tacky 的地方——赋值表达式的左侧除外——都改为调用 emit_tacky_and_convert。这个函数会把子表达式转换为 TACKY，然后对结果做左值转换。第二，凡是当前返回 TACKY 操作数的地方，都把该操作数包进 PlainOperand 构造函数。清单 14-21 展示了如何处理一元表达式，本章的改动以粗体标出。

```text
emit_tacky(e, instructions, symbols):
    match e with
    | --snip--
    | Unary(op, inner) ->
        src = emit_tacky_and_convert(inner, instructions, symbols)
        dst = make_tacky_variable(get_type(e), symbols)
        tacky_op = convert_unop(op)
        instructions.append(Unary(tacky_op, src, dst))
        return PlainOperand(dst)
```

*清单 14-21：把一元表达式翻译为 TACKY*

emit_tacky 当前处理的每一种表达式都做同样的修改。

接下来处理 Dereference 表达式。清单 14-22 演示了如何在 emit_tacky 中处理它。

```text
    | Dereference(inner) ->
        result = emit_tacky_and_convert(inner, instructions, symbols)
        return DereferencedPointer(result)
```

*清单 14-22：把 Dereference 表达式翻译为 TACKY*

处理这个表达式时，我们先处理其操作数并对它做左值转换。这会产生一个指针类型的 TACKY 操作数 result。然后，我们返回一个 DereferencedPointer，表示 result 指向的对象。

emit_tacky 返回 exp_result 之后，我们要么对它赋值，要么取它的地址，要么对它做左值转换。清单 14-23 演示了如何处理赋值。

```text
    | Assignment(left, right) ->
      ❶ lval = emit_tacky(left, instructions, symbols)
      ❷ rval = emit_tacky_and_convert(right, instructions, symbols)
        match lval with
        | PlainOperand(obj) ->
          ❸ instructions.append(Copy(rval, obj))
            return lval
        | DereferencedPointer(ptr) ->
          ❹ instructions.append(Store(rval, ptr))
            return PlainOperand(rval)
```

*清单 14-23：把赋值表达式翻译为 TACKY*

我们对赋值表达式的左侧 ❶ 不做左值转换，但对右侧 ❷ 做左值转换。如果左侧是 PlainOperand，就与前几章一样发射一条 Copy 指令 ❸。如果它是一个 DereferencedPointer，就发射一条 Store 指令，写入内层指针所指的位置 ❹。注意，即使是通过指针赋值，我们返回的结果也是 PlainOperand。这是因为赋值表达式的结果是存储在左侧对象中的值，而不是对象本身。

我们用类似的模式处理 AddrOf。清单 14-24 给出了伪代码。

```text
    | AddrOf(inner) ->
      ❶ v = emit_tacky(inner, instructions, symbols)
        match v with
        | PlainOperand(obj) ->
            dst = make_tacky_variable(get_type(e), symbols)
          ❷ instructions.append(GetAddress(obj, dst))
            return PlainOperand(dst)
        | DereferencedPointer(ptr) ->
          ❸ return PlainOperand(ptr)
```

*清单 14-24：把 AddrOf 表达式翻译为 TACKY*

我们对表达式的操作数不做左值转换直接处理 ❶，然后对结果做模式匹配来决定下一步怎么做。如果它是一个普通的值，就发射一条 GetAddress 指令 ❷。如果它是一个解引用指针，就丢弃解引用，直接返回该指针 ❸。

最后，我们在清单 14-25 中定义执行左值转换的 emit_tacky_and_convert。

```text
emit_tacky_and_convert(e, instructions, symbols):
    result = emit_tacky(e, instructions, symbols)
    match result with
    | PlainOperand(val) -> return val
    | DereferencedPointer(ptr) ->
        dst = make_tacky_variable(get_type(e), symbols)
        instructions.append(Load(ptr, dst))
        return dst
```

*清单 14-25：把表达式翻译为 TACKY 并执行左值转换*

要对一个解引用指针做左值转换，我们用一条 Load 指令取出它的值。其他操作数可以直接原样返回，无需发射任何额外指令。完整的表达式——即不属于其他表达式一部分的表达式——总是要经历左值转换。这意味着，处理完整表达式并获取其结果时，应当使用 emit_tacky_and_convert 而不是 emit_tacky。例如，处理循环和 if 语句的控制表达式时，就要用 emit_tacky_and_convert。

某些完整表达式的结果不会被使用——具体来说，就是表达式语句，以及 for 循环头部的第一和第三子句。作为一种优化，你可以用 emit_tacky 处理这些表达式，从而省掉一条不必要的 Load 指令。

作为本节的收尾，我们来实现与指针类型之间的强制转换。就强制转换而言，我们把指针类型完全当作 unsigned long 对待。例如，从 int 强制转换到任何指针类型用一条 SignExtend 指令，从指针类型强制转换到 int 用 Truncate。其他表达式（比如逻辑运算和比较）的 TACKY 实现不会改变。

## 汇编生成

在上一节中，我们添加了让我们能够读写内存的 Load 和 Store 指令。这意味着 TACKY 终于赶上了汇编——从第 2 章起，我们就一直在用汇编来读写内存。例如，操作数 -4(%rbp) 标识内存中的一个位置，我们可以用 mov 指令读取或写入它。

不过，RBP 并没有什么特别之处；我们可以通过存储在任何寄存器中的地址来访问内存。下面展示了如何从 RAX 寄存器中存储的地址读取值，并把它复制到 RCX：

```asm
movq    (%rax), %rcx
```

注意，(%rax) 等价于 0(%rax)。

汇编 AST 会稍作修改，以处理像 (%rax) 这样的操作数。首先，我们把 RBP 寄存器加入 AST：

```text
reg = AX | CX | DX | DI | SI | R8 | R9 | R10 | R11 | SP | BP | --snip--
```

然后，我们把 Stack 操作数——它让我们能够访问 RBP 中的地址偏移一定量的内存——替换成更通用的 Memory 操作数，后者可以使用存储在任何寄存器中的基地址：

```text
operand = Imm(int) | Reg(reg) | Pseudo(identifier) | Memory(reg, int) | Data(identifier)
```

这样一来，把 Load 或 Store 指令转换为汇编就非常简单了。我们把

```text
Load(ptr, dst)
```

翻译为：

```text
Mov(Quadword, ptr, Reg(AX))
Mov(<dst type>, Memory(AX, 0), dst)
```

第一条指令把内存地址 ptr 移入一个寄存器。第二条指令把存储在该地址的值——我们用 Memory 操作数访问它——移到目的地。在这个例子中，我们把 ptr 复制到 RAX，但任何通用寄存器都可以（R10、R11 或被调用者保存的寄存器除外）。

同样地，我们把

```text
Store(src, ptr)
```

翻译为：

```text
Mov(Quadword, ptr, Reg(AX))
Mov(<src type>, src, Memory(AX, 0))
```

注意，把指针复制到寄存器时，我们使用 Quadword 操作数类型，因为指针是 8 字节。但把值复制到指针所指的内存位置，或者从那里复制出来时，由值的类型决定 mov 指令的类型。

我们将用一条新的汇编指令实现 GetAddress：lea，它是 load effective address（加载有效地址）的缩写。指令 lea src, dst 把其源操作数（必须是内存操作数）的地址复制到目的地。例如，lea (%rbp), %rax 等价于 mov %rbp, %rax。你也可以用 lea 获取 RIP 相对地址，所以

```asm
lea    x(%rip), %rax
```

把符号 x 的地址存入 RAX 寄存器。

有了这条新指令，把 GetAddress 转换为汇编就很直截了当。我们把

```text
GetAddress(src, dst)
```

翻译为：

```text
Lea(src, dst)
```

正如我之前提到的，出于显而易见的原因，这里的 src 必须是内存操作数，不能是常量或寄存器。目前，我们必定满足这个约束；我们把每个伪寄存器都映射到内存地址，而且类型检查器会捕获任何对常量取地址的企图。但在第 III 部分实现寄存器分配时，我们会把一些变量存储在寄存器而不是内存中。到那时，要保证 lea 绝不会尝试加载寄存器的地址，还需要一些额外的工作。

清单 14-26 定义了完整的汇编 AST，包括新的 Memory 操作数、BP 寄存器和 Lea 指令。

```text
program = Program(top_level*)
assembly_type = Longword | Quadword | Double
top_level = Function(identifier name, bool global, instruction* instructions)
          | StaticVariable(identifier name, bool global, int alignment, static_init init)
          | StaticConstant(identifier name, int alignment, static_init init)
instruction = Mov(assembly_type, operand src, operand dst)
            | Movsx(operand src, operand dst)
            | MovZeroExtend(operand src, operand dst)
            | Lea(operand src, operand dst)
            | Cvttsd2si(assembly_type dst_type, operand src, operand dst)
            | Cvtsi2sd(assembly_type src_type, operand src, operand dst)
            | Unary(unary_operator, assembly_type, operand)
            | Binary(binary_operator, assembly_type, operand, operand)
            | Cmp(assembly_type, operand, operand)
            | Idiv(assembly_type, operand)
            | Div(assembly_type, operand)
            | Cdq(assembly_type)
            | Jmp(identifier)
            | JmpCC(cond_code, identifier)
            | SetCC(cond_code, operand)
            | Label(identifier)
            | Push(operand)
            | Call(identifier)
            | Ret

unary_operator = Neg | Not | Shr
binary_operator = Add | Sub | Mult | DivDouble | And | Or | Xor
operand = Imm(int) | Reg(reg) | Pseudo(identifier) | Memory(reg, int) | Data(identifier)
cond_code = E | NE | G | GE | L | LE | A | AE | B | BE
reg = AX | CX | DX | DI | SI | R8 | R9 | R10 | R11 | SP | BP
    | XMM0 | XMM1 | XMM2 | XMM3 | XMM4 | XMM5 | XMM6 | XMM7 | XMM14 | XMM15
```

*清单 14-26：加入 Memory 操作数、BP 寄存器和 Lea 指令的汇编 AST*

把其他 TACKY 指令翻译为汇编时，我们会把指针类型完全当作 unsigned long 对待。我们把指针类型转换为 Quadword 汇编类型，用 cmp 指令比较指针，在 RAX 寄存器中传递指针类型的返回值，并把指针类型的形参加整数形参一样放进相同的通用寄存器中传递。

我们还要做一个纯机械性的修改：凡是之前使用形如 Stack(<i>) 的操作数的地方，都改用 Memory(BP, <i>)。表 14-1 到表 14-3 总结了本章对 TACKY 到汇编转换的更新；照例，新构造以及对现有构造转换的改动以粗体标出。

*表 14-1：将 TACKY 顶层构造转换为汇编*

| TACKY 顶层构造 | 汇编顶层构造 |
| --- | --- |
| Function(name, global, params, instructions) | Function(name, global, [Mov(\<first int param type\>, Reg(DI), \<first int param\>), Mov(\<second int param type\>, Reg(SI), \<second int param\>), \<copy next four integer parameters from registers\>, Mov(Double, Reg(XMM0), \<first double param\>), Mov(Double, Reg(XMM1), \<second double param\>), \<copy next six double parameters from registers\>, Mov(\<first stack param type\>, Memory(BP, 16), \<first stack param\>), Mov(\<second stack param type\>, Memory(BP, 24), \<second stack param\>), \<copy remaining parameters from stack\>] + instructions) |

*表 14-2：将 TACKY 指令转换为汇编*

| TACKY 指令 | 汇编指令 |
| --- | --- |
| Load(ptr, dst) | Mov(Quadword, ptr, Reg(\<R\>)) Mov(\<dst type\>, Memory(\<R\>, 0), dst) |
| Store(src, ptr) | Mov(Quadword, ptr, Reg(\<R\>)) Mov(\<src type\>, src, Memory(\<R\>, 0)) |
| GetAddress(src, dst) | Lea(src, dst) |

*表 14-3：将类型转换为汇编*

| 源类型 | 汇编类型 | 对齐 |
| --- | --- | --- |
| Pointer(referenced_t) | Quadword | 8 |

接下来，我们更新伪寄存器替换和指令修补这两个遍。

### 用内存操作数替换伪寄存器

在这一遍中，我们会全程用新的 Memory 操作数取代旧的 Stack 操作数。我们还会扩展这一遍，替换 lea 指令中的伪寄存器。除此之外不做任何其他修改。把 TACKY 指针变量转换为伪寄存器时，我们给它们分配了 Quadword 汇编类型；现在我们会像对待其他任何 Quadword 一样为它们分配栈空间。

### 修补 lea 与 push 指令

lea 指令的目的地必须是寄存器；我们按通常的方式改写它。我们还要为 push 指令添加一条新的改写规则。正如我在上一章提到的，压入 XMM 寄存器是非法的，所以我们要把像

```asm
pushq   %xmm0
```

这样的指令改写为：

```asm
subq    $8, %rsp
movsd   %xmm0, (%rsp)
```

push 指令把栈指针递减 8 字节，然后把它的操作数移到栈顶。当不能使用 push 时，我们用两条指令完成同样的操作：先 sub 再 mov。操作数 (%rsp) 指定栈顶处的内存位置。

由于我们目前不会生成任何操作 XMM 寄存器的 push 指令，这条改写规则暂时并不是必需的。等我们在第 III 部分实现寄存器分配之后，它就会变得必要；那时，当前存储在内存中的值可能会被分配到 XMM 寄存器。

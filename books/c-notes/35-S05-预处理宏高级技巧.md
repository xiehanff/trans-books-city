# 预处理宏高级技巧

宏是 C 语言预处理器提供的文本替换机制。用好了是利器，用不好是地雷。

## 宏的本质

### 文本替换机制

宏的运作方式非常原始：预处理器把源代码中的宏名替换成对应的文本，不做任何语法分析。

```c
#define SQUARE(x) x * x

int a = SQUARE(3);        // 展开为: int a = 3 * 3;
int b = SQUARE(1 + 2);    // 展开为: int b = 1 + 2 * 1 + 2;  → 5，不是 9
```

预处理器不关心 C 语法，它只认文本。这就是坑的来源。

### 预处理器工作阶段

编译过程分为几个阶段：

1. **字符映射**：处理三字符组、行拼接（`\` 换行符续行）
2. **词法分析**：将源码分割为预处理 token 和空白字符序列
3. **预处理**：
   - 展开头文件 `#include`
   - 条件编译 `#if`、`#ifdef`
   - 宏展开 `#define`
4. **编译**：语法分析、生成目标代码

宏展开发生在语法分析之前，编译器根本看不到宏的原始形式。

### 宏 vs 函数

| 特性 | 宏 | 函数 |
|-----|---|-----|
| 执行时机 | 编译期文本替换 | 运行期调用 |
| 类型检查 | 无 | 有 |
| 参数求值 | 每次使用都求值 | 仅调用时求值一次 |
| 作用域 | 全局（从定义处开始） | 遵循作用域规则 |
| 调试 | 难（无符号信息） | 易（可设断点） |
| 代码体积 | 每处展开都生成代码 | 只有一份函数体 |
| 性能 | 无调用开销 | 有调用开销 |

简短、频繁调用的代码适合用宏；复杂逻辑、需要类型安全时用函数。

## 宏的常见陷阱

### 运算符优先级问题

经典翻车现场：

```c
#define DOUBLE(x) x + x

int a = DOUBLE(3) * 2;     // 期望 12，实际 3 + 3 * 2 = 9
```

解决方案：参数和整体都加括号。

```c
#define DOUBLE(x) ((x) + (x))

int a = DOUBLE(3) * 2;     // ((3) + (3)) * 2 = 12
```

### 参数多次求值问题

```c
#define MAX(a, b) ((a) > (b) ? (a) : (b))

int i = 5;
int m = MAX(i++, 10);      // 展开为: ((i++) > (10) ? (i++) : (10))
                           // i 被自增两次！
```

宏参数在展开后可能被求值多次。如果参数有副作用（如 `i++`），结果不可预测。

解决方案：用函数，或者在宏中使用临时变量（GNU C 扩展）：

```c
#define MAX(a, b) ({       \
    typeof(a) _a = (a);    \
    typeof(b) _b = (b);    \
    _a > _b ? _a : _b;     \
})
```

### 分号问题

```c
#define FOO(x) do_something(x);

if (cond)
    FOO(x);        // 多余的分号导致空语句
else
    FOO(y);        // else 悬挂，编译错误
```

正确写法：用 `do { ... } while(0)` 包裹。

```c
#define FOO(x) do {         \
    do_something(x);        \
} while(0)

if (cond)
    FOO(x);     // 展开后变成 do { ... } while(0);
else            // 语法正确
    FOO(y);
```

这个技巧让宏在任何需要语句的地方都能安全使用，包括 if-else、循环体等。

### 逗号问题

当宏需要返回值且包含多条语句时，逗号表达式是一种方案：

```c
#define INCREMENT(x) ((x)++, (x))

int a = 5;
int b = INCREMENT(a);    // a = 6, b = 6
```

但过度使用会降低可读性。复杂逻辑还是写成函数更好。

## 字符串化与拼接

### `#` 字符串化运算符

`#` 把宏参数转换成字符串字面量。

```c
#define STRINGIFY(x) #x

STRINGIFY(hello)          // "hello"
STRINGIFY(1 + 2)          // "1 + 2"
```

实际应用：打印变量名和值。

```c
#define PRINT_VAR(var) printf(#var " = %d\n", var)

int count = 42;
PRINT_VAR(count);         // 输出: count = 42
```

如果参数本身是宏，想展开后再字符串化，需要两层宏：

```c
#define STRINGIFY_IMPL(x) #x
#define STRINGIFY(x) STRINGIFY_IMPL(x)

#define VERSION 100
STRINGIFY(VERSION)        // "100"，不是 "VERSION"
```

原理：`STRINGIFY(VERSION)` 先展开 `VERSION` 得到 `STRINGIFY_IMPL(100)`，再字符串化。

### `##` 拼接运算符

`##` 把两个 token 拼接成一个。

```c
#define CONCAT(a, b) a##b

CONCAT(var, 1)            // var1
CONCAT(func, _name)       // func_name
```

典型用途：生成变量名、函数名。

```c
#define MAKE_VAR(name) int var_##name = 0

MAKE_VAR(count);          // int var_count = 0;
MAKE_VAR(index);          // int var_index = 0;
```

结合 `#` 和 `##` 可以做代码生成：

```c
#define REGISTER_HANDLER(name)       \
    void handler_##name(void);       \
    struct Handler handlers[] = {    \
        { #name, handler_##name }    \
    }

REGISTER_HANDLER(click);   // 生成 handler_click 函数声明和注册代码
```

## 可变参数宏

### `__VA_ARGS__` 用法

C99 支持可变参数宏，`__VA_ARGS__` 代表省略号部分的参数。

```c
#define DEBUG_PRINT(fmt, ...) \
    printf("[DEBUG] " fmt "\n", __VA_ARGS__)

DEBUG_PRINT("count = %d", 42);         // [DEBUG] count = 42
DEBUG_PRINT("x=%d, y=%d", 10, 20);     // [DEBUG] x=10, y=20
```

### `##__VA_ARGS__`（GCC 扩展）

标准 `__VA_ARGS__` 有个问题：如果可变参数为空，末尾会多一个逗号。

```c
#define LOG(fmt, ...) printf(fmt, __VA_ARGS__)

LOG("hello");            // 展开为 printf("hello", )，编译报错
```

GCC 提供了 `##__VA_ARGS__` 解决这个问题：当可变参数为空时，自动删除前面的逗号。

```c
#define LOG(fmt, ...) printf(fmt, ##__VA_ARGS__)

LOG("hello");            // 展开为 printf("hello")，OK
LOG("count = %d", 42);   // 展开为 printf("count = %d", 42)，OK
```

### 日志宏的典型实现

一个实用的日志系统：

```c
#include <stdio.h>

#define LOG_LEVEL_DEBUG 0
#define LOG_LEVEL_INFO  1
#define LOG_LEVEL_WARN  2
#define LOG_LEVEL_ERROR 3

#ifndef LOG_LEVEL
#define LOG_LEVEL LOG_LEVEL_DEBUG
#endif

#define LOG(level, fmt, ...)                                      \
    do {                                                          \
        if (level >= LOG_LEVEL) {                                 \
            const char *level_str[] = {"DEBUG", "INFO",           \
                                       "WARN", "ERROR"};          \
            printf("[%s][%s:%d] " fmt "\n",                       \
                   level_str[level], __FILE__, __LINE__,          \
                   ##__VA_ARGS__);                                \
        }                                                         \
    } while(0)

#define LOG_DBG(fmt, ...) LOG(LOG_LEVEL_DEBUG, fmt, ##__VA_ARGS__)
#define LOG_INF(fmt, ...) LOG(LOG_LEVEL_INFO,  fmt, ##__VA_ARGS__)
#define LOG_WRN(fmt, ...) LOG(LOG_LEVEL_WARN,  fmt, ##__VA_ARGS__)
#define LOG_ERR(fmt, ...) LOG(LOG_LEVEL_ERROR, fmt, ##__VA_ARGS__)

// 使用
int main(void) {
    LOG_DBG("debug message");
    LOG_INF("count = %d", 42);
    LOG_ERR("error code: %d", -1);
    return 0;
}
```

输出类似：

```
[DEBUG][main.c:22] debug message
[INFO][main.c:23] count = 42
[ERROR][main.c:24] error code: -1
```

## 编译时技巧

### `_Static_assert`（C11）

C11 引入了静态断言，在编译期检查条件。

```c
_Static_assert(sizeof(int) == 4, "int must be 4 bytes");
_Static_assert(sizeof(void*) == 8, "64-bit platform required");
```

如果条件为假，编译失败并显示错误信息。

结合数组和结构体：

```c
struct Header {
    int magic;
    int version;
    int length;
};

_Static_assert(sizeof(struct Header) == 12, "Header size mismatch");
```

### 编译时断言的旧式写法

C11 之前，用负数数组大小模拟静态断言：

```c
#define STATIC_ASSERT(cond, msg) \
    typedef char static_assert_##msg[(cond) ? 1 : -1]

STATIC_ASSERT(sizeof(int) == 4, int_must_be_4_bytes);
STATIC_ASSERT(sizeof(void*) == 8, need_64bit);
```

原理：如果 `cond` 为假，数组大小为负，编译报错。错误信息虽然不友好，但能定位问题。

### `#if` 与 `#ifdef` 的区别

`#ifdef` 检查宏是否定义，不关心值。

```c
#define DEBUG

#ifdef DEBUG
    // 这段代码会被编译
#endif
```

`#if` 检查宏的值，未定义的宏值为 0。

```c
#if DEBUG              // DEBUG 未定义或定义为 0，条件为假
    // 这段代码不会编译
#endif

#define DEBUG 1

#if DEBUG              // DEBUG 为 1，条件为真
    // 这段代码会被编译
#endif
```

`#if` 支持表达式：

```c
#if VERSION >= 100
    // 新版本代码
#elif VERSION >= 50
    // 中间版本代码
#else
    // 旧版本代码
#endif
```

`defined` 运算符可与 `#if` 配合：

```c
#if defined(DEBUG) && defined(VERBOSE)
    // 两个宏都定义时编译
#endif

#if defined(WIN32) || defined(_WIN32)
    // Windows 平台
#endif
```

### 条件编译的实际场景

**跨平台代码：**

```c
#if defined(_WIN32)
    #include <windows.h>
    #define SLEEP(ms) Sleep(ms)
#elif defined(__linux__)
    #include <unistd.h>
    #define SLEEP(ms) usleep((ms) * 1000)
#else
    #error "Unsupported platform"
#endif
```

**调试开关：**

```c
#ifdef DEBUG
    #define ASSERT(cond) assert(cond)
#else
    #define ASSERT(cond) ((void)0)
#endif
```

**功能裁剪：**

```c
#ifdef FEATURE_A
    void feature_a_init(void);
    void feature_a_process(void);
#endif

#ifdef FEATURE_B
    void feature_b_init(void);
#endif

void init(void) {
#ifdef FEATURE_A
    feature_a_init();
#endif
#ifdef FEATURE_B
    feature_b_init();
#endif
}
```

**防止重复包含：**

```c
#ifndef MYHEADER_H
#define MYHEADER_H

// 头文件内容

#endif // MYHEADER_H
```

## 预定义宏

### `__FILE__`, `__LINE__`, `__func__`

这三个宏用于定位代码位置，调试利器。

```c
void log_location(void) {
    printf("File: %s, Line: %d, Function: %s\n",
           __FILE__, __LINE__, __func__);
}
```

`__FILE__` 和 `__LINE__` 是预处理宏，`__func__` 是 C99 的预定义变量（不是宏）。

实际应用：

```c
#define CHECK_PTR(p)                                        \
    do {                                                    \
        if ((p) == NULL) {                                  \
            fprintf(stderr, "%s:%d: %s: null pointer\n",    \
                    __FILE__, __LINE__, __func__);          \
            abort();                                        \
        }                                                   \
    } while(0)
```

### `__DATE__`, `__TIME__`

记录编译时间。

```c
printf("Compiled on %s at %s\n", __DATE__, __TIME__);
// 输出: Compiled on May  1 2026 at 14:30:25
```

可用于版本信息：

```c
const char *build_info(void) {
    static char info[64];
    snprintf(info, sizeof(info), "Build: %s %s", __DATE__, __TIME__);
    return info;
}
```

### `__cplusplus`

判断是否在 C++ 编译环境下。

```c
#ifdef __cplusplus
extern "C" {
#endif

// C 函数声明

#ifdef __cplusplus
}
#endif
```

这对头文件特别重要，确保 C 代码能被 C++ 项目正确调用。

### 其他常用预定义宏

| 宏 | 说明 |
|---|------|
| `__STDC__` | 定义为 1 表示符合 ANSI C |
| `__STDC_VERSION__` | C 标准版本，如 199901L (C99)、201112L (C11) |
| `__GNUC__` | GCC 主版本号 |
| `__clang__` | Clang 编译器 |
| `_MSC_VER` | MSVC 版本号 |

根据编译器选择代码：

```c
#if defined(__GNUC__)
    #define ATTR_UNUSED __attribute__((unused))
#elif defined(_MSC_VER)
    #define ATTR_UNUSED __pragma(warning(suppress: 4100))
#else
    #define ATTR_UNUSED
#endif
```

### 自定义调试宏

封装一套通用的调试输出：

```c
#ifdef DEBUG

#define DBG_ENTER()  printf(">>> Enter %s\n", __func__)
#define DBG_EXIT()   printf("<<< Exit %s\n", __func__)
#define DBG_PRINT(fmt, ...) \
    printf("[%s:%d] " fmt "\n", __func__, __LINE__, ##__VA_ARGS__)

#else

#define DBG_ENTER()  ((void)0)
#define DBG_EXIT()   ((void)0)
#define DBG_PRINT(fmt, ...) ((void)0)

#endif

void process(int data) {
    DBG_ENTER();
    DBG_PRINT("data = %d", data);
    // 处理逻辑
    DBG_EXIT();
}
```

## 常用宏设计模式

### MIN/MAX 宏的正确写法

初学者版本（有问题）：

```c
#define MIN(a, b) (a < b ? a : b)           // 优先级问题
#define MIN(a, b) ((a) < (b) ? (a) : (b))   // 多次求值问题
```

GNU C 扩展版本：

```c
#define MIN(a, b) ({        \
    typeof(a) _a = (a);     \
    typeof(b) _b = (b);     \
    _a < _b ? _a : _b;      \
})

#define MAX(a, b) ({        \
    typeof(a) _a = (a);     \
    typeof(b) _b = (b);     \
    _a > _b ? _a : _b;      \
})
```

C11 泛型版本（类型安全）：

```c
#define MIN(a, b) _Generic((a), \
    int: min_int,               \
    long: min_long,             \
    double: min_double          \
)((a), (b))

static inline int min_int(int a, int b) { return a < b ? a : b; }
static inline long min_long(long a, long b) { return a < b ? a : b; }
static inline double min_double(double a, double b) { return a < b ? a : b; }
```

### 安全的容器宏

计算数组元素个数：

```c
#define ARRAY_SIZE(arr) (sizeof(arr) / sizeof((arr)[0]))

int arr[] = {1, 2, 3, 4, 5};
for (int i = 0; i < ARRAY_SIZE(arr); i++) {
    printf("%d ", arr[i]);
}
```

但指针传入时会出错：

```c
int *ptr = arr;
ARRAY_SIZE(ptr);    // sizeof(int*) / sizeof(int)，错误！
```

这个宏只适用于真实数组，不适用于指针。`sizeof(ptr) / sizeof(ptr[0])` 只是指针大小除以元素大小，没有任何保护效果。

如果你需要更强的约束，别指望宏自动识别“这是数组还是指针”。更稳的做法是把“数据 + 长度”封装成结构体，或者在接口层显式传长度。

遍历容器：

```c
#define FOR_EACH(item, arr)                     \
    for (int _i = 0; _i < ARRAY_SIZE(arr) &&    \
         ((item) = arr[_i], 1); _i++)

int nums[] = {1, 2, 3, 4, 5};
int n;
FOR_EACH(n, nums) {
    printf("%d ", n);
}
```

### 类型安全的泛型宏（C11 `_Generic`）

`_Generic` 根据第一个参数的类型选择不同的表达式。

基本语法：

```c
#define type_name(x) _Generic((x),   \
    int: "int",                      \
    float: "float",                  \
    double: "double",                \
    default: "unknown"               \
)

printf("%s\n", type_name(42));        // int
printf("%s\n", type_name(3.14));     // double
```

实现泛型打印函数：

```c
void print_int(int x) { printf("%d\n", x); }
void print_float(float x) { printf("%f\n", x); }
void print_double(double x) { printf("%f\n", x); }
void print_str(const char *x) { printf("%s\n", x); }

#define print(x) _Generic((x),           \
    int: print_int,                      \
    float: print_float,                  \
    double: print_double,                \
    const char*: print_str,              \
    char*: print_str                     \
)(x)

print(42);          // 输出: 42
print(3.14);        // 输出: 3.140000
print("hello");     // 输出: hello
```

实现泛型 swap：

```c
#define SWAP(a, b) _Generic((a),                 \
    int*: swap_int,                              \
    float*: swap_float,                          \
    double*: swap_double                         \
)((a), (b))

void swap_int(int *a, int *b) { int t = *a; *a = *b; *b = t; }
void swap_float(float *a, float *b) { float t = *a; *a = *b; *b = t; }
void swap_double(double *a, double *b) { double t = *a; *a = *b; *b = t; }

int x = 1, y = 2;
SWAP(&x, &y);
```

## 宏的最佳实践

### 何时用宏，何时用函数

**用宏的场景：**

- 编译期需要确定的东西（如常量、类型相关）
- 短小、频繁调用的代码（避免函数调用开销）
- 需要取类型信息（`sizeof`、`typeof`）
- 调试和日志（获取 `__FILE__`、`__LINE__`）
- 条件编译

**用函数的场景：**

- 复杂逻辑
- 需要类型检查
- 参数有副作用
- 需要调试（设断点）
- 需要递归

**经验法则：** 能用函数就别用宏。

### 宏命名规范

宏名全大写，单词间用下划线分隔。这是约定俗成的规则，便于区分宏和函数。

```c
// 好的命名
#define MAX_BUFFER_SIZE 1024
#define ARRAY_SIZE(arr) (sizeof(arr) / sizeof(arr[0]))

// 不好的命名
#define max_buffer_size 1024    // 看起来像变量
#define arraySize(arr) ...      // 看起来像函数
```

例外：某些标准库宏（如 `getchar`、`putc`）有时实现为宏，但它们的命名遵循函数风格。用户代码不应模仿这种例外。

### 复杂宏的注释方法

多行宏用 `\` 续行，缩进要统一。每行末尾的 `\` 前不要有空格。

```c
/*
 * DEBUG_LOG - 输出调试日志
 * @level: 日志级别 (0=debug, 1=info, 2=warn, 3=error)
 * @fmt: printf 格式字符串
 * @...: 可变参数
 *
 * 示例: DEBUG_LOG(1, "count = %d", count);
 */
static int current_log_level = 1;

#define DEBUG_LOG(level, fmt, ...)              \
    do {                                        \
        if (level >= current_log_level) {       \
            fprintf(stderr, "[%s:%d] " fmt "\n", \
                    __FILE__, __LINE__,         \
                    ##__VA_ARGS__);             \
        }                                       \
    } while(0)
```

宏定义超过 5 行就该考虑是否该写成函数了。

### 其他建议

**避免全局宏污染：** 在头文件中定义宏后，及时 `#undef`。或者用前缀避免冲突。

```c
// header.h
#ifndef MYLIB_HEADER_H
#define MYLIB_HEADER_H

// 临时宏，用完即弃
#define MYLIB_INTERNAL_TMP(x) ((x) * 2)
// ... 使用 MYLIB_INTERNAL_TMP
#undef MYLIB_INTERNAL_TMP

#endif
```

**用 `#error` 和 `#warning` 提前发现问题：**

```c
#if !defined(PLATFORM)
    #error "PLATFORM must be defined"
#endif

#if defined(USE_DEPRECATED_API)
    #warning "Using deprecated API"
#endif
```

**宏定义常量优于 `const` 变量（有时）：**

```c
#define MAX_SIZE 100        // 可用于数组大小、case 标签、编译期计算
const int max_size = 100;   // 运行期常量，有些场景不能用

int arr[MAX_SIZE];          // OK
// int arr[max_size];       // C89 不支持，C99 支持 VLA
```

## 常见错误

### 忘记括号

```c
#define SQUARE(x) x * x

int a = SQUARE(1 + 2);    // 1 + 2 * 1 + 2 = 5
```

正确写法：

```c
#define SQUARE(x) ((x) * (x))

int a = SQUARE(1 + 2);    // ((1 + 2) * (1 + 2)) = 9
```

### 参数有副作用

```c
#define ABS(x) ((x) >= 0 ? (x) : -(x))

int n = -5;
int a = ABS(n++);    // n 被自增两次
```

正确做法：用函数，或用 GNU C 的 `({})` 语法。

### 宏定义末尾加分号

```c
#define FOO(x) do_something(x);    // 错！

if (cond)
    FOO(x);
else
    FOO(y);
```

这会导致 if-else 结构被破坏。去掉末尾分号，让调用者加。

### 头文件重复包含

虽然编译器通常能处理，但会增加预处理时间和可能的问题：

```c
// myheader.h 中忘记 include guard

// file.c
#include "myheader.h"
#include "myheader.h"    // 重复包含
```

始终使用 include guard 或 `#pragma once`。

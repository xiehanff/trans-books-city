# 第 7 章　复合语句

*Chapter 7: Compound Statements*

本章中，你将实现复合语句（compound statement）。复合语句有两个重要用途。正如你在前两章看到的，它们可以把其他语句和声明组合成单个单元，放进更大的构造中，比如 if 语句里。更有意思的是，它们还划定了函数内各个作用域（scope）的边界。变量的作用域是程序中可以使用该变量的那部分区域；当你在复合语句内部声明变量时，它的作用域只延伸到该语句的末尾。

本章我们会花一点时间扩展解析器，让它能把块项（block item）归组到一起，但主要任务是扩展变量解析遍（variable resolution pass），让它跟踪每个变量的作用域。我们对 TACKY 生成阶段几乎不做改动，而且完全不会碰词法分析器和汇编生成阶段。在着手解析器之前，我先快速概述 C 语言中的作用域机制是如何工作的，并定义一些本章稍后会用到的术语。

## 聊聊作用域

一种能够包含声明、并决定这些声明的作用域的语言构造称为块（block）。复合语句和函数体都是块。循环也是块（我们将在第 8 章实现循环）。（严格来说，if 语句同样是块，但这对我们的实现无关紧要。）局部变量的作用域从声明该变量的那一处开始。这意味着变量的作用域可以从块的中间开始。它的作用域一直延伸到声明它的那个块的末尾。例如，在程序

```c
int main(void) {
    int a ❶ = 5;
    return a;
❷}
```

中，变量 a 的作用域从它的初始化器（initializer）之前 ❶ 开始，一直延伸到函数的最末尾 ❷。

复合语句既可以独立出现，也可以出现在另一条语句内部。在清单 7-1 中，我们把复合语句用作 if 语句体。

```c
int main(void) {
    if (1) {
        int a ❶ = 2;
        return a + 1;
  ❷}
    return 0;
}
```

*清单 7-1：将复合语句用作 if 语句体*

在这个例子中，变量 a 的作用域从 ❶ 延伸到复合语句的末尾 ❷。

进入新块之后，你仍然可以使用外层作用域中的变量，如下面这段代码所示：

```c
int a = 2;
{
    int b = a + 2;
}
```

尽管 a 声明于外层作用域，我们在内层作用域中初始化 b 时仍然可以引用它，因此 b 被初始化为 4。但看看清单 7-2 中会发生什么：我们在内层块中又声明了一个名为 a 的变量。

```c
❶ int a = 2;
{
  ❷ int a = 3;
    int b = a + 2;
}
```

*清单 7-2：声明两个同名但作用域不同的变量*

这一次，初始化 b 的时候，有两个不同的名为 a 的变量都处于作用域内：一个声明于外层作用域 ❶，另一个声明于内层作用域 ❷。在这种情况下，我们总是使用最内层作用域中声明的变量。因此 b 被初始化为 5。虽然外层的 a 仍在作用域内，我们却无法访问它；它被内层的同名变量隐藏——也就是被遮蔽（shadowing）了。

被隐藏与超出作用域是两回事，因为被隐藏的变量在程序稍后还可以重新变得可见。清单 7-3 与清单 7-2 几乎完全相同，它说明了这一区别。

```c
❶ int a = 2;
{
  ❷ int a = 3;
    int b = a + 2;
}
❸ return a;
```

*清单 7-3：被隐藏的变量重新变得可见*

正如上一个例子所见，a 的第一个声明 ❶ 被第二个声明 ❷ 隐藏。但 return 语句 ❸ 位于复合语句结束之后。此时，第二个 a 已不在作用域内，于是第一个 a 重新可见。因此，return 语句会使用第一个 a，返回 2。

如果把清单 7-2 中内层块里两条语句的顺序调换一下会怎样？那样就会得到：

```c
int a = 2;
{
    int b = a + 2;
    int a = 3;
}
```

现在声明 b 的时候，内层的 a 尚未进入作用域，因此它没有隐藏外层的 a。表达式 a + 2 将引用 a 的第一个声明，所以我们会把 b 初始化为 4。

作用域可以有很多层嵌套，如清单 7-4 所示。

```c
int main(void) {
  ❶ int x = 1;
    {
      ❷ int x = 2;
        if (x > 1) {
          ❸ x = 3;
          ❹ int x = 4;
        }
      ❺ return x;
    }
  ❻ return x;
}
```

*清单 7-4：多层嵌套的作用域*

在这个清单中，我们声明了三个名为 x 的变量，它们的作用域各不相同。第一个 x 声明于 ❶，第二个声明于 ❷。我们在 ❸ 处把 3 赋给第二个 x，并在 ❺ 处返回它，所以整个程序返回 3。第三个名为 x 的变量（声明于 ❹）从未被使用。我们永远执行不到 ❻ 处的最后一条 return 语句，但如果执行到了，它会返回 1，也就是早在 ❶ 处声明的那个第一个 x 变量的值。

我们还需要处理两种与变量作用域相关的错误情形。（第 5 章曾简要介绍过这两种情形，但在包含多个作用域的程序中，检测它们要稍微复杂一些。）第一，如果作用域内没有任何同名变量，使用该变量名就是非法的。清单 7-5 展示了这种错误。

```c
int main(void) {
    {
        int x ❶ = 4;
  ❷}
    return ❸ x;
    int x ❹ = 3;
❺}
```

*清单 7-5：使用未声明的变量*

在这个清单中，我们声明了两个不同的名为 x 的变量。第一个声明的作用域从 ❶ 开始、到 ❷ 结束。第二个声明的作用域从 ❹ 开始、延伸到函数末尾 ❺。在 ❸ 处，这两个声明都不在作用域内。此时使用变量名 x 是一个错误，因为这个名字不指代任何东西。

第二，同一变量名不能在同一作用域中被多次声明。如果两个变量的作用域恰好在同一点结束，我们就说它们具有相同的作用域；也就是说，它们声明在同一个块中。例如，下面这段代码是无效的：

```c
int a = 3;
{
    int b = a;
    int b = 1;
}
```

第二个 b 的声明是非法的，因为它的作用域与第一个声明相同。

现在你已经理解了需要实现的作用域规则，我们开始动手改解析器吧。

## 解析器

由花括号包裹的语句和声明列表，既可以是函数体，也可以是复合语句。我们来定义一个块 AST 节点来同时表示这两种构造：

```text
block = Block(block_item*)
```

注意，这个 AST 节点并不表示 if 语句，而且等到第 8 章实现循环之后，它也不会表示循环——尽管严格来说它们也是块。

接下来，我们扩展 statement 节点来表示复合语句：

```text
statement = Return(exp)
          | Expression(exp)
          | If(exp condition, statement then, statement? else)
          | Compound(block)
          | Null
```

同时，我们把 function_definition 节点也改为使用 block：

```text
function_definition = Function(identifier name, block body)
```

清单 7-6 给出了包含这些改动的新 AST 定义，改动部分以粗体标出。

```text
program = Program(function_definition)
function_definition = Function(identifier name, block body)
block_item = S(statement) | D(declaration)
block = Block(block_item*)
declaration = Declaration(identifier name, exp? init)
statement = Return(exp)
          | Expression(exp)
          | If(exp condition, statement then, statement? else)
          | Compound(block)
          | Null
exp = Constant(int)
    | Var(identifier)
    | Unary(unary_operator, exp)
    | Binary(binary_operator, exp, exp)
    | Assignment(exp, exp)
    | Conditional(exp condition, exp, exp)
unary_operator = Complement | Negate | Not
binary_operator = Add | Subtract | Multiply | Divide | Remainder | And | Or
                | Equal | NotEqual | LessThan | LessOrEqual
                | GreaterThan | GreaterOrEqual
```

*清单 7-6：带有复合语句的抽象语法树*

清单 7-7 展示了文法（grammar）的相应改动。

```text
<program> ::= <function>
<function> ::= "int" <identifier> "(" "void" ")" <block>
<block> ::= "{" {<block-item>} "}"
<block-item> ::= <statement> | <declaration>
<declaration> ::= "int" <identifier> ["=" <exp>] ";"
<statement> ::= "return" <exp> ";"
              | <exp> ";"
              | "if" "(" <exp> ")" <statement> ["else" <statement>]
              | <block>
              | ";"
<exp> ::= <factor> | <exp> <binop> <exp> | <exp> "?" <exp> ":" <exp>
<factor> ::= <int> | <identifier> | <unop> <factor> | "(" <exp> ")"
<unop> ::= "-" | "~" | "!"
<binop> ::= "-" | "+" | "*" | "/" | "%" | "&&" | "||"
          | "==" | "!=" | "<" | "<=" | ">" | ">=" | "="
<identifier> ::= ? 一个标识符词法单元 ?
<int> ::= ? 一个常量词法单元 ?
```

*清单 7-7：带有复合语句的文法*

记住，<block> 定义中的 "{" 和 "}" 是字面量花括号，而 { 和 } 表示重复。你可以用已经熟悉的递归下降（recursive descent）技术解析更新后的文法。解析 <statement> 符号时，{ 词法单元（token）会告诉你遇到了复合语句，正如 if 关键字标志着 if 语句的开始、return 标志着 return 语句的开始一样。

## 变量解析

现在，我们将更新变量解析遍，使其遵循本章开头讨论的作用域规则。原始程序中任何同名的局部变量，都会在这一遍中被赋予不同的名字。在后续各遍中，我们完全不必再考虑作用域；因为每个变量都有唯一的名字，我们可以像前几章那样，把 AST 中的每个变量先转换为 TACKY 变量、再转换为伪寄存器（pseudoregister）、最后转换为内存地址，而不用担心每个名字指的是哪个对象。

### 在多个作用域中解析变量

举个例子，我们再看看清单 7-4 中的程序：

```c
int main(void) {
    int x = 1;
    {
        int x = 2;
        if (x > 1) {
            x = 3;
            int x = 4;
        }
        return x;
    }
    return x;
}
```

清单 7-8 展示了该程序经过变量解析之后的样子。

```c
int main(void) {
    int x0 = 1;
    {
        int x1 = 2;
        if (x1 > 1) {
            x1 = 3;
            int x2 = 4;
        }
        return x1;
    }
    return x0;
}
```

*清单 7-8：清单 7-4 中的程序经过变量解析后的结果*

现在每个变量都有了不同的名字。这些新名字明确显示了我们在每个位置使用的到底是哪个变量。例如，现在可以清楚地看到，函数开头声明的那个变量（我们已将其改名为 x0）只被使用过一次，就在最后。

变量解析的基本思路与前几章相同：遍历 AST，并在过程中维护一个从用户定义名字到生成名字的映射。但现在，新的作用域规则决定了我们如何更新这个映射。表 7-1 展示了变量映射在清单 7-4 各个位置的样子。

*表 7-1：清单 7-4 各处的变量映射*

| 代码 | 变量映射 |
| --- | --- |
| `int main(void) {` | （空映射） |
| `int x = 1;`<br>`{` | x → x0 |
| `int x = 2;`<br>`if (x > 1) {`<br>`x = 3;` | x → x1 |
| `int x = 4;`<br>`}` | x → x2 |
| `return x;`<br>`}` | x → x1 |
| `return x;`<br>`}` | x → x0 |

变量映射的状态在两种情况下发生变化。第一，声明新变量时，我们把它加入映射，并覆盖任何同名的现有变量。第二，退出块时，我们恢复到进入该块之前的那份变量映射。

第一种情况我们已经很熟悉：每当遇到变量声明，我们就添加一个映射条目。为了处理第二种情况，我们在每次进入新块时都复制一份变量映射。在处理该块的过程中，我们把新条目添加到那份副本中，而让外层作用域的变量映射保持不变。

现在你对这一遍的工作方式有了大致了解，我们来过一遍伪代码。

### 更新变量解析伪代码

先来看声明。在前几章，编译器一旦看到同一变量名的两个声明就会失败：

```text
resolve_declaration(Declaration(name, init), variable_map):
    if name is in variable_map:
        fail("Duplicate variable declaration!")
    --snip--
```

但现在情况有点复杂了。在多个声明中复用同一变量名是合法的，但在同一个块中多次声明同一变量名则是非法的。为了实施这条规则，我们要为变量映射中的每个条目跟踪两件事：它新生成的名字，以及它是否是在当前块中声明的。清单 7-9 给出了处理声明的更新版伪代码，相对清单 5-9 中旧版本的改动以粗体标出。

```text
resolve_declaration(Declaration(name, init), variable_map):
    if name is in variable_map and variable_map.get(name).from_current_block:
        fail("Duplicate variable declaration!")
    unique_name = make_temporary()
    variable_map.add(name, MapEntry(new_name=unique_name, from_current_block=True))
    if init is not null:
        init = resolve_exp(init, variable_map)
    return Declaration(unique_name, init)
```

*清单 7-9：解析变量声明*

接下来，我们需要一个能按顺序处理块项的函数（在后面的伪代码清单中，我会把它称为 resolve_block）。处理函数体的这段代码你早已写过；现在只需对其进行重构，以便复用它来处理复合语句。记住，处理某个块项（具体来说就是声明）时所做的修改，在处理后续块项时必须仍然可见。

我们还要更新 resolve_statement 来处理复合语句。清单 7-10 给出了 resolve_statement 的更新版伪代码，相对清单 5-10 中旧版本的改动以粗体标出。这里的关键细节是：遍历复合语句时，我们会传入变量映射的一个副本，这样在复合语句内部处理的所有声明在它外部都不可见。

```text
resolve_statement(statement, variable_map):
    match statement with
    | Return(e) -> return Return(resolve_exp(e, variable_map))
    | Expression(e) -> return Expression(resolve_exp(e, variable_map))
    | Compound(block) ->
        new_variable_map = copy_variable_map(variable_map)
        return Compound(resolve_block(block, new_variable_map))
    | --snip--
```

*清单 7-10：解析复合语句*

最后，我们来实现 copy_variable_map。它应当创建变量映射的一个副本，并把其中每个条目的 from_current_block 标志都设为 False。这样一来，当我们处理内层作用域中那些遮蔽外层作用域声明的声明时，就不会抛出错误。

完成这些修改之后，你的变量解析遍就能处理嵌套作用域了！

## TACKY 生成

最后一步是扩展 TACKY 生成阶段来处理复合语句。这非常简单：要把复合语句转换为 TACKY，只需把它内部的每个块项都转换为 TACKY。总的来说，处理复合语句的方式应该与你现在已经用来处理函数体的方式完全相同。后续的编译器阶段完全不需要改动；一旦 TACKY 生成正常工作，本章就大功告成了！

## 小结

本章中，你只扩展了编译器中的少数几个阶段，就实现了一种新的语句。你编写了一个更完善的变量解析遍，能够正确解析多个作用域中的变量，从而大幅扩展了可编译的程序范围。接下来，你将实现循环、break 语句和 continue 语句。当你添加对 for 循环的支持时，本章的工作将尤为重要，因为单个 for 循环就包含两个不同的作用域。

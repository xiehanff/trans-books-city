# 第 15 章　数组与指针运算

*Chapter 15: Arrays and Pointer Arithmetic*

在本章中，你将实现数组类型。你还将添加程序员用来处理数组的主要语言特性：复合初始化器（compound initializer）、下标运算符（subscript operator）和指针算术（pointer arithmetic）。数组与指针是两种不同但又密切相关的类型。许多数组类型的表达式会被隐式转换为指针，而许多指针操作（比如下标）本就是为操作指向数组元素的指针而设计的。因此，为了支持数组，你将在上一章添加的指针支持的基础上继续构建。

类型检查器在这里扮演着尤为关键的角色。它将处理从数组到指针的隐式转换，并用你进行指针算术所依赖的类型信息来标注 AST。一旦类型检查器完成了所有繁重的工作，在 TACKY 生成阶段把下标运算符和复合初始化器分解为简单的指针操作就相对容易了。本章不会添加任何新的汇编指令，但你会引入新的操作数来表示内存中的对象以及这些对象内部的元素。

照例，我们先概述将要添加的语言构造。我们会特别关注指针与数组之间的关系，以及这种关系在指针算术和下标表达式中如何体现。这是 C 语言中特别容易让人困惑的一部分，也是本章所有内容的关键。

## 数组与指针运算

让我们先定义几个术语。在上一章中，我们把已知的每个对象类型分成了两类：算术类型和非算术类型。现在我们引入另一种区分。标量类型（scalar type）表示单个值。我们已经实现的指针类型和算术类型都是标量类型。聚合类型（aggregate type）表示一组值的集合。数组是聚合类型；结构也是，我们将在第 18 章实现结构。数组中所有值的类型都相同，这就是数组的元素类型（element type）。

### 数组声明与初始化器

声明数组时，我们要指定它的元素类型和它包含的元素个数。例如，我们可以声明一个包含三个 int 对象的数组：

```c
int int_array[3];
```

或者声明一个包含五个指向 double 的指针的数组：

```c
double *(ptr_array[5]);
```

（还记得吧，我们解释一个声明时，要从基本类型——这里是 double——开始，然后从外到内地应用各个类型派生。）

这两个例子使用的都是标量元素类型，但我们也可以使用聚合元素类型。下面的例子声明了一个包含三个元素的数组，其中每个元素本身又是一个包含两个 long 对象的数组：

```c
long nested_array[3][2];
```

像这样的数组的数组称为多维数组（multidimensional array）。注意，确定这个数组的类型时，我们仍然是从外到内地应用类型派生。我们从基本类型 long 出发，应用 [2] 指定的派生得到"包含两个 long 对象的数组"类型，再应用 [3] 指定的派生得到"包含三个'两个 long 对象的数组'的数组"类型。

你可以用复合初始化器来初始化数组，它为每个元素指定一个初始值：

```c
int int_array[3] = {1, foo(), a * 4};
```

还可以用嵌套的复合初始化器初始化多维数组：

```c
long nested_array[3][2] = {{a, a + 1}, {3l, -4}, {foo(), 6}};
```

这里，三个嵌套的复合初始化器分别初始化外层数组的三个元素。这三个元素中的每一个本身都是一个包含两个 long 对象的数组。为其中每个元素准备的嵌套初始化器都指定两个算术值（它们可以隐式转换为 long）。

你也可以让数组保持未初始化。如果它具有自动存储期，其初始值将是未定义的。如果它具有静态存储期，它会被初始化为全零。换句话说，我们对未初始化数组的处理与对未初始化标量对象的处理完全一样。

### 数组到指针的退化

定义并初始化一个数组之后，我们能用它做什么呢？事实证明，做不了多少。实际上，对数组类型的对象只有两种合法操作。第一，我们可以用 sizeof 运算符获取数组的大小，这个我们会在第 17 章实现。第二，我们可以用 `&` 运算符获取它的地址：

```c
int my_array[3] = {1, 2, 3};
int (*my_pointer)[3] = &my_array;
```

就这些！数组再没有其他合法操作了。这听起来可能很荒谬，因为 C 程序时时刻刻都在读写数组元素。这是怎么回事？C 标准（6.3.2.1 节第 3 段）给出了这个谜题的答案："除非它是 sizeof 运算符或一元 `&` 运算符的操作数……类型为'T 的数组'的表达式会被转换为类型为'指向 T 的指针'的表达式，它指向数组对象的初始元素，且不是左值。"

这种从数组到指针的隐式转换称为数组到指针的退化（array-to-pointer decay）。（我有时会说数组退化为指针，有时会说它被隐式转换为指针。这两种说法意思相同。）虽然我们对数组做不了多少事，但对指针可以执行各种有用的操作。其中一些操作我们已经实现了，本章还会再添加几个。

清单 15-3 中的代码片段展示了数组退化的一个例子。

```c
int my_array[3] = {1, 2, 3};
int *my_pointer = ❶ my_array;
return ❷ *my_pointer;
```

*清单 15-3：把数组隐式转换为指针*

假设 my_array 起始于地址 0x10。当 my_array 出现在这个清单中赋值表达式的右侧时，它会被隐式转换为一个类型为 int *、值为 0x10 的指针 ❶。然后我们可以把这个指针的值赋给 my_pointer。当我们解引用 my_pointer 时，结果是存储在 my_array 前 4 个字节中的 int 对象 ❷。因此，我们会返回这个对象的当前值 1。注意，地址 0x10 可以有几种不同的解释方式，取决于它的类型。作为 int *，它指向数组的初始元素，我们可以通过指针解引用操作读或写它。表达式 &my_array 的值同样是 0x10，但它指向整个数组，其类型是 int (*)[3]。

在处理多维数组时，跟踪指针的类型尤其重要。考虑清单 15-4，它试图给两个数组元素赋值。

```c
int nested_array[2][2] = {{1, 2}, {3, 4}};
**nested_array = 10;
*nested_array = 0;
```

*清单 15-4：对数组元素的合法与非法赋值*

第一个赋值表达式（给 **nested_array 赋值）是合法的。首先，我们把变量 nested_array 隐式转换为指向数组初始元素的指针。该元素的类型是 int[2]，所以这个指针的类型是 int(*)[2]。对这个指针的第一次解引用得到一个类型为 int[2] 的数组对象。我们把这个数组隐式转换为 int * 类型的指针。因此，第二次指针解引用产生一个 int 对象，我们可以给它赋值。这个赋值表达式用新值 10 覆盖该对象的当前值 1。这个表达式中的 int(*)[2] 指针和 int * 指针都指向 nested_array 的起点；只有类型不同。

下一个赋值表达式（给 *nested_array 赋值）是非法的。它一开始和前面一样：我们把 nested_array 隐式转换为 int(*)[2] 类型的指针，解引用它，再把结果隐式转换为 int * 类型的指针。然后我们试图直接给这个指针赋值，但 C 标准指出这个隐式转换的结果"不是左值"，所以我们不能给它赋值。即使允许，也不清楚这个赋值会做什么；这就像给 `&` 操作的结果赋值一样。

现在我们知道如何访问数组在任意维度上的初始元素了。我们甚至可以读写数组中的初始标量对象。然而，我们通常还想访问数组中的其他元素。为此，我们需要指针算术。

### 用指针算术访问数组元素

一旦有了指向数组初始元素的指针，我们就可以用指针加法产生指向其他元素的指针。让我们走一遍清单 15-5 中的例子。

```c
int array[3] = {1, 2, 3};
int *ptr = array + 1;
```

*清单 15-5：用指针算术访问靠后的数组元素*

我们仍然用 0x10 作为数组的起始地址。在表达式 array + 1 中，变量 array 照常退化为指向数组初始元素的指针。当我们给这个指针加 1 时，结果是指向数组中下一个 int 元素的指针。由于每个 int 是 4 字节，我们需要把 1 乘以 4 的比例因子（scale factor）来计算要给 array 的地址加上多少字节。结果指针的值是 0x14。如果我们解引用这个指针，会得到地址 0x14 处的 int 对象，其当前值是 2。数组元素的下标（index）从零开始，所以我们说 array 的初始元素位于下标 0，下一个元素位于下标 1。

更一般地，当我们给指针加一个整数 n 时，结果是指向数组中再往后 n 个位置处另一个元素的指针。类似地，我们可以通过减去一个整数（或加上一个负整数）在数组中向前移动。如果结果在任何方向上超出数组边界，行为就是未定义的。

**注意**

如果 x 是一个含 n 个元素的数组，x + n 指向 x 末尾再往后一个的位置。这个指针是一个特例。它不算越界，而且你可以在指针算术中使用它。例如，你可以把它与指向同一数组中元素的其他指针相比较。（在循环遍历数组元素时，这是检验是否到达末尾的一种有用方式。）但解引用它是未定义行为，因为它并不指向数组中的任何元素。

进行指针算术时，我们所指向的数组的嵌套结构很重要，因为它决定了什么算作一个元素。让我们看看清单 15-6，看看这一点如何在我们于清单 15-1 和清单 15-2 中定义的那两个数组（它们在内存中的内容完全相同）上体现出来。

```c
int six_ints[6] = {1, 2, 3, 4, 5, 6};
int three_arrays[3][2] = {{1, 2}, {3, 4}, {5, 6}};
❶ int *int_ptr = six_ints + 1;
❷ int (*array_ptr)[2] = three_arrays + 1;
```

*清单 15-6：对扁平数组与嵌套数组做指针算术*

表达式 six_ints + 1 的结果是指向 six_ints 中下标 1 处元素的指针 ❶。这个元素是值为 2 的 int。类似地，计算 three_arrays + 1 时，我们得到指向 three_arrays 中下标 1 处元素的指针 ❷。但在后一个例子中，这个元素本身是一个包含两个 int 对象的数组，其当前值是 3 和 4。尽管 six_ints 和 three_arrays 在内存中的内容可能完全相同，对它们执行同一个操作产生的结果却大相径庭。

那么，我们怎样才能访问 three_arrays 中的标量对象呢？比如，怎样才能读出这个数组中最后一个 int（值为 6）？首先，我们取得指向 three_arrays 中最后一个元素的指针：

```c
int (*outer_ptr)[2] = three_arrays + 2;
```

它指向整个两元素数组 {5, 6}。我们解引用它，转而得到指向该数组中单个标量元素的指针：

```c
int *inner_ptr = *outer_ptr;
```

这个解引用表达式的结果是一个 int[2] 类型的数组，它退化为 int * 类型的指针。现在 inner_ptr 指向这个嵌套数组中的第一个 int，值为 5。我们让它递增，指向下一个 int，值为 6：

```c
inner_ptr = inner_ptr + 1;
```

此时，我们可以用普通的指针解引用访问它的值：

```c
int result = *inner_ptr;
```

我们可以把这些语句合并成清单 15-7 中的单个表达式。

```c
int result = *(*(three_arrays + 2) + 1);
```

*清单 15-7：访问 three_arrays 中的最后一个 int*

通过反复的指针加法、解引用和从数组到指针的隐式转换，我们可以访问多维数组中的任何元素。这显然是件极其麻烦的事。下标运算符 `[]` 为完成同样的事情提供了更方便的语法。表达式 a[i] 等价于 *(a + i)，所以我们可以把清单 15-7 改写为清单 15-8。

```c
int result = three_arrays[2][1];
```

*清单 15-8：一种更方便的访问 three_arrays 中最后一个 int 的方式*

我想强调的最后一点是：下标和指针算术适用于所有指针，而不只是从数组退化而来的指针。如果被指向的对象不在数组中，我们就把它当作单元素数组中唯一的元素。例如，清单 15-9 完全合法。

```c
int a = 5;
int *ptr = &a;
return ptr[0] == 5;
```

*清单 15-9：对指向标量对象的指针做下标操作*

当我们给 ptr 加 0 并解引用结果时，取回的是对象 a。因此，表达式 ptr[0] == 5 的求值结果为 1（即真）。

### 更多指针运算

我们还将支持指针上的另外两种操作。第一种是减法；清单 15-10 给出了一个例子。

```c
int arr[3] = {1, 2, 3};
int *ptr = arr + 2;
return ptr - arr;
```

*清单 15-10：两个指针相减*

当我们把指向同一数组中两个元素的指针相减时，结果是它们下标之差。在这个例子中，我们不出所料地返回 2。

我们还可以比较指向数组元素的指针，比如清单 15-11。

```c
int arr[3] = {1, 2, 3};
int *ptr = arr + 2;
return ptr > arr;
```

*清单 15-11：比较指针*

指向数组中下标较大的元素的指针，大于指向下标较小元素的指针。在这个例子中，ptr 指向下标 2 处的元素，arr 退化为指向下标 0 处元素的指针，所以比较 ptr > arr 的求值结果为 1。如果两个指针不指向同一个数组，把它们相减或比较的结果是未定义的。

### 函数声明中的数组类型

函数返回数组是非法的，比如下面这个声明：

```c
int foo(void)[3];
```

函数也不能把数组作为形参。奇怪的是，C 标准允许你声明带有数组形参的函数，但它要求编译器把你的函数签名调整为接受指针。例如，声明

```c
int foo(int array_of_three_elements[3]);
```

会被改成：

```c
int foo(int *array_of_three_elements);
```

我们会在类型检查器中把具有数组类型的形参调整为相应的指针类型。

**"这是出于历史原因"**

可以声明数组类型的函数形参、却让编译器把它们当指针对待，这一点毫无道理可言。我当初了解到这个行为时，就觉得它既让人困惑又毫无用处。每当我遇到一个讲不通的 C 特性，我都会假设它是出于历史原因。在这个例子中，事实果然如此！Dennis Ritchie 在他的论文《C 语言的发展》（"The Development of the C Language"，ACM，1993）中谈到了这一点。他指出，在 int a[] 这样的形参声明中，数组声明器 [] 是"一块活化石。……这种表示法能幸存下来，部分是为了兼容性，部分是基于这样一个理由：它能让程序员向读者传达一个意图——传的是由数组生成的指针，而不是对单个整数的引用。不幸的是，它在提醒读者的同时，也同样地让学习者困惑。"

这篇论文更详细地介绍了 C 的指针和数组语义如何随时间演变；你可以在 https://www.bell-labs.com/usr/dmr/www/chist.html 读到它。

### 我们不实现的功能

我们不支持的特性足够重要，值得明确提一提。我们不会实现变长数组（variable-length array）——长度在运行时确定的数组，比如这个：

```c
int variable_length_array[x];
```

我们只允许常量作为数组声明中的维度。我们也不允许不完整数组类型（incomplete array type）的声明：

```c
int array[];
```

C 要求你在定义数组时指定其维度，但在声明时不需要。不过，我们会要求在声明和定义中都给出数组维度。

我们不会实现复合字面量（compound literal），它让你能在初始化器之外构造数组对象（以及其他聚合对象）：

```c
int *p = (int []){2, 4};
```

最后，我们不会完整支持 C 对初始化聚合对象的语义。复合初始化器有点随心所欲：你可以省略花括号、把标量值包在花括号里、或者只初始化一部分元素而留下另一部分。这使得弄清哪个表达式应该初始化哪个元素变得很棘手。我们会采取严格得多的做法。首先，我们要求每个嵌套数组的初始化器都带花括号。换句话说，我们会接受声明

```c
int arr[2][2] = {{1, 2}, {3, 4}};
```

但会拒绝下面这个等价的声明，尽管 C 标准允许它：

```c
int arr[2][2] = {1, 2, 3, 4};
```

我们也会拒绝给标量初始化器加花括号，比如下面这个例子：

```c
int i = {3};
```

而且我们不支持指派符（designator）——它让你能不按顺序初始化元素：

```c
int arr[3] = {0, [2] = 1};
```

不过，我们允许复合初始化器不初始化数组的每个元素，比如下面这个：

```c
int arr[3] = {1, 2};
```

在这种情况下，我们会把其余元素补零；这是 C 标准要求的行为。既然已经明确了我们做什么、不做什么，接下来就可以进入词法分析器了。

## 解析器

接下来，我们要把数组类型、下标表达式和复合初始化器加入 AST。数组的类型指明数组中元素的个数和这些元素的类型：

```text
type = --snip-- | Array(type element, int size)
```

我们可以嵌套 Array 构造器来指定多维数组。例如，我们会把声明

```c
int x[3][4];
```

的类型表示为 Array(Array(Int, 4), 3)。由于我们不支持变长数组，每个数组类型都必须有常量大小。

下标表达式包含两个子表达式：一个指针和一个下标：

```text
exp = --snip--
    | Subscript(exp, exp)
```

出人意料的是，这两个子表达式出现的顺序无关紧要；表达式 x[1] 和 1[x] 是等价的。

最后，我们要添加一个初始化器构造，同时支持标量变量初始化器和复合变量初始化器：

```text
initializer = SingleInit(exp) | CompoundInit(initializer*)
```

*清单 15-14：表示数组声明器*

接下来，我们把数组声明器加入文法。由于它们的优先级高于指针声明器，它们属于 `<direct-declarator>` 文法规则：

```text
<direct-declarator> ::= <simple-declarator> [<declarator-suffix>]
<declarator-suffix> ::= <param-list> | {"[" <const> "]"}+
```

直接声明器是一个简单声明器加一个可选后缀：要么是一个带括号的函数形参列表，要么是一系列形如 [const] 的常量数组维度。每个 ArrayDeclarator 只指定一个数组维度，所以我们会把带多个维度的 `<declarator-suffix>` 解析为一系列嵌套的 ArrayDeclarator 节点。例如，我们会把声明器 array[1][2] 解析为：

```text

```

`<declarator-suffix>` 的文法规则允许浮点常量作为数组维度，但 C 标准要求数组维度是整数。解析 `<declarator-suffix>` 时，你应该拒绝浮点常量、接受任何整数类型的常量。C 标准还要求数组维度大于零，不过 Clang 和 GCC 作为语言扩展支持零长度数组。接受还是拒绝零长度数组由你决定；测试套件不覆盖这种情况。


这条规则很直接：初始化器要么是一个表达式，要么是一个花括号包围的一个或多个嵌套初始化器的列表。注意，初始化器列表的最后一个元素后面可以有一个尾逗号：{1, 2, 3} 和 {1, 2, 3,} 都是合法的复合初始化器。

### 解析下标表达式

最后一个需要解析的新语言特性是下标运算符。下标是一个后缀运算符，跟在它所修饰的表达式后面。后缀运算符的优先级高于 `&`、`-`、`~` 这样的前缀运算符。我们要拆分 `<factor>` 文法规则来体现这种优先级差异。在最高优先级，我们有常量、变量、带括号的表达式和函数调用：

```text
<primary-exp> ::= <const> | <identifier> | "(" <exp> ")"
                | <identifier> "(" [<argument-list>] ")"
```

然后，我们把后缀表达式定义为一个主表达式、可选地跟着一串下标运算符的表达式：

```text
<postfix-exp> ::= <primary-exp> {"[" <exp> "]"}
```

每个下标运算符都是一个放在方括号中的表达式。最后，我们定义一元表达式，它同时涵盖前缀运算符和强制转换：

```text
<unary-exp> ::= <unop> <unary-exp>
              | "(" {<type-specifier>}+ [<abstract-declarator>] ")" <unary-exp>
              | <postfix-exp>
```

## 类型检查器

在本章中，类型检查器将承担大部分繁重工作。它将为下标表达式和指针算术表达式添加类型信息；校验复合初始化器的维度；并检测类型错误，比如把表达式强制转换为数组类型。它还会处理从数组类型到指针类型的隐式转换。正如我们通过向 AST 中插入 Cast 表达式来使隐式类型转换显式化一样，我们将插入 AddrOf 表达式来使从数组到指针的转换显式化。

### 把数组转换为指针

我们会把任何数组类型的表达式都转换为指针，除非它已经是某个 AddrOf 表达式的操作数。这听起来可能很耳熟：上一章我们对每个表达式的结果做左值转换，除了取它的地址或给它赋值的时候。在第 14 章，我们引入了一个新的 emit_tacky_and_convert 辅助函数来管理左值转换；现在我们将在另一个编译器遍（pass）中使用类似的设计模式。我们将定义一个新的 typecheck_and_convert 函数，如清单 15-19 所示。

```text
typecheck_and_convert(e, symbols):
    typed_e = typecheck_exp(e, symbols)
    match get_type(typed_e) with
    | Array(elem_t, size) ->
        addr_exp = AddrOf(typed_e)
        return set_type(addr_exp, Pointer(elem_t))
    | _ -> return typed_e
```

*清单 15-19：把数组隐式转换为指针*

如果一个表达式具有数组类型，我们就插入一个 AddrOf 操作来取得它的地址。然后我们记录它的结果类型，即指向数组元素类型的指针。这与我们从显式 `&` 运算符得到的结果类型不同，后者总是生成指向其操作数类型的指针。看下面这个声明：

```c
int arr[3];
```

表达式 &arr 的类型是 int (*)[3]。而表达式 arr 的类型是 int *。在类型检查后的 AST 中，我们用 AddrOf 表示取得一个对象地址的两种方式，它们产生不同的结果类型：一种经由隐式转换，一种经由显式 `&` 运算符。

引入 typecheck_and_convert 之后，我们会用它代替 typecheck_exp 来检查子表达式和完整表达式。唯一的例外是 AddrOf 操作数的类型检查。这个操作数不应该从数组转换为指针，所以我们将继续直接调用 typecheck_exp 来处理它。

### 校验左值

我们要对校验左值的方式做两处改动。第一，除了 Var 和 Dereference 之外，我们还应把 Subscript 表达式识别为左值。

第二，我们需要拒绝试图给数组赋值的赋值表达式。数组一旦退化为指针，就不再是左值，不能被赋值。为了捕获这些非法的赋值表达式，我们要先用 typecheck_and_convert 处理左操作数，再检查它是不是左值。清单 15-20 展示了类型检查赋值表达式的最新逻辑。

```text
typecheck_exp(e, symbols):
    match e with
    | --snip--
    | Assignment(left, right) ->
        typed_left = typecheck_and_convert(left, symbols)
        if typed_left is not an lvalue:
            fail("Tried to assign to non-lvalue")
        typed_right = typecheck_and_convert(right, symbols)
        --snip--
```

*清单 15-20：类型检查赋值表达式*

如果左操作数是数组，typecheck_and_convert 会把它包在一个 AddrOf 操作里。然后，由于 AddrOf 不是左值，类型检查器会抛出一个错误。

### 指针算术的类型检查

接下来，我们要扩展加法、减法和关系运算符，使它们能用于指针。给指针加上任何整数类型的值都是合法的。清单 15-21 演示了如何对加法做类型检查。

```text

        typed_e1 = typecheck_and_convert(e1, symbols)
        typed_e2 = typecheck_and_convert(e2, symbols)

        t2 = get_type(typed_e2)

            --snip--
        else if t1 is a pointer type and t2 is an integer type:
          ❶ converted_e2 = convert_to(typed_e2, Long)
            add_exp = Binary(Add, typed_e1, converted_e2)
          ❷ return set_type(add_exp, t1)
      ❸ else if t2 is a pointer type and t1 is an integer type:
            --snip--

```

*清单 15-21：类型检查指针加法*

对涉及一个指针和一个整数的加法做类型检查时，我们首先把整数操作数转换为 long ❶。这会简化后面的编译器遍，因为指针下标需要是 8 字节宽，我们才能把它们加到 8 字节的内存地址上。这个转换并非来自 C 标准；我们只是为了自己的方便而添加它。但它也不违反标准；把一个合法的数组下标转换为 long 不会改变它的值，所以整个表达式的结果在两种情况下都相同。（如果一个整数大到无法表示为 long，我们可以放心地假设它不是合法的数组下标，因为没有任何硬件支持元素数量接近 2^63 个的数组。）

指针加法的结果与指针操作数具有相同的类型 ❷。无论第一个还是第二个操作数是指针，我们使用的都是同一套逻辑，所以我省略了后一种情况的伪代码 ❸。最后，除了指针加整数或两个算术操作数相加之外的任何情况，我们都抛出一个错误。

从指针中减去一个整数的处理方式相同：我们把整数操作数转换为 long，并给结果标注与指针操作数相同的类型。唯一的区别在于操作数的顺序有讲究。你可以从指针中减去一个整数，但不能从整数中减去一个指针。

当我们把一个指针从另一个指针中减去时，两个操作数的类型必须相同，结果则具有一个由实现定义的有符号整数类型。我们在这里用 long 作为结果类型，这是 64 位系统上的惯例。这个类型本应在 <stddef.h> 头文件中被别名为 ptrdiff_t，以帮助用户写出更可移植的代码。由于我们不支持 typedef，因而无法编译 <stddef.h>，我们将忽略这一要求。

```text
            --snip--
```

*清单 15-22：类型检查指针减法*

如果表达式从指针中减去一个整数，我们像对待指针加法那样处理它 ❶。如果它把两个相同类型的指针相减，我们把 long 记录为结果类型 ❷。在任何其他情况下——表达式把两个不同类型的指针相减、从指针中减去 double、或者从算术值中减去指针——我们都会抛出错误。

最后来看 <、<=、> 和 >= 运算符。它们每一个都接受两个相同类型的指针操作数并返回一个 int。这些情况做类型检查非常简单，所以我不提供伪代码。

注意，这些运算符都不接受空指针常量；它们比较的是指向同一个数组中元素的指针，而空指针按定义不指向任何数组元素。基于同样的逻辑，你不能从空指针常量中减去一个指针。如果 x 是指针，表达式 x == 0 和 x != 0 是合法的，但 0 - x、0 < x 和 x >= 0 不合法。（Clang 和 GCC 在这方面比标准更宽松；作为语言扩展，它们都允许你对任何关系运算符使用空指针常量。有了这个扩展，任何非空指针与空指针常量比较的结果都是大于。）

### 下标表达式的类型检查

下标表达式的一个操作数必须是指针，另一个必须是整数。指针的引用类型（referenced type）就是结果类型。记住，这两个操作数可以以任意顺序出现；我们不能假定指针一定是第一个操作数。清单 15-23 展示了如何对下标表达式做类型检查。

```text

        typed_e1 = typecheck_and_convert(e1, symbols)
        typed_e2 = typecheck_and_convert(e2, symbols)
        t1 = get_type(typed_e1)
        t2 = get_type(typed_e2)
      ❶ if t1 is a pointer type and t2 is an integer type:
            ptr_type = t1
          ❷ typed_e2 = convert_to(typed_e2, Long)
        else if t1 is an integer type and t2 is a pointer type:
            ptr_type = t2
            typed_e1 = convert_to(typed_e1, Long)

        subscript_exp = Subscript(typed_e1, typed_e2)
      ❸ return set_type(subscript_exp, ptr_type.referenced)
```

*清单 15-23：类型检查下标表达式*

首先，我们验证一个操作数是指针、另一个是整数 ❶。然后我们把整数操作数转换为 long ❷。最后，我们用指针的引用类型为整个表达式做标注 ❸。

### 强制转换表达式的类型检查

这个很简单：你不能把表达式强制转换为数组类型。例如，表达式


是非法的，应当产生一个类型错误。

### 函数声明的类型检查

处理函数声明时，我们既要考虑它的返回类型，也要考虑它的形参类型。如果函数返回数组类型，我们抛出一个错误。如果它的任何形参具有数组类型，我们把它调整为指针类型。清单 15-24 描述了如何校验并隐式调整函数类型。

```text
typecheck_function_declaration(decl, symbols):
    if decl.fun_type.ret is an array type:
        fail("A function cannot return an array!")
    adjusted_params = []
    for t in decl.fun_type.params:
        match t with
        | Array(elem_t, size) ->
            adjusted_type = Pointer(elem_t)
            adjusted_params.append(adjusted_type)
        | _ -> adjusted_params.append(t)
    decl.fun_type.params = adjusted_params
    --snip--
```

*清单 15-24：调整函数声明中的数组类型*

你应当把这段逻辑加在 typecheck_function_declaration 的最前面，以便在检查函数是否与同一标识符的先前定义冲突之前，先调整函数的形参类型。你还应确保符号表和 AST 节点本身都使用调整后的形参类型。

### 复合初始化器的类型检查

我们需要为每个初始化器标注类型，并在初始化器与它要初始化的对象的类型不兼容时发出错误。要对复合初始化器做类型检查，我们先验证它初始化的对象是一个数组。然后，我们递归地对每个嵌套初始化器做类型检查，验证它与数组的元素类型兼容。清单 15-25 展示了这一方法。

```text
typecheck_init(target_type, init, symbols):
    match target_type, init with
    | _, SingleInit(e) -> ❶
        typechecked_exp = typecheck_and_convert(e, symbols)
        cast_exp = convert_by_assignment(typechecked_exp, target_type)
        return set_type(SingleInit(cast_exp), target_type)
    | Array(elem_t, size), CompoundInit(init_list) -> ❷
        if length(init_list) > size:
            fail("wrong number of values in initializer") ❸
        typechecked_list = []
        for init_elem in init_list:
            typechecked_elem = typecheck_init(elem_t, init_elem, symbols) ❹
            typechecked_list.append(typechecked_elem)
        while length(typechecked_list) < size:
            typechecked_list.append(zero_initializer(elem_t)) ❺
        return set_type(CompoundInit(typechecked_list), target_type) ❻
    | _ -> fail("can't initialize a scalar object with a compound initializer") ❼
```

*清单 15-25：类型检查初始化器*

在基础情形中，初始化器是单个表达式 ❶。我们对这个表达式做类型检查，然后调用我们在第 14 章定义的 convert_by_assignment 把它转换为目标类型。如果它与目标类型不兼容，convert_by_assignment 会抛出一个错误（这包括目标类型是数组类型的情况）。

在递归情形中，我们用复合初始化器初始化一个数组 ❷。列表中的每一项将初始化数组中的一个元素。首先，我们检查列表没有包含过多的元素 ❸。然后，我们递归地对每个列表项做类型检查，用数组的元素类型作为目标类型 ❹。如果初始化器列表包含的元素太少，我们用零来填充 ❺。我们将使用 zero_initializer 辅助函数（我没有为它提供伪代码）来产生可以加入初始化器列表的零值初始化器。给定一个标量类型，zero_initializer 应当返回一个该类型的、值为 0 的 SingleInit。给定一个数组类型，它应当返回一个 CompoundInit，其标量元素（可能嵌套好几层）的值都是 0。例如，对类型 UInt 调用 zero_initializer 应当返回

```text
SingleInit(Constant(ConstUInt(0)))
```

而对类型 Array(Array(Int, 2), 2) 调用应当返回：

```text
CompoundInit([
    CompoundInit([SingleInit(Constant(ConstInt(0))),
                  SingleInit(Constant(ConstInt(0)))]),
    CompoundInit([SingleInit(Constant(ConstInt(0))),
                  SingleInit(Constant(ConstInt(0)))])
])
```

建好完成类型检查的初始化器列表之后，我们把它打包成一个 CompoundInit，并给它标注目标类型 ❻。如果初始化器不是单个表达式、而目标类型又不是数组类型，那么我们就是在尝试用复合初始化器初始化一个标量对象，因此抛出一个错误 ❼。

### 初始化静态数组

与其他静态变量一样，我们把静态数组的初始值存储在符号表中。我们需要更新用来表示这些初始值的数据结构。我们将把每个对象的初始化器表示为一个标量值的列表：

```text
initial_value = Tentative | Initial(static_init* init_list) | NoInitializer
```

对标量对象来说，init_list 将只有一个元素。声明

```c
static int a = 3;
```

将具有这个初始化器：

```text
Initial([IntInit(3)])
```

对多维数组，我们会把所有嵌套结构展平。因此，声明

```c
static int nested[3][2] = {{1, 2}, {3, 4}, {5, 6}};
```

将具有这个初始化器：

```text
Initial([IntInit(1),
         IntInit(2),
         IntInit(3),
         IntInit(4),
         IntInit(5),
         IntInit(6)])
```

接下来，我们添加一个 static_init 构造器来表示任意大小的清零对象：

```text
static_init = IntInit(int) | LongInit(int) | UIntInit(int) | ULongInit(int)
            | DoubleInit(double) | ZeroInit(int bytes)
```

ZeroInit 的 bytes 实参指定要把多少个字节初始化为零。如果静态数组只被部分初始化，我们会用 ZeroInit 补齐所有未初始化的元素。例如，声明

```c
static int nested[3][2] = {{100}, {200, 300}};
```

将具有这个初始化器：

```text
Initial([IntInit(100),
         ZeroInit(4),
         IntInit(200),
         IntInit(300),
         ZeroInit(8)])
```

这个初始化器列表的第二个元素 ZeroInit(4) 初始化位于 nested[0][1] 的 int；最后一个元素 ZeroInit(8) 初始化嵌套数组 nested[2] 的两个元素。

更新完 initial_value 和 static_init 数据结构之后，编写一个把复合初始化器转换为 static_init 列表的函数。你需要校验静态数组的初始化器具有正确的大小和结构，就像校验非静态数组的初始化器一样；你应当拒绝元素过多的初始化器、给数组准备标量初始化器的情况，以及给标量对象准备复合初始化器的情况。这个转换我不会提供伪代码，因为它与清单 15-25 中我们对非静态初始化器做类型检查的方式类似。

### 用 ZeroInit 初始化标量变量

你也可以用 ZeroInit 把标量变量初始化为零。比如，给定声明

```c
static long x = 0;
```

你可以使用这个初始化器：

```text
Initial([ZeroInit(8)])
```

在这里使用 ZeroInit 是可选的，但它让代码发射更简单，因为你可以轻松分辨哪些初始化器属于 .data、哪些属于 .bss。只是要小心用 ZeroInit 初始化 double 的情况；只有当你确定该 double 的初始值是 0.0 而不是 -0.0 时，才使用它。

## TACKY 生成

为了适应指针算术和复合初始化器，我们要对 TACKY 中间表示（IR）做一些修改。首先，由于我们改变了符号表中初始化器的表示方式，我们要在 TACKY 中做出相应的修改：

```text
top_level = Function(identifier, bool global, identifier* params, instruction* body)
          | StaticVariable(identifier, bool global, type t, static_init* init_list)
```

我们还将引入一条新指令来支持指针算术：

```text
AddPtr(val ptr, val index, int scale, val dst)
```

我们将用这条指令给指针加上或减去一个整数，但不用它来把两个指针相减。scale 操作数是 ptr 所指数组中每个元素的大小（以字节计）。例如，如果 ptr 是 int *，scale 操作数就是 4，因为一个 int 是 4 字节。如果 ptr 是 int (*)[3]——指向一个包含三个 int 对象的数组的指针——那么 scale 就是 12。index 操作数告诉我们从基指针向前或向后移动多少个元素。在运行时，程序会把 index 乘以 scale，以确定要给基指针加上多少字节。用现有的乘法和加法 TACKY 指令来实现指针算术是可能的。不过，在这里引入一条专用的 AddPtr 指令将帮助我们利用 x64 架构对指针算术的内置支持。

我们还要再引入一条指令来支持复合初始化器：

```text
CopyToOffset(val src, identifier dst, int offset)
```

在这条指令中，src 是一个标量值，dst 是某个聚合类型变量的名字，offset 指定 dst 的起点与我们应把 src 拷贝到的位置之间相距的字节数。需要注意的是，dst 指定的是一个数组，而不是指向数组元素的指针。换句话说，CopyToOffset 不使用 dst 的值；它把 dst 用作标识一个在内存中具有固定位置的对象。因为这条指令直接操作数组而非指针，它适用于数组初始化，但不适用于下标操作。在第 18 章，我们还会用它来初始化和更新结构。

清单 15-26 展示了更新后的 TACKY IR，本章的改动以粗体标出。

```text
program = Program(top_level*)
top_level = Function(identifier, bool global, identifier* params, instruction* body)
          | StaticVariable(identifier, bool global, type t, static_init* init_list)
instruction = Return(val)
            | SignExtend(val src, val dst)
            | Truncate(val src, val dst)
            | ZeroExtend(val src, val dst)
            | DoubleToInt(val src, val dst)
            | DoubleToUInt(val src, val dst)
            | IntToDouble(val src, val dst)
            | UIntToDouble(val src, val dst)
            | Unary(unary_operator, val src, val dst)
            | Binary(binary_operator, val src1, val src2, val dst)
            | Copy(val src, val dst)
            | GetAddress(val src, val dst)
            | Load(val src_ptr, val dst)
            | Store(val src, val dst_ptr)
            | AddPtr(val ptr, val index, int scale, val dst)
            | CopyToOffset(val src, identifier dst, int offset)
            | Jump(identifier target)
            | JumpIfZero(val condition, identifier target)
            | JumpIfNotZero(val condition, identifier target)
            | Label(identifier)
            | FunCall(identifier fun_name, val* args, val dst)
val = Constant(const) | Var(identifier)
unary_operator = Complement | Negate | Not
binary_operator = Add | Subtract | Multiply | Divide | Remainder | Equal | NotEqual
                | LessThan | LessOrEqual | GreaterThan | GreaterOrEqual
```

*清单 15-26：向 TACKY IR 添加数组支持*

有了这些添加，我们就能实现本章的每个新运算符和构造。让我们逐一处理。

### 指针算术

我们将用一条 AddPtr 指令实现指针算术表达式 <ptr> + <int>，如清单 15-27 所示。

```text
<instructions for ptr>
p = <result of ptr>
<instructions for int>
i = <result of int>
result = AddPtr(p, i, <size of referenced type of ptr>)
```

*清单 15-27：在 TACKY 中给指针加一个整数*

关于这个清单有几点需要注意。第一，AddPtr 指令的第一个操作数总是指针，第二个操作数总是整数，无论原始表达式中哪个在前。第二，你需要在编译期计算指针的引用类型的大小，因为 scale 操作数是一个常量而不是一个 TACKY 值。

从指针减去一个整数的 TACKY 几乎完全相同；我们只是在把索引放进 AddPtr 之前先对它取负。我们会把 <ptr> - <int> 转换为清单 15-28 中的 TACKY。

```text
<instructions for ptr>
p = <result of ptr>
<instructions for int>
i = <result of int>
j = Unary(Negate, i)
result = AddPtr(p, j, <size of referenced type of ptr>)
```

*清单 15-28：在 TACKY 中从指针减去一个整数*

把一个指针从另一个指针中减去的工作方式稍有不同。首先，我们用一条普通的 Subtract 指令计算字节差。然后，我们把这个结果除以一个数组元素包含的字节数，以按数组下标计算两个指针之间的差。换句话说，我们会把 <ptr1> - <ptr2> 转换为清单 15-29 中的 TACKY。

```text
<instructions for ptr1>
p1 = <result of ptr1>
<instructions for ptr2>
p2 = <result of ptr2>
diff = Binary(Subtract, p1, p2)
result = Binary(Divide, diff, <size of referenced type of ptr1>)
```

*清单 15-29：在 TACKY 中把两个指针相减*

我们会在编译期计算引用类型的大小。这里你可以使用任何一个操作数的类型，因为类型检查器已经校验过它们两者的类型相同。

我们比较指针的方式与比较算术值完全一样，使用 LessThan、LessOrEqual、GreaterThan 和 GreaterOrEqual 运算符。

### 下标操作

按照 C 标准，下标表达式 <ptr>[<int>] 等价于 *(<ptr> + <int>)。因此，要实现下标表达式，我们生成清单 15-27 中指针加法的 TACKY，但向调用者返回 DereferencedPointer(result) 而不是 PlainOperand(result)。在这里生成正确的 TACKY 很简单，但理解它为什么可行——尤其是对多维数组——就稍微复杂一些。为了进一步探究，让我们走一遍清单 15-30 中的例子。

```c
int arr[3][4];
--snip--
return arr[i][j];
```

*清单 15-30：返回一个下标运算符的结果*

清单 15-31 展示了这个例子中 return 语句的 TACKY 实现。

```text
❶ tmp0 = GetAddress(arr)
tmp1 = AddPtr(tmp0, i, 16)
tmp2 = AddPtr(tmp1, j, 4)
❷ tmp3 = Load(tmp2)
Return(tmp3)
```

*清单 15-31：用 TACKY 实现清单 15-30*

首先，我们发射一条 GetAddress 指令来取得指向 arr 中第一个元素的指针。然后，我们发射两条 AddPtr 指令来计算指向数组元素 arr[i][j] 的指针。最后，我们用一条 Load 指令把该数组元素的当前值读入一个临时变量，并将其返回。清单 15-31 很高效，没有任何多余的指令。我们之前看到，数组下标要求我们反复取得数组元素的地址、执行指针算术、再解引用结果。但在这个清单中，我们只在开头取得一次数组的地址 ❶，只在末尾用一条 Load 指令解引用一次指针 ❷。我们的 TACKY 生成策略是如何产生这个结果的？

清单 15-32 给出了清单 15-30 中 return 语句的 AST。让我们弄清楚这个 AST 中的每个子表达式是如何转换为 TACKY 的。

```text
❶ Return(
  ❷ Subscript(
      ❸ AddrOf(
          ❹ Subscript(
              ❺ AddrOf(Var("arr")),
                Var("i")
            )
        ),
        Var("j")
    )
)
```

*清单 15-32：清单 15-30 的 AST*

这个 AST 包含我们在类型检查期间插入的两个 AddrOf 表达式。内层的那个 ❺ 取得 arr 的地址，外层的那个 ❸ 取得 arr[i] 的地址。当然，arr、i 和 j 在标识符解析期间会被重命名，但在这个例子（以及本章后面的例子）中，我们将忽略这个细节。

与往常一样，我们按后序把这个 AST 转换为 TACKY，在处理每个表达式本身之前先处理它的操作数。我们处理的第一个非叶 AST 节点是内层的 AddrOf 表达式，它取 arr 的地址 ❺。我们把它转换为一条 GetAddress 指令：

```text
tmp0 = GetAddress(arr)
```

接下来，为实现内层的 Subscript 表达式 ❹，我们发射一条 AddPtr 指令：

```text
tmp1 = AddPtr(tmp0, i, 16)
```

这里的比例是 16，因为 tmp0 指向一个包含四个 int 的数组。下标操作的第二部分是解引用结果，所以我们向调用者返回 DereferencedPointer(tmp1)。

在调用者中，我们处理外层的 AddrOf 表达式 ❸。当我们对一个已解引用的指针取地址时，这两个操作会相互抵消。因此，我们返回 PlainOperand(tmp1) 作为这个表达式的结果，而不发射任何更多指令。

现在处理外层的 Subscript 表达式 ❷。我们再次发射一条 AddPtr 指令：

```text
tmp2 = AddPtr(tmp1, j, 4)
```

然后我们向调用者返回 DereferencedPointer(tmp2)。因为这个 Subscript 表达式出现在 Return 语句 ❶ 中，而不是 AddrOf 或赋值表达式中，我们对这个结果做左值转换。这意味着我们发射一条 Load 指令：

```text
tmp3 = Load(tmp2)
```

现在 tmp3 包含整个表达式经过左值转换的结果，所以我们返回它：

```text
Return(tmp3)
```

正如这个例子所展示的，当我们对多维数组做下标操作时，解引用操作和隐式的地址加载会相互抵消，不会产生任何多余的指令。因此，在到达标量数组元素之前，任何下标和解引用运算符在 TACKY 中都归结为纯指针算术，不带任何 Load 或 Store 指令。

### 复合初始化器

要处理复合初始化器，我们求值初始化器中的每个标量表达式，并用一条 CopyToOffset 指令把它拷贝到内存中适当的位置。例如，我们会把初始化器

```c
long arr[3] = {1l, 2l, 3l};
```

转换为下面的指令序列：

```text
CopyToOffset(1l, "arr", 0)
CopyToOffset(2l, "arr", 8)
CopyToOffset(3l, "arr", 16)
```

由于 long 是 8 字节，偏移量随每个元素递增 8。即使处理嵌套初始化器，我们也只需要把叶子处的标量值拷贝到正确的内存位置。例如，我们会把

```c
long nested[2][3] = {{1l, 2l, 3l}, {4l, 5l, 6l}};
```

转换为：

```text
CopyToOffset(1l, "nested", 0)
CopyToOffset(2l, "nested", 8)
CopyToOffset(3l, "nested", 16)
CopyToOffset(4l, "nested", 24)
CopyToOffset(5l, "nested", 32)
CopyToOffset(6l, "nested", 40)
```

这个转换非常直接，所以我略去它的伪代码。不过我要指出，你应当使用类型检查器为每个复合初始化器添加的类型信息来计算每个元素的偏移量。

### 数组的暂定定义

回想一下，把符号表条目转换为 StaticVariable 构造时，我们会把暂定定义的变量初始化为零。暂定定义的数组也不例外。你应当使用上一节新增的初始化器 ZeroInit(n) 把一个 n 字节的数组初始化为零。

你也可以用 ZeroInit 初始化暂定定义的标量变量。为保持一致，只有当你在类型检查器中用 ZeroInit 把显式定义的标量变量初始化为零时，才应在这里使用 ZeroInit。

## 汇编生成

本章我们不会引入任何新的汇编指令。不过，我们会引入一种新的内存寻址模式（addressing mode），有时称为索引寻址（indexed addressing）。目前，我们可以用一个寄存器中的基址加一个常量偏移来指定内存操作数，比如 4(%rax)。使用索引寻址，我们可以把基址放在一个寄存器中，把索引放在另一个寄存器中。我们还可以指定一个比例（scale），它必须是常量 1、2、4 或 8 之一。下面是索引寻址实际使用的例子：

```asm
movl    $5, (%rax, %rbx, 4)
```

为了找到这条 movl 指令的目的地址，CPU 会计算 RAX + RBX × 4。然后，它把 4 字节常量 5 存储到这个地址。这种寻址模式对数组访问非常方便。如果 RAX 存放一个 int 对象数组的地址、RBX 存放该数组的下标 i，那么操作数 (%rax, %rbx, 4) 指定的就是下标 i 处的元素。

**把索引寻址用于通用算术**

尽管索引寻址是为指针算术设计的，它也是加法和乘普通整数的高效方式。例如，指令

```asm
lea    (%rax, %rbx, 2), %rax
```

与这些指令产生相同的结果：

```asm
imulq   $2, %rbx
addq    %rbx, %rax
```

我们的编译器只把索引寻址用于指针操作，但其他编译器经常把它用于通用整数算术。

我们将添加一个新操作数来支持索引寻址：

```text
Indexed(reg base, reg index, int scale)
```

我们还要对汇编 AST 做几处其他修改，以帮助后面的后端各遍做好簿记。首先，我们添加另一个操作数来表示尚未分配固定地址的聚合对象：

```text
PseudoMem(identifier, int)
```

PseudoMem 操作数的用途与现有的 Pseudo 操作数类似；它让我们能在为变量分配寄存器或内存位置之前，在汇编中表示它们。区别在于 PseudoMem 表示聚合对象，我们始终会把聚合对象存储在内存中（即使到第 III 部分实现寄存器分配之后也是如此）。而 Pseudo 表示的是有可能存储在寄存器中的标量对象。PseudoMem 操作数还允许我们指定所讨论对象内部的字节偏移。注意，这个操作数中的标识符指定的是一个聚合对象，而不是指向聚合对象的指针。

接下来，我们添加一个新的汇编类型来表示数组。在汇编中，我们把数组当作一块无差别的内存。我们不再需要跟踪这块内存中将存储多少个对象以及这些对象的类型是什么。不过，我们确实关心它的对齐和它占用的空间，以便为它分配栈空间。因此，我们把数组类型转换成一个新的 ByteArray 类型：

```text
assembly_type = Longword | Quadword | Double | ByteArray(int size, int alignment)
```

最后，我们调整静态变量的表示方式。与前面的编译器遍一样，我们用一个 static_init 值的列表（而不是单个值）来初始化静态变量：

```text
StaticVariable(identifier name, bool global, int alignment, static_init* init_list)
```

更新完汇编 AST 之后，我们将更新从 TACKY 到汇编的转换。

### 把 TACKY 转换为汇编

首先，处理数组类型的 TACKY 变量。为了把它们与标量值区分开，我们把它们转换为 PseudoMem 操作数而不是 Pseudo 操作数。例如，如果 arr 是数组，我们会把

```text
GetAddress(Var("arr"), Var("dst"))
```

转换为：

```text
Lea(PseudoMem("arr", 0), Pseudo("dst"))
```

每当我们把一个聚合的 TACKY Var 转换为汇编时，我们都使用偏移 0，以便指定整个对象。

接下来，处理新的 CopyToOffset 和 AddPtr 指令。我们将使用带相应偏移的 PseudoMem 操作数来表示 CopyToOffset 指令的目的地。因此，我们把

```text
CopyToOffset(src, dst, offset)
```

转换为：

```text
Mov(<src type>, src, PseudoMem(dst, offset))
```

我们用一条使用新 Indexed 操作数的 Lea 指令来实现 AddPtr。细节因比例和索引而异。首先，考虑比例是 1、2、4 或 8 的情况。我们把

```text
AddPtr(ptr, index, scale, dst)
```

转换为清单 15-34。

```text
Mov(Quadword, ptr, Reg(AX))
Mov(Quadword, index, Reg(DX))
Lea(Indexed(AX, DX, scale), dst)
```

*清单 15-34：在汇编中实现 AddPtr*

首先，我们把 ptr 和 index 拷贝到寄存器中；我这里用了 RAX 和 RDX，但除了被调用者保存寄存器或我们的暂存寄存器之外的任何寄存器都可以。然后，我们发射一条 Lea 指令来计算 ptr + index * scale，并把结果存入 dst。

AddPtr 的比例可能不是 Indexed 支持的那四个值之一，尤其是在我们对多维数组而不是标量对象的数组做下标时。在这种情况下，我们将用一条单独的指令把比例与索引相乘，如清单 15-35 所示。

```text
Mov(Quadword, ptr, Reg(AX))
Mov(Quadword, index, Reg(DX))
Binary(Mult, Quadword, Imm(scale), Reg(DX))
Lea(Indexed(AX, DX, 1), dst)
```

*清单 15-35：以非标准比例在汇编中实现 AddPtr*

如果索引操作数是常量，我们可以在编译期计算 index * scale，从而省下一条指令。此时，我们只生成清单 15-36 中的两条指令。

```text
Mov(Quadword, ptr, Reg(AX))
Lea(Memory(AX, index * scale), dst)
```

*清单 15-36：以常量索引实现 AddPtr*

接下来，处理指针比较。我们将完全像无符号整数比较那样实现它们，使用无符号条件码：A、AE、B 和 BE。

最后，谈谈数组的对齐要求。有两种情况需要计算数组的对齐：把数组类型的 StaticVariable 从 TACKY 转换为汇编时（汇编中的 StaticVariable 包含一个对齐字段），以及把数组类型的前端符号表条目转换为后端符号表中的相应条目时。后端符号表中每个数组的汇编类型将是具有适当大小和对齐的 ByteArray。大小是数组元素类型的字节大小乘以元素个数。计算对齐的规则就没那么明显了。

如果数组小于 16 字节，它的对齐与其标量元素相同。例如，类型为 int[2] 的数组和类型为 int[2][1] 的数组，对齐都是 4。如果一个数组类型的变量大于等于 16 字节，它的对齐就总是 16，无论它的元素是什么类型。这一要求使得可以用 SSE 指令一次操作多个数组元素。我们不这样使用 SSE 指令，但我们需要与可能这样做的其他目标文件保持 ABI 兼容。

注意，这个对齐要求只适用于变量，不适用于嵌套数组。例如，如果我们声明变量

```c
int nested[3][5];
```

那么 nested 需要从一个 16 字节对齐的地址开始，因为它的总大小是 60 字节。但它的第一个和第二个元素分别从 nested 起点之后的 20 和 40 字节处开始，所以它们不是 16 字节对齐的，尽管这两个元素各自也都大于 16 字节。

接下来，我们要用具体的地址替换 PseudoMem 操作数。

### 替换 PseudoMem 操作数

这个遍不能再叫"伪寄存器替换"了，因为我们还要替换聚合值。就像我们会为 Longword 分配 4 字节栈空间、为 Quadword 分配 8 字节一样，我们会为类型为 ByteArray(size, alignment) 的对象分配 size 字节。照例，我们要把数组的地址向下舍入到适当的对齐。

一旦数组被分配了内存地址，我们就替换引用它的所有 PseudoMem 操作数。PseudoMem 操作数包含一个相对数组起点的偏移，而数组的具体地址包含一个相对 RBP 中地址的偏移。我们把这两个偏移相加，构造出新的具体内存地址。例如，假设我们遇到下面这条指令：

```text
Mov(Longword, Imm(3), PseudoMem("arr", 4))
```

假设我们之前给 arr 分配的栈地址是 -12(%rbp)。我们计算 -12 + 4，得出新的具体操作数是 -8(%rbp)。然后相应地改写这条指令：

```text
Mov(Longword, Imm(3), Memory(BP, -8))
```

要访问具有静态存储期的数组，我们使用现有的 Data 操作数。如果 arr 是静态数组，我们把

```text
PseudoMem("arr", 0)
```

转换为：

```text
Data("arr")
```

如果我们遇到 PseudoMem("arr", n) 且 n 非零，那就麻烦了，因为 Data 操作数不包含偏移。幸运的是，这种情况不会出现。目前，我们只在初始化具有自动存储期的数组时使用带非零偏移的 PseudoMem 操作数，而不是在访问具有静态存储期的数组时。

RIP 相对寻址确实支持常量偏移——例如，foo+4(%rip) 表示符号 foo 之后 4 字节处的地址——但我们还无法在汇编 AST 中表示这些偏移。我们会在第 18 章添加它们，以支持对结构的操作。

### 修补指令

我们没有引入任何新指令，所以不需要新的指令修补规则。这个遍必须认识到，新的 Indexed 操作数指定的是一个内存地址，因此不能用在需要寄存器或立即数的地方。除此之外不需要任何修改。

## 小结

你刚刚实现了第一种聚合类型！在本章中，你学习了如何解析数组声明器和复合初始化器。在类型检查器中，你把从数组到指针的隐式转换显式化，并分析了指针算术表达式的类型。在 TACKY 生成期间，你依靠这些转换和类型信息干净利落地处理了对指针的操作，无论它们指向数组还是标量值。而在后端，你添加了新的、更灵活的内存寻址方式。

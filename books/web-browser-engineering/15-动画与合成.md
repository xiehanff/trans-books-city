# 第 13 章　动画与合成

*Chapter 13: Animating and Compositing*

复杂的 Web 应用在状态之间切换时会使用动画（animation）。这些动画帮助用户理解状态的变化，并以渐变取代突兀的跳变，从而提升视觉质感。但要想流畅地执行这些动画，浏览器必须把每个动画帧（animation frame）的耗时压到最低，利用 GPU 加速（GPU acceleration）来加快视觉效果，并借助合成（compositing）来减少渲染工作量。

## 13.1 JavaScript 动画

动画 [1] 是一连串快速连续展示的静态画面，在人眼中产生运动的错觉。¹ 典型的网页动画包括改变元素的颜色、淡入或淡出、调整元素大小。浏览器还会用动画来响应用户操作，比如滚动、缩放窗口和双指缩放（pinch-zooming）。此外，某些类型的动画媒体（比如视频）也可以嵌入网页。²

本章将聚焦于网页元素的动画。让我们先用第 12 章实现的 `requestAnimationFrame` API 写一个简单的动画。这个方法请求在下一帧运行某段 JavaScript 代码；要想在许多帧中反复运行，只需让这段 JavaScript 代码自己再次调用 `requestAnimationFrame` 即可：

```javascript
function run_animation_frame() {
    if (animate())
        requestAnimationFrame(run_animation_frame);
}
requestAnimationFrame(run_animation_frame);
```

随后 `animate` 函数对页面做一些微小的改变，从而营造出连续变化的印象。³ 通过改变 `animate` 的行为，我们就能改变动画的效果。

例如，我们可以把元素的不透明度（opacity）从 0.1 平滑地过渡到 0.999，实现淡入效果。⁴ 在 120 帧（大约四秒）内完成，意味着每帧将不透明度增加约 0.008。

我们先取这个包含一些文本的 `div`：

```html
<div>This text fades</div>
```

然后编写一个 `animate` 函数来逐步改变它的不透明度：

```javascript
var div = document.querySelectorAll("div")[0];
var total_frames = 120;
var current_frame = 0;
var change_per_frame = (0.999 - 0.1) / total_frames;
function animate() {
    current_frame++;
    var new_opacity = current_frame * change_per_frame + 0.1;
    div.style = "opacity:" + new_opacity;
    return current_frame < total_frames;
}
```

这个动画在我们的浏览器里差不多可以运行了，只差一件事：需要支持从 JavaScript 修改元素的 `style` 属性。为此，在 JavaScript 运行时中为 `Node` 的 `style` 属性注册一个 setter：

```javascript
Object.defineProperty(Node.prototype, 'style', {
    set: function(s) {
        call_python("style_set", this.handle, s.toString());
    }
});
```

然后在浏览器中定义 `style_set` 的处理函数：

```python
class JSContext:
    def __init__(self, tab):
        # ...
        self.interp.export_function("style_set", self.style_set)

    def style_set(self, handle, s):
        elt = self.handle_to_node[handle]
        elt.attributes["style"] = s;
        self.tab.set_needs_render()
```

重要的是，`style_set` 函数会设置 `needs_render` 标志，确保浏览器用新的样式参数重新渲染网页。做完这些改动之后，你现在应该可以在自己的浏览器中打开并运行这个动画了。

> **深入探索**
> 本节介绍的动画模式，正是第 2 章首次引入、并在第 12 章进一步演进的事件循环（event loop）的又一个例子。本章的新意在于：我们终于积累了足够的技术，能够真正创造出有意义、实用的动画。
>
> Web 的发展也是如此。从 `requestAnimationFrame` API 到 CSS 原生动画，一整套规范动画 API 大多是在 2010 年代才登场的 [3]。

## 13.2 GPU 加速

在你的浏览器里试试这个淡入淡出动画，你多半会注意到它并不怎么流畅。这并不意外；毕竟上一章已经表明，对于简单页面，光栅（raster）加绘制（draw）约需 62 ms，渲染（render）需要 23 ms。即使每帧只要 66 ms，我们的浏览器也勉强只有每秒 15 帧；而流畅的动画需要 30 帧！所以我们需要加速光栅和绘制。

最好的办法就是把光栅和绘制搬到 GPU 上 [4]。GPU（graphics processing unit，图形处理器）本质上是你电脑中的一块芯片，它像 CPU 一样运行程序，但专门针对以海量并行方式运行非常简单的程序而优化——它的设计初衷就是对屏幕上的每个像素并行地应用简单操作。这使得 GPU 在绘制简单形状时更快，在应用视觉效果时则快得多。

概括地说，要在 GPU 上进行光栅和绘制，我们的浏览器必须：⁵

- 把显示列表（display list）上传到专用 GPU 显存。
- 编译用于光栅和绘制该显示列表的 GPU 程序。⁶
- 把每条绘制命令光栅化到 GPU 纹理（texture）中。⁷
- 把这些纹理绘制到屏幕上。

幸运的是，SDL 和 Skia 都支持 GPU 以及上述所有步骤；这主要就是一个向它们传入正确参数、让这些工作发生在 GPU 上的问题。那就动手吧。注意，真实的浏览器通常同时实现 CPU 和 GPU 两种光栅与绘制路径，因为在某些情况下 CPU 光栅和绘制可能比用 GPU 更快，或者需要用它来绕开一些缺陷。⁸ 在我们的浏览器中，为了简单起见，我们将始终使用 GPU。

首先，我们需要安装 OpenGL 库：

```text
pip3 install PyOpenGL
```

并导入它：

```python
import OpenGL.GL
```

接下来，我们需要配置 SDL 使用 OpenGL，并在程序开头/结尾启动/停止一个 GL 上下文（GL context）[5]。就我们的目的而言，可以把这套 API 当作样板代码：⁹

```python
class Browser:
    def __init__(self):

        self.sdl_window = sdl2.SDL_CreateWindow(b"Browser",

            "renderer={}").format(
            OpenGL.GL.glGetString(OpenGL.GL.GL_VENDOR),
            OpenGL.GL.glGetString(OpenGL.GL.GL_RENDERER)))

    def handle_quit(self):
        # ...
        sdl2.SDL_GL_DeleteContext(self.gl_context)
        sdl2.SDL_DestroyWindow(self.sdl_window)
```

这条 print 语句会显示浏览器正在使用的 GPU 厂商和渲染器；这能帮助你确认它确实在用你的 GPU。我是用一台 Chromebook 写本章的，所以对我来说输出是：¹⁰

```text

```

现在我们可以配置 Skia 直接绘制到屏幕。咒语如下：¹¹

```python
class Browser:
    def __init__(self):
        #....
        self.skia_context = skia.GrDirectContext.MakeGL()
        self.root_surface = \
            skia.Surface.MakeFromBackendRenderTarget(
            self.skia_context,
            skia.GrBackendRenderTarget(
                WIDTH, HEIGHT, 0, 0,
                skia.GrGLFramebufferInfo(
                    0, OpenGL.GL.GL_RGBA8)),
            skia.kBottomLeft_GrSurfaceOrigin,
            skia.kRGBA_8888_ColorType,
            skia.ColorSpace.MakeSRGB())
        assert self.root_surface is not None
```

使用 OpenGL 的一个额外好处是，我们不再需要在 Skia 和 SDL 之间复制数据。我们只需刷新（flush）Skia 表面（Skia 的表面是惰性绘制的），并调用 `SDL_GL_SwapWindow` 来激活新的帧缓冲（framebuffer，这要归功于 OpenGL 的双缓冲机制（double-buffering）[7]）：

```python
class Browser:
    def draw(self):
        canvas = self.root_surface.getCanvas()
        # ...
        chrome_rect = skia.Rect.MakeLTRB(
            0, 0, WIDTH, self.chrome.bottom)
        canvas.save()
        canvas.clipRect(chrome_rect)
        self.chrome_surface.draw(canvas, 0, 0)
        canvas.restore()
        self.root_surface.flushAndSubmit()
        sdl2.SDL_GL_SwapWindow(self.sdl_window)
```

最后，我们的浏览器还要为 `chrome_surface` 和 `tab_surface` 创建 Skia 表面。我们不希望把它们直接绘制到屏幕上，所以咒语略有不同：

```python
class Browser:
    def __init__(self):
        # ...
        self.chrome_surface = skia.Surface.MakeRenderTarget(
                self.skia_context, skia.Budgeted.kNo,
                skia.ImageInfo.MakeN32Premul(
                    WIDTH, math.ceil(self.chrome.bottom)))
        assert self.chrome_surface is not None
```

同样，你应该把这些改动基本视为样板代码，因为 GPU 操作的细节不是我们此处的重点。¹² 记得对 `tab_surface` 做同样的处理（宽高参数不同）。

得益于 SDL 和 Skia 对 GPU 渲染的全面支持，我们的浏览器要在 GPU 上光栅和绘制，以上应该就是全部所需了。正如预期，速度大有改善。我发现光栅和绘制平均提升到了 7 ms（见图 13.1）。

这大约快了 10 倍，足以达到每秒 30 帧。（在你的电脑上，你看到的加速多半比我更多，所以对你来说在这个例子中可能已经够快了。）但如果还想更快，我们就得想办法减少渲染、光栅和绘制的总工作量。

> **深入探索**
> Skia 中高速、可靠且跨平台的 GPU 光栅路径，也只是最近几年才出现的。¹³ 在 Chromium 诞生之初，只有 CPU 光栅。滚动的实现方式与本书前面几章很相似，靠重新光栅化内容来完成。这在当时被认为是可接受的，因为那时的计算机总体上比今天慢得多，GPU 远不如现在可靠，动画也没那么频繁，而 Android 和 iOS 这样的移动平台才刚刚兴起。（事实上，Android 的最初几个版本也没有 GPU 加速。）Firefox 和 Safari 大体也是如此，不过 Safari 加速内容更容易一些，因为它只面向 macOS 和 iOS 支持的那有限几种 GPU。
>
> 实现 GPU 加速的光栅有许多挑战，其中包括：在众多 GPU 架构上都正确运行、在复杂或出错场景下优雅地回退到 CPU 光栅，以及找到在抗锯齿图形和复杂形状等困难场景下高效进行 GPU 光栅的办法。
>
> 所以，虽然你可能觉得我们的浏览器直到现在才开启 GPU 加速有些奇怪，但这其实也映射了浏览器演化的时间线。

## 13.3 合成

那么，如何在光栅与绘制阶段少做一些工作？答案是一种叫作合成（compositing）的技术，它的意思就是把一些光栅化好的图像缓存（cache）在 GPU 上，并在后续帧中复用它们。¹⁴

为了解释合成，我们需要考察浏览器的显示列表，而把它打印出来会很有帮助。例如，对 `DrawRect` 你可以这样打印：

```python
class DrawRect:
    def __repr__(self):
        return ("DrawRect(top={} left={} " +
            "bottom={} right={} color={})").format(
            self.top, self.left, self.bottom,
            self.right, self.color)
```

如果没有传入不透明度或混合模式，`Blend` 命令有时什么都不做；打印时标明这一点很有帮助：

```python
class Blend:
    def __repr__(self):
        args = ""
        if self.opacity < 1:
            args += ", opacity={}".format(self.opacity)
        if self.blend_mode:
            args += ", blend_mode={}".format(self.blend_mode)
        if not args:
            args = ", <no-op>"
        return "Blend({})".format(args[2:])
```

你还需要为所有绘制命令（paint command）添加 `children` 字段，因为 `print_tree` 依赖它们。现在我们可以打印浏览器的显示列表了：

```python
class Tab:
    def render(self):
        # ...
        for item in self.display_list:
            print_tree(item)
```

对于我们的不透明度示例，某一帧的显示列表（的关键部分）可能长这样：

```text
Blend(alpha=0.119867)
    DrawText(text=This)
    DrawText(text=text)
    DrawText(text=fades)
```

到了下一帧，它可能变成这样：

```text
Blend(alpha=0.112375)
    DrawText(text=This)
    DrawText(text=text)
    DrawText(text=fades)
```

无论哪一帧，光栅化这个显示列表都意味着：先把三个单词光栅化到由 `Blend` 创建的 Skia 表面，再把它复制到根表面（root surface），同时应用透明度。关键在于，两帧的光栅化部分完全相同；不同的只是复制这一步。这意味着我们可以用缓存来加速。

思路是先把这三个单词光栅化到一个单独的表面（但这次由我们自己持有，而不是 Skia），我们称之为合成层（composited layer），并将其保存以备后用：

```text
Composited Layer:
    DrawText(text=This)
    DrawText(text=text)
    DrawText(text=fades)
```

现在，我们不必再光栅化那三个单词，只需用一个 `DrawCompositedLayer` 命令把合成层复制过来：

```text
Blend(alpha=0.112375)
    DrawCompositedLayer()
```

重要的是，在下一帧，`Blend` 变了但 `DrawText` 没变，所以那一帧我们要做的只是重新执行 `Blend`：

```text
Blend(alpha=0.119866666667)
    DrawCompositedLayer()
```

换句话说，合成背后的思想是把显示列表拆成两部分：一组合成层（composited layer），它们在浏览器的光栅阶段被光栅化然后缓存；以及一个绘制显示列表（draw display list），它在浏览器的绘制阶段被绘制，并使用这些合成层。当动画的后续帧复用合成层时，合成就能提升性能。我们的例子正是如此，因为帧与帧之间唯一的差别就是位于绘制显示列表中的 `Blend`。

至于具体如何拆分显示列表，则由浏览器决定。通常，像不透明度这样的视觉效果在 GPU 上执行起来非常快，而绘制形状的绘制命令——在我们的浏览器中是 `DrawText`、`DrawRect`、`DrawRRect` 和 `DrawLine`——可能较慢。¹⁵ 由于通常被动画化的正是视觉效果，这意味着浏览器一般会把带动画的视觉效果留在绘制显示列表里，而把其他一切挪进合成层。当然，在真实浏览器中，硬件能力、GPU 显存和应用数据都会影响这些决策，但无论什么内容放在哪里，合成的核心思想都是一样的。

> **深入探索**
> 如果仔细观察本节的不透明度示例，你会注意到 `DrawText` 命令的矩形（rect）只有文本那么宽；而 `Blend` 的矩形却几乎和视口（viewport）一样宽。二者不同的原因在于：文本只需要它实际需要的宽度，而包含它的块级（block）元素则和可用宽度一样宽。
>
> 那么如果把它放进合成层，这个层需要和文本一样宽，还是和整个视口一样宽？实践中两种做法都可以实现。本章介绍的算法最终得到的是较小的那个，但真实浏览器根据其算法有时会选择较大的那个。另请注意，如果包含该文本的块级元素还关联着任何绘制命令（比如背景色），那么表面就必须和视口一样宽。同样，如果有多个内联（inline）子元素，它们边界（bounds）的并集也会贡献到表面尺寸中。

## 13.4 合成叶子

让我们实现合成。我们需要识别绘制命令并把它们移入合成层，然后创建把这些合成层与视觉效果结合起来的绘制显示列表。为简单起见，我们先为每条绘制命令创建一个合成层。

为了识别绘制命令，给它们统一加一个 `PaintCommand` 超类（superclass）会很有帮助：

```python
class PaintCommand:
    def __init__(self, rect):
        self.rect = rect
        self.children = []
```

现在每条绘制命令都需要成为 `PaintCommand` 的子类；为此，你需要在类声明处指明超类，并在构造函数中使用一些特殊语法：

```python
class DrawLine(PaintCommand):
    def __init__(self, x1, y1, x2, y2, color, thickness):
        super().__init__(skia.Rect.MakeLTRB(x1, y1, x2, y2))
        # ...
```

`MakeLTRB` 为 `PaintCommand` 构造函数创建矩形。把这些表示成 Skia 的 `Rect` 对象而不是四个 x1/y1/x2/y2 字段会很有用。

我们也可以为视觉效果（visual effect）加一个超类：

```python
class VisualEffect:
    def __init__(self, rect, children):
        self.rect = rect.makeOffset(0.0, 0.0)
        self.children = children
        for child in self.children:
            self.rect.join(child.rect)
```

注意，由于视觉效果有子节点（children），我们不仅要把这些子节点传给构造函数，还要把它们的 `rect` 字段并入自己的 `rect`。我用 `makeOffset` 函数复制了一份原始矩形，随后通过 `join` 方法将它扩大，把所有子节点也包含进来。

请继续修改每条绘制命令和每个视觉效果类，使它们成为这两个新类之一的子类。务必在 class 行声明超类，并在 `__init__` 方法中用 `super()` 语法调用超类构造函数。

现在我们可以用 `tree_to_list` 列出所有绘制命令：

```python
class Browser:
    def composite(self):
        all_commands = []
        for cmd in self.active_tab_display_list:
            all_commands = tree_to_list(cmd, all_commands)
        paint_commands = [cmd for cmd in all_commands
            if isinstance(cmd, PaintCommand)]
```

接下来，我们需要把绘制命令分组到各个层。眼下先做最简单的事：把每条绘制命令放进它自己的 `CompositedLayer`：

```python
class Browser:
    def __init__(self):
        # ...
        self.composited_layers = []

    def composite(self):
        self.composited_layers = []
        # ...
        for cmd in paint_commands:
            layer = CompositedLayer(self.skia_context, cmd)
            self.composited_layers.append(layer)
```

这里的 `CompositedLayer` 只是存储一个显示项（display item）列表（以及它们将被绘制到的表面）。¹⁶

```python
class CompositedLayer:
    def __init__(self, skia_context, display_item):
        self.skia_context = skia_context
        self.surface = None
        self.display_items = [display_item]
```

现在我们需要一个把合成层组合起来的绘制显示列表。为了构建它，我们从每个合成层向上回溯，构造出作用于它的全部视觉效果的链条，链的底端是一个 `DrawCompositedLayer`。首先，为了便于访问并比较这些祖先视觉效果，让我们给显示列表树加上父指针（parent pointer）：

```python
def add_parent_pointers(nodes, parent=None):
    for node in nodes:
        node.parent = parent
        add_parent_pointers(node.children, node)

class Browser:
    def composite(self):
        add_parent_pointers(self.active_tab_display_list)
        # ...
```

接下来，我们需要克隆（clone）层的绘制命令的每一个祖先，并注入新的子节点，所以让我们为视觉效果类添加一个新的 `clone` 方法。对 `Blend` 来说，它会创建一个参数相同但子节点不同的新 `Blend`：

```python
class Blend(VisualEffect):
    # ...
    def clone(self, child):
        return Blend(self.opacity, self.blend_mode,
                    self.node, [child])
```

我们的浏览器不会克隆绘制命令，因为它们统统会进入某个合成层，所以不需要为它们实现 `clone`。

现在可以构建绘制显示列表了。对每个合成层，创建一个 `DrawCompositedLayer` 命令（稍后马上定义它）。然后沿显示列表向上走，把该 `DrawCompositedLayer` 依次包进作用于这个合成层的每个视觉效果中：

```python
class Browser:
    def __init__(self):
        # ...
        self.draw_list = []

    def paint_draw_list(self):
        self.draw_list = []
        for composited_layer in self.composited_layers:
            current_effect = \
                DrawCompositedLayer(composited_layer)
            if not composited_layer.display_items: continue
            parent = composited_layer.display_items[0].parent
            while parent:
                current_effect = \
                    parent.clone(current_effect)
                parent = parent.parent
            self.draw_list.append(current_effect)
```

`paint_draw_list` 中的代码只是从每个合成层向上回溯，重新创建作用于它的所有效果。这基本可行——但如果一个效果作用于多个合成层，它就会变成多个相同的效果，分别应用于每个合成层。这是不对的，因为正如第 11 章讨论过的，操作顺序很重要。让我们通过复用克隆出的效果来修正：

```python
class Browser:
    def paint_draw_list(self):
        new_effects = {}
        self.draw_list = []
        for composited_layer in self.composited_layers:
            # ...
            while parent:
                if parent in new_effects:
                    new_parent = new_effects[parent]
                    new_parent.children.append(current_effect)
                    break
                else:
                    current_effect = \
                        parent.clone(current_effect)
                    new_effects[parent] = current_effect
                    parent = parent.parent
            if not parent:
                self.draw_list.append(current_effect)
```

就是这样！现在我们已把显示列表拆分为合成层和绘制显示列表，还需要更新浏览器的其余部分，让光栅和绘制用上它们。

先从光栅开始。在光栅步骤中，浏览器需要遍历合成层列表并逐个光栅化：

```python
class Browser:
    def raster_tab(self):
        for composited_layer in self.composited_layers:
            composited_layer.raster()
```

在 `raster` 内部，合成层需要分配一个表面来光栅化自己；要创建这个表面就需要知道它有多大。那就是它所有绘制命令的包围盒的并集——即 `rect` 字段：

```python
class CompositedLayer:
    # ...
    def composited_bounds(self):
        rect = skia.Rect.MakeEmpty()
        for item in self.display_items:
            rect.join(item.rect)
        # ...
```

注意，我们创建的表面刚好足以容纳这个合成层中的项；这减少了所需的 GPU 显存。话虽如此，还有一些棘手的边界情况要考虑，比如 Skia 为了美观或对齐像素网格，会把线条或抗锯齿（anti-aliased）文本光栅化到多个像素上。¹⁷ 所以让我们在每侧各多加一个像素来预留余量：

```python
    def composited_bounds(self):
        # ...
        rect.outset(1, 1)
        return rect
```

现在我们可以用这些边界创建表面了：

```python
class CompositedLayer:
    def raster(self):
        bounds = self.composited_bounds()
        if bounds.isEmpty(): return
        irect = bounds.roundOut()
        if not self.surface:
            self.surface = skia.Surface.MakeRenderTarget(
                self.skia_context, skia.Budgeted.kNo,
                skia.ImageInfo.MakeN32Premul(
                    irect.width(), irect.height()))
            assert self.surface
        canvas = self.surface.getCanvas()
```

要光栅化合成层，就把它的所有显示项绘制到这个表面上。唯一棘手的是需要按合成边界的左侧和顶部做偏移，因为表面边界不包含这个偏移：

```python
class CompositedLayer:
    def raster(self):
        # ...
        canvas.clear(skia.ColorTRANSPARENT)
        canvas.save()
        canvas.translate(-bounds.left(), -bounds.top())
        for item in self.display_items:
            item.execute(canvas)
        canvas.restore()
```

光栅阶段就这些。对于绘制阶段，我们首先要实现 `DrawCompositedLayer` 命令。它接收一个要绘制的合成层：

```python
class DrawCompositedLayer(PaintCommand):
    def __init__(self, composited_layer):
        self.composited_layer = composited_layer
        super().__init__(
            self.composited_layer.composited_bounds())

    def __repr__(self):
        return "DrawCompositedLayer()"
```

执行 `DrawCompositedLayer` 很直接——只需把它的表面绘制到父表面中，并调整到正确的偏移：

```python
class DrawCompositedLayer(PaintCommand):
    def execute(self, canvas):
        layer = self.composited_layer
        bounds = layer.composited_bounds()
        layer.surface.draw(canvas, bounds.left(), bounds.top())
```

与光栅相比，浏览器的绘制阶段简单得令人愉快：直接执行绘制显示列表即可。

```python
class Browser:
    def draw(self):
        # ...
        canvas.save()
        canvas.translate(0,
            self.chrome.bottom - self.active_tab_scroll)
        for item in self.draw_list:
            item.execute(canvas)
        canvas.restore()
        # ...
```

剩下的就是把这些方法接线了；我们把 `raster_and_draw` 改名为 `composite_raster_and_draw`（提醒我们如今多了一个合成步骤），并加入两个新方法。（别忘了把相应的脏位（dirty bit）和调用点也改名。）

```python
class Browser:
    def composite_raster_and_draw(self):
        # ...
        self.composite()
        self.raster_chrome()
        self.raster_tab()
        self.paint_draw_list()
        self.draw()
        # ...
```

如此简洁优雅！现在，在每一帧上，我们只是把显示列表拆分为合成层和绘制显示列表，然后让它们各自在自己的阶段中运行。我们离超级流畅的动画已经完成一半。剩下的就是：如果显示列表在帧与帧之间变化不大，就跳过布局（layout）和光栅步骤。

> **深入探索**
> 这里介绍的算法是 Chromium 实际实现的简化版。关于 Chromium 如何实现这些概念的更多细节与信息，可参见 Chrome 开发者博客的文章 [10] [11]；其他浏览器也做了大体类似的事情。Chromium 对「视觉效果嵌套」数据结构的实现称为属性树（property trees）[12]。名字用的是复数，因为树不止一棵——这是由滚动与裁剪的包含块（containing block）[13] 结构的复杂性造成的。

## 13.5 CSS 过渡

避免重新光栅化层的关键，是知道哪些层变了、哪些没变。目前我们基本上总是假设所有层都变了，但理想情况下我们应当确切知道帧与帧之间发生了什么变化。浏览器有各种复杂的方法来实现这一点，¹⁸ 但为简单起见，让我们实现一个与合成完美契合的 CSS 特性：CSS 过渡（CSS transition）[15]。

CSS 过渡把我们用来实现动画的 `requestAnimationFrame` 循环「搬进了浏览器」。网页只需添加一个 CSS `transition` 属性，它定义要动画化哪些属性以及动画持续多久。下面这条规则的意思是：`div` 的 `opacity` 变化应当以两秒钟的动画呈现：

```css
div { transition: opacity 2s; }
```

现在，无论 `div` 的 `opacity` 属性因为什么原因发生变化——比如修改了它的 `style` 属性——浏览器都会在两秒内于旧值和新值之间平滑插值。下面是一个示例 [16]，先看 HTML：

```html
<link rel=stylesheet href="example13-opacity-transition.css">
<button>Fade out</button>
<button>Fade in</button>
<div>This text fades</div>
<script src="example13-opacity-transition.js"></script>
```

CSS：

```css
div {
    opacity: 0.999;
    transition: opacity 2s;
}
```

以及 JS：

```javascript
var div = document.querySelectorAll("div")[0];
function start_fade_out(e) {
    div.style = "opacity:0.1";
    e.preventDefault();
}
function start_fade_in(e) {
    div.style = "opacity:0.999";
    e.preventDefault();
}
var buttons = document.querySelectorAll("button");
buttons[0].addEventListener("click", start_fade_out);
buttons[1].addEventListener("click", start_fade_in);
```

视觉上，它与 JavaScript 动画看起来几乎一模一样，¹⁹ 但由于浏览器理解这个动画，它可以优化动画的运行方式。例如，由于 `opacity` 只影响最终进入绘制显示列表的 `Blend` 命令，浏览器知道这个动画不需要布局或光栅，只需要 paint 与 draw 这两个阶段。

为了实现 CSS 过渡，我们需要在浏览器中表示动画状态——比如前一个例子中 `current_frame` 和 `change_per_frame` 这样的 JavaScript 变量。由于同一时刻可能有多个元素在动画，让我们在每个节点上存储一个 `animations` 字典，以被动画化的属性为键：²⁰

```python
class Text:
    def __init__(self, text, parent):
        # ...
        self.style = {}
        self.animations = {}

class Element:
    def __init__(self, tag, attributes, parent):
        # ...
        self.style = {}
        self.animations = {}
```

最容易动画化的一类东西是像 `opacity` 这样的数值属性：

```python
class NumericAnimation:
    def __init__(self, old_value, new_value, num_frames):
        self.old_value = float(old_value)
        self.new_value = float(new_value)
        self.num_frames = num_frames
        self.frame_count = 1
        total_change = self.new_value - self.old_value
        self.change_per_frame = total_change / num_frames
```

与 JavaScript 中类似，我们需要一个 `animate` 方法来递增帧计数、计算新值并返回它：

```python
class NumericAnimation:
    def animate(self):
        self.frame_count += 1
        if self.frame_count >= self.num_frames: return
        current_value = self.old_value + \
            self.change_per_frame * self.frame_count
        return str(current_value)
```

我们会在每次样式值变化时创建这些动画对象，这可以在 `style` 中通过对比每个节点的新旧样式来检测：

```python
def style(node, rules):
    old_style = node.style
    # ...
    if old_style:
        transitions = diff_styles(old_style, node.style)
```

这个 `diff_styles` 函数要找出所有在 `transition` 属性中提到、且在新旧样式之间发生了变化的属性。所以首先，我们得解析 `transition` 的值。

第一个挑战有些烦人：目前我们的 CSS 解析器不认为 `opacity 2s` 是合法的 CSS 值，因为它把值解析为单个单词。让我们升级解析器，让它识别由不属于指定字符集合的任意字符组成的字符串：

```python
class CSSParser:
    def until_chars(self, chars):
        start = self.i
        while self.i < len(self.s) and self.s[self.i] not in chars:
            self.i += 1
        return self.s[start:self.i]

    def pair(self, until):
        # ...
        val = self.until_chars(until)
        # ...
        return prop.casefold(), val.strip()
```

在 CSS 规则体内，属性值一直延续到分号或右花括号为止：

```python
class CSSParser:
    def body(self):
        while self.i < len(self.s) and self.s[self.i] != "}":
            try:
                prop, val = self.pair([";", "}"])
                # ...
```

既然能解析 CSS 属性了，我们就可以解析出带过渡的属性：²¹

```python
def parse_transition(value):
    properties = {}
    if not value: return properties
    for item in value.split(","):
        property, duration = item.split(" ", 1)
        frames = int(float(duration[:-1]) / REFRESH_RATE_SEC)
        properties[property] = frames
    return properties
```

现在 `diff_style` 可以遍历 `transition` 中提到的所有属性，看看哪些变了。它返回一个只包含正在过渡的属性的字典，把每个这样的属性映射到它的旧值、新值和持续时间（同样以帧为单位）。²²

```python
def diff_styles(old_style, new_style):
    transitions = {}
    for property, num_frames in \
        parse_transition(new_style.get("transition")).items():
        if property not in old_style: continue
        if property not in new_style: continue
        old_value = old_style[property]
        new_value = new_style[property]
        if old_value == new_value: continue
        transitions[property] = \
            (old_value, new_value, num_frames)
    return transitions
```

回到 `style` 中，我们要为每个正在过渡的属性创建一个新的动画对象——我们只支持 `opacity`。

```python
def style(node, rules, tab):
    if old_style:
        transitions = diff_styles(old_style, node.style)
        for property, (old_value, new_value, num_frames) \
            in transitions.items():
            if property == "opacity":
                tab.set_needs_render()
                animation = NumericAnimation(
                    old_value, new_value, num_frames)
                node.animations[property] = animation
                node.style[property] = animation.animate()
```

每当 `transition` 中列出的属性值发生变化，我们就创建一个动画并准备运行它。²³

运行动画需要遍历页面上所有活跃的动画并对其调用 `animate`。由于 CSS 过渡与 `requestAnimationFrame` 动画类似，让我们在处理完 `requestAnimationFrame` 回调之后立即运行动画：

```python
class Tab:
    def run_animation_frame(self,scroll):
        # ...
        self.js.interp.evaljs("__runRAFHandlers()")
        for node in tree_to_list(self.nodes,[]):
            for (property_name,animation) in \
                node.animations.items():
                # ...
```

在这个循环里我们要做两件事。第一，调用动画的 `animate` 方法并把新值保存到节点的样式中。第二，由于这改变了渲染输入，设置一个要求稍后重新渲染的脏位。²⁴

（示意：浏览器线程 `schedule_animation_frame` → 主线程依次执行 rAF 回调与 `render` 并 `commit` 提交 → 浏览器线程执行 `raster + draw`；用户的滚动操作（Scroll）再次触发 `schedule_animation_frame`，如此循环。）

然而，事情并没有「只要有动画活跃就设置 `needs_render`」这么简单。设置 `needs_render` 意味着重跑样式（style），而样式会注意到动画改了某个属性值，于是又启动一个新动画！在动画进行期间，我们想运行布局和绘制，但不想运行样式：²⁵

```python
class Tab:
    def run_animation_frame(self, scroll):
        for node in tree_to_list(self.nodes, []):
            for (property_name, animation) in \
                node.animations.items():
                value = animation.animate()
                if value:
                    node.style[property_name] = value
                    self.set_needs_layout()
```

要实现 `set_needs_layout`，我们需要把单一的 `needs_render` 标志换成三个标志：`needs_style`、`needs_layout` 和 `needs_paint`。在我们的实现中，设置流水线中更靠前的脏位会导致其后的所有阶段都运行，²⁶ 所以 `set_needs_render` 仍然只是设置 `needs_style` 标志：

```python
class Tab:
    def __init__(self, browser, tab_height):
        # ...
        self.needs_style = False
        self.needs_layout = False
        self.needs_paint = False
        # ...

    def set_needs_render(self):
        self.needs_style = True
        self.browser.set_needs_animation_frame(self)
```

现在我们可以编写一个 `set_needs_layout` 方法，它设置布局与绘制阶段的标志，但不设置样式阶段：

```python
class Tab:
    def set_needs_layout(self):
        self.needs_layout = True
        self.browser.set_needs_animation_frame(self)
```

为了支持这些新脏位，`render` 必须在开头检查每个阶段的标志位，而不是检查 `needs_render`：²⁷

```python
class Tab:
    def render(self):
        self.browser.measure.time('render')
        if self.needs_style:
            # ...
            self.needs_layout = True
            self.needs_style = False
        if self.needs_layout:
            # ...
            self.needs_paint = True
            self.needs_layout = False
        if self.needs_paint:
            # ...
            self.needs_paint = False
        self.browser.measure.stop('render')
```

好——做完这一切，我们的浏览器现在支持仅用 CSS 实现动画了。而且重要的是，我们可以让浏览器优化不透明度动画，避免布局和合成层的重新光栅化。

> **深入探索**
> CSS 过渡非常适合为由 JavaScript 的 DOM 更新触发的动画添加动效。但那些本身就是页面 UI 一部分、与视觉切换无关的动画呢？（例如按钮或光标上的脉冲式不透明度动画。）这类动画可以完全不借助 JavaScript，直接用 CSS 动画（CSS animation）[17] 以声明式的方式表达。
>
> 实现这个特性需要解析新的 `@keyframes` 语法和 `animation` CSS 属性。注意 `@keyframes` 是以声明方式定义起点和终点的，这让我们可以让动画无限往复，因为反向播放只是在关键帧（keyframe）之间倒着走。
>
> 此外还有 Web Animations API [18]，允许通过 JavaScript 创建和管理动画。

## 13.6 合成动画

我们终于可以教浏览器在运行某些动画时避免光栅（和布局）了。这类动画称为合成动画（composited animation），因为它们与「避免每帧光栅」的合成优化相兼容。就概念而言，避免不透明度动画的光栅与合成很简单：记录哪些内容正在动画，然后在每帧上只重新运行 paint、`paint_draw_list` 和 draw。

实现起来比听起来难。我们需要把新的显示列表拆分为旧的合成层和一个新的绘制显示列表。为此，我们需要知道新旧显示列表之间的关联，以及显示列表的哪些部分发生了变化。为此目的，我们为每个显示项添加一个 `node` 字段，存储绘制它的节点，作为一种标识符：

```python
class VisualEffect:
    def __init__(self, rect, children, node=None):
        # ...
        self.node = node
```

现在，当一个动画运行——而其他都没变——我们将用这些节点来确定绘制显示列表中哪些显示项需要更新。

首先，当合成动画运行时，把样式被改变的 `Element` 保存到一个名为 `composited_updates` 的新数组中。同时在此时只设置 `needs_paint` 标志，而不设置 `needs_layout`：

```python
class Tab:
    def __init__(self, browser):
        # ...
        self.composited_updates = []

    def run_animation_frame(self, scroll):
        for node in tree_to_list(self.nodes, []):
            for (property_name, animation) in \
                node.animations.items():
                value = animation.animate()
                if value:
                    node.style[property_name] = value
                    self.composited_updates.append(node)
                    self.set_needs_paint()
```

现在，当我们提交（commit）一个只需要绘制阶段的帧时，把 `composited_updates` 发送给浏览器线程，后者将用它来跳过 composite 和 raster。为每次动画更新跨线程发送的数据是一个 `Element` 和一个 `Blend`。

为此我们需要几个步骤。首先，在绘制 `Blend` 时，把它记录在 `Element` 上：

```python
def paint_visual_effects(node, cmds, rect):
    # ...
    blend_op = Blend(opacity, blend_mode, cmds)
    node.blend_op = blend_op
    return [blend_op]
```

接下来，向 `CommitData` 添加一个合成更新列表（其中每项将包含 `Element` 和 `Blend` 指针）。

```python
class CommitData:
    def __init__(self, url, scroll, height,
        display_list, composited_updates):
        # ...
        self.composited_updates = composited_updates
```

最后，提交这些新信息。²⁸

```python
class Tab:
    def run_animation_frame(self, scroll):
        # ...
        needs_composite = self.needs_style or self.needs_layout
        self.render()
        composited_updates = None
        if not needs_composite:
            composited_updates = {}
            for node in self.composited_updates:
                composited_updates[node] = node.blend_op
        self.composited_updates = []
        commit_data = CommitData(
            # ...
            composited_updates,
```

现在轮到浏览器线程。首先，添加 `needs_composite`、`needs_raster` 和 `needs_draw` 脏位，以及相应的 `set_needs_composite`、`set_needs_raster` 和 `set_needs_draw` 方法（并移除旧的脏位）：

```python
class Browser:
    def __init__(self):
        # ...
        self.needs_composite = False
        self.needs_raster = False
        self.needs_draw = False

    def set_needs_raster(self):
        self.needs_raster = True
        self.needs_draw = True

    def set_needs_composite(self):
        self.needs_composite = True
        self.needs_raster = True
        self.needs_draw = True

    def composite_raster_and_draw(self):
        if not self.needs_composite and \
            not self.needs_raster and \
            not self.needs_draw:
            self.lock.release()
            return
        if self.needs_composite:
            self.composite()
        if self.needs_raster:
            self.raster_chrome()
            self.raster_tab()
        if self.needs_draw:
            self.draw()
```

然后，在我们目前调用 `set_needs_raster_and_draw` 的地方（例如 `handle_down`），需要改为调用 `set_needs_raster`：

```python
    def handle_down(self):
        # ...
        self.set_needs_raster()
```

用 `commit` 传入的数据来决定调用 `set_needs_composite` 还是 `set_needs_draw`，并把更新保存到 `composited_updates` 中：

```python
                self.set_needs_draw()
```

现在来考虑绘制步骤。通常，我们从合成层创建绘制显示列表。但现在这行不通了，因为合成层来自旧的显示列表。如果只是重新运行 `paint_draw_list`，得到的会是旧的绘制显示列表！我们需要依据 `composited_updates` 更新 `draw_list`，使之考虑新的显示列表。为此，定义一个 `get_latest` 方法：如果 `composited_updates` 中存在某个视觉效果的更新版本，就取它：

```python
class Browser:
    # ...
    def get_latest(self, effect):
        node = effect.node
        if node not in self.composited_updates:
            return effect
        if not isinstance(effect, Blend):
            return effect
        return self.composited_updates[node]
```

在 `paint_draw_list` 中使用 `get_latest` 只需一行：

```python
class Browser:
    def paint_draw_list(self):
        for composited_layer in self.composited_layers:
            while parent:
                new_parent = self.get_latest(parent)
                # ...
```

把 `paint_draw_list` 中 while 循环的其余部分改为在创建新效果时引用 `new_parent` 而不是 `parent`（但从合成层向上回溯时仍用 `parent`）。

现在绘制显示列表将基于新的显示列表，而只需要绘制步骤的动画——比如我们的不透明度动画示例——将运行得超级流畅。

最后一点：切换标签页时需要清空合成数据结构。为此我们抽出一个 `clear_data` 方法，一次性清除所有内容。

```python
class Browser:
    def clear_data(self):
        self.active_tab_scroll = 0
        self.active_tab_url = None
        self.display_list = []
        self.composited_layers = []
        self.composited_updates = {}

    def set_active_tab(self, tab):
        # ...
        self.clear_data()
```

> **深入探索**
> 我们的浏览器中的视觉效果动画如今既高效又可合成，但它们并不像第 12 章所说的那样是线程化（threaded）的：动画仍在主线程（main thread）上滴答运转，如果有慢速 JavaScript 或其他任务堵塞任务队列，动画就会卡顿。这对真实浏览器是个重大问题，因此几乎所有浏览器都支持线程化的不透明度、变换（transform）和滤镜（filter）动画；有些还支持某些类型的裁剪（clip）动画。为我们的浏览器添加线程化动画留作练习 13.3。
>
> 尽管如此，人们常听到把「可合成」（composited）和「线程化」（threaded）当作同义词使用。这是因为在大多数浏览器中，合成是线程化的前提。原因在于：要想高效地运行动画，通常无论如何都需要合成一个纹理，而在浏览器里表达「基于 GPU 纹理的动画」要比表达「基于显示列表某一部分的动画」容易得多。

> **深入探索（续）**
> 话虽如此，为显示列表做动画并非不可能，也有一些浏览器尝试过。例如，Mozilla 的 WebRender [19] 项目的目标之一就是完全抛弃缓存的合成层，直接从显示列表出发，以 60 Hz 在 GPU 上光栅化并绘制来完成所有动画。这称为直接渲染（direct render）方法。实践中，以当前 GPU 技术很难达成这个目标，因为有些 GPU 比别的快。因此浏览器正缓慢演化成直接渲染与合成的混合体。
>
> 所有现代浏览器都拥有线程化动画，但有趣的是，截至写作时，Chromium 和 WebKit 都是在主线程上执行合成步骤，而我们的浏览器是在浏览器线程上做的。在这一点上，我们的浏览器其实领先于真实浏览器！Chromium 的合成之所以（还）没有发生在另一个线程上，是因为要做到这一点需要彻底重构整个合成算法。事实证明这极其困难，因为旧架构与渲染引擎的几乎每个方面都深度交织在一起。这项工作直到 2021 年才完成 [20]，所以也许不久之后这项工作在 Chromium 中也会被线程化。

## 13.7 优化合成

到这里，我们的浏览器已能成功运行合成动画并避免无谓的布局和光栅。但与真实浏览器相比，合成层实在太多了——每条绘制命令一个！这既浪费 GPU 显存也浪费时间：每个合成层都分配一个表面，每个表面都分配并占用 GPU 显存。GPU 显存是有限的，我们希望尽可能少用。为此，我们想用更少的合成层。最简单的做法是：如果若干绘制命令在显示列表中拥有完全相同的祖先视觉效果集合，就把它们放进同一个合成层。

让我们实现它。我们需要在合成层上加两个新方法：`add` 和 `can_merge`。`add` 方法只是把一个新的显示项加入合成层：

```python
class CompositedLayer:
    def add(self, display_item):
        self.display_items.append(display_item)
```

但只应把兼容的显示项加入同一个合成层，这由 `can_merge` 方法判定。一个显示项如果与合成层中现有项拥有相同的父节点，就可以合并：

```python
class CompositedLayer:
    def can_merge(self, display_item):
        return display_item.parent == \
            self.display_items[0].parent
```

现在我们要在 `composite` 中使用这些方法。基本思路是：不再为每条绘制命令新建合成层，而是反向³⁰ 遍历 `composited_layers`，尝试找一个能把该命令合并进去的合成层：³¹

```python
class Browser:
    def composite(self):
        for cmd in paint_commands:
            for layer in reversed(self.composited_layers):
                if layer.can_merge(cmd):
                    layer.add(cmd)
                    break
            else:
                # ...
```

有了这个实现，多条绘制命令有时会进入同一个合成层，但如果祖先效果不完全匹配，它们就不会合并。我们还可以更进一步：把整棵没有动画的显示列表子树放进同一个合成层。这让我们能把无动画的视觉效果放进光栅阶段，进一步减少合成层的数量。

为此，添加一个新的 `needs_compositing` 字段：当视觉效果应进入绘制显示列表时它为 `True`，当它应进入合成层时为 `False`。我们将为大多数视觉效果把它设为 `False`：

```python
class VisualEffect:
    def __init__(self, rect, children):
        self.needs_compositing = False
```

当合成能帮助我们做动画时，我们应把它设为 `True`。真实浏览器有各种复杂的启发式规则，但为简单起见，我们只对 `Blend`（当它们确实有实际效果、而非空操作时）设为 `True`，无论它们是否正在动画：

```python
class Blend(VisualEffect):
    def __init__(self, opacity, blend_mode, node, children):
        # ...
        if self.should_save:
            self.needs_compositing = True
```

如果任一后代需要合成，我们还需要把该视觉效果标记为需要合成。因为如果一个效果位于绘制阶段，那么它上面的那些效果也必须如此：

```python
class VisualEffect:
    def __init__(self, rect, children, node=None):
        # ...
        self.needs_compositing = any([
            child.needs_compositing for child in self.children
        ])
```

现在，层里装的不再是裸的绘制命令，而是由非合成命令构成的子树：

```python
class Browser:
    def composite(self):
        # ...
        non_composited_commands = [cmd
            for cmd in all_commands
            if isinstance(cmd, PaintCommand) or \
                not cmd.needs_compositing
            if not cmd.parent or cmd.parent.needs_compositing
        ]
        # ...
        for cmd in non_composited_commands:
            # ...
```

列表推导式中的多个 `if` 语句是按「与」逻辑组合的。

我们的合成算法现在创建的层少多了！它很好地把无动画内容分组以减少合成层数量（节省 GPU 显存），并尽可能把非动画工作放在光栅而非绘制中完成（让合成动画更快）。

到了这一步，合成算法及其对内容的影响已经相当复杂了。加入更多可视化调试手段来帮助理解正在发生什么，对你来说会非常有用。一个好办法是为我们的浏览器加一个命令行开关 [21]³²，在 `CompositedLayer` 内容周围画红色边框。这对 `CompositedLayer.raster` 来说是个很简单的补充：

```python
class CompositedLayer:

        # ...

            border_rect = skia.Rect.MakeXYWH(
                1, 1, irect.width() - 2, irect.height() - 2)
```

> **深入探索**
> 主要是为了简单，我们的浏览器不管 `Blend` 视觉效果是否在动画，都会合成它们。但事实上，总是合成某些视觉效果还有一些很好的理由。
>
> 第一，动画能够更快启动，因为不必先做光栅。这是因为每当合成理由（compositing reason）发生变化，浏览器就不得不重做合成并重新光栅化新的表面。
>
> 第二，合成有时会带来视觉副作用。理想情况下，合成后的纹理在屏幕上看起来应当与非合成的完全一致。但由于亚像素渲染（sub-pixel rendering）[22]、图像缩放滤波算法、混合和抗锯齿等对像素敏感的光栅技术的细节，这并不总是可能的。例如，由于浮点精度差异，常能观察到某些像素的细微颜色差别。「预合成」（pre-compositing）内容可以避免合成开始时页面上出现视觉跳变。
>
> 真实浏览器支持 `will-change` [23] CSS 属性，用于发出预合成信号。

## 13.8 重叠与变换

我们实现的合成算法在很多情况下都工作得很好。遗憾的是，对于相互重叠的显示列表命令，它无法正确工作。让我用一个例子解释原因。

设想一个浅蓝色方块被一个浅绿色方块重叠，后面是白色背景，如图 13.6 所示。³³ 现在假设我们想给蓝色方块做不透明度动画，但不给绿色方块做。于是蓝色方块进入自己的合成层——那绿色方块怎么办？它和背景拥有相同的祖先视觉效果。但我们不想把绿色方块和背景放进同一个合成层，因为蓝色方块必须绘制在背景和绿色方块之间。因此，绿色方块不得不进入自己的合成层。这称为合成的重叠理由（overlap reason），是所有真实浏览器都要面对的一大复杂之处——也是额外的内存占用和变慢的潜在根源。

*图 13.6　可能导致合成绘制错误的重叠示例。*

让我们修改合成算法以考虑重叠。基本思路是：在考虑某个显示项进入哪个合成层时，同时检查它是否与既有的合成层重叠。若是，就为这个显示项新开一个 `CompositedLayer`：

```python
class Browser:
    def composite(self):
        # ...
        for cmd in non_composited_commands:
            for layer in reversed(self.composited_layers):
                if layer.can_merge(cmd):
                    # ...
                elif skia.Rect.Intersects(
                    layer.composited_bounds(),
                    cmd.rect):
                    layer = CompositedLayer(self.skia_context, cmd)
                    self.composited_layers.append(layer)
                    break
```

不过这段代码有点难测试，因为我们的浏览器尚不支持任何作为视觉效果来移动或放大³⁴元素的手段，所以从来不会有东西重叠。哎呀！在真实浏览器中，有许多会导致重叠的视觉效果，其中（对动画而言）最重要的是变换（transform），它让你能把某个 DOM 子树的绘制输出在屏幕上移动。³⁵ 而且，变换可以在 GPU 上高效执行。

`transform` CSS 属性相当强大，允许在三维空间中应用任意线性变换（linear transform）[25]，但我们只做基本的二维平移。这就足以实现与蓝绿方块示例类似的东西了：³⁶

```html
<div style="background-color:lightblue;
            transform:translate(50px, 50px)">Underneath</div>
<div style="background-color:lightgreen;
            transform:translate(0px, 0px)">On top</div>
```

支持这些变换很简单。首先，解析属性值：³⁷

```python
def parse_transform(transform_str):
    if transform_str.find('translate(') < 0:
        return None
    left_paren = transform_str.find('(')
    right_paren = transform_str.find(')')
    (x_px, y_px) = \
        transform_str[left_paren + 1:right_paren].split(",")
    return (float(x_px[:-2]), float(y_px[:-2]))
```

然后，在 `paint_visual_effects` 中添加一些代码来加入新的 `Transform` 视觉效果：

```python
def paint_visual_effects(node, cmds, rect):
    translation = parse_transform(
        node.style.get("transform", ""))
    # ...
    return [Transform(translation, rect, node, [blend_op])]
```

这些 `Transform` 显示项只是调用 Skia 画布现成的 `translate` 方法：

```python
class Transform(VisualEffect):
    def __init__(self, translation, rect, node, children):
        super().__init__(rect, children, node)
        self.self_rect = rect
        self.translation = translation

    def execute(self, canvas):
        if self.translation:
            (x, y) = self.translation
            canvas.save()
            canvas.translate(x, y)
        for cmd in self.children:
            cmd.execute(canvas)
        if self.translation:
            canvas.restore()

    def clone(self, child):
        return Transform(self.translation, self.self_rect,
            self.node, [child])

    def __repr__(self):
        if self.translation:
            (x, y) = self.translation
            return "Transform(translate({}, {}))".format(x, y)
        else:
            return "Transform(<no-op>)"
```

我们还需要修正 `click` 中的命中测试（hit testing）算法，使其考虑平移。不能只把布局对象的位置与点击点比较，而应计算绝对边界——即以用户所见坐标表示、包含平移偏移的边界——再与之比较。我们用两个辅助方法来计算这样的边界。第一个把矩形按平移映射，第二个沿节点树向上，逐一映射所遇到的每个平移。

```python
def map_translation(rect, translation):
    if not translation:
        return rect
    else:
        (x, y) = translation
        matrix = skia.Matrix()
        matrix.setTranslate(x, y)
        return matrix.mapRect(rect)

def absolute_bounds_for_obj(obj):
    rect = skia.Rect.MakeXYWH(
        obj.x, obj.y, obj.width, obj.height)
    cur = obj.node
    while cur:
        rect = map_translation(rect,
            parse_transform(
                cur.style.get("transform", "")))
        cur = cur.parent
    return rect
```

然后在 `click` 中使用它：

```python
class Tab:
    # ...
    def click(self, x, y):
        # ...
        loc_rect = skia.Rect.MakeXYWH(x, y, 1, 1)
        objs = [obj for obj in tree_to_list(self.document, [])
                if absolute_bounds_for_obj(obj).intersects(
                    loc_rect)]
```

然而，如果你试着加载上面的示例，会发现它看起来仍然不对——蓝色方块本应在绿色方块下面，现在却在上面。³⁸ 这是因为我们测试重叠时，比较的是显示项的 `composited_bounds` 与合成层的 `composited_bounds`。也就是说，我们比较的是显示项的原始位置，而不是它平移后的位置。我们需要改为计算绝对边界：

```python

            for layer in reversed(self.composited_layers):

                elif skia.Rect.Intersects(
                    layer.absolute_bounds(),

                    # ...
```

`absolute_bounds` 方法长这样：

```python
class CompositedLayer:
```

要实现 `local_to_absolute`，我们首先需要 `Transform` 上一个新的 `map` 方法，它接收变换「内容」坐标系中的一个矩形，输出变换后坐标系中的矩形。例如，如果变换是 `translate(20px, 0px)`，那么对矩形调用 `map` 的输出会把它沿 x 方向平移 20 像素。

```python

```

对 `Blend`，值得为裁剪添加一个特例：

```python
        isinstance(self.children[-1], Blend) and \
        self.children[-1].blend_mode == "destination-in":
            bounds = rect.makeOffset(0.0, 0.0)
            bounds.intersect(self.children[-1].rect)
```

```python
def local_to_absolute(display_item, rect):
```

让我们把那些裁剪也应用到 `composited_bounds` 来修复这个问题。³⁹ 做法是先计算每个显示项的绝对边界，再把它映射回局部空间，其效果就是为每个显示项计算「裁剪后的局部矩形」：

```python
    def composited_bounds(self):
        rect = skia.Rect.MakeEmpty()
        for item in self.display_items:
            rect.join(absolute_to_local(
                item, local_to_absolute(item, item.rect)))
        rect.outset(1, 1)
        return rect
```

这需要实现 `absolute_to_local`：

```python
def absolute_to_local(display_item, rect):
    parent_chain = []
    while display_item.parent:
        parent_chain.append(display_item.parent)
        display_item = display_item.parent
    for parent in reversed(parent_chain):
        rect = parent.unmap(rect)
    return rect
```

至此，我们就完整讲完了合成动画的一个相当高性能的实现。

> **深入探索**
> 合成的重叠理由不仅在代码中制造麻烦，而且若浏览器和 Web 开发者不加小心，还可能导致巨量的 GPU 显存占用，以及管理所有这些额外合成层带来的页面变慢。一种可能的情形是：一个额外的合成层源于某元素与另一元素重叠，接着第三个层又因为它与第二个重叠而产生，如此以往。这种现象称为层爆炸（layer explosion）。我们浏览器的算法在大多数情况下能避免这个问题，因为它能把祖先效果兼容的多个显示项合并在一起；但实践中确实存在难以高效合并内容的复杂情形。
>
> 除了重叠之外，还有其他一些合成会带来不良副作用并导致性能问题的情形。例如，假设我们想在某些情况下（比如内存不多的机器上）关闭合成化滚动（composited scrolling），但仍对视觉效果动画使用合成。可如果动画作用在滚动器（scroller）下方的内容上呢？实践中，若不是干脆放弃抵抗、把滚动器也合成掉，这种情形很难正确实现。

## 13.9 总结

本章介绍了动画。你应该记住的要点有：

- 动画分为基于 DOM 的、由输入驱动的和类视频的几种。
- GPU 加速是流畅动画的必要条件。
- 对于流畅且线程化的视觉效果动画，合成通常是必要的。
- 优化合成层的数量很重要。
- 重叠测试可能导致额外的 GPU 显存占用，需要小心实现。

## 13.11 练习

### 练习 13.1：background-color

实现 `background-color` CSS 属性的动画。你需要定义一种适用于所有颜色通道的新插值方法。

### 练习 13.2：缓动函数

我们的浏览器只在起始值和终止值之间做线性插值，但缓动函数（easing function）[28] 还有许多别的选择（事实上，真实浏览器的默认值是 `cubic-bezier(0.25, 0.1, 0.25, 1.0)`，而不是线性）。请实现这个缓动函数，以及另外一两种。

### 练习 13.3：合成与线程化动画

我们的浏览器支持变换（transform）和滚动，但它们并未完全合成化与线程化，而且不支持变换过渡动画。请实现这些。（提示：对于变换，只需遵循与 `opacity` 相同的模式；对于滚动，需要在 `handle_down` 中设置更少的脏位。）完成之后，同时进行的变换加不透明度动画 [29] 应当可以无需任何光栅就能运行，且在该页面上滚动也不应触发光栅。

### 练习 13.4：宽度动画

（你需要先完成练习 6.2。）让 `width` 和 `height` 可动画化；你需要一个 `NumericAnimation` 的变体，能解析并产出像素值（字符串中的 `px` 后缀）。由于 `width` 和 `height` 会诱导布局（layout-inducing），请确保让它们动画化时设置的是 `needs_layout`。检查在你的浏览器中让 `width` 动画化确实会改变换行。实现了宽度动画后，一个宽度过渡示例 [30] 应当可以工作。⁴⁰

### 练习 13.5：CSS 动画

实现 CSS 动画 [31] API 的基础部分，特别是足够的 `animation` CSS 属性支持和 `@keyframes` 解析，以便在 browser.engineering 网站上实现两个演示 [32] [33]。

### 练习 13.6：含变换动画的重叠测试

（你需要先完成练习 13.3。）当变换动画导致重叠时隐时现时，我们的浏览器目前的重叠测试并不正确。请先构造一个能暴露该缺陷的演示，然后修复它。一种修复办法是：每当遇到带动画的变换显示项时就进入「假定重叠模式」。这意味着其后每个显示项都被认为与正在动画的那个重叠（即便此刻并没有），因此不能合并到列表中比动画项更早出现的任何 `CompositedLayer`。另一种办法是在浏览器线程中对每个动画帧都做重叠测试，如果结果与上一帧不同，就重做合成与光栅。⁴¹

### 练习 13.7：避免稀疏的合成层

我们的浏览器的算法目前总是合并祖先效果兼容的绘制块（paint chunk）。但这可能导致低效的情形，比如网页上视觉上相距很远的两个绘制块（例如一个在最顶端、另一个在低几千像素处）最终进入了同一个 `CompositedLayer`。这可能非常糟糕，因为它会产生一个巨大的 `skia.Surface`，其中大部分是被浪费的 GPU 显存。缓解这个问题的一种办法是：如果合并会使 `skia.Surface` 的总面积超过某个固定值，就停止合并。请实现它。⁴²

### 练习 13.8：短显示列表

在真实浏览器中，遇到的 `CompositedLayer` 只含单一纯色、或只含少数几条简单绘制命令的情况相当常见。⁴³ 请实现一种优化：对于绘制命令少于某个固定数量（比如三条）的 `CompositedLayer`，跳过存储 `skia.Surface`，改为直接执行这些命令。换言之，这些 `CompositedLayer` 上的光栅将是空操作，而绘制阶段将直接执行那些绘制命令。

### 练习 13.9：命中测试

目前处理点击时，我们把每个布局对象的边界转换为绝对坐标（通过 `absolute_bounds_for_obj`），再与点击位置比较。但我们也可以反过来，在遍历布局树时把点击位置转换到局部坐标。请改为实现后者。在每个布局对象上定义一个 `hit_test` 方法可能比较方便：它接收一个点击位置，为变换做调整，并递归调用子对象的 `hit_test` 方法。⁴⁴

### 练习 13.10：z-index

目前，HTML 文档中靠后的元素绘制在靠前元素的「上面」。`z-index` CSS 属性会改变这个顺序：`z-index` 较大的元素绘制在上面（相同时由现有顺序决定，默认 `z-index` 为 0）。要使 `z-index` 生效，元素的 `position` 属性必须设置为非 `static`（默认值）的其他值。请添加对 `z-index` 的支持。作为额外挑战，请支持带 `z-index` 属性的嵌套元素 [34]。

### 练习 13.11：动画化滚动

真实浏览器在滚动期间有各种各样的动画。例如，按下向下键或滚动条的向下箭头会引起令人愉悦的动画滚动，而不是我们浏览器目前实现的立即跳变。又如移动设备上，触摸交互常常按带摩擦力的、基于物理的滚动动量模型引起一次「甩动」（fling）。请实现 `<body>` 元素上的 `scroll-behavior` [35] CSS 属性，并通过把滚动委托给主线程动画，用它来在 `handle_down` 中触发动画滚动。⁴⁵ 你需要实现一个新的 `ScrollAnimation` 类以及 `run_animation_frame` 中的一些逻辑。变换过渡 [36] 示例中的滚动现在应当变得平滑，因为那个示例使用了 `scroll-behavior`。⁴⁶

### 练习 13.12：不透明度加绘制

如果 `DrawCompositedLayer` 命令出现在 `Blend(alpha=0.5)` 内部，那么现在可能出现两次表面复制：先把合成层的光栅缓冲复制到临时缓冲，再对其应用不透明度并复制到根表面。这并无必要——事实上 Skia 的 `Surface` 的 `draw` [41] API 本身就支持应用不透明度。请优化浏览器，在这种情形发生时把它们合并为一条绘制命令。（这是真实浏览器中一项重要的优化。）

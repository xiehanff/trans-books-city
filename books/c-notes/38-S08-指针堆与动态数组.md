# 指针、堆与动态数组：把数据的生命周期交给自己管理

栈上的数组写起来很简单：

```c
int values[100];
```

但它的容量在定义时就确定了，函数返回后它也不能继续存在。如果数据量来自用户输入，或者需要让一组数据在运行过程中增长，就需要一块生命周期更灵活的存储空间。

指针、堆内存和动态数组正好组成一条完整链路：**指针保存地址，堆提供可动态申请的存储，动态数组用额外的长度和容量信息管理这块存储。**

> 本篇讲一个可运行的 `int` 动态数组基础实现。更通用的 `void *` 容器见 [`M04_动态数组与泛型容器.md`](30-M04-%E5%8A%A8%E6%80%81%E6%95%B0%E7%BB%84%E4%B8%8E%E6%B3%9B%E5%9E%8B%E5%AE%B9%E5%99%A8.md)，内存函数的 API 速查见 [`C语言中操作内存的函数.md`](26-%E6%93%8D%E4%BD%9C%E5%86%85%E5%AD%98%E7%9A%84%E5%87%BD%E6%95%B0.md)。对应单元测试见 [`c_doc_test/`](#code/books/c-notes/code/c_doc_test/README.md)。

## 1. 先分清三个容易混淆的东西

```c
#include <stdlib.h>

int *data = malloc(10 * sizeof *data);
```

这行代码中有三个不同概念：

1. `data` 是一个指针变量，它自己也占用内存。
2. `malloc` 返回的那块空间是被 `data` 指向的对象存储区。
3. 这块空间由调用者负责释放；“谁拥有它”决定了“谁负责 `free`”。

可以把关系画成：

```text
栈上的指针变量                       堆上的动态存储区
+-----------+                        +----+----+----+----------+
| data      | ---------------------> |  0 |  0 |  0 | ...      |
+-----------+                        +----+----+----+----------+
```

指针本身不等于堆内存。`free(data)` 释放的是指针指向的堆内存，不是把指针变量从栈上删除。

## 2. 栈、堆与生命周期

“栈”和“堆”是常用的实现层概念。C 标准更关注对象的存储期，但在日常 C 编程中可以先这样理解：

| 存储区域 | 典型来源 | 生命周期 | 适合场景 |
|----------|----------|----------|----------|
| 自动存储区（通常称栈） | 函数内普通局部变量 | 进入作用域到离开作用域 | 生命周期短、大小已知的数据 |
| 动态存储区（通常称堆） | `malloc`、`calloc`、`realloc` | 从申请成功到 `free` | 运行时决定大小、跨函数传递的数据 |
| 静态存储区 | 全局变量、`static` 变量 | 整个程序运行期间 | 共享状态或固定生命周期的数据 |

下面的代码返回了局部数组地址，是错误的：

```c
int *wrong_array(void) {
    int values[3] = {1, 2, 3};
    return values;  // 错误：函数返回后 values 的生命周期结束
}
```

如果要把数组返回给调用者，可以把数组放在堆上，并把释放责任写清楚：

```c
#include <stddef.h>
#include <stdlib.h>

int *create_array(size_t count) {
    int *values = malloc(count * sizeof *values);
    if (values == NULL) {
        return NULL;
    }

    for (size_t i = 0; i < count; i++) {
        values[i] = (int)i;
    }
    return values;  // 调用者获得所有权
}

int main(void) {
    int *values = create_array(3);
    if (values == NULL) {
        return 1;
    }

    // 使用 values...
    free(values);   // 调用者释放
    return 0;
}
```

真实项目中还要检查 `count * sizeof *values` 是否可能发生整数溢出；后面的动态数组实现会展示这种检查。

## 3. `malloc`、`calloc`、`realloc` 与 `free`

### `malloc`：申请但不初始化

```c
int *values = malloc(10 * sizeof *values);
if (values == NULL) {
    return 1;
}
```

`malloc` 返回的字节内容没有确定的初始值。需要使用前必须自行初始化。

### `calloc`：申请并清零

```c
int *values = calloc(10, sizeof *values);
if (values == NULL) {
    return 1;
}
```

如果需求就是获得一组全零的元素，`calloc` 比 `malloc` 后再手动清零更直接。这里的“清零”是按字节处理；对于复杂结构体，不应把全字节为零当作所有字段的通用语义初始化。

### `realloc`：调整已有空间

扩容时不要直接覆盖原指针：

```c
int *temporary = realloc(values, 20 * sizeof *values);
if (temporary == NULL) {
    // 扩容失败时，原来的 values 仍然有效
    free(values);
    return 1;
}

values = temporary;
```

`realloc` 可能在原地扩展，也可能申请新区域并搬移数据。因此扩容后，原来指向旧元素的指针可能已经失效。

### `free`：释放并主动置空

```c
free(values);
values = NULL;
```

`free(NULL)` 是安全的，但把释放后的指针置为 `NULL` 能降低后续误用悬空指针的概率。动态内存必须释放一次且只能释放一次。

## 4. 动态分配的数组与可扩容数组不是一回事

下面这种写法是“运行时确定长度的数组”，申请后长度不再改变：

```c
size_t count = 10;
int *values = malloc(count * sizeof *values);
```

如果还需要在元素不足时自动增长，就要额外保存两个数字：

- `size`：当前已经存放的元素数量。
- `capacity`：当前堆空间最多能容纳的元素数量。

```text
data ──▶ [ 已使用元素 ][ 已申请但未使用的空间 ]
          ◀── size ──▶   ◀──── capacity - size ────▶
```

`size` 和 `capacity` 不能混为一谈：访问元素看 `size`，判断是否需要扩容看 `capacity`。

## 5. 从一个 `int` 动态数组开始

### 数据结构和初始化

```c
#include <stddef.h>

typedef struct {
    int *data;       // 堆上的连续元素
    size_t size;     // 当前元素数量
    size_t capacity; // 已申请的元素容量
} IntArray;

void int_array_init(IntArray *array) {
    if (array == NULL) {
        return;
    }

    // 1. 空数组不提前申请空间，第一次 push 时再扩容
    array->data = NULL;
    array->size = 0;
    array->capacity = 0;
}
```

### 预留容量

扩容函数只负责保证容量，不改变 `size`：

```c
#include <stdint.h>
#include <stdlib.h>

int int_array_reserve(IntArray *array, size_t minimum_capacity) {
    if (array == NULL || minimum_capacity <= array->capacity) {
        return array != NULL;
    }

    // 1. 检查“元素个数 × 单个元素大小”是否会溢出
    if (minimum_capacity > SIZE_MAX / sizeof *array->data) {
        return 0;
    }

    // 2. 使用临时指针，避免 realloc 失败时丢失原地址
    int *new_data = realloc(
        array->data,
        minimum_capacity * sizeof *array->data
    );
    if (new_data == NULL) {
        return 0;
    }

    // 3. realloc 成功后再更新结构体状态
    array->data = new_data;
    array->capacity = minimum_capacity;
    return 1;
}
```

### 追加元素与自动扩容

常用的扩容策略是容量翻倍。这样不会每加入一个元素都调用一次 `realloc`：

```c
int int_array_push(IntArray *array, int value) {
    if (array == NULL || array->size == SIZE_MAX) {
        return 0;
    }

    if (array->size == array->capacity) {
        // 1. 第一次申请 4 个位置，之后按 2 倍扩容
        size_t new_capacity = array->capacity == 0 ? 4 : array->capacity;
        if (new_capacity > SIZE_MAX / 2) {
            return 0;
        }
        new_capacity *= 2;

        // 2. 扩容失败时不写入元素，原数组仍保持有效
        if (!int_array_reserve(array, new_capacity)) {
            return 0;
        }
    }

    // 3. 还有空位时直接写入，最后才增加 size
    array->data[array->size] = value;
    array->size++;
    return 1;
}
```

容量翻倍使连续追加的摊还时间复杂度接近 `O(1)`，但扩容那一次仍可能需要搬移全部元素。

### 访问、弹出和释放

```c
int int_array_get(const IntArray *array, size_t index, int *value) {
    if (array == NULL || value == NULL || index >= array->size) {
        return 0;
    }

    *value = array->data[index];
    return 1;
}

int int_array_pop(IntArray *array, int *value) {
    if (array == NULL || array->size == 0) {
        return 0;
    }

    // 1. 先减少逻辑长度，最后一个有效元素的下标是新的 size
    array->size--;
    if (value != NULL) {
        *value = array->data[array->size];
    }
    return 1;
}

void int_array_free(IntArray *array) {
    if (array == NULL) {
        return;
    }

    // 2. 释放堆空间，并把结构体恢复成可再次初始化的状态
    free(array->data);
    array->data = NULL;
    array->size = 0;
    array->capacity = 0;
}
```

`pop` 只减少 `size`，不会立即缩小 `capacity`。这样再次 `push` 时可以复用已有空间；如果确实需要缩容，可以另写一个明确的 `shrink_to_fit` 操作。

## 6. 一个完整的使用流程

```c
#include <stdio.h>

int main(void) {
    IntArray numbers;
    int_array_init(&numbers);

    // 1. 元素数量运行时增长，内部会自动扩容
    for (int i = 0; i < 10; i++) {
        if (!int_array_push(&numbers, i * i)) {
            int_array_free(&numbers);
            return 1;
        }
    }

    // 2. 只能访问 [0, size) 范围内的元素
    for (size_t i = 0; i < numbers.size; i++) {
        int value = 0;
        int_array_get(&numbers, i, &value);
        printf("%d ", value);
    }
    putchar('\n');

    // 3. 使用完成后释放所有权
    int_array_free(&numbers);
    return 0;
}
```

## 7. `realloc` 为什么会让旧指针失效

动态数组扩容后，`data` 可能从旧地址换到新地址：

```c
int *element = &numbers.data[0];
int_array_push(&numbers, 100);  // 可能触发 realloc

// element 可能已经指向旧内存，不能再无条件解引用
```

如果必须长期保存某个元素的位置，应在扩容完成后重新获取；或者保存元素下标，使用时通过 `numbers.data[index]` 重新计算地址。

**关键认知：**`realloc` 成功后，`array->data` 是唯一可信的新基地址；不要假设它一定与旧地址相同。

## 8. 所有权与常见错误

### 内存泄漏

```c
int *values = malloc(10 * sizeof *values);
values = malloc(20 * sizeof *values);  // 第一块空间地址丢失，无法 free
```

如果需要替换指针，先用临时指针接收新分配结果，并在失败时保留旧指针。

### 把 `capacity` 当成 `size`

`capacity` 表示空间已经申请到哪里，未必每个位置都存有有效元素。遍历必须使用 `size`，否则可能读取未初始化区域。

### 重复释放或释放非堆地址

只能释放 `malloc`、`calloc` 或 `realloc` 返回的地址，并且每块地址只能释放一次。栈数组、字符串字面量和已经释放的地址都不能传给 `free`。

### 忽略整数溢出

`count * sizeof *data` 溢出后，实际申请的空间可能比预期小，后续写入就会造成堆缓冲区越界。申请前的乘法边界检查是动态容器的必要组成部分。

一句话总结：动态数组不是“只有一个指针”，而是由堆上的数据指针、当前长度、容量和明确的所有权规则共同组成的容器。

# 第 14 章 构建前端

*Chapter 14: Building the Frontend*

本章中，你将使用 React 组件（component）和 Next.js 页面（page）来构建前端，这两者分别在第 4 章和第 5 章讨论过。到本章结束时，你将得到一个应用初始版本，之后可以为它添加 OAuth 认证。

## 用户界面概览

我们的应用将由三个 Next.js 页面组成。起始页（start page）将显示从数据库中取回的地点列表。列表中的每一项都会链接到各自的地点详情页，其 URL 将使用地点的 ID 来构造，形如 /location/:location_id。第三个页面是用户的心愿单（wish list）页面。它与起始页类似，并遵循与地点详情页相同的动态 URL 模式，只是提供的是用户的 ID 而非地点的 ID。该页面只显示已加入心愿单的地点。

我们还必须考虑每个页面采用何种渲染策略。由于起始页的内容从不变化，我们将使用静态站点生成（SSG）在构建时渲染 HTML。由于详情页和心愿单页会随用户的操作而变化，我们将使用静态站点渲染（SSR）在每次请求时重新生成它们。

最后，这三个页面都应带有包含标志（logo）和指向起始页链接的页头（header）。在下一章加入 OAuth 数据后，我们还会在页头中显示用户名、指向用户心愿单的链接以及登录/登出按钮。

为此，我们需要创建以下 React 组件：

- 地点列表组件，它将使用地点列表项组件在起始页上渲染地点列表。之后，我们会用这些同样的组件来实现用户心愿单页面上的地点列表。
- 整体布局组件、页头组件和标志组件，它们定义每个页面的全局布局。
- 认证元素组件，让用户能够在页头中登录或登出。
- 一个用于各种任务的通用按钮组件。

让我们从起始页所需的组件开始。

*清单 14-2：components/locations-list-item/index.tsx 文件*

你在第 5 章应该已经熟悉这个文件的结构了。首先我们导入 next/link 组件（创建指向详情页的链接需要用到它）、我们刚刚添加的样式，以及来自 Mongoose 模式（schema）的 LocationType。

*清单 14-3：components/locations-list/index.module.css 文件*

地点列表组件的样式很简单：我们移除了组件根元素的外边距和内边距。清单 14-4 是组件本身，请把它复制到 index.tsx。

```tsx
import LocationsListItem from "components/locations-list-item";
import styles from "./index.module.css";
import {LocationType} from "mongoose/locations/schema";

interface PropsInterface {
    locations: LocationType[];
}

const LocationsList = (props: PropsInterface): JSX.Element => {
    return (
        <ul className={styles.root}>
            {props.locations.map((location) => {
                return (
                    <LocationsListItem
                        location={location}
                        key={location.location_id}
                    />
                );
            })}
        </ul>
    );
};

export default LocationsList;
```

*清单 14-4：components/locations-list/index.tsx 文件*

我们导入了刚实现的 LocationsListItem，以及该模块的样式和来自 Mongoose 模式的 LocationType。然后定义组件的 PropsInterface 来描述组件的 props 对象。在 LocationsList 组件中，我们使用数组的 map 函数遍历地点对象，为数组中的每一项渲染一个 LocationsListItem 组件，并使用 location 特性把地点详情传给这些组件。React 要求循环中渲染的每一项都有唯一的 ID，我们用地点 ID 来满足这一要求。

现在我们可以创建起始页，并把所有可用地点传给这个组件。之后，我们会在心愿单页面中复用同一个组件，来返回用户心愿单中的地点。

现在把 pages/index.tsx 文件的现有内容替换为清单 14-6 中的代码。

```tsx
import Head from "next/head";
import type {GetStaticProps, InferGetStaticPropsType, NextPage} from "next";

import LocationsList from "components/locations-list";
import dbConnect from "middleware/db-connect";
import {findAllLocations} from "mongoose/locations/services";
import {LocationType} from "mongoose/locations/schema";

const Home: NextPage = ( // 1
    props: InferGetStaticPropsType<typeof getStaticProps>
) => {

  const locations: LocationType[] = JSON.parse(props.data?.locations); // 2
    let title = `The Food Finder - Home`;

    return (
        <div>
            <Head>
                <title>{title}</title>
                <meta name="description" content="The Food Finder - Home" />
            </Head>

            <h1>Welcome to the Food Finder!</h1>
            <LocationsList locations={locations} />
        </div>
    );
};

export const getStaticProps: GetStaticProps = async () => { // 3
    let locations: LocationType[] | [];
    try {
        await dbConnect();
        locations = await findAllLocations(); // 4
    } catch (err: any) {
        return {notFound: true};
    }
  return { // 5
        props: {
            data: {locations: JSON.stringify(locations)},
        },
    };
};

export default Home;
```

*清单 14-6：pages/index.tsx 文件*

我们实现的这个 Next.js 页面与第 5 章讨论过的结构类似。首先导入所有依赖；然后创建 NextPage，把它保存在一个常量中，并在文件末尾导出（标记 1）。

Next.js 页面的 props 对象（即页面属性）包含我们从 getStaticProps 函数（标记 5）返回的数据，该函数在第 5 章讨论过。在这个异步函数中，我们连接到数据库（标记 3）。连接一旦就绪，我们就调用服务（service）方法取回所有地点（标记 4），然后把它们作为 JSON 字符串通过 props 对象的 data.locations 属性传给 NextPage。Next.js 会在构建时调用 getStaticProps 函数，只为该页面生成一次 HTML。我们可以使用这种渲染方式，因为可用地点的列表从不变化，它是静态的。

接着我们从页面属性中取回地点（标记 2），把 JSON 字符串解析回数组，并把页面标题存入一个变量。我们显式地为 locations 常量标注类型，因为 TSC 无法轻松推断出它的类型。然后我们构造 JSX。第一步，使用 next/head 组件设置页面专属的元数据。之后调用之前实现的 LocationsList 组件，并通过 locations 特性传入地点数组。这样，LocationsList 组件就会把所有地点渲染成一个概览列表。

### 布局

目前，我们有一个 Next.js 页面（起始页）和一个页头组件。把页头加入页面的最简单方式是把它导入 Next.js 页面并直接放进 JSX。但我们还要为应用添加两个页面——心愿单页面和地点详情页——所以我们想避免把页头导入三次。

为了简化整体应用设计，Next.js 提供了布局（layout）的概念，它其实只是另一个组件，我们可以用它把页头组件作为页面内容的同级元素加入。我们来创建一个新的布局组件。首先，为创建该组件的 CSS 文件，向 styles 文件夹中添加 layout.css，并把清单 14-11 中的代码粘贴进去。

```css
.layout-grid {
    align-items: center;
    display: flex;
    flex-direction: column;
    justify-content: space-between;
    margin: 0 auto;
    max-width: 800px;
    padding: 0 1rem;
    width: 100%;
}

@media (min-width: 600px) {
    .layout-grid {
        flex-direction: row;
        padding: 0 2rem;
    }
}
```

*清单 14-11：styles/layout.css 文件*

我们再次使用移动优先模式来定义一个基本的网格包裹器，为内容区域设置全局内边距和最大宽度。我们把包裹器的左右外边距设为 auto，这会让容器居中，因为这些外边距会占据固定宽度包裹器与窗口边缘之间的全部可用空间。

我们用 flexbox 把包裹器直接子元素的方向设为 column，让它们自上而下依次显示。由于标志以及之后加入的所有页头元素都是带有 layout-grid 类的元素的直接子元素，它们会受 flexbox 布局影响。相反，地点条目不是直接同级元素，因此在切换屏幕尺寸时不会改变方向。

然后我们用媒体查询为宽度大于 600px 的屏幕调整样式：增大内边距，并改变直接子元素的排列方向——不再使用 column，而是设为 row，元素随即并排显示。

由于这是全局样式文件而不是 CSS 模块，Next.js 不会自动为类名限定作用域。因此，我们给它们加上 layout- 前缀，并且在使用前无需把样式导入组件。

现在在 components 文件夹内创建 layout 文件夹，并在其中添加 index.tsx 文件，写入清单 14-12 中的组件代码。

```tsx
import Header from "components/header";

interface PropsInterface {
    children: React.ReactNode;
}

const Layout = (props: PropsInterface): JSX.Element => {
    return (
        <>
            <Header />
            <main className="layout-grid">
                {props.children}
            </main>
        </>
    );
};
export default Layout;
```

*清单 14-12：components/layout/index.tsx 文件*

在布局组件中，我们按惯常的结构定义了一个私有接口和组件。在组件内部，我们加入了 Header，以及一个使用全局布局样式、充当子元素包裹器的 main 元素，稍后我们会在 _app.tsx 文件中把子元素传给这个组件。

打开 _app.tsx 文件，按清单 14-13 所示修改。

```tsx

import "../styles/layout.css";
import type {AppProps} from "next/app";
```

*清单 14-13：pages/_app.tsx 文件*

首先我们把 layout.css 作为全局样式加入。至于布局，我们只有一个会用于所有页面的布局组件，在这里导入它。然后我们用布局包裹应用（即各个页面），并把当前页面通过组件的 children 属性传入。

现在，我们所有的 Next.js 页面都遵循相同的结构：Header 组件与包含页面内容的 main 元素并列。遵循这种模式的一个优点是，组件的状态会在页面切换和 React 组件重新渲染时得以保留。

```tsx
const LocationDetail = (props: PropsInterface): JSX.Element => {
    let location = props.location;
    return (
        <div>
            {location && (
                <ul className={styles.root}>
                    <li>
                        <b>Address: </b>
                        {location.address}
                    </li>
                    <li>
                        <b>Zipcode: </b>
                        {location.zipcode}
                    </li>

                        {location.cuisine}
```

### 页面

我们在“用户界面概览”（第 215 页）中提到过，地点详情页应可通过动态 URL /location/:location_id 访问。在 pages 目录中创建一个新的 location 文件夹，并在其中添加包含清单 14-16 代码的 [locationId].tsx 文件。

```tsx
import Head from "next/head";
import type {
    GetServerSideProps,
    GetServerSidePropsContext,
    InferGetServerSidePropsType,
    PreviewData,
    NextPage,
} from "next";
import LocationDetail from "components/location-details";
import dbConnect from "middleware/db-connect";
import {findLocationsById} from "mongoose/locations/services";
import {LocationType} from "mongoose/locations/schema";
import {ParsedUrlQuery} from "querystring";

const Location: NextPage = (
    props: InferGetServerSidePropsType<typeof getServerSideProps>
) => {
    let location: LocationType = JSON.parse(props.data?.location);
  let title = `The Food Finder - Details for ${location?.name}`; // 1
    return (
        <div>
            <Head>
                <title>{title}</title>
                <meta
                    name="description"
                    content={`The Food Finder. 
                        Details for ${location?.name}`}
                />
            </Head>
            <h1>{location?.name}</h1>
          <LocationDetail location={location} /> {/* 2 */}
        </div>
    );
};

export const getServerSideProps: GetServerSideProps = async ( // 3
    context: GetServerSidePropsContext<ParsedUrlQuery, PreviewData>
) => {
     let locations: LocationType[] | [];
  let {locationId} = context.query; // 4
     try {
        await dbConnect();
        locations = await findLocationsById([locationId as string]);
      if (!locations.length) { // 5
            throw new Error(`Locations ${locationId} not found`);
        }
    } catch (err: any) {
        return {
            notFound: true,
        };
    }
    return {
      props: {data: {location: JSON.stringify(locations.pop())}}, // 6
    };
};
```

*清单 14-16：pages/location/[locationId].tsx 文件*

起始页和地点详情页看起来相当相似。视觉上唯一的差别是页面的标题——我们用地点的名称来构造它（标记 1）；并且我们没有使用 LocationsList 组件，而是让 LocationDetail 组件接收单个地点对象（标记 2）。

然而从功能角度看，这两个页面并不相似。与使用 SSG 的起始页不同，地点详情页使用 SSR 和 getServerSideProp（标记 3）。这是因为一旦我们加入心愿单功能并实现加入/移除（Add To/Remove）按钮，页面的内容就应随用户的操作而变化。因此，我们需要在每次请求时重新生成 HTML。我们在第 5 章深入讨论过 SSR 与 SSG 的区别。

我们利用页面的 context（上下文）及其 query 属性，从动态 URL 中获取地点 ID（标记 4）。然后用这个 ID 从数据库中获取匹配的地点。与之前一样，我们直接使用服务，而不是调用公开暴露的 API，因为 Next.js 在服务器端运行 get...Prop 这类函数，可以直接访问我们应用中间件中的服务。

我们还实现了两种退出场景。第一，如果没有结果，我们就抛出一个错误以进入 catch 块（标记 5），从而把用户重定向到 404 Not Found 错误页面。否则，我们把结果中的第一个地点存入 location 属性（标记 6），并在最后一行把它传给我们导出的 Next.js 页面函数。

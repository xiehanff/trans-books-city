# 下一步

*Next Steps*

编程语言的世界十分广阔，还有很多内容等你去探索。自主扩展你的编译器，是围绕你最感兴趣的主题持续学习的好方法。

我留给你几个点子，帮你起步。

## 补全一些缺失的特性

最顺理成章的下一步，是实现本书没有涵盖的 C 语言的主要部分。如果你已经有一份特别想添加的特性的清单，就从它们开始。之后，如果你还想继续，就挑一个真实世界的 C 程序——选小一点的，别选 Linux 内核——然后不断完善你的编译器，直到它能成功编译那个程序。你可以再换一个程序，重复这个过程，直到你对自己实现了多少语言特性感到满意为止。务必一次只添加一个新的语言特性，在转向下一个之前，把每一个都彻底测试好。

## 安全地处理未定义行为

我们已经看到，C 编译器可以随意处置未定义行为（undefined behavior）。但能做某件事，并不意味着就应该去做。以干净、可预测的方式处理未定义行为会带来巨大的好处：它让 C 程序更安全、更容易调试，总体上也不那么令人生畏。例如，你可以保证有符号整数溢出总是回绕（wrap around）（这正是 -fwrapv 编译器选项所做的事）。或者，你可以让程序在遇到未定义行为时抛出错误并退出；Clang 和 GCC 都有一个叫 UndefinedBehaviorSanitizer 的特性，支持这种错误处理方式（https://clang.llvm.org/docs/UndefinedBehaviorSanitizer.html）。

回想一下我们在本书中讨论过的几个未定义行为的例子。你认为你的编译器应该怎样处理它们？这又会如何影响你已经实现的那些优化？有些类型的未定义行为很难检测，但另一些处理起来并不太难；挑一个看起来能驾驭的，看看你能否把它干净地处理掉。

## 编写更多 TACKY 优化

第 19 章只介绍了生产级编译器中你能见到的 IR 优化的一小部分。只要你愿意，可以自己实现更多。研究一下常见的编译器优化，挑选听起来最有趣的那些。如果走这条路，你可能想把 TACKY 代码转换成静态单赋值（static single assignment，SSA）形式，其中每个变量都恰好被定义一次。SSA 形式在现实世界的编译器（包括 Clang 和 GCC）中被广泛使用，因为它让许多优化更容易实现。

## 支持另一种目标架构

大多数生产级编译器都有若干个不同的后端（backend），以支持不同的目标架构（target architecture）。

你可以采用同样的策略：根据目标系统的不同，把 TACKY 转换成不同的汇编代码。如果你使用的是 Windows 或 ARM 系统，完成本书项目时需要借助虚拟化或模拟层，那么一个新的后端就能让你编译出在自己机器上原生运行的代码。

如果你添加对 Windows 的支持，你将能复用现有代码生成遍（code generation pass）的大部分内容，只有 ABI 会有所不同。添加 ARM 后端则是一个更雄心勃勃的项目：你需要学习一套全新的指令集（instruction set）。

## 为开源编程语言项目做贡献

改进你自己的编译器是很好的学习方式，但也不妨考虑拓宽范围，参与其他项目。许多被广泛使用的编译器都是开源的，并且欢迎新的贡献者。一大批相关项目同样如此，比如解释器（interpreter）、linter 和静态分析（static analysis）工具。选一个你喜欢的，弄清楚如何参与其中。这是让你的新技能派上用场的好方法，说不定还能让你最喜爱的编程语言变得更快、更安全、更易用或更容易学习。

## 到此收官！

我希望这本书为你继续构建编译器和编程语言打下了基础。我也希望它改变了你看待日常所用编程语言的方式。你现在能更好地领会创造这些语言时倾注的用心、努力和巧思；当出现问题时，你也不会害怕深入语言的内部实现，去弄清楚究竟发生了什么。编译器将不再像魔法，而是开始呈现出某种更有趣的样貌：普通的软件。

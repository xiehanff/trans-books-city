# 附录 C 常用匹配器

*Appendix C: Common Matchers*

在 Jest 中，匹配器（matcher）让我们能够检查某个特定的条件，例如两个值是否相等，或者当前 DOM 中是否存在某个 HTML 元素。Jest 自带一组内置匹配器。此外，testing library 提供的 JEST-DOM 包还提供了一组专门针对 DOM 的匹配器。

## 内置匹配器

本节介绍最常用的 Jest 内置匹配器。完整列表可以在 Jest 官方文档（https://jestjs.io/docs/expect）中查阅。

**toBe**　这是最简单、也是目前为止最常用的匹配器。它执行简单的相等性检查，判断两个值是否完全相同。它的行为类似于严格相等（strict equality，===）运算符，会考虑类型差异。但与严格相等运算符不同的是，它认为 +0 和 -0 是不同的值。

```javascript
test('toBe',  () => {
    expect(1 + 1).toBe(2);
})

```

**toEqual**　我们使用 toEqual 对对象和数组执行深度相等性检查（deep-equality check），比较它们的全部属性或全部元素。该匹配器会忽略 undefined 值和 undefined 数组元素。此外，它不会检查对象的类型（例如，它们是否是同一个类或同一个父对象的实例或子类）。如果你需要这类检查，请考虑改用 toStrictEqual 匹配器。

```javascript
test('toEqual', () => {
    expect([undefined, 1]).toEqual([1]);
})

```

**toStrictEqual**　toStrictEqual 匹配器对对象和数组执行结构与类型比较；要通过这项测试，对象必须属于相同的类型。此外，该匹配器会考虑 undefined 值和 undefined 数组元素。

```javascript
test('toStrictEqual', () => {
    expect([undefined, 1]).toStrictEqual([undefined, 1]);
})

```

**toBeCloseTo**　对于浮点数，我们使用 toBeCloseTo 而不是 toBe。这是因为 JavaScript 内部的浮点数计算存在缺陷，而该匹配器把这些舍入误差考虑了进去。

```javascript
test('toBeCloseTo', () => {
    expect(0.1 + 0.2).toBeCloseTo(0.3);
})

```

**toBeGreaterThan/toBeGreaterThanOrEqual**　对于数值，我们使用这些匹配器来验证结果大于某个值，或大于等于某个值，类似于 > 和 >= 运算符。

```javascript
test('toBeGreaterThan', () => {
    expect(1 + 1).toBeGreaterThan(1);
})

```

**toBeLessThan/toBeLessThanOrEqual**　这些匹配器与前面的 GreaterThan... 系列匹配器相反，同样用于数值，类似于 < 和 <= 运算符。

```javascript
test('toBeLessThan', () => {
    expect(1 + 1).toBeLessThan(3);
})

```

**toBeTruthy/toBeFalsy**　这些匹配器检查一个值是否存在，而不关心它的具体取值。它们把 JavaScript 中的六个值 0、''（空字符串）、null、undefined、NaN 和 false 视为假值（falsy），其余一切都视为真值（truthy）。

```javascript
test('toBeTruthy', () => {
    expect(1 + 1).toBeTruthy();
})

```

**toMatch**　该匹配器接受一个字符串或一个正则表达式，然后检查某个值是否包含给定的字符串，或者该正则表达式是否返回给定的结果。

```javascript
test('toMatch, () => {
    expect('apples and oranges').toMatch('apples');
})

```

**toContain**　toContain 匹配器与 toMatch 类似，但它接受的是一个数组或字符串，并在其中检查给定的字符串值。当用于数组时，该匹配器验证数组是否包含给定的字符串。

```javascript
test('toMatch, () => {
    expect(['apples', 'oranges']).toContain('apples');
})

```

**toThrow**　该匹配器验证某个函数会抛出错误。被检查的函数需要包在一层包装函数中，否则断言会失败。我们可以向它传入一个字符串或正则表达式，用法与 toMatch 函数类似。

```javascript
function functionThatThrows() {
    throw new Error();
}

test('toThrow', () => {
    expect(() => functionThatThrows()).toThrow();
})

```

## JEST-DOM 匹配器

JEST-DOM 包提供了直接操作 DOM 的匹配器，让我们能够轻松编写对 DOM 运行断言的测试，例如检查某个元素是否存在、其 HTML 内容、CSS 类或属性。

假设我们想检查 logo 元素是否带有类名 center。与其先手动检查元素是否存在、再用 toMatch 检查其 class 属性，我们可以直接使用 toHaveClass 匹配器，如代码清单 C-1 所示。

```javascript
<img data-testid="image" class="center full" alt="The Logo" src="logo.svg" />

test('toHaveClass', () => {
    const element = getByTestId('image');
    expect(element).toHaveClass('center');
})

```

代码清单 C-1：使用 DOM 进行测试的基本语法

首先，我们为 image 元素添加 data 属性 testid。然后，在测试中，我们使用这个 ID 获取该元素，并把它的引用存储到一个常量中。最后，我们在该元素的引用上使用 toHaveClass 匹配器，查看元素的类名中是否包含 center 类。

下面我们来看看最常用的与 DOM 相关的匹配器。

**getByTestId**　该匹配器让我们能够直接访问一个 DOM 元素并保存对它的引用，随后即可配合其他匹配器对这个元素进行各种断言。

```javascript
<img data-testid="image" class="center full" alt="The Logo" src="logo.svg" />

test('toHaveClass', () => {
    const element = getByTestId('image');
--snip--
})

```

**toBeInTheDocument**　该匹配器验证某个元素已被添加到文档树中。该匹配器只对当前属于 DOM 一部分的元素生效，会忽略已脱离文档的元素。

```javascript
<img data-testid="image" class="center full" alt="The Logo" src="logo.svg" />

test('toHaveClass', () => {
    const element = getByTestId('image');
    expect(element).toBeInTheDocument();
})

```

**toContainElement**　该匹配器测试我们关于元素子元素的假设，让我们能够验证例如某个元素是否是另一个元素的后代。

```javascript
<div data-testid="parent">
    <img data-testid="image" class="center full" alt="The Logo" src="logo.svg" />
</div>

test('toHaveClass', () => {
    const parent = getByTestId('parent');
    const element = getByTestId('image');
    expect(parent).toContainElement(element);
})

```

**toHaveAttribute**　该匹配器让我们能够对元素的属性运行断言，例如图像的 alt 属性，以及表单元素的 checked、disabled 或 error 状态。

```javascript
<img data-testid="image" class="center full" alt="The Logo" src="logo.svg" />

test('toHaveClass', () => {
    const element = getByTestId('image');
    expect(element).toHaveAttribute('alt', 'The Logo');
})

```

**toHaveClass**　toHaveClass 匹配器是 toHaveAttribute 匹配器的一个特定变体。它让我们能够显式断言某个元素带有特定的类名，从而编写出简洁的测试。

```javascript
<img data-testid="image" class="center full" alt="The Logo" src="logo.svg" />

test('toHaveClass', () => {
    const element = getByTestId('image');
    expect(element).toHaveClass('center');
})

```

# 第8章 动态规划

最有挑战的算法问题都会牵扯到最优化，这类问题中我们得找一个解能够最大化或最小化某个函数.旅行商问题是一个经典的最优化问题，该问题中我们需要寻找一个巡游以最小的总费用遍历图中所有顶点.但是正如第1章中所讨论的那样，很容易提出许多求解旅行商问题的“算法”，它们会生成一些看起来似乎很合理的解，但是无法在任何情况下构造出费用最少的巡游. 用于最优化问题的算法需要证明这种算法永远能返回最好的解.

贪心算法在每一步都会做出局部最优决策，这样通常很高效但也经常不能保证全局最优性.穷举搜索算法会尝试所有可能性并选择出最好的解，这样必然能产生最优解，但通常会导致时间复杂度上的代价极其高昂. 动态规划结合了上述两种算法思想中最优秀的特质1它给了我们一种以定制方式设计算法的方案，？能让我们一边去存储结果（避免了重复计算，从而带来了高效性），一边系统性地按一定次序去搜索所有可能性（从而确保了正确性）.

通过对所有可能有用的决策存储它们会带来的结果，再以一种系统性的方式使用这类信息，最终让总计算量得到了最小化. 一旦你理解了动态规划这种方式就会发现很好用，它也许应该是最简单易用的算法设计技术了，事实上，我发现完全依靠自己思考来设计动态规划算法更为简单，而在书里去查现成的算法还得找半天，也就是说，你要是还没有真正理解动态规划，那它看起来就如同魔法一般.你得弄明白其中的窍门才能去用它. 动态规划是一种通过存储部分结果从而高效实现递归算法的技术.窍门在于看出朴素的递归算法是否一次又一次地在计算相同的子问题，若是如此则将每个子问题的解存于表中，再遇到时只需查表而不用去重新计算，于是便能获得高效的算法.

你得从递归算法或递归定义开始来设计.只有当我们发现一个正确的递归算法之后，才会去操心如何使用结果矩阵来加速算法.3 对于那些其组件之间有着内蕴的从左到右次序的组合式对象，动态规划通常都是求解此类对象之上最优化问题的正确方案.从左到右式的对象包括：字符串，有根树，多边形，整数序列等.

## 8.1 缓存与计算

动态规划本质上说是一种拿空间去换时间的策略.对一个给定的量重复计算一般没什么坏处，但是次数多了的话在这上面所花的时间就会成为性能上的拖累，要是这样的话，我们就应该存储最初所计算的结果并在随后查找它直接使用，这样比再次重算这个量好多了. 动态规划充分利用了空间与时间之间的互换，计算Fibonacci数之类的递推关系式则是阐明这种互换的最好实例. 下面我们看看计算Fibonacci数三种不同的程序.

### 8.1.1 以递归计算Fibonacci数

Fibonacci数最初是由13世纪的意大利数学家Fibonacci对兔群数量增长建模时所定义的.兔子的繁殖嘛，就像兔子飞速奔跑那样增长，Fibonacci猜测某个年份出生的兔子对数应该等于前两年中所出生的兔子总对数，而且溯源到最开始那年是一对兔子.为了算出第n年出生的兔子数，他定义了如下递推关系式： F_n = F_{n-1} + F_{n-2} 并给出基础情形为 F_0 = 0 且 F_1 = 1。

因此，F_2 = 1，F_3 = 2，而这个级数会继续下去：3，5，8， 13，21，34，55，89，144，……事实证明，Fibonacci 的上述公式在兔子对数的计数上表现不佳，不过它却具备许多有意思的性质。因为 Fibonacci 数由一个递归公式定义，所以我们很容易写出一个递归程序去计算 F_n。用 C 语言写的一个递归函数算法实现看起来应该是这样的：

```c
long fib_r(int n)
{
    if (n == 0)
        return 0;
    if (n == 1)
        return 1;
    return fib_r(n - 1) + fib_r(n - 2);
}

```

### 8.1.2 以缓存计算Fibonacci数
事实上我们能够做得更好，我们可以显式地将每个Fibonacci数的计算结果F存储于查找表中（也可理解为缓存），而这个查找表数据结构以参数k作为索引。避免重复计算的关键在于：当你要去计算某个值之前先去检查清楚该值是否已算过。下面的实现要求调用者保证 `0 ≤ n ≤ MAXN`，否则会发生数组越界。

```c
#define MAXN 45          /* 我们所能考虑到的最大 n 值 */
#define UNKNOWN -1       /* 此值表示空单元 */
long f[MAXN + 1];        /* 用于缓存已算出的 Fibonacci 数的数组 */

long fib_c(int n)
{
    if (f[n] == UNKNOWN)
        f[n] = fib_c(n - 1) + fib_c(n - 2);
    return f[n];
}

```

### 8.1.3 以动态规划计算Fibonacci数
通过直接指定递推关系式的求值次序，我们可以更容易地在线性时间内计算出P：

```c
long fib_dp(int n)
{
    int i;                       /* 计数器 */
    long f[MAXN + 1];            /* 用于缓存已算出的 Fibonacci 数的数组 */

    f[0] = 0;
    f[1] = 1;
    for (i = 2; i <= n; i++)
        f[i] = f[i - 1] + f[i - 2];
    return f[n];
}

```

我们消除了所有递归调用！从最小到最大逐个计算 Fibonacci 数并存储结果，因此不论要计算哪个 `F_i`，`F_{i−1}` 和 `F_{i−2}` 的结果都已经准备好了。这种算法的线性时间性能很明显：一共计算 *n* 个值，每个值由两个整数相加得到，因此总时间和空间都是 `O(n)`。更仔细地研究会发现，我们不需要存储整个执行过程涉及的所有中间值。由于递推式只取决于前两个值，因此只需保留它们：

```c
long fib_ultimate(int n)
{
    int i;                       /* 计数器 */
    long back2 = 0, back1 = 1;   /* F[n] 的前两个值 */
    long next;                   /* 暂存求和值 */

    if (n == 0)
        return 0;
    for (i = 2; i < n; i++) {
        next = back1 + back2;
        back2 = back1;
        back1 = next;
    }
    return back1 + back2;
}

```

通过对递推的分析，所需存储降为常数空间，不过运行时间上没有渐近意义上的降阶.

### 8.1.4 二项式系数
现在再看一个例子：如何计算二项式系数（binomial coefficients）。它也可以通过确定求值次序来消除递归。二项式系数在计数中很重要：`C(n,k)` 表示从 *n* 个对象中选出 *k* 个的方案数。直接计算阶乘：

`C(n,k) = n! / ((n − k)! k!)`

虽然原则上可行，但中间值很容易导致算术溢出，即使最终的二项式系数能由整数变量正确表示。更稳定的方法是利用 Pascal 三角形构造过程中隐含的递推关系：

```text
                 1
              1     1
           1     2     1
        1     3     3     1
     1     4     6     4     1
  1     5    10    10     5     1

```

每个数字都是紧挨着它上方两个数字之和。隐含的递推关系是：

`C(n,k) = C(n−1,k−1) + C(n−1,k)`

考虑第 *n* 个元素是否出现在某个 *k* 元素子集中。如果在，可以从前 *n−1* 个元素中挑出 *k−1* 个来构造该子集；如果不在，则只能从前 *n−1* 个元素中挑出 *k* 个。这两种情况互不相交，且涵盖所有可能，因此该和式计数了所有 *k* 元素子集。递推式还需要基础情形。`C(n,0)=1`，因为从集合中选择零个对象只有一种方案，即空集；`C(n,1)=n`；`C(n,n)=1`，因为从集合中选择全部对象也只有一种方案。将基础情形和递推式合起来，就定义出了参数为自然数的二项式系数。

对此递推式求值的最好方法，是建立一个表来存储所有可能遇到的数值。表的尺寸由需要计算的参数决定。图 8.3 展示了计算 `M[5,4]` 的求值次序：初始化的单元标为 A–K，随后按 1–10 的次序计算其余单元；

每个单元取其正上方与紧挨的左上方两个单元之和。

```c
long binomial_coefficient(int n, int k)
{
    int i, j;                         /* 计数器 */
    long bc[MAXN + 1][MAXN + 1];       /* 存储二项式系数的表 */

    for (i = 0; i <= n; i++)
        bc[i][0] = 1;
    for (j = 0; j <= n; j++)
        bc[j][j] = 1;
    for (i = 2; i <= n; i++)
        for (j = 1; j < i; j++)
            bc[i][j] = bc[i - 1][j - 1] + bc[i - 1][j];

    return bc[n][k];
}

```

### 8.2.1 以递归计算编辑距离
我们观察到这样的事实—字符串中最后一个字符必然是属于匹配、替换、插入或删除这四种情况其一，可用此来定出一个递归算法.切除这个最后一次编辑操作所涉及的字符，则会留下一对较短的字符串，考虑P的某个前缀和T的某个前缀，令和j分别为它们最后一个字符的下标.在前一次操作后可能会形成三种较短的字符串对，它们分别对应匹配/替换，插入或删除操作后所得的字符串，要是我们知道编辑这三对较短字符串所需费用，就可以确定哪种选项可获得最好的解决方案，随后便可作出决策选择该方案.通过递归的魔力我们就能得知最低费用. 更精确地说，令 `D[i,j]` 为模式串 `P` 的前缀 `P₁…Pᵢ` 与文本串 `T` 中某个以 `Tⱼ` 结束的前缀片段之间的最小文本差异。换言之，`D[i,j]` 是以下三种选择所需费用的最小值：

- 若 `Pᵢ = Tⱼ`，费用为 `D[i−1,j−1]`；否则费用为 `D[i−1,j−1] + 1`。这对应两个尾部字符匹配，或用 `Tⱼ` 替换 `Pᵢ`。
- `D[i,j−1] + 1`：文本中多了一个字符，需要为插入操作支付一次费用。
- `D[i−1,j] + 1`：模式中多了一个字符，需要为删除操作支付一次费用。

```c
#define MATCH  0  /* 代表匹配的枚举类型符号 */
#define INSERT 1  /* 代表插入的枚举类型符号 */
#define DELETE 2  /* 代表删除的枚举类型符号 */

int string_compare(char *s, char *t, int i, int j)
{
    int k;                /* 计数器 */
    int opt[3];           /* 三种选项所花费用 */
    int lowest_cost;      /* 最低费用 */

    if (i == 0)
        return j * indel(' ');
    if (j == 0)
        return i * indel(' ');

    opt[MATCH] = string_compare(s, t, i - 1, j - 1) + match(s[i], t[j]);
    opt[INSERT] = string_compare(s, t, i, j - 1) + indel(t[j]);
    opt[DELETE] = string_compare(s, t, i - 1, j) + indel(s[i]);

    lowest_cost = opt[MATCH];
    for (k = INSERT; k <= DELETE; k++) {
        if (opt[k] < lowest_cost)
            lowest_cost = opt[k];
    }
    return lowest_cost;
}
```

### 8.2.2 以动态规划求解编辑距离
那么，我们怎么才能让该算法提速进而可以实用呢？这里有个重要的观察事实：大多数递归调用都在计算那些之前已被算过的东西.我们怎么知道的呢？由于只有|PI T种互不相同的（i,j）元素对可作为递归调用的参数，因此也只可能会有|PI•T|种不同的递归调用. 可将这些（ij）元素对所对应的某些函数值（例如费用）逐个存于表中，我们通过这种方法就可以只在需要时才去查表，从而避免了重复计算. 下面给出这种算法的动态规划实现，它是基于表来完成的.所用的表是一个二维矩阵m，它共有|PI•\T|个单元，其中每个单元包含了子问题最优解的费用，以及一个父亲指针（可对我们说清如何到达此处），表结构如下：

```c

    int parent;     /* 父亲所在单元位置 */

        column_init(i);
```

## 8.5 划分问题

一般情况下，问题可描述如下：

**问题：不需重排的整数划分** 输入：非负数序列 `S=(s₁,…,sₙ)` 和整数 `k`。输出：将 `S` 划分为 `k` 个（或少于 `k` 个）连续区域，不改变元素顺序，使各区域元素和的最大值最小。线性划分问题常见于并行处理：我们要平衡各处理器完成的工作量，以最小化总运行时间；瓶颈由工作量最大的处理器决定。第 7.10 节的 War Story 就围绕这个问题展开。递归考虑最后一块隔板的位置。若在第 `i` 个和第 `i+1` 个元素之间放隔板，则左侧 `i` 个元素由 `k−1` 个区域划分，右侧为最后一个区域。令 `M[n,k]` 表示将前 `n` 个元素划分为 `k` 个区域时，所有区域和的最大值所能达到的最小值，则：

`M[n,k] = min_{1≤i<n} max(M[i,k−1], ∑_{j=i+1}^{n} sⱼ)`

边界条件为：

`M[1,k] = s₁ (k>0)`，`M[n,1] = ∑_{i=1}^{n} sᵢ`。先存储所有子问题的结果，再按参数递增的顺序求值。若直接计算区间和，每个单元最多检查 `n` 个隔板位置，每次求和还需 `O(n)`，总时间为 `O(kn³)`。用前缀和 `p[i]=∑_{j=1}^{i}sⱼ`，可在常数时间内计算任一区间和 `p[i]−p[x]`，从而将时间降为 `O(kn²)`。

```c
void partition(int s[], int n, int k)
{
    int m[MAXN + 1][MAXK + 1]; /* 存储最优划分费用 */
    int d[MAXN + 1][MAXK + 1]; /* 存储隔板位置 */
    int p[MAXN + 1];           /* 前缀和 */
    int cost;
    int i, j, x;

    p[0] = 0;
    for (i = 1; i <= n; i++)
        p[i] = p[i - 1] + s[i];

    for (i = 1; i <= n; i++)
        m[i][1] = p[i];
    for (j = 1; j <= k; j++)
        m[1][j] = s[1];

    for (i = 2; i <= n; i++) {
        for (j = 2; j <= k; j++) {
            m[i][j] = MAXINT;
            for (x = 1; x <= i - 1; x++) {
                cost = max(m[x][j - 1], p[i] - p[x]);
                if (m[i][j] > cost) {
                    m[i][j] = cost;
                    d[i][j] = x;
                }
            }
        }
    }

    reconstruct_partition(s, d, n, k);
}

```

矩阵 `D` 记录每次更新 `M[i,j]` 时所用的隔板位置。由 `D[n,k]` 开始反向追踪，即可重建最优划分：

```c
void reconstruct_partition(int s[], int d[MAXN + 1][MAXK + 1], int n, int k)
{
    if (k == 1) {
        print_books(s, 1, n);
    } else {
        reconstruct_partition(s, d, d[n][k], k - 1);
        print_books(s, d[n][k] + 1, n);
    }
}

void print_books(int s[], int start, int end)
{
    int i;
    for (i = start; i <= end; i++)
        printf("%d ", s[i]);
    printf("\n");
}

```

递推表 `M` 给出最优划分的最大区域和；前缀和使每个状态的转移在 `O(n)` 时间内完成，因此总时间为 `O(kn²)`。

### 8.6.1 最小权三角剖分
上述语法分析中的递推思想也能用于计算几何。多边形 `P=(v₁,…,vₙ)` 的三角剖分是一组互不相交的对角线，它们将多边形划分为三角形；剖分的权是所有对角线长度之和。目标是找出权最小的三角剖分。固定多边形的一条边 `(i,j)`，选择第三个顶点 `k` 后，剩余部分分成两个子多边形，分别需要最优剖分。令 `T[i,j]` 为从顶点 `i` 到顶点 `j` 的子多边形最小剖分费用，不计边 `(i,j)` 的长度；令 `dᵢⱼ` 为顶点 `i,j` 间的距离，则：

`T[i,j] = min_{i<k<j} (T[i,k] + T[k,j] + dᵢₖ + dₖⱼ)`，且 `T[i,i+1]=0`。

```text
MinimumWeightTriangulation(P)
    for i = 1 to n − 1 do
        T[i, i + 1] = 0
    for gap = 2 to n − 1 do
        for i = 1 to n − gap do
            j = i + gap
            T[i, j] = min over k=i+1..j−1 of
                      (T[i, k] + T[k, j] + d[i, k] + d[k, j])
    return T[1, n]

```

由于右侧子问题的顶点数更少，可按 `j−i` 递增求值。`T` 有 `O(n²)` 个状态，每个状态检查 `O(n)` 个 `k`，因此时间为 `O(n³)`、空间为 `O(n²)`。

### 8.7.1 动态规划算法什么时候是正确的？
只有递推关系正确，动态规划算法才正确。令 `LP[i,j]` 表示从 `i` 到 `j` 的最长简单路径长度。若最后一条边是 `(x,j)`，表面上可写成：

`LP[i,j] = max_{(x,j)∈E} (LP[i,x] + c(x,j))`

其中 `c(x,j)` 是边 `(x,j)` 的费用。但这个递推式不正确：它没有记录 `j` 之前访问过哪些顶点，若 `j` 已在从 `i` 到 `x` 的路径中，加入边 `(x,j)` 就会形成环。若把状态改为同时排除某个顶点，仍可能需要记住所有已访问顶点。第二个问题是求值次序。一般图的顶点没有固定的从左到右次序，不能保证递推所需的较小子问题已先求出，计算可能陷入循环。动态规划适用于满足最优性原理的问题：部分解一旦求出，其后续最优决策只依赖部分解的状态，而不依赖达到该状态的具体操作序列。编辑距离就是例子：未来决策依赖前缀匹配状态，不必知道此前具体执行了哪些编辑操作。若问题限制操作的具体顺序，普通编辑距离状态可能不足；需要重新设计状态和递推式。

### 8.7.2 动态规划算法什么时候是高效的？
动态规划的运行时间取决于要记录的部分解数量，以及计算每个部分解所需的时间。对于字符串、数列和多边形等有固定元素次序的对象，输入中的位置往往能完整描述子问题，因此状态数较少，算法通常高效。对于没有固定次序的图，若状态记录从 `i` 到 `j` 的路径及其中间顶点的有序序列 `P`，则可写成：

`LP[i,j,P∪{x}] = max (LP[i,x,P] + c(x,j))`

取最大值的条件是 `(x,j)∈E`，且 `x,j` 不在已用顶点序列中。这样的状态几乎枚举了所有中间路径，状态数可达阶乘量级，实质上是在做组合搜索。改为只记录中间顶点集合 `S`，令 `LP′[i,j,S]` 表示中间顶点恰好为 `S` 的最长简单路径长度。则：

`LP′[i,j,S∪{x}] = max (LP′[i,x,S] + c(x,j))`

其中 `(x,j)∈E` 且 `x∉S`。最后取：

`LP[i,j] = max_S LP′[i,j,S]`

每个 `n` 顶点集合只有 `2ⁿ` 个子集，因此该方法比枚举所有 `n!` 条巡游有很大改进；它仍是指数时间算法。状态约为 `O(n²2ⁿ)`，逐状态枚举候选前驱时，运行时间为 `O(n³2ⁿ)`。这类方法适用于顶点数较小的旅行商实例。

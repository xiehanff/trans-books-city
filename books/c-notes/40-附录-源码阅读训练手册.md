## 从 Kilo 到 Linux Kernel 的顺序执行路线

> 目标：不是“看过很多 C 项目”，而是训练到能够独立定位入口、追调用链、理解内存与数据结构、使用调试器验证判断，并最终具备阅读 Nginx、SQLite、musl 和 Linux Kernel 等大型 C 工程的能力。

# 1. 固定源码阅读方法

以后每个项目都使用同一个循环：

```text
1. 先运行程序
        ↓
2. 提出一个非常具体的问题
        ↓
3. 找入口函数
        ↓
4. 画出你“猜测”的调用链
        ↓
5. 打 3～5 个断点
        ↓
6. 用 Call Stack 跟真实路径
        ↓
7. 观察 struct / pointer / memory
        ↓
8. 改一个变量或删除一段代码
        ↓
9. 再运行验证
        ↓
10. 写出最终调用链
```

绝对不要：

```text
打开一个源码文件
从第一行开始
看到最后一行
```

大型 C 工程根本不是这样读的。

---

# 2. C 源码阅读最重要的五种能力

## 2.1 看见 struct 就画内存

例如：

```c
struct user {
    int id;
    char *name;
    int age;
};
```

脑子里不要只看到：

```text
“一个 User 类”
```

而要看到：

```text
struct user

┌──────────────┐
│ id           │
├──────────────┤
│ padding?     │
├──────────────┤
│ name pointer │──────→ heap/string
├──────────────┤
│ age          │
├──────────────┤
│ padding?     │
└──────────────┘
```

后面必须逐渐学会关注：

```text
sizeof
alignment
padding
pointer ownership
lifetime
```

---

## 2.2 看见 pointer 就问 5 个问题

任何：

```c
Foo *p;
```

都问：

```text
1. p 指向哪里？
2. 谁创建的？
3. 谁拥有？
4. 谁修改？
5. 谁释放？
```

如果这五个问题回答不了，就还没有真正理解这段代码。

---

## 2.3 看见 function pointer 就找“控制反转”

例如：

```c
void (*callback)(void *);
```

不要只理解为“函数指针语法”。

问：

```text
谁赋值？
谁调用？
什么时候调用？
调用者为什么不知道具体实现？
```

这通常意味着：

```text
callback
event
plugin
driver
module
state machine
```

---

## 2.4 Call Stack 比 F12 更重要

你要经常看：

```text
main
 ↓
foo
 ↓
bar
 ↓
baz
```

Call Stack 能告诉你：

```text
我是怎么来到这里的？
```

而 F12 只能告诉你：

```text
这个函数定义在哪里。
```

---

## 2.5 控制阅读边界

例如你今天研究：

```text
dict rehash
```

那么：

```text
network
cluster
replication
AOF
TLS
```

全部先无视。

真正的高手不是“什么都看”。

而是知道：

> 现在哪些东西不应该看。

```text

```

```text

```

macOS：

```text
lldb
Instruments

```

编译自己的实验项目时推荐：

```bash
clang \
  -g \
  -O0 \
  -Wall \
  -Wextra \
  -fsanitize=address,undefined \
  main.c \
  -o app
```

其中：

```text
-g
→ 调试符号

-O0
→ 禁止优化，方便单步

-Wall -Wextra
→ 开更多警告

AddressSanitizer
→ 越界 / use-after-free 等

UndefinedBehaviorSanitizer
→ 未定义行为
```

# 10. 如何读 intrusive data structure

到 Nginx / Kernel 后会大量看到：

```text
对象本身嵌 list node
```

而不是：

```text
List<Node *>
```

例如概念：

```c
struct task {
    ...
    struct list_head node;
};
```

这意味着：

```text
task object
┌─────────────────┐
│ fields          │
├─────────────────┤
│ list_head node  │
└─────────────────┘
```

链表节点就在对象里面。

这是 Linux Kernel 源码必须掌握的思想。

# 13. 最终原则

源码阅读不是：

```text
看了多少行
```

而是：

```text
看到一个行为
      ↓
知道属于哪一层
      ↓
找到入口
      ↓
找核心 struct
      ↓
追状态变化
      ↓
看调用栈
      ↓
画内存
      ↓
修改源码验证
```

真正达到“读懂”的标志是：

> 你在修改源码之前，就能够大致预测程序会怎样坏。

而不是：

> “这个文件我看完了。”

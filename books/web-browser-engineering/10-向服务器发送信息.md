# 第 8 章　向服务器发送信息

*Chapter 8: Sending Information to Servers*

到目前为止，我们的浏览器一直把 Web 视为只读的——但当你在 Facebook 上发帖、填写调查问卷或在 Google 中搜索时，你不仅在从服务器接收信息，也在向服务器发送信息。本章我们将开始把浏览器改造成一个 Web 应用（web application）平台，为此要实现对 HTML 表单（form）的支持——这是浏览器向服务器发送信息最简单的方式。

## 8.1 表单如何工作

HTML 表单由几个活动部件组成。首先，在 HTML 中有一个 form 元素（element），其中包含若干 input 元素，¹ 用户可以编辑这些 input 元素的内容。因此，一个表单可能会写成这样：

```html
<form action="/submit" method="post">
    <p>Name: <input name=name value=1></p>
    <p>Comment: <input name=comment value=2></p>
    <p><button>Submit!</button></p>
</form>
```

渲染出来则如图 8.1 所示。

*图 8.1　我们的浏览器中的示例表单。*

这个表单包含两个文本输入框，分别名为 name 和 comment。用户访问这个页面时，可以点击这些输入框来编辑其中的值。然后，当用户点击表单末尾的按钮时，浏览器会收集所有的名称–值对（name–value pair），把它们打包进一个 HTTP POST 请求（由 method 属性指定），发送到 form 元素的 action 属性所给出的 URL——相对 URL（relative URL）的规则照旧适用，本例中就是 /submit。这个 POST 请求看起来像这样：

```text
POST /submit HTTP/1.0
Host: example.org
Content-Length: 16
name=1&comment=2
```

换句话说，它与我们已经见过的普通 GET 请求非常相似，区别在于它带有一个主体（body）——你已经见过带主体的 HTTP 响应了，其实请求也可以有。注意 Content-Length 头字段；它对 POST 请求是必需的。服务器用一个网页来响应这个请求，一如平常，浏览器随后也照常完成它平时所做的一切。

实现表单需要扩展浏览器的许多部分：从实现 HTTP POST，到绘制 input 元素的新布局对象（layout object），再到处理按钮点击。这使它成为把浏览器改造成应用平台的绝佳起点——这正是接下来几章的目标。让我们开始动手实现这一切吧！

> **深入探索**
> HTML 表单最早在 HTML+ [1] 中得到标准化，那份文档还提出了表格、数学公式以及环绕图像排列的文字。令人惊叹的是，这三项技术全都留存了下来，只是存在于完全不同的标准之中：表格在 RFC 1942 [2] 里，公式在 MathML [3] 里，而浮动图像则在 CSS 1.0 [4] 里。

## 8.2 渲染控件

首先，让我们绘制用户将要输入内容的输入区（input area）。² 输入区是行内内容（inline content），与文字一起排布在行中。因此，要支持 input，我们需要一种新的布局对象，我称之为 InputLayout。我们可以复制 TextLayout 并把它当作模板，不过需要做一些快速的修改。

首先，InputLayout 没有 word 参数：

```python
class InputLayout:
    def __init__(self, node, parent, previous):
        self.node = node
        self.children = []
        self.parent = parent
        self.previous = previous
```

其次，input 元素通常具有固定的宽度：

```python
INPUT_WIDTH_PX = 200
class InputLayout:
    def layout(self):
        # ...
        self.width = INPUT_WIDTH_PX
        # ...
```

input 和 button 元素需要在视觉上有所区分，好让用户轻松找到它们。我们的浏览器样式能力有限，那就用背景色（background color）来做到这一点：

```css
input {
    font-size: 16px; font-weight: normal; font-style: normal;
    background-color: lightblue;
}
button {
    font-size: 16px; font-weight: normal; font-style: normal;
    background-color: orange;
}
```

浏览器绘制（paint）InputLayout 时，需要绘制背景：

```python
class InputLayout:
    def paint(self):
        cmds = []
        bgcolor = self.node.style.get("background-color",
                                    "transparent")
        if bgcolor != "transparent":
            rect = DrawRect(self.self_rect(), bgcolor)
            cmds.append(rect)
        return cmds
```

接着需要获取 input 元素的文本内容：

```python
class InputLayout:
    def paint(self):
        # ...
        if self.node.tag == "input":
            text = self.node.attributes.get("value", "")
        elif self.node.tag == "button":
            if len(self.node.children) == 1 and \
            isinstance(self.node.children[0], Text):
                text = self.node.children[0].text
            else:
                print("Ignoring HTML contents inside button")
                text = ""
        # ...
```

注意，<button> 元素原则上可以包含复杂的 HTML，而不只是一个文本节点。这对本章来说太复杂了，因此在那种情况下，我让浏览器打印一条警告并跳过这些文本。³ 最后，我们绘制这段文本：

```python
class InputLayout:
    def paint(self):
        # ...
        color = self.node.style["color"]
        cmds.append(
            DrawText(self.x, self.y, text, self.font, color))
        return cmds
```

读到本书的这个阶段，你已经见过很多布局对象了，所以这些修改我就从简说明。这里的要点是：新增布局对象是扩展浏览器的一种常见方式。

现在我们需要创建一些 InputLayout，这可以在 BlockLayout 中完成：

```python
class BlockLayout:
    def recurse(self, node):
        if isinstance(node, Text):
            # ...
        else:
            if node.tag == "br":
                self.new_line()
            elif node.tag == "input" or node.tag == "button":
                self.input(node)
            else:
                for child in node.children:
                    self.recurse(child)
```

最后，这个新的 input 方法与处理文本的方法类似——创建一个新的布局对象并把它加入当前行：⁴

```python
class BlockLayout:
    def input(self, node):
        w = INPUT_WIDTH_PX
        if self.cursor_x + w > self.width:
            self.new_line()
        line = self.children[-1]
        previous_word = line.children[-1] if line.children else None
        input = InputLayout(node, line, previous_word)
        line.children.append(input)
        weight = node.style["font-weight"]
        style = node.style["font-style"]
        if style == "normal": style = "roman"
        size = int(float(node.style["font-size"][:-2]) * .75)
        font = get_font(size, weight, style)
        self.cursor_x += w + font.measure(" ")
```

不过实际上，由于我们解决「块级元素与行内兄弟元素混排」问题的方式（见第 5 章），还有几处额外的复杂情况。其一，如果一个节点没有子节点，我们会假定它是块级元素（block element）。但 <input> 元素没有子节点，却必须采用行内布局（inline layout），否则无法正确绘制。

同样，<button> 确实有子节点，但这些子节点会被特殊处理。⁵ 我们可以通过下面这处对 layout_mode 的修改来修复，为返回 "inline" 增加第二个条件：

```python
class BlockLayout:
    def layout_mode(self):
        # ...
        elif self.node.children or self.node.tag == "input":
            return "inline"
        # ...
```

第二个问题是，同样由于存在块级兄弟元素，<input> 或 <button> 元素有时会创建一个 BlockLayout（其内部再创建一个 InputLayout）。在这种情况下，我们不希望把背景绘制两次，所以让我们通过一个新的 should_paint 方法加入一点简单的逻辑，让 BlockLayout 在这种情况下跳过背景绘制：⁶

```python
class BlockLayout:
    # ...
    def should_paint(self):
        return isinstance(self.node, Text) or \
            (self.node.tag != "input" and self.node.tag != "button")
```

给其余所有布局对象类型都添加一个直接返回 True 的简单 should_paint 方法。现在我们就可以依据 should_paint 来跳过某些对象的绘制：

```python
def paint_tree(layout_object, display_list):
    if layout_object.should_paint():
        display_list.extend(layout_object.paint())
    # ...
```

经过这些修改，浏览器现在应该会把 input 和 button 元素绘制成蓝色和橙色的矩形。

> **深入探索**
> 按钮会包围其内容而输入区不会，原因在于按钮可以包含图像、带样式的文本或其他内容。在真实浏览器中，这依赖于 inline-block [6] 显示模式（display mode）：一种把块级元素放进一行文字中的办法。还有一种更古老的 <input type=button> 语法，它与文本输入框更为相似。

## 8.3 与控件交互

input 元素已经能渲染了，但你还无法编辑其中的内容。可这当然正是全部意义所在！所以，让我们让 input 元素像地址栏那样工作——点击它会将其清空，然后就可以在其中输入了。

清空很容易，在 Tab 的 click 方法里再加一个分支：

```python
class Tab:
    def click(self, x, y):
        while elt:
            # ...
            elif elt.tag == "input":
                elt.attributes["value"] = ""
            # ...
```

然而，如果你试一下就会发现，点击并不能真正清空 input 元素。这是因为上面的代码更新的是 HTML 树——但要让变化出现在屏幕上，我们还需要更新布局树（layout tree），再更新显示列表（display list）。目前，布局树和显示列表是在 load 中计算的，但我们不想重新加载整个页面；我们只想重做样式、布局、绘制和 draw 各阶段。这些阶段合起来称为渲染（rendering）。所以，让我们把这些阶段提取成一个新的 Tab 方法 render：

```python
class Tab:
    def load(self, url, payload=None):
        # ...
        self.render()
    def render(self):
        style(self.nodes, sorted(self.rules, key=cascade_priority))
        self.document = DocumentLayout(self.nodes)
        self.document.layout()
        self.display_list = []
        paint_tree(self.document, self.display_list)
```

要让这段代码工作，你还需要把 nodes 和 rules 从 load 方法中的局部变量改成 Tab 上的新字段。注意，样式计算从 load 移到了 render，但下载样式表（style sheet）的部分没有移——我们可不会每敲一个键就重新下载一次样式表！⁷

现在，当我们点击一个 input 元素并清空其内容后，就可以调用 render 来重绘页面，让清空后的输入框显示出来：

```python
class Tab:
    def click(self, x, y):
        while elt:
            elif elt.tag == "input":
                elt.attributes["value"] = ""
                return self.render()
```

点击输入区就是这样。但键入更难。回想一下第 7 章实现地址栏的方式：我们添加了一个 focus 字段来记住我们点击过的对象，以便之后把按键发送给它。输入区也需要一个类似的 focus 字段，但情况会更复杂，因为输入区位于 Tab 内部，而不是 Browser 内部。

很自然，每个 Tab 上都需要一个 focus 字段，用来记住我们最近点击过哪个文本输入框（如果有的话）：

```python
class Tab:
    def __init__(self):
        # ...
        self.focus = None
```

现在，当我们点击一个 input 元素时，需要设置 focus（如果没有找到可聚焦的对象，则清除 focus）：

```python
class Tab:
    def click(self, x, y):
        self.focus = None
        # ...
        while elt:
            elif elt.tag == "input":
                self.focus = elt
                # ...
```

但请记住，键盘输入不是由 Tab 处理的——它由 Browser 处理。那么，Browser 究竟怎么知道什么时候该把键盘事件发给 Tab 呢？Browser 必须把这件事记在它自己的 focus 字段里！换句话说，当你点击网页时，Browser 会更新自己的 focus 字段，记住用户正在与页面交互，而不是与浏览器镶边（browser chrome）交互。若是如此，它还应当让浏览器镶边失焦（「blur」）：

```python
class Chrome:
    def blur(self):
        self.focus = None
class Browser:
    def handle_click(self, e):
        if e.y < self.chrome.bottom:
            self.focus = None
            # ...
        else:
            self.focus = "content"
            self.chrome.blur()
            # ...
        self.draw()
```

对应浏览器镶边内点击的那个 if 分支会取消 focus，这意味着焦点不再位于页面内容上，按键因此会被发送给 Chrome。

按键发生时，Browser 要么把它发送给地址栏，要么调用活动标签页的 keypress 方法（如果什么都没有聚焦，则两者都不做）：

```python
class Browser:
    def handle_key(self, e):
        # ...
        if self.chrome.keypress(e.char):
            self.draw()
        elif self.focus == "content":
            self.active_tab.keypress(e.char)
            self.draw()
```

这里我把 keypress 改成在浏览器镶边消费了该按键时返回 true：

```python
class Chrome:
    def keypress(self, char):
        if self.focus == "address bar":
            self.address_bar += char
            return True
        return False
```

接着，Tab 的 keypress 方法使用标签页的 focus 字段，把字符放进正确的文本输入框：

```python
class Tab:
    def keypress(self, char):
        if self.focus:
            self.focus.attributes["value"] += char
            self.render()
```

注意这里我们调用的是 render 而不是 draw，因为我们修改了网页，所以需要重新生成显示列表，而不只是把它重新绘制到屏幕上。

层次化的焦点处理是组合图形控件（graphical widget）的一种重要模式；在真实浏览器中，网页可以通过 iframe 相互嵌套，⁸ 焦点树（focus tree）可以有任意深度。

现在，用户输入已经可以在 input 元素上工作了。在继续之前，还有最后一处小调整要做：在 Tab 的 render 方法中绘制文本光标。这实际上比预想的更难：光标应当由聚焦节点的 InputLayout 绘制，而这就意味着每个节点都得知道自己是否处于聚焦状态：

```python
class Element:
    def __init__(self, tag, attributes, parent):
        # ...
        self.is_focused = False
```

给 Text 节点也加上同样的字段；它们永远不会被聚焦、永远不会绘制光标，但让 Text 和 Element 拥有相同的字段会更方便。当我们把焦点移到某个 input 元素上时，就会设置它：

```python
class Tab:
    def click(self, x, y):
        while elt:
            elif elt.tag == "input":
                elt.attributes["value"] = ""
                if self.focus:
                    self.focus.is_focused = False
                self.focus = elt
                elt.is_focused = True
                return self.render()
```

注意，我们必须取消当前聚焦元素的聚焦状态，免得它继续绘制自己的光标。总之，现在只要某个 input 元素处于聚焦状态，我们就可以绘制光标了：

```python
class InputLayout:
    def paint(self):
        # ...
        if self.node.is_focused:
            cx = self.x + self.font.measure(text)
            cmds.append(DrawLine(
                cx, self.y, cx, self.y + self.height, "black", 1))
        # ...
```

现在你可以点击一个文本输入框、在其中键入并修改它的值了。下一步是提交此时已填写完毕的表单。

> **深入探索**
> 这种绘制文本光标的方式——让 InputLayout 来绘制——使视觉效果能够作用于光标，我们将在第 11 章看到这一点。但并非每个浏览器都这样做。例如，Chrome 会跟踪一个全局的聚焦元素 [7]，以确保光标可以被全局地设置样式 [8]。

## 8.4 提交表单

提交表单的方式是点击按钮。所以让我们在 click 的大 while 循环中再加一个条件：

```python
class Tab:
    def click(self, x, y):
        while elt:
            # ...
            elif elt.tag == "button":
                # ...
            # ...
```

找到按钮之后，我们需要沿着 HTML 树向上走，找到它所在的表单：

```python
elif elt.tag == "button":
    while elt:
        if elt.tag == "form" and "action" in elt.attributes:
            return self.submit_form(elt)
        elt = elt.parent
```

接下来，submit_form 方法负责找到所有 input 元素、以正确的格式编码它们，并发送 POST 请求。首先，我们遍历表单的所有后代节点来找出 input 元素：

```python
class Tab:
    def submit_form(self, elt):
        inputs = [node for node in tree_to_list(elt, [])
                if isinstance(node, Element)
                and node.tag == "input"
                and "name" in node.attributes]
```

对其中每个 input 元素，我们需要提取 name 属性和 value 属性，并对两者做表单编码（form encoding）。表单编码规定了名称–值对在 HTTP POST 请求中的格式化方式。基本上就是：名称，然后是等号，然后是值；各个名称–值对之间用 & 分隔：

```python
class Tab:
    def submit_form(self, elt):
        # ...
        body = ""
        for input in inputs:
            name = input.attributes["name"]
            value = input.attributes.get("value", "")
            body += "&" + name + "=" + value
        body = body[1:]
```

这里，body 一开始会在开头多拼一个 &，最后一行再把它去掉。

现在，每当你看到这样的特殊语法，都必须问一句：如果名称或值本身含有等号或 & 会怎么样？因此，实际上「百分号编码（percent encoding）」会把所有特殊字符替换成百分号后跟该字符的十六进制码。例如，空格变成 %20，句点变成 %2e。Python 在 urllib.parse 模块中提供了百分号编码函数 quote：⁹

```python
for input in inputs:
    # ...
    name = urllib.parse.quote(name)
    value = urllib.parse.quote(value)
    # ...
```

既然 submit_form 已经构造好了请求主体，接下来就要发出 POST 请求了。我打算把这份职责交给负责发请求的 load 函数：

```python
def submit_form(self, elt):
    # ...
    url = self.url.resolve(elt.attributes["action"])
    self.load(url, body)
```

load 新增的 payload 参数随后被传递给 request：

```python
def load(self, url, payload=None):
    # ...
    body = url.request(payload)
    # ...
```

在 request 中，这个新参数用来决定发 GET 还是 POST 请求：

```python
class URL:
    def request(self, payload=None):
        # ...
        method = "POST" if payload else "GET"
        # ...
        request = "{} {} HTTP/1.0\r\n".format(method, self.path)
        # ...
```

如果是 POST 请求，Content-Length 头字段是必需的：

```python
class URL:
    def request(self, payload=None):
        # ...
        if payload:
            length = len(payload.encode("utf8"))
            request += "Content-Length: {}\r\n".format(length)
        # ...
```

注意，Content-Length 是请求主体按字节计的长度，它未必等于按字符计的长度。¹⁰ 最后，在所有头字段之后，我们发送请求主体本身：

```python
class URL:
    def request(self, payload=None):
        # ...
        if payload: request += payload
        s.send(request.encode("utf8"))
        # ...
```

POST 请求就是这样发送出去的。随后，服务器用一个 HTML 页面作为响应，浏览器将以完全正常的方式渲染它。¹¹ 表单的内容基本上就是这些了！

> **深入探索**
> 虽然大多数表单提交使用的都是这里讲的表单编码，但带文件上传的表单（使用 <input type=file>）使用另一种编码 [9]，它会为每个键–值对附上元数据（比如文件名或文件类型）。此外还有一种鲜为人知的 text/plain 编码 [10] 选项，它不做任何转义，甚至连标准都告诫不要使用它。

## 8.5 Web 应用如何工作

那么……Web 应用（web app）究竟是如何使用表单的？当你在浏览器中使用某个应用时——无论你是在登记投票、翻看小堂弟的照片，还是在查收邮件——通常¹²都会涉及两个程序：运行在浏览器中的客户端代码（client code），和运行在服务器上的服务器端代码（server code）。当你在应用中点击或执行操作时，运行的是客户端代码，它再通过 HTTP 请求把数据发给服务器。

例如，想象一个简单的留言板应用。服务器存储留言板的状态——谁发了什么——并带有更新该状态的逻辑。但与页面之间的全部实际交互——绘制帖子、让用户输入新帖子——都发生在浏览器中。这两个组件缺一不可。

浏览器与服务器通过 HTTP 交互。浏览器首先向服务器发出一个 GET 请求，加载当前的留言板。用户与浏览器交互，敲出一篇新帖子并提交给服务器（比如通过表单）。这会使浏览器向服务器发出一个 POST 请求，指示服务器更新留言板状态。然后，服务器需要让浏览器更新用户所见的内容；对于表单来说，服务器会在对 POST 请求的响应中发回一个新的 HTML 页面。这个过程如图 8.2 所示。

*图 8.2　多页应用的请求与响应循环。*
（示意图：浏览器发出 GET 请求 → 服务器返回 HTML，显示「页面」；浏览器发出 POST 请求 → 服务器返回新 HTML，显示更新后的「页面」；浏览器再发出 GET 请求 → 服务器返回 HTML，再次显示「页面」）

表单以简单而最小的方式引入了这个请求与响应的循环，很适合作为理解浏览器应用工作方式的入门。它们也在每个浏览器中都得到了实现，并已存在数十年。如今，许多 Web 应用仍在使用表单元素，但用由 JavaScript 驱动的异步请求取代了同步的 POST 请求，¹³ 通过隐藏发起 HTTP 请求的耗时，让应用更迅捷。作为迅捷的代价，这些 JavaScript 代码现在必须处理错误、校验输入并指示加载时间。无论如何，表单的同步与异步用法都建立在同样的客户端与服务器代码原理之上。

> **深入探索**
> 除了 GET 和 POST，还有别的请求类型，比如 PUT [12]（不存在则创建）和 DELETE [13]，以及更冷僻的 CONNECT 和 TRACE。2010 年，PATCH 方法 [14] 在 RFC 5789 [15] 中标准化。新方法本意是作为 HTTP 的一种标准扩展机制，一些协议也确实以这种方式构建（比如 WebDAV [16] 的 PROPFIND、MOVE 和 LOCK 方法），但这并没有成为扩展 Web 本身的持久方式，HTTP 2.0 和 3.0 也没有增加任何新方法。

## 8.6 接收 POST 请求

为了更好地理解请求/响应循环，让我们写一个简单的 Web 服务器（web server）。它将实现一个在线留言簿（guest book），¹⁴ 有点像一个公开的匿名评论区。这是一本讲 Web 浏览器工程的书，所以我不会那么透彻地讨论 Web 服务器的实现。但我希望你能看到一个应用的服务器端是如何工作的。

Web 服务器是与 Web 浏览器相互独立的另一个程序，所以我们来新建一个文件。这个服务器需要：

- 打开一个套接字（socket）并监听连接；
- 解析收到的 HTTP 请求；
- 用 HTML 网页响应这些请求。

先从打开套接字开始。与浏览器那边一样，我们需要创建一个使用 TCP 的互联网流式套接字：

```python
import socket
s = socket.socket(
    family=socket.AF_INET,
    type=socket.SOCK_STREAM,
    proto=socket.IPPROTO_TCP)
s.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
```

setsockopt 这个调用是可选的。通常，当一个程序开着套接字时崩溃了，操作系统会在一小段时间内禁止复用该端口。¹⁵ 这在开发服务器时很烦人；带上 SO_REUSEADDR 选项调用 setsockopt，就可以让操作系统立即复用该端口。

现在，对这个套接字，我们不再调用 connect（去连接别的服务器），而是调用 bind，等待其他计算机来连接：

```python
s.bind(('', 8000))
s.listen()
```

先看 bind 调用。它的第一个参数说明谁被允许连接到这台服务器；空字符串意味着任何人都可以连接。第二个参数是别人与我们服务器通信时必须使用的端口；我选了 8000。我没法用 80，因为低于 1024 的端口需要管理员权限；不过如果由于某种原因，你的机器上 8000 端口被占用了，也可以挑一个 8000 以外的端口。最后，在 bind 调用之后，listen 调用告诉操作系统，我们已准备好接受连接。

要真正接受这些连接，我们进入一个循环，每个连接执行一轮。循环的开头调用 s.accept 来等待新连接：

```python
while True:
    conx, addr = s.accept()
    handle_connection(conx)
```

令人困惑的是，那个连接对象（connection object）也是一个套接字：它是对应着那一个连接的套接字。我们知道拿它能做什么：读取内容并解析 HTTP 消息。但在服务器这边做这件事比浏览器那边稍麻烦，因为服务器不能一直从套接字读数据、读到连接关闭为止——浏览器正在等待服务器，不会关闭连接。所以我们必须逐行从套接字读取。首先，读取请求行（request line）：

```python
def handle_connection(conx):
    req = conx.makefile("b")
    reqline = req.readline().decode('utf8')
    method, url, version = reqline.split(" ", 2)
    assert method in ["GET", "POST"]
```

然后读取各个头字段，直到遇到空行为止，并把它们累积到一个字典（dictionary）里：

```python
def handle_connection(conx):
    # ...
    headers = {}
    while True:
        line = req.readline().decode('utf8')
        if line == '\r\n': break
        header, value = line.split(":", 1)
        headers[header.casefold()] = value.strip()
```

最后读取请求主体，但仅当 Content-Length 头字段告诉我们该读多少时才读（这正是该头字段在 POST 请求中为必需的原因）：

```python
def handle_connection(conx):
    # ...
    if 'content-length' in headers:
        length = int(headers['content-length'])
        body = req.read(length).decode('utf8')
    else:
        body = None
```

现在，服务器需要生成一个网页作为响应。这部分稍后再讲；眼下先把它抽象到一个 do_request 调用背后：

```python
def handle_connection(conx):
    # ...
    status, body = do_request(method, url, headers, body)
```

然后服务器把这个页面发回浏览器：

```python
def handle_connection(conx):
    # ...
    response = "HTTP/1.0 {}\r\n".format(status)
    response += "Content-Length: {}\r\n".format(
        len(body.encode("utf8")))
    response += "\r\n" + body
    conx.send(response.encode('utf8'))
    conx.close()
```

服务器的架构概括在图 8.3 中。我们的实现相当简陋：服务器不检查浏览器是否在用 HTTP 1.0 与它通信；除了 Content-Length 之外完全不返回任何头字段；不支持 TLS；等等。再说一遍：这是一本讲 Web 浏览器的书——够用就行。

*图 8.3　本章简单 Web 服务器的架构。*
（示意图：`if __name__` → `socket.accept` → `handle_connection` → 解析 HTTP → `do_request` → 分派至 `show_comments`、`add_entry` 或 `not_found`）

> Ilya Grigorik 的《High Performance Browser Networking》[17] 对网络以及在 Web 应用中如何为之优化做了一次出色的深入探讨。客户端可以做一些事（减少请求数、避免轮询、复用连接），服务器也可以做一些事（压缩、协议支持、共享域名）。

## 8.7 生成网页

到目前为止，这些服务器代码全都是「样板」（boilerplate）——任何 Web 应用都会有类似的代码。而让我们的服务器成为留言簿的，是 do_request 内部所做的事情。它需要存储留言簿状态、生成 HTML 页面，并响应 POST 请求。

我们把留言簿条目存放在一个 Python 列表里。通常，Web 应用会使用持久化状态（persistent state），比如数据库（database），这样服务器重启后也不会丢失状态，但我们的留言簿不必如此坚韧。

```python
ENTRIES = [ 'Pavel was here' ]
```

接下来，do_request 要输出展示这些条目的 HTML：

```python
def do_request(method, url, headers, body):
    out = "<!doctype html>"
    for entry in ENTRIES:
        out += "<p>" + entry + "</p>"
    return "200 OK", out
```

这绝对是「极简」HTML，好在我们的浏览器会插入隐式标签（implicit tag）并且自带一些默认样式！你可以运行这个极简 Web 服务器来测试：在它运行期间，把浏览器指向 http://localhost:8000/。其中 localhost 是你的计算机对自身的称呼，8000 则是我们先前选的端口。你应该会看到一条留言簿条目。

顺便说一句，在调试这个 Web 服务器时，改用真实浏览器（而不是本书的浏览器）与它交互可能更好。这样你在修服务器的 bug 时就不必同时操心浏览器的 bug。不过这个服务器对真实浏览器和玩具浏览器都支持。

我们将用表单让访客在留言簿上留言：

```python
def do_request(method, url, headers, body):
    # ...
    out += "<form action=add method=post>"
    out +=   "<p><input name=guest></p>"
    out +=   "<p><button>Sign the book!</button></p>"
    out += "</form>"
    # ...
```

提交这个表单时，浏览器会向 http://localhost:8000/add 发送一个 POST 请求。所以服务器需要对这些提交作出反应。这意味着 do_request 要处理两类请求：常规浏览和表单提交。我们把这两类请求分开到不同的函数中。首先，把现在的 do_request 改名为 show_comments：

```python
def show_comments():
    # ...
    return out
```

这就把 do_request 函数腾了出来，让它负责判断对每个请求该调用哪个函数：

```python
def do_request(method, url, headers, body):
    if method == "GET" and url == "/":
        return "200 OK", show_comments()
    elif method == "POST" and url == "/add":
        params = form_decode(body)
        return "200 OK", add_entry(params)
    else:
        return "404 Not Found", not_found(url, method)
```

发往 /add 的 POST 请求到来时，第一步是解码请求主体：

```python
def form_decode(body):
    params = {}
    for field in body.split("&"):
        name, value = field.split("=", 1)
        name = urllib.parse.unquote_plus(name)
        value = urllib.parse.unquote_plus(value)
        params[name] = value
    return params
```

注意，这里我用的是 unquote_plus 而不是 unquote，因为浏览器也可能用加号来编码空格。接着，add_entry 函数查找 guest 参数，并把它的内容添加为一条新的留言簿条目：

```python
def add_entry(params):
    if 'guest' in params:
        ENTRIES.append(params['guest'])
    return show_comments()
```

我还加了一个「404」响应。为契合我们留言簿的朴素风格，这就是 404 页面：

```python
def not_found(url, method):
    out = "<!doctype html>"
    out += "<h1>{} {} not found!</h1>".format(method, url)
    return out
```

试一试吧！你应该可以重启服务器、在浏览器中打开它，并多次更新留言簿。你也应该可以在真实浏览器中使用这个留言簿。

## 8.10 练习

**8.1　回车键。** 在大多数浏览器中，如果焦点位于某个文本输入框内时按下「Enter」或「Return」键，就会提交该输入框所在的表单。为你的浏览器添加这一特性。

**8.2　GET 表单。** 表单既可以通过 POST 请求提交，也可以通过 GET 请求提交。在 GET 请求中，表单编码的数据会被拼接到 URL 的末尾，与路径之间用问号分隔，例如 /search?q=hi；GET 表单提交没有请求主体。实现 GET 表单提交。

**8.3　失焦。** 目前，如果你先点击某个文本输入框内部，再点击地址栏，屏幕上会出现两个光标。要修复这个问题，请给每个 Tab 添加一个 blur 方法，让它取消任何已聚焦对象的焦点，并在改变焦点之前调用它。

**8.4　复选框。** 在 HTML 中，input 元素有一个 type 属性。当它设为 checkbox 时，input 元素看起来就像一个复选框（checkbox）；如果设置了 checked 属性，它就是勾选状态，否则为未勾选。¹⁶ 提交表单时，只有复选框被勾选，它的 name=value 对才会被包含进去。（如果复选框没有 value 属性，默认值是字符串 on。）

**8.5　重新提交请求。** 区分 GET 与 POST 请求的一个原因是：GET 请求应当是幂等的（idempotent，基本上就是只读），而 POST 请求则被认为会改变 Web 服务器的状态。这意味着「后退」到一个 GET 请求（重新发起该请求）是安全的，而「后退」到一个 POST 请求则不是个好主意。修改浏览器历史，让它记录访问每个 URL 所使用的方法，以及所用到的 POST 请求主体。当你后退到一个曾以 POST 访问的 URL 时，询问用户是否要重新提交表单。如果用户说不，就不要后退；如果说是，就提交一个与之前请求主体相同的 POST 请求。

**8.6　留言板。** 现在我们的 Web 服务器只是一个简单的留言簿。通过增加对主题的支持，把它扩展成一个简单的留言板。每个主题应当有自己的 URL 和自己的消息列表。例如，/cooking 应当是一个帖子页（关于烹饪），通过该页面上的表单提交的评论应当只在访问 /cooking 时出现，而在访问 /cars 时不出现。让位于 / 的主页列出可用主题，并附上指向每个主题页面的链接。让用户可以添加新主题。

**8.7　持久化。** 用一个文件来支撑服务器的留言簿条目列表，这样服务器重启后就不会丢失数据。

**8.8　富按钮。** 让按钮可以包含任意元素作为子节点，并正确渲染它们。子元素应当被容纳在按钮内部而不是溢出——这可能让按钮变得非常高。想一想边界情况，比如按钮里包含另一个按钮、一个输入区或一个链接，并测试真实浏览器看看它们会怎么做。

**8.9　HTML 镶边。** 在真实浏览器中，浏览器镶边相当复杂，有字号、内边距（padding）、轮廓（outline）、阴影、图标等棘手的细节。这让人很想尝试复用我们的布局引擎（layout engine）来实现它。动手实现吧：用 <button> 元素做新建标签页按钮和后退按钮，用 <input> 元素做地址栏，用 <a> 元素做标签页名称。它看起来不会与现在的镶边一模一样——比如 outline 要等到第 14 章——但只要调整默认 CSS，你应该能让它看起来还过得去。¹⁷

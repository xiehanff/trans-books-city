# 第 2 章　一元运算符

*Chapter 2: Unary Operators*

C 语言有若干一元运算符（unary operator），它们只作用于单个值。在本章中，你将扩展编译器来处理两个一元运算符：取负（negation）和按位取反（bitwise complement）。你将把复杂、嵌套的一元表达式变换成可以用汇编表达的简单操作。我们不会在单独一个编译遍（pass）中完成这个变换，而是引入一种新的中间表示（intermediate representation，IR），放在语法分析器产生的抽象语法树（AST）与汇编生成遍产生的汇编 AST 之间。你还会把汇编生成拆分成若干个更小的遍。本章开头示意图中加粗标出的就是这些新增的遍。

在动手之前，我们先看一个使用新的一元运算符的 C 程序，以及我们将生成的对应汇编代码。

## 汇编中的取负与按位取反

在本章中，你将学会编译类似清单 2-1 的程序。

```c
int main(void) {
    return ~(-2);
}
```

*清单 2-1：一个使用取负和按位取反的 C 程序*

这个程序包含一个同时用到两个新的一元运算符的嵌套表达式。第一个运算符是取负（`-`），它对一个整数取负——这没什么意外的。按位取反（`~`）运算符会翻转整数的每一个二进制位，其效果等同于对该整数取负后再减一。（之所以有这样的效果，是因为计算机使用一种称为补码（two's complement）的系统来表示有符号整数。如果你不熟悉补码，可以参见第 45 页的“延伸资源”，其中有几篇解释其工作原理的文章链接。）

你的编译器会把清单 2-1 转换为清单 2-2 中的汇编代码。

```asm
    .globl main
main:
    pushq   %rbp
    movq     %rsp, %rbp
    subq     $8, %rsp
  ❶ movl     $2, ❷ -4(%rbp)
  ❸ negl     -4(%rbp)
  ❹ movl     -4(%rbp), %r10d
  ❺ movl     %r10d, -8(%rbp)
  ❻ notl     -8(%rbp)
  ❼ movl     -8(%rbp), %eax
    movq     %rbp, %rsp
    popq     %rbp
    ret
```

*清单 2-2：清单 2-1 对应的汇编代码*

`main` 之后的前三条指令构成函数序言（function prologue），它负责建立当前的栈帧（stack frame）；我会在下一节详细讨论栈的时候介绍它们。在函数序言之后，我们先计算中间结果 -2，再计算最终结果 1，并把每个结果存储到一个独一无二的内存地址。这样做的效率并不高，因为我们浪费了大量指令在不同的地址之间复制值。我们在第 III 部分实现的优化会清掉大部分这类多余的复制。

第一条 `mov` 指令❶把 2 存入内存中的某个地址。操作数 `-4(%rbp)`❷的意思是“RBP 寄存器中存储的值减去四”。RBP 中的值是栈上的一个内存地址（稍后详述），因此 `-4(%rbp)` 指向比它低 4 字节的另一个内存地址。接着，我们用 `neg` 指令❸对这个地址上的值取负，于是 `-4(%rbp)` 中存储的值变成了 -2。（和 `mov` 一样，`neg` 也有一个 `l` 后缀，表明它操作的是 32 位的值。）

然后我们处理外层的按位取反表达式。我们先把存储在 `-4(%rbp)` 中的源值复制到目的地址 `-8(%rbp)`。这一步无法用一条指令完成，因为 `mov` 的源操作数和目的操作数不能同时是内存地址——`mov` 的两个操作数中至少要有一个是寄存器或立即数（immediate value）。为了绕过这个限制，我们先把 -2 从内存复制到暂存寄存器（scratch register）R10D❹，再从那里复制到目的内存地址❺。然后，我们用 `not` 指令❻对 -2 按位取反，于是内存地址 `-8(%rbp)` 中现在存储的就是我们要返回的值：`~(-2)`，其求值结果为 1。为了返回这个值，我们把它移入 EAX❼。最后三条指令是函数尾声（function epilogue），它负责拆除栈帧并从函数返回。

> **注意**
>
> 如果你用 GCC、Clang 或其他任何生产级 C 编译器把清单 2-1 编译成汇编，得到的代码不会和清单 2-2 有任何相似之处。这是因为那些编译器会在编译期求值常量表达式，即使你关闭了优化也是如此！我猜它们这样做的原因是：某些常量表达式（比如静态变量的初始化器）必须在编译期求值，而把所有常量表达式都在编译期求值，要比只对其中的部分求值更简单。

## 栈

关于清单 2-2，还有两个问题没有回答：函数序言和尾声到底做了什么，以及我们为什么要相对于 RBP 寄存器中的值来引用栈地址。要回答这些问题，我们需要谈谈程序内存中称为栈（stack）的那一段。RSP 寄存器也称为栈指针（stack pointer），它始终保存栈顶的地址。（RSP 指向最后一个已使用的栈槽，而不是第一个空闲的栈槽。）与任何栈数据结构一样，你可以把值压入（push）栈中，也可以把值从栈中弹出（pop）；`push` 和 `pop` 汇编指令做的正是这件事。

栈朝更低的内存地址方向增长。当你向栈中压入某个值时，RSP 会递减。这意味着“栈顶”——RSP 中存储的地址——是栈上最低的地址。本书中的栈示意图都把较低的内存地址放在顶部，因此栈顶位于示意图的上方。你可以把这些示意图中的内存地址想象成代码清单里的行号：代码清单的第一行是第 1 行，行号往下递增；同样，这些示意图中的地址也沿着页面向下递增。注意，大多数其他书籍和文章中的栈示意图采用相反的方向：它们把栈顶放在示意图的底部，因此较低的内存地址出现在页面下方。我觉得那种布局实在让人困惑，不过如果你更喜欢它，把书倒过来读就行了。

像 `push $3` 这样的指令做两件事：

1. 把要压入的值（本例中是 3）写入栈上的下一个空位。`push` 和 `pop` 指令以 8 字节为步长调整栈指针，而栈顶的值当前就位于 RSP 中存储的地址处，因此下一个空位是 RSP – 8。
2. 把 RSP 递减 8 字节。RSP 中的新地址现在就是栈顶，且该地址处的值为 3。

图 2-1 展示了 `push` 指令对栈和 RSP 寄存器的影响。

*图 2-1：`push $3` 对内存和 RSP 的影响*

`pop` 指令执行相反的操作。例如，`pop %rax` 会把栈顶的值复制到 RAX 寄存器中，然后给 RSP 加上 8 字节。

由于 `push` 指令把栈指针递减 8 字节，它必须压入一个 8 字节的值。同样，`pop` 指令总是从栈中弹出 8 字节的值。而 `int` 类型的值——比如清单 2-1 中的返回值——只有 4 字节。你不能只把 4 字节压入栈，但可以用 `movl` 把一个 4 字节的值复制到已经分配好的栈空间中。清单 2-2 中有几条指令就是这么做的，包括 `movl $2, -4(%rbp)`。（在 32 位系统上情况正好相反：你可以压入和弹出 4 字节的值，但不能是 8 字节的值。在这两类系统上，也可以用 `pushw` 和 `popw` 指令压入和弹出 2 字节的值，尽管这非常罕见；`w` 后缀代表 word（字），表示该指令接受 2 字节的操作数。本书不会使用 `pushw`、`popw` 或其他任何 2 字节指令。）x64 系统上的内存地址是 8 字节，所以可以用 `push` 和 `pop` 把它们压入和弹出栈。这一点马上就会派上用场。

栈并不是一块无差别的内存；它被划分为一个个称为栈帧的区域。每当函数被调用时，它都会通过递减栈指针在栈顶分配一些内存。这块内存就是该函数的栈帧，函数在其中存储局部变量和临时值。就在函数返回之前，它会释放自己的栈帧，把栈指针恢复为原来的值。按照惯例，RBP 寄存器指向当前栈帧的基底，因此它有时也被称为基指针（base pointer）。我们相对于 RBP 中存储的地址来引用当前栈帧中的数据。这意味着我们不需要绝对地址——绝对地址是我们无法提前知道的。由于栈朝更低的内存地址增长，当前栈帧中的每个地址都低于 RBP 中存储的地址；这就是为什么局部变量的地址（如 `-4(%rbp)`）相对于 RBP 的偏移量全都是负的。在后面的章节中，我们还会相对于 RBP 引用调用者栈帧中的数据，比如函数参数。（也可以改为相对于 RSP 引用局部变量和参数，完全不碰 RBP；大多数生产级编译器把这作为一种优化手段。）

现在你理解了栈的工作方式，我们来更详细地看看函数序言和尾声。函数序言用三条指令建立栈帧：

1. `pushq %rbp` 把 RBP 的当前值——即调用者栈帧基底的地址——保存到栈上。稍后恢复调用者的栈帧时会用到这个值。这个值将位于下一条指令所建立的新栈帧的底部。
2. `movq %rsp, %rbp` 使栈顶成为新栈帧的基底。此时，当前栈帧的顶部和底部是同一个位置。当前栈帧恰好保存一个值，RSP 和 RBP 都指向它：也就是我们在上一条指令中保存的调用者栈帧的基底。
3. `subq $n, %rsp` 把栈指针递减 n 字节。现在栈帧中有 n 字节可用于存储局部变量和临时变量。

图 2-2 展示了函数序言中每条指令对栈的影响。在这幅图中，`subq` 指令分配了 24 字节，足够容纳六个 4 字节整数。

*图 2-2：函数序言中各时刻的栈状态*

函数尾声通过把 RSP 和 RBP 恢复为函数序言之前的值，来恢复调用者的栈帧。这需要两条指令：

1. `movq %rbp, %rsp` 让我们回到函数序言第二条指令之后的状态：RSP 和 RBP 都指向当前栈帧的底部，其中保存着调用者的 RBP 值。
2. `popq %rbp` 逆转函数序言的第一条指令，为 RSP 和 RBP 寄存器恢复调用者的值。它之所以能恢复 RBP，是因为栈顶的值正是我们在序言开头保存的调用者栈帧的基底地址。它之所以能恢复 RSP，是因为它把这个栈帧中的最后一个值从栈上移除，使 RSP 指向调用者栈帧的顶部。

## 词法分析器

在本章中，你将扩展词法分析器（lexer）来识别三个新的词法单元（token）：

| 词法单元 | 含义 |
| --- | --- |
| `~` | 波浪号（tilde），按位取反运算符 |
| `-` | 连字符（hyphen），取负运算符 |
| `--` | 两个连字符，自减（decrement）运算符 |

虽然本章不会实现自减运算符，但你仍然需要为它添加一个词法单元。否则，你的编译器会接受本应拒绝的程序，比如清单 2-3 中的程序。

```c
int main(void) {
    return --2;
}
```

*清单 2-3：一个使用自减运算符的非法 C 程序*

这个程序不应该通过编译，因为你不能对一个常量做自减。但如果你的编译器不知道 `--` 是一个独立的词法单元，它就会认为清单 2-3 等价于清单 2-4，而后者是一个完全合法的程序。

```c
int main(void) {
    return -(-2);
}
```

*清单 2-4：一个连续使用两个取负运算符的合法 C 程序*

你的编译器应当拒绝那些你尚未实现的语言特性，而不是错误地编译它们。这就是为什么你的词法分析器需要知道 `--` 是单个词法单元，而不只是连续两个取负运算符。（另一方面，词法分析器应当把 `~~` 词法分析为连续两个按位取反运算符。像 `~~2` 这样的表达式是合法的。）

处理这些新词法单元的方式，与你在第 1 章中处理 `;` 和 `(` 之类标点符号的方式相同。首先，你需要为每个新词法单元定义一个正则表达式（regular expression）。这里的正则表达式就是字符串 `~`、`-` 和 `--`。接下来，让词法分析器在每次尝试产生一个词法单元时，把输入流的开头与这些新正则表达式以及上一章的正则表达式逐一比对。当输入流的开始处可以匹配多于一个可能的词法单元时，选择最长的那个。例如，如果输入流以 `--` 开头，就把它解析为自减运算符，而不是两个取负运算符。

## 语法分析器

要解析本章的新运算符，我们首先需要扩展第 1 章中定义的 AST 和形式文法。先看 AST。由于一元运算本身就是表达式，我们为 exp AST 节点添加一个新的构造器来表示它们。清单 2-5 给出了更新后的 AST 定义，新增部分以粗体标出。

```text
program = Program(function_definition)
function_definition = Function(identifier name, statement body)
statement = Return(exp)
exp = Constant(int) | Unary(unary_operator, exp)
unary_operator = Complement | Negate
```

*清单 2-5：带一元运算的抽象语法树*

更新后的 exp 规则表明，一个表达式要么是一个整型常量，要么是一个一元运算。一元运算由两个一元运算符（Complement 或 Negate）之一作用于一个内层表达式构成。注意 exp 的定义是递归的：exp 节点的 Unary 构造器内部包含另一个 exp 节点。这让我们能够构造任意深度嵌套的表达式，比如 `-(~(-~-(-4)))`。

我们还需要对文法做相应的修改，如清单 2-6 所示。

```text
<program> ::= <function>
<function> ::= "int" <identifier> "(" "void" ")" "{" <statement> "}"
<statement> ::= "return" <exp> ";"
<exp> ::= <int> | <unop> <exp> | "(" <exp> ")"
<unop> ::= "-" | "~"
<identifier> ::= ? 一个标识符词法单元 ?
<int> ::= ? 一个常量词法单元 ?
```

*清单 2-6：带一元运算的形式文法*

清单 2-6 为一元表达式新增了一条产生式（production rule），并新增了一个 `<unop>` 符号来表示两个一元运算符。这些修改与清单 2-5 中对 AST 的扩充一一对应。我们还为 exp 符号添加了第三条产生式，用于描述带括号的表达式。它在 AST 中没有对应的构造器，因为编译器的其余部分不需要区分带括号的表达式和不带括号的同一个表达式。表达式 `1`、`(1)` 和 `((((1))))` 都由同一个 AST 节点表示：`Constant(1)`。

自减运算符（`--`）在这个文法中完全没有出现，所以语法分析器遇到 `--` 词法单元时应当报错。

为了更新语法分析阶段，请修改编译器的 AST 数据结构以匹配清单 2-5。然后，更新你的递归下降（recursive descent）语法分析代码，以反映清单 2-6 中的改动。本章中解析表达式变得稍微复杂了一些，因为你需要判断应当应用 `<exp>` 符号的三条不同产生式中的哪一条。清单 2-7 中的伪代码演示了如何解析一个表达式。

```text
parse_exp(tokens):
    next_token = peek(tokens)
  ❶ if next_token is an int:
        --snip--
  ❷ else if next_token is "~" or "-":
        operator = parse_unop(tokens)
        inner_exp = parse_exp(tokens)
      ❸ return Unary(operator, inner_exp)
  ❹ else if next_token == "(":
        take_token(tokens)
        inner_exp = parse_exp(tokens)
        expect(")", tokens)
      ❺ return inner_exp
  ❻ else:
        fail("Malformed expression")
```

*清单 2-7：解析一个表达式*

首先，我们查看输入中的下一个词法单元，判断应当应用哪条产生式。我们调用 `peek` 来查看这个词法单元，而不把它从输入流中移除。一旦知道该用哪条产生式，我们就要用那条规则处理整个输入，包括第一个词法单元。所以，我们暂时还不想从输入中消费这个词法单元。

如果我们将要解析的表达式是合法的，next_token 应当是一个整数、一个一元运算符，或者一个左括号。如果它是一个整数❶，我们按照上一章的方式来解析它。如果它是一个一元运算符❷，我们应用清单 2-6 中 `<exp>` 的第二条产生式来构造一个一元表达式。这条产生式是 `<unop> <exp>`，所以我们先解析一元运算符，再解析内层表达式。`<unop>` 符号是单个词法单元 next_token，我们已经检查过它了。在清单 2-7 中，我们用一个单独的函数来处理 `<unop>`（parse_unop，其定义已省略）。实践中，解析单个词法单元多半不需要单独的函数。无论采用哪种方式，我们最终都会得到一个表示相应一元运算符的 AST 节点。产生式中的下一个符号是 `<exp>`，我们通过递归调用 parse_exp 来解析它。（这就是“递归下降”中“递归”的由来。）这次调用应返回一个表示该一元表达式的操作数（operand）的 exp AST 节点。现在我们有了运算符和操作数各自的 AST 节点，于是返回整个一元表达式的 AST 节点❸。

如果 next_token 是左括号❹，我们应用 `<exp>` 的第三条产生式，即 `"(" <exp> ")"`。我们从输入流中移除左括号，然后递归调用 parse_exp 处理其后的表达式。接着，我们调用 expect 移除右括号；如果右括号缺失就抛出语法错误。由于 AST 不需要记录括号的存在，我们直接原样返回内层表达式❺。

最后，如果 next_token 既不是整数、一元运算符，也不是左括号❻，说明表达式格式错误，于是抛出语法错误。

## TACKY：一种新的中间表示

把 AST 转换为汇编不再像上一章那样直接。C 表达式可以有嵌套的子表达式，而汇编指令不行。像 `-(~2)` 这样的单个表达式需要被拆分成两条汇编指令：一条应用内层的按位取反操作，另一条应用外层的取负操作。

我们将用一种新的中间表示——三地址码（three-address code，TAC）——来弥合 C 与汇编之间的鸿沟。在三地址码中，每条指令的操作数是常量或变量，而不是嵌套表达式。它之所以叫三地址码，是因为大多数指令最多使用三个值：两个源操作数和一个目的操作数。（本章的指令只使用一个或两个值；等到第 3 章实现二元运算符时，我们会引入使用三个值的指令。）为了用三地址码改写嵌套表达式，我们常常需要引入新的临时变量。例如，清单 2-8 给出了 `return 1 + 2 * 3;` 的三地址码。

```text
tmp0 = 2 * 3
tmp1 = 1 + tmp0
return tmp1
```

*清单 2-8：`return 1 + 2 * 3;` 的三地址码*

使用三地址码而不是把 AST 直接转换成汇编，主要有两个原因。第一，它让我们能把重大的结构性变换——比如消除嵌套表达式——与汇编语言的细节（比如弄清哪些指令允许哪些操作数）分开处理。这意味着我们可以编写若干个更小、更简单的编译遍，而不是一个庞大而复杂的汇编生成遍。第二，三地址码非常适合我们在第 III 部分要实现的多种优化。它结构简单而统一，很容易回答诸如“这个表达式的结果有没有被使用？”或“这个变量的值是否始终相同？”之类的问题。这些问题的答案决定了执行哪些优化是安全的。

> **多语言、多目标**
>
> 像三地址码这样的中间表示之所以有用，还有另一个原因，尽管它与本项目无关。IR 可以为多种源语言提供公共的编译目标，也可以为面向多种目标架构的汇编生成提供公共的起点。LLVM 编译器框架（https://llvm.org）就是一个绝佳的例子：它用单一的中间表示支持多个前端和后端。如果你想编译一门新的编程语言，只需把它编译到 LLVM IR，LLVM 会负责优化该 IR 并为不同的 CPU 架构生成机器码。又或者，你想让软件运行在某种新奇的目标 CPU 架构上，只需编写一个把 LLVM IR 转换为该架构机器码的后端。这样，任何带有 LLVM 前端的语言都可以被编译到那种架构上。

大多数编译器内部都使用某种形式的三地址码，但细节各有不同。我决定把本书中的中间表示命名为 TACKY。（给中间表示起名字，在我看来是编译器设计最有趣的部分之一。）TACKY 是我为本书发明的，但它与其他编译器中的三地址码很相似。

### 定义 TACKY

我们将像定义其他中间表示一样，用 ASDL 来定义 TACKY。清单 2-9 中 TACKY 的定义看起来与清单 2-5 中的 AST 定义相似，但有几个重要区别。

```text
program = Program(function_definition)
function_definition = Function(identifier, ❶ instruction* body)
instruction = Return(val) | Unary(unary_operator, val src, val dst)
val = Constant(int) | Var(identifier)
unary_operator = Complement | Negate
```

*清单 2-9：TACKY 中间表示*

在 TACKY 中，函数体由一个指令列表❶构成，而不是单条语句。在这一点上，它与我们上一章定义的汇编 AST 相似。目前 TACKY 有两条指令：Return 和 Unary。Return 返回一个值；Unary 对表达式的源值 src 执行某个一元运算，并把结果存入目的值 dst。这两条指令都作用于 val，val 既可以是整型常量（Constant），也可以是临时变量（Var）。我们生成的 TACKY 必须满足一个清单 2-9 中没有明确写出的要求：一元运算的 dst 必须是临时 Var，而不能是 Constant。给常量赋值是没有意义的。

看过了 TACKY 的 ASDL 定义之后，你需要在自己的编译器中实现这个定义，就像实现 AST 和汇编 AST 的定义一样。有了 TACKY 数据结构之后，你就可以编写 IR 生成阶段了，它把 AST 转换为 TACKY。

### 生成 TACKY

你的 TACKY 生成遍应当遍历清单 2-5 那种形式的 AST，并返回清单 2-9 那种形式的 TACKY。棘手的部分是把 exp 节点变成一个指令列表；解决了这个问题之后，处理其他 AST 节点就容易了。表 2-1 列出了几个 AST 及其对应 TACKY 的例子。

*表 2-1：一元表达式的 TACKY 表示*

| AST | TACKY |
| --- | --- |
| Return(Constant(3)) | Return(Constant(3)) |
| Return(Unary(Complement, Constant(2))) | Unary(Complement, Constant(2), Var("tmp.0"))<br>Return(Var("tmp.0")) |
| Return(Unary(Negate,<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;Unary(Complement,<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;Unary(Negate, Constant(8))))) | Unary(Negate, Constant(8), Var("tmp.0"))<br>Unary(Complement, Var("tmp.0"), Var("tmp.1"))<br>Unary(Negate, Var("tmp.1"), Var("tmp.2"))<br>Return(Var("tmp.2")) |

在这些例子中，我们把每个一元运算转换为一条 Unary TACKY 指令，从最内层的表达式开始，逐步向外处理。我们把每条 Unary 指令的结果存入一个临时变量，然后在更外层的表达式或 return 语句中使用它。清单 2-10 描述了如何把 exp AST 节点转换为 TACKY。

```text
emit_tacky(e, instructions):
    match e with
  ❶ | Constant(c) ->
        return ❷ Constant(c)
    | Unary(op, inner) ->
        src = emit_tacky(inner, instructions)
        dst_name = make_temporary()
        dst = Var(dst_name)
        tacky_op = convert_unop(op)
        instructions.append(Unary(tacky_op, src, dst))
        return dst
```

*清单 2-10：把一个表达式转换成 TACKY 指令列表*

这段伪代码通过向 instructions 参数追加指令，来发出计算表达式所需的指令。它还返回一个表示表达式结果的 TACKY val，供我们翻译外层表达式或语句时使用。

清单 2-10 中的 match 语句检查我们正在翻译哪种类型的表达式，然后运行处理该表达式的子句。如果表达式是常量，我们直接返回等价的 TACKY Constant，不生成任何新指令。注意，这段代码里出现了两个不同的 Constant 构造：我们匹配的那个❶是原始 AST 中的节点，而我们返回的那个❷是 TACKY AST 中的节点。下面一个子句中出现的两个 Unary 构造也是如此。

如果 e 是一元表达式，我们为源和目的构造 TACKY 值。首先，我们对源表达式递归调用 emit_tacky，得到对应的 TACKY 值；这同时也会生成计算该值的 TACKY 指令。然后，我们为目的创建一个新的临时变量。辅助函数 make_temporary 为这个变量生成一个唯一的名字。我们再用另一个辅助函数 convert_unop 把一元运算符转换为它在 TACKY 中的等价形式。有了源、目的和一元运算符之后，我们构造 Unary TACKY 指令，并把它追加到指令列表中。最后，我们返回 dst 作为整个表达式的结果。

请记住，emit_tacky 处理的是表达式，而不是 return 语句。你需要一个单独的函数（我不会给出它的伪代码）把 return 语句转换为 TACKY。这个函数应当调用 emit_tacky 处理语句的返回值，然后发出一条 TACKY Return 指令。

### 为临时变量生成名称

显然，每个临时变量都需要一个互不相同的名字。在后面的章节中，我们还需要保证这些自动生成的名字不会与用户定义的函数名和全局变量名冲突，也不会与不同函数自动生成的名字冲突。这些标识符必须全部唯一，因为我们要把它们——自动生成的名字和用户定义的函数名、变量名——全部存放在同一张表里。

一个简单的解决方案是维护一个全局整数计数器；要生成一个唯一的名字，就递增计数器，并用它的新值作为临时变量的名字。这个名字不会与其他临时名字冲突，因为计数器每次递增都会产生一个新值。它也不会与用户定义的标识符冲突，因为整数不是合法的 C 标识符。在表 2-1 中，我使用了这种方案的一个变体：把一个描述性字符串、一个句点以及全局计数器的值拼接起来，生成 `tmp.0` 这样唯一的标识符。它们不会与用户定义的标识符冲突，因为 C 标识符不能包含句点。使用这种命名方案，你可以在自动生成的名字中编码有用的信息，比如使用该变量的函数的名字。（如果你把每个变量都命名为 tmp，就像我在这里做的那样，这种方案的意义就不大了。）

## 汇编生成

TACKY 离汇编更近了，但它仍没有确切指明我们需要哪些汇编指令。下一步是把程序从 TACKY 转换为上一章定义的汇编 AST。我们将用三个小编译遍来完成这件事。首先，我们生成汇编 AST，但仍直接引用临时变量。接着，我们把这些变量替换为栈上的具体地址。那一步会产生一些非法指令，因为许多 x64 汇编指令不允许两个操作数都是内存地址。因此，在最后一个编译遍中，我们将改写汇编 AST，修复所有非法指令。

### 把 TACKY 转换为汇编

我们先扩展上一章定义的汇编 AST。我们需要一些新构造来表示清单 2-2 中的 `neg` 和 `not` 指令。我们还需要决定如何在汇编 AST 中表示函数序言和尾声。

处理序言和尾声有几种不同的方式。我们可以把 `push`、`pop` 和 `sub` 指令加进汇编 AST。我们可以添加与整个序言和尾声相对应的高层指令，而不维持汇编 AST 构造与汇编指令之间的一一对应关系。或者，我们可以完全省略函数序言和尾声，在代码发射（code emission）阶段再添加它们。我将采用第一种和最后一种方式的组合。本章的汇编 AST（见清单 2-11）包含一个与 `sub` 指令（函数序言的第三条指令）对应的构造。这个构造指定我们需要从栈指针中减去多少字节。汇编 AST 不包含序言和尾声中的其他指令；这些指令总是相同的，所以我们可以在代码发射时添加它们。话虽如此，表示函数序言和尾声的其他方法同样可行，所以选一个你最喜欢的就好。

我们还将引入伪寄存器（pseudoregister）来表示临时变量。我们把伪寄存器当作汇编指令的操作数来使用，就像真实寄存器一样；唯一的区别是伪寄存器的数量是无限的。因为它们不是真实的寄存器，所以不能出现在最终的汇编程序里；在后面的编译遍中，它们需要被替换为真实的寄存器或内存地址。目前，我们会把每个伪寄存器分配到内存中一个不同的地址。在第 III 部分中，我们将编写一个寄存器分配器（register allocator），尽可能多地把伪寄存器分配到硬件寄存器而不是内存地址。

清单 2-11 给出了更新后的汇编 AST，新增部分以粗体标出。

```text
program = Program(function_definition)
function_definition = Function(identifier name, instruction* instructions)
instruction = Mov(operand src, operand dst)
            | Unary(unary_operator, operand)
            | AllocateStack(int)
            | Ret
unary_operator = Neg | Not
operand = Imm(int) | Reg(reg) | Pseudo(identifier) | Stack(int)
reg = AX | R10
```

*清单 2-11：带一元运算符的汇编 AST*

instruction 节点新增了几个构造器来表示新的汇编指令。Unary 构造器表示单条 `not` 或 `neg` 指令，它接受一个同时用作源和目的的操作数。AllocateStack 构造器表示函数序言的第三条指令 `subq $n, %rsp`。它唯一的孩子是一个整数，指明我们从 RSP 中减去的字节数。

我们还有几个新的指令操作数。Reg 构造器表示一个硬件寄存器。它可以指定到目前为止我们见过的两个硬件寄存器中的任意一个：EAX 或 R10D。Pseudo 操作数让我们可以用任意标识符作为伪寄存器；我们用它来指代生成 TACKY 时产生的临时变量。最终，我们需要把每个伪寄存器替换为栈上的一个位置；我们用 Stack 操作数来表示这些位置，它指明相对于 RBP 的给定偏移处的栈地址。例如，我们用汇编 AST 节点 `Stack(-4)` 来表示操作数 `-4(%rbp)`。

> **注意**
>
> 每个硬件寄存器都有若干别名，取决于你需要使用寄存器的多少个字节。EAX 指 64 位 RAX 寄存器的低 32 位，R10D 指 64 位 R10 寄存器的低 32 位。名字 AL 和 R10B 分别指 RAX 和 R10 的低 8 位。汇编 AST 中的寄存器名与大小无关，因此清单 2-11 中的 AX 根据上下文可以指寄存器别名 RAX、EAX 或 AL。（AX 这个名字通常指 RAX 的低 16 字节，但本书不会使用 16 字节的寄存器别名。）

现在我们可以编写从 TACKY 到汇编的直接转换了，如表 2-2 至表 2-5 所示。如表 2-2 所示，我们把 TACKY 的 Program 和 Function 节点转换为对应的汇编构造。

*表 2-2：把顶层 TACKY 构造转换为汇编*

| TACKY 顶层构造 | 汇编顶层构造 |
| --- | --- |
| Program(function_definition) | Program(function_definition) |
| Function(name, instructions) | Function(name, instructions) |

我们会把每条 TACKY 指令转换为一个汇编指令序列，如表 2-3 所示。由于新的汇编指令的源和目的使用同一个操作数，我们在发出一元的 `neg` 或 `not` 指令之前，先把源值复制到目的。

*表 2-3：把 TACKY 指令转换为汇编*

| TACKY 指令 | 汇编指令 |
| --- | --- |
| Return(val) | Mov(val, Reg(AX))　Ret |
| Unary(unary_operator, src, dst) | Mov(src, dst)　Unary(unary_operator, dst) |

*表 2-4：把 TACKY 算术运算符转换为汇编*

| TACKY 运算符 | 汇编运算符 |
| --- | --- |
| Complement | Not |
| Negate | Neg |

*表 2-5：把 TACKY 操作数转换为汇编*

| TACKY 操作数 | 汇编操作数 |
| --- | --- |

| Var(identifier) | Pseudo(identifier) |

注意，我们目前还没有使用 AllocateStack 指令；等知道了需要分配多少字节之后，我们会在代码发射前的最后一个遍中添加它。我们也还没有使用任何 Stack 操作数；在下一个编译遍中，我们会把每个 Pseudo 操作数替换为 Stack 操作数。而且我们还没有使用 R10D 寄存器；在改写非法指令时我们会引入它。

### 替换伪寄存器

接下来，我们编写一个编译遍，把每个 Pseudo 操作数替换为 Stack 操作数，汇编 AST 的其余部分保持不变。在清单 2-2 中，我们使用了两个栈位置：`-4(%rbp)` 和 `-8(%rbp)`。这一遍遵循同样的模式：我们把遇到的第一个临时变量替换为 `Stack(-4)`，下一个替换为 `Stack(-8)`，依此类推。每遇到一个新变量就减去四，因为每个临时变量都是一个 4 字节整数。你需要一边处理一边维护一个从标识符到偏移量的映射，这样同一个伪寄存器每次出现时，你都能把它替换为栈上的同一个地址。例如，如果你处理指令

```text
Mov(Imm(2), Pseudo("a"))
Unary(Neg, Pseudo("a"))
```

你应当在两条指令中都把 `Pseudo("a")` 替换为同一个 Stack 操作数。

这个编译遍还应当返回最后一个临时变量的栈偏移量，因为它告诉我们下一个遍需要在栈上分配多少字节。

### 修补指令

现在我们需要再遍历一次汇编 AST，做两处小修补。第一，在 function_definition 的指令列表最前面插入 AllocateStack 指令。AllocateStack 的整数参数应当是上一个编译遍中分配的最后一个临时变量的栈偏移量。这样，我们在栈上分配的空间就足以容纳我们使用的每一个地址。例如，如果我们替换了三个临时变量，最后一个替换为 `-12(%rbp)`，那么就在指令列表开头插入 `AllocateStack(12)`。

第二处修补是改写非法的 Mov 指令。当我们用栈地址替换伪寄存器之后，可能得到源和目的都是 Stack 操作数的 Mov 指令。当程序中的一元表达式至少有一层嵌套时，就会出现这种情况。但是 `mov` 和许多其他指令一样，不允许源和目的同时是内存地址。如果你试图汇编一个含有 `movl -4(%rbp), -8(%rbp)` 这样指令的程序，汇编器会拒绝它。遇到非法的 `mov` 指令时，把它改写为先从源地址复制到 R10D，再从 R10D 复制到目的。例如，指令

```asm
movl    -4(%rbp), -8(%rbp)
```

变为：

```asm
movl    -4(%rbp), %r10d
movl    %r10d, -8(%rbp)
```

我选择 R10D 作为暂存寄存器，是因为它不承担任何其他特殊用途。某些寄存器是特定指令所必需的；例如，执行除法的 `idiv` 指令要求被除数存储在 EAX 中。另一些寄存器用于在函数调用期间传递参数。在这个阶段把这些寄存器用作暂存寄存器可能导致冲突。比如，你可能已经把某个函数参数复制到了正确的寄存器中，但随后在用该寄存器在不同内存地址之间搬运另一个值时，不小心把它覆盖了。因为 R10D 没有任何特殊用途，我们不必担心这些冲突。

| Program(function_definition) | 打印函数定义。在 Linux 上，在文件末尾添加：<br>`    .section .note.GNU-stack,"",@progbits` |
| Function(name, instructions) | `    .globl <name>`<br>`<name>:`<br>`    pushq    %rbp`<br>`    movq    %rsp, %rbp`<br>`    <instructions>` |

表 2-7 展示了如何在 Ret 指令之前加入函数尾声，以及如何发射新的 Unary 和 AllocateStack 指令。

*表 2-7：格式化汇编指令*

| 汇编指令 | 输出 |
| --- | --- |
| Mov(src, dst) | `movl      <src>, <dst>` |
| Ret | `movq    %rbp, %rsp`<br>`popq    %rbp`<br>`ret` |
| Unary(unary_operator, operand) | `<unary_operator>    <operand>` |
| AllocateStack(int) | `subq    $<int>, %rsp` |

如表所示，你应当把 AllocateStack 发射为一条 `subq` 指令。把 Unary 按其 unary_operator 参数发射为 `negl` 或 `notl` 指令。表 2-8 给出了每个 unary_operator 对应的指令名称。

*表 2-8：汇编运算符的指令名称*

| 汇编运算符 | 指令名称 |
| --- | --- |
| Neg | negl |
| Not | notl |

最后，表 2-9 展示了如何打印新的 Reg 和 Stack 操作数。

*表 2-9：格式化汇编操作数*

| 汇编操作数 | 输出 |
| --- | --- |
| Reg(AX) | %eax |
| Reg(R10) | %r10d |
| Stack(int) | <int>(%rbp) |
| Imm(int) | $<int> |

由于 RBP 和 RSP 中存储的是内存地址，长度为 8 字节，我们对它们总是使用带 `q` 后缀的四字（quadword）指令。表 2-7 中的 `movl` 指令与序言、尾声中的 `movq` 指令除了操作数大小之外完全相同。

## 延伸资源

本章提到了补码，即所有现代计算机表示有符号整数的方式。补码将贯穿本书，所以值得花时间理解它。下面是几篇关于其工作原理的概述：

Thomas Finley 的“Two's Complement”讲述了补码表示如何以及为什么有效（https://www.cs.cornell.edu/~tomf/notes/cps104/twoscomp.html）。

Noam Nisan 和 Shimon Schocken 的 The Elements of Computing Systems（MIT Press，2005）第 2 章从更偏硬件的角度讲述了类似的材料。该书是 Nand to Tetris 项目的配套用书。这一章可在 https://www.nand2tetris.org/course 免费获取；点击“Project 2: Boolean Arithmetic”下方的书本图标即可。

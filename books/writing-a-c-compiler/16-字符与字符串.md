# 第 16 章　字符与字符串

*Chapter 16: Characters and Strings*

本章中，你将实现三种新的整数类型：char、signed char 和 unsigned char。它们就是字符类型（character type），大小为 1 字节。由于你的编译器已经支持多种大小的有符号和无符号整数，添加这些新类型几乎不费什么力气。你还将添加对字符串字面量（string literal）和字符常量（character constant）的支持。字符串字面量在 C 中扮演着一个奇怪的角色：有时它们的行为像复合初始化器（compound initializer），有时它们又表示常量 char 数组。为了支持后一种情况，你会把常量字符串与变量一起存放在符号表中，并在 TACKY 中引入一种新的顶层构造——静态常量（static constant）。

在本章末尾，我们将编译 "Hello, World!"。在第 9 章中，我们编译过这个程序的一个版本，它一次只打印一个字符。这一次，我们将编译一个更合理的版本，把整个字符串一次性打印出来。在动手之前，我先介绍一些背景知识：首先谈谈字符类型与其他整数类型之间的几个显著差异，然后介绍字符串在 C 和汇编中如何工作。

## 字符类型的特性

字符类型最令人意外的一点是它居然有三种。int 和 signed int 之间、long 和 signed long 之间并无区别，但说明符 char 和 signed char 指的却是两种不同的类型。"普通" char 到底是有符号还是无符号是由实现定义的（implementation-defined）。我们将遵循 System V ABI，其中规定 char 是有符号的。

尽管在我们的实现中 char 和 signed char 的行为完全相同，但它们是不同类型这一事实会带来实际的后果。例如，清单 16-1 是非法的，因为它把同一个全局变量既声明为 char 又声明为 signed char。

```c
char c;
signed char c;
```

*清单 16-1：使用不同字符类型的相互冲突的文件作用域变量声明*

而把一个全局变量同时声明为 int 和 signed int 则完全合法，因为两个声明指定的是同一种类型。

字符类型遵循的类型转换规则也与其他整数类型略有不同。当一个字符被用于一元 `+`、`-` 或 `~` 运算、按位二元运算，或寻常算术转换（usual arithmetic conversions）时，它首先会被转换为 int。这些转换被称为整数提升（integer promotion）。（如果 int 无法容纳某个字符类型的所有值，该字符会被转换为 unsigned int。在我们的实现中，int 可以容纳每种字符类型的所有值，所以这一点无关紧要。当然，对于我们尚未实现的运算，比如一元 `+` 和按位二元运算，我们可以忽略它们的类型规则；我在这里提到它们只是为了完整起见。）

字符与其他整数之间还有一个值得注意的区别：在 C17 中，不存在字符类型的标量常量。像 `'a'` 这样的词法单元（token）的类型都是 int，尽管它们被称为"字符常量"。也有一些具有宽字符类型（wide character type）的常量，比如 char16_t、char32_t 和 wchar_t，它们用于表示多字节字符，但我们不会实现它们。

> **注意**
>
> C23 引入了类型为 unsigned char 的 u8 字符常量。它们表示 1 字节的 UTF-8 字符。

## 字符串字面量

在本章中，我会区分字符串字面量（string literal）和字符串（string）这两个概念。字符串字面量是出现在源代码中的表达式，比如 `"abc"`。字符串是内存中的一个对象——具体来说，是一个以空字节（null byte）结尾的 char 数组。有些字符串不能在运行时修改；我会把它们称为常量字符串（constant string），尽管这并不是一个标准术语。

你可以以两种不同的方式使用字符串字面量。第一种是初始化任意字符类型的数组：

```c
signed char array[4] = "abc";
```

只要还有空间，我们就会包含结尾的空字节；没有空间就省略它。这与我们通常的数组初始化规则正好吻合：如果初始化器比目标对象短，我们就用零填充剩余部分。因此，前面这个声明等价于：

```c
signed char array[4] = {'a', 'b', 'c', 0};
```

而在清单 16-2 中，由于 array1 的长度不足以容纳空字节，我们省略了它。因此，array1 和 array2 的内容完全相同。

```c
char array1[3] = "abc";
char array2[3] = {'a', 'b', 'c'};
```

*清单 16-2：把字符串字面量用作不带空字节的数组初始化器*

当字符串字面量出现在数组初始化器以外的任何地方时，它指代（designate）一个常量字符串。在这种情况下，字符串字面量的行为非常像其他数组类型的表达式。它们和其他数组表达式一样会衰退（decay）为指针，所以你可以对它们做下标运算，或者把它们赋给 char * 类型的对象。下面的声明把常量字符串 `"abc"` 中第一个字符的地址初始化给变量 str_ptr：

```c
char *str_ptr = "abc";
```

字符串字面量也是左值（lvalue），所以它们支持 `&` 运算符。这里，我们用这个运算符取常量字符串 `"abc"` 的地址，然后把它赋给 array_ptr：

```c
char (*array_ptr)[4] = &"abc";
```

与上一个例子的唯一区别是，这里的字符串字面量没有经历数组衰退。我们得到的是一个指向整个字符串的指针，类型为 char (*)[4]，而不是指向其第一个元素的指针，类型为 char *。在这两个例子中，我们都把 `"abc"` 当作任何其他数组类型的表达式来对待。

与其他数组不同，常量字符串——顾名思义——是常量。试图修改它们（如清单 16-3 所示）会产生未定义行为。

```c
char *ptr = "abc";
ptr[0] = 'x';
```

*清单 16-3：非法地修改常量字符串*

这段代码虽然能通过编译，但很可能在运行时抛出错误，因为大多数 C 实现——包括我们的实现——都把常量字符串存放在只读内存（read-only memory）中。（我们不会实现的 const 限定符（qualifier）会告知编译器某个对象不能被修改。如果清单 16-3 是某个真实 C 程序的一部分，给 ptr 加上 const 限定符会是个好主意。）

让我们再看一个例子（清单 16-4），来厘清指代常量字符串的字符串字面量与初始化数组的字符串字面量之间的区别。

```c
char arr[3] = "abc";
arr[0] = 'x';
```

*清单 16-4：合法地修改一个由字符串字面量初始化的数组*

与清单 16-3 不同，这段代码完全合法。在清单 16-3 中，ptr 指向常量字符串 `"abc"` 的起始位置。而在清单 16-4 中，我们用字符串字面量 `"abc"` 的每个字符来初始化 arr 的各个元素，而 arr 是一个普通的、非常量的 char 数组。

一旦看到这两种情况如何翻译为汇编，它们就都容易理解了。

## 在汇编中使用字符串

我们将使用两种不同的汇编伪指令（directive）在汇编中初始化字符串。.ascii 和 .asciz 伪指令都告诉汇编器向目标文件（object file）写入一个 ASCII 字符串，就像 .quad 告诉它写入一个 quadword 一样。两者的区别在于 .asciz 会包含结尾的空字节，而 .ascii 不会。下面这三个声明

```c
static char null_terminated[4] = "abc";
static char not_null_terminated[3] = "abc";
static char extra_padding[5] = "abc";
```

对应于清单 16-5 中的汇编代码。

```asm
    .data
null_terminated:
    .asciz "abc"
not_null_terminated:
    .ascii "abc"
extra_padding:
    .asciz "abc"
    .zero 1
```

*清单 16-5：在汇编中用字符串字面量初始化三个静态 char 数组*

由于 null_terminated 的长度足以容纳一个空字节，我们用 .asciz 伪指令初始化它。我们用 .ascii 初始化 not_null_terminated，这样就不会超出数组的边界。由于 extra_padding 还需要两个零字节才能达到正确的长度，我们先写入一个以空字节结尾的字符串，再用 .zero 伪指令写入一个额外的零字节。注意，这些变量都不需要 .align 伪指令。字符类型都是按 1 字节对齐的，所以字符数组也是。（包含 16 个及以上字符的数组变量是例外；与所有 16 字节或更大的数组变量一样，它们按 16 字节对齐。）

.ascii 和 .asciz 伪指令初始化的是具有静态存储期（static storage duration）的对象。接下来，让我们看看清单 16-6，它初始化一个非静态数组。

```c
int main(void) {
    char letters[6] = "abcde";
    return 0;
}
```

*清单 16-6：用字符串字面量初始化一个非静态数组*

清单 16-7 展示了在汇编中初始化 letters 的一种方式：一次一个字节地把 "abcde" 复制到栈上。

```asm
movb    $97,  -8(%rbp)
movb    $98,  -7(%rbp)
movb    $99,  -6(%rbp)
movb    $100, -5(%rbp)
movb    $101, -4(%rbp)
movb    $0,   -3(%rbp)
```

*清单 16-7：在汇编中初始化一个非静态 char 数组*

字符 'a'、'b'、'c'、'd' 和 'e' 的 ASCII 值分别是 97、98、99、100 和 101。假设 letters 起始于栈地址 -8(%rbp)，清单 16-7 中的指令会把每个字符复制到数组中相应的位置。每条 movb 指令中的 b 后缀表明它操作单个字节。

清单 16-8 演示了一种更高效的做法。我们用一条 movl 指令初始化这个字符串的前 4 个字节，再用 movb 指令初始化剩下的 2 个字节。

```asm
movl    $1684234849, -8(%rbp)
movb    $101, -4(%rbp)
movb    $0,   -3(%rbp)
```

*清单 16-8：在汇编中更高效地初始化一个非静态 char 数组*

1684234849 是把这个字符串的前 4 个字节解释为一个整数得到的。（我会在本章稍后更详细地讨论这个整数是怎么来的。）这段代码的效果与清单 16-7 相同，但省下了几条指令。

接下来看看常量字符串。我们把它们写入目标文件的只读节（read-only section）中，就像浮点常量一样。在 Linux 上，我们把常量字符串存放在 .rodata 中；在 macOS 上，我们把它们存放在 .cstring 节中。考虑清单 16-9 中的代码片段，它返回一个指向常量字符串起始位置的指针。

```c
return "A profound statement.";
```

*清单 16-9：返回一个指向字符串起始位置的指针*

我们会为这个字符串生成一个唯一的标号（label），然后在相应的节中定义它。清单 16-10 给出了生成的汇编代码。

```asm
    .section .rodata
.Lstring.0:
    .asciz "A profound statement."
```

*清单 16-10：在汇编中定义一个常量字符串*

常量字符串总是以空字节结尾，因为它们不需要塞进任何特定的数组尺寸。定义好常量字符串之后，我们就可以像访问其他任何静态对象一样，用 RIP 相对寻址（RIP-relative addressing）访问它。在这个例子中，我们想返回字符串的地址，所以用这条指令把它加载到 RAX 中：

```asm
leaq    .Lstring.0(%rip), %rax
```

最后，让我们看看如何用一个字符串字面量初始化静态指针，如清单 16-11 所示。

```c
static char *ptr = "A profound statement.";
```

*清单 16-11：用一个字符串字面量初始化静态 char \**

我们会像清单 16-10 中那样定义这个字符串。但是，我们不能用 lea 指令把它加载到 ptr 中。因为 ptr 是静态的，它必须在程序开始运行之前完成初始化。幸运的是，.quad 伪指令除了接受常量之外也接受标号。清单 16-12 展示了如何用这个伪指令初始化 ptr。

```asm
    .data
    .align 8
ptr:
    .quad .Lstring.0
```

*清单 16-12：用一个静态常量的地址初始化静态变量*

伪指令 .quad .Lstring.0 告诉汇编器和链接器写入 .Lstring.0 的地址。

顺带一提，任何静态指针都可以用这种方式初始化，不限于指向字符串的指针。虽然我们的实现不接受像 `&x` 这样的表达式作为静态初始化器，但一个更完整的编译器可能会把

```c
static int x = 10;
static int *ptr = &x;
```

翻译成：

```asm
    .data
    .align 4
x:
    .long 10
    .align 8
ptr:
    .quad x
```

至此，你已经充分了解了如何在 C 和汇编中使用字符串，可以开始动手了。第一步是扩展词法分析器，让它识别字符串字面量和字符常量。

## 词法分析器

本章中，你将添加三种新的词法单元（token）：

- char：一个关键字，用于指定字符类型
- 字符常量：单个字符，比如 'a' 和 '\n'
- 字符串字面量：字符序列，比如 "Hello, World!"

字符常量由一个字符（比如 a）或转义序列（escape sequence，比如 \n）构成，外面用单引号括起来。C 标准第 6.4.4.4 节定义了一组表示特殊字符的转义序列。表 16-1 列出了这些转义序列及其 ASCII 码。

*表 16-1：特殊字符的转义序列*

| 转义序列 | 描述 | ASCII 码 |
| --- | --- | --- |
| \' | 单引号 | 39 |
| \" | 双引号 | 34 |
| \? | 问号 | 63 |
| \\ | 反斜杠 | 92 |
| \a | 响铃 | 7 |
| \b | 退格 | 8 |
| \f | 换页 | 12 |
| \n | 换行 | 10 |
| \r | 回车 | 13 |
| \t | 水平制表符 | 9 |
| \v | 垂直制表符 | 11 |

换行、单引号（'）和反斜杠（\）字符不能单独作为字符常量出现，必须转义。其他任何字符只要属于源字符集（source character set）——即可以出现在源文件中的全部字符——就可以直接用作字符常量。

源字符集是由实现定义的，但它必须至少包含基本源字符集（basic source character set），后者由 C 标准第 5.2.1 节规定。在我们的实现中，源字符集包含所有可打印的 ASCII 字符，再加上必需的控制字符：换行、水平制表符、垂直制表符和换页。你不需要显式地拒绝这个集合之外的字符；直接假设它们永远不会出现在源文件中即可。

表 16-1 中的一些字符，比如响铃（\a）和退格（\b），不在我们的源字符集中，所以只能用转义字符表示。其他字符，包括双引号（"）、问号（?）、换页、水平制表符和垂直制表符，都在源字符集中；它们在字符常量中可以被转义，但不是必须的。例如，字符常量 '?' 和 '\?' 是等价的；它们都表示问号字符。换行、单引号和反斜杠虽然都在源字符集中，但仍然必须转义。

我们可以用清单 16-13 中那个糟糕透顶的正则表达式来识别字符常量。

```text
'([^'\\\n]|\\['"?\\abfnrtv])'
```

*清单 16-13：识别字符常量的正则表达式*

来把它拆解一下。括号表达式中的第一个备选项，字符类 [^'\\\n]，匹配除单引号、反斜杠和换行之外的任意单个字符。我们必须转义反斜杠，因为它在 PCRE 正则表达式和 C 字符串字面量中都是控制字符。类似地，我们在正则表达式中用转义序列 \n 来匹配一个字面的换行字符。第二个备选项，\\['"?\\abfnrtv]，匹配一个转义序列。开头的 \\ 匹配单个反斜杠，随后的字符类包含了转义序列中可以跟在反斜杠后面的所有字符。整个表达式必须以单引号开始和结束。

字符串字面量由零个或多个字符和转义序列构成，外面用双引号括起来。单引号可以在字符串字面量中单独出现，但双引号必须转义。清单 16-14 展示了识别字符串字面量的正则表达式。

```text
"([^"\\\n]|\\['"\\?abfnrtv])*"
```

*清单 16-14：识别字符串字面量的正则表达式*

这里，[^"\\\n] 匹配除双引号、反斜杠或换行之外的任意单个字符。与清单 16-13 一样，第二个备选项匹配所有转义序列。我们对整个括号表达式应用 * 量词，因为它可以重复零次或多次，并用双引号把这一切括起来。

在完成对一个字符串字面量或字符词法单元的词法分析之后，你需要对它做反转义（unescape）。换句话说，你要把这个词法单元中的每个转义序列都转换为对应的 ASCII 字符。这件事你可以现在做，也可以留到解析器中做。

标准还定义了另外几种我们不会实现的字符串字面量和字符常量。具体来说，我们不支持像 \xff 这样的十六进制转义序列、像 \012 这样的八进制转义序列，以及像 'ab' 这样的多字符常量。我们也不支持任何用于非 ASCII 编码的类型或常量，比如宽字符类型、宽字符串字面量或 UTF-8 字符串字面量。

**测试词法分析器**

要测试词法分析器，运行：

```bash
$ ./test_compiler /path/to/your_compiler --chapter 16 --stage lex
```

你的词法分析器应该拒绝 tests/chapter_16/invalid_lex 中的所有测试用例。这些测试包括非法的转义序列、未转义的特殊字符，以及未终止的字符常量和字符串字面量。词法分析器应该能成功处理本章的所有其他测试用例。

## 解析器

我们将从三个方面扩展 AST 的定义。第一，添加 char、signed char 和 unsigned char 类型。第二，添加一种新的表达式来表示字符串字面量。第三，扩展 const AST 节点以表示字符类型的常量：

```text
const = ConstInt(int) | ConstLong(int) | ConstUInt(int) | ConstULong(int)
      | ConstDouble(double) | ConstChar(int) | ConstUChar(int)
```

这些新的常量构造器（constructor）有点不寻常，因为它们并不对应 C 程序中实际出现的常量字面量。像 'a' 这样的字符常量的类型是 int，所以解析器会把它们转换为 ConstInt 节点；它根本不会用新的 ConstChar 和 ConstUChar 构造器。但在类型检查阶段填充部分初始化的字符数组时，以及在 TACKY 中初始化字符数组时，我们会需要这些构造器。

清单 16-15 给出了完整的 AST 定义，本章的改动以粗体标出。

```text
program = Program(declaration*)
declaration = FunDecl(function_declaration) | VarDecl(variable_declaration)
variable_declaration = (identifier name, initializer? init,
                        type var_type, storage_class?)
function_declaration = (identifier name, identifier* params, block? body,
                        type fun_type, storage_class?)
initializer = SingleInit(exp) | CompoundInit(initializer*)
type = Char | SChar | UChar | Int | Long | UInt | ULong | Double
     | FunType(type* params, type ret)
     | Pointer(type referenced)
     | Array(type element, int size)
storage_class = Static | Extern
block_item = S(statement) | D(declaration)
block = Block(block_item*)
for_init = InitDecl(variable_declaration) | InitExp(exp?)
statement = Return(exp)
          | Expression(exp)
          | If(exp condition, statement then, statement? else)
          | Compound(block)
          | Break
          | Continue
          | While(exp condition, statement body)
          | DoWhile(statement body, exp condition)
          | For(for_init init, exp? condition, exp? post, statement body)
          | Null
exp = Constant(const)
    | String(string)
    | Var(identifier)
    | Cast(type target_type, exp)
    | Unary(unary_operator, exp)
    | Binary(binary_operator, exp, exp)
    | Assignment(exp, exp)
    | Conditional(exp condition, exp, exp)
    | FunctionCall(identifier, exp* args)
    | Dereference(exp)
    | AddrOf(exp)
    | Subscript(exp, exp)
unary_operator = Complement | Negate | Not
binary_operator = Add | Subtract | Multiply | Divide | Remainder | And | Or
                | Equal | NotEqual | LessThan | LessOrEqual
                | GreaterThan | GreaterOrEqual
const = ConstInt(int) | ConstLong(int) | ConstUInt(int) | ConstULong(int)
      | ConstDouble(double) | ConstChar(int) | ConstUChar(int)
```

*清单 16-15：加入字符类型、字符常量和字符串字面量的抽象语法树*

扩展 const 而不是 exp 来包含字符串字面量也许很诱人，但字符串字面量与其他类型的常量差别足够大，单独定义它们最为简单。例如，类型检查器在处理初始化器时，就需要把它们与其他常量区别对待。

### 解析类型说明符

我们需要扩展 parse_type——它把一列类型说明符转换为一个类型 AST 节点——来处理字符类型。我不会给出这一部分的伪代码，因为逻辑非常简单。如果 char 单独出现在声明中，它指定的是普通 char 类型。如果它与 unsigned 关键字一起出现，它指定的是 unsigned char 类型。如果它与 signed 关键字一起出现，它指定的是 signed char 类型。与往常一样，类型说明符的顺序无关紧要。char 与任何其他类型说明符同时出现在声明中都是非法的。

### 解析字符常量

解析器应该把每个字符常量词法单元转换为带有相应 ASCII 值的 ConstInt。它应该把词法单元 'a' 转换为 ConstInt(97)，把 '\n' 转换为 ConstInt(10)，以此类推。

### 解析字符串字面量

如果词法分析器还没有做反转义，解析器应该对字符串字面量做反转义。字符串字面量中的每个字符——包括源代码中由转义序列表示的字符——在内部都必须表示为单个字节。否则，我们在类型检查器中算出的字符串长度会不准确，在运行时也会用错误的值初始化数组。

相邻的字符串字面量词法单元应该被拼接成单个 String AST 节点。例如，解析器应该把语句

```c
return "foo" "bar";
```

转换为 AST 节点 Return(String("foobar"))。

## 类型检查器

在大多数情况下，类型检查器可以像对待其他整数类型一样对待字符。它们遵循相同的类型规则，支持相同的运算。整数提升是这一模式中唯一的例外，所以我们将在本节实现它。我们还会引入字符类型的静态初始化器。

字符串字面量的类型检查更具挑战性，尤其是当它们出现在初始化器中时。我们需要跟踪每个字符串应该被直接使用还是被转换为指针，以及哪些字符串应该以空字节结尾。我们会在符号表中添加几个新构造来分别表示这些情况。

### 字符

我们将在寻常算术转换的过程中把字符类型提升为 int。清单 16-17 展示了如何在 get_common_type 中执行这个提升。

```text
get_common_type(type1, type2):
    if type1 is a character type:
        type1 = Int
    if type2 is a character type:
        type2 = Int
    --snip--
```

*清单 16-17：在寻常算术转换期间应用整数提升*

提升两个操作数的类型之后，我们照常求出它们的公共类型。我们还会提升一元 `-` 和 `~` 运算的操作数。清单 16-18 演示了如何提升一个取负的操作数。

```text
typecheck_exp(e, symbols):
    match e with
    | --snip--
    | Unary(Negate, inner) ->
        typed_inner = typecheck_and_convert(inner, symbols)
        inner_t = get_type(typed_inner)
        if inner_t is a pointer type:
            fail("Can't negate a pointer")
      ❶ if inner_t is a character type:
            typed_inner = convert_to(typed_inner, Int)
        unary_exp = Unary(Negate, typed_inner)
      ❷ return set_type(unary_exp, get_type(typed_inner))
```

*清单 16-18：对取负表达式应用整数提升*

首先，我们确保操作数不是指针（这个检查是我们在第 14 章引入的）。然后，我们应用整数提升。我们检查操作数是否属于某种字符类型 ❶；如果是，就把它转换为 Int，然后对提升后的值取负。表达式的结果类型与其提升后的操作数的类型相同 ❷。我们对 `~` 的处理方式完全相同，所以我就不在这里给出它的伪代码了。

在类型检查期间，我们始终把字符识别为整数类型。例如，我们会接受字符作为 `~` 和 `%` 表达式的操作数，以及指针算术中的下标。由于所有整数类型也都是算术类型（arithmetic type），我们会允许字符类型与任何其他算术类型之间在 convert_by_assignment 中做隐式转换。

我们将为字符类型添加两个静态初始化器。清单 16-19 给出了 static_init 的更新后的定义。

```text
static_init = IntInit(int) | LongInit(int) | UIntInit(int) | ULongInit(int)
            | CharInit(int) | UCharInit(int)
            | DoubleInit(double) | ZeroInit(int bytes)
```

*清单 16-19：添加字符类型的静态初始化器*

由于 signed char 和普通 char 都是有符号类型，我们用 CharInit 来初始化这两种类型。我们会按照第 11 章和第 12 章中讲过的类型转换规则，把每个初始化器转换为它所初始化的类型。例如，如果一个 unsigned char 被一个大于 255 的值初始化，我们会把它的值按 256 取模。

最后，我们对非静态数组的复合初始化器的类型检查方式做一个小而直接的更新。（初始化数组的字符串字面量将作为单独的情况在下一节处理。）在上一章中，我们通过用零填充剩余元素来处理部分初始化的数组。我当时建议编写一个 zero_initializer 辅助函数来生成这些清零的初始化器。现在我们可以扩展这个函数，让它发射 ConstChar 和 ConstUChar 来把字符类型的元素清零。

### 表达式中的字符串字面量

当我们在表达式中（而不是在数组初始化器中）遇到一个字符串字面量时，我们会把它标注为具有相应大小的 char 数组。清单 16-20 展示了如何在 typecheck_exp 中处理字符串字面量。

```text
typecheck_exp(e, symbols):
    match e with
    | --snip--
    | String(s) -> return set_type(e, Array(Char, length(s) + 1))
```

*清单 16-20：对字符串字面量做类型检查*

注意，数组的大小把结尾的空字节也算在内。类型检查器已经在 typecheck_and_convert 中处理了从数组到指针的隐式转换。现在 typecheck_and_convert 也会把字符串字面量转换为指针，因为它们同样具有数组类型。

接下来，我们要更新类型检查器，让它把 String 表达式与变量、下标运算符和解引用表达式一起识别为左值。这样，程序就可以用 `&` 运算符取它们的地址。

表达式中的字符串字面量就处理完了；现在我们来对初始化器中的字符串字面量做类型检查。

### 初始化非静态变量的字符串字面量

通常，我们用 typecheck_and_convert 对 SingleInit 构造做类型检查，它会把数组类型的值转换为指针。这种做法能正确处理初始化指针的字符串字面量。但当字符串字面量被用来初始化数组时，我们要换一种方式对它做类型检查。清单 16-21 展示了如何处理这种情况。

```text
typecheck_init(target_type, init, symbols):
    match target_type, init with
    | Array(elem_t, size), SingleInit(String(s)) ->
      ❶ if elem_t is not a character type:
            fail("Can't initialize a non-character type with a string literal")
      ❷ if length(s) > size:
            fail("Too many characters in string literal")
      ❸ return set_type(init, target_type)
    | --snip--
```

*清单 16-21：对初始化数组的字符串字面量做类型检查*

首先，我们确保目标类型是字符数组，因为字符串字面量不能初始化任何其他类型的数组 ❶。然后，我们验证字符串没有长到装不进这个数组 ❷。最后，我们用目标类型标注这个初始化器 ❸。稍后我们会用这个标注来确定要在字符串末尾追加多少个空字节。

### 初始化静态变量的字符串字面量

我们的最后一项任务是处理初始化静态变量的字符串字面量。我们需要在符号表中表示两种新的初始值：ASCII 字符串（对应 .ascii 和 .asciz 伪指令）和静态对象的地址（对应像 .quad .Lstring.0 这样的伪指令）。我们将再次更新 static_init，把这两种初始化器都包含进来。清单 16-22 给出了新的定义，这两处新增以粗体标出。

```text
static_init = IntInit(int) | LongInit(int)
            | UIntInit(int) | ULongInit(int)
            | CharInit(int) | UCharInit(int)
            | DoubleInit(double) | ZeroInit(int bytes)
            | StringInit(string, bool null_terminated)
            | PointerInit(string name)
```

*清单 16-22：添加字符串和指针的静态初始化器*

StringInit 定义一个 ASCII 字符串初始化器。我们会用它来初始化常量字符串和字符数组。null_terminated 参数指定是否在末尾包含一个空字节；我们会在代码发射期间用这个参数在 .ascii 和 .asciz 伪指令之间做选择。PointerInit 用另一个静态对象的地址初始化一个指针。

我们还会开始在符号表中跟踪常量字符串。清单 16-23 给出了 identifier_attrs 的更新后的定义，其中包含了常量。

```text
identifier_attrs = FunAttr(bool defined, bool global)
                 | StaticAttr(initial_value init, bool global)
                 | ConstantAttr(static_init init)
                 | LocalAttr
```

*清单 16-23：在符号表中跟踪常量*

与可能未初始化、被临时初始化或被一列值初始化的变量不同，常量是用单个值初始化的。它也不需要全局标志，因为我们永远不会定义全局常量。

既然已经扩展了 static_init 和 identifier_attrs，接下来讨论如何处理字符数组和 char 指针这两种情况的字符串初始化器。

#### 用字符串字面量初始化静态数组

如果一个字符串字面量初始化一个静态数组，我们首先验证数组的类型：确保数组元素具有字符类型，并且数组足以容纳这个字符串。（这与我们之前在清单 16-21 中对非静态数组执行的验证相同。）然后，我们把字符串字面量转换为一个 StringInit 初始化器；如果数组有足够的空间容纳结尾的空字节，就设置 null_terminated 标志。如果需要用额外的空字节填充，我们就在初始化器列表中加入 ZeroInit。例如，我们会把声明

```c
static char letters[10] = "abc";
```

转换为清单 16-24 中的符号表条目。

```text
name="letters"
type=Array(Char, 10)
attrs=StaticAttr(init=Initial([StringInit("abc", True), ZeroInit(6)]),
                 global=False)
```

*清单 16-24：一个由字符串字面量初始化的数组的符号表条目*

这个条目用以空字节结尾的字符串 "abc" 加上 6 个零字节初始化 letters。

#### 用字符串字面量初始化静态指针

如果一个字符串字面量初始化一个 char * 类型的静态变量，我们会在符号表中创建两个条目。第一个定义字符串本身，第二个定义指向该字符串的变量。来看一个例子：

```c
static char *message = "Hello!";
```

首先，我们为常量字符串 "Hello!" 生成一个标识符；假设这个标识符是 "string.0"。然后，我们把清单 16-25 中所示的条目加入符号表。

```text
name="string.0"
type=Array(Char, 7)
attrs=ConstantAttr(StringInit("Hello!", True))
```

*清单 16-25：在符号表中定义一个常量字符串*

这个标识符必须全局唯一，并且必须是汇编中语法有效的标号。换句话说，它应该遵循与我们为浮点常量生成的标识符相同的约束。因为清单 16-25 定义的是一个常量字符串，我们使用新的 ConstantAttr 构造，并用以空字节结尾的字符串 "Hello!" 初始化它。

然后，当我们把 message 本身加入符号表时，用一个指向刚才所添加符号的指针来初始化它。清单 16-26 展示了 message 的符号表条目。

```text
name="message"
type=Pointer(Char)
attrs=StaticAttr(init=Initial([PointerInit("string.0")]), global=False)
```

*清单 16-26：在符号表中定义一个指向字符串的静态指针*

如果字符串字面量初始化的是指向 char 以外类型的指针，我们就抛出错误。（注意，在非静态的情况下，typecheck_init 已经捕获了这个错误。）甚至用字符串字面量初始化 signed char * 或 unsigned char * 也是非法的。这与普通的类型转换规则是一致的：字符串字面量的类型是 char *，而我们不能从一种指针类型隐式转换为另一种。相比之下，字符串字面量可以初始化任何字符类型的数组，因为把每个字符从一种字符类型隐式转换为另一种是合法的。

至此，我们已经为出现在静态初始化器中的所有字符串建立了符号表条目。在 TACKY 生成阶段，我们还会把程序中所有其他的常量字符串加入符号表。

## TACKY 生成

把程序转换为 TACKY 时，我们可以把字符完全当作其他所有整数来对待。具体来说，我们会用现有的类型转换指令实现与字符类型之间的相互转换。例如，我们用 DoubleToUInt 指令实现从 double 到 unsigned char 的转换，用 SignExtend 实现从 char 到 int 的转换。但处理字符串字面量需要多做一点工作。

### 作为数组初始化器的字符串字面量

在类型检查器中，我们处理了初始化静态数组的字符串字面量。现在，我们要对具有自动存储期（automatic storage duration）的数组做同样的事。

正如我们在本章前面看到的，这里有两种选择。较简单的选择是一次初始化一个字符。较高效的选择是一次初始化整个 4 字节或 8 字节的块。无论哪种方式，我们都会用一系列 CopyToOffset 指令把字符串复制到数组中。

让我们把两种选择都走一遍。我们将使用清单 16-6 的初始化器（在这里复现）作为贯穿示例：

```c
int main(void) {
    char letters[6] = "abcde";
    return 0;
}
```

第一次看这个例子时，我们了解到 'a'、'b'、'c'、'd' 和 'e' 的 ASCII 值分别是 97、98、99、100 和 101。使用简单的一次一字节的方案，我们将用清单 16-27 中的 TACKY 指令初始化 letters。

```text
CopyToOffset(Constant(ConstChar(97)),  "letters", 0)
CopyToOffset(Constant(ConstChar(98)),  "letters", 1)
CopyToOffset(Constant(ConstChar(99)),  "letters", 2)
CopyToOffset(Constant(ConstChar(100)), "letters", 3)
CopyToOffset(Constant(ConstChar(101)), "letters", 4)
CopyToOffset(Constant(ConstChar(0)),   "letters", 5)
```

*清单 16-27：在 TACKY 中一次一个字节地初始化非静态数组*

使用更高效的方案，我们先用单个 4 字节整数初始化 letters，再初始化 2 个单独的字节：

```text
CopyToOffset(Constant(ConstInt(1684234849)), "letters", 0)
CopyToOffset(Constant(ConstChar(101)),       "letters", 4)
CopyToOffset(Constant(ConstChar(0)),         "letters", 5)
```

为了得到整数 1684234849，我们把 97、98、99 和 100 这 4 个字节解释为一个单独的小端（little-endian）整数。用十六进制表示，这些字节是 0x61、0x62、0x63 和 0x64。小端整数中的第一个字节是最低有效字节，所以把这个字节序列解释为整数得到 0x64636261，也就是十进制的 1684234849。无论你用什么语言实现编译器，它很可能都提供了操作字节缓冲区并把它们解释为整数的工具函数，所以你不需要自己实现这种琐碎的逻辑。

要一次初始化八个字符，我们将使用 ConstLong 而不是 ConstInt。我们必须小心，不要超出正在初始化的数组的边界；在这个例子中，用两个 4 字节整数初始化 letters 是不正确的，因为那会破坏相邻的值。

使用这两种方案中的哪一种由你决定；它们同样正确。无论哪种情况，都要确保在字符串末尾初始化正确数量的空字节。在类型检查器中，你为包括字符串字面量在内的每个初始化器都标注了类型信息。现在你要用这些类型信息来确定要包含多少个空字节。如果字符串字面量比它初始化的数组更长，就只复制数组能容纳的那么多字符——换句话说，省略空字节。如果字符串字面量太短，就把零复制到数组的剩余部分。

### 表达式中的字符串字面量

当我们在数组初始化器之外遇到一个字符串字面量时，我们将把它作为常量字符串加入符号表。然后，我们把它的标识符用作 TACKY 的 Var。让我们重新看一下清单 16-9，它返回一个指向字符串第一个字符的指针：

```c
return "A profound statement.";
```

解析器和类型检查器把它转换为下面的 AST 节点：

```text
Return(AddrOf(String("A profound statement.")))
```

要把这个 AST 节点转换为 TACKY，我们首先在符号表中定义 "A profound statement."：

```text
name="string.1"
type=Array(Char, 22)
attrs=ConstantAttr(StringInit("A profound statement.", True))
```

这个条目与我们在类型检查器中定义的常量字符串没有任何区别。它有一个全局唯一的、自动生成的标号。它是一个刚好足以容纳整个字符串（包括结尾空字节）的 char 数组。它用新的 ConstantAttr 构造初始化，因为我们最终会把它存放在只读内存中。

现在，我们可以引用刚刚定义的标识符——在这个例子中是 string.1——来加载字符串的地址：

```text
GetAddress(Var("string.1"), Var("tmp2"))
Return(Var("tmp2"))
```

简而言之，我们像使用任何其他数组类型的符号一样使用 string.1。

## 汇编生成

在这一阶段，我们不会做什么太花哨的事情。首先，我们把对单个字符的操作转换为汇编。这需要对汇编 AST 做几处修改。然后，我们处理 TACKY 的 StaticConstant 构造，并把常量字符串加入后端符号表。

### 字符上的操作

大多数指令既支持 longword 和 quadword 操作数，也支持 1 字节操作数。像 movb 和 andb 指令中的 b 后缀表明该指令操作单个字节。我们将引入一个新的 Byte 汇编类型来表示这种新的操作数大小：

```text
assembly_type = Byte | --snip--
```

我们会把 char、signed char 和 unsigned char 类型转换为 Byte。通用寄存器也有 1 字节的别名；例如，%al 是 RAX 的 1 字节别名。幸运的是，我们的代码发射遍已经支持这些别名了。

除了添加 Byte 类型之外，我们还需要正确地实现与字符类型之间的相互转换。你可以用 movz 指令把一个 1 字节的值零扩展（zero extension）到更宽的类型。这条指令带一个由两个字母组成的后缀，分别表明源类型和目的类型。movzbl 指令把一个字节扩展为 longword，movzbq 把一个字节扩展为 quadword。（你也可以用 movzwl 或 movzwq 把一个 2 字节的 word 扩展为更大的类型，但我们不使用 2 字节操作数。）我们将在汇编 AST 中用现有的 MovZeroExtend 指令表示 movz，但要加上两个操作数的类型：

```text
MovZeroExtend(assembly_type src_type, assembly_type dst_type, operand src, operand dst)
```

如果 src_type 是 Byte，我们最终会发射一条带有正确后缀的 movz 指令。如果 src_type 是 Longword，我们会在修补遍中把它改写为一条普通的 mov 指令，与前几章的做法相同。

要把一个字节符号扩展（sign extension）到更大的类型，我们将使用现有的 Movsx 指令。这条指令同样带有一个后缀来指定源类型和目的类型：movsbl 把一个字节扩展为 longword，movsbq 把一个字节扩展为 quadword，movslq 把一个 longword 扩展为 quadword。我们也将在汇编 AST 中为这条指令加上类型信息：

```text
Movsx(assembly_type src_type, assembly_type dst_type, operand src, operand dst)
```

你可以用 movb 指令把一个更大的整数截断为单个字节，就像你可以用 movl 把一个 quadword 截断为 longword 一样。注意，当你用 movb 指令把一个值复制到寄存器时，寄存器的高位字节不会被清零。这不是问题；无论我们操作的是单个字节还是 longword，我们都只使用寄存器中保存值本身的那一部分，而忽略寄存器的高位字节。

**Clang 的离经叛道**

有一种情况，寄存器高位字节的内容可能会有影响：当你调用一个由 Clang 编译的函数时。如果一个函数参数窄于 4 字节，Clang 总是让调用方把它符号扩展或零扩展到 4 字节。然后，在被调用方中，它假设该参数已经被扩展到了 4 字节。

这个假设违反了 System V ABI，后者并不要求调用方扩展窄的函数参数。看下面这段 C 代码：

```c
int accept_int(int i);

int accept_char(char c) {
    return accept_int(c);
}
```

当一个函数调用 accept_char 时，它把形参 c 放在 EDI 的最低有效字节中传递，这个字节的别名是 %dil。然后，当 accept_char 调用 accept_int 时，它在 EDI 中传递 c 的值的 4 字节表示。如果我们严格遵循 ABI，就要假设 EDI 的最高 3 个字节在 accept_char 开头时是垃圾，所以我们在把 c 传给 accept_int 之前显式地做符号扩展：

```asm
movsbl  %dil, %edi
call    accept_int
```

但 Clang 并没有严格遵循 ABI：开启优化时，它会省略 movsbl 指令。这意味着，如果 accept_char 的调用方没有事先对 c 做符号扩展，我们可能得到错误的结果！这并非只是杞人之忧：Intel 的老牌 C 编译器 ICC 不扩展窄参数，因此它与 Clang 在 ABI 上不兼容。（Intel 基于 Clang 和 LLVM 构建的较新 C 编译器没有这个问题。）

GCC 采取最保守的做法：它让调用方扩展窄参数，但不假设被调用方中的参数已被扩展。因此，它可以同时与 ICC 和 Clang 正确互操作。

替 Clang 说句公道话，ABI 在这一点上并不十分明确。理想情况下，System V ABI 的维护者应该明确允许或明确禁止 Clang 的做法。

那么我们该怎么办？我们将效仿 ICC，不去费心扩展窄参数。但如果你想让你的编译器更健壮，可以采用 GCC 的做法：在生成调用函数的汇编代码时，对任何 unsigned char 参数做零扩展，对任何 char 或 signed char 参数做符号扩展。

我是从 Peter Cordes 在 Stack Overflow 上的一个精彩回答（https://stackoverflow.com/a/36760539）中了解到这个丑陋的边角案例的。他的回答写于 2016 年；截至 2024 年春，ABI 和 Clang 的行为都没有改变。

最后，让我们考虑如何在 double 和字符类型之间转换。没有哪条汇编指令能把 double 直接转换为 1 字节整数，反过来也不行。我们会以 int 为中间步骤进行转换。要把 double 转换为任何字符类型，我们首先把它转换为 int，然后截断，如清单 16-29 所示。

接下来，我们转到伪操作数替换和指令修补。这两个遍的更新都非常直接。

### 伪操作数替换

我们会为每个 Byte 对象在栈上分配 1 字节。我们不需要把它们向下舍入到正确的对齐，因为它们都是按 1 字节对齐的。

这一遍不需要任何专门处理常量字符串的逻辑。我们已经在后端符号表中记录了它们具有静态存储期。现在，我们会像访问其他任何静态对象一样，用 Data 操作数访问它们。

### 指令修补

movz 指令的目的地必须是寄存器，且它的源不能是立即数。如果一条 MovZeroExtend 指令的源操作数大小为 1 字节，而它的源或目的地无效，我们就按照通常的模式改写它。例如，我们把

```asm
movzbl  $10, -4(%rbp)
```

改写为：

```asm
movb    $10, %r10b
movzbl  %r10b, %r11d
movl    %r11d, -4(%rbp)
```

如果它的源操作数是 longword，我们就用一条或多条 mov 指令替换它，与前几章的做法相同。

如果 movb 指令的源是一个无法容纳在单个字节中的立即数，我们就把它按 256 取模。例如，我们会把

```asm
movb    $258, %al
```

改写为：

```asm
movb    $2, %al
```

这与我们在第 11 章中为处理源操作数为 8 字节立即数的 movl 指令而引入的模式相同。

## 代码发射

代码发射阶段需要支持字符串常量、指针初始化器，以及其他一些改动。我们会把每个 StringInit 发射为 .ascii 或 .asciz 伪指令，取决于它是否应包含空字节。ASCII 字符串中的双引号、反斜杠和换行必须转义。要转义这些字符，你可以使用 \"、\\ 和 \n 转义序列，或者使用指定其 ASCII 值的三位八进制转义序列。例如，反斜杠字符的 ASCII 码是 92，即八进制的 134，所以你可以用转义序列 \134 来表示它。你也可以转义其他特殊字符，但没有必要。有些转义序列（比如 \a）在 C 中有效但在汇编中无效，所以八进制转义序列是转义任意字符最安全的方式。

我们会把每个 PointerInit 发射为一条 .quad 伪指令，后跟我们想要指向的标号。我们把 CharInit 和 UCharInit 转换为 .byte 伪指令，它的工作方式与 .long 和 .quad 完全相同。发射一个按 1 字节对齐的对象时，.align 伪指令写不写都行。根据定义，每个对象都至少按 1 字节对齐，所以指定 1 字节对齐没有任何效果。

在 Linux 上，字符串常量将和浮点常量一起存放在 .rodata 节中。在 macOS 上，它们将存放在 .cstring 节中。如果你为浮点常量使用了局部标号（以 .L 或 L 开头），你也应该为字符串常量使用局部标号。为 Data 操作数添加这个前缀的逻辑不会改变；我们仍然会在后端符号表中查找每个 Data 操作数，并在其 is_constant 属性为真时添加这个前缀。

## 又见 “Hello, World!”

回到第 9 章，我们当时是一次打印一个字符地输出 "Hello, World!"。现在，我们可以使用 puts 标准库函数编写一个更传统的 "Hello, World!" 程序，它的签名如下：

```c
int puts(const char *s);
```

由于我们不支持 const，我们声明 puts 时会去掉它。清单 16-33 展示了我们新的 "Hello, World!" 程序。

```c
int puts(char *c);
int main(void) {
    puts("Hello, World!");
    return 0;
}
```

*清单 16-33：用 puts 打印一个字符串*

这段代码并不完全合法，因为 puts 的声明与标准库中的定义不兼容。不过，尽管有这点小小的违规，程序应该仍能正确工作。编译它，然后运行它，向 stdout 打印一条消息：

```bash
$ ./hello_world
Hello, World!
```

如果你想玩得更疯一点，甚至可以编译清单 16-34，它从 stdin 读取输入。

```c
int getchar(void);
int puts(char *c);
char *strncat(char *s1, char *s2, unsigned long n);
char *strcat(char *s1, char *s2);
unsigned long strlen(char *s);

❶ static char name[30];
❷ static char message[40] = "Hello, ";

int main(void) {
    puts("Please enter your name: ");

    int idx = 0;
    while (idx < 29) {
        int c = getchar();

        // 将 EOF、空字节或换行符视为输入结束
        if (c <= 0 || c == '\n') {
            break;
        }

        name[idx] = c;
        idx = idx + 1;
    }

  ❸ name[idx] = 0; // 为 name 添加结尾的空字节

    // 把 name 追加到 message，为空字节
    // 和感叹号留出空间
    strncat(message, name, 40 - strlen(message) - 2);

    // 追加感叹号
    strcat(message, "!");
    puts(message);
    return 0;
}
```

*清单 16-34：从 stdin 读取*

正如清单 16-33 声明 puts 时省去了 const 限定符，这个程序在声明几个库函数时也省去了它们惯常带的限定符，包括 const 和 restrict。我们用 getchar 一次一个字符地从 stdin 读取，因为使用 C 标准库函数从 stdin 读取的大多数其他方式，我们的编译器都不容易处理。

清单 16-34 声明了两个静态数组：name 和 message。由于 name 是静态的且没有显式的初始化器，它将被初始化为全零 ❶。message 的开头用字符串 "Hello, " 初始化，其余部分用空字节填充 ❷。这个程序调用 puts 输出一条提示语，然后在循环中调用 getchar 把用户的响应一次一个字符地读入 name 数组。当 getchar 返回负数（表示文件结束或错误）、空字节或换行符时，或者当我们已经读入 29 个字符时——以先到者为准——我们退出循环。（我们检查结果是否为负，而不是像普通 C 程序那样把它与 EOF 宏比较，因为我们无法包含定义 EOF 的 <stdio.h>。）最多读入 29 个字符是为结尾的空字节留出空间，退出循环后我们把它加到 name 末尾 ❸。

对 strncat 的调用把用户的名字追加到 message，随后对 strcat 的调用追加一个感叹号。最后，第二次调用 puts 把整条消息写入 stdout。你的编译器应该能处理这个清单；动手试试吧！我要用这个程序向我的狗 Arlo 问好。（我答应过他至少在这本书里提他一次。）

你的编译器现在可以处理与文本打交道的程序了。在本章中，你学习了如何对字符串字面量和字符常量做词法分析，并扩展了类型检查器来区分常量字符串与初始化数组的字符串字面量。你还引入了在符号表和 TACKY IR 中定义常量的新方式。在下一章中，你将引入两个让动态内存分配更容易的特性：sizeof 运算符和 void 类型。

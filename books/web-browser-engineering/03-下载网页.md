# 第二部分　加载页面（Part 2: Loading Pages）

# 第 1 章　下载网页

*Chapter 1: Downloading Web Pages*

Web 浏览器显示由 URL 标识的信息。而第一步，就是用这个 URL 去连接 Internet 上的某台服务器，并从中下载信息。

## 1.1 连接到服务器

浏览 Internet 从 URL（uniform resource locator，统一资源定位符）¹ 开始，它是一个短字符串，用于标识浏览器要访问的特定网页。

URL 由三部分组成（见图 1.1）：方案（scheme）说明如何获取信息；主机名（host name）说明从哪里获取；路径（path）说明要获取什么信息。URL 还有一些可选部分，比如端口（port）、查询（query）和片段（fragment），我们稍后会见到。

```text
http://example.org/index.html
```

（方案 `http://` ＋ 主机名 `example.org` ＋ 路径 `/index.html`）

*图 1.1　URL 的语法。*

有了 URL，浏览器就可以开始下载网页的过程。浏览器首先请求本地操作系统（operating system，OS）帮它与主机名所描述的服务器建立联系。OS 随后与一台域名系统（Domain Name System，DNS）服务器通信，由它把 example.org 这样的主机名转换²成 93.184.216.34 这样的目标 IP 地址。³接着，OS 借助所谓路由表（routing table）来决定用哪种硬件与该目标 IP 地址通信最合适（比如无线或有线），然后通过设备驱动程序（device driver）在线缆上或空中发送信号。⁴这些信号会被一系列路由器（router）⁵接收并转发，每个路由器都会选择发送消息的最佳方向，使消息最终到达目的地。⁶当消息到达服务器时，连接就建立起来了。总之，这里的要点是：浏览器告诉 OS「嘿，帮我接通 example.org」，然后它就照办了。

在许多系统上，你可以用 telnet 程序建立这种连接，像这样：⁷

```text
telnet example.org 80
```

（注意：当你看到黑色边框的代码块时，表示该代码只是一个示例，并不是我们浏览器代码的一部分。）

> **安装**
>
> 你可能需要安装 telnet，它常常默认被禁用。在 Windows 上，打开控制面板中的「程序和功能 / 启用或关闭 Windows 功能」[2]；你需要重启电脑。运行它时，它会清屏而不是打印什么内容，除此之外一切正常。在 macOS 上，你可以用 `nc -v` 命令来代替 telnet：输出会略有不同，但工作方式是一样的。在大多数 Linux 系统上，你可以从包管理器安装 telnet 或 nc，通常位于名为 telnet 和 netcat 的软件包中。

你会得到类似这样的输出：

```text
Trying 93.184.216.34...
Connected to example.org.
Escape character is '^]'.
```

这说明 OS 已把主机名 example.org 转换成 IP 地址 93.184.216.34，并成功连接上了。⁸现在你可以和 example.org 对话了。

> **深入探索**
>
> URL 的语法定义在 RFC 3987 [3] 中，它的第一作者是 Tim Berners-Lee——这一点也不奇怪！第二作者是 Roy Fielding，他是 HTTP 设计的重要贡献者，还因在其博士论文 [4] 中描述 Web 的表述性状态转移（Representational State Transfer，REST）架构而闻名，该论文解释了 REST 如何让 Web 以去中心化的方式成长。如今，许多服务提供同样遵循这些原则的「RESTful API」，不过围绕它似乎存在一些混淆 [5]。

## 1.2 请求信息

连接建立之后，浏览器就向服务器请求信息，方式是给出自己的路径（path）——也就是 URL 中主机名之后的部分，例如 /index.html。请求的结构如图 1.2 所示。把下面内容输入 telnet 试一试。

```text
GET /index.html HTTP/1.0
Host: example.org
```

（方法 `GET`、路径 `/index.html`、HTTP 版本 `HTTP/1.0`；头名称 `Host`、值 `example.org`）

*图 1.2　带注释的 HTTP GET 请求。*

这里，单词 GET 表示浏览器想要接收信息，⁹接下来是路径，最后是 HTTP/1.0 这个词，它告诉主机浏览器说的是 1.0 版的 HTTP [6]。HTTP 有多个版本（0.9、1.0、1.1、2.0 和 3.0 [7]）。HTTP 1.1 标准增加了不少有用的特性，比如 keep-alive（长连接），但为了简单起见，我们的浏览器不会使用它们。我们也不实现 HTTP 2.0；它比 1.x 系列复杂得多，是为大型复杂的 Web 应用设计的，而我们的浏览器反正也运行不了这类应用。

第一行之后，每一行都包含一个头（header），它有一个名称（如 Host）和一个值（如 example.org）。不同的头含义不同；例如 Host 头会告诉服务器你认为它是谁。¹⁰还有很多其他头可以发送，但目前我们先只用 Host。

最后，头之后是一个空行；它告诉主机你已发送完所有头。所以在 telnet 中输入一个空行（在输入请求的两行之后再按一次 Enter），你应该就会收到 example.org 的响应。

> **深入探索**
>
> HTTP/1.0 标准化于 RFC 1945 [8]，HTTP/1.1 标准化于 RFC 2616 [9]。HTTP 的设计初衷就是易于理解和实现，使任何类型的计算机都能轻松采纳它。你可以直接在 telnet 里输入 HTTP 并非巧合！HTTP 是一个「基于行的协议」（line-based protocol），使用纯文本和换行符，这与电子邮件的简单邮件传输协议（Simple Mail Transfer Protocol，SMTP [10]）类似，这也不是偶然。归根结底，这整套模式源自早期计算机只有基于行的文本输入这一事实。实际上，最早的两个浏览器之一就采用了行模式 UI [11]。

## 1.3 服务器的响应

服务器的响应以图 1.3 中这一行开始。它告诉你：主机确认它也讲 HTTP/1.0，并且它认为你的请求「OK」（其数字代码为 200）。你可能熟悉 404 Not Found；那是另一个数字代码和响应，403 Forbidden 和 500 Server Error 也是如此。这类代码有很多，它们的组织方案相当巧妙：¹¹

- 100 多的是信息性消息；
- 200 多的表示你成功了；
- 300 多的要求后续操作（通常是重定向）；
- 400 多的表示你发送了错误的请求；
- 500 多的表示服务器处理请求出错。

注意这里有 400 多和 500 多两组错误代码，用来告诉你谁是过错方——服务器还是浏览器——这一点设计得非常妙。¹²你可以在 Wikipedia [13] 上找到所有代码的完整列表，而且新的代码也时不时会被加入。

```text
HTTP/1.0 200 OK
```

（HTTP 版本 `HTTP/1.0`、响应码 `200`、响应描述 `OK`）

*图 1.3　HTTP 响应首行的注释说明。*

在 200 OK 这一行之后，服务器会发送它自己的头。我做这个实验时，收到的是下面这些头（你的会有所不同）：

```text
Age: 545933
Cache-Control: max-age=604800
Content-Type: text/html; charset=UTF-8
Date: Mon, 25 Feb 2019 16:49:28 GMT
Etag: "1541025663+gzip+ident"
Expires: Mon, 04 Mar 2019 16:49:28 GMT
Last-Modified: Fri, 09 Aug 2013 23:54:35 GMT
Server: ECS (sec/96EC)
Vary: Accept-Encoding
X-Cache: HIT
Content-Length: 1270
Connection: close
```

这里面的内容很多：有关于你所请求信息的（Content-Type、Content-Length 和 Last-Modified），关于服务器本身的（Server、X-Cache），关于浏览器应当把这份信息缓存多久的（Cache-Control、Expires、Etag），还有各种其他内容。我们暂时先跳过。

浏览器 → `GET /index.html HTTP/1.0` → 服务器；服务器 → `HTTP/1.0 200 OK` → 浏览器。

*图 1.4　一对 HTTP 请求与响应，就是 Web 浏览器从 Web 服务器获取网页的方式。*

头之后是一个空行，再往后是一大段 HTML [14] 代码。这称为服务器响应的主体（body），你的浏览器知道它是 HTML，靠的是 Content-Type 头，它标明这是 text/html。正是这段 HTML 代码包含了网页本身的内容。

HTTP 请求/响应事务总结如图 1.4 所示。现在让我们从手动建立连接切换到 Python。

## 1.4 用 Python 实现 Telnet

到目前为止，我们一直在用 telnet 与另一台计算机通信。但事实证明 telnet 是个相当简单的程序，我们可以用编程的方式做同样的事情。这需要从 URL 中提取主机名和路径、创建套接字（socket）、发送请求并接收响应。¹³

让我们从解析 URL 开始。我打算让解析 URL 的代码返回一个 URL 对象，并把解析代码放进构造函数（constructor）里：

```python
class URL:
    def __init__(self, url):
        # ...
```

`__init__` 方法是 Python 类构造函数的特殊语法，而 `self` 参数——任何方法都必须把它作为第一个参数——是 Python 中对应 C++ 或 Java 里 this 的写法。

先从方案（scheme）开始，它通过 `://` 与 URL 的其余部分分隔。我们的浏览器只支持 http，所以也顺便检查一下：

```python
class URL:
    def __init__(self, url):
        self.scheme, url = url.split("://", 1)
        assert self.scheme == "http"
```

现在必须把主机和路径分开。主机位于第一个 / 之前，而路径就是这个斜杠及其后的所有内容。

```python
class URL:
    def __init__(self, url):
        # ...
        if "/" not in url:
            url = url + "/"
        self.host, url = url.split("/", 1)
        self.path = "/" + url
```

（当你看到像这样带有 `# ...` 的代码块时，表示你是在向已有的方法或代码块中添加代码。）`split(s, n)` 方法会在字符串中前 n 个 s 处切分字符串。注意，这里处理主机名与路径之间那个斜杠的逻辑有点绕：那个（可选的）斜杠属于路径的一部分。

现在 URL 对象有了 host 和 path 字段，我们就可以下载该 URL 处的网页了。我们在一个新方法 `request` 中完成这件事：

```python
class URL:
    def request(self):
        # ...
```

注意，在 Python 中写方法时永远要写上 `self` 参数。以后我不会每次都这么大张旗鼓地介绍一个方法的定义——如果你看到一个代码块里的代码位于某个尚不存在的方法或函数中，那就表示我们正在定义它。

下载网页的第一步是连接到主机。操作系统为此提供了一项叫做「套接字」（socket）的功能。当你想与其他计算机对话（无论是告诉它们什么，还是等它们告诉你什么）时，你就创建一个套接字，然后用这个套接字来回发送信息。套接字分为几种不同的类别，因为与其他计算机通信的方式有多种：

- 套接字有一个地址族（address family），它告诉你如何找到对方计算机。地址族的名称以 AF 开头。我们要的是 AF_INET，不过 AF_BLUETOOTH 是另一个例子。
- 套接字有一个类型（type），它描述将要进行的对话的种类。类型的名称以 SOCK 开头。我们要的是 SOCK_STREAM，它意味着每台计算机都可以发送任意数量的数据；此外还有 SOCK_DGRAM，使用它时计算机之间互发的是固定大小的数据包（packet）。¹⁴
- 套接字有一个协议（protocol），它描述两台计算机建立连接的步骤。协议的名称取决于地址族，我们要的是 IPPROTO_TCP。¹⁵

把这些选项都选定后，就可以像这样创建套接字：¹⁶

```python
import socket

class URL:
    def request(self):
        s = socket.socket(
            family=socket.AF_INET,
            type=socket.SOCK_STREAM,
            proto=socket.IPPROTO_TCP,
        )
```

一旦有了套接字，你就需要让它连接到另一台计算机。为此，你需要主机和端口（port）。端口取决于你使用的协议；目前它应该是 80。

```python
class URL:
    def request(self):
        # ...
        s.connect((self.host, 80))
```

这会与 example.org 通信以建立连接，让两台计算机做好交换数据的准备。

> **怪癖**
>
> 自然，如果你处于离线状态，这是行不通的。如果你在使用代理（proxy），或者处于其他更复杂的网络环境中，它也可能无法工作。解决办法取决于你的具体环境——可能简单到关掉代理，也可能复杂得多。

注意 connect 调用中有两层括号：connect 只接受一个参数，而这个参数是一个由主机和端口组成的二元组。这是因为不同的地址族所需的参数个数不同。

> **深入探索**
>
> Python 或多或少直接实现的「套接字」API，源自 1983 年为 4.2 BSD Unix 设计的最初「Berkeley 套接字 [19]」API。当然，Windows 和 Linux 只是对该 API 的重新实现，但 macOS 和 iOS 至今确实仍在使用 [20] 大量源自 BSD Unix 的代码。

## 1.5 请求与响应

有了连接之后，我们向对方服务器发起请求。为此，我们用 send 方法向它发送一些数据：

```python
class URL:
    def request(self):
        # ...
        request = "GET {} HTTP/1.0\r\n".format(self.path)
        request += "Host: {}\r\n".format(self.host)
        request += "\r\n"
        s.send(request.encode("utf8"))
```

send 方法只是把请求发送给服务器。¹⁷这段代码里有几处必须完全正确的地方。首先，换行符一定要用 \r\n 而不是 \n，这一点非常重要。同样关键的是，末尾要放两个 \r\n 换行，这样请求结尾的那个空行才会被发送出去。如果你忘了这一点，对方计算机会一直等你发送那个换行符，而你也会一直等它的响应。¹⁸

还要注意 encode 调用。发送数据时，务必记住你发送的是原始的比特和字节；它们可能构成文本、图像或视频。而 Python 字符串专门用于表示文本。encode 方法把文本转换成字节，还有一个反方向的对应方法 decode。¹⁹Python 通过给文本和字节赋予不同类型，提醒你要小心区分：

```python
>>> type("text")
<class 'str'>
>>> type("text".encode("utf8"))
<class 'bytes'>
```

如果你看到关于 str 与 bytes 的错误，那是因为你忘了在某处调用 encode 或 decode。

要读取服务器的响应，你可以使用套接字上的 read 函数，它会返回响应中已经到达的那些比特。然后你写一个循环，在数据到达时逐段收集。不过，在 Python 中你可以使用 makefile 辅助函数，它帮你把循环隐藏起来：²⁰

```python
class URL:
    def request(self):
        # ...
        response = s.makefile("r", encoding="utf8", newline="\r\n")
```

这里，makefile 返回一个类文件（file-like）对象，其中包含我们从服务器接收到的每一个字节。我指示 Python 使用 utf8 编码（encoding，即把字节与字符对应起来的方法）把这些字节转换成字符串。²¹我还告诉了 Python HTTP 那种古怪的行结尾。

现在让我们把响应拆分成几部分。第一行是状态行（status line）：²²

```python
class URL:
    def request(self):
        # ...
        statusline = response.readline()
        version, status, explanation = statusline.split(" ", 2)
```

注意，我没有检查服务器的 HTTP 版本是否与我的一致；这听起来也许是个好主意，但世界上有大量配置不当的服务器，即使你用 HTTP 1.0 与它们对话，它们也会用 HTTP 1.1 来响应。²³

状态行之后是各个头：

```python
class URL:
    def request(self):
        # ...
        response_headers = {}
        while True:
            line = response.readline()
            if line == "\r\n": break
            header, value = line.split(":", 1)
            response_headers[header.casefold()] = value.strip()
```

对于这些头，我在第一个冒号处切分每一行，并填充一张从头名称到头值的映射。头是不区分大小写的，所以我统一转换为小写。²⁴另外，HTTP 头值中的空白字符无关紧要，所以我剥掉了首尾多余的空白。

头可以描述各种信息，但有两个头尤其重要，因为它们表明我们要访问的数据正在以不寻常的方式发送。让我们确保这些头都不存在。²⁵

```python
class URL:
    def request(self):
        # ...
        assert "transfer-encoding" not in response_headers
        assert "content-encoding" not in response_headers
```

于是，发送数据的常规方式，就是头之后的所有内容：

```python
class URL:
    def request(self):
        # ...
        content = response.read()
        s.close()
```

我们要显示的正是主体，所以把它返回：

```python
class URL:
    def request(self):
        # ...
        return content
```

现在让我们实际显示响应主体中的文本。

> **深入探索**
>
> Content-Encoding [22] 头允许服务器在发送网页之前先压缩它们。大型的、文本密集的网页压缩效果很好，因此页面加载得更快。浏览器需要在它的请求中发送 Accept-Encoding 头 [23]，列出它支持的压缩算法。Transfer-Encoding [24] 与之类似，还允许数据「分块」（chunked）传输，许多服务器似乎会把分块与压缩结合使用。

## 1.6 显示 HTML

响应主体中的 HTML 代码定义了你在浏览器窗口访问 http://example.org/index.html 时看到的内容。在以后的章节里我还会大量、大量地谈论 HTML，不过现在先让它保持非常简单。HTML 中有标签（tag）和文本（text）。每个标签以 < 开始、以 > 结束；一般来说，标签告诉你某段内容是什么类型的东西，而文本是实际的内容。²⁶大多数标签成对出现，包括开始标签和结束标签；例如，页面的标题就被一对标签包围：<title> 和 </title>。每个标签在尖括号内有一个标签名（比如这里的 title），随后可选地有一个空格加属性（attribute）；与之配对的标签则以 / 开头后跟标签名（没有属性）。

那么，为了打造我们这个非常非常简单的 Web 浏览器，让我们取出页面的 HTML，打印其中所有的文本，但不打印标签。²⁷我把这件事放在一个新函数 show 里完成：²⁸

```python
def show(body):
    in_tag = False
    for c in body:
        if c == "<":
            in_tag = True
        elif c == ">":
            in_tag = False
        elif not in_tag:
            print(c, end="")
```

这段代码相当复杂。它逐字符遍历请求主体，并有两个状态：in_tag（当前位于一对尖括号之间）和非 in_tag。当前字符是尖括号时，就在这两个状态之间切换；不在标签内部的普通字符则被打印出来。²⁹

现在，只要把 request 和 show 串起来，我们就能加载一个网页了：³⁰

```python
def load(url):
    body = url.request()
    show(body)
```

再加上以下代码，以便从命令行运行 load：

```python
if __name__ == "__main__":
    import sys
    load(URL(sys.argv[1]))
```

第一行是 Python 版的主函数（main function），只有从命令行执行这个脚本时才会运行。这段代码从命令行读取第一个参数（sys.argv[1]）并将其用作 URL。试着在 URL http://example.org/ 上运行这段代码：

```text
python3 browser.py http://example.org/
```

你应该会看到一段简短的文字，欢迎你来到官方示例网页。你也可以拿本章 [25] 来试一试！

> **深入探索**
>
> HTML 与 URL 和 HTTP 一样，其设计初衷都是在基本层面上非常易于解析和显示。早期 HTML 的特性非常少，因此完全可能写出一个并不比我们这里的代码复杂多少的程序，却仍能以可用的方式显示内容。就连我们这个超级简单的 HTML 解析器，也已经能打印出 browser.engineering [26] 网站的文本了。

## 1.7 加密连接

到目前为止，我们的浏览器支持 http 方案。这是个相当常见的方案。但越来越多的网站正在迁移到 https 方案，而且许多网站要求必须使用它。

http 与 https 的区别在于 https 更安全——不过让我们说得再具体一点。https 方案，更正式的名称是基于 TLS 的 HTTP（HTTP over TLS，TLS 即 Transport Layer Security，传输层安全），与普通的 http 方案完全相同，唯一的例外是浏览器与主机之间的所有通信都经过加密。它的工作机制有不少细节：使用哪些加密算法、如何协商出一个共同的加密密钥，当然还有如何确保浏览器连接的是正确的主机。所涉协议层的差异如图 1.5 所示。

HTTP 的协议栈自上而下是：HTTP → TCP → IP → 802.11；HTTPS 则是：HTTP → TLS → TCP → IP → 802.11。

*图 1.5　HTTP 与 HTTPS 的区别在于增加了一个 TLS 层。*

幸运的是，Python 的 ssl 库为我们实现了所有这些细节，因此建立加密连接几乎与建立普通连接一样容易。这种易用性的代价是接受一些默认设置，它们在某些场合可能并不合适，但用于教学是没有问题的。

用 ssl 建立加密连接非常简单。假设你已经创建了套接字 s 并把它连接到了 example.org。要加密这条连接，你先用 ssl.create_default_context 创建一个上下文 ctx，再用这个上下文去包装（wrap）套接字 s：

```python
import ssl

ctx = ssl.create_default_context()
s = ctx.wrap_socket(s, server_hostname=host)
```

注意，wrap_socket 返回一个新套接字，我把它存回了 s 变量。这是因为你不希望再通过原始套接字发送任何数据：那样发送的数据既未加密，也容易造成混乱。server_hostname 参数用于检查你连接的是否是正确的服务器，它应当与 Host 头一致。

> **安装**
>
> 在 macOS 上，你需要先运行一个叫「Install Certificates」[27] 的程序，然后才能在大多数网站上使用 Python 的 ssl 包。

让我们试着把这段代码加进 request。首先，我们需要检测正在使用的是哪种方案：

```python
class URL:
    def __init__(self, url):
        self.scheme, url = url.split("://", 1)
        assert self.scheme in ["http", "https"]
        # ...
```

（注意，这里你需要用这段新代码替换原有的方案解析代码。需要替换什么，通常从上下文和代码本身就能看清楚。）

加密的 HTTP 连接通常使用 443 端口，而不是 80 端口：

```python
class URL:
    def __init__(self, url):
        # ...
        if self.scheme == "http":
            self.port = 80
        elif self.scheme == "https":
            self.port = 443
```

创建套接字时就可以用上这个端口：

```python
class URL:
    def request(self):
        # ...
        s.connect((self.host, self.port))
        # ...
```

接下来，我们用 ssl 库包装套接字：

```python
class URL:
    def request(self):
        # ...
        if self.scheme == "https":
            ctx = ssl.create_default_context()
            s = ctx.wrap_socket(s, server_hostname=self.host)
        # ...
```

你的浏览器现在应该能连接 HTTPS 网站了。

```text
http://example.org:8080/index.html
```

（端口 `8080` 位于主机名之后的冒号后面）

*图 1.6　端口在 URL 中的位置。*

既然做到这里了，顺便再加上对自定义端口的支持吧：在 URL 中，端口通过在主机名后放一个冒号来指定，如图 1.6 所示。

如果 URL 带有端口，我们可以把它解析出来并加以使用：

```python
class URL:
    def __init__(self, url):
        # ...
        if ":" in self.host:
            self.host, port = self.host.split(":", 1)
            self.port = int(port)
```

自定义端口在调试时很好用。Python 内置了一个 Web 服务器，你可以用它在你自己的计算机上提供文件服务。例如，如果你运行

```text
python3 -m http.server 8000 -d /some/directory
```

那么访问 http://localhost:8000/ 就应该能看到该目录下的所有文件。这是测试你的浏览器的好方法。

## 1.8 小结

本章从一个空文件起步，做出了一个能完成以下功能的初级 Web 浏览器：

- 把 URL 解析成方案、主机、端口和路径；
- 使用 socket 和 ssl 库连接到该主机；
- 向该主机发送 HTTP 请求，包括 Host 头；
- 把 HTTP 响应拆分成状态行、头和主体；
- 打印主体中的文本（而不打印标签）。

是的，比起 Web 浏览器，它现在还更像一个命令行工具，但它已经具备了浏览器的一些核心能力。

## 1.10 练习

**1.1　HTTP/1.1。** 在 request 函数中随 Host 一起发送值为 close 的 Connection 头。你的浏览器现在可以声明自己使用的是 HTTP/1.1 了。另外再加一个 User-Agent 头，它的值随你定——它用来向主机标识你的浏览器。要让以后添加更多头变得容易。

**1.2　file URL。** 增加 file 方案的支持，让浏览器能打开本地文件。例如 file:///path/goes/here 应当指你计算机上位于 /path/goes/here 的文件。还要做到：如果你的浏览器启动时没有给定 URL，就打开你计算机上的某个特定文件。你可以用这个文件做快速测试。

**1.3　data。** 还有一种方案是 data，它允许把 HTML 内容内联到 URL 本身。试着在真实浏览器中访问 data:text/html,Hello world! 看会发生什么。为你的浏览器添加对该方案的支持。data 方案对于编写测试特别方便，不必把测试放进单独的文件。

**1.4　实体。** 实现对小于号（&lt;）和大于号（&gt;）实体（entity）的支持。它们应当分别打印为 < 和 >。例如，如果 HTML 响应是 &lt;div&gt;，你的浏览器的 show 方法就应打印 <div>。实体让网页可以包含这些特殊字符，而不会被浏览器当作标签来解释。

**1.5　view-source。** 增加 view-source 方案的支持；访问 view-source:http://example.org/ 应显示 HTML 源码而不是渲染后的页面。为你的浏览器添加对该方案的支持。你的浏览器应当把整个 HTML 文件当作纯文本打印出来。你最好已经完成了练习 1.4。

**1.6　Keep-alive。** 实现练习 1.1；但是不要发送 Connection: close 头。相反，从套接字读取主体时，只读取 Content-Length 头给出的字节数，并且之后不关闭套接字。而是保存这个套接字，如果随后向同一台服务器发起另一个请求，就复用同一个套接字，而不是新建一个。这会加快对同一服务器的重复请求，而这种请求很常见。

**1.7　重定向。** 300 段的错误代码表示重定向。当你的浏览器遇到这种响应时，应当向 Location 头给出的 URL 发起新请求。有时候 Location 头是完整的 URL，但有时它会省略主机和方案、直接以 / 开头（表示与原始请求相同的主机和方案）。新的 URL 本身也可能又是一个重定向，所以务必处理这种情况。不过，你不希望陷入重定向循环，因此一定要限制浏览器连续跟随的重定向次数。你可以用 URL http://browser.engineering/redirect 测试，它重定向回本页；它的 /redirect2 [30] 和 /redirect3 [31] 表亲则做更复杂的重定向链。

**1.8　缓存。** 通常，同样的图片、样式和脚本会被多个页面使用；反复下载它们是一种浪费。一般来说，缓存任何 HTTP 响应都是合法的，只要它是以 GET 请求并以 200 响应收到的。³¹在你的浏览器中实现一个缓存，并通过多次请求同一个文件来测试它。服务器通过 Cache-Control 头控制缓存。为这个头添加支持，具体支持 no-store 和 max-age 这两个值。如果 Cache-Control 头包含这两个值以外的任何值，最好不要缓存该响应。

**1.9　压缩。** 增加 HTTP 压缩的支持，即由浏览器告知服务器 [32] 它可以接受压缩数据。你的浏览器必须发送值为 gzip 的 Accept-Encoding 头。如果服务器支持压缩，它的响应会带有值为 gzip 的 Content-Encoding 头，主体就是压缩过的。为这种情况添加支持。要解压数据，你可以使用 gzip 模块中的 decompress 方法。GZip 数据不是 utf8 编码的，所以要把 "rb" 传给 makefile，以处理原始字节。大多数 Web 服务器以一种叫 chunked 的 Transfer-Encoding 发送压缩数据。³²你也需要为它添加支持。

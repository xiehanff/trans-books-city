# 第 2 章　绘制到屏幕

*Chapter 2: Drawing to the Screen*

Web 浏览器不只是下载网页，还要把网页展示给用户。在二十一世纪，这意味着一个图形化应用程序。¹ 所以在本章中，我们将为我们的浏览器配备一个图形用户界面（graphical user interface，GUI）。

## 2.1　创建窗口

台式机和笔记本电脑运行的操作系统会提供桌面环境（desktop environment）：窗口、按钮和鼠标。于是职责最终被拆分：程序控制它们自己的窗口，而桌面环境控制屏幕。因此：

- 程序请求一个新窗口，而由桌面环境实际把它显示出来。
- 程序在它的窗口上绘制，桌面环境把这些内容呈现到屏幕上。
- 桌面环境把点击和按键告知程序，程序做出响应并重绘它的窗口。

手动完成这一切有点麻烦，所以程序通常会使用图形工具包（graphical toolkit）来简化这些步骤。Python 在 `tkinter` 包中自带了一个名为 Tk 的图形工具包。² 它的使用非常简单：

```python
import tkinter
window = tkinter.Tk()
tkinter.mainloop()
```

这里，`tkinter.Tk()` 请求桌面环境创建一个窗口，并返回一个你可以用来在窗口上绘制的对象。`tkinter.mainloop()` 调用会进入一个像下面这样的循环：³

```python
while True:
    for evt in pendingEvents():
        handleEvent(evt)
    drawScreen()
```

这里，`pendingEvents` 先向桌面环境询问最近的鼠标点击或按键，接着 `handleEvent` 调用你的应用程序来更新状态，然后 `drawScreen` 重绘窗口。这种事件循环（event loop）模式（参见图 2.1）在许多应用中都很常见，从 Web 浏览器到电子游戏，因为在复杂的图形应用中，它确保所有事件最终都会被处理、屏幕最终都会被更新。

*图 2.1　事件处理循环的流程图。*

示意图：USB 输入设备 → IRQ/CPU/内核 → 信号 → 浏览器处理事件 → 帧缓冲/纹理 → 绘制 → GPU/内核 → 屏幕。

> **深入探索**
> 尽管你很可能是在台式计算机上编写浏览器，但许多人通过手机或平板电脑等移动设备访问 Web。移动设备上依然有屏幕、渲染循环，以及本书讨论的大多数其他内容。⁴
>
> 不过有若干差别值得注意。应用通常是全屏的，同一时刻只有一个应用在向屏幕绘制。没有鼠标，只有一个虚拟键盘，所以交互的主要形式是触摸。还有一个桌面环境上不存在的「可视视口」（visual viewport）概念，用于兼容「仅限桌面」（desktop-only）和「适配移动」（mobile-ready）的网站以及双指缩放（pinch zoom）。⁵ 此外，屏幕像素密度高得多，但屏幕总分辨率通常更低。支持所有这些差别是可行的，但工作量相当大。本书不会再深入实现它们，只是某些情况下会作为练习。
>
> 另外，能效重要得多，因为设备靠电池运行，与此同时中央处理器（CPU）和内存明显更慢、能力更弱。这使得利用图形处理器（GPU）变得重要得多——缓慢的 CPU 让良好的性能更难实现。移动浏览器充满挑战！

## 2.2　绘制到窗口

我们的浏览器将把网页文本绘制到画布（canvas）上——一个可以在上面绘制圆、线和文本的矩形 Tk 部件（widget）。例如，你可以像这样用 Tk 创建一个画布：⁶

```python
window = tkinter.Tk()
canvas = tkinter.Canvas(window, width=800, height=600)
canvas.pack()
```

第一行创建窗口，第二行在该窗口内创建 `Canvas`。我们把窗口作为参数传入，这样 Tk 就知道在哪里显示画布。其他参数定义了画布的尺寸；我选择 800 × 600，因为那是一种常见的老式显示器尺寸。⁷ 第三行是 Tk 的一个特殊之处，它把画布定位在窗口内。Tk 也有按钮、对话框这样的部件，但我们的浏览器不会使用它们：我们需要对外观更细粒度的控制，而这正是画布所提供的。⁸

为了保持条理，让我们把这些代码放进一个类里：

```python
WIDTH, HEIGHT = 800, 600
class Browser:
    def __init__(self):
        self.window = tkinter.Tk()
        self.canvas = tkinter.Canvas(
            self.window,
            width=WIDTH,
            height=HEIGHT
        )
        self.canvas.pack()
```

创建好画布之后，你就可以调用在画布上绘制形状的方法了。让我们在 `load` 里做这件事，`load` 将被移入新的 `Browser` 类：

```python
class Browser:
    def load(self, url):
        # ...
        self.canvas.create_rectangle(10, 20, 400, 300)
        self.canvas.create_oval(100, 100, 150, 150)
        self.canvas.create_text(200, 150, text="Hi!")
```

要运行这些代码，先创建一个 `Browser`，调用 `load`，然后启动 Tk 主循环：

```python
if __name__ == "__main__":
    import sys
    Browser().load(URL(sys.argv[1]))
    tkinter.mainloop()
```

你应该会看到：一个矩形，从画布左上角附近开始，到画布中心结束；然后是矩形内的一个圆；再然后是圆旁边的文本 "Hi!"，如图 2.2 所示。

*图 2.2　预期示例输出：一个矩形、一个圆和一段文本。*

Tk 中的坐标指的是从左到右的 x 位置和从上到下的 y 位置。换句话说，屏幕底部具有更大的 y 值，与你在数学中习惯的正好相反。试着改一改上面的坐标，弄清楚每个参数分别指什么。⁹

> **深入探索**
> Tk 的画布部件比我们在这里用到的功能强大得多。正如教程 [3] 所示，你可以移动绘制到画布上的各个元素、监听每个元素上的点击事件等等。我在本书中不使用这些功能，因为我想教你如何自己实现它们。

## 2.3　布局文本

让我们在这个画布上绘制一个简单的网页。到目前为止，我们的浏览器逐字符遍历网页源代码，并把文本（不含标签）打印到控制台窗口。现在我们要把这些字符绘制到画布上。

首先，让我们把上一章的 `show` 函数改造成一个我将称之为 `lex`¹⁰ 的函数，它只返回 HTML 文档的文本内容而不打印：

```python
def lex(body):
    text = ""
    # ...
    for c in body:
        # ...
        elif not in_tag:
            text += c
    return text
```

然后，`load` 将逐字符绘制这些文本：

```python
def load(self, url):
    # ...
    for c in text:
        self.canvas.create_text(100, 100, text=c)
```

让我们在一个真实网页上测试这些代码。出于一些也许显得难以理解的原因，¹¹ 我们用《西游记》（Journey to the West）[4] 的第一回做测试——这是一部关于一只猴子的中国古典小说。把这个 URL¹² 依次送过 `request`、`lex` 和 `load`。你应该会看到一个窗口，其中一团黑色像素从窗口左上角稍微向内缩进。

为什么是一团而不是一个个字母？嗯，当然是因为我们把每个字母都画在了同一个位置，所以它们全都重叠了！让我们来修复：

```python
HSTEP, VSTEP = 13, 18
cursor_x, cursor_y = HSTEP, VSTEP
for c in text:
    self.canvas.create_text(cursor_x, cursor_y, text=c)
    cursor_x += HSTEP
```

变量 `cursor_x` 和 `cursor_y` 指向下一个字符将要出现的位置，就好像你正在把文本输入文字处理器一样。这些魔法数字——13 和 18——是我尝试了几个不同的值之后挑出来的，选的是看起来最易读的那一个。¹³

现在文本从左到右排成了一行。但对于 800 像素宽的画布、每字符 13 像素来说，一行只能容纳大约 60 个字符。读小说需要的远不止这些，所以我们还需要在到达屏幕边缘时对文本换行：

```python
for c in text:
    # ...
    if cursor_x >= WIDTH - HSTEP:
        cursor_y += VSTEP
        cursor_x = HSTEP
```

一旦 `cursor_x` 超过 787 像素，这段代码就会增大 `cursor_y` 并重置 `cursor_x`。¹⁴ ¹⁵ 该过程如图 2.3 所示。以这种方式换行让我们可以阅读不止一行的内容。

*图 2.3　绘制每个字符时光标移动过程的流程图。*

示意图：绘制字符 → 移动光标 →（到达行尾时）折行 → 绘制下一个字符。

至此，你应该能在你的浏览器里加载我们的示例页面，并且看起来会和图 2.4 差不多。

*图 2.4　在我们的浏览器中渲染出来的《西游记》第一回。*

现在我们能读到很多文本了，但仍然不是全部：如果文本足够多，并不是所有的行都能放进屏幕。我们希望用户能滚动页面来查看它的不同部分。

> **深入探索**
> 在英文文本中，你不能在一个单词中间换行（至少在不使用连字符断词（hyphenation）的情况下不行），但在中文里这是默认行为，即使是对于由多个字符组成的词也是如此。例如，「开关」由「开」和「关」组成，但在「开」之后断行完全没问题。你可以用 `word-break` CSS 属性改变默认行为：`break-all` 允许在任意位置断行，而 `auto-phrase` 甚至在中文或日语的词、短语（如「开关」）内部也阻止断行 [6]。这里的「auto」是指这些词并不是由作者标注的，而是自动检测出来的，通常基于词频表 [8] 使用动态规划（dynamic programming）[7] 实现。

## 2.4　滚动文本

滚动在页面坐标（page coordinates：这段文本距页面顶部 132 像素）与屏幕坐标（screen coordinates：由于你已经向下滚动了 60 像素，这段文本距屏幕顶部 72 像素）之间引入了一层间接——参见图 2.5。一般来说，浏览器以页面坐标来布局（layout）页面——确定页面上的每样东西放在哪里——然后以屏幕坐标来光栅化（raster）页面——绘制出所有内容。¹⁶

*图 2.5　页面坐标与屏幕坐标的区别。*

示意图：页面（完整文档）在屏幕中只显示一部分，滚动条表示当前可见区域在整页中的位置。

我们的浏览器将采用同样的拆分。目前 `load` 既计算每个字符的位置又绘制它：布局与渲染。让我们改用一个 `layout` 函数来计算并存储每个字符的位置，再由一个单独的 `draw` 函数根据存储的位置来绘制每个字符。这样，`layout` 可以按页面坐标运作，而只有 `draw` 需要考虑屏幕坐标。

让我们从 `layout` 开始。与其在每个字符上调用 `canvas.create_text`，不如把它连同它的位置一起添加到一个列表中。由于 `layout` 不需要访问 `Browser` 中的任何东西，它可以是一个独立的函数：

```python
def layout(text):
    display_list = []
    cursor_x, cursor_y = HSTEP, VSTEP
    for c in text:
        display_list.append((cursor_x, cursor_y, c))
        # ...
    return display_list
```

所得到的这个待显示内容的列表被称为显示列表（display list）。¹⁷ 由于 `layout` 全部围绕页面坐标，我们不需要为支持滚动而对它做任何其他改动。

显示列表计算好之后，`draw` 需要遍历它并绘制每个字符。由于 `draw` 确实需要访问画布，我们把它做成 `Browser` 上的一个方法：

```python
class Browser:
    def draw(self):
        for x, y, c in self.display_list:
            self.canvas.create_text(x, y, text=c)
```

现在 `load` 只需要先调用 `layout` 再调用 `draw`：

```python
class Browser:
    def load(self, url):
        body = url.request()
        text = lex(body)
        self.display_list = layout(text)
        self.draw()
```

现在我们可以添加滚动了。让我们添加一个字段来表示你已经滚动了多远：

```python
class Browser:
    def __init__(self):
        # ...
        self.scroll = 0
```

这样，页面坐标 `y` 对应的屏幕坐标就是 `y - self.scroll`：

```python
def draw(self):
    for x, y, c in self.display_list:
        self.canvas.create_text(x, y - self.scroll, text=c)
```

如果你改变 `scroll` 的值，页面现在就会上下滚动。但用户如何改变 `scroll` 呢？

大多数浏览器在你按下上下方向键、转动滚轮、拖动滚动条或在屏幕上使用触摸手势时滚动页面。为了简单起见，我们只实现下方向键。

Tk 允许你把一个函数绑定到某个键上，这会指示 Tk 在该键被按下时调用那个函数。例如，要绑定下方向键，这样写：

```python
def __init__(self):
    # ...
    self.window.bind("<Down>", self.scrolldown)
```

这里，`self.scrolldown` 是一个事件处理器（event handler）——一个每当下方向键被按下 Tk 就会调用的函数。¹⁸ 它要做的只是增大 `scroll` 并重绘画布：

```python
SCROLL_STEP = 100
def scrolldown(self, e):
    self.scroll += SCROLL_STEP
    self.draw()
```

如果你试一下，就会发现滚动把所有文本又绘制了一遍。这是因为我们在绘制新文本之前没有擦除旧文本。调用 `canvas.delete` 来清除旧文本：

```python
def draw(self):
    self.canvas.delete("all")
    # ...
```

滚动现在应该可以正常工作了！

> **深入探索**
> 存储显示列表让滚动更快：浏览器不用在每次滚动时都重新做布局。现代浏览器更进一步 [9]，即使网页因 JavaScript 或用户交互而改变，也会保留显示列表的大部分。
>
> 总的来说，滚动是用户与网页最常见的交互。真实浏览器因此在让滚动变快上投入了海量时间；本书后面还会介绍他们实现这一点的更多方式。

## 2.5　更快地渲染

应用程序必须快速重绘页面内容，交互才会感觉流畅，¹⁹ 而且必须快速响应点击和按键，用户才不会烦躁。

「感觉流畅」可以说得更精确。诸如浏览器这样的图形应用通常力争以等于屏幕刷新率（refresh rate）或帧率（frame rate）的速度重绘，以及/或者以固定的 60 Hz 重绘。²⁰ 这意味着浏览器必须在不到 1/60 秒（即 16 毫秒）内完成它的全部工作，才能跟得上。出于这个原因，16 毫秒被称为应用程序的动画帧预算（animation frame budget）。

但我们浏览器里的滚动相当慢。²¹ 为什么？事实证明，在 `create_text` 内部加载关于字符形状的信息需要一些时间。为了加速滚动，我们需要确保只在必要时才做这件事（同时保证屏幕上的像素始终正确）。

真实浏览器为此有许多相当精巧的优化，但对于我们的浏览器，让我们只做一个简单的改进：跳过绘制屏幕外的字符：

```python
for x, y, c in self.display_list:
    if y > self.scroll + HEIGHT: continue
    if y + VSTEP < self.scroll: continue
    # ...
```

第一个 `if` 语句跳过可视窗口下方的字符；第二个跳过可视窗口上方的字符。在第二个 `if` 语句中，`y + VSTEP` 是字符的下边缘，因为只有一半在可视窗口内的字符仍然必须绘制。

滚动现在应该快得舒服，希望已接近 16 毫秒的动画帧预算。²² 而且因为我们把 `layout` 和 `draw` 拆开了，实现这个优化完全不需要改动 `layout`。

> **深入探索**
> 你还应当记住，并非所有网页交互都是动画——还有诸如鼠标点击这样的离散动作。研究表明，在 100 毫秒内 [11] 响应一个离散动作通常就足够了——低于这个阈值，大多数人对离散动作的速度并不敏感。这与滚动之类的交互非常不同：对后者而言，速度一旦低于大约 60 Hz，就会相当明显地被察觉。两者之间的差异与人脑处理运动（动画）和离散动作的方式，以及大脑决定这样一个动作、执行它并理解其结果所需的时间有关。

## 2.6　总结

本章从一个简陋的命令行浏览器起步，最终得到了一个带有可滚动文本的图形用户界面。浏览器现在：

- 与你的操作系统对话以创建窗口；
- 布局文本并把它绘制到该窗口上；
- 监听键盘命令；
- 作为响应滚动窗口。

接下来，我们将让这个浏览器处理英文文本，应对诸如宽度可变的字符、行内布局和格式化等复杂性。

## 2.8　练习

### 练习 2.1　换行（Line breaks）

修改 `layout`，让它在看到换行符时结束当前行并开始新的一行。把 y 的增量设得比 `VSTEP` 更大，以营造出段落间隔的感觉。《西游记》里嵌有一些诗词；现在你可以把它们分辨出来了。

### 练习 2.2　鼠标滚轮（Mouse wheel）

添加在按下上方向键时向上滚动的支持。确保你不能滚动到页面顶部之上。然后绑定 `<MouseWheel>` 事件，它在你用鼠标滚轮滚动时触发。²³ 关联的事件对象有一个 `event.delta` 值，告诉你滚动的距离和方向。不幸的是，macOS 和 Windows 给出的 `event.delta` 对象符号相反、比例不同，而在 Linux 上滚动改用 `<Button-4>` 和 `<Button-5>` 事件。²⁴

### 练习 2.3　调整大小（Resizing）

让浏览器可以调整大小。为此，把 `fill` 和 `expand` 参数 [13] 传给 `canvas.pack`，并绑定 `<Configure>` 事件，它在窗口大小改变时发生。窗口新的宽度和高度可以在事件对象的 `width` 和 `height` 字段中找到。记住，当窗口大小改变时，换行位置也必须改变，所以你需要再次调用 `layout`。

### 练习 2.4　滚动条（Scrollbar）

阻止你的浏览器向下滚动越过显示列表的最后一条。²⁵ 在屏幕右缘绘制一个蓝色的矩形滚动条。确保滚动条的大小和位置反映了浏览器正在查看整个文档的哪个部分，如图 2.5 所示。如果整个文档都能放进屏幕，则隐藏滚动条。

### 练习 2.5　Emoji

为你的浏览器添加 emoji 支持。emoji 是字符，你可以调用 `create_text` 来绘制它们，但效果不太好。相反，前往 OpenMoji 项目 [14]，把「grinning face」（咧嘴笑）[15] 的 emoji 下载为 PNG 文件，把它调整为 16 × 16 像素大小，并保存到浏览器所在的同一文件夹。使用 Tk 的 `PhotoImage` 类加载该图像，然后用 `create_image` 方法把它绘制到画布上。事实上，下载整个 OpenMoji 库（在右上角找「Get OpenMojis」按钮）——这样你的浏览器就能查找页面中用到的任何 emoji。

### 练习 2.6　about:blank

目前，畸形的 URL 会导致浏览器崩溃。最好能为这种情况提供错误恢复，转而显示一个空白页面，让用户可以修正错误。为此，添加对特殊 URL `about:blank` 的支持——它只渲染一个空白页面——并让畸形的 URL 自动按 `about:blank` 来渲染。

### 练习 2.7　替代的文字方向（Alternate text direction）

并非所有语言都从左向右阅读和布局。阿拉伯语、波斯语和希伯来语是从右向左语言的典型例子。通过浏览器的一个命令行标志为此实现基本支持。²⁶ 英文句子仍应从左向右布局，但应该从屏幕右侧开始生长（在你喜欢的浏览器中加载这个示例 [17]，你就明白我的意思了）。²⁷

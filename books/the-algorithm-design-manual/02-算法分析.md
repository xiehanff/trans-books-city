# 第2章 算法分析

算法是计算机科学中最重要和最历久弥新的组成部分，其原因是它能以一种与语言和机器都无关的方式来研究。这就意味着，我们需要一些技术可让我们无须实现算法即可比较不同算法的效率.我们将介绍两种最重要的工具：（1） RAM计算模型，（2）最坏情况复杂度的渐近分析，评估算法意义下的性能会用到“大O”记号，事实证明它对于算法的比较分析以及设计更高效算法都是不可或缺的.尽管对于那些声称自己从事实际工作的人可能会碰到理论分析的这些概念而脸色苍白（他们确实难以学会），我们还是提供了这部分内容，因为它在构想算法时实在是太有用了.

算法分析本质上是一种记分（keeping score）方法，，它应该是本书中数学要求最高的部分了.不过你一旦理解了算法分析思想背后的直观意义，那种数学公式的形式化处理就变得容易多了.

## 2.1 RAM计算模型

与机器无关的算法设计依赖于一种假想中的计算机，它称之为随机存取机（Random Access Machine）或RAM.在此计算模型下，我们所用的计算机有下列特性：

- 每个单功能操作（例如：+，*，一，三，主，函数调用）恰好用去一个时间步（简称步）.
- 循环和子程序（subroutine）不可视为单功能操作.它们反而是多个单步操作所组成的复合操作.同理，将排序看成单步操作也是说不通的，因为对1000 000项数据排序所需时间肯定比对10项数据排序用时要长得多.运行完一段循环或执行一段子程序所用时间取决于循环迭代次数或子程序的具体特征.
- 每次内存访问恰好用去一个时间步，此外，我们需要多少内存就有多少，RAM模型不关注数据是在缓存中还是在磁盘中.

在RAM模型下，我们可以通过数出某个算法在一个给定算例上所用的总步数来测算运行时间.若我们假设RAM每秒执行固定步数（具体数值会给定），这种操作的计数可自然地转换成实际运行时间.

RAM是一种描述计算机如何运行的简单模型. 可能这个模型说起来太简单了.在大多数处理器上，两数相乘毕竟要比两数相加费时更多，这违背了RAM模型的第1条假设.最先进的编译器的循环展开和超线程技术可能完全违背第2条假设，当然，内存访问时间肯定也译者注：可以理解成逐个记下所有的时间和空间的开销最后算出总数.

会有很大的差异，这取决于数据位于缓存中还是磁盘上.这三点将使RAM基本假设的正确性不复存在. 尽管上面对RAM模型提出了好些抱怨，然而你要是想理解某个算法如何在一台真实计算机上运行，那么RAM就是为此而设的绝佳模型，并且它已经被无数事实所验证.我们既想保留计算机运行过程的本质要素，同时还要让模型便于理论分析，而RAM则达到了一种非常不错的折中方案.

之所以用RAM模型，是因为它在实际中非常有用. 每种模型都有一个适用范围，超过这个尺度该模型便会无效.例如，我们采用“地球是平的”这个模型.你可能认为这是一个拙劣的模型，因地球其实是球体，人类早己相当清楚地确认过这个事实.

但是，当我们给房屋打地基时，这种平地球（Bat earth）模型已足够精确，因此使用该模型是可靠的.平地球模型用起来非常简易方便，因此，要是完全不需要球体模型时你绝对不想去考虑复杂的球体模型.工对于RAM计算模型情况也如此.

我们所做的这种抽象通常都能很好地发挥作用.很难设计出一种算法能让RAM模型给你一个与实际执行相去甚远的结果.RAM的稳健性可让我们以一种与机器无关的方式分析算法.

> [!TIP] 所得教益：算法能以一种与语言和机器都无关的方式来理解和研究.

### 2.1.1 最好、最坏和平均情况下的复杂度

使用RAM计算模型，对于任意给定输入算例，我们只需将算法在RAM上执行便可数出算法处理完该算例需要用多少步，然而，要弄清一个算法在一般情况下有多好或有多差，我们必须要了解它在所有算例上是如何运行的. 要搞懂最好、最坏和平均情况下的复杂度，可考虑一个算法在所有算例上的运行情况，注意算例的数据必须能够被该算法所接受.对于排序问题，能被接受的输入算例集包含了n个键的所有排列，而n可取任意值.

### 停下来想想：回归定义

问题：2ⁿ⁺¹ = Θ(2ⁿ) 吗？解：运用大 O 记号的最好方式就是回到定义，再利用它推理。

- 2ⁿ⁺¹ = O(2ⁿ) 吗？是。因为 2ⁿ⁺¹ = 2·2ⁿ，所以对任意 c ≥ 2，都有 2ⁿ⁺¹ ≤ c·2ⁿ。
- 2ⁿ⁺¹ = Ω(2ⁿ) 吗？是。因为对任意 0 < c ≤ 2，都有 2ⁿ⁺¹ ≥ c·2ⁿ。大 O 界和大 Ω 界合起来便可知 2ⁿ⁺¹ = Θ(2ⁿ)。

### 停下来想想：和的平方能用平方和来界定吗？

问题：(x + y)² = O(x² + y²) 吗？解：由定义知，此式成立当且仅当存在某个 c，使得 (x + y)² ≤ c(x² + y²)。展开左侧可得 x² + 2xy + y²。若 x ≤ y，则 2xy ≤ 2y² ≤ 2(x² + y²)；若 x ≥ y，则 2xy ≤ 2x² ≤ 2(x² + y²)。因此中间项不超过右侧表达式的两倍，故 (x + y)² ≤ 3(x² + y²)，从而 (x + y)² = O(x² + y²)。

### 2.6.5 快速求幂

```text
    if n = 0 then
        return 1
    x = power(a, floor(n / 2))
    if n 为偶数 then

    else

```

## 2.7 对数的特性

正如我们所看到的，声明 $b^x=y$ 等价于说 $x=\log_a y$。其中 $b$ 这项通常称为对数的底（base）。由于数学上和历史上的原因，下列三种底特别重要：

- 底 $b=2$——二进制对数（binary logarithm），通常记为 $\log_2 x$，它是以 2 为底的对数。每当不断进行减半（例如二分查找）或加倍（例如树中的结点）时，它就会出现；我们已见过相关实例。大部分对数的算法应用必然会涉及二进制对数。

- 底 $b=e$——自然对数（natural logarithm），通常记为 $\ln x$，它是以 $e=2.71828\ldots$ 为底的对数。$\ln$ 的逆是在计算器上的指数函数 $\exp(x)=e^x$。因此，将这两个函数复合则会得出：

$$
\exp(\ln x)=x
$$

- 底 $b=10$——以 10 为底的对数或常用对数（common logarithm），通常记为 $\lg x$。在手持计算器未出现之前，计算尺和对数表都采用了这种底.

我们已见过对数的一条重要特性，即

$$
\log_a(xy)=\log_a x+\log_a y
$$

另一个事实也要记住：对数可以轻松地换底，它是下述公式的推论：

$$
\log_a b=\frac{\log_c b}{\log_c a}
$$

因此，要将 $\log_a b$ 从以 $a$ 为底的对数换成以 $c$ 为底的对数，只要除以 $\log_c a$ 即可。很容易将常用对数函数换成自然对数函数，反之亦然。

### 2.9.1 一些深奧难懂的函数
常见复杂度函数类在2.3.1节中己给出.此外，更多深奥难懂的函数将在高等算法分析中露面.虽然我们在本书中不太会看到它们，但了解它们指的是什么和来自哪里仍然很有价值.

- 逆Ackermann函数（inverse Ackermann's function）f(n) = α(n)——此函数出现在若干算法的详细分析中，尤其是6.1.3节所讨论的合并一查找（Union-Find）数据结构.

此函数的精确定义以及它到底是怎么来的，此处不作深入讨论.把它看成是极客用语足矣，这个词代表增长最慢的复杂度函数，该函数不像常函数f（n）=1那样基本不增长，它在n—∞时最终会达到无穷大，但会很慢很慢才会到达，事实上，对于任何物理世界中所能表述的n而言，a（n） <5.

- f(n) = log log n——“log log”函数就是n的对数的对数。一个自然的例子是：在一个仅有 log n 个元素的有序数组中做二分查找。
- f(n) = log n / log log n——此函数增长速度比log n略慢一点，因为它所除以的函数增长更慢。要看看这在哪出现，考虑一棵度为d且有n个叶子结点的有根树.对于二叉树情况（即d=2），高度h可由下式给出：

n = 2^h  →  h = log n

上式是通过对等式两边取对数而得.现在考虑当度为d=logn情况下的这样一棵树，则有

n = (log n)^h  →  h = log n / log log n

- f(n) = log² n——这是对数函数的积，即(log n)×(log n)。对n个元素做二分查找，其中每个元素都是从1到n²范围内的整数，如果统计所查看的比特总数，此函数将出现。每个这样的整数要 log(n²) 个比特表示，而我们查了 log n 个整数，共计 2 log² n 比特。

“对数平方”函数通常出现在那些有着复杂嵌套的数据结构设计中，例如一棵二叉树的每个结点代表着另一种数据结构（它可能依据另一个键定次序）.

- √n——平方根不是很深奥的知识，但 √n 是“次线性多项式”这类函数的典型代表，这是因为 √n = n^(1/2)。此类函数出现在构建包含 n 个点的 d 维网格时。边长为 √n 的正方形面积为 n，边长为 n^(1/3) 的立方体体积也为 n。一般情况下，边长为 n^(1/d) 的 d 维超立方体体积为 n。
- f(n) = n^(1+ε)——Epsilon（即 ε）是表示某常数的数学符号，可以令它任意小，但绝不能让它小到完全不见了（为0）。下述方式可让其出现：假定我设计了一个算法能在 2^c n^(1+1/c) 时间内运行，现在我开始挑选到底哪个 c 是我最想要的。对于 c=2，时间为 4n^(3/2)，即 O(n^(3/2))；对于 c=3，时间为 8n^(4/3)，这个更好。实际上，我若令 c 增大，指数将一直变小。问题在于我不能让 c 任意大，这样 2^c 项将会显示其强势之处。我们只能将这个算法的运行时间描述为 O(n^(1+ε)) 来代替 2^c n^(1+1/c) 式子，而这个最佳的 ε 值选取工作还是留给旁观者吧。

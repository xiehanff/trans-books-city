# 第3章 数据结构

在运行缓慢的程序中更换数据结构，效果类似于对患者实施器官移植手术.那些重要的抽象数据类型（abstract data types），如容器、字典、优先级队列等，都可用功能等价但手段各异的数据结构（data structures）实现.由于从原理上来讲，我们仅仅是从一种正确的实现方案转换为另一种同样正确的实现方案而已，所以更换数据结构不会影响到程序的正确性.

然而，新的实现方法会重新协调抽象数据类型中各种操作的执行时间，因此整个程序的性能会有惊人的改善，正如患者所需要的只是移植某一个器官，解决程序运行缓慢的问题可能也仅需更换一个模块. 不过，生来就有颗健康心脏的人显然比苦等移植手术的患者幸福.因此，从一开始便围绕着优良的数据结构进行程序设计，才能获得最大收益.我们假设读者此前对基本的数据结构和指针操作已有所了解.

不过，如今的数据结构课程（CS II）-更关注数据抽象和面向对象，而较少涉及应如何在内存中表示数据的存储结构这样的细节问题，我们将对这部分内容进行回顾，以确保你能着实明了. 学习数据结构与其他科目一样，掌握基本内容远胜于略知高深概念.所以我们将侧重于三种基本的抽象数据类型（即容器、字典和优先级队列），并考虑如何用数组和列表实现它们.当然还存在众多更为精巧的实现方法，而选用时应如何权衡的细节问题将留待便览中相应抽象数据类型的词条中详加讨论.

## 3.1 紧接数据结构与链接数据结构

数据结构基本上可简单地划分为两类：紧接（contiguous）和链接（knked），这取决于该数据结构是基于数组还是指针：

- 紧接分配数据结构（contiguous allocated data structures）由许多相邻的内存块组合而成一体，数组、矩阵、堆、散列表皆属此类.
- 链接数据结构（linked data structures）由大量分散于各处的内存块通过指针连接而成，列表、树、图的邻接表皆属此类.

在本节中，我们将评述紧接数据结构与链接数据结构各自的相对优势二者的权衡相当微妙，绝非一目了然的事.因此，即便是对这两种数据结构都已熟悉的读者，我仍强烈建议你跟我一起重温它们.

### 3.1.1 数组

数组（array）是最基本的紧接数据结构，数组是一种由固定大小的数据记录所组成的结构，它能让我们通过下标（indea）或（与其等价的）存储地址高效地对其中的元素进行定位将数组比作一条盖满房屋的街道真是再恰当不过了，数组元素相当于这里的房屋，而数组下标则相当于房屋门牌号.假定所有房屋大小相同，且从1到n依次编号，那么可通过门牌号迅速算出每间房屋的精确位置.1 紧接分配的数组具有下列优点：

- 给定下标可在常数时间内访问元素（constant-time access given the inder）-

一由于数组中每个元素的下标直接对应了内存中的特定地址，如果能知道下标，则可迅速访问该数据项.

- 节约空间（space efficiency）——数组完全由数据构成，不存在因链接或其他格式信息（formatting information）而造成的浪费，此外，数组由数目固定的若干个记录松成，从而不需要记录终止（end-of-record）信息来标记数组结束.
- 内存局部性（memory locality）编程常常需要对数据结构中所有元素从头至尾进行迭代，事实上这是程序设计中的一种惯用法（idiom）. 由于数组体现了极好的内存局部性，因此它非常适宜于开展迭代.在对数据进行相继访问时，数据地址在物理上的连续性有助于充分利用现代计算机系统结构中的高速缓存.

数组的不足之处在于，我们无法在程序执行过程中调整数组的大小，假定初始仅分配了能容纳n个记录的空间（房间），如果我们试图加入第n+1个记录（房客），程序便会立刻崩溃.为弥补此缺陷，我们可在初始时分配非常大的数组，但这种方案会浪费空间，而且仍然会面临空间不足的问题.

实际上，利用神奇的动态数组（dynamic arrays），我们便可根据需要对数组进行高效的扩张.假定数组的初始大小为1，每当面临空间耗尽的情况时，便将其大小加倍，即从m变成2m.此加倍过程包含下列步骤：首先按紧接方式分配一个大小为2m的新数组，其次将原数组中的内容复制到新数组的前半部分，最后将原数组所占空间退还给存储分配系统.

很明显，在每次加倍扩张过程中对原有内容重新复制是一种重复劳动.那么在进行几次插入后，某一元素究竟需要被重新复制多少次呢？不妨先考虑第一个插入的元素：数组进行完第1，2，4，8次插入后，再要插入都会由于空间不够而扩张，而每次扩张时都需重新复制该元素.当数组刚拥有n个位置时，我们一共执行了1ogn次加倍操作.当然大多数元素不需要折腾这么多次.事实上，第（n/2+1）个到第n个元素至多会搬运一次，甚至有可能连一次都不动.

```c
list *search_list(list *l, item_type x)
{
    if (l == NULL) return NULL;
    if (l->item == x) return l;
    else return search_list(l->next, x);
}

```

在列表中插入对一个单链表（singly-linked list）进行插入是非常好的指针操作练习，其解答如下文所示.由于我们不需要以任何形式的次序维护列表，不妨将每个新项插入至最易于到达的位置，插入到列表头部无须进行任何遍历，但该方法需要我们对指向列表数据结构头部的指针（记为1）进行更新.

```c
void insert_list(list **l, item_type x)
{
    list *p; /* 暂用指针 */
    p = malloc(sizeof(list));
    p->item = x;
    p->next = *l;
    *l = p;
}

```

在列表中删除从列表中删除元素略为复杂.我们首先要找到待删除项的前驱，可通过递归方法得到：

```c
list *predecessor_list(list *l, item_type x)
{
    if ((l == NULL) || (l->next == NULL)) {
        printf("Error: predecessor sought on null list.\n");
        return NULL;
    }
    if (l->next->item == x) return l;
    return predecessor_list(l->next, x);
}

```

这个前驱必须得找出来，因为删除操作完成后它链接着一个已不存在的结点，所以前驱结点的next指针必须更改，一旦排除了待删除元素不存在的情况，那么实际的删除过程也就不难了.需要特别注意的是，当首元素被删除时，列表的头部（12）需要重置.

```c
void delete_list(list **l, item_type x)
{
    list *p; /* 指向待删除项的指针 */
    list *pred;
    list *search_list(), *predecessor_list();
    p = search_list(*l, x);
    if (p != NULL) {
        pred = predecessor_list(*l, x);
        if (pred == NULL) /* 删除后应衔接的前驱在列表之外 */
            *l = p->next;
        else
            pred->next = p->next;
        free(p); /* 释放结点所占用的内存 */
    }
}

```

C语言要求显式地去释放已分配的内存，因此当我们不再需要某结点时，必须使用free操作将已删除结点所占用的内存还给系统.

注意：这段实现以键定位待删元素和其前驱；若允许不同元素具有相同键，前驱查找可能定位错误并破坏链表。该实现应限于键唯一的情形，或改用能区分元素身份的定位方式。



### 3.1.3 对比

相对于静态的数组而言，链表的优点是：

- 使用链接结构不会发生溢出现象，除非内存确实已满.
- 插入和删除比数组（可视为紧接的表）中的相应操作要简单，
- 处理大记录时，比起移动记录项本身来说，改变指针值既简单又迅速.

相对于链表而言，数组的优点是：

- 链表需要额外空间以存储指针域.
- 链表不允许对其中的元素进行高效的随机访问.
- 相比于随机的指针跳转而言，只有使用数组才有可能获得更良好的内存局部性和缓存性能.

> [!TIP] 所得教益：对于有限的存储资源应如何使用且在何处更能发挥作用的问题，动态内存分配为我们提供了灵活的解决方案.

最后，关于这两种基本数据结构还存在一种处理思想，也即它们都可视为递归式对象.

- 链表1—除去链表的首元素后，余下部分是一个稍小的链表.这个论断同样也适用于字符串，因为从字符串中移除部分字符后，剩下部分仍是字符串，由此可见，链表是递归式对象.
- 数组——从一个具有n个元素的数组中分离出前k个元素，将会得到两个稍小的数组，大小分别为k和n一k.因此，数组也是递归式对象.

这种深刻见解能引出更简洁的表处理过程，还能启发我们设计高效的分治算法，比如快速排序和二分查找.

```c
void insert_tree(tree **l, item_type x, tree *parent)
{
    tree *p;
    if (*l == NULL) {
        p = malloc(sizeof(tree));
        p->item = x;
        p->left = p->right = NULL;
        p->parent = parent;
        *l = p;
        return;
    }
    if (x < (*l)->item)
        insert_tree(&((*l)->left), x, *l);
    else
        insert_tree(&((*l)->right), x, *l);
}

```

### 3.4.2 二叉查找树究竟能有多好？
使用二叉查找树实现字典时，字典的3种操作都只需O（h）时间，其中h为树高.当树的形状相当平衡时，树会达到最低高度，即h=「logn］，这也是理论上能获得的最好结果，树具备最低高度固然很好，但此时的树得相当平衡才行. 我们的插入算法将每个新项放到某个新生成的叶子结点中，而它原本就该在这里被查找操作找到.这将使树的形状随插入次序的变化而不同，而更重要的是树的高度也将随之而变化. 不幸的是，通过插入来建立一棵树可能会出现一些不好的形态，而数据结构自身却无法控制插入的次序.

可考虑某用户插入已排过序的键的情形，如使用insert（a）以插入Q，再通过insert继续插入b，c，d.•••这样将产生一棵极瘦的树，其中每个结点只有右孩子，且树的高度等于结点数.2 因此二叉树的高度可能在1ogn到n之间.二叉树的平均高度又将如何呢？该算法的平均情况分析难以进行，其原因在于我们必须仔细说明究竟是哪种“平均”，如果我们假定所有n！种插入次序发生的可能性相等，则此问题将非常明确.果真如此，那么我们真是走运，因为此情况下所生成的树以高概率具备O（1ogn）的高度.4.6节将展示此结论. 事实上，这是体现随机化方法功效的一个有力论据：我们经常可以开发一些能以高概率提供优异性能的简单算法.我们还将看到与此类似的思想支撑了最快的排序算法，即著名的快速排序.

### 3.4.3 平衡二叉树
随机查找树通常不错.但如果我们不幸地碰到上文提到的那种插入次序，那么最终仍会在最坏情况下得到一棵线性高度”的树而告终，这种最坏情况超出了我们的掌控范围，因为树必须按用户的要求而构建，而实际中会有一些讨厌的用户给出糟糕的插入次序，我们若在每棵树的插入/删除操作后略作调整，则将使情况好转，即树会尽可能接近平衡进而保证最大高度为对数级.已经发展出一种精巧的数据结构，即平衡二叉查找树（balanced binary search tree），它能保证树高始终为O（logn）.

因此字典的所有操作（插入、删除和查询）都只需O（logn）时间.平衡二叉查找树的一些实现方法，如红黑树和伸展树（splay trees），将在12.1节中讨论. 1译者注：其言外之意是按照查找算法所停止的位置进行插入. 2 译者注：请注意作者所采用树的高度定义.例如图3.4中从左到右的树高分别为5，5, 4, 4.

## 3.5 优先级队列

许多算法需要按特定次序处理项目.例如，假定你要根据作业的相对重要程度进行作业调度.调度这些作业需要按重要程度对它们进行排序，再按此顺序量化不同作业的重要程度. 相对于简单地将元素排序而言，使用优先级队列（priority queue）这种抽象数据类型能提供更多的灵活性，也即它允许新元素在任意时段进入系统.优先级队列处理此情况的开销相比于对元素重新排序要少得多. 优先级队列最起码支持下列3种基本操作：

- Insert（Q,2）-

给定z，其键为K，将z插入至优先级队列Q中，

- Find-Minimum（Q）或Find-Macimum（Q）—返回优先级队列中具有最小（最大）键值的元素指针.
- Delete-Minimum（Q）或Delete-Marimum（Q）-

删除优先级队列中键值最小（最大）元素.

可以对许多现实中的事件产生过程进行精确建模.单身小伙子心中有一个约会侯选人的优先级队列，尽管他内心深处并不那么清楚地了解它：如果他在聚会上认识了一位新朋友，则会马上对她打印象分，它衡量了她的吸引力或她与他的合意程度.尔后他将她加入其“女友通讯录”（little black book）优先级队列中，且用与她的合意程度作为该项的键域.那么约会过程就是：从此数据结构中选出最中意的朋友，再花上一个夜晚对她展开深入了解，便可估计出与她再次约会的可能性，随后再将其重新插入到优先级队列中。

> [!TIP] 所得教益：围绕字典和优先级队列这两种抽象数据类型来构建算法，不但能令算法结构清晰，还会取得优异的性能.

按逆序存储数组（最大元在首位），则最小元总将位于数组末位.只要简单地对数组内元素的个数n进行减1操作，即可实现删除，还不用移动任何元素，因此删除操作可在常数时间内执行完毕. 所有问题皆已清楚，然而下表却宣称其中所有数据结构能实现常数时间的寻找最小元操作： Insert（Q,z） Find-Minimum（Q） Delete-Minimum（Q）无序数组有序数组平衡二叉查找树 0（1） O（n） O（logn） O（1） O（1） O（1） O（n） O（1） O（logn）实现常数时间的寻找最小元操作的技巧在于额外再用一个变量存储其指针/下标，因此，无论何时我们需要寻找最小元，只需返回该指针值即可.

在插入中更新此指针不难：当且仅当插入值小于它时才更新.而在删除最小元操作中又该怎么办呢？我们先清除现有的最小元指针，再“真正”地去找一次最小元，并让该指针指向新的最小元，待其他操作需要时即可使用这个预先设置好的（canned）指针.

在无序数组和平衡二叉查找树中“真正”寻找最小元分别需要线性和对数时间，与删除操作的渐近时间复杂度一致，因此可将其融入删除操作而不改变其渐近时间. 优先级队列是非常有用的抽象数据类型.事实上，这些形式各异的优先级队列将成为本章中两部War Story中的主角，而且它们还将在下一章中继续出演.我们将在4.3节中讨论一种特别精妙的优先级队列实现（即堆），此外，便览中的12.2节将展示一整套各式各样的优先级队列实现方案.

我们设法将这些顶点划分成尽可能少的带.若能划分成一条路径意味着我们发现了一条Hamilton路径，由定义知这种路径访问每个顶点恰为一次.由于寻找一条Hamilton路径是NP完全问题（见16.5节），我们不应去寻求—一种最优算法，相反地应全力以赴去研究启发式方法. 寻找带覆盖（strip cover）最简单的启发式方法可这样进行：从任一个三角形开始，再进行左右交替式行走直到该次行走结束，即遇到整个对象的边界或某个已访问过的三角形，这种启发式方法的优势在于快而简单，尽管我们不知道它到底能不能对所给的三角剖分找到实际所能达到的最小左右交替带集合. 然而，贪心（greedy）启发式方法也许更有可能获得数目较少的带，贪心后发式方法总试图最先抓住可能性最大的事物.

在三角剖分这个例子中，自然而然会想到的一个贪心启发式方法就是先找出那个能得到最长左右交替带的起始三角形，然后最先剥去这条三角形带. 贪心同样也不能保你一定能获得最优解，这是因为你所剥去的第一条带也许会断开大量我们以后有可能回过头来想用的带.不过话又说回来，你要是想发财，“贪心”二字就是最管用的经验总结.由于移除最长的带会为以后构造新的三角形带留下数目最少的三角形，按道理说贪心启发式方法应该会胜过上述朴素的启发式方法. 但是寻找下一次要剥去的那种最长的带会用多少时间呢？令k为从一顶点出发所能走到的平均长度，我们用最简单可行的实现方案：可从n个项点中的每一个点开始行走以寻找现存的最长带，直至最后报出结果，共需O（kn）时间.

我们可推断出约有n/ 条带，对每一条带都按此处理，这样会带来一个O（n”）时间的实现方案，而在一个拥有20000个三角形的典型几何模型上执行该方案会慢得让人绝望. 我们怎样才能提升速度呢？在删除一条带后，再从每个三角形开始重新行走似乎浪费了很多在操作中遇到但未保存下来的信息.我们可在一个数据结构中维护所有将来可能被选中的带的长度.然而，每当我们剥去一条带时，都要更新所有受影响的带的长度.这些带会缩短，其原因是它们所走过的三角形不复存在，从抽象数据类型的角度看，这种数据结构存在两种表现形态：

- 优先级队列——由于我们要不断地寻找出现存的最长带，因此需要一个存储这些带的优先级队列，它依照带的长度来定次序，下一个待剥去的带始终位于优先级队列顶部.无论何时我们更新带的长度，我们的优先级队列都必须能对其中任意元素进行优先级降低操作，从而反映那些被剥离的三角形，考虑到所有带的长度被限于一个相对而言不算太大的范围之内（由于硬件上的限制，一条三角形带所拥有的结点个数不得超过256），所以我们使用一个高度限界（bounded-height）优先级队列（也就是一个桶（bucket）数组，如图3.7所示，12.2节会述及该结构）.一个普通的堆也能完成任务，但只能算差强人意.

为了更新每个三角形所关联的优先级队列条目，我们需要迅速找到该三角形在何处.这意味着我们还需要一个…

- 字典—对网格中的每个三角形，我们需要了解它位于优先级队列中的哪个地方.

这意味着要去存储指向字典中每个三角形的指针.通过对这个字典与前述优先级队列的集成，我们制造了一个具备多类不同操作的数据结构.

尽管还有各种各样的其他困难，比如快速地重新计算受剥离操作影响的那些带的长度，但获取更好性能所需的关键思想是使用优先级队列.采用此种抽象数据类型之后，运行时间降低了好几个数量级.

### 3.7.2 凭借散列实现高效的字符串匹配

### 3.7.3 凭借散列实现副本检测



散列的关键思想是将大的对象（可能是一个键、一个字符串或一个子串）以一个数字来表示.

其目标是将大对象表示为能在常数时间内操纵的独特实体，这样一来两个不同的大对象映射成同一个值就相对来说就不太可能了. 散列所拥有多种多样的巧妙应用远不止加速搜索这点能力. 我曾经听Udi Manber（时任Yahoo首席科学家）谈论他的公司所使用的算法.他说，Yahoo最重要的三个算法是一散列，散列，还是散列. 考虑下面这些能用散列巧妙解决的问题：

- 是否某个所给文档与一个大文档库（corpus）中其他所有文档不同？—一个由n个文档组成的巨型数据库的搜索引擎用爬虫程序又抓到了一个网页.如何能分辨出该新增网页是新素材（因此得添加进数据库），还是它仅仅是某网页（存在于网络中别处）的一个副本？对大文档库而言，将这个新文档D与所有n个文档进行精确比较将会低效得让人绝望.但是我们可以将D散列为一个整数，并将其与文档库中其他的散列码进行比较.

仅当存在碰撞时，D才可能是副本.由于我们已预计到几乎不会出现假匹配，因此只需对极少数的拥有完全一致散列码的那些文档进行逐字比较即可，而这几乎不费什么事.

## 3.8 专用数据结构

迄今为止所描述的基本数据结构都是用来表示无内在结构的数据集，其目的是为了让检索集合元素更容易.这些数据结构已为大多数程序员所熟知.而用于表示那些内在结构更明显或者特定种类的对象（如空间中的点、字符串和图）的数据结构，则不那么为人所知. 设计这些专用数据结构跟为基本对象去设计数据结构的原理相同.在这里我们仍然会碰到一组基本操作，它们会经常用到，而我们要找一个能支持这些操作并且效率非常高的数据结构.这些高效的专用数据结构对于设计高效的图算法与几何算法很重要，因此读者应了解有这么些数据结构可用.便览中的数据结构部分都是关子下列结构的详细阐述.

- 字符串数据结构—

—字符串通常以字符数组表示，可能会以某一特殊字符标记该字符串的结束.后缀树/后缀数组这样的特殊数据结构将对字符串进行预处理，从而能让模式匹配操作更快.有关细节可见12.3节.

- 几何数据结构——几何数据通常由大量点和区域构成.平面中的区域可用多边形描述，其中多边形的边界由一连串线段给出.多边形能以点的数组（21，••，2n,21）表示，形如（2,0+1）的序偶是一段边界.空间数据结构如kd树将点和区域按几何位置合理组织以支持快速查找. 更多细节见12.6节.
- 图数据结构——图通常以邻接矩阵或邻接表来表示.正如第6章和12.4节所讨论的那样，表示方式的选择是否合适对设计由此衍生出的图算法有着相当可观的影响.
- 集合数据结构——子集由全集中一些项组成，它可用字典表示，这样可以支持快速的属于关系查询操作.不过，位向量（bit vector）也可供选择，它是这样的一个布尔数组：若i在子集中则第个比特呈“真”状态. 操纵集合的数据结构可见12.5节中的相关简介.用于集合划分的合并一查找数据结构将在6.1.3节中讲到.

## 3.9 War Story：把它们串起来

人类的基因组对造出一个人所需的全部信息给予了编码. 人类基因组计划已对医学和分子生物学产生了极大的影响.而现在算法学家也对该计划很有兴趣，有以下几个原因：

- DNA序列能用基于4字符字母表｛A,C,T,G］的字符串精准表示，生物学家的实际需求创造了诸如最长公共超串（见18.3节）这样的新问题，而与此同时他们的需求也让算法学家对旧有算法如字符串匹配（见18.9节）重新提起了兴趣，因为我们需要处理DNA序列的更快算法.
- DNA序列是非常长的字符串. 人类基因组所包含的碱基对（可将碱基视为字符）大约30亿个，如此大规模的问题意味着对生物学问题中的算法进行渐近复杂度分析通常不会出一点儿偏差，给出大O记号之后算法性能基本上高下立判.

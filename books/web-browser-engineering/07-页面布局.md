# 第 5 章　页面布局

*Chapter 5: Laying Out Pages*

到目前为止，布局一直是一个线性过程：元素的开始标签和结束标签各自独立处理。但网页是树，看起来也像树——边框和背景在视觉上层层嵌套。为了支持这一点，本章将转向基于树的布局（tree-based layout）：在绘制之前，先把元素树转换成由布局对象组成的布局树。在这个过程中，我们还会通过背景让网页变得更有色彩。

## 5.1 布局树

目前，我们的浏览器是把元素的开始标签和结束标签分开布局的。两种标签都会修改全局状态（例如 `cursor_x` 和 `cursor_y` 变量），但除此之外并无关联，而关于元素整体的信息（比如它的宽度和高度）则从未被计算。这样一来，想在元素后面绘制背景就相当困难，更不用说更复杂的视觉效果了。因此，真实浏览器采用了不同的方式来组织布局。

在浏览器中，布局的目标是生成一棵布局树（layout tree），它的节点是布局对象（layout object），每个布局对象都关联着一个 HTML 元素¹，并拥有自己的尺寸和位置。浏览器遍历 HTML 树生成布局树，然后计算每个布局对象的尺寸和位置，最后把每个布局对象绘制到屏幕上。

先来看看现有的 `Layout` 类是如何使用的：

```python
class Browser:
    def load(self, url):
        # ...
        self.display_list = Layout(self.nodes).display_list
        # ...
```

这里，`Layout` 对象只是被短暂创建，随即就被丢弃了。我们改为把它保存到 `Browser` 的一个字段中，让它成为布局树的起点：

```python
class Browser:
    def load(self, url):
        # ...
        self.document = Layout(self.nodes)
        self.document.layout()
        # ...
```

注意，我把原先放在构造函数里的布局工作移到了一个 `layout` 方法中，这样“构造布局对象”和“实际执行布局”就可以成为两个不同的步骤。构造函数现在只是保存传入的节点：

```python
class Layout:
    def __init__(self, node):
        self.node = node
```

到目前为止，我们还没有得到一棵树——只有一个孤零零的 `Layout` 对象。要把它变成树，需要添加子节点和父节点指针。我还会加一个指向前一个兄弟节点（previous sibling）的指针，因为稍后计算尺寸和位置时会用到它：

```python
class Layout:
    def __init__(self, node, parent, previous):
        self.node = node
        self.parent = parent
        self.previous = previous
        self.children = []
```

不过，现在要求提供 parent 和 previous 对象，会让在 `Browser` 中构造 `Layout` 对象变得麻烦，因为布局树的根显然不能有父对象。为了解决这个问题，我们再引入第二种布局对象，充当布局树的根²。我把这个根看作文档本身，因此把它命名为 `DocumentLayout`：

```python
class DocumentLayout:
    def __init__(self, node):
        self.node = node
        self.parent = None
        self.children = []
    def layout(self):
        child = Layout(self.node, self, None)
        self.children.append(child)
        child.layout()
        self.display_list = child.display_list
```

注意这个新的 `layout` 方法有一个有趣之处：它的职责是创建子布局对象，然后递归调用它们的 `layout` 方法。这是构造树的一种常见模式，本书中还会反复见到。

现在，当我们在 `load` 中构造 `DocumentLayout` 对象时，我们就是在构建一棵树；一棵非常矮的树，甚至更像一个树桩（只有“文档”和位于其下的 html 元素），但它毕竟是一棵树！

顺便说一句，既然现在有了 `DocumentLayout`，我们把 `Layout` 改个名字，以免歧义。我喜欢 `BlockLayout` 这个名字，因为我们最终希望它表示一个文本块（block），比如一个段落或一个标题：

```python
class BlockLayout:
    # ...
```

记得把 `DocumentLayout` 中对 `Layout` 构造函数的调用也一并改名。一如既往，测试你的浏览器，确认经过这些重构之后一切仍然正常。

> **深入探索**
> 布局树对 Web 开发者是不可见的，因此它没有被标准化，不同浏览器的结构各不相同，甚至连名字都不一致：Chrome 称之为布局树（layout tree）[1]，Safari 称之为渲染树（render tree）[2]，Firefox 称之为框架树（frame tree）[3]。

## 5.2 块布局

到目前为止，我们关注的都是文本布局——而文本是按行水平排列的³。但网页实际上是由更大的块（block）搭建起来的，比如标题、段落和菜单，它们一个接一个垂直堆叠。我们需要为浏览器添加对这种布局的支持，而做法就是扩展我们已经建立的布局树。

核心思想是：我们将拥有一整棵 `BlockLayout` 对象树（根为 `DocumentLayout`）。其中一些代表包含文本的叶子块（leaf block），它们按我们已经实现的方式布局内容；此外还会出现新的中间层 `BlockLayout`，其子节点也是 `BlockLayout`，它们负责把子节点垂直堆叠起来。（示例见图 5.1。）

*图 5.1　一个 HTML 树与对应布局树的示例。*

```text
HTML 树                          布局树
html                             Document
└─ body                          └─ Block（html）
   ├─ h1                            └─ Block（body）
   │  └─ Text                          ├─ Block（h1）
   └─ p                                └─ Block（p）
      ├─ Text
      ├─ a
      │  └─ Text
      └─ Text
```

要创建这些中间层 `BlockLayout` 子对象，可以使用像这样的循环：

```python
class BlockLayout:
    def layout_intermediate(self):
        previous = None
        for child in self.node.children:
            next = BlockLayout(child, self, previous)
            self.children.append(next)
            previous = next
```

我把这个方法命名为 `layout_intermediate`，只是为了让你可以先把它加入代码，再与现有的 `recurse` 方法对比。

这段代码有些绕，请仔细阅读。它涉及两棵树：`node` 和 `child` 指向 HTML 树；`self`、`previous` 和 `next` 指向布局树。两棵树结构相似，很容易混淆。但请记住：这段代码是从 HTML 树构造布局树，因此它读取 `node.children`（HTML 树），写入 `self.children`（布局树）。

如此一来，布局一个元素就有了两种方式：要么调用 `recurse` 和 `flush`，要么使用这个 `layout_intermediate` 函数。要确定一个布局对象该采用哪种方式，需要知道它的 HTML 节点包含哪类内容：是文本以及 `<b>` 这类与文本相关的标签，还是 `<p>`、`<h1>` 这类块。该函数大致如下：

```python
class BlockLayout:
    def layout_mode(self):
        if isinstance(self.node, Text):
            return "inline"
        elif any([isinstance(child, Element) and \
                child.tag in BLOCK_ELEMENTS
                for child in self.node.children]):
            return "block"
        elif self.node.children:
            return "inline"
        else:
            return "block"
```

这里的 `BLOCK_ELEMENTS` 列表基本如你所料，列出了所有表示块和容器的标签⁴：

```python
BLOCK_ELEMENTS = [
    "html", "body", "article", "section", "nav", "aside",
    "h1", "h2", "h3", "h4", "h5", "h6", "hgroup", "header",
    "footer", "address", "p", "hr", "pre", "blockquote",
    "ol", "ul", "menu", "li", "dl", "dt", "dd", "figure",
    "figcaption", "main", "div", "table", "form", "fieldset",
    "legend", "details", "summary"
]
```

`layout_mode` 方法必须处理一种棘手的情形：一个节点既包含块级（block-level）子节点（如 `<p>` 元素），又包含文本类子节点（如文本节点或 `<b>` 元素）。这最好被视为 Web 开发者犯的一种错误。就像第 4 章处理隐式标签（implicit tag）那样，我们需要一种修复机制来应对这种局面；在这种情况下我选择了 block 模式⁵。

现在，`BlockLayout` 可以根据其 HTML 节点的 `layout_mode` 来决定执行哪种布局：

```python
class BlockLayout:
    def layout(self):
        mode = self.layout_mode()
        if mode == "block":
            previous = None
            for child in self.node.children:
                next = BlockLayout(child, self, previous)
                self.children.append(next)
                previous = next
        else:
            self.cursor_x = 0
            self.cursor_y = 0
            self.weight = "normal"
            self.style = "roman"
            self.size = 12
            self.line = []
            self.recurse(self.node)
            self.flush()
```

最后，由于 `BlockLayout` 现在可以拥有子对象，`layout` 方法接下来还需要递归调用 `layout`，让这些子对象再去构造它们自己的子对象，如此递归下去：

```python
class BlockLayout:
    def layout(self):
        # ...
        for child in self.children:
            child.layout()
```

我们的浏览器现在会构造一整棵 `BlockLayout` 对象树；你可以在 `Browser` 的 `load` 方法中使用 `print_tree` 查看这棵树。你会看到，像本章网页这样的大型页面会产生庞大而复杂的布局树！接下来，我们需要让每个 `BlockLayout` 对象在页面上拥有自己的尺寸和位置。

> **深入探索**
> 在 CSS 中，布局模式由 `display` 属性 [6] 设置。最早的 CSS 布局模式（如 `inline` 和 `block`）是设置在子元素而非父元素上的，由此产生了匿名块盒（anonymous block boxes）之类的麻烦。较新的取值如 `inline-block`、`flex` 和 `grid` 则设置在父元素上，从而避免了这类错误。

## 5.3 尺寸与位置

在上一章中，`Layout` 对象负责整个网页，因此它只是从页面顶部开始布局内容。现在我们有了多个 `BlockLayout` 对象，每个各含一段不同的文本，所以需要稍微换一种做法：为每个布局对象分别计算尺寸和位置。

首先为每种布局对象添加 `x`、`y`、`width` 和 `height` 字段：

```python
class BlockLayout:
    def __init__(self, node, parent, previous):
        # ...
        self.x = None
        self.y = None
        self.width = None
        self.height = None
```

对 `DocumentLayout` 做同样的修改。接下来要更新 `layout` 方法来使用这些字段。

先从 `cursor_x` 和 `cursor_y` 着手。我们不再让它们表示页面上的绝对位置，而是让它们相对于 `BlockLayout` 的 `x` 和 `y`。因此，无论是在 `layout` 还是 `flush` 中，它们现在都应从 0 开始，而不是从 `HSTEP` 和 `VSTEP` 开始：

```python
class BlockLayout:
    def layout(self):
        else:
            self.cursor_x = 0
            self.cursor_y = 0
    def flush(self):
        # ...
        self.cursor_x = 0
        # ...
```

由于这些字段现在是相对坐标，在 `flush` 中计算显示列表（display list）时需要加上该块的 `x` 和 `y` 位置：

```python
class BlockLayout:
    def flush(self):
        # ...
        for rel_x, word, font in self.line:
            x = self.x + rel_x
            y = self.y + baseline - font.metrics("ascent")
            self.display_list.append((x, y, word, font))
        # ...
```

类似地，折行时不能再拿 `cursor_x` 与 `WIDTH` 比较，因为 `cursor_x` 是相对位置，而 `WIDTH` 是绝对位置；正确做法是当 `cursor_x` 达到该块的宽度时折行：

```python
class BlockLayout:
    def word(self, word):
        # ...
        if self.cursor_x + w > self.width:
            # ...
        # ...
```

现在剩下的问题就是计算这些 `x`、`y` 和 `width` 字段了。回想一下，`BlockLayout` 表示段落或标题这样的文本块，它们一个叠一个垂直排列。这意味着每个块都从其父对象的左边缘开始，并横向铺满父对象⁶：

```python
class BlockLayout:
    def layout(self):
        self.x = self.parent.x
        self.width = self.parent.width
        # ...
```

布局对象的垂直位置取决于是否存在前一个兄弟节点：如果有，它就紧接在前一个兄弟之后；否则，它从其父对象的顶边开始：

```python
class BlockLayout:
    def layout(self):
        if self.previous:
            self.y = self.previous.y + self.previous.height
        else:
            self.y = self.parent.y
        # ...
```

最后是 `height`，它稍微有点微妙。包含其他块的 `BlockLayout` 必须高到足以容纳其所有子对象，因此它的高度应为所有子对象高度之和：

```python
class BlockLayout:
    def layout(self):
        # ...
        if mode == "block":
            self.height = sum([
                child.height for child in self.children])
```

而包含文本的 `BlockLayout` 没有子对象；它需要高到足以容纳其全部文本，而这个值恰好可以从 `cursor_y` 直接读出⁷：

```python
class BlockLayout:
    def layout(self):
        # ...
        else:
            self.height = self.cursor_y
```

这些规则看起来很简单，但其中有一个微妙之处必须说明。考虑 `x` 位置：要计算一个块的 `x` 位置，其父块的 `x` 位置必须已经计算完毕。因此，块的 `x` 必须在其子块的 `x` 之前计算。也就是说，`x` 的计算必须放在递归调用布局之前。

另一方面，元素的 `height` 字段取决于其子对象的高度。因此，`x` 必须在递归调用之前计算，而 `height` 必须在递归调用之后计算。同样，由于块的 `y` 位置取决于其前一个兄弟的 `y` 位置，递归布局调用必须从第一个兄弟开始，沿列表正向依次进行。

也就是说，`layout` 方法应按以下顺序执行各步骤（见图 5.2）：

1. `layout` 被调用时，首先读取父布局对象和前一个布局对象，计算 `width`、`x` 和 `y` 字段。
2. 接着，为每个子元素创建子布局对象。
3. 然后，调用子布局对象的 `layout` 方法，递归地布局这些子布局节点。
4. 最后，读取子布局对象，计算 `height` 字段。

*图 5.2　一张流程图：宽度自上而下计算（父 → 子），高度自下而上计算（子 → 父）。*

宽度（Width）沿 Parent → Element → Children 自顶向下传播；高度（Height）沿 Children → Element → Parent 自底向上汇总。

这种依赖关系的推理对布局至关重要，更广泛地说，对任何在树上进行的计算都是如此。如果操作顺序弄错了，某个布局对象就会读取一个尚未计算出的值，浏览器随之出现 bug。我们将在第 16 章回到依赖这个话题，届时它会变得更加重要。

`DocumentLayout` 也需要一些布局代码，不过由于文档总是从同一个位置开始，这段代码非常简单：

```python
class DocumentLayout:
    def layout(self):
        # ...
        self.width = WIDTH - 2*HSTEP
        self.x = HSTEP
        self.y = VSTEP
        child.layout()
        self.height = child.height
```

注意，内容周围留有一些内边距（padding）——左右各 `HSTEP`，上下各 `VSTEP`。这是为了让文字不会顶到窗口边缘而被裁掉。

总之，现在所有尺寸和位置都能正确计算了，我们的浏览器应该能把页面上的所有文字都显示在正确的位置上。

> **深入探索**
> 从形式上看，这类树上的计算可以用属性文法（attribute grammar）[7] 来描述。属性文法引擎会分析不同属性之间的依赖关系，以确定遍历树并计算各属性的正确顺序。

## 5.4 递归绘制

现在，`layout` 方法承担了相当多的工作：计算尺寸和位置、创建子布局对象、递归布局这些子布局对象，以及聚合显示列表以便把文字绘制到屏幕上。这有些杂乱，所以我们花点时间只把其中一部分——显示列表部分——抽取出来。顺带地，我们也不再需要在沿布局树向上时一遍又一遍地复制显示列表内容。

我认为最方便的做法是给每个布局对象添加一个 `paint` 函数，其返回值是该对象的显示列表项；再写一个单独的函数 `paint_tree`，在所有布局对象上递归调用 `paint`：

```python
def paint_tree(layout_object, display_list):
    display_list.extend(layout_object.paint())
    for child in layout_object.children:
        paint_tree(child, display_list)
```

对 `DocumentLayout` 来说，没有什么要绘制的：

```python
class DocumentLayout:
    def paint(self):
        return []
```

现在可以删掉为 `DocumentLayout` 计算 `display_list` 字段的那行代码了。

对 `BlockLayout` 对象，只需把它在 `recurse` 和 `flush` 期间计算出的 `display_list` 字段返回即可⁸：

```python
class BlockLayout:
    def paint(self):
        return self.display_list
```

现在，浏览器可以使用 `paint_tree` 来收集自己的 `display_list` 变量：

```python
class Browser:
    def load(self, url):
        # ...
        self.display_list = []
        paint_tree(self.document, self.display_list)
        self.draw()
```

看看吧：我们的浏览器现在用上了炫酷的树式布局！我建议停下来测试和调试一番。树式布局强大但复杂，而且我们马上还要添加更多功能。地基牢固，房子才住得安稳。

> **深入探索**
> 布局树在图形用户界面（GUI）框架 [8] 中很常见，但组织布局还有其他方式，例如基于约束的布局（constraint-based layout）。TeX 的 boxes 与 glue 机制 [9] 以及 iOS 的自动布局（auto-layout）[10] 是这种替代范式的两个例子。

## 5.5 背景

布局树在浏览器中的用途很多⁹，其中一个简单而视觉效果出众的用例就是绘制背景。

背景是矩形，因此我们的第一项任务就是把矩形放进显示列表。目前，显示列表是要绘制到屏幕上的单词列表，但我们可以把它重新理解为一个命令（command）列表——只是目前只有一种命令而已。我们现在需要两种命令：

```python
class DrawText:
    def __init__(self, x1, y1, text, font):
        self.top = y1
        self.left = x1
        self.text = text
        self.font = font
class DrawRect:
    def __init__(self, x1, y1, x2, y2, color):
        self.top = y1
        self.left = x1
        self.bottom = y2
        self.right = x2
        self.color = color
```

接下来，`BlockLayout` 必须为每个想要绘制的单词添加 `DrawText` 对象，但只在行内（inline）模式下¹⁰：

```python
class BlockLayout:
    def paint(self):
        cmds = []
        if self.layout_mode() == "inline":
            for x, y, word, font in self.display_list:
                cmds.append(DrawText(x, y, word, font))
        return cmds
```

它还可以添加一条 `DrawRect` 命令来绘制背景。我们来给 `pre` 标签（用于代码示例）加上灰色背景：

```python
class BlockLayout:
    def paint(self):
        # ...
        if isinstance(self.node, Element) and self.node.tag == "pre":
            x2, y2 = self.x + self.width, self.y + self.height
            rect = DrawRect(self.x, self.y, x2, y2, "gray")
            cmds.append(rect)
        # ...
```

请确保这段代码位于添加 `DrawText` 对象的循环之前：背景必须绘制在文字下方。还要注意，`paint_tree` 会先调用 `paint` 再递归进入子树，因此子树也会绘制在这块背景之上，正合所需。

显示列表填充完毕后，我们需要真正绘制每条图形命令。为此添加一个 `execute` 方法。在 `DrawText` 上，它调用 `create_text`：

```python
class DrawText:
    def execute(self, scroll, canvas):
        canvas.create_text(
            self.left, self.top - scroll,
            text=self.text,
            font=self.font,
            anchor='nw')
```

注意，`execute` 把滚动量作为参数传入；这样每条图形命令都能自行完成相应的坐标转换。`DrawRect` 也一样，调用的是 `create_rectangle`：

```python
class DrawRect:
    def execute(self, scroll, canvas):
        canvas.create_rectangle(
            self.left, self.top - scroll,
            self.right, self.bottom - scroll,
            width=0,
            fill=self.color)
```

默认情况下，`create_rectangle` 会画出一像素宽的黑色边框，而背景并不需要它，所以务必传入 `width=0`。

我们仍然希望跳过屏幕之外的图形命令，因此给 `DrawText` 添加一个 `bottom` 字段，以便知道何时跳过它们：

```python
def __init__(self, x1, y1, text, font):
    # ...
    self.bottom = y1 + font.metrics("linespace")
```

现在，浏览器的 `draw` 方法只需根据 `top` 和 `bottom` 来决定执行哪些命令：

```python
class Browser:
    def draw(self):
        self.canvas.delete("all")
        for cmd in self.display_list:
            if cmd.top > self.scroll + HEIGHT: continue
            if cmd.bottom < self.scroll: continue
            cmd.execute(self.scroll, self.canvas)
```

找一个带代码片段的页面——比如本章的网页 [11]——用你的浏览器试试。你应该能看到每个代码片段都衬上了灰色背景。

树式布局还有一个可爱的好处：我们现在记录了整个页面的高度。浏览器可以利用它来避免滚动越过底部：

```python
def scrolldown(self, e):
    max_y = max(self.document.height + 2*VSTEP - HEIGHT, 0)
    self.scroll = min(self.scroll + SCROLL_STEP, max_y)
    self.draw()
```

注意这里的 `2*VSTEP`，它对应页面顶部和底部各 `VSTEP` 的留白。

以上就是基于树的布局的基础！事实上，正如接下来两章将看到的，这只是布局树在浏览器中的核心作用的一部分。但在那之前，我们需要先给浏览器添加一些样式能力。不过，即使只加上布局，browser.engineering [12] 的主页看起来也已经好了一些——见图 5.3。

## 5.6 小结

本章对浏览器的布局引擎（layout engine）做了一次大刀阔斧的重写：

- 布局现在基于树，会产出一棵布局树。
- 树中的每个节点采用两种布局模式之一。
- 布局为每个布局对象计算尺寸和位置。
- 显示列表现在包含通用的命令。
- 此外，源代码片段现在有了背景。

树式布局让我们得以大幅扩展浏览器的样式能力。下一章就来着手做这件事。

## 5.8 练习

### 练习 5.1：链接栏（Links bar）

本书网页版每一章的顶部和底部都有一个灰色条，标明章节名称并提供后退和前进链接。它由 `<nav class="links">` 标签包裹。请让你的浏览器为这个链接栏加上真实浏览器那样的浅灰色背景。

### 练习 5.2：隐藏的 head（Hidden head）

你的浏览器很可能仍会在你访问的每个页面顶部显示脚本、样式和页面标题。请让 `<head>` 元素及其内容永远不被显示：这些元素仍应保留在 HTML 树中，但不出现在布局树里。

### 练习 5.3：项目符号（Bullets）

为列表项（HTML 中的 `<li>` 标签）添加项目符号。可以把它们做成小方块，位于列表项本身的左侧。另外，请缩进 `<li>` 元素，使元素内的文字位于项目符号的右侧。

### 练习 5.4：目录（Table of contents）

本书网页版每一章的顶部都有一个目录，由 `<nav id="toc">` 标签包裹，其中包含一组链接。请在该列表上方添加带灰色背景的文字 “Table of Contents”。不要修改词法分析器或解析器。

### 练习 5.5：匿名块盒（Anonymous block boxes）

有时，一个元素会同时拥有文本类子节点和容器类子节点。例如在这个 HTML 中：

```html
    <div><i>Hello,</i> <b>world!</b><p>So it began...</p></div>
```

`<div>` 元素有三个子元素：`<i>`、`<b>` 和 `<p>`。前两个是文本类的，最后一个是容器类的。它本应显示为两个段落：一段由 `<i>` 和 `<b>` 组成，另一段是 `<p>`。请让你的浏览器做到这一点。具体来说，修改 `BlockLayout`，使它可以接收一组兄弟节点而非单个节点；然后修改构建布局树的算法，使任何连续的文本类元素序列都被放进同一个 `BlockLayout`。

### 练习 5.6：Run-in 标题（Run-ins）

“run-in 标题（run-in heading）”是作为下一段落文本的一部分绘制的标题¹¹。请修改你的浏览器，将 `<h6>` 元素渲染为 run-in 标题。你需要先完成前面关于匿名块盒的练习，然后为 `<h6>` 元素添加一个特殊处理。

# 《The Complete Developer》原书勘误清单

> 排查方式：3 个独立代理逐章对照英文原文（z-lib 转制 EPUB，No Starch Press 2024 印次 P1.0）与代码，交叉验证：No Starch [官方勘误 PDF](https://nostarch.com/download/CompleteDeveloper_errata_p1.pdf)、MDN、TypeScript/Next.js/React 官方文档、RFC 6749/7519、IANA JWT 注册表、Docker/Mongoose/MongoDB 官方文档。只排查原书自身错误，EPUB 提取伪影不计入。查询日期 2026-11-02。
>
> 统计：逻辑/技术错误约 75 处，表达错误约 45 处，存疑 10 处，合计约 130 处。官方勘误页（P1.0）仅收录 3 条（p55-56 create-react-app、p67 weather URL、p90 [zipcode].js、p176 EXPORT），本书未经官方勘误覆盖的错误密度显著高于平均水平。

## 高严重度速览（编译级/运行级硬错误）

## 分章明细

### 第 1 章 Node.js（5 处逻辑 + 1 处官方）

- **定性错误**：称 Next.js 是 "single-page application framework"——它是支持 SSR/SSG/ISR 的全栈 React 框架（与本书第 4/5 章自述矛盾）。
- **"内置服务器大量借鉴 Express"**——Next.js 内置服务器为自研，仅中间件风格类似（存疑级）。
- accept and vary → **accepts**（包名，清单 1-2 自证）；清单 1-2 "vary" 缺 node_modules/ 前缀（存疑）。
- LTS 论据失实：包不"要求"LTS 版本。
- 官方勘误已收录相关条目见 p55-56（create-react-app 提示）。

### 第 2 章 现代 JavaScript（5 处）

- "Next.js exports" → ES.Next/JavaScript exports（笔误）。
- 标签模板 literal 数组讲解与代码矛盾：`' minus '` 应为 `' plus '`。
- 展开运算符 "complete clones / keeps no reference"——实为**浅拷贝**（MDN）。
- "UMD/AMD 用 require 加载"——require 是 CommonJS；AMD 用 define()。
- "网络请求阻塞应用，所以要用异步"——与全章论点自相矛盾（应为 "can block"）。

### 第 3 章 TypeScript（10 处，含编译级 #1）

- **`npx tsc -init` → `--init`**（速览 #1）。
- **"告诉运行时环境期望的类型"**——类型在转译时擦除，与本节开头自相矛盾；应为"告诉编译器"。
- "JavaScript 有五种原始类型"——现行标准 7 种（漏 symbol/bigint，MDN）。
- 清单 3-5 交叉引用错误（应指 3-8）。
- tsconfig extends 语义颠倒（"preset 覆盖 base"应为 preset 构成 base）。
- "好代码从不注解局部变量"与练习 3 及清单 3-20 实际做法矛盾。
- 练习 3 清单引用 3-20 应为 3-21。
- `[]` 解释为"未指定类型"——实为空元组类型（never 元素）。
- "这些都是具名导出"——express 是默认导入。
- 下划线前缀"让 TSC 忽略参数"仅在 noUnusedParameters 开启时生效（存疑级）。

### 第 4 章 React（5 处逻辑 + 4 处表达）

- **虚拟 DOM 机制表述错误**："内存中的浏览器 DOM 克隆、与真实 DOM 比差异"——实为轻量 JS 对象树，与上一份虚拟 DOM 做 diff（react.dev Render and Commit）；"创建 HTML 字符串"与同章 "plain JavaScript objects" 矛盾。
- "React 库转译 JSX 并创建 HTML 字符串"——构建期 Babel/SWC 转译；产物是 React 元素对象。
- "Next.js 内部用 create-react-app 变体做脚手架"——实为 create-next-app（官方勘误 p55-56 相关）。
- 练习 4 URL weather-component → weather（**官方勘误已收录** p67）。
- useEffect "optional return object" → return **function**。
- 表达：window.object、operation system's、on runtime、regional states（应为 local）。

### 第 5 章 Next.js（10 处逻辑 + 4 处表达）

- **`next export` 已移除**（速览 #10；多处出现：Development Scripts/API Routes/Pre-rendering/Static Exporting；nextjs.org Next 14 博客 + Static Exports 文档）。
- create-react-app → create-next-app（正文命令自证）。
- 清单 5-3 `res.status(500)` 不结束响应——应 `.end()`。
- 清单 5-15 useEffect 缺依赖数组——无限请求循环。
- 清单 5-14 图注 getServerSideProps → getStaticProps（ISR 只能经 getStaticProps.revalidate）。
- 清单 5-12 交叉引用（5-9 应为 5-12）；component/weather → components；"React Link 元素"（无此物，基于 `<a>`）；req.params.zipcode 是属性非函数。
- 表达：commands starts、getStaticProp's、清单目录名 page/ → pages/。

### 第 6 章 REST 与 GraphQL API（4 处逻辑 + 4 处表达）

- PUT 示例正文 96814 vs curl 96815 矛盾。
- **Expire 头 → Expires**（MDN）。
- 清单 6-1 example 96815（数字）与 "should be a string" 矛盾。
- 清单 6-6 friends ["96814","96814"] 第二个应为 96815（第 7 章同数据自证）。
- 表达：qql → gql；正文 WeatherLocationType/Input 与 schema LocationWeatherType/Input 不符；resolver 用到未定义接口；3 处引号/格式。

### 第 7 章 MongoDB 与 Mongoose（4 处逻辑 + 4 处表达）

- **create "既创建又更新"**——create 总是插入新文档；upsert 需 updateOne/findOneAndUpdate（mongoosejs.com）。
- updateOne "find+create 的组合"——同上不准确。
- 清单 7-6 返回类型 Array|null 与 findOne 语义矛盾、正文两种说法互相矛盾。
- Weathers 集合——Mongoose 小写复数化为 weathers。
- 表达：readByZip → findByZip；"connects to the API" → database；导入路径多斜杠。

### 第 8 章 Jest（11 处逻辑 + 6 处表达）

- **text command → test**（清单 8-1 图注）。
- **stub "returns a string" → number**（清单 8-16 返回 999 自证）。
- **sum.test.js → sum.test.ts**（全书 TS）。
- **快照测试正文 jsdom vs 代码 @jest-environment node 矛盾**（清单 8-24/8-26）。
- **清单 8-13 `toBe(" ")` → `toBe("")`**（速览 #6）。
- **清单 8-23 nextJest 双重调用错误**（速览 #5；nextjs.org jest 指南对照）。
- __mocks__ "adjacent to the test file" —— 应与被 mock 模块相邻且须显式 jest.mock()（jestjs.io）。
- "快照失败因我们修改了测试用例"——清单 8-26 首个用例与 8-24 相同未修改（存疑级解说错位）。
- 覆盖率表把测试文件自身列为被测行；"Jest 自动替换依赖"（automock 默认关闭）。
- 表达：dbconnect/db-connect、缺 to、sum.test.file、@testing-library 包名缺 @。

### 第 9 章 OAuth（9 处逻辑 + 3 处表达）

- **"auth" 注册 claim 不存在 → aud**（IANA JWT 注册表）。
- **nfb → nbf**（RFC 7519 §4.1.5，正文与代码均错）。
- **implicit flow "跳过授权步骤"**——跳过的是授权码交换，用户同意照常（RFC 6749 §4.2）。
- **/oauth/authorize vs /oauth/authenticate** 正文与 curl 不一致（两处）。
- **JWT 编码不符规范**：base64/hex 而非 Base64URL（速览 #9）。
- "role is a private claim"——载荷里是 weather_private_type，无 role。
- Summary "认证是用凭证来授权访问"——与本章开头定义自相矛盾。
- "data-raw flag"——实际用 -d。
- 向授权端点 POST 用户名密码偏离 RFC 6749 §4.1（教学简化，存疑级）。
- 表达：Then 大写；"HTTP/2 200 OK" 两处（HTTP/2 无 reason phrase）。

### 第 10 章 Docker（6 处逻辑 + 4 处表达）

- **EXPORT → EXPOSE**（**官方勘误已收录** p176；docs.docker.com）。
- "Express.js 服务器的状态消息"——容器内是 Next.js。
- 构建输出 alpine vs 正文 Debian vs Dockerfile node:current 三方矛盾。
- --volume "创建 Docker volume"——实为 bind mount（docs.docker.com 明确区分）。
- "用 SSH 在容器内执行命令"——应用 docker exec。
- "docker compose down 发送 SIGTERM"——stop 才是；down 还会移除容器/网络。
- 表达：service.ts → services.ts、`<containerid`、IMAGE 表头、CRTL-C → CTRL-C。

### 第 11 章 Docker 环境（2 处逻辑 + 2 处表达）

- DB_NAME 等定义为"集合"——实为**数据库**（MongoDB 官方镜像文档）。
- `db.locations.insert()` 已弃用——mongosh 应用 insertMany()。
- 表达：CRTL-C；docker exec 提示符上下文矛盾（低优先）。
- 存疑：清单 11-3 卷路径指向 code/code 疑描述不完整。

### 第 12 章 中间件（1 处逻辑 + 3 处表达）

- mongoose/location → locations（3 处）；未翻译 interface；"Location 模型"命名统一。

### 第 13 章 GraphQL API（4 处表达 + 1 存疑）

### 第 14 章 前端（2 处 + 1 表达）

- locations-details/location-details 目录名前后矛盾（14-15 章各一处）。

### 第 15 章 OAuth 集成（4 处编译级 + 6 处表达）

### 附录 A（3 处）

- **skipLibCheck "设为 false 减少编译时间"**——应为 **true**（typescriptlang.org/tsconfig/skipLibCheck）；且针对的是声明文件有错的依赖，非"无类型"依赖。
- incremental 是 Boolean 非 string。
- lib "编译器把 polyfill 加进生成代码"——lib 只提供类型定义，不注入 polyfill。

### 附录 B（9 处）

- **清单 B-3 fetch 双重语法错误**（速览 #8）。
- 清单 B-6 revalidate 20 vs 正文 30 矛盾。

- RequestContext vs ReqContext 接口名不一致。

- "不能同时在 pages 和 app 有 api 文件夹"——与官方文档及本附录开头矛盾（仅同 URL 冲突才报错）。
